# ui-unit-test-v2

- 무기 카드는 굵은 아래 선 끝에 가는 위 선 시작을 붙이고, 원의 오른쪽 끝을 가는 사선 중점에서 왼쪽으로 12px 띄운다. 장비 배율 1.0·원본 420×132px·원 80px로 표시하며 이름/글꼴 원본 크기도 함께 조절한다. 근접 `SLASH`·원거리 `IMPACT`, 한 무기의 `FIRE` 아이콘은 시연 데이터다. 속성/MELEE/RANGED는 가물치 무료고딕이며 속성별 색은 미정이다. E/F 전환·블러는 기존 제어를 사용한다. 배치는 `v2.style.weapon_card`와 `v2.layout.weapons`, 표시 데이터는 `hud_sample.json`에서 조절한다. [표시 규격](../../docs/unit-tests/weapon_card.md)을 따른다.

- 플레이어 피격 시 HP·에너지·LV·필살기 아이콘과 부착 문구를 한 레이어로 그려 약한 중심형 모션 블러를 한 번 적용한다. `v2.style.resource_hit_blur`는 셔터 0.008초·최대 3 화면 px·세기 0.22·33샘플·영역 여백 8 논리 px다. 속도가 낮아지면 길이·세기도 줄며 방향 전환 끝점에서는 필터를 건너뛴다. HP 개별 블러는 제거했으며 대시·록온·흡수 입자는 이 필터 밖이다.

- 카운터 블러는 `counter_motion_blur.forward_bias=1`로 이동 방향 쪽에 치우쳐 표시한다. 기본 여백은 사방 48px이며 편향을 반영한 전체 번짐 길이+8px까지 자동으로 넓힌다. 최대 길이는 128px·이동량 배율은 1.3이다. 노출 0.06초·전환 0.18초는 유지한다. 로드아웃·무기·HP 블러는 기본 `forward_bias=0`의 중심형을 유지한다.

- 에너지 오브의 평균 이동시간은 0.9875초다. 고정 도착 간격 대신 `v2.energy_absorption.duration_variation=0.18`로 최대 ±18% 변동을 생성 Compute에서 적용한다. 짝의 증감을 상쇄하고 홀수 요청의 마지막은 평균값을 사용해 요청당 평균을 보존한다. 개별 도착 시 분할 회복·동적 목표는 유지하며 추가 입자 상태 버퍼나 프로그램은 없다.
- HIT·DAMAGE는 로드아웃과 같은 순간 속도×노출 시간으로 연속 GPU 블러를 계산한다. 노출 0.06초·세기 0.85·최대 128px, 숫자 전환은 0.18초다. `counter_motion_blur.overscan_pixels=48`는 최소 여백이며 실제 번짐 반경에 따라 사방으로 늘려 합성 결과가 숫자 상자에 잘리지 않게 한다. 원래 숫자 전환의 문자 마스크는 유지하며 레이블·고정 자릿수는 필터 밖이다.

- 필살기 쿨다운 동안 아이콘·외곽은 밝기 22%로 어둡게 표시한다. `ultimate_cooldown_seconds / ultimate_cooldown_duration_seconds`로 남은 비율을 계산해 아래에서 위로 원래 밝기를 드러낸다. 남은/전체 시간은 게임이 공급하며 예제는 5초다. 완료 flash·LV3/쿨다운 0 강조선 조건은 유지한다.
- `v2.style.ultimate_border_width_pixels`·`resource_border_width_pixels`는 필살기 외곽·HP/에너지/LV 외곽의 3px 두께다. 쿨다운 밝기는 `ultimate_cooldown_dim_opacity=0.22`다. 내부 아이콘 그림·채움 끝선의 기존 두께와 구분한다.
- LV 영역 윗선은 HP 바 윗선과 같은 높이다. 오른쪽 위/아래 사선은 `v2.layout.level_right_bevel_pixels=7`로 짧게 하고 같은 길이를 유지한다. 레벨 왼쪽과 HP 오른쪽은 같은 수직선으로 연결한다. `level_bevel_pixels`는 기존 접합 위치의 수평 여유를 유지한다. LV 레이블은 숫자 왼쪽 아래에 맞춘다.

- 록온·필살기 강조선은 `v2.style.accent_profile`의 공통 분절형이다. 경로 뒤쪽의 가는 꼬리 → 작은 조각 2개 → 앞쪽의 긴 본체 순서이며 최대 굵기는 `lock_accent_pixels=4.5`다. `sections`는 각 조각의 시작/끝 길이 비율과 시작/끝 굵기 비율이다. 조각 사이에는 기본 테두리가 보이며 번짐을 추가하지 않는다. `length_sides=1.0`으로 한 변 길이를 차지하고 모서리를 지나는 단면을 공유한다. 이전 `accent_hatching`은 비활성이다. 공통 순환은 5차 보간에 등속 성분을 섞어 시작/끝 속도를 평균 속도의 25%로 유지하고 중간 t=0.5에서 최대 속도이며 이동 0.5초·대기 0초로 반복한다. 양끝에서도 느린 속도로 이동하며 가속·감속을 반복한다.
- `v2.energy_fill_seconds=0.12`는 에너지 증가 표시 시간이다. 실제 충전량·레벨·필살기 준비·Overdrive 판정은 즉시 반영하고 누적 에너지 표시만 현재 위치에서 새 목표로 보간한다. 연속 도착은 진행 중인 보간의 남은 시간을 공유하며 완료 시각을 뒤로 미루지 않는다. 레벨 경계에서는 채운 뒤 다음 구간으로 넘어가며 역방향 축소 보간을 하지 않는다. 기본 게이지·Overdrive 추가 게이지·끝선·경계 입자 위치에 표시 값을 사용한다. 흡수 입자의 도착 판정·회복량은 기존 경로를 유지한다. 감소·초기화는 즉시 반영하고 일시정지 중에는 표시도 멈춘다.
- `EnergyTintMotion`은 논리 충전량과 별개로 표시 색을 0.24초 동안 보간한다. 바·회복 flash·흡수 입자에 같은 `energy_tint_ratio`를 공급한다. `v2.style.energy_tint_seconds`로 시간을 조절하며 정지 중 멈춘다. 충전/Overdrive 판정은 지연하지 않는다.
- Overdrive 완충 뒤에도 채움 끝의 불꽃을 유지한다. 일반 40개/초·0.8초 수명에서 Overdrive 96개/초·1초·강도 1.8로 전환한다. `energy_boundary.overdrive_*`로 조절한다. 생성 강도는 GPU 속도·크기에 적용하며 생성/갱신 Compute 두 개를 유지한다.
- HIT·DAMAGE의 바뀌는 자릿수는 별도 투명 레이어에 그리고 실제 원근 투영 이동축을 따라 연속 GPU 방향성 필터를 적용한다. 고정 자릿수·레이블·받침판은 필터 밖이다. `v2.style.counter_motion_blur`는 노출 0.06초·세기 0.85·49샘플·최대 128px·이동량 배율 1.3이다. LV 숫자의 기존 잔상은 유지한다.

- `v2.style.overdrive_entry_streak`: 등장 순간 중앙에서 수평으로 뻗는 빛을 한 번 표시한다. 0.045초 확장·0.025초 유지·0.17초 fade-out, 최대 길이는 바 폭의 88%다. Overdrive 퇴장 투명도를 함께 적용하며 일시정지 때 등장 시계도 멈춘다.


- 오른쪽 LV 외곽의 위·아래 사선은 같은 가로/세로 변화량을 사용한다. 가운데 수직선은 전체 높이에서 두 사선 높이를 뺀 길이다.
- `v2.style.energy_boundary`: 채움과 빈 공간의 경계에 흰 선과 GPU 불꽃을 표시한다. `energy_boundary.color=#FFFFFF`는 채움 끝선·경계 광의 공통 색이다. 십자 반짝임 도형은 표시하지 않는다. 초당 40개·수명 0.8초이며 위로 상승하고 옆으로 흩어진다. 생성/갱신 Compute의 효과 종류 1을 사용하며 CPU는 요청 주기만 관리한다. 회복량은 0이고 빈 게이지에서는 새 불꽃을 만들지 않는다. Overdrive 완충 뒤에는 강화된 불꽃을 유지한다. Overdrive 추가 충전 중에는 그 추가 채움 경계를 사용한다.
- `HealthHitMotion.damping`·`lock_motion.hit_damping`의 기본값은 1.8이다. 지수 감쇠와 종료 구간 완화를 함께 사용하며 위치·속도는 종료 때 0이다. 0이면 지수 감쇠만 끈다. 피격·연타는 진폭 상한을 누적하지 않는다.
- 필살기 준비 조건은 `energy_level == 3`과 `ultimate_cooldown_seconds == 0`이다. `HudV2State.ultimate_ready`로 확인하며 준비 중에만 마름모에 강조선 두 개를 그린다. 록온과 같은 `accent_position`·`outline_segment` 및 `lock_motion.move_seconds/hold_seconds`를 공유한다. 준비 상태로 바뀌면 0.28초 flash가 한 번 재생된다.
- 샘플의 **V**는 준비됐을 때만 필살기를 사용하며 에너지는 유지하고 5초 쿨다운을 시작한다. 재입력으로 남은 시간을 초기화하지 않는다. `v2.ultimate_sample.cooldown_seconds/flash_seconds`는 예제 수치다. 본편은 실제 남은 쿨다운을 상태로 공급한다. 쿨다운·피격·Overdrive 전환·입자 시간은 일시정지 중 멈춘다.


- 에너지는 `EnergyCharge`의 누적 충전량으로 계산한다. 한 게이지마다 LV1→LV2→LV3으로 오르고, **LV3 게이지 완충 후 추가 한 게이지**를 채워야 Overdrive에 진입한다. 추가 충전은 기본 채움 위의 밝은 영역으로 표시하며 `overdrive_charge_ratio` 0→1에 따라 바·흡수 오브·리본·회복 flash가 청록→빨강으로 변한다. 빨강은 `v2.style.overdrive_red`다. 샘플 기본 상태는 LV3·72%이며 Overdrive 전이다. 6은 완충/Overdrive 비교용 조작이다.
- HIT·DAMAGE와 LV 상승 숫자는 v01의 탄성 이동·방향성 잔상을 사용한다. `damage_counter.duration_seconds=0.18`이며 `vertical_easing`·`elastic_*`·`outgoing_fade_power`를 공유한다. HIT/DAMAGE 필터는 `counter_motion_blur`, LV 잔상은 `damage_counter.blur_*`를 사용한다. COUNTER! 메시지는 이 숫자 전환과 별개다.
- HP·LV 접합부는 곡선 없이 사선으로 연결하고 오른쪽 외곽은 `\`·`|`·`/` 순서다. `v2.style.level_bevel_pixels`는 모서리 크기, `level_text`는 숫자와 왼쪽 아래 LV 레이블의 간격/크기, `counter_label_*`는 HIT/DAMAGE 레이블의 오른쪽 여백·받침판 아래 간격이다.
- 타겟 선택 변경·해제 때도 현재 HP 비율을 보존한 채 독립적으로 페이드아웃한다. 처치 시 HP는 0에서 페이드하며 록온 마커의 기존 회전·확대 퇴장은 유지한다.


`concept/ui-concept-v2.png`를 바탕으로 배치와 스타일을 다듬는 독립 UI 테스트다. 도안 이미지는 실행 입력이 아니며, 샘플 도형·수치와 저장소에 배포하는 폰트만 사용한다. 기존 v1과 별도 설정을 사용한다.

## 실행

Pico2D 1.5.1이 설치된 Python 3.11 환경에서 프로젝트 루트 기준으로 실행한다.

```text
python tests/ui_unit_test_v2.py
```

Unit Test Runner에서 `tests/ui_unit_test_v2.py`를 선택하거나 Runner 창에 드롭해도 실행한다. 최초 화면은 1280×720 전투 HUD다. `Esc`로 일시정지를 열고 `타이틀로`를 누르면 타이틀 화면을 확인한다. 설정은 아직 비활성이다.

## 조절 위치

- `v2.style.health_hit_motion`: 타겟 HP `(0, ±5px)`·플레이어의 연결된 자원 UI 묶음 `(0, ±7px)`의 피격 진동이다. HP·에너지·레벨·필살기 아이콘/문구가 함께 움직이며 분리된 대시는 고정한다. 연결된 자원 묶음의 약한 블러는 `resource_hit_blur`에서 조절한다.
- `v2.absorption_routes.paths_by_side`: 왼쪽·오른쪽 각 6개 고정 경로다. 양쪽 모두 바 아래를 지나며 필살기 아이콘을 필수 경유하지 않는다. 경로 번호는 생성 때 선택하고 최신 에너지 채움 끝점에 맞춰 진입 구간을 변형한다.
- `v2.energy_absorption`: 예제 입자 수 6개·총 회복량 10%·평균 이동 0.9875초·최대 ±18% 변동·풀 256개·회복 flash 0.16초·처치 HP 퇴장 0.32초다. 회복량은 예제 수치다. 입자별 도착 때만 분할 회복하며 CPU UI는 완료된 비동기 집계를 받은 프레임에 반영한다. `4`/`G`도 도착을 기다리며 `3`의 감소는 즉시 반영한다.
- `v2.style.lock_motion.hit_seconds/hit_scale/hit_shake_pixels`: 일반 피격의 록온 마커 확대·진동이다. 기본은 0.26초·상한 1.5배·2.2 화면 px이며 `hit_damping=1.8`의 지수 감쇠를 적용해 실제 확대 피크는 약 1.24배다. 처치 때는 기존 퇴장 효과를 유지한다.
- `v2.style.absorption_trail`: 필압 꼬리·오브 크기·오른쪽 경유 여백을 조절한다. 기본 `renderer=compute`는 OpenGL 4.3 이상을 요구한다. CPU는 생성 요청과 프레임 시간만 보내며 GPU의 생성/갱신 Ubershader 두 개가 입자 생성·경로 선택·수명·이동·Trail을 처리한다. 활성 목록·간접 Instancing을 사용해 프레임 중 입자 상태를 CPU로 읽지 않는다. 프로그램은 로딩 중 한 번 컴파일·링크한다.
- `1`은 적 피해·HP바/록온 피격 반응·오브 6개 회복, `2`는 플레이어 피해·자원 UI 진동/HP 블러다. 적 HP가 0이면 HP바는 페이드아웃하고 마커는 기존 효과로 퇴장한다. `G`는 피해 없이 흡수·회복을 시연한다. `Esc`는 효과 정지/재개, `F5`는 초기화다. 좌클릭 모션의 실제 피해 판정·본편 에너지 규칙 연결은 별도다.
- 대량 생성·갱신·렌더 계측은 [Massive Energy Particle Stress](../massive_energy_particle_stress/README.md)에서 별도로 실행한다.

- `ui_config.json`의 `v2.layout`: 미니맵·록온·타겟 HP·플레이어 HP·에너지·필살기 아이콘·레벨·무장·카운터 배치.
- `v2.layout.hp_bar`·`energy_bar`·`ultimate_center_x`·`ultimate_radius_pixels`: 바의 높이/오른쪽 끝과 아이콘 위치·크기. 두 바의 왼쪽 경계는 마름모 변에 맞춰 계산한다. HP 안쪽 여백은 없고 수치/HP는 바 위에 자동 정렬한다.
- `v2.layout.energy_level_width_pixels`·`v2.style.level_bevel_pixels`: HP 옆에 붙는 레벨 영역의 폭과 사선 모서리 크기. HP/에너지 접합 위치를 함께 계산하며 레벨 왼쪽은 수직이다.
- HIT·누적 데미지 전체 크기는 각각 `v2.style.counters.*.ui_scale=0.9`로 조절한다. 숫자·레이블·받침판·정적 잔상을 함께 10% 축소한다. `v2.layout.hit_y=276`·`damage_y=366`으로 간격을 90px로 맞추고 기본 샘플의 묶음을 화면 오른쪽 중앙에 배치한다. 오른쪽 여백은 14px다.

도안 배치를 바로 볼 수 있도록 최초부터 98 HIT·12,004 DAMAGE·COUNTER를 표시한다. 이 값은 전투 규칙·자동 카운터 판정이 아니다. 에너지 조절·레벨·Overdrive 표기도 서로 독립적인 샘플 조작이다. V는 필살기 키 **후보 표기**이며 필살기를 발동하지 않는다. 무기 전환은 고정된 두 행의 위치·밝기를 전환하며, v1의 로드아웃 시간 상태와 무기 선택 가중치만 재사용한다.

미니맵 지형과 플레이어·적은 기본 도형이다. 최초 A는 시연용 선택이며 첫 마우스 입력 전에는 유지한다. 마우스를 움직이면 월드 좌표 최근접 후보를 자동 확인하고 1초 뒤 교체한다. R 선택은 제거했다. 기체·록온·레이더·피해 숫자는 같은 카메라로 투영하고 HUD는 고정한다. 적별 HP는 보존한다. 합의한 규칙과 연결 범위는 [자동 표적 명세](../../docs/ranged_targeting.md)를 따른다.

대화창은 표시용 샘플이다. 위쪽 적·록온·HP 위에 그려 UI 가림을 재현하며, 후보 선택은 유지한다. 실제 대화 진행·선택지·월드 장애물의 시야 차단은 포함하지 않는다.

몸통 크기는 `target_body_size_pixels`로 공급한다. 게임에서는 전체 스프라이트 경계 대신 실제 몸통의 화면 Rect를 `HudV2State.target_body`로 전달한다. 무기 카드의 위/아랫변과 01·02 번호·무기 구분·잔탄은 수평이며 입체 기울임/회전 표현은 제거했다. 사선 옆변과 비활성 카드 80% 크기는 유지한다.

## 등장 효과 연결 지점

히트·누적 데미지 카운터의 숫자/레이블만 `v2.style.text_flicker`를 적용한다. 최소 불투명도 0.9·주기 `period_seconds=0.12`·감광 시간 `dim_seconds=0.06`·전환 보간 `transition_seconds=0.06`이다. 유지 구간 없이 90~100%를 smoothstep으로 왕복하고 두 카운터는 같은 위상을 사용한다. MAP·HP 글자·무기/잔탄·COUNTER 메시지·개별 피해 숫자는 제외한다. 호흡은 `energy_breathing`의 최소 0.65·주기 2.4초다. 각각 최소 불투명도를 1로 두면 해당 변화가 정지한다. 기존 `ScanlineVisual.elapsed_seconds`를 사용하며 카운터 받침판에는 점멸을 적용하지 않는다.

피해 숫자의 실제 펼침 설정은 `damage_popup.width_expand_seconds=0.025`·`height_expand_seconds=0.035`다. 각 등장/퇴장 0.06초이며 총 표시 시간은 유지한다. COUNTER는 `IndicatorFade`를 갱신해 `view.combat(counter_message_opacity=...)`로 공급한다. 시간은 `counter_message_motion`의 등장 0.06초·퇴장 0.05초다. 이는 HIT/DAMAGE의 숫자 자리 갱신 시간이나 록온 개폐 시간과 별개다.

HP flash는 `HealthDamageFlash.trigger(피해 전 비율, 피해 후 비율)`·`update(delta_seconds)`로 관리하고 `visuals`를 `view.combat(player_damage_flashes=..., target_damage_flashes=...)`에 공급한다. 실제 피해가 0이면 발생시키지 않는다. 상태는 실제 HP·빨간 Trail과 분리하며 샘플에서는 Trail과 함께 일시정지한다. 표적 교체와 F5는 해당 flash를 비운다. `v2.style.health_damage_flash`의 등장/유지/퇴장은 0.012/0/0.14초다. 흰 구간은 이번 실제 피해량이다. 에너지의 스캔·밝은 띠·노이즈는 `panel_layer(effect_surface=...)`로 사선 채널 마스크를 공유한다.

록온은 `LockOnMotion.select(target_id, body)`·`update(delta_seconds)`로 제어하고 `visuals`를 `view.combat(lock_visuals=...)`에 공급한다. 몸통 Rect는 카메라 투영 후 좌표다. 선택 유지 중과 퇴장 중에도 적의 월드 위치를 현재 카메라로 투영한다. 자동 선택 규칙은 `MouseAutoTargeting`, 좌표 변환은 `LookAheadCamera`가 맡는다. 새 선택 ID에서 기존 표시 퇴장과 신규 등장을 재생한다. `view.combat(player_screen=...)`는 레이더 중심을 실제 플레이어 화면 위치에 맞춘다.

`v2.style.lock_motion`은 등장 0.32초·캐럿 0.16초·퇴장 0.2초·강조선 이동 0.5초/대기 0초·최저 속도는 평균의 25%(`minimum_speed_ratio`)·시작 배율 0.25/퇴장 배율 1.5를 조절한다. 기본형은 정사각형이며 등장 완료 45°는 마름모다. 가이드 조작키 색/설명 투명도는 `dialogue_key_color`·`dialogue_description_opacity`다.

OVERDRIVE 문구만 SUITE Regular 18px로 게이지 중앙에 표시한다. ENERGY 문구는 표시하지 않는다. 문구 폭은 바 폭의 60%(`overdrive_width_ratio=0.6`)다. 등장 때 불투명도는 0.065초에 올라가고 0.42초 동안 글자가 중앙에서 퍼지며 개별 반짝임·에너지색 Bloom을 낸다. 퇴장은 0.18초 fade-out만 사용한다. 시간은 `v2.style.overdrive_motion`, Bloom은 `overdrive_bloom`으로 조절한다. 준비된 네온 텍스처를 재사용한다.

등장 중 취소도 역재생하지 않는다. 취소 시점의 실제 회전값/배율을 저장해 그 값부터 회전은 2배, 크기는 `exit_scale`배까지 확대하며 흐려진다. 완료 뒤 취소는 기존 45→90°·1→1.5배와 같다.

곡선 정의는 Flutter 공식 [elasticOut](https://api.flutter.dev/flutter/animation/ElasticOutCurve-class.html), [easeInOutCubicEmphasized](https://api.flutter.dev/flutter/animation/Curves/easeInOutCubicEmphasized-constant.html), [easeInOut](https://api.flutter.dev/flutter/animation/Curves/easeInOut-constant.html)를 따른다. Flutter 런타임 의존성은 추가하지 않는다.

`ferrial_drive/ui_v2/panels.py`의 `build_panel_geometry()`는 `surface`와 `border_parts`를 따로 반환한다. 테두리 ID는 `upper_corner`·`upper_rail`·`upper_fragment_0~2`, `lower_corner`·`lower_rail`·`lower_fragment_0~2`다. 면은 `panel_surface()`, 테두리는 `panel_border()`로 그린다. `part_opacities`로 각 조각을 독립 표시할 수 있다. 입력·시간·등장 순서는 형상 모듈에 넣지 않는다.

Scanline 시간은 `effects.py`의 `ScanlineMotion`이 관리한다. 같은 `visual`을 `UiV2View.combat/menu/pause(scanline_visual=...)`에 공급한다. 테스트 실행부는 일시정지 중에도 UI 시계를 갱신하고 게임 갱신만 멈춘다.

대화창은 `DialoguePanelMotion.request(opened)`·`update(delta_seconds)`로 제어하고 `visual`을 `view.combat(dialogue_visual=...)`에 공급한다. 닫힘 중에는 `DialogueInfo`를 유지하고 `phase == "closed"`가 된 뒤 제거한다. 조회와 실제 출력은 같은 표시값을 사용해 펼쳐지는 패널의 Y 구간도 밝은 띠 경로에 반영한다. 글자를 압축하지 않고 완성 뒤 표시하며, 다른 패널의 개폐와 테두리 조각별 순차 등장은 후속 범위다.

프레임 출력 전에 `view.prepare_panel_effects(draw_panels)`로 그릴 UI를 한 번 조회한다. 이 단계는 도형을 출력하지 않고 보이는 패널의 Y 구간을 수집하므로 콜백 안에서 입력·시간·게임 상태를 갱신하지 않는다. 실제 출력과 같은 레이아웃·배율·clip을 사용하며 등장/퇴장 중인 패널도 반영한다.

OVERDRIVE 문구는 에너지 채움 영역의 가로·세로 중앙에 SUITE Regular 16px로 표시한다. 전체 문구 폭이 바 중앙 높이의 가로 폭 75%가 되도록 자간을 자동 계산한다. 글꼴은 `fonts.v2_overdrive`, 폭 비율은 `v2.style.overdrive_width_ratio=0.75`에서 조절한다. 에너지 색 Bloom은 `v2.style.overdrive_bloom`의 반경 6px·세기 1·2회 겹침을 사용하고, 기존 에너지 호흡과 같은 2.4초·65~100% 주기로 변한다. 네온 본문은 3배 해상도에서 생성해 선형 축소하고 광과 동일한 소수점 좌표로 표시한다.

- `v2.camera_motion_blur`: 카메라 속도에 따른 노출 길이를 `amount / target_fps`초로 계산한다. 기본 `amount=0.75`·`target_fps=60`은 0.0125초이며 최대 24 화면 px·33샘플이다. 선명한 원본을 별도로 섞지 않고 노출 구간을 중심형으로 적분한다. 기체·적 레이어만 합성하며 HUD·록온·피해 숫자·흡수 효과·타이틀은 필터 밖이다. 정지·일시정지·장면 전환에는 생략한다. 기존 OpenGL 필터를 재사용하며 소프트웨어 렌더러는 필터 없이 그린다. 픽셀별 물체 속도·깊이·가림 복원은 없는 2D 카메라 평행 이동 근사다.
