# 메뉴·전투 HUD 직접 테스트

현재 UI 시안은 사용자 승인을 받았다. 이후 코드 정리에서 배치·폰트·효과 값은 유지하고 글자 측정·링 계산 캐시와 불필요한 상태·버튼 객체 생성을 줄였다. 정리 후 화면 비교·실행·성능 측정은 수행하지 않았다. 일시정지·재개, 타겟 유무·HP 0의 버튼 비활성, 좌우 HP 바 전환, 카운터 만료 후 재적중과 창 종료·재드롭을 다시 확인한다.

후속 색상 요청으로 패널 채움만 `colors.panel_surface=#39444A`의 Bezel 근사색을 시험한다. Pantone 공식 환산값으로 확인한 것은 아니며 [색상 기준과 임시 적용 범위](../../docs/Ferrial_Drive_PRE_PRD_v0.1.md)를 따른다. 타이틀·타겟 패널 알파 0.45·일시정지 알파 0.85를 유지하므로 실제 화면색은 배경과 합성된다. `panel_style.metallic`의 정적인 반사 띠·가로 결로 금속 느낌을 더하며, 실제 조명·환경 반사 셰이더와 구분한다. `enabled=false`로 단색과 비교하고 `contrast`(0.22)·`grain_strength`(0.012)로 강도를 조절한다. 질감은 저장해 재사용하며 최초 생성·실행 성능은 측정 전이다. 버튼·기체·테두리·글자색은 기존 역할을 유지한다. 같은 파일을 재드롭해 타이틀·타겟·일시정지 패널의 인상을 확인한다.

`tests/ui_test.py`는 Runner import·상속 없이 직접 실행하는 메뉴·전투 HUD 미리보기다. 자체 창·루프는 `ferrial_drive/ui/standalone.py`가 관리한다. 게임·세이브·AI 생성 에셋 없이 공개 폰트와 기본 도형을 사용한다.

기존 실행기를 닫고 `tests/Unit Test Runner.lnk`로 다시 연 뒤, 같은 폴더의 **`ui_test.py`를 열린 Runner GUI 창에 드롭**한다. UI 테스트는 별도 창으로 열린다. 이후 공유 UI 모듈·설정 변경은 같은 파일을 Runner에 재드롭해 새로 실행한다. [공통 실행기 안내](../../Tools/unit_test_runner/README.md)를 따른다.

## 포함 파일

- `ui_config.json`: 1280×720 창, 배치·문구·색·폰트 역할·버튼 동작 ID, 피해량·애니메이션 시간. `panel_style.fill_opacity`는 0.45, `colors.panel_border`는 선명해진 테두리 색이다.
- `hud_sample.json`: 가짜 HP·타겟·콤보·누적 가한 피해·레이더 상대 좌표. 파일 변경 후 `ui_test.py`를 다시 드롭해 반영한다.
- `../../data/fonts/`: 메뉴 제목·소제목·본문·설명·버튼·순번에는 Cafe24OhsquareAir-v2.0.otf를 비교 시안으로 적용한다. HIT·이번 피해·누적 DAMAGE 숫자는 학교안심 운동장을 사용한다. 나머지 HUD 텍스트는 에스코어 드림을 유지한다. 크기와 효과는 기존 값을 유지하며 [폰트 안내](../../data/fonts/README.md)에 역할을 정리했다.
- `../../ferrial_drive/ui/`: 표시용 데이터·입력·위젯 표현·이동·페이드·독립 피해 숫자. 게임 엔티티나 테스트 실행기를 import하지 않는다.
- `../../tests/ui_test.py`: 가짜 상태 공급·버튼·Esc 연결과 자체 실행 진입점. 본편은 이 파일을 거치지 않고 재사용 UI 모듈에 실제 상태를 전달한다.

메뉴 좌표의 원점은 왼쪽 위이며 단위는 픽셀이다. 시간은 초다. `buttons`의 `label`은 표시명, `action`은 동작 식별자다. 현재 버튼 판정 영역은 겹치지 않아야 한다. 크로스헤어 색은 `colors.crosshair`(흰색), 반지름은 `layout.crosshair_radius`, 원 두께는 `layout.crosshair_thickness_pixels`(3px), 십자 두께는 `layout.crosshair_cross_thickness_pixels`(2px)에서 조절한다. 첫 포인터 입력 전에는 중앙에 두고 창 밖에서는 마지막 유효 위치를 유지한다. 버튼 위·장면 전환·일시정지와 열기/닫기 중에도 마우스를 따른다. `hit_padding`은 표시 크기와 별개다.

장면 제목의 위치는 `layout.combat_heading`(기본 `[28, 24]`), 크기는 `fonts.combat_title.size`(기본 42)로 조절한다. 전용 에스코어 드림 Medium 역할을 사용해 메뉴의 `heading` 크기와 독립적이다. HUD 본문·작은 설명은 `hud_body`·`hud_small`로 메뉴의 `body`·`small`과 분리한다. `샘플 상태 조작` 안내 문구는 제거했다. 타겟 패널은 상단 중앙 y=24의 372×58px, 플레이어 HP는 공격 반대편의 6×72px 세로 바만 표시하며, 샘플 버튼은 y=656·높이 48px로 아래 여백 16px에 맞춘다. 타겟 패널은 왼쪽 TARGET·오른쪽 적 이름의 세로 중심을 맞추고 전용 `fonts.target_heading`(Bold 14px)·`fonts.target_name`(Regular 18px)을 사용한다. HP 숫자는 숨기며 바 두께는 6px다. `layout.target_name_max_width`(240px)로 긴 이름의 말줄임 폭을 조절한다.

## 직접 실행

타이틀에는 `전투 HUD 보기 / 설정 / 테스트 종료`를 표시한다. 일시정지는 `계속 / 설정 / 타이틀로 / 테스트 종료` 순서다. 설정 항목·기능은 미정이라 양쪽 설정 버튼은 비활성 상태로 배치한다. 클릭해도 화면 전환·오류·배경 동작이 없어야 한다. 일시정지 제목만 더 굵은 Cafe24 Ohsquare 일반형 26px를 쓰며 `fonts.pause_heading`으로 분리했다. 타이틀의 초기화 버튼은 제거했으며 전투 HUD 하단의 테스트 초기화는 유지한다. 일시정지 패널 자체의 채움 알파는 `pause.panel_fill_opacity`(0.85)로 조절한다. 배경 어둡게 하기 0.75·타이틀/타겟 패널 알파 0.45와는 별도다.

플레이어·훈련 표적 A의 임시 도형과 기체 아래 이름표는 `tests/ui_test.py`에서만 그린다. 재사용 `UiView.combat`에는 이 도형·이름표·하단 테스트 버튼이 포함되지 않는다. 타겟 패널의 이름은 실제 게임에서도 `TargetInfo.name`으로 공급한다. `샘플 상태 조작` 안내 문구만 제거했으며 테스트 창의 하단 버튼은 유지한다.

전투 중 **Esc**는 일시정지 창을 연다. `계속` 또는 Esc로 돌아오고, `타이틀로`로 메뉴에 복귀한다. `테스트 종료`는 테스트 창을 닫는다. 일시정지의 열기·닫기 0.16초 동안에도 전투 버튼을 차단하며, 피해 숫자·카운터·표시 수명·HP 감소 효과·공격 방향은 멈춘 상태를 유지한다. 크로스헤어 위치는 계속 갱신한다. 효과가 나오는 중 Esc를 눌러 2초 이상 기다린 뒤 계속했을 때, 정지한 지점부터 이어지는지 확인한다. 배경 피해 버튼을 눌러도 HP가 변하지 않아야 한다.

플레이어 HP는 `player_hp_bar`의 폭 6px·높이 72px·중심에서 좌우 거리 56px로 표시한다. 마우스를 플레이어 오른쪽에 두면 오른쪽 공격 방향을 공급해 HP 바가 왼쪽으로 가고, 왼쪽에 두면 반대로 간다. 정중앙·창 밖·버튼 위·장면 전환 중에는 마지막 방향을 유지한다. 이는 실제 공격 없이 좌우 배치를 확인하는 샘플 입력이며, 게임은 `HudState.attack_direction_x`(-1/1)로 실제 공격의 좌우 방향을 전달한다. UI의 x·y 화면 좌표는 오른쪽·아래가 양수다.

카운터 표시명은 COMBO에서 HIT로 바꿨다. **HIT·DAMAGE 모두 내 공격이 적에게 적중할 때 나타난다.** DAMAGE는 내가 적에게 가한 피해 합계다. 최초·초기화 직후에는 둘 다 숨기고, `적 피해 +120`으로 양수 피해가 적용되면 함께 표시한다. 마지막 적중 후 유지 2초·SmoothStep 페이드 0.3초는 임시값이며 `counter_visibility.hold_seconds`·`fade_seconds`에서 조절한다. 추가 적중은 유지 시간을 갱신한다. 플레이어 피격·타겟 전환은 표시 수명을 갱신하지 않는다. 페이드가 완전히 끝나면 HIT·DAMAGE의 누적 값과 회전 표시 상태를 모두 0으로 초기화한다. 다음 적중은 1 HIT·이번 피해량부터 시작한다. 페이드 도중 재적중은 기존 값에 이어서 누적한다. 메뉴에서도 표시 시간은 흐르고 수명이 끝나면 초기화하지만 일시정지 중에는 멈춘다. 컬러테마 재설계는 3D 프리렌더 씬 제작 뒤의 별도 과제로 남긴다.

Python 3.11과 `requirements-ui.txt`의 Pico2D 1.5.1 환경을 사용한다. GUI에 드롭하거나 프로젝트 루트에서 다음처럼 직접 실행한다.

```text
python tests/ui_test.py
```

선택적으로 `python tests/ui_test.py --profile`을 실행하면 함수·구간별 경과 시간과 호출 횟수를 정상 종료 시 `output/performance/ui-...Z.json`에 저장한다. `--profile 경로`로 파일을 지정할 수 있다. 기본 실행·Runner 드롭에는 계측을 추가하지 않는다. [계측 대상·반복 측정·로그 해석](../../docs/tool-usage/performance_timing.md)을 따른다. 이번 계측 연결은 실행 확인 전이다.

직접 실행·GUI 실행 모두 메뉴의 테스트 종료 또는 UI 창 X로 해당 테스트만 닫는다. GUI 실행에서는 Runner 창이 남으며, Runner X를 누르면 소유한 UI 테스트도 종료한다. UI 테스트 창에 파일을 드롭하지 않고 Runner 창에 드롭한다. 샘플 원본은 실행 중 저장·수정하지 않는다.

## 조작과 기대 결과

플레이어·적 피해 버튼을 누르면 실제 HP 바는 즉시 줄고, 빠진 구간이 진한 빨간색으로 남았다가 `t²`로 점점 빨리 줄어든다. 효과 도중 다시 같은 기체에 피해를 주면 현재 빨간 영역 끝을 유지하며 목표를 갱신하고 t=0으로 재시작해야 한다. 기본 시간은 `health_trail.duration_seconds=0.6`, 색은 `colors.health_loss=#8F2028`이다. 플레이어 세로 바·타겟 가로 바에서 각각 확인한다. 실제 HP가 같으면 재시작하지 않는다. 표시 초기화는 두 효과를 지우고, 타겟 유무 전환은 타겟 효과만 지운다. HP 0에서도 남은 빨간 구간이 끝까지 줄어드는지 확인한다.

1. 최초 화면은 메뉴다. 전투 HUD 보기 또는 **Esc**로 전환한다.
2. **0.32초**의 SmoothStep 이동·페이드가 진행된다. 전환 중 Esc·좌클릭은 소비하며 완료 후 다시 받는다.
3. 플레이어 초기 HP는 내부 상태 **860/1200**이며, 숫자는 숨기고 플레이어 옆 세로 바에 약 71.7%로 표시한다. 표적 A의 초기 HP는 내부 상태 **540/800**이며, 타겟 패널에서는 숫자를 숨기고 약 67.5%의 얇은 바만 표시한다. TARGET 왼쪽·훈련 표적 A 오른쪽 정렬과 세로 중심 정렬을 확인한다. 중앙 플레이어 주변의 레이더 링과 적 방향을 향하는 **채워진 이등변삼각형**, 마우스를 따라 움직이는 흰색 원+십자 크로스헤어가 표시된다. 플레이어와 레이더 링은 중앙을 유지한다. 별도 레이더 패널과 점은 없다.
   플레이어 도형은 창 크기에서 계산한 화면 중앙에 고정하며 HUD가 전환되는 동안에도 옆으로 이동하지 않는다. 플레이어 피해 숫자도 같은 위치를 기준으로 표시한다.
4. **적 피해 +120**: 적 근처에 학교안심 운동장의 빨간 120, 표적 HP 바 약 52.5%(내부 상태 420/800), 오른쪽에 숫자 `1` 아래 HIT·숫자 `120` 아래 DAMAGE가 표시된다. 타겟 HP 수치는 표시하지 않는다. 콤보·누적 피해에는 패널이 없다. 누적 피해의 바뀌는 자리만 0.20초 동안 아래에서 올라와 이전 숫자를 위로 밀어내며, 이전 숫자는 점점 투명해진다. 움직이는 글자는 손가락으로 쓸듯 위쪽으로 늘이는 방향성 블러가 보인다. 자릿수가 같은 `120→240`에서도 백·십의 자리는 움직이며, 값이 같은 일의 자리 0은 선명하게 고정한다. DAMAGE와 쉼표도 고정한다. 이번 피해 숫자는 피격 기체 주변의 무작위 위치에 높이 1px 선으로 생겨 가로부터 완성 폭까지 펼친다. 다음으로 가로 폭을 유지하며 세로를 펼쳐 숫자가 나타난다. 완성 크기를 유지하다가 세로가 먼저 1px로 접히고, 남은 가로선이 중앙으로 접히며 사라진다. 자체 알파와 위치는 유지한다. 전체 수명은 등장·퇴장을 포함해 1.15초다. 숫자와 아래 레이블의 오른쪽 정렬·자간·패널 안 글자 여백도 확인한다.
5. **플레이어 피해 +75**: 플레이어 근처에 빨간 75, 플레이어 HP 바가 약 65.4%(내부 상태 785/1200)로 줄어들며 수치는 표시하지 않는다. 누적 가한 피해는 바뀌지 않는다.
6. 적 피해는 남은 HP까지만 적용한다. 표적 HP가 60일 때 누르면 빨간 60과 합계 +60으로 반영된다. HP가 0이면 해당 피해 버튼을 비활성화한다.
7. **타겟 유무**: 타겟 없음·빈 게이지를 표시하고 적 피해 버튼을 비활성화한다. 다시 누르면 이전 타겟 HP로 복원한다. 누적 가한 피해는 유지한다.
8. 연속으로 적 피해 버튼을 누르면 회전을 계속 처음부터 재시작하지 않고, 진행 중 회전이 끝난 뒤 최신 합계 하나로 반영한다. 플레이어 피해·타겟 유무 변경은 누적 피해 회전을 새로 시작하지 않는다. Esc로 일시정지하면 효과 시간이 멈춘다. 일시정지의 타이틀로 버튼으로 메뉴에 다녀와도 HP·누적 값은 유지하며, 메뉴에서는 회전 시간이 진행한다. **표시 초기화**는 JSON의 초기 상태와 콤보·합계를 즉시 복원하고 피해 숫자·카운터 잔상을 지운다.
9. 메뉴의 **테스트 종료**로 마친다.

최초 HUD 진입 시 HIT·DAMAGE가 숨겨졌는지, 플레이어 피해만으로는 나타나지 않는지 확인한다. 적 피해를 주면 둘이 함께 나타나고 마지막 적중에서 2.3초 뒤에는 완전히 사라져야 한다. 페이드 중 다시 적중하면 즉시 선명하게 표시하며 유지 시간이 갱신된다. 플레이어 피해·타겟 전환으로는 타이머를 늘리지 않고, 표시 초기화는 즉시 숨긴다. 완전히 사라진 뒤에는 두 카운터가 0으로 초기화되며 HP는 유지되는지 확인한다. 이후 적에게 다시 피해를 주면 이전 합계에 더하지 않고 1 HIT·이번 피해량부터 시작해야 한다.

타겟팅은 고정된 훈련 표적 A의 표시·숨김 시연이며 조준으로 대상을 선택하는 기능은 없다. 이 값과 동작은 UI를 확인할 가짜 상태다. 샘플 콤보는 적 피해 버튼의 유효 적용 횟수이며 실제 전투·이동·발사·타겟 선택·콤보 규칙이 아니다.

상단 브랜드·UI 테스트 표시·구분선과 하단 조작 안내는 제거했다. 타겟 제목은 `TARGET`만 표시한다. 이번 실행기 구조 변경을 처음 적용할 때만 Runner 창을 완전히 닫고 다시 연다. 이후 공유 UI 모듈을 수정하면 같은 ui_test.py를 Runner에 재드롭해 반영하는 경로다.

이번 피해 숫자의 기준 좌표는 피격 기체의 화면 위치이며 왼쪽 위 원점의 픽셀이다. 생성 시 x ±64px·y ±44px를 무작위 추출하고 표시 중에는 위치를 유지한다. 범위는 `animation.damage_scatter_x_pixels`·`damage_scatter_y_pixels`에서 조절한다. 적·플레이어 피해 모두 각 피격 기체 주변에 표시하며 HIT·DAMAGE 카운터들은 이 배치 변경의 대상이 아니다. 레이더 상대 좌표는 x 양수가 오른쪽, y 양수가 위다. 샘플 감지 거리는 1.0이다. 화면에서 플레이어 중심 반경 200px 이하의 적은 화살표를 숨긴다. 가까운 훈련 표적 (756,342)의 화살표는 사라지고, 원 밖인 왼쪽 위 중거리 적과 오른쪽 아래 감지 한계 적의 화살표 2개가 남아야 한다. 감지 한계 적은 중거리 적보다 작고 흐려야 한다. 범위 밖 적과 아군은 표시하지 않는다. 꼭짓점은 거리가 달라도 동일한 화면 링 반경에 유지한다.

`ui_config.json`의 `radar.range_units`는 상대 좌표와 같은 거리 단위, `radius_pixels`는 화면 링 반경이다. 기본 반경은 200px이며 링 두께는 `ring_thickness_pixels`의 2px다. `arrow_length_pixels`(20px)는 근거리 기준 높이, `arrow_half_width_pixels`(10px)는 밑변 반폭이다. 거리를 감지 거리로 나눈 비율에 따라 크기와 알파가 선형으로 감소한다. 감지 한계에서는 `arrow_min_scale`(0.45)로 높이 9px·전체 밑변 9px, `arrow_min_opacity`(0.25)로 알파 25%가 된다. 전환 중에는 장면 알파도 곱한다. 두 최소값과 링 투명도는 같은 설정에서 조정하며, 실제 게임의 감지 거리와 적 목록은 게임 연결부에서 제공한다. RadarContact의 필수 screen_x/screen_y에는 카메라 투영 후 절대 화면 좌표를 넣는다. 화면은 왼쪽 위 원점이며 y는 아래가 양수다. x/y는 기존 감지용 상대 좌표를 유지한다. 첫 적의 화면 좌표만 (840,360)으로 바꾸면 정확히 200px라 숨고, (841,360)이면 다시 보여야 한다. 샘플 파일 수정은 재드롭 후 반영된다.

## 확인 상태

카운터 갱신에서 숫자의 세로 이동은 페이드·블러와 분리했다. `damage_counter.vertical_easing=elastic_in_out`이면 같은 시간의 SmoothStep·elasticInOut을 `elastic_strength`(시안 0.35)로 혼합한다. `elastic_period`(시안 0.4)는 정규화 시간의 탄성 주기다. 강도 0 또는 `vertical_easing=smooth_step`이면 기존 세로 이동, 강도 1이면 elasticInOut 전체다. 탄성 출력은 이동에만 사용하고 페이드·블러 강도·블러 길이·카운터 전체 숨김은 기존 유계 진행률을 유지한다. 두 카운터에 모두 적용하며 이동 시간은 0.20초로 단축했다. 숫자가 바뀔 때 세로 이동의 인상, 이전 숫자의 단조로운 페이드, 변경되지 않는 자리의 고정을 확인한다.

콤보에도 같은 밀기·페이드·위쪽 방향성 블러를 적용한다. 사용자 정정에 따라 HIT 숫자는 76px로 복원하고 아래 레이블의 크기만 키운다. 기존 색과 바뀌지 않는 자리의 고정은 유지한다. 두 효과는 `damage_counter` 설정을 공유하지만 표시 상태는 독립적이다. 적 피해 버튼으로 두 숫자가 함께 변하는지, 플레이어 피해·타겟 전환에는 재생되지 않는지, 표시 초기화에서 두 잔상이 즉시 사라지는지 확인한다. `layout.combo_max_width`(312)는 숫자의 최대 폭이며 아래 레이블 공간은 차감하지 않는다.

콤보·데미지 카운터를 합쳐 **카운터들**이라고 부른다. 각 카운터는 **숫자 위·HIT/DAMAGE 레이블 아래**로 두고 숫자와 레이블의 오른쪽 끝을 맞춘다. 레이블은 16→20px로 키우며 글자 사이에 `layout.counter_stack.label_letter_spacing_pixels`(3px)를 더한다. HIT 묶음을 위, DAMAGE 묶음을 아래에 두고 `right_margin_pixels`는 오른쪽 여백(32px), `row_gap_pixels`는 두 묶음 사이 간격(8px)이다. 여백 중심은 화면 높이의 절반에 맞춘다. 720px 높이에서 HIT 레이블 하단은 356px, DAMAGE 숫자 상단은 364px이며 간격 중심은 360px이다. HIT 묶음 상단은 숫자 높이·레이블 간격·레이블 높이의 합에서 역산한다. 자릿수가 늘어도 오른쪽 끝과 여백 중심이 유지되는지 확인한다. 숫자와 레이블의 세로 간격은 각 `combo_label_gap`·`damage_label_gap`(4px), 숫자 최대 폭은 `combo_max_width`·`damage_max_width`(312px)로 조절한다. 작은 DAMAGE 폰트는 `fonts.damage_label`이다. 후속 배치·금속 질감은 실행 확인 전이다.

`damage_counter.duration_seconds`는 이동 시간, `blur_shutter_seconds`는 잔상 시간 폭, `blur_samples`는 잔상 샘플 수(0~12), `blur_opacity`는 잔상 강도(0~1)다. 기본값은 각각 0.20초·0.085초·9개·0.58이다. `blur_direction`(기본 `[0,-1]`)은 쓸리는 방향이며 x 양수는 오른쪽, y 양수는 아래다. `blur_length_pixels`(기본 28)는 최대 길이이며 실제 길이는 셔터 구간 이동량으로 제한한다. 잔상은 끝으로 갈수록 흐려진다. `outgoing_fade_power`(기본 1.4)를 높이면 이전 숫자가 더 빨리 흐려진다. 움직이는 자리만 2D 이동·페이드·방향성 블러를 사용하며 숫자 영역 안에서만 그린다.

2026-11-03 이번 구현의 **자동 검사·프로그램 실행·렌더링·조작은 수행하지 않았다.** 위 목록은 사용자가 확인할 기대 결과다. 이전 공통 실행기·메뉴 초안의 검사 통과를 이번 테스트의 검증 결과로 사용하지 않는다.

이번 피해 숫자 등장 시간은 `animation.damage_width_expand_seconds`(가로 0.05초)·`damage_height_expand_seconds`(세로 0.06초)에서 조절한다. 가로 단계는 높이를 정확히 1px로 유지한다. 등장 후 완성 크기를 0.93초 유지하고, 마지막 0.11초는 같은 곡선을 역재생해 세로 0.06초→가로 0.05초 순으로 접는다. 자체 알파는 끝까지 1이며 등장·퇴장 시간 합은 전체 수명보다 짧아야 한다. 두 값을 모두 0으로 두면 즉시 나타나고 수명 끝에 즉시 사라진다. 기존 HIT·DAMAGE 카운터 갱신 애니메이션은 이 등장 효과와 별개다.
