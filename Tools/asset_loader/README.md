# FDrive 에셋 로더

모델의 **3D 프리렌더·애니메이션 조립·미리보기·ID 등록·디버그 핫 로드**를 제공한다. 모델 렌더에는 Blender가 필요하며 기존 이미지·시트·본체/그림자 번들은 Blender 없이 읽는다.

## 실행

Pico2D가 설치된 Python 3.11 이상 환경에서 실행한다.

```text
python Tools/asset_loader/run.py
python Tools/asset_loader/run.py 경로/bundle.json --debug
python Tools/asset_loader/run.py --catalog 작업경로/catalog.json --debug
```

인자 없이 실행하면 `data/catalog/samples/asset_loader/`의 도형 샘플을 연다. 처음 실행할 때 공개 샘플 원본을 이곳에 복사하고 `data/catalog/catalog.json`에 샘플 3종을 등록한다. 기존 파일과 등록 목록은 덮어쓰지 않는다.

기본 카탈로그에 외부 에셋을 등록하면 이미지·시트·번들의 필요한 파일을 `data/catalog/prerender/<ID>/<버전>/`에 복사한 뒤 그 사본을 등록한다. 이미 `data/catalog/` 안에 필요한 파일이 모두 있으면 같은 파일을 참조한다. `--catalog`로 별도 목록을 지정하면 기존처럼 원본 경로를 참조한다. `data/catalog/`의 실제 파일은 Git 추적에서 제외한다.

Windows 바로가기 생성:

```text
python Tools/asset_loader/create_launcher.py
```

프로젝트 루트의 `FDrive Asset Loader.lnk`는 디버그 모드로 연다. 바로가기는 현재 환경의 경로를 포함하며 Git에서 제외한다. [독립 테스트 진입점](../../tests/asset_loader_test.py)도 Runner 목록에서 실행할 수 있다.

## 조작

| 조작 | 동작 |
|---|---|
| 불러오기 | .blend 모델·PNG·JPG·BMP 또는 시트·번들 JSON 선택 |
| 3D 렌더 | 모델·프레임·해상도·렌더 설정과 별도 Blender 작업 시작 |
| 애니메이션 조립 | 현재 에셋의 동작·프레임 순서·FPS·피봇 편집 |
| 관리 → 렌더 취소 | 이 도구에서 실행한 Blender 작업 정리 |
| 메카 설정 | 메카 레이어·동작·전환 시점 작업본 편집 |
| 관리 → ID 변경 | 등록할 ID 변경. 영문·숫자·밑줄·점·하이픈 |
| 등록 | 현재 원본을 다시 검증하고 카탈로그에 추가. 중복 ID는 거절 |
| 관리 → 핫 로드 전환 | 디버그 자동 갱신 켜기·끄기 |
| 관리 → 새로고침 | 다시 불러오기. 디버그에서는 실패 시 이전 정상 자원 유지 |
| 관리 → 카탈로그 열기 | 기존 등록 파일 열기. 목록 항목 클릭으로 미리보기 |
| ← / → | 동작·방향 변경 |
| Space / . | 재생·정지 / 다음 프레임 |
| 휠 / 맞춤 / 1:1 | 확대·축소 / 영역 맞춤 / 원래 배율 |
| 본체 / 그림자 | 본체 / 그림자 표시 전환 |
| 오른쪽 필터 메뉴 | Nearest / Linear / Bicubic 표시 비교 |
| PgUp / PgDn | 등록 목록 페이지 이동 |
| Esc / 창 X | 종료·GPU 자원 정리 |

화면의 십자는 프레임 피봇이며 기존 시트의 bottom-left 규격을 따른다. RGBA8 추정치는 픽셀 수 × 4바이트로 계산하며 실제 GPU 점유·임시 복사본·드라이버 비용을 측정한 값이 아니다.

상단은 파일/등록과 제작 버튼을 구분한 도구줄, ID·원본·동작·프레임·FPS 한 줄로 구성한다. 자주 사용하지 않는 ID·카탈로그·핫 로드·새로고침·렌더 취소는 **관리** 메뉴에 모은다. 미리보기는 화면 위 88px부터 사용하며 배율·재생/정지·앞뒤 프레임은 아래에 둔다. 종류·메모리 추정·핫 로드 상태·카탈로그 경로는 오른쪽 **상세 정보**를 펼쳐 확인한다. 내부 갱신 세대는 표시하지 않는다. 등록 목록의 휠은 목록 이동, 미리보기의 휠은 확대/축소로 작동한다.

## 메카 · 무기 분리 작업본

**이 패널은 제작 설정의 편집·저장 기능이다.** 기존 본체/그림자 렌더·조립과 별개이며, 입력한 설정을 Blender 분리 출력이나 게임 합성에 자동 적용하지 않는다. 원본 모델·메시·기존 번들은 변경하지 않는다.

왼쪽에서 **모델·출력 / 애니메이션 / 확인**으로 구분한 항목을 고르고 오른쪽에서 편집한다. 세부 설정·프레임별 순서·도움말은 필요한 경우 펼친다. 동작·방향·무기·가림 방식은 목록에서 직접 선택한다.

| 분류 | 편집 범위 |
|---|---|
| 공통 렌더 | 카메라 이름·기본 Blender 프레임·FPS·정사영 범위·이미지 크기·공통 기준점·전투/장비 미리보기 용도 |
| 출력 단위 | 손목까지의 본체, 좌우 손+무기, 수납 검/총, 칼집+부착부, 독립 검/총의 오브젝트와 부착 기준. 좌우 빈손 출력도 각각 지정 |
| 동작·순서 | 수납/장착 대기·이동, 꺼내기, 검 공격, 총 조준/사격, 넣기, 사출, 장비 미리보기. 클립·프레임·재사용 동작·메모와 동작/방향별 순서 |
| 전환 시점 | 각 동작의 좌우 손·검/총별 파지, 손 부착, 장착부 이탈, 수납 고정, 손 놓기, 독립 이동의 Blender 프레임 |
| 무기 조건·검수 | 겹침, 부착 연속성/중복/누락, 검 경로·길이 복귀·안전장치·칼집 에너지, 총 결합부 정렬·가림의 수동 검수 상태. 검 길이 복귀 시작·허리 수납·미확정 사항과 메모 |

그리기 순서는 **위에서 아래로 뒤 → 앞**이다. 출력 단위를 선택해 뒤로/앞으로 옮기며 좌우 손을 각각 다룬다. 기본 정면은 본체 → 손+무기, 후면은 손+무기 → 본체다. 사선 방향과 장착물의 초기 순서는 검토용 초안이다. 옆모습·휘두르기의 복합 가림은 방향별로 `미정 / 순서만 사용 / 추가 분할 필요 / 가림 처리 필요`를 지정한다.

출력 단위는 오브젝트·부착 기준·빈손 오브젝트를 같은 행에 배치한 표에서 함께 편집한다. 공통 렌더는 장면·프레임과 이미지·재생으로 구분하며 정사영 범위와 기준점은 **세부 설정** 안에 둔다.

프레임별 순서를 바꾸려면 **프레임별 순서**를 펼치고 Blender 프레임을 입력한 뒤 **이 프레임 편집**을 누른다. 기본 순서와 다른 방향에는 영향을 주지 않는다. 같은 프레임을 다시 선택하면 기록된 순서를 편집한다. **기본 순서**와 **현재 예외 삭제**로 기본값 복귀/해당 예외 제거를 구분한다.

모든 레이어는 같은 장면·카메라·배율·방향·크기·기준점과 해당 동작의 프레임을 공유한다. 동작별 프레임이 비어 있으면 공통 프레임을 사용한다. 손·검·총·칼집은 독립 오브젝트로 유지하고 출력 때만 손+무기로 묶는다. 빈 전환 프레임은 미지정이며 `1,3,5,7` 동작에서는 `2` 같은 재생 인덱스를 받지 않는다. 검 길이 복귀 시작은 수납 동작 프레임에서만 지정한다. 검수의 `확인`은 사용자가 실제 결과를 검사한 표시이며 자동 검증 결과가 아니다.

작업본은 에셋 ID와 원본 경로의 조합별로 `Tools/asset_loader/workspace/mech_plans/`에 저장한다. 원본 옆에 파일을 생성하지 않는다. **저장**은 입력 형식을 검사한 뒤 기록하고, **저장본 불러오기**는 마지막 저장 내용으로 돌아간다. 저장하지 않고 닫아도 같은 실행 중에는 입력을 유지하며, 프로그램 종료 후 복원하려면 저장해야 한다. 손상된 저장본은 현재 편집 내용을 교체하지 않는다. 기존 작업본의 형식과 저장 경로는 유지한다.

현재 모델의 준비 범위는 파지·수납 정지 상태와 부착 위치 전환이다. 연속 발도·수납, 공격·사격·사출·도신 연장, 레이어별 Blender 출력, 게임 합성 및 실행 중 Blender 렌더는 별도 구현이 필요하다. 이 패널에서 설정을 저장해도 위 기능의 구현 완료를 의미하지 않는다.

파일 선택·ID 입력·렌더 설정·애니메이션 조립은 **같은 Pico2D 창 안의 패널**로 열린다. Esc·패널 오른쪽 X·취소는 패널을 닫으며, 파일 선택에서 돌아와도 이전 설정을 유지한다. 창 제목줄의 X와 Alt+F4는 프로그램을 종료한다. 파일 선택은 경로 입력/붙여넣기와 Enter, 목록 더블클릭, 상위 폴더와 휠 이동을 지원한다. 필드 이동은 Tab/Shift+Tab, 전체 선택은 Ctrl+A, 복사/붙여넣기는 Ctrl+C/V다.

## 모델에서 스프라이트까지

렌더 설정의 기본 프레임 크기는 **240×240px**다. 현재 비교용 기준이며 최종 게임 표시 크기는 별도로 조정한다.

**샤프닝은 사전 처리, Bicubic은 표시 시 처리**한다. 새 프리렌더는 본체 시트에 강도 `0.35`의 샤프닝을 적용한다. 제작 패널의 **본체 샤프닝**을 끄면 원래 색상을 보존한다. 원본 프레임·그림자와 프레임 해상도·알파는 유지하며 PNG를 확대 저장하지 않는다. 기존 시트를 열기만 해서는 샤프닝을 새로 적용하지 않는다.

미리보기의 기본 필터는 **GPU Bicubic(Catmull-Rom)**이다. 화면에 그리는 스프라이트 픽셀을 보간하며 게임·독립 테스트의 공통 `PicoAssetResource`와 `PicoSprite`도 같은 경로를 사용한다. 프레임 경계에서 샘플을 제한해 인접 시트 프레임을 섞지 않고 투명 색상의 번짐을 억제한다. HUD·폰트에는 적용하지 않는다.

도구는 [FDrive 공통 실행부·렌더링](../../docs/rendering.md)의 OpenGL 캔버스를 사용한다. 다른 드라이버·SDL dummy에서는 Linear로 대체하며 오른쪽 메뉴에 **실제로 적용한 필터**를 표시한다. Pico2D 원본은 변경하지 않는다. SDL의 기본 `best`는 Bicubic이 아니므로 별도 셰이더를 사용한다. 근거: [SDL 필터 모드](https://wiki.libsdl.org/SDL2/SDL_HINT_RENDER_SCALE_QUALITY), [SDL 텍스처의 OpenGL 연결](https://wiki.libsdl.org/SDL2/SDL_GL_BindTexture), [SDL/외부 렌더 명령 동기화](https://wiki.libsdl.org/SDL2/SDL_RenderFlush).

프리렌더 중에는 하단에 `프리렌더 45% (29/64)`처럼 완료 PNG 수와 비율을 표시한다. 전체 수는 방향 × 프레임 × 본체/그림자 2레이어다. 렌더 후에는 `100% (64/64) · 시트 패킹 중`, 패킹까지 성공하면 `프리렌더 완료 100% (64/64)`로 표시한다. 준비·실패·취소 상태와 완료를 구분하며 Blender 로그에 기록된 실제 완료 수를 사용한다.

기본 광원은 `(-3, -4, 12)`, 광량은 `1400`으로 설정한다. 높이를 올려 그림자를 줄이고 거리 증가에 맞춰 광량을 보정한 비교값이다. 렌더용 작업본에는 도구 조명을 적용하며 원본 `.blend`를 바꾸지 않는다. 원본 장면 조명을 사용할 설정 파일은 `use_scene_lighting: true`로 지정한다.

공통 Pico2D 표시기의 분리 그림자는 기본 **50% 불투명도**로 합성한다. 원본 PNG의 알파는 보존하며 `draw()`/`draw_frame()`의 `shadow_opacity`로 표시 강도를 바꿀 수 있다. 본체와 그림자가 같은 텍스처를 공유해도 그리기 후 알파 상태를 복원한다. 광원 위치는 새 렌더에 적용되고 표시 강도는 기존 시트에도 적용된다.

1. **3D 렌더**에서 저장된 `.blend`를 선택한다. 기존 리그·활성 동작·키프레임을 사용하며 원본은 덮어쓰지 않는다. 모델 루트를 비우면 `ActorRoot`, 없으면 장면의 최상위 모델 계층을 사용한다. 카메라·광원·ShadowCatcher는 필요하면 렌더용 작업본에 생성한다. 모델·동작은 위쪽, 이미지 크기/FPS와 카메라/품질은 항목별로 모아 표시한다.
2. 동작 이름·Blender 프레임 목록·FPS·해상도·정사영 범위·렌더 샘플을 지정한다. **기체·그림자 자동 맞춤**은 기본으로 켜지며 전체 방향·프레임의 변형된 모델 경계와 지면 그림자를 같은 중심·배율에 맞춘다. 지정한 정사영 범위는 필요할 때 확대한다. **모델에 저장된 카메라 사용**을 선택하면 원래 구도를 유지하며 자동 맞춤은 적용하지 않는다. 기본 도형 샘플도 같은 경로로 실행한다. 렌더는 별도 백그라운드 Blender에서 수행하며 완료하면 8방향 본체/그림자 시트를 자동으로 연다.
3. **애니메이션 조립**에서 원본 동작/방향을 고른다. 목록을 드래그해 순서를 바꾸고 Delete로 제외하거나 Ctrl+D로 반복한다. FPS·피봇을 편집하며 본체 재생 미리보기로 확인한다. 피봇 두 칸을 비우면 원본의 프레임별 피봇을 보존한다.
4. 다른 이름으로 **동작 적용**하면 새 동작을 추가한다. 같은 이름은 해당 동작을 편집한다. 번들은 본체·그림자를 항상 함께 수정하고, **모든 방향에 적용**을 켜면 동일한 순서·FPS·피봇을 방향별로 적용한다. 여러 동작을 구성한 뒤 **스프라이트 저장**을 선택한다.
5. 저장한 결과가 미리보기에 열리면 ID를 확인하고 등록한다. 저장 시 선택한 동작을 번들의 기본 방향 대응으로 유지한다. 기존 시트 픽셀을 공유하며 프레임 순서를 JSON에 기록한다. 편집에서 제외한 픽셀까지 시트를 다시 크롭·압축하는 기능은 아니다.

설정은 `Tools/asset_loader/workspace/render_jobs/`, 조립한 완성 에셋은 `data/catalog/prerender/<ID>/<버전>/`, 렌더 중간 결과와 로그는 `output/asset_loader/renders/`에 둔다. 조립 결과는 새 폴더에 이미지와 JSON을 함께 저장하며 입력 파일을 수정하지 않는다. 렌더 실패·취소 시 기존 미리보기를 유지한다.

`SSheetCutil.py`의 v1 JSON·bottom-left 영역·피봇·동작별 FPS 규격과 기존 패킹 경로를 재사용한다. 생성한 JSON을 기존 편집기에서도 읽을 수 있다. 기존 리그 재생은 지원하며 **본 생성·스키닝·리타기팅·3D 동작 편집 UI는 후속 범위**다. 모델의 방향·배율·지면·활성 동작은 원본 장면에서 준비한다.

Blender는 설치 경로 또는 `BLENDER_EXECUTABLE`에서 찾는다. [리그 도형 샘플](../../samples/asset_loader/README.md)로 게임 에셋 없이 확인할 수 있다.

## 지원 규격과 등록

- 일반 이미지: PNG/JPG/BMP. 단일 프레임·아래 중앙 피봇으로 미리보기한다.
- 시트: SSheetCutil v1 JSON의 이미지·동작·FPS·프레임·피봇.
- 번들: 기존 `bundle.json`의 본체/그림자 시트와 방향별 동작. 본체와 그림자의 크기·프레임·FPS·피봇 일치를 검사한다.
- 카탈로그: [샘플 규격](../../samples/asset_loader/catalog.json)의 `version: 1`, `assets` 목록, 항목별 `id`·`kind`·`source`.

등록 목록은 ID·참조 경로를 저장한다. 저장 위치 기준 상대 경로를 사용하며 Windows의 서로 다른 드라이브는 절대 경로로 저장한다. 기본 보관 경로는 `data/catalog/`이며 이 폴더의 목록·이미지·메타데이터를 함께 옮겨야 한다. 목록 JSON 하나만으로 에셋이 패키징되는 것은 아니다.

원본 파일을 손상시킨 상태에서는 마지막 정상 미리보기가 남아 있어도 등록을 거절한다. 외부에서 변경한 카탈로그는 등록 직전에 다시 읽어 보존한다. 샘플 카탈로그는 읽기 전용이다.

## FDrive·Unit Test 공통 사용

재사용 모듈은 `ferrial_drive/assets/`다. 게임은 `Tools`나 테스트 실행부를 import하지 않는다.

본편과 도구는 `ferrial_drive.runtime.run_application()` 또는 `ferrial_drive.rendering.PicoCanvas`를 사용한다. 공통 기본 드라이버는 OpenGL이며 실행부마다 SDL 초기화를 복제하지 않는다. `PicoAssetBackend(filtering='bicubic')`가 기본이며 자원의 `set_filtering()`으로 변경한다. 실제 적용 결과는 `resource.filtering`에서 확인한다.

다수 에셋을 연속으로 그릴 때는 한 자원의 `render_batch()` 문맥 안에서 같은 렌더러의 에셋들을 그려 GL 상태 저장/복원을 묶을 수 있다. 이 문맥 안에서는 SDL UI 그리기·뷰포트/렌더 타깃 변경을 섞지 않는다. 종료 시 SDL 상태를 복원한다. GPU 드라이버와 자원은 렌더러 소유 스레드에서 사용한다.

1. 열린 Pico2D 렌더러에서 `AssetCatalog.load(path)`와 `PicoAssetBackend`로 `AssetManager`를 구성한다.
2. `manager.acquire(asset_id)`로 핸들을 얻는다. 같은 관리자에서 같은 ID를 획득하면 자원을 공유한다. 서로 다른 ID나 서로 다른 관리자는 별도 캐시다.
3. 개체마다 재생 시간·동작을 관리하고 그릴 때 `handle.resource`의 최신 자원을 조회한다. `generation` 변화로 동작·프레임 구성 변경에 대응할 수 있다.
4. 사용이 끝난 핸들은 `close()`한다. 마지막 핸들이 닫히면 자원을 해제한다. 관리자 종료는 모든 소유 자원을 해제하며 렌더러를 닫기 전에 수행한다.
5. 개발 실행에서만 `debug=True`로 구성하고 프레임 갱신에서 `poll_reload()`를 호출한다. 기본 폴링 간격은 0.4초다.

핫 로드는 카탈로그·메타데이터·참조 이미지를 감지한다. 새 자원을 완전히 검증·로딩한 뒤 교체하고 이전 자원을 해제한다. 실패하면 정상 자원을 유지하고 디버그 다음 폴링에서 복구를 다시 시도한다. 사용 중인 ID가 카탈로그에서 삭제되면 기존 핸들은 해제 전까지 유지하며 신규 획득은 거절한다.

파일 처리와 GPU 교체는 **렌더러 소유 스레드에서 동기적으로 실행**한다. 작업 스레드·비동기 스트리밍 로더가 아니다. 일반 실행의 `debug=False`에서는 자동 파일 조회·핫 로드를 하지 않는다.

도구에서 편집 패널이 열려 있는 동안에는 미리보기 자원을 유지하고 자동 핫 로드 폴링을 잠시 보류한다. 패널을 닫으면 변경 감지를 재개한다.

## 선택적 계측·화면 검증

```text
python Tools/asset_loader/run.py --debug --profile output/performance/asset-loader.json
python Tools/asset_loader/run.py --frames 3 --capture output/asset_loader_review/tool.png
```

기존 TimingRecorder를 선택적으로 연결한다. `assets.metadata`와 `assets.texture_load`, 화면 표시·프레임 대기를 기록한다. GPU 실행시간·전체 메모리 실측과 구분한다.

## 확인 상태

- 에셋 자동 검사 **84개 통과**: 기존 로더/패킹/도구 경로와 사전 샤프닝·필터 메뉴를 포함한다. 이 중 **6개는 실제 OpenGL GPU**에서 원래 배율·Bicubic 확대·투명 경계/인접 프레임·클리핑·렌더 타깃·SDL 상태 복원을 확인했다. `FDRIVE_GPU_TESTS=1`을 지정하지 않으면 GPU 6개는 건너뛴다.
- 기존 실제 모델 프레임을 재패킹해 본체 샤프닝·240px/원본 보존·OpenGL 미리보기의 Bicubic 적용을 확인했다. 이번 검사는 Blender 재렌더나 목표 Iris 기기의 60FPS 달성 검증은 아니다.
- 단일 본·스키닝·키프레임이 있는 기본 도형의 실제 Blender 8방향 × 2프레임 × 본체/그림자 렌더·시트 패킹·순서 조립·Pico2D 로딩을 확인했다. 원본 .blend 해시 보존과 키프레임에 따른 이미지 변화도 검사했다.
- 실제 모델의 8방향 × 4프레임 × 본체/그림자 64장도 자동 맞춤으로 렌더·패킹했다. 픽셀 경계 검사는 유지하며 잘린 본체·그림자는 계속 거절한다.
- SDL dummy로 실제 도형 이미지·시트·번들 로딩, 합성 키 입력·등록 저장/재로딩과 툴 화면을 확인했다.
- 패널의 Esc/닫기·창 종료 이벤트·Alt+F4·UTF-8 입력·IME 조합 전달·프레임 드래그/반복/저장을 자동 검사했다. 실제 Windows 창에서 렌더·파일 패널 표시와 닫기 버튼을 확인했고 사용자가 실행 성공을 확인했다. 전체 입력 방식의 사용감·대형 게임 에셋과 낮은 사양 기기의 성능 검증은 별도다.
