# 대화 기록

프로젝트의 Markdown 요약을 대화형 화면으로 읽고 누락 필드를 보완한다. **원문 찾기**에서 선택한 Codex 프로젝트의 로컬 공개 발언과 기록 시각을 읽는다. Codex 원본은 변경하지 않으며 게임 코드를 실행하지 않는다. 프로젝트 루트의 **대화 기록.lnk**에서 연다. 링크 위치나 작업 폴더와 관계없이 프로젝트 `docs/ai-dev-log/`를 연다.

## 사용

- 왼쪽: 검색, 전체/누락 필터, 기록 선택. 날짜가 같으면 확인한 사용자 발언 시각으로 정렬한다.
- 가운데: 사용자·AI·기록 필터, 읽기용 Markdown 요약, 이전 형식 기록 열람. **요약을 실제 원문 발언처럼 재구성한 화면이 아니다.** `요약 · 원문 연결`과 `사용자 보완`을 구분한다.
- 일곱 항목은 큰 헤딩으로 나누며, 첫 네 항목은 **사용자 제안 → AI가 수용한 사용자 제안 → AI 제안 → 사용자가 수용한 AI 제안** 순서다. 과거 기록도 헤딩 의미를 기준으로 이 순서로 읽는다.
- 굵은 글씨·인라인 코드·기록 ID를 강조하고 HTML 내부 주석은 숨긴다. `scope`는 **대화 전체**, `U1-U3`는 **사용자 제안 1~3**, `A1`은 **AI 제안 1**처럼 표시한다. 원래 Markdown과 누락 태그 ID는 유지한다.
- 같은 대상의 시각·출처를 **동일한 Codex 발언과 시각**으로 보완한 경우 상단 요약을 **연결된 원문 근거** 하나로 묶는다. 시각·대화·원문을 보여주고, 별도로 작성한 보완 내용은 함께 남긴다. 근거나 시각이 다르거나 아직 미확인인 항목은 합치지 않는다. 원래 보완 기록과 저장·취소 단위는 유지한다.
- 오른쪽: 누락 필드 선택 → **사용자 회고**로 직접 보완하거나 상단 **원문 찾기**에서 근거 가져오기 → 내용 확인 → 적용. 수동 원문 확인 버튼은 제거했으며, 과거 원문 확인 기록·임시 입력은 보존한다.
- 누락 필드를 클릭하면 가운데 필터를 전체 요약으로 바꾸고 해당 태그로 이동한다. 머리말의 누락도 기록 정보 말풍선에 표시한다. 모든 누락은 강조색·밑줄, 선택한 누락은 밝은 배경으로 구분하며 줄바꿈돼도 같은 필드로 추적한다. 오른쪽의 중복 설명 대신 보완 입력칸을 넓혔다.
- **원문 찾기**: 상단의 **보완할 내용·선택한 기록·관련 제안** 확인 → 프로젝트 선택 → 검색 구절 입력 → 발언과 한국 기록 시각 확인 → **선택 근거 가져오기** 순서다. 상단 대상 설명이 길면 그 영역에서 휠로 읽는다. 기록에 명시된 검색 구절이 있으면 초깃값으로 넣는다. 기본 프로젝트는 Ferrial Drive다. 채팅별 검색과 사용자/AI 필터를 지원한다.
- 가져오기는 보완 초안의 근거·시각을 채운다. 기존 보완 내용은 유지하고 근거는 길이 한도 내에서 합친다. **기존 적용 버튼을 눌러야 Markdown과 누락 인덱스를 저장**한다. 의미 연결은 사용자가 확인하며, 선택 전후 원문이 바뀌면 가져오기를 차단한다.
- 여러 발언을 묶은 항목은 첫 발언의 **범위 시작 선택** → 마지막 발언의 **선택 근거 가져오기**로 시간 범위를 가져온다. 시작 선택 버튼을 다시 누르면 해제한다.
- 다른 프로젝트·미소속 관련 채팅은 UUID 형식의 **채팅 ID**로 직접 추가한다. 같은 ID의 **추가 해제**로 제외한다. 추가 범위는 선택 프로젝트별로 보관한다. 작업 폴더가 같다는 이유로 다른 프로젝트를 포함하지 않는다.
- 화면과 가져온 근거에는 한국 시각만 표시한다. 기존 기록에 단독 UTC가 있으면 한국 시각으로 변환해 읽는다. **결과 JSON 저장**은 원래 시각과 UTC/KST 식별 정보를 `workspace/exports/`에 보존한다. 원문 전체 내보내기는 빈 검색으로 원하는 채팅을 고른 뒤 실행한다. 숨겨진 추론·도구 출력은 포함하지 않는다.
- 기록 시각은 원문 레코드에 저장된 시각이다. 시각이 없거나 시간대가 불명확하면 미상으로 표시한다. 턴 시작·종료나 파일 수정 시각으로 보충하지 않는다. 시각 없는 발언을 TIME 항목에 가져오지는 못한다.
- 시각 입력은 날짜, 분·초·소수 초(최대 6자리), `시작 ~ 끝` 범위를 지원한다. 날짜만 입력하면 자정 시각을 만들어 넣지 않는다. [작성 예와 확인 범위](../../docs/tool-usage/conversation_log_evidence.md)를 따른다.
- `적용`은 선택한 누락 하나를 보완하고 Markdown·MISSING_INDEX.md를 함께 갱신한다. 원기록 영역은 보존한다. 입력 출처·보완 시각·당시 시각을 따로 남긴다.
- `마지막 보완 취소`는 선택 기록의 마지막 보완을 취소한다. 다른 기록의 보완은 유지하고 인덱스를 현재 상태로 다시 만든다. 프로그램을 다시 열어도 이력을 이용한다.
- 휠은 포인터가 있는 목록/대화/누락 목록을 스크롤한다. F5는 새로고침, Tab은 입력창 이동, Ctrl+Enter는 적용이다. Ctrl+A/C/X/V와 방향키·Home/End·Backspace/Delete를 지원한다.

입력은 적용 전까지 문서를 바꾸지 않는다. 기록/필드를 옮겨도 임시 입력을 유지하고 종료 시 로컬 workspace/drafts.json에 보관한다. 외부에서 바뀐 파일은 덮어쓰지 않고 새로고침을 요청한다. 저장/되돌리기 이력은 `workspace/history/`에만 두며 Git에 올리지 않는다. 원문 검색 설정은 기록 위치별 `workspace/codex_sources_*.json`에 둔다. Markdown의 보완 내용은 프로젝트 문서에 남지만 로컬 원문 경로는 가져온 근거에 포함하지 않는다.

## Codex 원문 접근 범위

이 버전은 **로컬 저장 형식의 읽기 전용 어댑터**다. `CODEX_HOME` 또는 기본 Codex 폴더의 프로젝트 소속 정보·채팅 제목 인덱스·sessions/archived_sessions 기록을 읽는다. 공식 App Server 연동은 구현하지 않았다. 데스크톱 저장 형식이 바뀌면 프로젝트 목록 읽기가 실패할 수 있으며, 오류를 표시하고 채팅 ID 직접 추가를 지원한다. 원문 자체가 로컬에 없으면 시각을 복원할 수 없다. 원격 호스트의 기록을 자동으로 가져오지는 않는다.

`--codex-home 경로`와 `--codex-project 이름`으로 기록 위치·기본 프로젝트를 지정한다. `--demo`는 [가짜 Codex 원문 샘플](../../samples/conversation_log_viewer/README.md)을 사용하며 실제 계정 기록을 읽지 않는다. `--source-query 구절`은 원문 검색 화면에서 시작하는 확인용 옵션이다.

## 실행 환경

Python 3.11 이상·Pico2D 1.5.1과 기존 SDL 환경을 사용한다. 이번 도구에 새 패키지는 추가하지 않는다. 창·기본 이벤트는 기존 실행기 어댑터를 재사용하며 실행기 GUI나 게임 모듈을 import하지 않는다. 같은 프로젝트의 `theme_reference/`, `unit_test_runner/` 공통 모듈이 필요하다.

```text
python Tools/conversation_log_viewer/run.py
python Tools/conversation_log_viewer/create_launcher.py
python Tools/conversation_log_viewer/run.py --demo
```

`--demo`는 공개 샘플을 `workspace/demo_logs/`로 한 번 복사한다. 원본 샘플과 실제 개발 로그는 수정하지 않는다. `--logs`와 `--workspace`로 별도 로그/로컬 이력 폴더를 지정할 수도 있다.

`--frames N`·`--screenshot 경로`·`--select 파일명`은 자동 실행/렌더링 확인용이다. 실제 실행 화면과 검증 결과는 [개발 기록](../../docs/ai-dev-log/README.md)에 구분한다.

## 테마

[공통 기준](../../docs/theme_reference.md)의 JSON을 Unit Test Runner와 함께 읽는다. 제목은 Cafe24 써라운드 일반형, 본문·보조 문구는 에스코어 드림 Regular다. 폰트 파일은 프로젝트 공개 OTF를 읽고, 툴만 복사한 경우에는 Pico2D 기본 폰트를 사용한다.
