# 독립 Unit Test 실행기

Runner는 **폴더·.py 탐색·파일 선택·별도 테스트 실행·종료·상태·오류 표시**를 담당한다. 테스트의 게임 코드·UI·폰트·렌더링 모듈은 Runner GUI 프로세스에 import하지 않는다. 목록에서 실행하거나 GUI에 드롭하면 테스트가 별도 창으로 열린다.

## 실행

Python 3.11 이상과 `requirements.txt`의 Pico2D 1.5.1 환경에서 실행한다.

색상·글꼴의 실제 값은 형제 폴더 [theme_reference/theme.json](../theme_reference/theme.json)에서 읽고 `theme.py`가 Runner 역할에 연결한다. [공통 테마 기준](../../docs/theme_reference.md)을 따른다. 실행기를 별도로 복사할 때는 `unit_test_runner/`와 `theme_reference/`를 같은 부모 폴더에 함께 둔다.

```text
python Tools/unit_test_runner/run.py
```

처음에는 프로젝트 `tests/` 폴더를 표시한다. **폴더와 `.py` 파일만** 표시하며 폴더를 먼저 정렬한다. 현재 폴더만 읽고 하위 폴더를 미리 재귀 탐색하지 않는다.

목록 첫 항목 `..`는 상위 폴더로 이동한다. 드라이브 루트에서는 표시하지 않으며 항목 수 집계에서도 제외한다. 각 행에는 구분선을, 이름/실행 상태 열 사이에는 세로 구분선을 표시한다. 제목·경로 / 파일 목록 / 선택 정보 / 실행 상태는 별도 패널로 나눈다. 상단 도구 버튼은 표시하지 않는다. 색상은 `theme.py`에서 관리하며 Ferrial Drive의 스틸 블루 `#91AEBB`·Bezel 근사색 `#39444A`·텍스트 `#D8E6ED`를 적용한다. 게임 코드나 UI 샘플 설정 파일에 런타임으로 의존하지 않는다.

글꼴도 `theme.py`에서 역할별로 지정한다. 실행기/소개 제목은 굵기가 더 있는 Cafe24 써라운드 일반형 20px, 목록·파일명·경로·소개·실행 상태·오류는 에스코어 드림 Regular 18px다. 시스템 설치 없이 프로젝트 `data/fonts/`의 원본 OTF를 읽고 역할별 글꼴로 너비와 말줄임을 계산한다. 텍스트 좌표는 행의 세로 중앙을 기준으로 하며 Pico2D의 중앙 정렬에 추가 크기 보정을 적용하지 않는다. 경로는 글꼴의 원화 기호 혼동을 피하도록 `/`로 표시한다. 툴 폴더만 별도로 복사해 해당 폰트가 없으면 기존 Pico2D 기본 글꼴로 대체한다.

- 한 번 클릭: 선택과 실행 불가 사유 확인.
- 두 번 클릭 또는 Enter: 폴더 열기 또는 실행 가능한 테스트 시작.
- `..` 더블클릭/Enter 또는 Backspace: 상위 폴더 이동.
- 마우스 휠·위/아래·PageUp/PageDown: 목록 탐색.
- F5: 파일 추가·수정과 실행 가능 여부 갱신.

문법 검사 후 최상위 `UNIT_TEST_ENTRYPOINT = "standalone"` 선언 또는 필수 인자 없는 일반 `create_test()` 정의를 확인한다. 실행할 수 없는 파일도 선택할 수 있지만 흐리게 표시하고 실행을 차단한다. 동적 생성·외부 import로만 제공하는 진입점은 자동 판별하지 않는다. **실행 가능 표시는 진입 규약 확인 결과**이며, 라이브러리 누락·리소스 오류·반환값 등 실제 실행 오류는 별도 테스트 프로세스의 오류로 표시한다.

기존처럼 열린 **Runner GUI 창**에 테스트 `.py` 하나를 드롭해 바로 실행할 수도 있다. 테스트 창은 파일을 받는 실행기 창과 구분한다. 같은 파일을 다시 실행·드롭하면 이전 테스트를 종료하고 새 프로세스에서 다시 실행한다. UI 모듈·설정 변경은 재실행으로 반영한다. 실행 직전에도 소스를 다시 판별하므로 목록 표시 이후 생긴 오류는 기존 테스트를 종료하기 전에 거절한다.

- 테스트 창 X·테스트 자체 종료: 해당 테스트만 종료하고 Runner를 앞으로 올린다. 오류 종료에도 동일하게 복귀한다. 실행 중 매 프레임 창을 올리거나 항상 위에 고정하지 않는다.
- Runner 창 X: Runner가 시작한 테스트를 종료하고 실행기도 닫는다.
- 여러 파일·없는 파일·구문 오류: 오류를 표시하고 기존 테스트는 유지한다.
- 새 테스트 시작·실행 실패: 종료 코드와 오류 출력 끝부분을 표시하고 다음 드롭을 받는다.

현재 구조 변경을 처음 적용할 때는 기존 Runner를 한 번 완전히 닫고 다시 연다. 이후 UI 테스트 코드를 바꿀 때 Runner 전체를 다시 켤 필요 없이 재드롭하는 구조다. 실제 동작은 사용자 확인 전이다.

파일 인자 실행도 별도 프로세스를 사용한다.

```text
python Tools/unit_test_runner/run.py tests/ui_test.py
python Tools/unit_test_runner/run.py samples/unit_test_runner/basic_flow.py
```

`--frames N`은 제한 프레임 실행용이다. GUI에서는 Runner 프레임을 제한하며, 파일 인자 실행에서는 테스트에 제한값을 전달한다.

## 새 독립 테스트

파일 맨 위에 모듈 docstring으로 **제목과 짧은 소개**를 작성한다. 첫 줄은 제목, 빈 줄 뒤 나머지는 소개다. Runner에서 파일을 선택하면 제목·소개 최대 두 줄·실행 상태/사유를 표시한다. 긴 소개는 말줄임한다. 설명이 없는 기존 파일은 파일명과 `등록된 소개 없음`을 표시하며 실행 가능 여부는 바뀌지 않는다. 문법 오류로 소스를 읽을 수 없으면 파일명과 문법 오류 사유를 표시한다.

```python
"""메뉴·전투 HUD

타이틀부터 전투까지 이어지는 화면 흐름과 정보의 가독성을 확인한다.
체력·피격·레이더·무장 전환을 샘플 상태로 살펴본다.
"""
```

소개는 소스의 AST에서 읽으며 테스트를 import하거나 실행하지 않는다. `tests/ui_test.py`와 기본 화면 전환 샘플에 적용했다. 수정 후 Runner에서 F5로 새로고침하면 소개를 다시 읽는다.

새 테스트는 일반 Python 프로그램으로 직접 실행할 수 있어야 한다. Runner를 import하거나 TestProgram을 상속하지 않는다. 최상위에 리터럴 메타데이터 `UNIT_TEST_ENTRYPOINT = "standalone"`을 선언하고 `__main__`에서 자체 실행을 시작한다. `--frames`를 쓰려면 해당 인자를 지원한다.

Runner는 소스 구문·메타데이터를 AST로 확인한 뒤 현재 Python 환경으로 파일을 실행한다. 파일 경로는 인자 목록으로 전달하며 shell을 사용하지 않는다. 작업 폴더는 선택 파일의 부모 폴더이므로 데이터·에셋은 파일 위치 기준 경로를 사용한다.

`tests/ui_test.py`가 이 방식이다. `python tests/ui_test.py`는 `Tools/unit_test_runner` 없이 동작하는 코드 경로이며, 자체 Pico2D 루프는 `ferrial_drive/ui/standalone.py`에 있다. 프로젝트 UI 모듈·설정·폰트·Pico2D는 여전히 필요하다. UI 모듈 import만으로 창·루프를 시작하지 않는다.

## 기존 create_test 호환

메타데이터가 없거나 `legacy`인 기존 파일은 부모에서 `create_test()` 정의를 확인한 뒤 새 자식 프로세스의 `worker.py`에서만 실행한다. 기존 `TestProgram`·`WindowSpec`·`Stop`·`SwitchTo`·`create_test()` 규약은 이 경로에서 유지한다. 새 UI 테스트는 이 규약을 사용하지 않는다.

| 기존 요소 | 역할 |
| --- | --- |
| `create_test()` | TestProgram 인스턴스 반환 |
| `WINDOW` | 선택적인 WindowSpec |
| `enter()` | 자식 창 생성 뒤 리소스 준비 |
| `handle_event(event)` | 자식 창의 입력 해석 |
| `update(delta_seconds)` | 초 단위 상태·시간 갱신 |
| `draw()` | 배경부터 테스트 화면 전체 그리기 |
| `exit()` | 정상 종료·장면 교체 시 정리 |

기존 샘플의 SwitchTo는 **자식 테스트 창 안에서** 장면을 바꾼다. Stop과 자식 창 X는 테스트만 종료하며 Runner GUI는 유지한다. 호환 코드는 `interface.py`·`loader.py`·`runner.py`에 두고, GUI는 TestHost나 테스트 렌더러를 사용하지 않는다.

## 다시 실행과 정리

매 실행은 새 프로세스·새 모듈 상태를 사용한다. 바이트코드 캐시도 실행별 탐색 경로로 분리하고 쓰기를 막으므로 예전 보조 모듈 pyc를 재사용하지 않는다. 기존 프로세스 안에서 importlib.reload로 섞어 갱신하지 않는다.

교체·Runner 종료는 소유한 직접 자식 프로세스를 종료하고 기다린다. 필요하면 강제 종료해 운영체제가 자식 창·렌더러·폰트 등 프로세스 자원을 회수한다. **교체·강제 종료에서는 테스트의 Python exit 콜백은 보장하지 않는다.** 저장이 필요한 테스트는 자체 저장·종료 경로를 제공해야 한다. 이 UI 테스트는 샘플 원본을 실행 중 수정하지 않는다.

이 분리는 OS 보안 격리가 아니다. 테스트가 따로 만든 손자 프로세스까지 종료하는 기능은 제공하지 않는다. 자식 stdout/stderr는 GUI 경로에서 임시 파일로 받고 오류 끝부분만 읽어 파이프 대기로 멈추는 문제를 피한다.

## 바로가기와 샘플

기존 바로가기 경로·대상 스크립트는 유지한다. Python 환경이 바뀌거나 바로가기를 새로 만들 때 다음 명령을 사용한다.

```text
python Tools/unit_test_runner/create_launcher.py
```

프로젝트 루트의 `Unit Test Runner.lnk`를 더블클릭하면 GUI가 열린다. 바로가기 생성 기본 위치도 프로젝트 루트다. 탐색 시작 폴더는 링크 위치·현재 작업 폴더와 관계없이 프로젝트 `tests/`다. 테스트 파일은 **열린 Runner GUI에** 드롭할 수도 있다. 생성한 바로가기에는 로컬 Python 경로가 들어가므로 Git에서 제외한다.

- [메뉴·전투 HUD](../../samples/ui_unit_test/README.md): Runner에 의존하지 않는 새 독립 진입점.
- [기존 두 화면 샘플](../../samples/unit_test_runner/README.md): create_test 호환 경로.
- [자동 검사 준비 파일](../../tests/automated/README.md): 실행 경계·교체·캐시·오류 정리 검사.
