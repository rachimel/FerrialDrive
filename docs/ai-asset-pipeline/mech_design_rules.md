# Ferrial Drive 메카 디자인·제작 규칙

## 1. 적용 범위와 근거

이 문서는 Ferrial Drive의 메카를 설계·조형·리깅하고 프리렌더 에셋으로 제작할 때 적용한다. 사용자가 지정한 밀리터리·산업용 병기의 실용적 구조를 상위 방향으로 삼는다. 제작 명령과 독립 검사 사용법은 [모델 제작 흐름](model_workflow.md), 게임 출력은 [Blender 에셋 경로](blender_pipeline.md)를 따른다.

디자인 분석의 기준은 로컬 `data/models/player_mech/player_mech.blend`와 `release_v1.json`이다. v078에서 출발한 **1차 최종 플레이어 모델**이며 이후 수정본은 해시로 구분한다. 이 모델의 외형·색·치수·본 개수를 모든 후속 기체의 규격으로 강제하지 않는다. 임무와 운용 방식에 따른 기체별 차이를 허용한다.

아래에서 **관찰**은 기준 모델에서 확인한 특징, **규칙**은 앞으로 준수할 제작 기준, **미검증**은 아직 보증하지 못한 상태를 뜻한다. 제작 규칙의 존재가 현재 모델의 전 항목 통과를 의미하지 않는다. 세계관의 장치 역할은 [메카·군사 기술 설정](../FerrialDrive_Mech_Worldbuilding.md)을 참조하고 후보 설정을 확정 기능으로 전환하지 않는다.

## 2. 기준 모델의 조형 분석

| 관찰한 특징 | 채택할 조형 원리 | 일반화하지 않을 것 |
| --- | --- | --- |
| 넓게 펼쳐진 어깨, 압축된 몸통, 좁은 허리, 긴 하체와 큰 발 | 큰 덩어리의 대비로 역할과 하중 지지 방향을 읽게 한다. 어깨·몸통·골반·다리를 먼저 구분한다. | 현재의 어깨 폭, 다리 길이, 날개형 어깨 자체를 공통 비율로 고정하지 않는다. |
| 몸통·팔·다리의 넓은 장갑면, 절제된 모서리와 단차 | 주 장갑면을 보존하고 두께·겹침·분리 방향으로 구조를 표현한다. | 불필요한 굴곡, 비평면 면의 음영 깨짐, 둥글게 부푼 스커트를 양식으로 삼지 않는다. |
| 어두운 관절, 링 형태의 연결부, 외피와 내부 기구의 명도 차 | 회전 중심과 장갑이 움직일 여유를 읽게 한다. 원형은 회전·결합부에, 넓은 면은 보호 외피에 사용한다. | 모든 연결부를 링으로 만들거나 겹친 메시를 기계적 결합으로 간주하지 않는다. |
| 분할된 스커트, 옆구리의 접이식 무장 고리, 후방 리액터·지지 구조 | 외부 장치에는 장착점·지지 경로·가동 방향을 부여한다. 장치가 주요 실루엣과 구별되게 한다. | 현재 고리 크기·장착 좌표나 장치 개수를 모든 기체의 표준으로 고정하지 않는다. |
| 회색 외피와 어두운 내부, 가는 청색 에너지 경로·홈 발광 | 보호 외피, 기구, 에너지 상태의 시각적 역할을 분리한다. 에너지 표현은 공급·연결·사용 지점과 연관시킨다. | 모든 기체의 색상을 회색/청색으로 강제하거나 발광선을 임의의 회로 장식으로 늘리지 않는다. |
| 패널별 도장 차이와 국소 마모, 큰 면에 비해 적은 미세 장식 | 작은 디테일은 정비·접촉·분리 경계의 설명을 돕는다. 실제 출력 크기에서 읽히는 정보에 우선순위를 둔다. | 구버전 통풍구 텍스처, 반복 볼트, 임의 파이프를 고유 디자인 언어로 취급하지 않는다. |

정리하면 **보호하는 큰 외피 → 움직이는 연결부 → 기능을 전달하는 장치 → 제한된 표면 정보**의 순서로 읽히게 한다. 플레이어 기체의 독특한 실루엣은 보존하되 후속 기체는 같은 구조적 설득력을 서로 다른 비율과 장치 구성으로 표현할 수 있다.

## 3. 디자인 언어

### 큰 형상과 비율

- 실루엣, 장갑 덩어리의 비율, 관절과 기계적 연결 구조를 먼저 결정한다. 미세 패널과 마모로 큰 형상의 문제를 가리지 않는다.
- 기체별 역할, 보호해야 할 부위, 관절 위치, 무장 운용을 기준으로 덩어리를 배치한다. 승인된 주요 실루엣과 디자인을 수정 요청 밖에서 임의로 바꾸지 않는다.
- 큰 장갑면에는 시각적 여백을 남긴다. 모서리·단차·틈은 조립 방향, 덮개 두께, 가동 경계를 설명해야 한다.
- 기존 모델의 수치를 복사하는 대신 정면·측면·후면·사선과 게임 표시 크기에서 덩어리 관계를 비교한다. 실제 미터 크기·공통 체형 비율은 현재 미확정이다.

### 기능성 디테일

- 부품을 추가하기 전에 보호, 하중 전달, 회전/슬라이드, 장착, 정비 접근, 냉각, 에너지 전달 중 어떤 역할인지 설명한다. 근거가 없으면 추가하지 않는다.
- 반복 패널·구멍·볼트·그릴로 빈 면을 채우지 않는다. 냉각부는 해당 열원과 배출 방향을 설명할 수 있을 때만 사용한다.
- 외부 배관은 연결할 두 장치와 가동 여유가 있어야 한다. 승인 없이 가슴 배선을 되살리지 않는다. 패널 경계와 마모를 배관으로 대체하지 않는다.
- 에너지 경로는 공급원에서 사용 지점으로 이어지는 간결한 방향성을 우선한다. 불필요한 분기와 회로판 같은 굴곡을 피한다. 모든 경로를 외부에 노출할 필요는 없다.
- 발광을 넣을 위치가 패널 표면인지, 홈 바닥인지, 외피와 패널 사이의 틈인지 구분한다. 기준 모델의 다리 발광은 이 구분의 사례이지 모든 기체의 의무 장식이 아니다.
- 실제 깊이·윤곽·가동 간격이 필요한 곳은 메시로 만든다. 작은 패널 구분, 도장 차이, 국소 마모는 텍스처로 표현할 수 있다. 마모는 접촉·마찰·정비 지점에 집중한다.

## 4. 모델링과 데이터 구조

### 메시·음영

- 변형에 필요한 부위와 강체 장갑을 구분한다. 강체 부품은 모양을 유지하고 관절 사이의 벨로즈 등만 의도적으로 변형한다.
- 중복 정점, 면적 0 면, 잘못된 노멀, 의도하지 않은 내부 면·자가 교차를 검사한다. 열린 면과 겹침은 부품 의도를 확인한 뒤 처리한다. 전체 메시를 일괄 용접하거나 평탄화하지 않는다.
- 큰 장갑면의 비평면 여부와 삼각분할 후 음영을 확인한다. smooth, bevel, weighted normal로 실제 형상 오류를 숨기지 않는다. 자동 삼각분할 자체를 형상 교정으로 간주하지 않는다.
- Shape Key가 있는 형상은 Basis만 수정하지 않는다. 관련 키, Boolean 커터, 부착 디테일도 같은 좌표 변환과 의도된 변형을 따라야 한다.
- 형상 수정 전후 재질 슬롯·UV·웨이트·모디파이어 순서가 보존되는지 확인한다. 폴리곤·오브젝트 예산은 아직 공통 수치로 확정하지 않는다.

### 좌표·계층·장착

- 에셋 루트, 전방/상방 축, 단위, 리그와 장치의 부모를 명시한다. 현재 플레이어는 `ActorRoot`, `PlayerRigidRig`, +X 전방/+Z 상방이다. 새 모델은 자신의 축을 명시하고 출력 경로와 맞춘다.
- 변환은 어느 좌표계에서 적용했는지 기록한다. 월드·루트·오브젝트·본 로컬 좌표를 혼용하지 않는다. 리깅된 모델에 무조건 Apply Transform을 실행하지 않는다.
- 가시 부품, 가동 제어, Boolean 커터와 장착용 숨김 메시의 책임을 분리한다. 숨겨졌다는 이유만으로 삭제하지 않는다. 드라이버·모디파이어·정점 부모·장착 참조를 먼저 조사한다.
- 무장 마운트는 위치뿐 아니라 기준축, 회전 방향, 부모, 장착 무기의 피봇, 손잡이 위치와 인출 방향을 계약으로 관리한다. 연결된 무기가 없으면 호환성은 미검증이다.
- 몸통·골반·팔다리 비율을 바꿀 때 고리/소켓, 손의 도달 범위, 장착 무기의 본체 간섭, 수납·인출 경로를 다시 확인한다. 이전 검사 결과를 재사용하지 않는다.
- VERTEX_3 부모의 평가 프레임과 AXIS_ANGLE 축은 보존한다. 행렬만 재설정해 0도 회전축을 잃지 않도록 한다. 저장·재로딩·프레임 변경 후 위치를 재검증한다.

### UV·텍스처·재질

- 현재 플레이어의 제작 기준은 1K이며, 다리·스커트·허리는 개별 아틀라스 구분을 유지한다. 새 에셋의 개수와 해상도는 사용 크기와 용량에 맞춰 정하고 이 구성을 무조건 복제하지 않는다.
- 깨짐이 보이면 해상도 증가보다 UV 면적, 왜곡, 아일랜드 경계, 패딩, 밀도, 텍스처 보간과 노멀을 먼저 확인한다. 0~1 범위 통과만으로 UV 품질을 승인하지 않는다.
- 공통 면에서 해상도가 급변하지 않게 밀도를 검토한다. 정확한 texel density와 패딩 수치는 출력 조건에 맞춰 결정하며 아직 공통 고정값은 없다.
- 의도된 대칭 UV 공유와 고유 마모·문양이 필요한 UV를 구분한다. 재패킹 시 기존 도장과 패널 경계의 대응을 비교한다.
- BaseColor는 sRGB, Roughness/Metallic/Height/Normal/Mask는 Non-Color 사용과 실제 노드 연결을 확인한다. 노멀 입력에는 올바른 변환 노드를 사용한다.
- 에너지 색·세기·레벨은 공통 제어에 연결한다. 장치별로 발광색을 임의 하드코딩하지 않는다.
- 패킹 및 외부 참조를 확인하고 원본 텍스처 보존과 `.blend` 자체의 독립성을 구분한다. Material Preview는 참고이며 최종 조명·색 관리·렌더 크기로 확인한다.

## 5. 리깅·애니메이션

- 관절 중심은 실제 연결부와 맞춘다. 본의 head/tail, roll, 부모·연결 여부와 강체 웨이트를 함께 확인한다. 좌우 숫자의 부호만 같게 하는 것으로 방향 일치를 보증하지 않는다.
- Rest Pose, Pose 값, Action, Constraint, Driver가 적용된 평가 결과를 따로 확인한다. 기본 본 방향을 바꾸면 기존 회피 제어축·회전 공간·혼합 순서도 재검토한다.
- 기본 자세는 좌우 대칭을 기준으로 검사하되 사용자가 승인한 비대칭 장치·자세는 유지한다. 화면 좌우와 모델 L/R을 명시한다. 본의 roll은 단순 복사하거나 음수 스케일로 반전하지 않는다.
- 관절과 장갑의 작동 범위는 기체별로 정한다. 현재 고리 제어의 -90/0/+90 수납 값은 장치 설정이지 다른 관절의 허용 각도가 아니다.
- 중립 자세, 양 끝 가동 자세, 중간 표본을 검사한다. 손/무기, 고리/팔, 고리/몸체, 스커트/다리, 볼/소켓 내부 여유를 서로 다른 항목으로 다룬다.
- 애니메이션은 발 접지, 무게 이동, 무장 파지, 인출·수납 시점과 가동 장치의 추종을 확인한다. 빠른 동작은 정지 표본만으로 연속 충돌이 없다고 판정하지 않는다.
- Action과 이벤트·출력 프레임/FPS는 에셋별 설정으로 관리한다. 게임은 제작 리그 대신 출력 이미지와 메타데이터를 읽는다. 현재 모델의 전투 모션 전체 및 무기 장착 호환성은 미검증이다.

## 6. 변경·검증·출력

| 단계 | 남길 근거 | 통과가 뜻하지 않는 것 |
| --- | --- | --- |
| 수정 전 | 소스 경로/해시, 요청 범위, 유지할 실루엣, 인접 부품·장착 의존성, 같은 구도의 기준 화면 | 구버전 이름만으로 동일 소스 보증 |
| 수정 후 구조 | 변경 객체/본, UV·재질·웨이트·키·계층 변화, 제약/드라이버의 평가 결과 | 객체 지문만으로 노드·모디파이어·Action 전체 동등성 보증 |
| 독립 검사 | 형상, UV, 이미지, 간섭을 각각 실행한 설정·대상·결과 | 한 검사 통과를 전체 품질 통과로 확대 |
| 외형 | 저장·재로딩 후 같은 카메라/조명의 정면·후면·측면 또는 사선, 국소 확대, 게임 표시 크기 | Material Preview만으로 최종 외형 확정 |
| 가동 | 실제 사용할 장치 상태·자세, 극값/중간 표본, 무장과 인접 장갑 | 표면 교차 0으로 내부 포함·최소 간격·모든 모션 보증 |
| 게임 에셋 | 공통 카메라/배율, 8방향, 본체/그림자 기준점, 패킹·로더 재생 확인 | 모델 승인을 게임 출력 승인으로 간주 |

기존 기준 소스는 새 후보에서 수정하는 것을 기본으로 한다. 사용자가 기존 파일의 직접 수정을 명시하면 임시 후보로 검사한 뒤 요청한 파일에 반영하고 기준 해시·레지스트리를 동기화한다. 백업·임시 스크립트·검토 출력은 요청한 파일 수와 보존 범위에 맞춰 정리한다. 매 버전마다 영구 Python 파일을 추가하지 않는다.

실패 항목은 신규 문제와 기존 문제로 구분해 기록한다. 기존 문제라는 이유로 통과 처리하지 않으며, 요청 범위를 벗어난 재조형을 자동 실행하지 않는다. 사용자 외관 승인, 구조 검사, 가동 검사, 게임 재생 완료는 각각 별도 상태로 남긴다.

## 7. 현재 기준의 한계

- 기준 모델은 디자인 참고와 1차 최종 플레이어 모델이다. 전체 전투 애니메이션·모든 무기 조합·연속 충돌 검증이 끝난 게임 출하 모델이라는 의미는 아니다.
- 독립 형상 검사에서 고리 볼/소켓의 면적 0 삼각형과 일부 비평면 면이 확인됐다. 이는 조형 언어의 일부가 아니며, 수정 범위와 영향 검토가 필요한 기존 데이터 문제다.
- UV 검사 범위와 이미지 패킹 확인은 전체 UV 겹침·밀도·모든 재질 노드의 품질을 보증하지 않는다.
- 실제 표시 크기, 공통 카메라/배율, 성능 예산과 관절별 허용 각도의 프로젝트 전체 정량 규격은 아직 확정하지 않는다. 에셋별 설정·실측 결과와 프로젝트 공통 규칙을 구분한다.
- 최신 수정의 수치·해시·검사 표본 및 사용자 승인 여부는 로컬 릴리스 정보와 개발 로그에서 관리한다. 이 문서에 매번 버전별 결과를 복제하지 않는다.
