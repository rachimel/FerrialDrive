# Unreal 애니메이션 제작 흐름

**Unreal 새 리그 → 짧은 동작 초안 제작 → 전체 재생 검수 → 수정·재검수 → Unreal 프리렌더 → 툴 2D 조립·패킹**로 진행한다. 모델링은 Blender, 리깅·포즈·키·타이밍·보간 편집은 Unreal에서 수행한다. 기존 Blender 리그는 재사용하지 않는다. 전체 역할은 [Unreal 제작·인계 흐름](unreal_pipeline.md)을 따른다.

KeyPose는 동작을 만들거나 문제를 진단하는 수단이다. 정지 키포즈 묶음의 별도 사전 승인·확정 대기 단계를 두지 않는다. 사용자의 Unreal 직접 편집은 선택 사항이며, AI가 초안과 수정을 담당할 수 있어야 한다.

메카의 형상·관절 기준은 [디자인·제작 규칙](mech_design_rules.md), 동작·입력·방향·캔슬은 [기본 무기 사양](basic_weapon_animations.md)과 [PRE-PRD 4.8절](../Ferrial_Drive_PRE_PRD_v0.1.md)을 따른다.

## 1. 짧은 동작 초안

- 기준 모델·Unreal 리그·Skeleton·Skeletal Mesh·편집 Sequence와 수정 범위를 고정한다. 승인된 원본과 사용자 편집 키를 보존한다. 리깅과 제어점 작성·수정은 Unreal에서 수행한다.
- 짧은 동작 하나에 시작·끝·타이밍·중간 자세를 포함해 바로 재생 가능한 초안을 만든다. 준비·타격·회수·체중 이동의 의도가 읽혀야 한다. 단순 수치 변화나 팔만 움직이는 결과를 완성 동작으로 제시하지 않는다.
- 무기별 수납과 인출은 독립 클립으로 제작한다. 무기 전환은 현재 무기의 수납과 다음 무기의 인출을 연결한다. 공통 빈손 연결 자세·수납 완료/파지 시작 시점·무기 부착 상태를 명시하고, 특정 두 무기 조합을 필수 제작 단위로 고정하지 않는다. 새로운 무기군의 파지·장착 간섭은 개별 검증한다.
- AI가 지지발·체중 방향, 손/무기 접촉, 이동·조준·공격 방향과 보존 대상을 정리한다. 검·총 및 조준 여부와 관계없이 이동·공격 중에도 시선 추종을 적용한다. 검 달리기의 기존 전진 모션과 옆걸음·뒷걸음 품질은 구분해 검수한다. 제작 목표는 실제 시선·머리·팔·상체의 선행 보간과, 방향 차이 ±45° 초과 시 시작해 정렬까지 이어지는 하체 보간 추종이다. 현재 전신 출력과 새 독립 조준 제작을 구분한다. 허용각은 월드 수평면 회전 기준이며 각 관절의 로컬 회전을 각각 누적하지 않는다. 미정인 회전 속도·입력 수치는 임의 확정하지 않는다.
- 상·하체 방향은 [원거리 표적 규칙](../ranged_targeting.md)을 따른다. 실제 시선·상체도 목표 방향으로 보간하고, ±45°는 하체 추종을 시작하는 기준이다. 하체는 시작각 안에 재진입한 뒤에도 정렬될 때까지 보간한다. 해당 규칙의 정지 조준 후보를 먼저 확인하며 기존 전신 출력의 제작 완료로 취급하지 않는다.
- 먼저 한 동작으로 제작·반환·기존 출력 연결을 확인한 뒤 확장한다. 기존 41개 FK 초안과 정지 자세 카탈로그는 참고 데이터이며 품질 승인이나 정상 자세의 근거가 아니다.

## 2. AI의 전체 동작 확인

- 정상 속도·느린 재생과 프레임 이동으로 시작부터 끝까지 직접 확인한다. 앞/옆/사선에서 동작을 읽고, 이상 부위는 확대해 평가된 실제 자세를 확인한다. 사용자에게 정상 속도의 전체 재생과 핵심 문제 프레임을 함께 제시한다.
- **팔은 상박·하박의 상대 각도와 실제 팔꿈치 굽힘 면을 확인한다.** 지나치게 좁은 V자 접힘, 상박/하박·장갑의 겹침, 반대 방향 접힘, 어깨·팔꿈치·손목 비틀림을 단순히 연결된 자세라는 이유로 정상 판정하지 않는다. 손 목표 도달·키 존재·수치 검사 통과도 정상 외관의 근거가 아니다.
- 관절 중심·연결, 강체 장갑 변형, 발 접지·체중 이동, 파지·수납/인출 경로와 중간 궤적을 확인한다. 달리기의 의도하지 않은 발 미끄러짐과 대시·부스트의 지면 접촉 슬라이딩을 구분한다.
- 횡이동에서 의도한 다리 교차와 실제 다리 메시 겹침을 구분한다. 정면·측면·사선과 프레임 사이의 통과 경로를 확인하고, 교차 자체를 없애는 대신 무릎·발의 통과 공간을 확보한다.
- 정해진 허용각이 있으면 Unreal 평가 결과와 반환 결과에서 확인한다. 미정인 허용각을 새 수치로 고정하지 않는다. 읽히지 않거나 확인하지 못한 자세는 미검증/수정 대상으로 남긴다.
- AI가 찾은 명백한 결함은 제시 전에 Unreal에서 수정한다. 이전 AI의 통과 판정을 재확인 없이 재사용하지 않는다. 정지 이미지·끝점·극값·정수 프레임 행렬 일치는 전체 모션 품질과 연속 간섭을 보증하지 않는다.

## 3. 사용자 재생 검수와 수정

- 사용자는 전체 동작의 자세·속도·무게감·연결 문제를 지적한다. AI가 해당 구간·부위·의도를 정리하고 Unreal에서 수정·재제시한다. 별도 KeyPose 승인 절차를 추가하지 않는다.
- 사용자가 직접 수정할 때는 해당 Sequence·프레임·제어점을 연다. 수정한 키와 Sequence를 저장하고 AI는 현재 키를 읽어 반환한다. 초안 생성/키 작성 명령을 다시 호출해 사용자 편집을 덮어쓰지 않는다.
- 승인된 모델 실루엣·리그 구조·손 위치·파지·공격 궤적을 바꿔야 하면 영향과 후보를 설명하고 확인한다. 동작 초안의 재생 검수와 모델 외형 변경 승인은 구분한다.
- 침묵·렌더 성공·AI 자체 판단·일괄 초안 생성을 사용자 품질 승인으로 취급하지 않는다. 동작의 승인 범위와 남은 문제를 기록한다.

### 스커트의 다리 접촉 반응

- 앞·옆·뒤를 좌우로 나눈 6패널은 다리의 실제 메시 접촉 때만 개방한다. 닫힌 상태에서 비접촉이면 골반 기준 패널의 추가 회전·이동은 0이다. 몸의 자세 변화에 따른 부모 변환은 유지한다.
- 충돌 대상은 양쪽 허벅지·정강이·발 부품이다. 무기·칼집·장비는 제외한다. 다리 각도에 비례한 선행 개방이나 임의의 기본 개방각을 넣지 않는다.
- Unreal 메시의 삼각형 교차와 체적 포함을 검사해 분리되는 첫 회전 구간을 탐색한다. 현재 도구는 준정적 힌지 접촉 보정이며 Chaos의 질량·관성·마찰 시뮬레이션과 구분한다. 힌지 위치·탐색 제한은 제작 설정이며 확정 관절 허용각으로 취급하지 않는다.
- 몸·손·파지·무기 궤적·타이밍을 보존하고 새 후보에 저장한다. 비접촉 추가 변환 0, 실제 메시 교차, 전체 재생과 문제 프레임을 각각 확인한다. 저장 표본 사이의 연속 충돌까지 검사했다고 확대하지 않는다.
- Blender의 독립 교차 검사는 Unreal에서 내보낸 실제 삼각분할과 평가 변환을 사용한다. 원본 `.blend`와 Unreal의 삼각분할이 다를 수 있으므로 원본 검사와 실제 Unreal 메시 검사를 구분한다.


## 4. Unreal 프리렌더와 2D 출력

- 편집 Sequence를 보존하고 Unreal의 동일 카메라·프레임·크기·기준점으로 파츠를 렌더한다.
- PNG 파츠+JSON을 `unreal.import`로 패킹한 뒤 기존 Asset Tool에서 2D 조립·레이어·상태·출력을 편집한다. `.blend` 왕복은 필수 단계가 아니다.
- 전체 참조 렌더와 재합성을 비교한다. 파츠 가림·알파·노출·그림자와 실제 표시 크기를 확인한다. [인계 규약](unreal_pipeline.md)을 따른다.
- 달리기↔사격, 공격 각 구간→부스트, 부스트 중 조준/사격/무기 전환과 종료 후 복귀는 실제 동작 검수로 확인한다.

## 도구와 완료 상태

| 역할 | 경로와 범위 |
| --- | --- |
| 리깅·동작 편집 | Unreal 새 리그·FK/Sequencer. 실제 동작 품질은 별도 검수한다. |
| 프리렌더 | automate/unreal/prerender.py의 MRQ 파츠 레이어 출력 |
| 2D 조립·출력 | Asset Tool unreal.import·plan.create/update/export와 기존 Pico2D 로더 |
| 기존 골격 FBX 왕복·Blender 렌더 | 호환 경로. 현행 제작의 필수 단계로 사용하지 않는다. |

Pose Tool·`keypose_pipeline.py`·`motion_blocking.py`·`pose_refinement.py`·`animation_pipeline.py`는 현행 동작 제작에서 제외한다. 기존 코드·샘플·작업본은 과거 자료/호환 용도로 보존한다. 문서 채택, 구현, 자동 검사, 실제 창 조작, 사용자 품질 승인과 게임 연결 완료를 각각 기록한다.
