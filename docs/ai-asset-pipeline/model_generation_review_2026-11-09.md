# 플레이어 메카 표면 작업 평가와 모델 생성 파이프라인 개선 보고서

작성일: 2026-11-09 KST. 대상은 플레이어 메카의 1K 재질, 패널·구분선, 스커트 UV 및 음영 수정 작업이다.

## 1. 결론과 이번 작업의 종료 범위

이번 스커트 수정은 화면에서 납득할 만한 개선을 만들지 못했다. 기존 메시의 정점 좌표를 수치적으로 보정하는 방법을 반복하면서, 의도한 장갑면과 실제 면 구성이 일치하는지 직접 확인하는 과정이 부족했다. **Python 자체의 한계로 단정할 수는 없지만, 이번에 선택한 자동화 방식과 시각적 판단 절차는 실패했다.**

사용자 최종 지시에 따라 스커트 재생성·면·노멀·UV 수정은 중단한다. 기존 도장·재질·거칠기·가슴 패널·다른 부위 구분선은 유지하고, 스커트의 구분선만 해제했다. 목 구분선 시험 후보는 반영하지 않았다. 구분선 제거는 삼각 음영을 해결한 것이 아니다. 기존 면과 UV 문제는 남겨 둔 상태다.

이 문서의 개선 절차는 다음 모델 제작을 위한 제안이다. 파이프라인 전체가 이미 개선되었거나, 사용자가 아래 세부 기준을 승인했다는 뜻은 아니다.

## 2. 확인된 사실과 원인 해석

| 관찰·검사 | 확인한 내용 | 이 결과만으로 확정할 수 없는 내용 |
| --- | --- | --- |
| 기존 스커트 렌더 | 넓은 장갑면 안에 삼각형 단위 명암이 보인다. | 어느 정점·면·노멀 설정 하나가 유일한 원인인지 |
| 단색 재질, 재질 Normal 연결 해제 | 삼각 음영이 남는다. | UV 결함이 전혀 없다는 결론 |
| 표면색을 무조명 발광으로 출력 | 넓은 삼각 명암이 보이지 않는다. | 형상이 정상이라는 결론. 발광 출력은 형상 음영을 없앤다. |
| 스커트 셸 UV 검사 | 활성 렌더 UV인 UV_Paint에서 면적이 거의 0인 삼각형 119개를 검출했다. 별도 UV_Boundary는 같은 기준에서 0개다. | UV 전체의 겹침·밀도·패딩이 정상이라는 결론 |
| 비활성 UVMap 검사 | 같은 셸의 비활성 레이어에서 867개를 검출했다. | 비활성 레이어가 현재 도장의 삼각 얼룩을 만든다는 결론 |
| 앞 장갑 변형 연결 | Surface Deform 연결이 있으며 원본 정점과 평가된 정점이 다르다. 재바인딩을 포함한 후보도 만들었다. | 재바인딩만으로 외관·움직임이 해결된다는 결론 |
| 후보 렌더 비교와 사용자 피드백 | 반복 보정으로 충분한 외관 개선을 제시하지 못했다. | 사용자가 최종 스커트 외관을 승인했다는 결론 |

UV의 면적 검사는 UV 좌표 삼각형의 외적 절댓값이 1e-12 미만인 경우를 집계했다. 이 수치는 겹친 아일랜드 수나 메시의 구멍 수가 아니다. 현재 공통 도장은 부품 로컬 박스 투영을 사용하므로, 활성 UV의 결함 수를 그대로 현재 PBR 도장의 원인으로 연결해서도 안 된다.

**해석:** 넓은 삼각 얼룩은 색 텍스처만으로 설명되지 않으며, 실제 장갑면의 기울기·노멀·변형 후 형상을 먼저 조사해야 한다. UV에는 별도의 결함이 존재한다. 두 문제를 분리하지 않은 채 UV·선 마스크·형상을 동시에 고치면 무엇이 좋아졌는지 판단하기 어렵다.

근거 파일은 로컬 `output/player_mech_skirt_uv/uv_audit.json`, `before/`, `constant_shaded/`, `unlit_texture/`, `planes.json`이다. 이들은 이번 원본을 대상으로 한 진단 결과이며, 다음 모델에서도 동일한 문제가 발생한다는 증거는 아니다.

## 3. 같은 결과를 반복한 이유

### 기존 면 구성을 유지한 수치 보정에 의존했다

면 방향과 좌표 범위로 정점을 골라 평면·능선에 맞추는 방식은 대상이 정확할 때 유용하다. 그러나 이번 장갑에는 돌출면·능선·경사면·두께·변형 연결이 섞여 있었다. 그 상태에서 기존 연결 구조를 유지한 좌표 보정만 반복하면 의도하지 않은 면 경계와 명암이 계속 남을 수 있다. 다음 수치를 바꾸기 전에 선택된 면과 목표 장갑면을 화면에서 확인했어야 한다.

Python은 Blender의 데이터와 연산을 제어하는 수단이다. 잘 정의된 면 구성을 생성하거나 편집하는 데도 사용할 수 있다. 문제는 언어 자체보다 **기존 메시를 보존하는 보정 방식에 머물렀고, 그 방식이 부적합하다는 시각적 증거에 늦게 반응했다는 점**이다. 반대로 마우스로 편집한다는 사실만으로 좋은 결과가 보장되지는 않는다.

### 원본 메시와 변형 후 메시를 늦게 분리했다

기존 정점 좌표를 바꿔도 변형 연결을 거친 화면에서는 다른 형상이 나타날 수 있다. Surface Deform은 바인딩 시점의 두 메시 관계를 바탕으로 이후 변형을 전달한다. 따라서 면 편집 전후에 원본 메시와 평가된 메시를 따로 확인할 필요가 있다. [Blender Surface Deform 설명](https://docs.blender.org/manual/en/dev/modeling/modifiers/deform/surface_deform.html)

이번 재바인딩 시험은 이 관계를 조사한 과정이다. 외관 개선이나 리그 검증을 완료한 해결책으로 기록하지 않는다.

### 검사 통과와 외관 개선을 혼동하기 쉬운 구조였다

저장·재로딩 성공, UV 범위 정상, 이미지 패킹, 해시 일치는 데이터 손상을 막는 검사다. 사용자가 지적한 삼각 음영이 줄었는지는 별도로 비교해야 한다. 면적이 거의 0인 UV에 최소 크기를 부여해서 검사만 통과시키는 방법 역시 왜곡·밀도·원래 메시의 결함을 해결했다는 증거가 될 수 없다.

### 중단 기준이 없었다

설명을 추가하고 수치를 바꾸는 동안 외관이 거의 같아도 다음 시도로 넘어갔다. 새 후보를 만들기 위한 조건이 원인에 대한 새로운 근거보다 구현 가능성에 치우쳤다. 개선이 확인되지 않는 반복을 일찍 끊는 절차가 필요하다.

| 형상 계획 | 장갑 부품의 역할, 큰 평면·경사면·곡면·능선·두께를 구분한다. | 정면·측면·사선에서 면의 의도와 외곽이 설명된다. |

노멀은 형상 확인을 대체하지 않는다. Blender의 Flat/Smooth 설정은 노멀에 따른 음영을 바꾼다. 이번처럼 넓은 장갑면의 결함을 조사할 때 무조건 Smooth로 덮으면 원인 확인이 어려워질 수 있다. [Blender 음영 설정](https://docs.blender.org/manual/en/latest/scene_layout/object/editing/shading.html)

## 5. 자동화와 직접 편집의 역할

**계속 자동화할 작업:** 반복 부품 생성, 대칭·치수 제약, 명확한 규칙의 형상 생성, 재질 연결, 파일 경로와 패킹, 검사, 고정 조건 렌더, 기준 해시와 레지스트리 갱신이다. 같은 입력으로 같은 결과를 만들고 변경 범위를 추적하는 데 유리하다.

**화면 확인을 전제로 할 작업:** 사용자가 지적한 국소 면의 선택, 능선·단차의 조형 판단, 문제 면의 재구성, 노멀 경계 선택, UV 심과 왜곡 조정이다. 자동 후보를 쓰더라도 편집 전 선택 면과 편집 후 평가 결과를 확인해야 한다. 직접 편집이 필요한 시점에 연결된 Blender를 조작할 수 없다면, 그 제약을 밝히고 구체적인 편집 대상으로 인계한다. 같은 보정식을 계속 실행하는 것으로 대체하지 않는다.

공통 제작 코드에는 반복해서 쓸 수 있는 일반 연산만 남긴다. 부품별 역할·목표 치수·허용 변경·참고 뷰는 에셋 설정으로 관리한다. 단순 좌표 범위를 부품 의미의 유일한 기준으로 쓰지 않고, 명시한 면 그룹이나 부품 역할 정보와 대조한다. 사용자에게 필요한 것은 스크립트 수가 아니라 외관과 편집 가능성이므로, 버전별 보정 스크립트를 누적하는 방식은 개선 목표에서 제외한다.

## 6. 비교와 중단 절차

다음 규칙은 도입 제안이며 이번에 자동 적용한 정책은 아니다.

1. 시도 전에 결함 위치와 기대 변화를 적는다. 예: “앞 돌출 장갑의 넓은 평면 내부 삼각 명암을 줄이고 외곽과 중앙 능선은 유지한다.”
2. 원본과 후보에 같은 대상 객체·카메라·투영·프레임·조명·노출·출력 크기를 사용한다. 자동 맞춤 구도가 후보마다 달라지지 않게 카메라를 고정한다.
3. 단색 음영, 무조명 색, UV 체커, 최종 재질을 구분해 비교한다. 한 번에 한 원인 범위만 변경한다.
4. 확대와 실제 표시 크기를 함께 본다. 수치 차이·픽셀 차이만으로 미적 개선을 판정하지 않는다.
5. 같은 접근을 두 번 시도했는데 결함이 여전히 보이면, 새로운 원인 근거 없이 세 번째 수치 보정을 하지 않는다. 직접 면 편집으로 전환하거나 보류한다.
6. 저장된 후보를 다시 열어 확인한 뒤에만 원본에 반영한다. 승인된 외관과 기술 검사 상태는 별도로 기록한다.

이번 후보 중 일부 부위 렌더는 표시 대상 부품의 구성이 달랐다. 따라서 자동 맞춤된 후보 이미지끼리 외곽이나 크기를 직접 비교해서는 안 된다. 종료 검토에서는 원본과 같은 스커트·골반 표시 대상 목록으로 다시 렌더했다. 앞으로는 비교 조건 자체를 검토 결과와 함께 저장해야 한다.

## 7. 1K 텍스처 품질의 판단 기준

1K는 이미지 크기이며 표면 품질 보증이 아니다. 작은 UV 영역에 정보가 몰리거나, 큰 미세 노이즈가 장갑면을 덮거나, 원래 형상 결함을 재질로 가리면 1K 이미지여도 품질이 떨어진다.

다음 제작에서는 체커로 밀도를 확인한 뒤, 큰 도장 명암·재질 거칠기·미세 노멀·기능적 패널을 순서대로 추가한다. 가슴 패널과 구분선은 장갑의 주요 면을 읽기 쉽게 해야 한다. 모든 꺾임을 일괄 강조하면 불필요한 대각선까지 디자인처럼 드러날 수 있으므로, 실제 구조선과 단순 삼각 분할을 구분한다.

가느다란 선의 최소 크기는 텍스처 원본 픽셀 수뿐 아니라 UV 점유율·화면 투영·축소 필터에 영향을 받는다. “텍스처에서 2px”만으로 게임 화면 가독성을 보장하지 않는다. 최종 표시 크기에서 선이 끊기거나 얼룩으로 합쳐지는지를 확인한다. 사용자 지정 1K를 유지하면서 이 검토를 먼저 수행하고, 해상도 증가는 별도 요구가 있을 때 판단한다.
