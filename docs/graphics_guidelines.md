# 그래픽스 작업 가이드라인

Ferrial Drive의 렌더링, 셰이더, GPU 자원, 아틀라스, 화면 합성 작업에 적용한다. 기존 품질·실행 조건과 작업의 검증 기준을 코드 수정 전에 확인한다. [렌더링 현행 명세](rendering.md) · [아틀라스 메모리 옵션](tool-usage/atlas_memory_options.md)

## 렌더 상태와 제출

- GL 상태는 같은 렌더러와 컨텍스트 안에서 관리한다. SDL↔GL 경계에서 SDL 큐를 비우고, GL이 수정하는 상태를 확보한다. GL 구간 중에는 상태 소유자를 하나로 두고, 프로그램·타깃·뷰포트·블렌드·텍스처는 그 구간의 기록으로 접근한다. SDL 또는 별도 코드에 제어권을 넘길 때 수정한 상태를 복원하고 기록을 무효화한다. 예외 경로에도 같은 규칙을 적용한다. [SDL_RenderFlush](https://wiki.libsdl.org/SDL2/SDL_RenderFlush)
- 같은 상태의 재설정과 핫 패스의 반복 조회를 줄인다. 상태 캐시를 우회하는 GL 호출이나 SDL 타깃 변경은 소유자가 볼 수 있는 경계에서 처리한다. 기종과 기능이 같은 계약을 따르거나 동일 형식의 임시 자원을 사용하면 소유자와 자원을 공유한다.
- 한 번의 제출로 묶을 수 있는 연속 작업을 찾되, 겹침·깊이·클립·알파·가산 블렌드 순서를 보존한다. 효과나 필터가 요구하는 정밀도·색 공간·프리멀티플라이 규약을 지킨다.

## GPU 자원과 호환성

- 프레임 루프의 할당, 셰이더 컴파일, 업로드와 읽기 되돌림을 구분해 조사한다. 반복 자원은 수명과 메모리 상한을 정해 재사용한다. GPU가 읽고 있는 저장소에 다시 쓰는 경로는 fence·버퍼 수명과 함께 확인한다. 동기 대기는 실제 타임라인에서 구간과 원인을 확인한다. [Buffer Storage](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_buffer_storage.txt)
- 배열·배치·인스턴싱은 실제 채널 형식, 샘플러 한도, 패딩과 상주량까지 계산한다. OpenGL 기능을 도입할 때 활성 컨텍스트의 버전·지원 기능을 확인하고, 기존 지원 프로필의 경로와 실패 시 자원 정리를 검증한다.

## 검증과 전수 조사

- 화면 유지가 목표면 같은 입력에서 대상 타깃의 RGBA와 최종 합성 화면을 대조한다. 리사이즈, 클립, 타깃 전환 등 변경의 영향을 받는 경계를 포함한다. 동일 조건 재실행에도 차이가 있으면 대조군을 추가해 위치·픽셀 수·최대 채널 차이로 기록한다.
- 성능은 느린 실제 경로에 효과를 유지한 채 추적한다. 전후 입력·해상도·품질·제한 조건을 맞추고, 기본 성능 반복 실행과 상세 계측을 구분한다. 함수별 CPU 시간·호출 수, GPU 패스 시간, 프레임 P99·FPS와 해당하는 경우 메모리·업로드를 기록한다. 병목은 기능·함수·발생 조건·시간을 명시하고, 가설은 실측과 구분한다. [성능 계측 사용법](tool-usage/performance_timing.md)
- 전수 조사에서는 게임·프레임워크·도구·테스트·셰이더의 범위를 기록한다. 수정 대상으로 판정한 파일마다 호출 위치, 실제 실행 조건, 위반 근거, 수정안과 확인 방법을 남긴다. 공통 구조로 고칠 항목과 성능 계측이 필요한 후보를 전체 파일을 기준으로 논의한다.
