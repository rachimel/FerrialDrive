# 성능 목표와 잠정 사양 검증표

**최소 사양 검증 기준은 i3-10100·UHD 630·RAM 8GB·SSD 256GB이며 FHD 60FPS, 프레임당 약 16.67ms를 목표로 한다.** 권장 사양은 FHD 165FPS, 프레임당 약 6.06ms를 목표로 하며 구체적인 부품은 미정이다. 두 목표 모두 실제 달성 여부는 목표 규모의 전투로 확인한다. 아래 외장 GPU 비교군은 AI의 검증 후보이며 출시 사양이나 목표 FPS의 실측 보장이 아니다.

## 범위와 현재 근거

- 사용자 지정 목표: 소수 기종의 에셋을 공유하는 수백 기 규모, FHD·QHD 출력. 정확한 최대 활성 수·가시 수·기종 수·탄환 수는 아직 미정이다.
- 사용자 지정 최소 사양 목표: **Core i3-10100·Intel UHD Graphics 630·DDR4 RAM 8GB·SSD 256GB에서 FHD 60FPS**, 프레임당 약 **16.67ms**다.
- 사용자 지정 권장 사양 목표: **FHD 165FPS**, 프레임당 약 **6.06ms**다. 권장 CPU·GPU·RAM·저장장치 구성은 미정이다. 모니터·출력 단자의 주사율 지원만으로 게임 성능 충족을 판정하지 않는다.
- 평균 FPS만으로 충족을 판정하지 않는다. 기준 전투의 p95/p99·프레임 예산 초과 횟수와 비율을 함께 확인하고, 측정 구간의 모든 프레임이 예산 안에 드는 것을 목표로 한다. 로딩·전환 비용은 별도로 기록한다.
- 사용자 지정 메모리 목표: 기본 시나리오 게임 전체 1GiB 안팎, 규모가 커지는 시나리오는 2GiB 안팎이다. 최소 사양 검증 장비의 전체 RAM은 8GB다. OS·백그라운드 프로그램·내장 GPU 공유 메모리까지 고려해 실기에서 확인한다. 아래 외장 GPU는 비교군이며 최소 지원 대상으로 확정한 것이 아니다.
- 현재 벤치마크의 프로세스/Job 커밋 상한은 2GiB다. 로딩 여유를 위한 실행 제한이며 게임 전체 메모리 목표 충족 판정과 구분한다.
- 품질 정책: 기체 색상·보간은 높음 75%·보통 50%·낮음 25%, 그림자는 높음 50%·보통 25%·낮음 12.5%다. 모두 가로·세로 배율이며 첫 실행은 낮음, 이후에는 저장 등급을 따른다. HUD·지형·원본 PNG를 축소하지 않는다. 그림자는 원본 좌표와 화면 기준 부드러움을 유지한다.
- 현재 실측은 플레이어 1기와 고정 표적의 훈련장이다. 수백 기 AI·충돌·다중 기체 그리기 성능을 측정한 결과가 아니다.
- 측정 장비: Core Ultra 9 275HX, 시스템 RAM 약 63.43GiB, RTX 5070 Laptop GPU, Windows/Python 3.11.16, OpenGL, FHD. 노트북과 데스크톱 GPU를 제품명만으로 동급 처리하지 않는다.
- 일반 실행 루프와 최소 사양 벤치마크의 기본 목표는 60FPS다. 자동 벤치마크는 목표 FPS의 역수로 갱신하며, `--target-fps 165`로 권장 사양의 시간 예산을 검사한다. 이 옵션만으로 권장 장비를 재현하지 않는다.
- Trail 결은 사전 파일로 준비한다. 파일 적재·셰이더 컴파일·버퍼 예약·첫 GPU 실행은 로딩에서 수행하며, 초기 준비 비용과 전투 프레임을 나눠 측정한다. [준비 규약](tool-usage/trail_texture_preparation.md)을 따른다.

## 기존 자원·기능 제한 벤치마크: 2026-11-15, 당시 165FPS 조건

[독립 벤치마크](tool-usage/hardware_profile_benchmark.md)를 추가했다. 논리 CPU 8개·Job CPU 시간 상한 50%·프로세스/Job 커밋 1024MiB와 `uhd630_gl45_conservative` 기능 가드를 연결한다. 50%는 AI가 첫 부하 시험용으로 정한 값이며 i3-10100과 성능 보정하지 않았다. Windows 조회 결과와 실제 초과 할당 거절을 검사했다. UHD 630의 처리량·대역폭·실제 드라이버는 재현하지 않는다.

같은 호스트 Ultra 9 275HX·RTX 5070 Laptop에서 FHD, 현재 50% 품질, 플레이어 1기 레벨 3 공격 유지, 고정 1/165초 갱신, 준비 165/측정 600프레임으로 실행했다. VSync를 끄고 목표 제한만 165FPS로 뒀다. 두 번째 측정끼리 비교하며 백그라운드 부하·계측 비용은 보정하지 않았다.

| 항목 | 제한 없음 | CPU·메모리·기능 제한 |
| --- | ---: | ---: |
| 실측 FPS | 59.47 | 56.60 |
| 평균 work | 16.81ms | 17.66ms |
| work p99 | 36.46ms | 38.98ms |
| 6.06ms 초과 프레임 | 600/600 | 600/600 |

**현재 시나리오는 165FPS 미달이다.** 제한 실행은 기능 위반 0건, 정상 600프레임 완료, Job peak commit 약 625.29MiB였다. 그리기 제출 평균은 15.02ms, 갱신 2.34ms다. HUD만으로 전체 목표 예산을 넘으므로 HUD 경로를 먼저 세분화한다. HUD 전체 시간을 모션 블러만의 비용으로 단정하지 않는다. CPU 값은 대기·선점 포함 wall 시간이며 GPU elapsed는 제출 간격도 포함할 수 있다.

원자료는 `output/performance/hardware_profile/sword_limited_02/`와 `sword_unrestricted_02/`의 `report.json`, `limits_final.json`, `timings.json`이다. 첫 비교는 제한 59.05FPS·무제한 59.44FPS였다. 결과 변동을 보존하며 기능 가드의 순수 오버헤드로 환산하지 않는다. 이 표는 실제 i3/UHD 630 FPS, 수백 기 성능, 게임 전체 1GiB 달성의 증거가 아니다.

## Compute 전환 후 비교: 2026-11-15

같은 제한 장면에서 CPU/Compute Trail 정점을 조건당 660프레임×2회 비교했다. 기체 50%·그림자 25%, FHD이며 별도 UHD 630 실기가 아닌 위 호스트와 기능 가드다. 평균 프레임 wall 18.93→13.89ms, FPS 52.83→72.01, 월드 wall 8.02→3.62ms였다. 전체 wall 감소는 약 26.6%이며 GPU elapsed 평균은 1.216→1.250ms다. 둘 모두 165FPS 목표 미달이다. 원자료는 `output/performance/compute_trail_20261115/comparison_final/report.json`, 검증 범위는 [구현 기록](ai-dev-log/2026-11-15-compute-trail-shadow-quality.md)을 따른다.

그림자 선택 등급의 R8 적재량은 약 67.04/16.77/4.20MiB다. GPU/CPU 전체 메모리 예산 충족과 구분한다. 아래는 이전 50% 보간·50% 그림자 비교 기록이며 현행 낮음의 기본 적재량이 아니다.

## 50% 보간·그림자 자원 비교 기록

HUD·월드의 후속 병목 분석은 `output/performance/hud_world_20261115/report.md`에 기록했다. 같은 장면을 메모리에 고정한 50% 품질 대조에서 평균 work 20.14ms, HUD 구간 8.19ms·월드 8.48ms였다. HUD 생략은 약 8.49ms, Trail 표시 생략은 약 5.01ms 감소했다. 블러 3종을 각각 생략한 차이는 약 0.13~0.26ms로 회차 변동보다 작다. 현행 HUD는 입력 순서를 유지하는 도형 큐와 재사용 정점·인덱스·사각형 버퍼를 사용한다. 적용 범위와 후속 비교는 [HUD 배치 제출](unit-tests/ui_unit_test.md#hud-배치-제출)과 [구현 기록](ai-dev-log/2026-11-15-hud-batch-render-queue.md)을 따른다. 후속 직접 조작 벤치마크는 실제 경과 시간과 현재 저장 품질을 사용한다. 이 기록의 50%와 이후 갱신된 low=25%를 구분한다.

| 항목 | 100% 보간·100% 그림자 측정 기준 | 50% 보간·50% 그림자 측정 기준 |
| --- | ---: | ---: |
| 동작 × 방향 | 20 × 8 = 160클립 | 동일 |
| 보간 구간 | 912개 | 동일 |
| 고유 색상 프레임 / 벡터 맵 | 1,051 / 1,824개 | 동일 |
| 아틀라스 페이지 | 색상 34 + 벡터 58 | 색상 8 + 벡터 14 |

이는 에셋의 논리적 GPU 페이로드이며 드라이버·렌더 타깃·UI·지형·입자를 포함한 전체 VRAM 점유량이 아니다. 고유 프레임 수와 GPU가 매 순간 계산하는 중간 프레임 수를 혼동하지 않는다.

현재 사용자 품질은 높음 75%·보통 50%·낮음 25%이며 기본 낮음이다. 160클립 보간 GPU 페이로드는 각각 약 508.69/236.06/65.96MiB이고 그림자 50%는 별도다. 품질은 저장 즉시 실행 중 교체하며 위치·공격 진행·HP를 유지한다. 이 품질별 자원 확인을 위 FPS·시작 시간 측정의 재검증으로 해석하지 않는다.

그림자 축소 전 동일 설정의 보간 50%는 시작→첫 게임 화면이 Work 1개 2.10~2.63초, 4개 1.84초였다. 보간 100%의 별도 1회 비교는 3.87초·2.68초였다. 최종 보간·그림자 모두 50%와 부드러운 표시를 적용한 첫 화면은 약 1.58~1.66초였다. OS 캐시를 비우지 않았고 Python 프로세스 생성·인터프리터 시작은 제외했다. 첫 회의 파일 읽기가 느렸으므로 단축량 전부를 스레드 수만의 효과로 단정하지 않는다.

최종 50%·4 Work·부드러운 그림자 조건의 프로세스 private bytes는 로딩 후 약 556MiB, 공격 계측 후 약 597MiB였고 peak working set은 약 370MiB였다. private bytes·working set·실제 물리 메모리 사용·GPU 페이로드는 서로 다른 지표다. RAM과 GPU 페이로드를 단순 합산해 1GiB 목표 달성을 확정하지 않는다.

최종 레벨 3 오른쪽 연속 공격, 60프레임 예열·240프레임 측정, VSync·프레임 제한 없음에서 CPU 측 프레임 경과는 평균 17.77ms/p95 32.30ms, GPU draw 질의는 평균 0.88ms/p95 4.54ms였다. 그림자 축소 전 360프레임의 보간 50%·100% 비교에서는 CPU 평균 18.84~19.11ms로 비슷했다. 표본 수·설정이 달라 두 결과의 차이를 그림자 최적화의 순수 개선량으로 단정하지 않는다. CPU 값은 update·draw·present와 대기를 포함하며, GPU 질의도 제출 공백을 포함할 수 있다. 계측 오버헤드·백그라운드 부하는 통제하지 않았다.

**앞선 표본은 1기에서도 최소 목표 60FPS 예산 16.67ms와 권장 목표 165FPS 예산 6.06ms를 넘었다.** 보간 해상도 감소와 로딩 병렬화가 CPU 중심의 전투 프레임 비용을 해결했다고 해석하지 않는다. 17.77ms를 6.06ms로 줄이는 데 필요한 약 2.93배는 해당 표본의 시간 비율일 뿐 다른 CPU에서의 성능 환산값이 아니다. UI/그리기 준비·제출·규칙 갱신을 우선 분리 계측한다. GPU 교체만으로 수백 기·고주사율이 해결된다는 근거는 없다.

## 최소 사양을 결정하기 위한 검증 후보

하한 검증 장비는 사용자가 지정했고 외장 비교군의 부품 배치는 AI의 잠정 제안이다. 현재 측정 장비보다 낮은 장비에서의 FPS를 환산하지 않았다. FHD·QHD는 동일한 가시 기체 수·효과·카메라 범위를 맞춰 비교한다. QHD에서 월드 시야까지 넓혀 더 많은 기체를 보이면 별도 조건으로 측정한다.

| 목표 출력 | 프레임 예산 | CPU 검증 시작점 | FHD GPU 검증 시작점 | QHD GPU 검증 시작점 | RAM·저장장치 |
| --- | ---: | --- | --- | --- | --- |
| FHD 60FPS 최소 사양 목표 | 16.67ms | Core i3-10100 | Intel UHD Graphics 630 | 별도 검증 | DDR4 RAM 8GB·SSD 256GB |
| FHD 165FPS 권장 사양 목표 | 6.06ms | 미정 | 미정 | 별도 검증 | 미정 |
| 60Hz 외장 GPU 비교군 | 16.67ms | Ryzen 5 5600급 6코어/12스레드 | RTX 3060 12GB | RTX 3060 12GB부터 확인 | 비교 장비 RAM 16GB, SSD |
| 120~144Hz 비교군 | 8.33~6.94ms | Ryzen 5 7600급, 메인 스레드 처리량 우선 | RTX 4060 8GB | RTX 4060 Ti 16GB | 비교 장비 RAM 16GB, SSD |
| 240Hz 확장 검토 | 4.17ms | 산정 보류 | 산정 보류 | 산정 보류 | RAM 용량으로 CPU 프레임 초과를 해결할 수 없음 |

60Hz·120~144Hz 외장 비교군은 병목 분리를 위한 참고 장비이며 최소·권장 사양의 확정 부품이 아니다. QHD라는 이유만으로 하한 GPU 등급을 미리 올리지 않는다. 고주사율 QHD의 4060 Ti는 처리량·상주 여유를 검증할 후보이며 필요성이나 144FPS가 입증됐다는 뜻이 아니다. 지정한 UHD 630의 60FPS 달성과 권장 장비의 165FPS 달성은 미검증이며 240Hz용 부품은 미정이다.

### CPU를 이렇게 선택한 이유

- i3-10100은 사용자가 선택한 최소 사양 검증 CPU다. 4코어/8스레드·UHD 630 내장 그래픽 사양은 [Intel 공식 명세](https://www.intel.com/content/www/us/en/products/sku/199283/intel-core-i310100-processor-6m-cache-up-to-4-30-ghz/specifications.html)를 따른다. 선택은 검증 기준의 확정이며 게임의 60FPS 실측 통과가 아니다.
- 2020년 제품군의 CPU·RAM·저장장치 선택지는 [Lenovo 당시 제품 자료](https://psref.lenovo.com/syspool/Sys/PDF/datasheet/ideacentre_3_07IMB05_datasheet_EN.pdf)를 참고했다. 시장 전체의 통일된 최저 사양이나 가장 많이 판매된 구성이라는 통계로 사용하지 않는다.
- 현재 메인 스레드의 경과 비용이 크다. 코어 수를 늘리는 것만으로 같은 루프가 빨라진다고 가정하지 않는다.
- 5600의 6코어/12스레드는 메인 스레드와 제한된 4개 CPU Work를 시험할 기준점이다. 로딩 Work가 4개라는 이유로 4배의 게임 FPS를 기대하지 않는다.
- 7600은 더 짧은 프레임 예산을 시험할 후속 기준점이다. 이 프로젝트에서 두 CPU의 실제 차이는 아직 측정하지 않았다. 특정 캐시 구조나 최고급 CPU가 반드시 필요하다고 정하지 않는다.
- CPU별 AI·충돌·HUD·렌더 제출의 p95/p99를 측정하고, 목표를 통과한 장비보다 아래 단계도 확인해야 최저선을 정할 수 있다.

제품의 코어·스레드·아키텍처는 [AMD Ryzen 5 5600](https://www.amd.com/en/support/downloads/drivers.html/processors/ryzen/ryzen-5000-series/amd-ryzen-5-5600.html), [AMD Ryzen 5 7600](https://www.amd.com/en/products/processors/desktops/ryzen/7000-series/amd-ryzen-5-7600.html) 명세를 확인했다. 모델 배치는 이 프로젝트의 잠정 검증 계획이며 제조사의 FPS 보장이 아니다.

### GPU·VRAM을 이렇게 선택한 이유

- 현재 경로의 핵심은 BC7 색상·무손실 RGBA 벡터·R8 그림자와 반복 보간이다. 이 게임에서 레이 트레이싱·Tensor 성능 때문에 해당 제품을 고른 것은 아니다. 현재 기능은 OpenGL compute shader와 BC7 지원도 확인해야 한다.
- 기준 GPU는 i3-10100의 UHD 630이다. 별도 VRAM 용량 대신 시스템 메모리 공유·대역폭·드라이버와 출력 단자를 실제 기준 장비에서 확인한다. CPU·GPU의 모델 지정과 정상 실행·목표 FPS 검증은 구분한다.
- 3060 12GB는 처리량과 별개로 여러 기종·추가 동작을 상주시킬 여유가 있는 기준 장비다. 8GB 이하에서 실패한다고 측정한 것은 아니다.
- 4060 8GB는 고주사율 FHD의 렌더 처리량을 확인할 후보이며, 3060 12GB보다 VRAM이 많다는 뜻이 아니다. 메모리 압박은 반드시 별도로 확인한다.
- 4060 Ti 16GB는 QHD 처리량과 향후 동작·기종 확장의 상주 여유를 함께 시험할 후보이다. 16GB가 QHD 해상도만으로 필요하다는 뜻은 아니다.
- 같은 기종 300대를 표시해도 에셋을 공유하면 텍스처 300벌을 적재하지 않는다. 기체별 자세·보간 입력·AI·충돌·그리기·겹침 비용은 별도로 늘어난다.

용량과 API 지원은 [NVIDIA RTX 3060 계열](https://www.nvidia.com/en-us/geforce/graphics-cards/30-series/rtx-3060-3060ti/), [RTX 4060 계열](https://www.nvidia.com/en-us/geforce/graphics-cards/40-series/rtx-4060-4060ti/) 명세를 확인했다. GPU 등급 배치는 잠정 제안이며 실제 게임 성능 비교 자료로 사용하지 않는다.

### RAM·SSD를 이렇게 선택한 이유

- 최종 1기 표본의 private bytes는 공격 계측 후 약 597MiB였다. 로컬 작업용 Unreal·이미지 제작 도구는 게임의 요구 RAM에 포함하지 않는다.
- DDR4 RAM 8GB는 사용자가 선택한 최소 사양 검증 장비의 전체 RAM이다. 내장 GPU는 메모리를 공유하므로 OS·백그라운드 점유와 채널 구성·공유 점유·페이지 파일 접근을 함께 검증한다. RAM의 채널 구성과 속도는 이번에 별도 확정하지 않았다. 비교군의 16GB는 측정 장비의 여유이며 최소 사양 RAM과 구분한다.
- Work 수를 제한해 준비 버퍼가 전체 아틀라스 크기만큼 무제한 늘지 않게 한다. VRAM 자원에 대한 드라이버의 시스템 메모리 사용도 기기별로 확인한다.
- SSD 256GB는 사용자가 선택한 기준 장비의 드라이브 용량이며 게임 설치 여유 공간 256GB를 요구한다는 뜻이 아니다. 초기 읽기·페이지 스트리밍 지연을 검증하며 특정 인터페이스·PCIe 세대·순차 읽기 속도는 확정하지 않았다. 이미 상주한 자원을 그릴 때 NVMe가 매 프레임의 CPU 비용을 줄이지는 않는다. HDD·SATA SSD·NVMe의 콜드 읽기는 미측정이다.

## 액션 확장과 Page Table VT 판단

사용자는 50% 표현 차이가 크지 않다고 관찰했다. 이는 현재 확인한 장면의 피드백이며 모든 동작·실제 QHD·더 낮은 해상도의 최종 품질 승인이 아니다. 추가 다운샘플링은 검토만 한다.

- 50%에서 전체 보간은 236MiB지만 `idle_loop/s`·`run_loop/s`·`combo_01/e` 한 클립의 색상+벡터 페이지 요구는 각각 약 19.75·18.46·19.04MiB였다. 이는 해당 클립이 참조하는 전체 페이지의 크기이고 프레임 자체의 크기가 아니다.
- 같은 데이터 밀도에서 동작이 20→40개로 늘어난다고 가정하면 보간+그림자가 기종당 대략 0.30→0.59GiB가 될 수 있다. 이 조건으로 5기종을 상주시킬 때의 단순 추정은 약 1.48→2.96GiB다. 40동작·5기종은 설명용 가정이며 사용자 확정 수량이 아니다. 실제 패킹·공유·NPC 모션 구성에 따라 달라진다.
- 따라서 전체 사전 적재를 계속 확대하기보다, 현재/다음 클립이 요구하는 페이지를 요청하고 상주 예산을 관리하는 방향을 우선 검토한다. 모션 전환이 예측 가능한 프리렌더 스프라이트에서는 GPU 가시성 피드백 없이 클립 메타데이터로 요청할 수 있다.
- 타일 단위 Page Table VT는 텍스처를 작은 고정 타일로 나눠 필요한 타일만 상주시키는 추가 구조다. 페이지 테이블 갱신·캐시 교체·필터 경계·선행 적재·미적재 대체 표현이 필요하다. 일반적인 타일 스트리밍과 추가 샘플 비용은 [Epic SVT 문서](https://dev.epicgames.com/documentation/en-us/unreal-engine/streaming-virtual-texturing-in-unreal-engine)를 참고했다. 이는 개념 근거이며 Pico2D에 Unreal 기능을 연결한다는 뜻이 아니다.
- 현 보간 셰이더는 이미 반복 벡터 조회와 모션 블러를 수행한다. 추가 간접 조회의 비용은 실제 셰이더에서 측정해야 한다. 이번 Work 구조는 나중의 페이지 요청에도 재사용할 수 있지만 그 자체가 VT 구현은 아니다.

37.5% 후보의 면적 비율 추정은 보간 약 133MiB·R8 그림자를 포함하면 약 200MiB이며 아직 생성하지 않았다. 현재 적용한 25% 품질은 재패킹 후 보간 약 65.96MiB·그림자를 포함하면 약 133MiB다. 이 자원 수치를 해당 품질의 FPS·로딩 시간 실측으로 해석하지 않는다.

기체 자원의 기본 배분 검토안 256MiB와 비교하면 현재 플레이어의 전체 모션·그림자만 약 303MiB로 이미 초과한다. 전체 시나리오 1GiB 목표를 충족하려면 기체 공유만으로 충분하다고 볼 수 없으며 현재/다음 클립의 필요 페이지와 그림자 시트를 선택적으로 상주시켜야 한다. 아직 상주 예산 관리·스트리밍은 구현하지 않았다.

## 최소 사양 확정에 필요한 다음 검증

1. 실제 AI·피해·충돌·탄환을 포함해 목표 수백 기를 재현하고, 활성 수와 실제 표시 수를 구분한다. 같은 기종 반복과 기종 증가도 분리한다.
2. CPU 갱신·그리기 준비/제출·GPU 실행·present·페이지 준비·전송을 나눠 측정한다. 기체 수에 단순 비례한다고 추정하지 않는다.
3. 고주사율 출력 정책과 시간 갱신을 검증한다. 모니터 주사율만큼 같은 프레임을 표시하거나 보간만 더하는 것을 게임 FPS 증가로 기록하지 않는다.
4. FHD/QHD, 현재와 증가한 동작 수, 전투·전환·카메라 이동·장시간 실행에서 평균·p95/p99·프레임 예산 초과 횟수·메모리 피크·로딩 중 끊김을 측정한다. 최소 60FPS·권장 165FPS 각각의 측정 구간 전체에서 예산 초과가 없는 것을 목표로 하며, 실기 보장 범위와 여유 목표는 따로 확인한다.
5. 표의 장비와 그보다 낮은 장비에서 같은 장면을 확인한 뒤 실제 최소/권장 사양을 확정한다.

원시 결과·구현 상태는 [병렬 적재 기록](ai-dev-log/2026-11-15-parallel-page-loading-target-spec.md)을 따른다.
