# Blender 모델 파이프라인 1차·플레이어 최종 기준·파일 정리

- **기록 ID: FDLOG-20261108-blender-model-pipeline-v1**
- 출처: 현재 대화. v001~v078 정보를 요약/개선한 파이프라인과 AGENTS 연결, 버전별 Python 생성 억제, 검사 독립 파일, 구버전 정리, **1차 최종 플레이어 모델** 명칭, player_mech 파일 통합 요청. 개별 발언 시각 미확인: [[FDLOG_MISSING_TIME:FDLOG-20261108-blender-model-pipeline-v1:request]] 해당 원문 시각으로 보완한다.

## 1. 사용자가 제안한 것

- **U1**: v001~v078 스크립트/연계 정보를 요약하고 개선해 Blender asset pipeline을 1차 구축하고 AGENTS에 연결한다.
- **U2**: 새 모델에도 공통 모듈을 사용하고 매번 Python 파일을 만들지 않는다. 검사는 별도 파일로 분리한다.
- **U3**: 용량을 차지하는 구버전 모델과 불필요한 player_mech 파일을 정리하고 필요한 정보는 역할별 파일로 통합한다.
- **U4**: v078을 정확히 **1차 최종 플레이어 모델**로 승격한다.

## 2. 사용자 제안 중 AI가 수용한 것

- 제작은 공통 모듈+JSON, 검사는 형상/UV/이미지/간섭 독립 실행 파일로 분리했다. 기존 프리렌더·패킹·게임 로더는 재사용한다.
- 파일 삭제 전에 실제 용량·최종 모델 외부 참조를 조사하고 구체적인 삭제 목록을 제시했다.
- 최종 플레이어 모델의 승인 범위를 형상/텍스처로 기록하고 전체 모션/게임 출력 완료와 구분했다.

## 3. AI가 제안한 것

- **A1**: 기준 파일 해시·수정 범위 고정, 새 후보 저장/재로딩, 확대/실제 크기 검토 렌더, 독립 검사별 결과를 제공한다.
- **A2**: 구버전 모델/백업 90개와 해당 렌더/중간 출력 약 2.30GiB를 삭제하되 최종 모델/스크립트/기록/텍스처/참고 자료는 유지한다.
- **A3**: 후속 파일 정리에서 과거 코드·설정·제어 문서는 실행 경로 밖의 단일 기록 압축파일로 보관하고, 필요한 부위 편집 기능은 공통 모듈로 옮긴다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U1/U2/U4는 사용자 명시 요청이다. A2는 “구버전 모델과 출력물 삭제 (약 2.30GiB)”를 선택해 승인했다.
- 이후 U3에서 불필요한 파일 제거와 필요한 파일 통합을 명시했다. 보존하기로 한 텍스처 원본/참고 이미지는 유지한다.

## 5. 반영 후 발견한 문제

- 초기 초안은 모델별 build(context) Python과 통합 검사였으나 U2에 따라 폐기하고 JSON 공통 연산/독립 검사로 변경했다. 이 초안을 현재 기능으로 설명하지 않는다.
- Blender의 GENERATED 이미지가 type 기반 필터에서 빠져 source 기준으로 수정했다. 독립 검사 CLI의 import 경로 오류도 수정해 별도 프로세스에서 실행을 확인했다.
- 테스트 임시 폴더 접근 제한으로 실행이 실패해 허용된 실행으로 확인한 뒤, 개발용 임시 파일은 프로젝트 output 아래에서만 만들고 정리하도록 개선했다.
- 정리 도중 최종 파일명이 player_mech.blend로 바뀌어 있는 것을 발견했다. 변경 주체는 확인하지 않았으며 파일 내용을 바꾸거나 이름을 되돌리지 않았다. v078과 동일한 SHA-256을 확인하고 참조를 현재 경로로 동기화했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- 제작: model_pipeline / model_operations / model_primitives / model_geometry / model_snapshot. JSON으로 기본 도형·단면 메시·변환·속성·재질/패킹을 처리한다. 부족한 일반 기능은 공통 연산으로 확장하도록 문서/AGENTS에 명시했다.
- 독립 검사: check_model_geometry / check_model_uv / check_model_images / check_model_collisions. 제작은 candidate_unchecked로 저장하며 품질 검사를 자동 실행하지 않는다. 설정/결과도 검사별로 나눈다.
- 부위/프로파일·본·재질·장착 편집 기능은 model_design / model_design_schema로 옮겨 v061 의존성을 제거했다. 새 레지스트리 추출기는 모델별 root/rig를 입력받는다.
- 로컬 release_v1.json에 **1차 최종 플레이어 모델**의 경로·해시·승인 범위를 기록했다. 모델은 복제하지 않았다. 최종 player_mech.blend는 원래 v078과 동일하다.

## 7. AI 해결 제안과 실제 해결 과정

- 524개 작업 스크립트를 실행하지 않고 정적 목록화했고 v001~v078 참조 누락이 없었다. 이는 버전 전체 재현 검증이 아니다.
- 승인한 구버전 모델/출력 244개 최상위 대상을 삭제해 **2,467,418,240 bytes(약 2.30GiB)**를 확보했다. 최종 모델 해시는 보존됐다.
- 과거 파일 672개를 약 1.1MB 기록 ZIP으로 보관하고 각 항목 해시/ZIP 무결성을 검증한 뒤 중복 개별 파일 670개와 캐시를 제거했다. 텍스처/참고 자료는 유지한다. 기록 ZIP은 Git 제외다.
- 새 모델 제작/실패 처리/해시/범위/UV·이미지 오류/Shape Key/장착 프레임 등 **Blender 회귀 테스트 9개 통과**. 기본 도형 후보 저장·재로딩·6장 렌더, 독립 검사 CLI 4개, 부위 편집 샘플을 확인했다.
- 최종 플레이어 모델에서 이미지/패킹, 지정한 가슴/팔 UV, 프레임 1 스커트/다리 간섭을 별도 실행해 통과했다. 전체 모델의 UV 겹침·모든 재질 노드·연속 충돌·전체 전투 모션·게임 재출력·UI 직접 조작은 이번 검증이 아니다.
- AGENTS.md와 모델 제작 안내를 연결했다. 실제 메카/기록 ZIP/로컬 레지스트리/렌더를 공개 코드에 포함하지 않는다.
