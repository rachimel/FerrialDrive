# FDrive 전투 장면 규모·이동 영역·ADV 실행 요구

- 출처: 현재 대화의 “Player랑 NPC, 또는 동료 메카, 적들”, “대략 수백개”, “이동가능 영역을 지정”, “전투 시스템 기획은 일단 이대로 Go”, “ADV만 별도로 스크립트 기반”, “주인공은 실루엣 처리”, “Ctrl키로 스킵”이다.
- 개별 요구와 진행 확인의 정확한 발언 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261108-fdrive-combat-scene-adv-requirements:scope]] 위 검색 구절의 원문에서 시각을 확인한다. 사용자 제안 1~3과 AI 제안 1~2에 공통 적용한다.
- 상태: **PRE-PRD의 기능 요구사항 반영**. 전투 장면·대규모 처리·ADV 구현이나 성능 검증 완료를 뜻하지 않는다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** FDrive 전투 장면에 플레이어·NPC·동료 메카·적이 존재해야 하며, 목표 적 규모는 대략 수백 기다. 전투 시스템 기획은 현재 방향으로 진행한다.
  - 이유·근거: 게임 기반 프레임워크가 지원할 전투 장면의 구성과 규모를 직접 지정했다. 정확한 개체 수와 목표 프레임률은 제시하지 않았다.
- **사용자 제안 2 (U2):** 높이맵의 필요성은 낮으며 이동 가능 영역을 지정하면 될 것으로 판단했다. 오브젝트 표시가 필요하고 배경에 합쳐 배치하는 방안도 검토했다.
  - 이유·근거: 높이 기반 지형 대신 단순한 통행 영역으로 초기 맵을 구성하려는 설명이다. 모든 오브젝트를 배경에 합친다는 확정은 아니다.
- **사용자 제안 3 (U3):** 전투 장면 안의 ADV와 별도의 스크립트 기반 ADV가 모두 가능해야 한다. Live2D 또는 일러스트 화상과 배경을 표시하고 주인공은 실루엣으로 처리한다. Ctrl키로 스킵하며 ADV UI는 차차 정한다.
  - 이유·근거: ADV의 실행 맥락과 표현 요구를 직접 제시했다. 전투 정지 여부와 스킵 세부 동작은 설명하지 않았다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1~U3를 PRE-PRD 5.3·7.4·7.5절과 8.4절에 기록한다. 첫 교전 프로토타입과 수백 기 목표 장면을 구분하고, 기존 전투 규칙의 미정 수치와 밸런싱은 그대로 남긴다.
- ADV의 공통 기능 요구는 공개 PRE-PRD에 두고, 개별 대본·분기·엔딩 등 핵심 서사와 구분한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1), 설계 검토:** 수백 기의 이동·충돌 후보 검색·AI 탐색·그리기와 정렬 비용을 구분해 확인한다. 공간 분할 자료구조와 경로 탐색·AI 갱신 주기를 실측 전에 확정하지 않는다.
  - 이유·근거: 장면에 존재하는 수와 화면 표시·AI 처리 수는 비용이 다르며, 현재 코드가 수백 기를 처리한다고 검증한 상태가 아니기 때문이다.
- **AI 제안 2 (A2), 기존 규칙과 정합:** 고정 장식은 배경 합성이 가능하되 파괴·상호작용·개별 상태·앞뒤 가림이 필요한 오브젝트와 구분한다. 시각 이미지와 이동·충돌 데이터를 별도로 관리한다.
  - 이유·근거: 기존 5.3절의 가림 오브젝트 검토안, 파괴물·그림자 분리, 이동 가능 데이터 분리 규칙을 유지하려는 판단이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1/A2는 이번 요구를 반영하면서 제시한 설계 검토와 기존 규칙의 적용이다. 사용자가 구체적인 공간 분할·AI 처리·경로 탐색·오브젝트 출력 방식을 승인한 것으로 기록하지 않는다.
- 전투 정지, Ctrl 유지/토글·읽은 대사/전체 스킵, 선택지·이벤트 처리와 ADV UI는 후속 결정 사항이다.

## 5. 반영 후 발견한 문제

- **발견한 문제 1 (I1), 범위 구분:** 적 한 기와 적 유형 3종의 초기 검증만으로 수백 기 목표의 성능을 충족했다고 판단할 수 없다. 기존 프로토타입과 목표 장면 규모를 구분할 필요가 있다.
- **발견한 문제 2 (I2), 표현과 데이터:** 오브젝트를 배경에 합치는 경우에도 시각 이미지가 통행·충돌 데이터를 대신하지 않는다. 가림·상태 변화가 필요한 대상을 전부 고정 배경으로 처리한다고 가정하지 않는다.
- 구현 후 발견한 실행 버그는 아니다. 이번 작업은 요구사항의 문서화다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1: 장면 구성과 수백 기 목표를 직접 지정했다. 초기 프로토타입 범위와 함께 문서에 기록한다.
- I2 ↔ U2: 높이맵 중심 요구를 줄이고 이동 가능 영역 지정과 배경 합성 방안을 제시했다. 필요한 상태·가림 처리는 기존 규칙과 구분해 남긴다.
- U3: ADV의 두 실행 방식·화상·배경·실루엣·스킵 요구를 추가하고 UI의 구체화는 후속으로 남겼다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 7.4절에 장면 구성·목표 규모·현재 전투 기획 진행을 기록하고 성능 검증과 정확한 처리 규모를 분리한다.
- I2: 5.3절에 고정 장식의 배경 합성 가능성과 이동·충돌 데이터 분리, 초기 높이맵 비필수를 명시한다.
- 7.5절에 ADV 실행·표현 요구를 두고 8.3·8.4절에서 공통 기능과 후속 설계를 연결한다. 구체적인 대본이나 서사는 포함하지 않는다.
- 확인 범위: 문서 요구사항·미정 사항·상대 링크·로그 형식·누락 인덱스와 공백을 확인한다. 게임 실행·대규모 성능·Live2D 합성·시각적 품질은 검증하지 않는다.
