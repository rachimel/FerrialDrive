## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 에셋에 시간을 오래 쓰지 않고 간단한 게임 전투 프로토타입을 먼저 만든다.
  - 이유·판단 근거: 사용자가 “너무 에셋에 시간 끌기도 그러하니까”라고 직접 설명했다.
  - 시각·출처: 현재 대화, 위 대화 범위의 TIME 누락 참조.
- **사용자 제안 2 (U2):** 직접 구현에 앞서 구조부터 함께 검토한다.
  - 이유·판단 근거: AI가 제시한 세 가지 진행 방식 중 사용자가 이 방식을 명시 선택했다. 별도의 선택 동기는 추가 해석하지 않는다.
  - 시각·출처: 현재 범위 질문 응답, 위 대화 범위의 TIME 누락 참조.
- **사용자 제안 3 (U3):** 첫 프로토타입의 최소 범위에 적 한 기까지 포함한다.
  - 판단 근거: 사용자가 “일단, 적 하나까지는 만들어야할듯”이라고 범위를 지정했다. 이 응답을 적의 종류·공격 패턴이나 직접 구현 지시로 확대하지 않는다.
  - 시각·출처: 현재 후속 사용자 발언, 위 대화 범위의 TIME 누락 참조.
- **사용자 제안 4 (U4):** 첫 적 행동 제안에 동의하면서, 공격 경고 표시는 보스 공격 같은 경우에만 두고 일반 적은 실력으로 회피하도록 정정했다.
  - 이유·판단 근거: 사용자가 “공격 예고는 보스의 공격 같은 것만 표시하고 일단 실력으로 피하는걸로”라고 직접 설명했다.
  - 시각·출처: 현재 후속 사용자 발언, 위 대화 범위의 TIME 누락 참조.

## 2. 사용자 제안 중 AI가 수용한 것

- U1: 정식 에셋을 기다리지 않는 전투 검증 방향을 수용했다. 현행 명세와 기존 구현을 조회했다.
- U2: 구현 전 구조 검토로 범위를 제한했다. 게임 코드·샘플 수치·현행 전투 명세를 변경하지 않았다.
- U3: 적 한 기와의 교전까지 도달하는 것을 최소 범위로 수용했다. 적 한 기의 배치만으로 완료 처리하지 않는 방향으로 검토한다.
- U4: 일반 적의 별도 경고 표시를 제외하고 보스급 특정 공격의 표시로 범위를 제한했다. 일반 적의 자연스러운 공격 동작과 별도 경고 표시는 구분한다.
- 수용 시각·근거: 현재 대화의 AI 진행 보고, 위 대화 범위의 TIME 누락 참조.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 도형 기체, WASD 이동·Shift 달리기·Space 대시·마우스 공격·E 검/총 전환·적 한 기·승패/재시작을 첫 범위로 제시했다. 미정 수치는 조절 가능한 임시값, 에너지·카운터·Break·Overdrive는 후속 단계로 제안했다.
  - 이유·판단 근거: PRE-PRD 첫 교전 범위를 작게 나누고 에셋 제작 의존을 줄이기 위함이다. **범위 제안이며 확정된 제외 목록이나 키 배치가 아니다.**
  - 시각·출처: 현재 AI 범위 질문, 위 대화 범위의 TIME 누락 참조.
- **AI 제안 2 (A2):** 입력 해석·전투 상태/규칙·화면 표현·독립 실행부를 분리하고, 속도·거리·시간·피해량은 설정으로 관리한다. 현재 공통 실행부·표시용 HUD 상태·렌더러를 재사용 후보로 둔다.
  - 이유·판단 근거: 테스트 실행부에 규칙을 넣거나 임시 그림에 공격 판정을 종속시키면 본편 연결과 에셋 교체 때 재작업이 커진다. 월드 좌표와 화면 좌표를 분리한다. 기존 HUD의 플레이어 앵커는 설정 기반이므로 이동하는 기체 연결은 별도 설계가 필요하다.
  - 시각·출처: 현재 구조 검토, 위 대화 범위의 TIME 누락 참조. 구현상 판단을 검토안으로 제시한 것이며 코드 반영은 없다.
- **AI 제안 3 (A3):** 첫 적은 접근→공격 예고→근접 공격→회수/빈틈을 반복하는 근접형 한 기로 제안한다. 공격 예고가 끝나면 공격 방향을 고정하고, 대시 회피·반격·양측 피격·승패/재시작을 검토한다.
  - 이유·판단 근거: 최소한의 상태로 적의 의도를 읽고 회피·반격하는 흐름을 확인하기 위함이다. AI는 플레이어와 같은 이동·공격·피해 규칙에 행동 요청을 전달하는 역할로 둔다.
  - 시각·출처: 현재 후속 구조 검토, 위 대화 범위의 TIME 누락 참조. 사용자 수용 전 제안이다.
  - **후속 정정:** U4에 따라 일반 적에 별도 경고 표시를 두지 않는다. 현재 행동 흐름은 접근→공격 준비 동작→근접 공격→회수/빈틈으로 정리한다. 준비 동작은 별도 범위·타이밍 경고 표시를 뜻하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1 중 적 한 기까지 포함하는 범위는 U3에서 사용자 요구로 명확해졌다.
- A3는 U4의 “ㅇㅇ”와 경고 표시 정정을 함께 반영한 **부분 수용**이다. 일반 적의 별도 경고 표시를 제외한다. 공격 시간·거리·방향 고정 시점 등 세부 값은 미정이다.
- 나머지 A1 세부 범위·수치·A2 구조는 확인 대기다. 구조 검토 단계이며 직접 구현 승인을 추정하지 않는다.

## 5. 반영 후 발견한 문제

- 코드 반영을 수행하지 않아 이번 변경으로 발생한 실행 문제는 평가하지 않았다.
- 조회상 연결 과제: 기존 `tests/ui_test.py`는 가짜 상태를 바꾸는 HUD 시연이며 실제 전투가 아니다. `UiView`의 플레이어 HP·레이더는 설정의 플레이어 앵커를 사용한다. 게임 연결 시 실제 기체 화면 위치와 동기화해야 한다. 실행 결함을 재현한 결과는 아니다.
- 설계 정정: A3의 “공격 예고”에 대해 사용자가 일반 적의 경고 표시를 제외하도록 범위를 명확히 했다. 구현 후 버그가 아니다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1: 에셋 제작을 기다리지 않는 프로토타입 방향을 제시했다. 이번에는 현황 조회와 구조 검토까지 수행했다.
- U2: 구현 전 구조 검토를 선택했다. 직접 구현은 진행하지 않았다.
- U3: 첫 완료 범위에 적 한 기를 포함하도록 검토 기록을 보완했다. 적 AI 코드는 작성하지 않았다.
- U4: 일반 적의 경고 표시 제외와 보스급 특정 공격의 예외를 PRE-PRD 6.1절에 반영했다.

## 7. AI 해결 제안과 실제 해결 과정

- 현재 명세와 코드 경계를 읽고 재사용 후보 및 좌표·판정·표현 분리 필요를 정리했다.
- 최초 구조 검토에서는 기록·로그 목록·누락 인덱스만 변경했다. 후속 U4까지 반영하며 PRE-PRD의 현재 우선순위도 프리렌더 에셋 제작에서 임시 에셋 전투 프로토타입으로 맞추고, 일반 적/보스급 공격의 경고 표시 기준을 추가했다. 관련 없는 기존 사용자 변경은 보존했다.
- 자동 검사·화면 렌더·창 조작·성능 검증·사용자 게임성 평가·커밋·업로드는 수행하지 않았다.
