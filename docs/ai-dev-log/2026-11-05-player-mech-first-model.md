# 플레이어 기체 첫 조형·저장 장면 렌더·그림자 조정

- 기록 ID: `FDLOG-20261105-player-mech-first-model`
- 기록 기준 시각: 2026-11-05 04:12:13 KST(작업 중 시계 확인).
- 출처: 현재 대화의 “그림자가 너무 스프레이 처럼”, “플레이어 기체 모델 하나만”, 레퍼런스 13장과 설명, 선택 응답 “1번 중심: 묵직하고 투박한 군용 비례”.
- 사용자 요청·대기 지시·참고 자료·선택과 개별 구현의 정확한 시각은 모른다. [[FDLOG_MISSING_TIME:FDLOG-20261105-player-mech-first-model:scope]] 보완 시 위 검색 구절과 “내가 레퍼런스 줄테니까 대기”의 원문 시각을 확인한다. 아래 U1~U3/A1에 공통 적용한다.
- 작성 시점 상태: 로컬 기체 모델·검토 렌더·8방향 본체/그림자 출력·실제 로딩 확인, 자동 검사 8개 통과. 직접 창 조작·조형/배색 승인·공격 동작·업로드는 미수행이다. 범용 코드의 기능 커밋 전 기록이다.

## 1. 사용자가 제안한 것

- U1: 기존 그림자가 스프레이처럼 보인다고 지적하고 플레이어 기체 모델 하나를 만들자고 요청했다. 이후 레퍼런스를 줄 때까지 대기하도록 했다. AI는 자료 도착 전 모델을 제작하지 않았다.
- U2: 1번 발더 불릿, 2번 아머드 코어6, 3번 발더 스카이, 4/5번 발더 스카이 프리렌더, 6번 발더 포스 프리렌더, 7~9번 반다이30mm, 10/11번 마브러브 얼터너티브라는 설명과 총 13장을 제공했다. 12/13번의 별도 번호별 출처는 직접 명시하지 않았다.
- U3: 비례 질문에 **1번 중심의 묵직하고 투박한 군용 비례**를 선택했다. 다른 이미지와 동등 비중으로 혼합하라는 요청으로 해석하지 않는다.

## 2. AI가 제안한 것

- A1: 작은 머리·넓은 흉갑·큰 어깨/전완/종아리와 장갑 사이 관절을 중심으로 첫 조형을 만들고, 작은 게임 화면과 8방향에서 읽히는지 확인한다. 4~6번은 프리렌더 가독성 기준으로 구분한다. 이는 AI가 설명한 참고 방식이며 모든 개별 조형 요소의 사용자 승인을 뜻하지 않는다.
- 첫 배색은 임시 올리브/샌드·적색 센서, 몸체는 강체 장갑과 관절로 구성한다. 무장·공격 동작·최종 잔디테일보다 본체 비례를 먼저 확인한다. 배색·관절 구조·상세 수치는 구현상 판단이다.
- 그림자는 샘플 증가·denoise·작은 광원으로 조정한다. 실제 기체는 본체128/그림자256 samples, 기본 샘플은64/128을 사용한다. 수치는 비교값이며 게임 렌더 규격 확정이 아니다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U3에 따라 기체 본체 v001을 Blender에서 만들었다. 로컬 작업본은 `data/models/player_mech/player_mech_v001.blend`, 생성 작업 코드는 `Tools/blender_pipeline/workspace/player_mech/`에 둔다. 86개 독립 메시와 강체 관절용13개 뼈·작은 대기 포즈를 구성했다. 전투 애니메이션 완성은 아니다.
- 사용자 제공 13장 원본 사본·번호별 설명·해시는 같은 에셋의 로컬 `references/`에 보관했다. 선택하지 않은 비례를 기체의 주 기준으로 바꾸지 않았다. 원본·작업 코드·레퍼런스·렌더는 Git 제외 대상이다.
- 1000px 정면·앞3/4·뒤3/4 검토 렌더와, 기본 샘플과 같은 게임 카메라/출력 배율의 160px×8방향×4프레임 본체/그림자를 생성했다.
- 기존 Asset Load Test에 `--scene`을 추가해 저장 장면 원본을 읽고 별도 작업본을 저장/재로딩한 뒤 출력한다. `ActorRoot`·`ShadowCatcher`·카메라를 갖춘 입력을 대상으로 한다. 입력 장면 해시를 캐시 조건에 포함하고 `idle` 등 설정 동작명을 보존했다.
- 같은 테스트를 쓰는 로컬 Runner 프리셋 `preview_player_mech.py`를 작업 폴더에 제공했다. 기본 공개 샘플에 기체 작업본을 필수 의존성으로 연결하지 않았다.

## 4. AI 제안 중 사용자가 수용한 것

- U3는 1번을 주 비례로 삼는다는 명시 선택이다. 실제 v001 조형·배색·샘플 수·세부 구조에는 아직 사용자 시각 승인 응답이 없다. AI 구현·검사 결과를 승인으로 취급하지 않는다.

## 5. 반영 후 발견한 문제

- I1: 사용자가 지적한 기존 분리 그림자의 점 노이즈는 최초 샘플의8 samples·denoise 비활성·큰 광원 설정과 함께 확인했다. 모델을 바꾸면서 렌더 설정도 조정했으므로 특정 설정 하나의 정량적 개선율을 주장하지 않는다.
- I2: 기존 첫 경로는 샘플 도형 재생성만 지원해 별도 제작한 `.blend`를 그대로 입력할 수 없었다. 이번 실제 기체를 확인하려면 저장 장면 입력이 필요했다.
- 남은 범위: 본체 조형과 비례는 초안이며 무장·공격·최종 디테일·실제 창 직접 입력·본편 연결·맵은 미검증이다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1의 레퍼런스 대기를 지켰고 U2/U3를 받은 뒤 제작을 시작했다. 사용자는 주 비례를 정했고, AI가 구체적인 메시·임시 배색·리그와 렌더를 구현했다. 조형의 사후 수정안은 아직 받지 않았다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 본체와 그림자별 샘플 수·denoise 설정을 분리하고 광원 크기를 줄였다. 실제 분리 그림자와 3배 확대 Pico2D 화면에서 점 노이즈가 줄고 형태가 이어지는 것을 확인했다. 그림자 알파를 지우거나 가짜 도형으로 대체하지 않았다.
- I2: 원본 `.blend`를 읽는 경로·원본 해시/캐시 무효화·설정 동작명 보존을 추가했다. 기체 장면에서 본체32장·그림자32장·시트2장·같은 피봇의 메타데이터를 생성하고 실제 로더로 읽었다. 렌더 도중 원본을 덮어쓰지 않는다.
- 자동8개 통과. 저장 장면의 내용 변경 시 캐시 재사용 거부와 사용자 지정 `idle` 이름 보존을 추가 확인했다. 기존 RGBA/알파·좌표·FPS·실패 게시 차단·편집기 호환·import 비실행 검사도 통과했다.
- 로컬 프리셋의 SDL dummy 3프레임 실행·8방향 전체/선택 확대/분리 그림자 화면을 확인했다. 실제 창 조작·사용자 시각 승인·GPU 성능과 구분한다. 기체 조형과 그림자 비교 이미지는 `output/player_mech/v001/`에 보관한다.
