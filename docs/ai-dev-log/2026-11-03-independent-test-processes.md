# Runner와 UI 테스트 실행 경계 분리

- 사용자 요청: Runner와 ui_test의 의존·재실행 경계를 정리해 독립적으로 만든다.

## 구현

- `ui_test.py`의 Runner import·TestProgram 상속·Stop/WindowSpec 사용·Tools 경로 추가를 제거했다. `UiTest`는 일반 클래스로 종료 상태를 가지며, 직접 실행 시 `ui/standalone.py`가 자체 Pico2D 창·입력·시간·렌더링·리소스 정리를 관리한다. 재사용 뷰·게임 UI 효과는 실행기와 독립된 구조를 유지한다.
- Runner GUI는 선택한 파일을 부모에 import하지 않는다. 소스 구문과 진입점 메타데이터만 읽고 별도 프로세스를 시작한다. 새 UI 진입점은 `UNIT_TEST_ENTRYPOINT="standalone"`으로 직접 실행한다. 기존 create_test 규약은 `worker.py`에서만 불러 실행하므로 기존 샘플은 유지된다.
- Runner 창과 테스트 창을 분리했다. 테스트 창 X·메뉴 종료는 해당 테스트만 종료하고 Runner는 다음 드롭을 받는다. 재드롭은 소유한 이전 자식 프로세스를 종료한 뒤 새로 시작한다. Runner 종료도 소유한 자식만 정리한다. 교체·강제 종료에서는 운영체제가 프로세스 리소스를 회수하며 테스트의 Python exit 콜백 실행은 보장하지 않는다. 정상 테스트 종료는 자체 정리 경로를 따른다.
- 매 실행은 새 프로세스·새 모듈 상태·별도 바이트코드 캐시 탐색 경로를 사용한다. 바이트코드 쓰기는 비활성화하므로 캐시 경로를 새로 생성하지 않는다. 같은 타임스탬프·같은 크기로 보조 소스를 바꾼 경우에도 기존 pyc를 재사용하지 않는다.
- 파일 경로는 인자 목록으로 전달하며 shell을 사용하지 않는다. 구문·파일 오류는 기존 테스트를 유지하고, 시작/실행 오류는 Runner에 표시한다. 자식 출력은 임시 파일에 받아 PIPE 정체를 피하며 종료 후 끝부분만 읽는다. 파일 인자 CLI·바로가기에도 같은 실행 경계를 연결하고 자식 종료 코드를 전달한다.
