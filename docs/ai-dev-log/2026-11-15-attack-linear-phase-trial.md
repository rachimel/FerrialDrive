# 공격 선형 위상 시험

**기록 ID: FDLOG-20261115-attack-linear-phase-trial**

- 작성: 2026-11-15 15:40:45 KST.
- 범위: Trail 등장 지연에 대한 보간 변경과 현재 곡선 확인.
- 개별 발언·적용·검사의 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261115-attack-linear-phase-trial:scope]] 현재 대화에서 `Trail이 등장하는 시간이 너무 느려`, `일단 linear로 바꾸고`, `지금은 smooth step이야`를 찾아 보완한다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1)**: Trail 등장 지연을 줄이도록 보간을 변경한다. 이유·근거는 사용자가 느낀 등장 지연이다. 출처: 현재 대화.
- **사용자 제안 2 (U2)**: 우선 linear를 시험하고, 마음에 들지 않으면 quint 등을 검토한다. 출처: 보간 범위 확인 질문에 대한 사용자 응답. **잠정 시험이며 quint 적용 승인은 아니다.**

## 2. 사용자 제안 중 AI가 수용한 것

- U1·U2에 따라 공격 설정을 linear로 변경했다. 재생 배속 1.5와 공격 이동의 constant 설정은 유지했다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1)**: 공격 전체를 linear로 바꾸어 검 동작·Trail·판정을 함께 앞당기는 범위를 제시했다. 이유는 각 요소가 같은 재생 위상을 사용하기 때문이다. Trail 표시만 변경하는 선택도 확인 질문에 함께 제시했다. 출처: 현재 대화의 범위 확인 질문.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1에 사용자가 `일단 linear로 바꾸고`라고 응답했다. 공격 전체의 선형 위상 시험을 수용한 것으로 적용했으며 외관·사용감 승인은 대기 상태다.

## 5. 반영 후 발견한 문제

- 이 설정 변경 뒤 새 문제는 자동 검사에서 발견하지 못했다. 실제 창의 사용감은 미검증이다.
- 요청 당시 등장 지연은 기존 동작에 대한 사용자 보고다. 사전 준비 기능의 첫 공격 멈춤 문제와 구분한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U2에 따라 `samples/sword_movement/movement_config.json`의 `combat.easing`을 accelerate에서 linear로 변경했다. 관련 샘플 안내와 독립 테스트 명세도 갱신했다. quint는 후속 후보로 남겼다.

## 7. AI 해결 제안과 실제 해결 과정

- 기존 accelerate는 `2t³−t⁴`이며 SmoothStep 속도를 누적·정규화한 위상이다. SmoothStep 위상 `3t²−2t³` 자체와 구분해 설명했다. 근거: `ferrial_drive/rendering/motion_vectors.py`의 `target_phase`.
- 현재 linear는 `p(t)=t`다. 본체·그림자·검 궤적·판정이 같은 위상을 유지한다.
- 자동 검사: `test_sword_movement.py`, `test_sword_effects.py`의 총 46개 통과. 실제 화면·조작 감각은 미검증이다.
- 커밋·업로드는 수행하지 않았다. 기존 미커밋 변경과 신규 모듈에 의존하는 작업 상태를 보존했다.
