## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 화면 해상도를 설정에서 조절하도록 요청했다. 출처는 현재 세션의 위 검색 단서이며 정확한 시각은 scope 누락 항목을 따른다. 앞선 Combat Test 최적화와 연결된 요청이다. 해상도별 성능 목표는 별도로 제시하지 않았다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1: 설정 메뉴에서 선택·취소·저장·즉시 적용·다음 실행 복원을 제공한다. 기존 품질·사용키 표시와 같은 설정 문서에 저장하며 기존 설정 파일에 항목이 없으면 프로그램 기본 창 크기를 유지한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1), 구현상 판단:** 1280×720·1600×900·1920×1080의 16:9 출력 크기를 제공한다. 기존 FHD UI·월드 좌표와 화면 구도를 유지하고 SDL 논리 크기 기능으로 표시·마우스 좌표를 함께 변환한다. 지원 크기·저장 즉시 적용 방침은 현재 세션 진행 보고에서 설명했다.
- 이유·근거: 고정 픽셀로 구성된 기존 HUD·메뉴·조준 좌표와 직접 연결되며, 실제 창·출력 픽셀 수를 조절할 수 있다. Pico2D 원본 수정 없이 기존 SDL 렌더러를 사용한다. CPU 최적화 또는 해상도별 FPS 달성을 의미하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1에 대한 별도 명시 수용은 현재 기록에 없다. U1의 구현상 선택으로 구분하며 사용자 승인을 추정하지 않는다.

## 5. 반영 후 발견한 문제

- **I1, 연결상 제약:** UI·게임은 FHD 논리 좌표를 사용하므로 실제 출력 크기만 바꾸면 입력·캡처 크기를 함께 확인해야 한다. 캡처는 기존 요청 크기로 surface를 만들고 있었으며 성능 보고서도 설정상의 논리 크기를 출력 크기로 기록하고 있었다. 새 기능 연결 과정에서 AI가 확인했다. 개별 확인 시각은 scope 누락 항목을 따른다.
- 표시 확인 중 해상도 구분 문자 `×`가 현재 버튼 글꼴에서 표시되지 않아 UI 버튼에는 `x`를 사용했다.
- 기존 전체 작업 트리의 `git diff --check`는 관계없는 과거 문서 두 줄의 후행 공백으로 실패했다. 해당 문서는 수정하지 않았다. 이번 수정 파일은 컴파일·실행 검사로 확인했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1: 해상도 항목을 기존 설정 메뉴에 추가했다. 기존 플레이 진행·위치·적 상태를 초기화하지 않으며 해상도 변경만으로 기체 아틀라스를 재로딩하지 않는다. 사용자 추가 수정안은 아직 제시되지 않았다.

## 7. AI 해결 제안과 실제 해결 과정

- A1 ↔ I1: `GameSettings.screen_resolution`과 `graphics.screen_resolution` 저장을 추가했다. `PicoCanvas`에서 실제 창 크기·SDL 논리 크기를 적용하고 저장 실패 시 이전 크기로 복귀한다. 이전 설정을 보존하는 원자적 저장 방식은 유지한다.
- 메뉴 패널 높이·행 배치를 조정해 텍스처 품질·화면 해상도·사용키 표시·뒤로/저장을 표시한다. 타이틀·일시정지의 기존 진입점을 공유한다.
- `save_frame`은 렌더러의 실제 출력 크기를 조회해 PNG를 만든다. 성능 보고서는 시작·종료 출력 크기와 논리 크기를 구분하고 변경 여부를 기록한다.
- 자동 검사: 설정·타이틀·팝업·보고서·UI v2·HUD 배치·도형 배치 총 117개 중 107개 통과·선택 GPU 등 10개 건너뜀. 저장 왕복·취소·비정상 값 거절·저장 실패 복원·SDL 출력 크기·논리 좌표·이동/누름/뗌 이벤트 매핑·실제 크기의 PNG를 확인했다.
- 실제 OpenGL: 도형 Combat Test에서 720p→900p→1080p→720p를 적용했다. 각 출력 크기·설정 재읽기·변경 직전/직후 플레이어 위치와 전투 시간 보존을 확인했다. 설정·전투 PNG를 생성했고 720p·900p 설정과 720p 전투 이미지를 직접 열어 표시를 확인했다.
- 벤치마크 연결 검사: 진단 프로세스에만 저장 해상도 1280×720을 제공해 10프레임 실행했다. 시작·종료 출력 1280×720, 논리 크기 1920×1080, 해상도 변경 여부 false를 확인했다. 이는 시작 적용·보고서 필드 확인이며 성능 비교 자료로 사용하지 않는다. 근거는 위 진단 폴더의 `benchmark/report.json`이다.

- 미검증: 실제 기체 에셋 전체·사용자 수동 조작·최소 사양 PC·해상도별 성능 비교·전체화면/비16:9 화면. 이번 기능은 창 출력 해상도 선택이며 전체화면 모드는 추가하지 않았다.
