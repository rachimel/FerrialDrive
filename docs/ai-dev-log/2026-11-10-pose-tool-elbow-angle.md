# Pose Tool 팔꿈치 각도와 손 추종

- 기록 ID: **pose-tool-elbow-angle**
- 기록 시각: 2026-11-10 13:24:33 KST
- 범위: 팔꿈치 각도 편집, 손 목표 추종, 저장 및 동작 출력. 원본 모델의 메시·rest 본·웨이트는 수정하지 않는다.
- 개별 발언 시각은 제공되지 않았다. [[FDLOG_MISSING_TIME:pose-tool-elbow-angle:scope]] 검색 단서: "팔꿈치 각도를 바꾸면 손 위치도 움직이게", "네 그렇게 구현해주세요".

## 1. 사용자가 제안한 것

**사용자 제안 1 (U1)**: 팔꿈치의 굽힘 각도를 직접 제어하고 각도가 바뀌면 손 위치도 움직이게 한다. 의도는 팔을 의도적으로 굽힌 자세를 쉽게 만드는 것이다. 근거는 현재 대화의 제어점 문제 제기와 위 인용 발언이다.

## 2. AI가 제안한 것

**AI 제안 1 (A1)**: 어깨·상박은 유지하고 하박과 손이 팔꿈치 관절축을 중심으로 함께 회전하게 한다. 손 위치 고정 IK와 충돌하지 않게 한다. 이유는 손 위치를 고정하면 팔꿈치 각도를 독립적으로 바꿀 수 없기 때문이다. 출처는 현재 대화의 구현 전 동작 설명이다.

구현상 판단: 새 FK 모드를 추가하지 않고 손·pole 목표와 IK 입력 자세를 함께 계산한다. 각도 입력·증분 버튼·좌우 드래그를 제공한다. 기준 리그의 정면 +X를 이용해 양의 굽힘 방향을 정하며, 음수는 반대 방향이다. -179.9~179.9도 입력 범위와 드래그 감도는 AI의 구현상 판단이며 사용자의 수치 승인으로 간주하지 않는다.

## 3. 사용자 제안 중 AI가 수용한 것

**U1 수용**: 팔꿈치 각도를 우선하고 손 목표도 함께 이동시키는 동작을 구현했다. 기존 손 목표 직접 이동과 손목·손가락 경로를 재사용했다.

## 4. AI 제안 중 사용자가 수용한 것

**A1 명시 수용**: 사용자는 "어 그러면 팔꿈치 각도를 바꾸면 손 위치도 움직이게 하는 식으로"라고 확인한 뒤 "네 그렇게 구현해주세요"라고 구현을 요청했다. 이후 전원 종료 뒤 재개를 요청했다. 내부 알고리즘·수치·최종 화면 사용감의 별도 승인은 아직 없다.

## 5. 반영 후 발견한 문제

**문제 1 (I1)**: 0도에서 프레임을 다시 평가하면 이전 굽힘이 남았다. 손 목표만 저장하고 새 상박·하박 입력 자세를 키에 저장하지 않은 것이 원인이었다.

**문제 2 (I2)**: 수치 검사는 통과했지만 전후 렌더에서 양의 각도가 등 쪽으로 접혔다. 원본의 미세한 역굽힘을 양의 굽힘으로 해석한 것이 원인이었다.

**문제 3 (I3)**: 기존 동작 출력 회귀 검사에서 `model_review` import가 실패했다. Blender 실행에서 모듈 경로 추가가 import보다 늦게 수행되고 있었다.

## 6. 사용자 해결 제안과 실제 해결 과정

**U1 / A1**: 손 위치 고정 대신 팔꿈치 회전에 손이 따라가도록 확인한 요구를 적용했다. 이후 사용자가 별도의 알고리즘 수정안을 제시한 것은 아니다. 전원 종료 후 재개 요청에 따라 저장된 파일과 검사 결과를 확인하고 남은 출력 오류를 처리했다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1**: 손·pole 목표, 상박·하박 입력 자세와 pole angle을 함께 키에 저장했다. 같은 각도 반복 적용은 누적 회전을 만들지 않도록 했다. 실패·드래그 취소용 자세 복구와 양손 고정 해제/복구를 연결했다.
- **I2**: 좌우의 실제 굽힘 면과 rest 축을 각각 사용하고 기준 정면을 기준으로 부호를 정했다. 앞쪽 굽힘을 독립 검사하고 전후 6면·양팔 확대 16장을 확인했다.
- **I3**: `animation_pipeline.py`의 기존 모듈 경로 추가를 `model_review` import 앞으로 이동했다. 검사·승인 함수를 우회하지 않았다.
- **자동 검사**: Blender 5.2.3 LTS에서 기본 도형 `output/pose_tool/elbow_angles_20261110_sample_v2/`와 실제 메카 `output/pose_tool/elbow_angles_20261110_model_v2/` 검사 통과. 양팔 각도 표본 22개씩, 0도·역방향·179.9도 경계, 상박 유지·손 추종·반대 팔 보존·반복 적용·기존 손 IK·취소용 복구·저장/재로딩·원본 해시 보존을 확인했다.
- **출력 회귀**: `output/pose_tool/elbow_angles_20261110_regression_v2/`에서 기존 파츠 편집·저장·동작 굽기·렌더 설정 생성 검사 `POSE_NATIVE_CHECK_OK` 통과.
- **미검증**: 실제 창의 마우스 드래그·Undo 입력, 사용자 사용감 승인, 전체 가동 범위의 장갑 간섭과 무기 핏. 무릎 각도 제어와 어깨 상하부 연동은 이번 팔꿈치 변경에 포함하지 않았다.
