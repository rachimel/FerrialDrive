## 1. 사용자가 제안한 것

- **U1:** 검의 시각용 궤적·정점을 GPU에서 계산하고, 전신 잔상에 기존 프레임 보간 데이터를 재사용한다. 의도는 효과 사용 시 렉 완화다. 근거는 현재 대화의 GPU 계산 셰이더·보간 데이터 재사용 발언이다.
- **U2:** `그러면 계측 한 번 돌려봐.` 원인 추정을 실측으로 확인하도록 요청했다. 개별 시각은 위 scope 태그로 보완한다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1: 가능한 설계 방향으로 검토했다. 현재 잔상은 원본·모션 벡터를 공유하지만, 보간된 최종 픽셀은 매 프레임 다시 계산함을 확인했다. 구현·성능 개선 확정으로 취급하지 않는다.
- U2: 수용하여 같은 입력에서 효과별 그리기 생략·보간 생략·HUD 생략을 비교했다. 수용 근거는 본 대화의 계측 시작 보고와 아래 실행 결과다.

## 3. AI가 제안한 것

- **A1:** 생성·충돌 판정 비용과 시각 효과 그리기 비용을 분리하고, 기존 `TimingRecorder`·`GpuFrameTimer`로 CPU 경과와 GPU elapsed를 함께 기록한다. 이유는 GPU 이전이 실제 병목에 맞는지 확인하기 위해서다. 제안 근거는 본 대화의 비교 계측 안내이며 개별 시각은 scope 태그 대상이다.
- **A2:** 결과 확인 후 HUD의 정적 도형 재사용·제출 묶기, 효과의 반복 그리기 준비 공유를 우선 검토한다. 위 결과 확인 시점을 근거로 도출한 AI 제안이며 구현하지 않았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1의 계측 진행은 U2로 요청받았다. 상세 비교 조건과 A2의 최적화 구현에 대한 별도 사용자 수용은 확인하지 않았다.
- GPU 이전·잔상 결과 캐시는 제안 상태다. 계측 실행을 제품 변경 승인으로 확대하지 않는다.

## 5. 반영 후 발견한 문제

- **I1:** 사용자는 Trail·잔상 사용 중 렉을 보고했다. 제품 수정 전 조사이므로 새 수정으로 생긴 회귀로 단정하지 않는다.
- RTX 5070 Laptop GPU, OpenGL 4.6, 1920×1080, 현행 high 품질, 레벨 3 오른쪽 연속 공격에서 기본 CPU 프레임 평균 14.665ms, p95 19.661ms였다. 제한 없는 실행의 측정 프레임 중 28.2%가 16.67ms를 넘었다.
- 기본 CPU 구간 평균은 HUD 9.819ms, 잔상 그리기 0.999ms, Trail 그리기 0.595ms, 검 효과 갱신 0.350ms였다. 중첩 구간은 합산하지 않는다.
- GPU draw elapsed 평균은 0.439ms였다. GPU 포화보다 CPU 도형 생성·준비·반복 제출이 우선 병목이라는 해석을 지지한다. CPU 값은 드라이버 대기를 포함한 경과 시간이며 CPU 점유율이 아니다. GPU query도 제출 공백을 포함할 수 있다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1: GPU 계산·보간 결과 재사용의 구현은 진행하지 않았다.
- 잔상 보간만 생략한 진단 경로는 CPU 프레임 평균 14.755ms로, 기본보다 개선되지 않았다. 보간된 픽셀의 GPU 텍스처 캐시와 동일한 구현은 아니므로 캐시의 실제 이득을 확정하지 않는다.
- I1 ↔ U2: 게임 코드·사용자 설정을 유지한 별도 계측 실행부를 만들고 실제 창에서 자동 입력했다. 화면 제한·VSync를 끄고 고정 60Hz로 갱신했다.

## 7. AI 해결 제안과 실제 해결 과정

- I1 ↔ A1: 기본/잔상 생략/Trail 생략/둘 다 생략/잔상 보간 생략/검 효과 갱신·그리기 생략 6조건을 각 3회 측정했다. 회당 60프레임 예열과 240프레임 측정, 120프레임마다 위치·공격 초기화를 적용했다. 실행 순서를 회차마다 순환했다.
- CPU 평균은 기본 14.665ms → 잔상 생략 13.673ms, Trail 생략 13.996ms, 둘 다 생략 13.161ms, 검 효과 갱신·그리기 생략 12.785ms였다. 잔상 10개 이상인 프레임은 기본 18.642ms → 둘 다 생략 15.339ms였다.
- HUD 표시만 생략한 별도 대조 2회에서는 기본 14.741ms → 4.652ms였다. 지형·기체·검 효과는 유지했다.
- 별도 cProfile 240프레임에서는 UI `filled_triangle` 109,920회(458회/프레임), 무기 카드·보조 슬롯 도형 경로와 정점·좌표 객체 생성 비용이 크게 잡혔다. 이 실행은 계측 오버헤드 때문에 약 28ms/프레임으로, 기본 성능 비교에 포함하지 않았다. 패널 범위 수집용 순회를 화면 이중 렌더로 해석하지 않는다.
- I1 ↔ A2: CPU 준비와 제출 횟수 감소를 우선순위로 제시한다. 최적화 코드와 시각 결과 변경은 없다.
