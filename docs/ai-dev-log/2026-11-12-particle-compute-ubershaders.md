# 파티클 생성·갱신 Compute Ubershader와 대량 스트레스 테스트

- **기록 ID:** `FDLOG-20261112-particle-compute-ubershaders`
- 대화 범위: 2026-11-12 현재 대화. 개별 제안·수용·증상 보고의 정확한 시각은 미확인 — [[FDLOG_MISSING_TIME:FDLOG-20261112-particle-compute-ubershaders:scope]]. 현재 대화의 `생성용이랑 갱신용 Compute Ubershader 두 개`, `Massive Energy Particle Stress`, `이 범위로 정리해`, `옵티머스` 발언을 검색한다.
- 기록 작성 기준 시각: 2026-11-12 20:21:00 KST.
- 근거: 현재 대화, UI v2 명세·샘플, 실제 OpenGL 검사·벤치마크 출력.
- 상태: 구현·자동 검사·숨긴 실제 GPU 렌더 검토. 직접 창 조작·본편 연결·최종 외관 승인은 별도다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** CPU의 입자 생성·갱신을 GPU로 옮기고 생성용·갱신용 Compute Ubershader 두 개로 구현한다. 입자 수가 적을 때의 상태 전환 비용을 고려했으며, 효과별 셰이더 분리는 switch의 실제 병목이 확인된 뒤 검토한다.
- **사용자 제안 2 (U2):** 독립 Unit Test **Massive Energy Particle Stress**에서 대규모 파티클을 벤치마크하고 미사용 기능의 테스트·문서를 정리한다. 삭제 후보를 먼저 보고 결정하도록 요청했다.
- **사용자 제안 3 (U3):** 후보 목록을 보고 `이 범위로 정리해`라고 명시 수용했다. 승인 범위는 이전 렌더 검사 파일 1개, CPU 흡수 경로 검사 4개, 기존 UI의 CPU 흡수 검사 3개와 현행 문서의 이전 파이프라인 설명이다. 필요한 아틀라스·HP 검사와 과거 개발 로그는 보존한다.
- **사용자 보고 1 (U4):** 파티클 실행 때 UI 깜박임·글자 일시 왜곡을 관찰했다. 사용자는 내장 GPU 부하·옵티머스를 원인 후보로 제시했으며 원인 확정은 하지 않았다.
- 개별 발언 시각은 위 scope 누락 범위다.

## 2. AI가 제안한 것

- **AI 구현상 판단 1 (A1):** CPU에는 생성 요청과 시간 명령만 두고, GPU 풀·경로 선택·201개 경로 좌표·수명·현재 위치·Trail 좌표·활성 목록·간접 그리기 개수를 GPU에서 처리한다. 프레임 중 입자 상태 readback은 하지 않는다.
- **AI 구현상 판단 2 (A2):** 풀은 순환 슬롯을 재사용한다. UI는 기존 상한 24개, 스트레스 기본값은 16,384개다. 가득 차면 이전 생성 슬롯을 덮어쓴다. 공용 아틀라스·방향별 6개 경로 제어점은 로딩 시 한 번 전송한다.
- **AI 구현상 판단 3 (A3):** 스트레스 프로그램은 30프레임 예열·120프레임 측정·고정 1/60초로 CPU 제출과 GPU 생성/갱신/렌더 시간을 나눠 기록한다. 프로그램 컴파일·링크는 로딩 시 수행하며 디스크 바이너리 캐시는 이번 구현 범위가 아니다.
- **AI 제안 1 (A4):** 삭제 후보를 제한해 제시했다. 기존 파티클 파일의 유효 아틀라스 검사를 새 GPU 검사로 옮기고 다른 기능과 개발 이력은 유지한다.
- 근거는 이번 코드·검사·현재 대화이며 정확한 제시 시각은 scope 누락 범위다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U3를 구현했다. 생성·갱신 프로그램은 두 개이며 각 effect_type switch의 현재 지원은 에너지 오브 0이다. 이후 효과별 함수·프로그램 분리를 미리 구현하지 않는다.
- U4는 사용자 관찰로 기록한다. 원인을 그래픽카드 고장·내장 GPU·옵티머스·코드 결함 중 하나로 확정하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A4의 구체적 정리 범위는 사용자 답변 `이 범위로 정리해`로 수용됐다.
- A1~A3의 풀 구조·측정 수치·세부 구현은 구현상 판단이며 사용자 최종 외관 승인으로 취급하지 않는다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1):** 초기 GPU 타이머 쿼리 풀이 부족해 대량 측정의 일부 프레임을 놓쳤다. 예열·측정 프레임 수에 맞춰 쿼리를 미리 확보한 뒤 각 단계 120개 샘플 수집을 확인했다.
- **문제 2 (I2):** U4의 UI 깜박임·글자 왜곡은 원인 미확정이다. 새 프로세스는 `NVIDIA GeForce RTX 5070 Laptop GPU`·OpenGL 4.6·드라이버 592.01을 보고했다. 기존 창과 새 실행의 GPU가 같다고 추정하지 않는다.
- **문제 3 (I3):** 자동 벤치마크 검사 한 건이 임시 폴더의 로그 저장 중 멈췄다. 타임아웃 스택은 GPU가 아닌 tempfile 저장을 가리켰다. 검사 출력 임시 폴더를 작업 공간의 output 아래로 지정한 뒤 통과했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I2 ↔ U4: 사용자는 내장 GPU 부하·옵티머스를 후보로 제시했다. 실제 선택된 GPU를 테스트 UI·결과 JSON에 표시하고 서로 다른 GPU의 결과 파일을 구분했다. 시스템 GPU 설정은 AI가 변경하지 않았다.
- U3 ↔ A4: `tests/rendering/test_ui_particles.py`를 삭제하고 유효 아틀라스 검사 1개를 새 GPU 검사로 옮겼다. `AbsorptionRouteTests` 4개와 UI의 이전 CPU 흡수 검사 3개를 제거했다. HP·다른 UI 검사와 과거 기록은 보존했다.

## 7. AI 해결 제안과 실제 해결 과정

- I1 ↔ A3: 기본 네 입자 수에서 GPU 갱신·렌더 각 120개 샘플, 생성 요청 각 2개 샘플을 수집했다. 생성 total_ms는 좌우 요청 합이고 mean_ms는 요청당 평균이다.
- I2 ↔ A1: 같은 버퍼를 셰이더·버퍼 갱신 API·간접 그리기에서 재사용할 때의 배리어를 보강했다. 고정 UI 글자 영역을 16프레임 비교한 자동 검사에서는 픽셀 변화가 없었다. 이 결과를 사용자 환경의 간헐적 화면 왜곡 해결로 확대하지 않는다.
- **자동 검사:** UI v2 81개·CPU 요청/독립 실행 6개·실제 OpenGL 렌더 17개, 총 104개 통과했다. GPU 생성·수명·이동·경로 고정·리본 필압·순환 풀·GPU 초기화·읽기 없는 프레임·타이머·리소스 해제·렌더 상태 복원·벤치마크 샘플 수를 확인했다.
- **렌더:** 기본 도형으로 좌우 피격·흡수 120프레임과 스트레스 화면을 출력하고 주요 이미지를 직접 열었다. 미리보기는 `output/compute_particles/ui_compute_preview.gif`다. 직접 창 키·마우스 조작과 구분한다.
- **RTX 벤치마크:** `output/performance/massive_energy_particle_stress_rtx5070.json`. 16,384개 활성 수 일치, GPU 생성 두 요청 합 약 0.186ms·프레임 갱신 평균 약 0.078ms·렌더 약 0.554ms다. 예열 30·측정 120프레임, 해상도 1280×720·Trail 24구간 조건이다. CPU 제출·GPU 단계 시간·UI/present·전체 프레임 성능을 구분한다.
- **미확인:** 사용자 화면 깜박임의 원인·실제 창 사용감·본편 전투 연결·최종 외관 승인. 업로드는 수행하지 않는다. 기능 커밋은 Git 기록에서 구분한다.
