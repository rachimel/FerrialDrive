# 전투 에셋 분류·맵 구역 출력·바닥 기준 판정

- 기록 ID: `FDLOG-20261105-prerender-asset-types-map-chunks`
- 기록 기준 시각: 2026-11-05 02:03:40 KST(작업 중 시계 확인).
- 출처: 현재 대화의 “기본적인 에셋들에 대한 정의”, “전체 3D 맵을 미리 베이킹”, “바닥과 배경을 구역별로 합치는건 찬성”, “나중에 높이가 필요한지” 발언과 사이의 AI 답변.
- 각 제안·수용 발언의 정확한 시각은 모른다. [[FDLOG_MISSING_TIME:FDLOG-20261105-prerender-asset-types-map-chunks:scope]] 보완 시 위 검색 구절과 후속 “높이 별로 통행 가능 여부” 발언의 원문 시각을 확인한다. U1~U4/A1~A2 및 I2 정정에 공통 적용한다.
- 상태: 요구사항·설계 방향 문서 반영. 도구 확장·렌더링·게임 판정은 미구현·미검증.
- 현재 정의 정정: **높이맵은 위치(X, Y)·높이(Z)별 통행 가능 여부를 저장하는 데이터**다. 아래 A2의 지면 높이 해석은 당시 AI의 오해이며 후속 U4로 정정했다.

## 1. 사용자가 제안한 것

- U1: 플레이어·적 등 움직이는 엔티티는 모델·애니메이션을 제작해 8방향으로 렌더하고, `SSheetCutil.py`를 확장해 시트와 애니메이션을 다룬다. 고정/파괴 오브젝트는 3/4 시점으로 렌더한다.
- U2: 전체 3D 맵을 제작한 뒤 조각별로 렌더하는 방식을 제시했고, 후속 발언에서 바닥·배경을 구역별로 합치는 데 동의했다. 파괴물 제거와 함께 그 그림자도 사라지게 한다.
- U3: 충돌·이동 가능 영역은 우선 바닥 데이터와 일치시킨다. 높이가 필요한지는 미정이며, 필요해지면 높이맵을 검토한다.
- U4: “높이맵은 높이 별로 통행 가능 여부를 저장한거”라고 정의를 명확히 했다. AI의 지면 높이 해석을 바로잡는 사용자 직접 정정이다. 높이 판정의 즉시 도입 요청으로 바꾸지 않는다.
- 내용·의도는 사용자 직접 발언을 기준으로 한다. 이 분류·맵 출력 방식·높이 보류를 선택한 추가 이유는 모른다. [[FDLOG_MISSING_REASON:FDLOG-20261105-prerender-asset-types-map-chunks:U1-U3]] 보완 시 위 사용자 발언의 의도 설명을 확인하며, AI의 설계상 이점을 사용자 이유로 대체하지 않는다.

## 2. AI가 제안한 것

- A1: 바닥·배경은 구역별로 합치되, 플레이어와 앞뒤 관계가 바뀌는 가림 오브젝트 및 파괴물은 별도로 출력하는 방향을 권했다.
  - 이유·근거: 한 장에 합친 배경만으로는 이동하는 엔티티의 앞뒤 가림과 파괴 상태 변화를 처리하기 어렵다는 구조 검토다. 구역 밖 형상이 만드는 그림자·경계 이음새도 검증 대상으로 제시했다.
- A2: 시각 출력과 판정은 같은 바닥 좌표를 사용하되 별도 정보로 유지하고, 높이 정보와 통행 가능 여부를 구분한다.
  - 이유·근거: 바닥 높이만으로 오브젝트 장애물 여부를 표현한다고 가정하지 않기 위해서다. 현행 PRD의 장애물 추가/제거·중첩 처리 규칙을 유지한다.
  - 후속 정정: 프로젝트 높이맵을 지면 높이 데이터로 본 부분은 잘못된 해석이다. U4의 높이별 통행 가능 데이터 정의를 현재 기준으로 사용한다.
- 도구 소스 검토: 기존 시트 도구에는 프레임 영역·피봇·FPS·JSON 저장과 재생이 있다. 렌더 이미지 패킹과 8방향 대응은 추가 개발 대상이며, Sonic 전용 플레이/이벤트의 분리는 AI 구조 개선안이다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U3를 PRE-PRD 5.3·5.4절과 Blender 제작 안내에 반영한다. 반복 타일 조립과 기존 타일 단위 기체 크기를 현재 맵 제작의 전제로 두지 않는다.
- 파괴물과 연결 그림자의 제거, 바닥 기준의 초기 판정, 높이맵의 조건부 검토를 명시한다. 구역 크기·출력 해상도·판정 데이터 추출 형식은 정하지 않는다.
- U4를 수용해 두 기준 문서에서 높이맵 정의를 정정한다. 기존 0/1 통행 판정의 높이별 확장으로 설명하고, 실제 도입 시점과 저장 방식은 계속 보류한다.

## 4. AI 제안 중 사용자가 수용한 것

- A1 중 바닥·배경 구역 합치기와 파괴물 그림자 제거는 사용자 후속 발언으로 명시 수용했다.
- 별도 가림 오브젝트의 정렬 구현 방식, 구역 경계 처리 방법, Sonic 전용 부분의 분리 방식은 사용자 확인 전 설계안이다. 높이맵 역시 즉시 구현 확정이 아니다.

## 5. 반영 후 발견한 문제

- 새 렌더·게임 기능을 실행하지 않아 반영 후 동작 문제는 검증하지 않았다.
- I1: 반영 전 문서에 반복 타일 기반 맵과 새 제작 도구의 시트 작업 전담 문구가 남아 있어 최신 사용자 정의와 차이가 있었다. 기존 기준 문서의 갱신 대상이며 새 구현 버그가 아니다.
- I2: AI가 높이맵을 지면 높이 데이터로 해석해 문서에 반영한 뒤 사용자가 U4로 정정했다. 원인은 AI의 용어 해석 오류이며, 게임 동작 버그가 아니라 문서의 의미 오류다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1/U2/U3: 사용자 정의에 따라 맵 출력 단위·도구 역할·바닥 판정·높이 보류를 갱신한다. 기존 메카 충돌 영역·장애물 갱신 규칙은 보존한다.
- I2 ↔ U4: 사용자의 정의에 따라 위치·높이별 통행 가능 여부로 바로잡는다. 높이별 0/1 판정과 초기 바닥 기준의 단계 구분을 유지한다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 두 기준 문서와 기록 인덱스를 갱신하고 이전 반복 타일 전제의 잔존 여부·로컬 링크·공백을 확인한다. 이전 문서 변경과 사용자 보완은 보존한다.
- I2: PRE-PRD와 Blender 제작 안내의 잘못된 지면 높이 정의를 교체하고, 이 기록에는 당시 AI 해석과 사용자 정정을 구분해 남긴다. 누락 태그 수는 변하지 않으며 기존 scope 태그에 후속 정정 시각을 포함한다.
- 실제 시트 도구 수정·Blender 실행·에셋 생성·청크 경계·가림·그림자 제거·이동 판정 검증은 수행하지 않는다. 이번 결과는 문서 반영이다. 커밋·업로드는 수행하지 않는다.
