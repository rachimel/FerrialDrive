# FDrive 초기 책임·독립 테스트·선택적 성능 계측

- 출처: 현재 대화의 “게임의 Base가 될 Framework”, “Unit Test에서 FDrive의 기능들을”, “성능 측정 모듈도 FDrive에 선택적으로 Binding”, “이걸 PRE_PRD에 반영해줘”와 직전 AI 구조 리뷰다.
- 제안·수용·반영 요청의 정확한 발언 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261108-fdrive-framework-binding-plan:scope]] 위 검색 구절의 원문에서 시각을 확인한다. 사용자 제안 1~2와 AI 제안 1~3, 수용에 공통 적용한다.
- 상태: **설계 방향의 문서 반영**. FDrive 코드 구현·이관·실행 검증은 수행하지 않는다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 게임의 기반이 될 FDrive를 구성하고 독립 Unit Test에서도 같은 기능을 사용한다. 기존 성능 측정 모듈을 선택적으로 Binding할 수 있도록 초기부터 설계한다.
  - 이유·근거: 사용자는 UI가 대략 만들어진 상태에서 게임 기반 프레임워크가 필요하며, 기존 측정 모듈을 선택적으로 연결하겠다고 설명했다.
- **사용자 제안 2 (U2):** AI의 구조 리뷰에 동의하고 PRE-PRD에 반영하도록 요청했다.
  - 이유·근거: “ㅇㅇ 이걸 PRE_PRD에 반영해줘”라는 명시 요청이다. 구현을 요청한 것으로 확대하지 않는다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1의 공통 기능 사용과 선택적 계측을 FDrive의 초기 설계 원칙으로 기록한다.
- U2에 따라 PRE-PRD 7.1~7.3절에 책임·의존성·연결 규칙·첫 구현 목표를 기록하고 8.4절의 미정 기술 항목과 맞춘다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 공통 실행부, 시간·입력, 장면 관리, UI·애니메이션·에셋 기능, 계측 연결부, 본편·테스트 구성을 구분한다. 본편과 테스트는 FDrive를 사용하고 Runner는 별도 프로세스 실행을 담당한다.
  - 이유·근거: `ui/standalone.py`에 창·루프·시간·입력·종료 책임이 있고, 테스트와 재사용 UI 상태가 이미 일부 분리된 실제 구조를 검토했다. 로드아웃·무기 규칙이 공통 기능에 섞일 위험을 줄이려는 제안이다.
- **AI 제안 2 (A2):** TimingRecorder를 재사용하고 실행 시작 시 선택적으로 연결한다. 계측 기본 비활성, 구간별 측정, 중복 연결 방지, 실행 쪽의 저장 정책을 둔다.
  - 이유·근거: 기존 측정기는 비활성 시 원함수를 그대로 반환한다. 현재 UI 테스트가 객체별 메서드를 직접 감싸는 방식을 테스트마다 반복하지 않도록 공통 연결 원칙이 필요하다.
- **AI 제안 3 (A3):** 기존 UI Unit Test를 최소 FDrive 실행부에 연결하는 것을 첫 구현 목표로 하고, 동일한 입력·시간 조건에서 계측 활성 여부에 따른 상태·호출 의미를 비교한다.
  - 이유·근거: 실제 사용처에서 공통 책임을 추출하고 불필요한 엔진 확장을 피하려는 제안이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U2의 명시 요청으로 A1~A3를 설계 방향으로 수용했다. 실제 패키지 경로·클래스명·공개 API·구현 알고리즘의 확정이나 코드 작성 요청은 아니다.

## 5. 반영 후 발견한 문제

- **발견한 문제 1 (I1), 기존 구조의 설계 검토:** 공통 실행 책임이 UI 미리보기 모듈에 있고 UI 테스트가 계측 연결을 직접 관리한다. 게임과 여러 독립 테스트에 확장할 때 책임과 연결 방식이 중복될 수 있다. 현재 실행 버그로 확정한 것은 아니다.
- **발견한 문제 2 (I2), 문구의 범위:** 계측 비활성 시 타이머를 읽지 않는다는 요구는 계측을 위한 조회에 해당한다. 실행 루프의 프레임 시간 계산까지 금지하는 뜻으로 해석하지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1: FDrive 기능을 본편·Unit Test에서 공통으로 사용하고 성능 측정의 선택적 연결을 초기 설계에 포함하도록 제시했다.
- U2: 합의한 내용을 현재 기획 문서에 반영하도록 요청했다. 이번 작업은 문서화에 한정한다.

## 7. AI 해결 제안과 실제 해결 과정

- I1 ↔ A1~A3: PRE-PRD에 공통 실행부와 테스트·본편·Runner의 책임, 계측 연결 수명과 저장 정책, UI 테스트를 통한 첫 연결 목표를 기록한다.
- I2: 프레임 시간 계산과 성능 계측의 타이머 조회를 구분하고, 활성/비활성 비교도 실행 속도의 일치가 아닌 상태·호출 의미의 유지로 명시한다.
- 확인 범위: PRE-PRD의 기존 범위와 미정 사항, 상대 링크·로그 7개 절·누락 인덱스·공백을 확인한다. 게임 실행·계측 성능·UI 사용감은 검증하지 않는다.
- 기존 UI·폰트·기체 작업의 변경은 이번 커밋에 포함하지 않는다. 로컬 전용 서사와 제품명 후보는 다루지 않는다.
