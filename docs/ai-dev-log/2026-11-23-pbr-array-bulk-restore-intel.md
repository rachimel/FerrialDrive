# PBR 배열 바인딩 일괄 복원과 Intel 내장 GPU 비교

- **기록 ID** `FDLOG-20261123-pbr-array-bulk-restore-intel`
- 작업일 2026-11-23 KST.

## 1. 사용자가 제안한 것

- **U1** 배열 바인딩 일괄 복원을 연결하고 내장 GPU에서 같은 180기 입력과 품질을 사용해 화면·64 MiB 한도·바인딩·함수별 CPU/GPU 시간·프레임 P99·FPS를 확인하고 별도 커밋한다. 정확한 요청 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261123-pbr-array-bulk-restore-intel:U1]]` 검색 단서는 `배열 바인딩 일괄 복원부터 연결해`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 게임의 2D 기본값과 벤치마크 전용 배열 후보를 둔다. 동일 배열 데이터에서 복원 방식만 바꾼 비교와 2D 화면 대조를 수행한다.

## 3. AI가 제안한 것

- **구현상 판단** GL 구간의 배열·2D 각 사용 유닛 범위를 장치에서 한 번 검증한다. 두 범위를 보호할 수 있을 때 텍스처 상태 스택 한 번으로 복원한다. 상태 소유권과 예외 복구는 기존 SDL 경계의 계약을 따른다. [OpenGL 호환 프로필](https://registry.khronos.org/OpenGL/specs/gl/glspec46.compatibility.pdf)

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U1에 따라 연결했다. 구체적인 검증 방식과 순서는 구현에서 정했다.

## 5. 반영 후 발견한 문제

- **I1** 배열의 수동·일괄 복원에서 전체 화면 RGB 35개 중 33개가 일치했다. 나머지는 화면 하단 HUD에서 49픽셀과 6픽셀이 최대 채널 값 1만큼 달랐다.
- **I2** 2D 기준과 일괄 복원의 배열 후보는 전체 RGB 8/35개가 일치했다. 프레임 41에서 22,846픽셀과 최대 채널 값 207의 차이가 남았다. 배열 후보의 상주·샘플링 조건은 따로 비교해야 한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 각 실행의 실제 OpenGL renderer를 확인했다. Intel(R) Graphics, GL 4.6 호환 프로필, 드라이버 32.0.101.8860에서 180기·간격 15m·HP 100,000·FHD Medium/SMAA·자동 검 60Hz·VSync 끔·예열 120·측정 240프레임을 사용했다.

## 7. AI 해결 제안과 실제 해결 과정

- Intel에서 2D·배열 32개 유닛 사전 검사 후 5개 배열 입력과 환경 맵이 섞인 실제 `PartPainter` 패스에 일괄 복원이 적용됐다.
- 180기 정순·역순에서 수동→일괄 FPS는 42.97→43.30 / 47.38→45.16이었다. 작업 프레임 P99는 36.95→42.32 / 29.32→42.53ms였다. 2D 참조의 FPS는 47.04·48.66, P99는 49.25·29.56ms였다. 기능 비교에서는 충분한 FPS 개선이 확인되지 않았다.
- 등 무기 `back_deploy`의 논리 GPU 할당 최고치는 2D 17.59MiB, 수동·일괄 모두 19.72MiB였다. 64MiB 한도와 19.55MiB 배열 저장소는 양쪽이 같다.
- 상세 계측은 등 무기 2방향 보간 236회에서 `glBindTexture` 14→8회/제출, `SDL_GL_BindTexture` 1→1회, `glGetIntegerv` 11→5회였다. 기존 2D의 총 바인딩은 15회/제출이다.
- 첫 상세 비교의 등 무기 CPU 포함 경과는 `PartPainter.paint` 0.3337→0.3244, `bind_atlas_textures` 진입 0.0308→0.0293, 복귀 0.0119→0.0082, `TexturedQuadPass.draw` 0.0215→0.0219ms/프레임이었다.
- 첫 상세 비교 GPU 평균은 등 무기 0.0677→0.0902ms/제출이고, 패스 경과는 `enemy_render` 1.849→2.716, `surface_parts` 0.475→0.811, `part_upscale` 0.151→0.168, `shadow_map` 0.062→0.054, `shadow_surface_map` 0.042→0.057, `surface_ground` 0.020→0.021ms였다.
- 상세 역순의 등 무기 CPU 포함 경과는 `PartPainter.paint` 0.3049→0.3176, 바인딩 진입 0.0272→0.0300, 복귀 0.0099→0.0077, `TexturedQuadPass.draw` 0.0201→0.0205ms/프레임이었다. 바인딩과 조회 횟수는 첫 상세 비교와 같았다.
- 상세 역순의 GPU 평균은 등 무기 0.0700→0.0699ms/제출이었다. 패스 경과는 `enemy_render` 1.794→1.574, `surface_parts` 0.516→0.497, `part_upscale` 0.130→0.131, `shadow_map` 0.057→0.056, `shadow_surface_map` 0.042→0.064, `surface_ground` 0.021→0.020ms였다. 순서별 편차가 커 GPU 개선이나 회귀를 일괄 복원에 귀인할 근거는 부족하다.
- 미계측 상위 3프레임의 평균 CPU 그리기 제출 시간은 정순 35.90→39.77, 역순 29.02→38.21ms였다. 복귀 함수에서 줄어든 약 0.002~0.004ms/프레임으로 전체 P99 변화는 설명되지 않는다.
- **I1** 같은 상태·리소스를 수동과 일괄로 그린 실제 등 무기 렌더 타깃 RGBA 16/16개가 바이트 단위로 같다. 전체 화면의 전투 영역은 35개 모두 일치했다. 상태 스택을 강제로 끈 경우와 지원된 경우에 예외 후 배열·2D 바인딩이 돌아오는 검사 포함 18개가 통과했다.
- 게임 기본 경로는 2D 방향 페이지를 사용한다. `--pbr-direction-arrays`의 배열 경로에서는 확인된 유닛에 일괄 복원이 연결됐다.
- 원시 계측과 픽셀은 `output/performance/pbr_array_bulk_intel_20261123/`에 보관했다.
