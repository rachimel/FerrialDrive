# UI v2 GPU 방향성 모션 블러 전환

- **기록 ID:** `FDLOG-20261112-ui-v2-weapon-blur-stronger`

- 대화 범위: 2026-11-12 KST. 개별 발언 시각 미확인 [[FDLOG_MISSING_TIME:FDLOG-20261112-ui-v2-weapon-blur-stronger:scope]] — 현재 대화에서 “모션 블러 더 강하게”, “잔상이 아니라 진짜”, “연속적인 방향성 블러로 바꿔보자” 검색.

- 상태: 반영·자동 검사·실제 GPU 렌더 확인. 사용자 최종 외관 수용 미확인.

## 1. 사용자가 제안한 것

- **U1:** 모션 블러를 더 강하게 조정한다.
- **U2:** 여러 장의 잔상 대신 실제 모션 블러 방식을 질문했고, 확인 질문에서 “연속적인 방향성 블러로 바꿔보자”를 명시 선택했다. 추가 배경은 제시되지 않았다. 시각·출처는 위 대화 범위를 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1의 강도 조정 시험 이후 U2를 최종 기준으로 삼아 v2의 카드 반복 그리기를 제거했다. 각 카드를 한 번 렌더하고 이동 방향의 픽셀 필터로 합성한다. 01·02는 필터에서 제외한다.

## 3. AI가 제안한 것

- **구현상 판단 A1:** 33개 이상의 선형 샘플을 사용하는 GLSL 방향성 필터, 셔터 0.06초·세기 0.75·최대 길이 16px를 사용한다. 무기 교체 시간은 0.12초를 유지한다. 로드아웃 전환도 같은 필터를 사용하며 해당 셔터·세기·길이 설정을 따른다.
- **구현상 판단 A2:** 기존 Bicubic의 OpenGL 셰이더 연결·상태 복원을 재사용하고 Pico2D 원본은 변경하지 않는다. 렌더 대상 한 장을 재사용하며 premultiplied alpha를 합산한 뒤 복원해 투명 카드가 과도하게 어두워지지 않게 한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U2에서 표현과 처리 방식 전환을 명시 수용했다. A1의 구체적인 수치와 최종 외관에 대한 사용자 응답은 아직 없다.

## 5. 반영 후 발견한 문제

- 최초 GPU 실행에서 bytes 셰이더 안의 비 ASCII 주석으로 구문 오류가 발생했다. 해당 주석을 제거했다. 이전 잔상 장수 기준 자동 검사는 새 방식에 맞춰 카드당 한 번 그리기·두 행의 반대 방향·길이 제한·정지 후 필터 제외 검사로 교체했다.
- 소프트웨어 렌더러에서는 GPU 필터를 적용하지 않고 카드를 직접 그린다. OpenGL 화면 검증과 소프트웨어 기반 UI 논리 검사를 구분한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U2에 따라 카드 한 장의 현재 형상을 투명 레이어에 렌더한 뒤 이동 방향으로 필터링한다. 기존 시간 샘플링 잔상 시안은 최종 표현에서 대체됐다. 번호 패널·정지 상태는 필터 대상이 아니다.

## 7. AI 해결 제안과 실제 해결 과정

- UI v2 검사 79개, 실제 OpenGL 방향성 필터 검사 4개, 기존 Bicubic GPU 회귀 검사 6개 통과. 연속 번짐·양방향·투명도 중복 곱셈 방지·상태 성공/실패 복원·텍스처 재사용·자원 해제를 확인했다. Bicubic 검사는 명시 활성화 후 6개를 실제 실행했다.
- 실제 OpenGL에서 로드아웃 31·무기 교체 13프레임을 렌더하고 이전 잔상/강화 잔상/방향성 필터의 같은 시점 비교를 직접 열었다. 두 카드 높이와 대응 변 길이도 유지됐다. 결과는 `output/ui_unit_test_v2/equipment_directional/`의 `swap.gif`·`loadout.gif`·`comparison.png`다.
- 기술 근거: [SDL 텍스처 OpenGL 연결](https://wiki.libsdl.org/SDL2/SDL_GL_BindTexture), [GPU Gems의 이동 방향 후처리 개념](https://developer.nvidia.com/gpugems/gpugems3/part-iv-image-effects/chapter-27-motion-blur-post-processing-effect). 현재 구현은 UI 카드의 알려진 2D 이동을 사용하며 깊이 기반 3D 속도 복원은 구현하지 않는다.
