# 플레이어 표시 크기·분리 패스·Energy Mask

- **기록 ID:** `FDLOG-20261111-player-split-energy`

- 발언·작업별 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261111-player-split-energy:scope]] 현재 대화의 “Player는 384x384로 변경”, “원본은 768 유지”, “크기 256x256으로 줄여도 될듯”과 구현 보고를 검색한다.
- 상태: 구현·자동 검사·실제 OpenGL 렌더 확인. 최종 외관 승인·직접 마우스 조작·커밋·업로드는 별도다.

## 1. 사용자가 제안한 것

- **U1:** 플레이어 384×384, 분리 패스 출력 확인, Energy Mask 추가를 요청했다. 의도는 표시 크기 조절과 실제 파츠 출력 확인이다. 출처는 현재 요청 원문이다.
- **U2:** 해상도 확인 질문에 UI 표시만 384×384로 바꾸고 원본은 768×768로 유지하도록 선택했다. 이후 표시 크기를 256×256으로 줄여도 된다고 정정했다. 최종 표시 기준은 U2의 후속 정정이다.

## 2. AI가 제안한 것

- **A1, 구현상 판단:** 기존 Unreal 8개 파츠·Energy 장면·MRQ·Asset Tool을 재사용한다. 애니메이션·리그·외관 변경 없이 가림·마스크·조립만 확인하기 위한 선택이다.
- **A2, 구현상 판단:** 실제 16개 시트 로드에서 3600MiB가 확인돼 공통 투명 여백 제거를 제안하고 적용했다. 원본을 보존하며 같은 crop과 보정 피봇을 사용해 픽셀·배치를 유지하는 목적이다. 코드와 검증 결과가 근거다. 제시·수용의 개별 시각은 scope의 미확인 항목이다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1·U2: 최종 원본 768×768·UI 표시 영역 256×256·배율 1/3로 반영했다. 분리 파츠 8개와 파츠별 Energy Mask 8개를 같은 에셋에 연결했다. 원본/표시 모두 384로 진행하던 해석은 U2의 선택으로 종료했고 당시 384 출력은 진단 결과로만 남겼다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1·A2는 요청 범위의 구현 선택이다. 사용자의 별도 외관 승인이나 패킹 방식 명시 승인으로 해석하지 않는다. 최종 표시 크기와 원본 유지 조건은 사용자 U2의 직접 지정이다.

## 5. 반영 후 발견한 문제

- **I1:** 단일 body에만 화면 전환 알파를 적용하던 방식은 손·장비가 분리됐을 때 투명도가 달라질 수 있었다. AI가 현재 UI 그리기 코드를 확인해 발견했다.
- **I2:** 768 프레임의 투명 여백을 유지한 16개 텍스처는 추정 합계 3600MiB였다. 실제 OpenGL 로드는 성공했지만 같은 입력을 더 작게 패킹할 필요가 있었다.
- **I3:** 통합 렌더와 조립 결과의 실루엣은 96장 모두 같았다. RGB 차이 2를 넘는 픽셀은 검의 얇은 경계에서 총 10개(7프레임, 프레임당 1~2개)였다. 원인은 확정하지 않았으며 확대 비교와 실제 표시를 직접 열어 확인했다. 완전한 RGB 동일성으로 보고하지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U2에 따라 원본 768을 유지하고 UI 배율만 1/3로 설정했다. 384 원본 시안은 실제 연결에 사용하지 않는다. 애니메이션의 허리·골반·무릎 키는 이번 작업에서 바꾸지 않았다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 공통 `PicoAssetResource.opacity()`가 공유 텍스처를 한 번씩 조절하고 중첩·예외 뒤 원래 알파를 복원하게 했다. UI는 이 컨텍스트로 전체 파츠를 그린다.
- I2 ↔ A2: `unreal.import`에 선택 `trim_padding`을 추가했다. 모든 파츠·방향의 가시 영역 합집합과 피봇·2px 필터 여백을 유지한다. 원본 crop은 top-left `[247,183,521,547]`, 패킹 프레임은 274×364·피봇 `[137,163]`이다. 1370×7280 시트 16개의 합계는 약 608.74MiB다. 일반 도형으로 색상·마스크 픽셀·원본 보존·피봇이 가시 영역 밖인 경우를 검사했다.
- 기존 8방향 장면으로 색상 768장·Energy Mask 768장·통합 비교 96장을 출력했다. 모든 마스크의 알파는 소유 파츠와 정확히 같았고 전체 조립 실루엣도 같았다. 가림으로 안 보이거나 에너지 재질이 없는 파츠의 검정/빈 마스크는 유지한다. 기존 AnimSequence SHA-256도 유지됐다.
- 입력 1536개 PNG를 `Tools/asset_loader/workspace/player_mech_idle_split_energy_8dir/input/`에 해시와 함께 보존했다. 실행 에셋은 `data/catalog/prerender/player_mech_idle_split_energy_8dir_trimmed/mech.json`이다. 패킹 결과를 원래 768 캔버스로 복원한 1536장 전부의 RGBA가 원본과 같았다.
- 관련 자동 검사 **79개 통과**. 실제 OpenGL에서 16개 텍스처·8방향×12프레임·합성 마우스 방향·정지/재개·초기화·전체 알파 복원·마스크 표시·자원 해제를 확인했다. 전체 UI·8방향·색상/마스크·원본의 얇은 경계 비교 이미지를 직접 열었다. 실시간 발광색/강도 제어는 이번 연결 범위에 포함하지 않았다.
