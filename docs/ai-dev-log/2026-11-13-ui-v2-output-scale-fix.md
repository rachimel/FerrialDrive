# UI v2 보간 원본 정합·DPI·FHD와 구 출력 폐기

- **기록 ID:** `FDLOG-20261113-ui-v2-output-scale-fix`
- 정리 기준: 2026-11-13 00:06:27 KST. 작업 대화는 2026-11-12~13에 걸쳤으며 개별 발언 시각과 구분한다.
- 출처: 현재 대화의 “원인 파악해서 수정”, “128px보다 더 크게”, “현재 크기 기준이랑 맞지 않는 시안들은 폐기”, 출력물만 폐기한다는 선택, “1920 x 1080 ㄱㄴ”. 개별 발언의 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261113-ui-v2-output-scale-fix:scope]] 위 검색 구절과 범위 선택 응답을 찾는다.
- **상태:** 보간 원본 교체·물리 FHD 창·HUD/월드 좌표 정리·145개 검사·구 출력/보간 데이터 12폴더 삭제 완료. 구 `data/frame_interpolation/ui_v2`는 자동 승인 검토 거부 후 사용자의 경로별 명시 승인을 받아 2026-11-13 00:08:45 KST에 삭제했다. 원본 모델·동작은 폐기 대상이 아니다. 사용자 최종 외관 승인·직접 마우스 검수·커밋/업로드는 미수행이다.

## 1. 사용자가 제안한 것

- **U1:** 보간 출력이 기존보다 커지는 원인을 조사·수정하고, 현재 UI가 128px 기준보다 커 보이는 현상을 확인한다. 출력 간 정합과 실제 화면 크기를 함께 확인하는 요청이다.
- **U2:** 현재 크기 기준과 맞지 않는 시안을 폐기한다. 범위 질문에서 **미리보기·프리렌더·보간 출력만 폐기**를 선택했다. 원본 모델·동작 작업본 삭제는 선택하지 않았다.
- **U3:** DPI 인식 상태에서 1920×1080 실행을 요청했다. 기존 크기 기준을 유지한 물리 FHD 창으로 적용한다. 시각·출처는 scope를 따른다.
- **U4:** 추가 질문에서 `data/frame_interpolation/ui_v2`의 구 보간 데이터 1,704파일·약 118MiB 삭제를 명시 승인했다. 근거는 “구 보간 데이터 폴더도 삭제 승인” 응답이다.

## 2. AI가 제안한 것

- **A1, 구현상 판단:** 기존 파츠가 사용하는 원본 동작을 이미지/manifest로 확인하고 같은 동작의 벡터를 다시 출력한다. UI 파츠 경로·메타데이터 SHA-256을 보간 카탈로그에 바인딩해 잘못된 후보 연결을 거절한다.
- **A2, 구현상 판단:** 게임 배율을 보상 축소하는 대신 공통 `PicoCanvas`에서 Windows 비디오 초기화 전 DPI 인식과 픽셀 좌표를 지정한다. 물리 해상도와 렌더 해상도를 일치시키기 위한 수정이다.
- **A3, 구현상 판단:** FHD의 HUD 픽셀 크기를 유지하며 위/아래·중앙/오른쪽 기준 위치를 옮긴다. 샘플 플레이어 월드 위치를 화면 중앙 좌표와 분리해 해상도 변경이 적과의 거리·획득 범위를 바꾸지 않게 한다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U3을 반영했다. 화면 크기·출력 후보를 수정했으며 3D 모델·리그·동작 키는 수정하거나 삭제하지 않았다. 크기는 정면 팔 내림 기준 어깨 너비 128px·공통 배율 `128/202`를 유지한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 사용자는 DPI 인식 변경을 확인하고 FHD 요청으로 이어갔다. 출력만 폐기하는 범위와 U4의 구 데이터 경로 삭제는 명시 선택이다. 세부 검사 방식·블러 품질·UI 외관의 최종 승인은 별개다.

## 5. 반영 후 발견한 문제

- **I1, 이전 구현 오류:** 기존 UI의 콤보는 `SwordCombo_Follow_20261112`·`SwordCombo_Follow_v02_20261112`인데 AI가 이전 `SwordCombo_Timing_20261112`을 보간에 연결했다. 정면 첫 프레임 4타격의 현재 body 아틀라스 복원은 Follow 입력과 바이트 단위로 같았고 Timing 입력과 달랐다. 이전 기록의 최대 21px 외곽 차이는 같은 자세 비교가 아니었다.
- **I2, 표시 환경:** 기존 창은 DPI 비인식이었다. Windows 배율 150%에서 SDL 1280×720이 물리 1920×1080으로 확대됐다. 따라서 명목 128px 어깨가 물리 화면에서는 약 192px로 보였다. SDK의 DPI 인식 수준 0과 실제 좌표 변환으로 확인했다.
- **I3, FHD 연결:** 샘플 플레이어 월드 위치가 화면 중앙에서 파생돼 FHD 변경 시 적과의 거리가 달라졌다. 기존 입력 검사에도 1280×720 마우스 좌표가 고정돼 있었다.
- **I4, 폐기 승인 검토:** 첫 12폴더 재귀 삭제 명령은 실행 전에 거부됐다. 자동 승인 검토는 사용자 승인 범위를 출력물로 해석하고, `data/frame_interpolation/ui_v2`는 런타임 입력 카탈로그이므로 범위 초과라고 판단했다. 우회하지 않고 `output/`만 삭제했으며 해당 데이터 폴더의 삭제는 별도 질문으로 분리했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U2의 범위 선택에 따라 원본을 폐기하지 않고 확인된 구규격 출력과 잘못 연결된 출력만 분리했다. U3에 따라 작은 창의 OS 확대가 아닌 물리 1920×1080으로 전환했다. 구 데이터 경로의 개별 삭제 승인 질문은 I4 이후 제시했고 U4 승인 후 삭제했다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1 / A1:** 현재 파츠 manifest의 `native_animation`과 출력 맵을 기준으로 콤보 32클립·96개 MRQ 작업을 새로 실행했다. 같은 카메라의 384px 색상/벡터를 변환하고 정상 Idle 8클립과 함께 `data/frame_interpolation/ui_v2_matched/catalog.json`으로 연결했다. 원본과 다른 카탈로그/메타데이터는 로딩을 거절한다.
- **I1 검증:** 블러와 위상 곡선 효과를 분리하고 원본 시점 **304개**를 투명 RGBA 타깃에서 기존 파츠와 비교했다. 알파>20 경계 차이는 **최대 2px**이며 2px 초과면 실패하는 검사를 추가했다. 불투명 창 버퍼 전체를 비교했던 최초 0px 주장의 재발을 막기 위해 투명 타깃과 비어 있지 않은 제한된 외곽을 확인한다. 출력 해상도/필터 차이를 포함한 경계 검사이며 임의 중간 위상·가림 복원 품질 통과로 확대하지 않는다.
- **I2 / A2:** `SDL_WINDOWS_DPI_AWARENESS=permonitorv2`·`SDL_WINDOWS_DPI_SCALING=0`을 Pico2D 원본 수정 없이 설정했다. [SDL DPI 인식](https://wiki.libsdl.org/SDL2/SDL_HINT_WINDOWS_DPI_AWARENESS)과 [DPI 좌표](https://wiki.libsdl.org/SDL2/SDL_HINT_WINDOWS_DPI_SCALING)의 비디오 초기화 전 지정·물리 픽셀 의미를 확인했다. 수정 후 DPI 144·인식 수준 2·클라이언트 물리 크기 1280×720을 확인했고, FHD에서는 렌더와 물리 클라이언트가 모두 **1920×1080**이었다. 새 프로세스의 실제 창을 검사하는 회귀 검사를 추가했다.
- **크기 검증:** 기존 팔 내림 기준 자세의 body 입력을 보존 입력 `data/animations/player_mech/display_reference_arms_down_20261112/`에 복사했다. 설정상 어깨 너비 128px, 실제 알파 경계 약 129px로 픽셀 반올림/필터 1px 수준이다. 전체 높이·검 포함 실루엣을 128px로 강제하지 않았다. 기준 자세·정면/사선 Idle·128px 눈금 이미지를 직접 열어 확인했다.
- **I3 / A3:** 샘플 `player_world_position=[640,360]`을 추가했다. 카메라가 이 월드 위치를 FHD 화면 중앙에 투영하며 적과의 실제 거리는 유지한다. HUD는 크기를 유지하고 자원부는 아래 중앙, 무장은 오른쪽 아래, HIT/DAMAGE는 오른쪽 중앙에 맞췄다. 마우스 검사는 화면 중앙/월드 투영에서 좌표를 계산한다.
- **자동 검사:** UI v2 전체 검사와 공통 실행부·프레임 보간·콤보·방향 재생 검사 **145개 통과**. 실제 OpenGL·로컬 벡터·새 Windows 프로세스의 물리 해상도 검사를 포함한다. 출력물 정리 후 일반 진입점 30프레임 재실행도 성공했다.
- **현재 비용·한계:** 보간 텍스처 추정 약 198.49MiB, 이번 장치 시작 준비 약 2.97초. GPU 실행 시간/드라이버 메모리와 구분한다. 빠른 검·팔의 가림 경계 왜곡과 파츠별 Energy Mask 보간 미연결은 남는다.
- **U2/U4 / I4:** 구 크기 미리보기 9폴더·잘못된 네이티브 출력·구 UI 보간 시연 출력, 합계 `output/` 11폴더를 삭제했다. U4 승인 후 구 데이터 1,704파일·약 118MiB도 삭제해 총 12폴더·약 553.34MiB를 정리하고 부재를 확인했다. 기존 검증 JSON은 작업 기록의 `retired_reports/`에 보존했다. 데이터 삭제 후 새 진입점 30프레임 실행도 성공했다. 경로·개수·용량·승인 검토와 삭제 상태는 `automate/workspace/ui_v2_interpolation_fix_20261112/discard_manifest.json`을 따른다.
- **근거·공개:** `output/ui_unit_test_v2/interpolation_fix/`에 전체 프레임 비교·DPI 전후·기준 크기·FHD 화면·교체 전후 비교를 보존했다. 생성 이미지/벡터/작업 요청은 Git 제외를 확인했다. 관계없는 기존 미커밋 변경과 미추적 의존 코드가 있어 커밋·업로드는 하지 않았다.
