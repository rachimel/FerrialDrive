# CPU·메모리·UHD 630 기능 제한 벤치마크

- **기록 ID:** `FDLOG-20261115-hardware-profile-benchmark`
- 대화 범위: 사용자의 자원 제한 모듈 요청부터 실제 검 이동 훈련장 165FPS 시험·모션 블러 경로 확인까지.
- 개별 발언 시각 미확인: `[[FDLOG_MISSING_TIME:FDLOG-20261115-hardware-profile-benchmark:scope]]`. 현재 대화의 `CPU·메모리 제한이랑 UHD 630 기능 제한 프로필`, `각 요소별로 블러`, `모션블러` 발언에서 보완한다.
- 기록 작성일: 2026-11-15 KST. 실제 두 번째 측정의 시작·저장 UTC는 각 report와 TimingRecorder에 있다.
- 근거: 현재 대화, `tests/hardware_profile_benchmark.py`, 공통 diagnostics 3모듈, `output/performance/hardware_profile/`.
- 상태: 구현·제한 적용 확인·실제 OpenGL 실행. 165FPS 미달. UHD 630 실기·수백 기·QHD 미검증.

## 1. 사용자가 제안한 것

- **U1:** CPU·메모리 제한과 UHD 630 기능 제한을 끼울 수 있는 벤치마크 모듈을 넣고 165FPS를 목표로 시험한다. 앞서 지정한 i3-10100·UHD 630·RAM 8GB·SSD 256GB 하한을 개발 중 검토하려는 요청이다. 출처는 현재 사용자 발언이며 개별 시각은 위 TIME 범위 태그를 따른다.
- **U2:** 현재 각 요소별로 모션 블러를 처리하는지 확인한다. 현재 대화에서 `블러`를 `모션블러`로 명확히 했다. 블러 통합·삭제·품질 변경은 요청하지 않았다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1을 구현·시험 범위로 수용했다. Windows 자식만 제한하고 적용 조회가 일치한 후에 게임 로딩을 허용한다. 기존 일반 실행은 기본 60FPS로 유지한다. 실기 처리량 에뮬레이션과 구분한다.
- U2는 현행 코드에서 기체 시간축 블러, UI 영역별 방향 블러, 월드 카메라 블러를 확인해 답했다. 표현 값·셰이더 방식은 변경하지 않았다.

## 3. AI가 제안한 것

- **A1, 구현상 판단:** 기본 부하 조건을 논리 CPU 8개·Job CPU 50%·커밋 1024MiB로 정했다. 값은 외부 JSON과 옵션으로 바꾼다. 코어/스레드 구조·클럭 차이를 보정하지 않은 임시 시험 조건이다. 이유는 자식 프로세스만 재현 가능한 제한으로 실행하고 1GiB 부근의 실패를 드러내기 위해서다.
- **A2, 구현상 판단:** GPU는 OpenGL 4.5 범위의 현행 함수 허용 목록·GLSL 버전·텍스처/버퍼/dispatch 상한을 가드한다. 실기 cap 전체를 수집하지 않았으므로 이름에 conservative를 표시하고 검사 범위를 보고서에 적는다. 실제 벤더와 드라이버 표시는 유지한다.
- **A3, 분석 제안:** 6.06ms 초과 비율·p99·제한 없는 비교·HUD/월드 분리를 기록한다. 평균 FPS만으로 스파이크나 큰 UI 비용을 숨기지 않기 위해서다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 사용자는 모듈 구현과 목표 시험을 명시 요청했다. A1의 CPU 50% 등 개별 기본 수치를 i3 보정값으로 승인한 근거는 없다. 모듈 내부의 첫 시험값으로만 사용한다.
- A2/A3는 요청 수행 중의 구현·계측 판단이다. 추가로 사용자 승인을 받았다고 기록하지 않는다. 모션 블러 통합은 제안·구현·수용으로 확정하지 않는다.

## 5. 반영 후 발견한 문제

- **I1, AI 확인:** 첫 시연에서 격리 설정 파일의 스키마를 잘못 작성해 창을 열기 전에 실패했다. 기존 `GameSettingsStore.save()`를 사용하도록 고쳤다. `demo_smoke_01` 실패 폴더를 결과에서 구분한다.
- **I2, AI 확인:** 첫 실제 시험에서 제한 59.05FPS·무제한 59.44FPS로 모두 목표 미달이었다. 최종 세분화 계측에서 제한 56.60FPS·무제한 59.47FPS, 두 실행 모두 600/600프레임이 6.06ms를 초과했다.
- **I3, AI 확인:** 최종 제한 상태의 HUD 8.05ms, 월드 6.70ms, 그리기 제출 15.02ms였다. HUD만으로 예산을 넘는다. 모션 블러 단독 비용이나 UHD 630에서의 GPU 처리량은 아직 측정하지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U2에서 모션 블러 경로를 확인했다. 실제 구조는 기체 9회 시간축 샘플, UI 영역별 필터, 월드 카메라 필터다. 사용자의 추가 통합·최적화 지시는 이 기록 범위에서 없다. I2/I3 해결을 구현했다고 표시하지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 기존 설정 저장 모듈 재사용으로 수정했다. 자식 시작 실패와 기능 위반을 정상 완료와 구분하고, 제한 조회·마지막 Job peak commit을 저장한다.
- `diagnostics/resource_limits.py`는 Windows Job과 affinity, 게이트·자식 수명 관리를 제공한다. `gpu_profile.py`는 공통 GL 바인딩과 SDL 텍스처 3경로를 검사한다. `frame_benchmark.py`는 고정 갱신·프레임 분포·GPU 질의·메모리를 기록한다. 기존 렌더러의 직접 바인딩은 공통 경로로 연결했다.
- 기본 도형과 실제 에셋을 같은 독립 진입점으로 실행했다. 최종 제한 실행은 기능 위반 0건, GLSL 120/330/430 사용, Job peak commit 625.29MiB였다. CPU/GPU 메모리를 합쳐 게임 전체 1GiB에 들었다는 결론은 내리지 않는다.
- 테스트는 Windows의 실제 초과 커밋 거절, CPU/affinity/Job 조회, 기능 초과 호출의 드라이버 도달 전 차단, 분할 shader 지시문, 창 없는 import, 종료 후 SDL 함수 복구와 기존 그림자/텍스처 렌더링을 확인했다. 자세한 실행 수는 아래 확인 상태에 기록한다.
- 다음 분석 우선순위는 HUD 그리기 세분화다. 블러만의 비용은 비활성 비교나 구간별 계측이 더 필요하다. 이번 범위에서는 표현을 바꾸지 않았다.

## 확인 상태

- 구현·문서: 완료. 기본 도형 실제 OpenGL 실행과 실제 에셋 600프레임 제한/무제한 비교 완료.
- 자동 검사: 관련 CPU·Windows 제한·실제 GPU·DPI·전투 회귀 검사 64개 모두 통과. 이후 확장 warn/줄 연결 우회 가드 보강도 하한 프로필 검사 14개로 재확인해 통과했다. 앞선 중복 실행을 합산하지 않는다.
- 실제 창: 자동 시나리오 실행. 사용자 직접 조작·외관 승인·장기 안정성은 미검증이다.
- 목표 성능: 현재 플레이어 1기 시나리오 165FPS 미달. 실제 기준 장비·수백 기·QHD 미검증.
- 커밋·업로드: 미수행. 기존 대량 미커밋 변경과 분리할 수 있도록 이번 파일·연결 범위만 기록했다.
