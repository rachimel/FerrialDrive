# 적 군집의 CPU Numba 이동과 순차 충돌

**기록 ID** `FDLOG-20261121-enemy-numba-movement`

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1)** 900~1,000기 전투의 적 이동을 Numba로 묶는다. 개별 발언 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261121-enemy-numba-movement:U1]]이다. 같은 대화의 `적 이동은 Numba로 합쳐`에서 확인할 수 있다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 교전 서브스텝마다 기체 상태를 연속 배열로 모아 CPU에서 한 번 호출한다. 검·총 넉백, 사격 후 거리 조절, 몸체 밀림과 이동 모션 누적 거리까지 포함한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1)** 추적과 후퇴의 방향 계산은 개별·군집 경로가 공유한다. 공간 해시로 후보를 찾고, 겹친 적을 출현 순서로 해결한다. 이동한 즉시 버킷을 갱신해 다음 기체가 새 위치를 사용한다. 공격 타이머·명중 판정·발사는 기존 Python 교전 코드에 둔다.
- **AI 제안 2 (A2)** 배열 준비 비용을 고려해 32기부터 Numba를 선택하고 로딩 중 컴파일한다. 같은 교전 재생에서 1·4·8·16기는 개별 실행이 더 빨랐다. 32·64·1,000기에서는 군집 실행 쪽의 평균 갱신 시간이 짧았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- CPU Numba 선택은 사용자의 명시 지시다. 32기 기준과 해시 버킷의 구조는 구현 결정이다.

## 5. 반영 후 발견한 문제

- **I1** 첫 Numba 경로는 100기 밀집 교전에서 미세한 거리 차이가 생겼다. 1,000기 5초 시험에서는 233번째 프레임에 전투 결과가 처음 갈라졌다. 출현 순서를 보존해도 거리 반올림 차이가 연쇄 밀림에 누적될 수 있었다.
- **I2** 적 갱신을 단축한 뒤에도 전체 FHD 교전은 60 FPS에 미달했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 2026-11-21 00:39 KST `96b5fb0`에서 이동 규칙과 공격 타이머를 분리했다. 분리 직후 기존 코드와 비교한 100기·120프레임은 좌표와 전투 결과가 같았다. 00:45 KST `4e3eaa7`에서 Numba 이동과 대조 검사를 연결했다.

## 7. AI 해결 제안과 실제 해결 과정

- **A1 ↔ I1** Numba 경로에서 제곱과 합의 반올림 잔차로 길이를 보정했다. 기존 Python 경로가 사용하는 `math.hypot`의 정밀도 처리는 CPython 3.13의 `vector_norm`에서 확인했다. [CPython mathmodule.c](https://github.com/python/cpython/blob/3.13/Modules/mathmodule.c)
- 변경 전 코드와 매 프레임 비교했다. 1,000기·12m 간격·300프레임과 900기·4m 간격·240프레임 모두 위치·방향·이동량·타이머 최대 절대 차이가 0이었다. 두 시험에서 각각 554발·771발이 발사됐고, 명중 기록·남은 탄환 소유자 순서·적 상태 전이가 일치했다. 자동 대조에는 검·총 넉백, 사망 후 잔여 밀림, 직접 재배치, 개체 추가와 리셋도 포함한다.
- **A2 ↔ I2** 1,000기 시뮬레이션을 준비 30프레임 후 120프레임 측정했다. 렌더링을 뺀 교전 갱신 평균은 개별 경로 8.03·7.47ms, Numba 3.84·3.75ms였다. 이 구간에는 배열 변환·객체 반영·기존 명중 및 탄환 코드가 포함된다.
- **전체 교전** Intel Graphics, FHD, 중간 PBR, 1,000기·12m 간격, 자동 SMG, 사운드 끔, 무제한으로 준비 30·측정 90프레임을 사용했다. 같은 프로세스에서 순서를 뒤집었다. 마지막 프레임은 네 실행 모두 표시 후보 306기, 본체 285기였다.
