## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 레벨에 따라 Bullet Trail이 더 길어지도록 요청했다. 이유는 직접 밝히지 않았으며 레벨별 길이 증가가 명시된 의도다.
- **사용자 제안 2 (U2):** 사거리 조회에 이어 `그러면 사거리 75m`를 지정했다. 방향별 환산값이 달랐던 설명 다음의 요청이다. 별도 수치 선정 이유는 미제공이다. 두 발언 시각은 scope 태그 참조.

## 2. AI가 제안한 것

- **AI 제안 1 (A1, 구현상 판단):** LV1/LV2/LV3의 Trail 길이를 108/135/162 투영 px, 배율 1/1.25/1.5로 둔다. Overdrive도 현재 레벨 길이를 따른다. 단계별 길이 차이를 보이면서 기존 LV1 표현을 유지하는 판단이다. 사용자에게 구현 방향을 보고했다.
- **AI 제안 2 (A2, 구현상 판단):** 실제 발사 방향을 역투영해 미터당 투영 거리로 사거리 한도를 구한다. 기존 소멸·연속 충돌 검사와 탄환 자료구조는 재사용한다. 방향별 압축률이 달라도 75m를 유지하는 것이 근거다. 시각은 scope 태그 참조.

## 3. 사용자 제안 중 AI가 수용한 것

- U1: 총탄 렌더러에 레벨별 표시 배율을 연결했다. 실제 누적 이동 거리 상한을 유지해 총구 뒤로 Trail이 생기지 않게 한다.
- U2: 이동 훈련장·교전·속도 시험이 공유하는 양쪽 총에 월드 75m 사거리와 투영을 연결했다. 설정은 `weapons.range_m=75`다. 록온 거리·탄속은 수정하지 않았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 75m는 사용자 직접 지정이다. Trail 세부 배율·길이와 최종 외관의 사용자 승인은 아직 확인하지 않았다.

## 5. 반영 후 발견한 문제

- **I1:** 수정 전 사거리는 투영 좌표 900px여서 현행 배율에서 가로 약 35m·세로 약 110m로 달랐다. 소스의 이동 한도와 투영식을 조회해 확인했다. 같은 픽셀 상한을 단순히 75m의 가로 환산값으로 바꾸면 세로 사거리는 여전히 틀린다.
- 새 구현에 대한 관련 자동 검사 실패는 없었다. 실제 플레이 사용감은 미검증이다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U2/I1: 사용자가 월드 사거리 75m를 지정했다. AI가 방향별 투영 보정을 구현·검증했다.

## 7. AI 해결 제안과 실제 해결 과정

- I1/A2: `RangedCombat`에 미터 사거리와 투영을 함께 공급하면 발사 시 최종 분산 방향의 역투영 길이로 투영 좌표 이동 한도를 구한다. 소멸은 기존 남은 거리와 연속 충돌 검사를 따른다. 투영을 사용하지 않는 기존 독립 전투 경로의 `bullet_range_units`는 호환 유지한다.
- U1/A1: `PicoGunEffects.draw()`에 현재 에너지 레벨을 전달하고 설정 배율을 적용한다. 텍스처 재생성 없이 정점 길이를 바꾼다.
- 자동 검사: 총 피드백·이동 사격·적 교전 50개 통과. 8방향×30/60/144FPS에서 75m 소멸, 가로·세로·대각선의 74m 표적 명중/76m 표적 비명중, 레벨별 Trail 길이와 이동 거리 제한을 확인했다.
- 화면 확인: OpenGL로 LV1/LV2/LV3 길이·색상을 그린 `output/spark_visibility/trail_levels.png`를 직접 확인했다. 기본 렌더 검토이며 실제 교전 플레이·GPU 성능 실측과 구분한다.
