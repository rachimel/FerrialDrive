# 화면 거리 교체 실험·Q 커서 록온

- **기록 ID:** `FDLOG-20261117-screen-distance-switch-q-lock`
- 범위: 2026-11-17 현재 세션. 개별 발언·검증의 정확한 시각은 미제공이다. [[FDLOG_MISSING_TIME:FDLOG-20261117-screen-distance-switch-q-lock:scope]] 검색 단서: `화면 안에서 좀 멀리 떨어지면 다른 표적`, `Q키 눌러서 마우스에서 가장 가까운 후보`.
- 상태: 실험 설정·입력·공통 선택기·현행 명세 반영, 자동 검사·짧은 실제 Combat 실행 완료. 직접 조작 사용감·최종 밸런스 승인·커밋·업로드는 미수행.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 화면 안에서 멀리 떨어지면 다른 표적을 잡는 방향을 우선 실험한다. 최종 확정과 시험을 구분했다.
- **사용자 제안 2 (U2):** Q를 눌러 마우스와 가장 가까운 후보를 향해 록온한다. 발언 출처·시각은 scope를 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1을 플레이어와 현재 표적의 화면 간격이 커지면 더 가까운 유효 후보로 교체하는 실험으로 해석해 연결했다. U2는 같은 화면 내 주변 후보를 대상으로 즉시 선택하도록 했다.

## 3. AI가 제안한 것

- **구현상 판단:** 화면 반폭·반높이로 정규화한 간격 0.7에서 거리 교체에 들어가고 0.55에서 복귀한다. 기존보다 25% 이상 가까운 후보가 0.25초 유지될 때 교체한다. 대체 후보가 없으면 유지한다. 가까운 표적 선택 뒤 먼 기존 표적으로 마우스 자동 교체가 왕복하지 않게 한다.
- **구현상 판단:** Q 선택은 자동 교체로부터 1초 보호한다. 사망·비활성·플레이어 완전 화면 이탈 해제는 그대로 적용한다. 기존 Q 종료 매핑은 제거하고 F10을 유지한다. 입력 반복·일시정지·메뉴·설정창에서 Q 선택을 막는다.
- **구현상 판단:** 거리 교체와 Q 보호는 실제 초를 사용해 Overdrive 애니메이션 가속과 분리한다. `screen_distance_switch.enabled=false`로 거리 교체 실험을 끌 수 있다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 실험 진행과 Q 선택은 U1·U2의 요구다. 플레이어 간격이라는 해석·정규화 수치·대기·보호 시간·최종 조작감은 별도 사용자 수용 전이다.

## 5. 반영 후 발견한 문제

- **I1:** 정확히 1초를 여러 갱신으로 합산할 때 보호 시간이 부동소수점 잔여값 때문에 한 번 더 유지되는 경계를 자동 검사에서 발견했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1의 실험 설정을 공통 이동·Combat에 활성화했다. U2의 Q를 현재 입력 경로에 연결해 공통 선택기의 대기 상태를 초기화하고 HUD 록온 표시를 즉시 변경한다.

## 7. AI 해결 제안과 실제 해결 과정

- 공통 선택기는 외부 우선 표적·교체 대기를 선택적으로 받아 기존 UI 시연 호출과 호환한다. 가시성·카메라 경계 반복 방지는 유지했다.
- I1은 1e-9초 미만 잔여값을 0으로 처리했다. 표적 무효화 시 거리 상태·수동 보호도 초기화한다.
- 관련 검사 **51개 통과**. 0.25초 경계·충분한 거리 개선이 없는 경우 유지·커서에 의한 먼 표적 왕복 방지·Q 즉시 선택/종료 방지·입력 반복/정지 차단·1초 보호·Overdrive 시간 분리·기존 경계 반복과 다수 적 전투를 확인했다.
- 실제 low Combat·SMG에서 준비 5·측정 45프레임이 정상 종료했다. 근거: `output/performance/lock_screen_switch_q_20261117/combat/report.json`. 짧은 실행이며 사용자 직접 입력 검수나 FPS 목표 달성으로 확대하지 않는다.
