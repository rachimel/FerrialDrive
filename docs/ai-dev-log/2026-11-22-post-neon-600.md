# 잔탄 네온 제거 후 600기 CPU·GPU 병목 재계측

**기록 ID** `FDLOG-20261122-post-neon-600`

2026-11-22 KST 작성. 작업 트리 기준 `2432cd8`, RTX 5070 Laptop GPU, OpenGL 4.6, FHD, 중간 PBR·SMAA, 600기·12m 간격, 자동 SMG, 고정 1/60초 갱신·무음·VSync 해제·프레임 제한 해제다.

## 1. 사용자가 제안한 것

- **U1** 현행 카드의 네온 광을 뺀 상태로 600기 전체를 다시 계측한다. CPU 준비·제출·대기와 GPU 패스 시간을 분리하고 가장 큰 병목을 확인한다. 정확한 요청 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261122-post-neon-600:U1-U2]]로 남긴다. 검색 단서는 `네온 뺀 지금 상태로 600기 전체 다시 계측`과 `RenderDoc 사용해봤어?`다.
- **U2** 계측에 RenderDoc을 사용했는지 확인한다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 표준 벤치마크 240프레임, 세부 구간 160프레임씩을 실행했다. 별도로 근거리 그림자 구간을 240프레임씩 두 번 대조했다.
- **U2** 기존 측정은 OpenGL 타이머였다고 답했다. 설치된 RenderDoc 1.44로 실제 교전 캡처도 시도했다.

## 3. AI가 제안한 것

- **A1** 일반 실행, 준비 구간, 네이티브 API 진입~복귀, 강제 대기, GPU 타임스탬프와 Python 호출 추적을 별도 회차로 실행한다.
- **A2** 평균만으로 그림자 패스를 평가하지 않고 타일 깊이 기록과 바닥 합성으로 나눠 느린 프레임을 추적한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- CPU와 GPU 비용 분리는 사용자 요청이다. 타이밍 경계, 별도 회차, 그림자 재검사와 RenderDoc 시도는 구현상 판단이다.

## 5. 반영 후 발견한 문제

- **I1** 일반 GPU 시간보다 훨씬 긴 샘플이 그림자 상위 구간에 잡혔다. 해당 프레임의 CPU 구간은 평소 범위였고, 더 좁은 GPU 구간에서 귀속을 확인해야 했다.
- **I2** RenderDoc DLL이 주입됐으나 실제 교전의 두 캡처 요청이 모두 시작되지 않았고 캡처 수는 0이다. 일반 실행에서 `glBegin/glEnd`가 오류 없이 실행되는 것을 확인했다. RenderDoc이 명시한 OpenGL 지원 범위는 Core 프로필이다. 최종 GPU 판정은 OpenGL 타이머에서 얻었다. [RenderDoc 지원 범위](https://github.com/baldurk/renderdoc/blob/v1.x/README.md)

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 일반 회차의 작업 평균은 34.29ms, P95는 50.34ms였다. 입력 0.61ms, 갱신 6.18ms, 그리기·말단 제출 27.45ms, `present` 0.057ms였다. 일반 GPU draw 구간은 평균 2.14ms·중앙값 1.18ms·P95 6.22ms다.
- **U1** 별도 실행에서 마지막 SDL flush는 약 0.003ms였다. 제출 뒤 `glFinish`의 강제 완료 대기는 평균 1.89ms·P95 3.09ms다. 정상 프레임의 작업 시간에 강제 대기를 합산하지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

### CPU 그리기

상세 구간을 가볍게 잰 160프레임에서 그리기 CPU 경과 평균은 25.39ms였다. 적 전체 11.47ms가 가장 크고 HUD 7.73ms, 플레이어 파츠 2.81ms가 뒤따랐다. 적 안에서는 본체 최종 합성·공격 표시 3.44ms, 근거리 PBR 씬 준비 및 시트 그리기 2.56ms, 근거리 그림자 0.92ms였다. 공격/도형 인스턴스 렌더 호출은 약 17.74회·1.58ms로 최종 합성과 겹치는 하위 구간이다. HUD는 장비 1.36ms, 자원 1.23ms, 카운터 1.13ms, 스캔라인 0.38ms였다.

상세 API 실행의 그리기 35.17ms에서 계측한 API 시간의 합계는 8.94ms다. GL 상태 조회 4.03ms, GL 상태 변경 1.65ms, SDL flush/렌더 타깃 등 경계 1.13ms, SDL 그리기 요청 1.07ms, GL draw/dispatch 0.06ms, 나머지 계측 API 약 0.99ms다. 호출한 `glGet*`은 평균 294.4회이고, GL 상태 조회 묶음에는 `glIs*` 등도 포함된다. API 복귀까지의 시간에는 내부 대기 가능성이 있다.

아틀라스 준비·포즈 형상·컬링·HUD 패널 배치 등 이름을 붙여 잰 준비의 중복 및 API 시간을 뺀 합계는 4.03ms다. 상세 실행의 나머지 22.21ms에는 아직 별도로 이름 붙이지 않은 Python/준비·미계측 호출과 계측비가 섞인다. Python 추적에서 적 도형 정점 기록 `PrimitiveBatch._append`, 엔티티 읽기, 적 재생 상태 선택 및 HUD 도형 큐가 두드러졌다. 상태 조회의 가장 큰 호출 위치는 적 도형 배치의 공통 패스로 약 71회·1.13ms다.
