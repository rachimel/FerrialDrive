# 게임 텍스처 품질 설정과 타격별 자동 전진

- 근거: 현재 대화, [검 이동 명세](../unit-tests/sword_movement.md), [압축 비교 명세](../unit-tests/texture_compression.md), 로컬 `output/game_settings/`, `output/attack_movement/smoothstep_report.json`, 160클립 비교 결과.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 914MiB를 크다고 판단하고 실제 게임 메뉴에서 텍스처 품질을 선택하도록 요청했다. 반해상도뿐 아니라 75%를 추가하고 첫 실행 기본값은 높음 100%로 지정했다. 이유는 용량 부담이며 근거는 해당 사용자 발언, 시각은 scope 참조.
- **사용자 제안 2 (U2):** Ys처럼 공격하며 이동하는 시험을 요청했다. 일반/대시 기준 1·2타 45/90m/s, 3타 60/120m/s, 후속으로 4타 30/60m/s를 지정했다. 4타 대시 60m/s는 질문에 명시 응답했다. 타격별 수치의 세부 선택 이유는 미제시다. [[FDLOG_MISSING_REASON:FDLOG-20261113-game-quality-moving-attacks:U2]] 검색 단서: `걸을 때 공격하면 45m/s`, `3타는 걷기시 60m/s`, `4타는 30m/s`. 시각은 scope 참조.
- **사용자 제안 3 (U3):** 검 공격은 마우스를 바라보며 각 타격 시작 순간 방향을 그 타격 동안 유지하도록 선택했다. 공격 이동도 같은 방향으로 하고 이동 키 없이 자동 전진하도록 선택했다. 타격 중 추적과 예약 클릭 순간 고정은 선택하지 않았다. 방향·이동 일치 요구를 근거로 하며 시각은 scope 참조.
- **사용자 제안 4 (U4):** 전진 가속에 SmoothStep을 요청하고, 짧은 0.1/0.15초 대신 타격 전체 시간에 걸친 가속을 선택했다. 질문에 명시한 타격마다 재가속 기준을 따른다. 세부 감각상의 이유는 미제시다. [[FDLOG_MISSING_REASON:FDLOG-20261113-game-quality-moving-attacks:U4]] 검색 단서: `전진 가속에 smooth step`, `타격 전체 시간 — 끝까지 서서히 가속`. 시각은 scope 참조.

## 2. 사용자 제안 중 AI가 수용한 것

- U1: 높음/중간/낮음 100/75/50%와 기본 높음, 저장/취소, 실제 공유 타이틀·일시정지 메뉴를 연결했다. 75%는 색상과 수치 벡터를 함께 축소한 Oodle BC7/무손실 벡터 후보로 추가했다.
- U2·U3: 4타별 목표 속도를 설정으로 분리하고 타격 시작 마우스 방향으로 자동 전진한다. 예약된 다음 타격은 시작 시 현재 방향을 다시 읽는다. 연계 대기에서는 정지하며 이동 입력으로 대기를 해제한다. 부스트 캔슬은 유지한다.
- U4: 타격 진행률 `t`에 속도 배율 `3t²-2t³`를 적용했다. 각 타격 전체 시간의 평균 속도는 목표의 절반임을 설명했다. 이전 고정 속도 검사 결과를 새 가속 방식의 결과로 사용하지 않는다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 가속 시간을 0.1초/0.15초/타격 전체로 질문했다. 짧은 반응과 점진적인 가속 감각을 선택할 수 있도록 한 질문이며 U4의 명시 답변을 받았다. 시각은 scope 참조.
- **AI 제안 2 (A2):** 4타 대시를 일반의 두 배인 60m/s로 할지, 둘 다 30m/s로 할지 질문했다. 대시 속도가 미정인 요구를 구체화하기 위한 질문이며 U2의 명시 답변을 받았다. 시각은 scope 참조.
- **구현상 판단:** 품질 변경은 원자적으로 저장하고 다음 실행부터 적용한다. 초기 기본값과 저장값을 분리하고 다른 사용자 설정을 보존한다. 실행 중 대용량 자원을 중복 적재하는 교체 경로는 추가하지 않았다. 사용자에게 다음 실행 적용을 표시하지만 별도 명시 승인으로 간주하지 않는다.
- **구현상 판단:** 기존 PNG 본체는 아틀라스와 중복 적재하지 않는다. 검정 RGB의 그림자는 원해상도 알파를 GL_R8로 적재하고 스위즐로 동일한 검정 RGBA 샘플링을 복원한다. 그림자 축소·벡터 손실 압축을 임의로 추가하지 않는다.
- **구현상 판단:** SmoothStep의 구간 적분으로 프레임 이동량을 계산하고 타격 경계에서 시간을 나눈다. 프레임률이 달라도 이동 거리와 다음 타격 속도가 같도록 한다. 모션 포즈 보간과 게임 위치 가속은 별개다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1: 타격 전체 시간 가속을 명시 선택했다. 0.1초 추천안은 채택하지 않았다.
- A2: 일반 30/대시 60m/s를 명시 선택했다.
- 다음 실행 적용·R8·적분 구현은 별도 사용자 승인으로 확정하지 않는다. 이번 사용자 요청을 연결하기 위한 구현 선택이다. 화면과 사용감의 최종 승인은 미수행이다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1):** 아틀라스를 연결해도 기존 PNG 본체·그림자를 그대로 올리면 품질 절감 외에 큰 고정 비용이 남았다. 기존 RGBA 그림자만 약 670.57MiB였다. AI가 실제 보고서에서 발견했다.
- **문제 2 (I2):** 첫 R8 그림자 적용 후 실제 창의 바닥/본체가 검게 표시됐다. GL 텍스처 활성 상태가 SDL 렌더러의 예상과 어긋난 회귀였다. 최초 실패 캡처와 수정 후 캡처를 구분한다.
- **문제 3 (I3):** 타격 전체 가속으로 요구가 바뀌면 기존 고정 속도의 위치 기대값은 더 이상 유효하지 않았다. 이는 이전 구현 버그가 아닌 요구 변경이다. 가속을 프레임 끝 값만으로 계산하면 프레임률별 거리 차이도 생길 수 있어 적분 계산으로 검증했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1은 메모리 부담에 대한 품질 선택 요구다. 75%와 기본 높음을 반영했다. 보간 GPU Storage는 높음 약 **914.16MiB**, 중간 **527.04MiB**, 낮음 **244.39MiB**다. 별도 준비된 75% 후보는 디스크 53.08MiB·로딩 후 Working Set 565.62MiB·첫 present 2.438초였다. 독립 보간 계층 측정이며 게임 전체 로딩/물리 VRAM 수치가 아니다.
- U3·U4로 초기 WASD 방향 공격 이동을 자동 전진으로 바꾸고 고정 속도에서 타격 전체 가속으로 변경했다. 최종 목표 속도는 1·2타 45/90, 3타 60/120, 4타 30/60m/s다. 1.25배 재생 기준 타격 시간은 0.4/0.4/0.4/약 0.533초이며, 일반 공격 한 타격의 총 전진 거리는 각각 **9/9/12/8m**다. 대시를 끝까지 유지하면 두 배다.
- I2의 해결은 사용자 제안으로 확인하지 않았다. AI의 진단/수정은 다음 절에 기록한다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 일반 PNG 로더에서 본체를 제외하고 그림자만 로드했다. 그림자는 RGB를 생략해 약 **167.64MiB**로 줄였고, 중간 품질 실제 실행 보고서는 보간 **552,637,040바이트**, 그림자 **175,784,434바이트**였다. HUD/바닥·드라이버 할당 비용은 별도다.
- I2: `SDL_GL_UnbindTexture`를 수행하고 이전 `GL_TEXTURE_2D` 활성 상태·unpack alignment를 복원했다. 실제 OpenGL에서 RGBA 그림자/R8 그림자의 픽셀이 같고 그리기 상태가 복원되는 검사와 수정 후 화면을 확인했다. 첫 실패 캡처를 성공 근거로 쓰지 않는다.
- I3: `MovementCombat`에서 타격별 목표 속도와 진행률별 평균 속도를 계산하고 다음 타격 경계를 나눠 이동했다. 2→3타 속도·방향 변경, 4타 잔여 시간의 일반 이동 복귀, 방향 정규화, 자동 전진/연계 대기·부스트 캔슬과 30/60/144fps 총 거리를 검사했다.
- **현재 자동 검사:** 검 이동/공격 40개, UI v2 54개, 에셋 로더 15개, 콤보 4개 — 총 **113개 통과**. 에셋 로더 검사는 제한된 임시 폴더 접근으로 처음 실패해 정상 권한에서 같은 15개를 재실행해 통과했다. 구현 결함으로 분류하지 않는다.
- **앞선 동일 작업 중 실제 OpenGL 검사:** 품질 저장 후 새 프로세스 재실행 7개와 압축/캐시/R8 픽셀 비교 11개 통과. 최신 공격 가속 후 재실행한 113개와 구분한다.
- **현재 실제 OpenGL 사전 지정 입력:** 중간 품질 112프레임을 재실행했다. 이동 키 없이 4타 연계, Shift 목표 전환, 각 타격 방향 고정/갱신, 가속 초반/후반, 4타 후 정지를 trace와 캡처로 확인했다. 4타 후반 약 29.80m/s, 이후 0m/s였다. 물리 키보드 조작과 사용자 사용감 승인은 별도다.
- 품질 설정 화면과 공격 캡처를 직접 열어 본체·바닥·그림자·HUD 표시를 확인했다. 모든 방향/모션의 품질 승인이나 전용 공격 하체 모션 제작을 뜻하지 않는다. 병렬 이미지 로딩·화면 전체 보간·일반 대시 방향 통일은 이번에 구현하지 않았다.
