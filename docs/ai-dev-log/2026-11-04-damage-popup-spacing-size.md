# 개별 피해 숫자의 겹침 방지와 자릿수별 크기

## 1. 사용자가 제안한 것

- U1: 공격하거나 피격됐을 때 기체 근처에 뜨는 빨간 개별 피해 숫자를 서로 겹치지 않게 한다.
- U2: 우선 피해량의 자릿수를 기준으로 숫자 크기를 바꾼다.
- U3: 확인 질문에서 순차 표시 대신 ‘주변 빈자리로 펼치기’를 선택했다.
- 이유·의도·판단 근거: 피해 숫자의 읽기 어려운 겹침을 줄이고, 피해량의 크기 차이가 효과에서 더 극적으로 대비되게 하려는 사용자 설명이다.

## 2. AI가 제안한 것

- A1(구현상 판단): 기존 숫자는 고정하고 새 숫자만 가장 가까운 빈자리로 옮긴다. TV 애니메이션이 끝까지 펼쳐진 크기를 미리 예약한다.
- A2(조절용 시안): 1/2/3/4/5자리 이상을 0.75/1/1.3/1.6/1.9배로 표시한다. 기존 2자리 크기를 기준으로 두고 최대 배율을 제한한다.
- 이유·판단 근거: 이미 뜬 숫자까지 계속 밀면 연속 타격 때 화면이 흔들린다. 현재 접힌 크기만 피하면 등장 뒤 다시 겹친다. 자릿수 증가와 함께 크기를 키우되 큰 숫자의 무제한 확대는 제한한다. 정확한 배율과 6px 간격은 사용자가 정한 값이 아니라 설정에서 바꿀 수 있는 시안이다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U3을 수용했다. `DamageNumbers`가 실제 표시 글꼴의 측정 함수를 받아 완성 크기를 구하고, 기존 숫자들과 6px 간격을 둔 가까운 자리를 찾는다.
- `DamageVisual.font_scale`을 TV 등장·퇴장과 함께 그리기에 전달한다. 폰트·빨간색·표시 수명·원래 피해량은 유지한다.
- 현재 75는 1배, 120은 1.3배로 표시한다. 적용 피해량이 줄어 자릿수가 바뀌면 그 값의 자릿수로 크기를 계산한다.

## 4. AI 제안 중 사용자가 수용한 것

- 사용자가 주변 빈자리 배치를 직접 선택했다. 순차 표시·대기열은 채택하지 않았다.
- A1의 기존 숫자 고정 방식과 A2의 정확한 배율은 구현상 판단/시안이며 별도 승인·화면 체감 확인 발언은 아직 없다.

## 5. 반영 후 발견한 문제

- I1: 기존 무작위 분산은 새 숫자가 기존 숫자의 영역 안에 생성되는 것을 막지 않았다. 숫자는 모두 같은 크기여서 피해량의 자릿수에 따른 크기 대비가 없었다. 사용자가 지적했다.
- I2: AI 코드 검토에서 플레이어 피해 숫자는 장면 전환 중 고정되고 타겟 숫자는 이동하므로, 정지 화면에서만 떨어뜨리면 전환 중 다시 겹칠 수 있는 예외를 확인했다.
- 원인: I1은 기존 배치가 점의 무작위 오프셋만 사용한 데 있고, I2는 서로 다른 장면 이동 기준에 있다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1/U2/U3: 사용자가 비겹침·자릿수 크기 대비·주변 빈자리 배치를 제시했다.
- 실제 조치: 초기 무작위 후보 주변에서 완성된 글자 사각형이 들어갈 빈자리를 찾고 수명 동안 고정한다. 겹침을 피할 때는 기존 ±64/44px 분산 범위를 벗어날 수 있다.
- 자릿수별 배율은 `damage_popup.digit_scales`, 간격은 `gap_pixels`로 조정한다. 현재 회피 대상은 개별 피해 숫자끼리이며 다른 HUD·기체·화면 경계 회피는 별도다.

## 7. AI 해결 제안과 실제 해결 과정

- I2: 생성 시 `offset_x_range`로 장면 전환 이동 범위까지 예약한다. 플레이어는 0, 타겟은 현재 전환 폭 36px다. 재사용 모듈은 게임/폰트 모듈을 직접 읽지 않고 실행부가 측정 함수·이동 범위를 전달한다.
- 가로·세로 배율은 함께 적용하고 TV 가로선은 1px을 유지한다. 등장/퇴장 시 중심이 고정되는지 검사했다. 만료·소유자별 제거·전체 초기화 후에는 예약 공간도 해제된다.
- 새 자동 검사 7개를 포함한 UI 검사 50개 통과. 자릿수 경계·상한·동시 생성·소유자 간 회피·기존 위치 고정·공간 재사용·전환 중 비겹침·잘못된 입력을 확인했다.
- 실제 폰트의 Pico2D/SDL dummy 렌더링에서 피해 숫자 8개 동시 표시의 비겹침과 1~5자리 크기를 확인했다. 산출물은 `output/damage_popups/`다. 실제 창 조작·연속 타격의 사용감·실전 성능은 확인 전이다.
- 이 작업은 개별 피해 숫자의 UI 수정이다. 에너지 UI와 핵심 전투 규칙은 이번에 구현하지 않았다. 별도 기획서의 개념 사전 문단은 수정/커밋 대상에서 제외한다.
