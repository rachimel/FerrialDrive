## 1. 사용자가 제안한 것

- **U1:** 허리만 움직이고 무릎 변화가 없어 Idle 느낌이 약하므로 하체를 먼저 굽힌다. 부족하면 후속 피드백하기로 했다.
- **U2:** 허리의 기울기는 유지하고 높이도 맞춰 다리가 굽혀지게 한다.
- **U3, 확인 질문:** 현재 플레이어 해상도와 파츠별 렌더 여부를 확인한다. 파츠 분리 변경 요청으로 확대하지 않는다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1·U2: 기존 허리/상체/팔 회전과 무기 파지를 유지하고 골반 높이·다리 회전만 조정한다. 발 위치·회전·간격은 고정한다. 모델·리그 구조는 유지하고 별도 후보에 저장한다.
- U3: 원본은 768×768, UI는 0.25배의 192×192 영역이며 사선 기체 자체는 약 45×77~79px라고 현재 파일에서 확인해 답했다. 현재 UI는 손·장비 포함 통합 `body` 한 레이어다. 기존 분리 설정은 본체·양손·총·검·칼집·양쪽 슬롯 8개이며 팔/다리별 분리까지 된 상태는 아니다.

## 3. AI가 제안한 것

- **A1, 구현상 판단:** 기존 앞으로 숙이는 9프레임에서 골반이 가장 낮도록 추가 하강량 `7×(1-sin(2π×frame/12))cm`를 적용한다. 추가 0~14cm는 검토용 초안 수치다.
- **A2, 실제 제어 방식:** 현재 제작 코드와 저장 후보는 FK 키다. 허벅지·정강이·발 회전을 발 고정 조건으로 계산한 뒤 기존 `unreal-animation`에 JSON으로 전달해 저장한다. 발 IK 노드가 이미 있다는 가정을 구현 근거로 사용하지 않고 새 리그를 추가하지 않는다.
- 선택 근거는 기존 13개 표본에서 골반 높이와 무릎 굽힘이 모두 일정했던 점이다. 현재 공통 Unreal 제작·렌더·Asset Tool 패킹 경로를 재사용한다. 제시/구현 개별 시각은 scope의 미확인 항목이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 높이와 기울기를 함께 고려하는 방향은 사용자 U2의 직접 요청이다. 14cm·최종 굽힘 강도·새 외관의 승인은 아직 확인하지 않았다.

## 5. 반영 후 발견한 문제

- **I1, 기존 문제:** 기존 무릎은 왼쪽 약 31.61도·오른쪽 약 35.52도 굽힌 자세로 고정돼 있었고, 0~12프레임에서 변화가 없었다.
- **I2, 제어 구분:** 현재 Unreal 리그 생성은 FKControlRig를 사용한다. 허리 본만 낮추면 부모가 다른 다리가 자동으로 굽혀지는 구조가 아니므로 골반 높이와 양다리 키를 함께 조정해야 했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U2: 허리 회전 키를 유지하고 골반 높이를 기존 숙임 위상과 맞춰 낮춘다. 양발 접지를 유지하는 다리 포즈를 반영했다.
- U1의 후속 피드백 방침을 유지하며 AI의 수치 통과를 사용자의 굽힘 강도 승인으로 처리하지 않는다.
