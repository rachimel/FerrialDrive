## 6. 사용자 해결 제안과 실제 해결 과정

- **U1, I1** 기존 16m 실행은 별도로 보존했다. 추가 검증에서 중형의 근거리 반경만 양쪽 모두 60m로 맞췄다. 180기·15m·플레이어 HP 100,000·FHD Medium/SMAA·자동 검 입력 및 모든 효과를 유지했다. 런타임 설정 반경은 변경하지 않았다.
- **U2** 기존 258개 점검표를 프로젝트 코드·셰이더 997개로 확대했다. 전수 정적 탐색 뒤 GL·SDL 호출의 런타임 경로와 도구·검증 경계를 확인해 개선 필요 7개, 조건부 위험 19개와 파일별 근거·수정 후보를 `output/performance/enemy_gl_sheet_20261123/opengl_file_review.md`에 저장했다.

## 7. AI 해결 제안과 실제 해결 과정

- 60m 검증의 중형 시트 위치와 RGBA 원본 134개가 같았다. 기본 SDL 렌더를 덧그리는 별도 GPU 픽셀 검사도 통과했다.
- 추가 상세 계측 240프레임씩에서 양쪽 모두 SMAA 시트 206개였다. GL 조회는 전체 344.98→295.25회/프레임, 선택 중형은 62.07→12.26회/프레임이었다. 중형 조회의 CPU 경과는 0.290→0.082ms/프레임이었다.
- 포함 CPU 경과는 중형 `EnemyPartBatch.prepare` 1.048→0.520ms/프레임, `_paint_groups` 0.289→0.287ms, `PartPainter.paint` 0.227→0.234ms, `PartSheetUpscaler.draw` 0.559→0.115ms였다.
- GPU timestamp 평균은 시트당 파츠 0.0739→0.0733ms, Bicubic 0.0056→0.0051ms, edge 0.0042→0.0031ms, weights 0.0084→0.0074ms, blend 0.0042→0.0031ms였다.
- 60m 조건 240프레임 정순·역순 2회 중앙값은 38.91→39.78 FPS와 프레임 P99 33.54→32.14ms였다. 첫 순서의 FPS는 38.66→38.65였고 역순에서는 39.15→40.91이었다. 16m 조건에서는 새 경로가 실행되지 않았으므로 전체 개선 수치에 포함하지 않았다.
- 업데이트마다 한 번만 그리는 전체 화면 RGB 검증을 변경 전→변경 후→변경 전 순서로 실행했다. 변경 후에 GL 시트 경로를 165회 실행했고 두 번째 변경 전과 RGB 해시 35개가 모두 일치했다. 첫 번째 변경 전의 샘플 2개는 다른 두 실행과 동일한 위치에서 각각 107·65픽셀이 달랐다. 최대 채널 차이는 2였다.
- **후속 논의** `gl_pass.py`·`part_upscale.py`·`smaa.py`·`enemy_part_batch.py`는 SDL과 GL 사이의 상태 소유권을 공통화하는 것이 먼저다. `part_painter.py`의 방향 페이지 배열화는 크기·형식별 패딩 및 캐시 예산을 대조하고, `hud_batch.py`·`ui_v2/pico_renderer.py`의 제출 묶음은 기존 알파·가산 순서 안에서 검증한다. 버퍼 업로드의 동기 대기는 타임라인에서 확인한 호출에 한해 별도 검토한다.
- 순서별 원시 실행, 픽셀과 상세 데이터는 `output/performance/enemy_gl_sheet_20261123/`에 보관했다. 실제 조작과 Intel 실기는 미검증이다.
