# 그림자 알파 전용 적재와 아틀라스 병렬 해제 조사

- **기록 ID:** `FDLOG-20261115-shadow-alpha-loading`
- 대화 날짜: 2026-11-15 KST. 사용자 지시와 검증·기록 시각은 구분한다. 개별 발언 시각은 미수집이다. `[[FDLOG_MISSING_TIME:FDLOG-20261115-shadow-alpha-loading:scope]]` 검색 단서: `그림자부터 알파 전용 데이터로 바꿔`, `아틀라스 압축 해제 비용은 어떻게`.
- 근거: 현재 대화, 현행 소스, `output/performance/loading_20261114/`의 고정 설정 비교·전체 알파 일치 검사·압축 해제 벤치마크. 폴더 날짜는 이전 조사 경로를 재사용한 것이며 이번 발언 시각이 아니다.
- **상태:** 그림자 준비·적재 구현과 로컬 데이터 18장 준비 완료. 아틀라스 병렬화는 조사·제안만 했으며 제품 코드에 적용하지 않았다. 직접 조작 승인·커밋·업로드 없음.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 그림자를 알파 전용 데이터로 바꾸도록 요청했다. 이유는 직전 로딩 병목 조사에서 그림자 변환 비용을 확인했기 때문이다. 출처는 현재 대화, 시각은 scope 참조.
- **사용자 제안 2 (U2):** 아틀라스 압축 해제 비용을 어떻게 줄일지 질문했다. 개선책 검토 요청이며 구현 명령으로 확대하지 않는다. 출처·시각은 scope 참조.

## 2. 사용자 제안 중 AI가 수용한 것

- U1을 수용해 PNG 보존형 알파 데이터와 적재 경로를 연결했다. U2는 현행 데이터의 순차·2개·4개 병렬 해제를 별도 비교했다. 수용 근거는 현재 대화의 작업 보고이며 시각은 scope 참조.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 무압축 R8을 사전 준비해 PNG 해제·RGBA 변환·채널 추출을 제거한다. 해상도·알파값은 유지하고 기존 Pico2D GPU 경로를 재사용한다. 무압축 파일·헤더·검증 방식은 AI의 구현상 판단이다. 사용자가 이 세부 형식을 따로 승인했다고 해석하지 않는다.
- **AI 제안 2 (A2):** 아틀라스는 CPU 해제를 4개 이내로 제한하고 GPU 생성·전송은 메인 스레드에 유지하는 방식을 다음 구현 후보로 제시했다. 이유는 아래 분리 계측에서 병렬 해제의 이득을 확인했기 때문이다. 실제 시작 시간 단축은 아직 측정하지 않았다.
- 제안 출처는 현재 대화의 진행 보고와 실측이며 개별 시각은 scope 참조.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 알파 전용 데이터로 바꾸는 범위는 U1로 명시 요청받았다. A1 세부 저장 형식은 구현상 판단이다. A2의 아틀라스 병렬화 구현 여부는 아직 사용자 결정 전이다.

## 5. 반영 후 발견한 문제

- **I1, 기존 시작 지연:** 그림자 18장의 PNG→RGBA 변환이 로딩의 주요 비용이었다. 원본 약 10.89MiB를 누적 약 1,072.53MiB RGBA로 풀었다.
- **I2, 별도 기존 검사 실패:** 확장 OpenGL 회귀 검사 17개 중 잔상 크기 검사 `test_trail_echo_shrinks_in_length_and_width_with_age` 1개가 `initial(32,37).green > 0`에서 실패했다. 알파 전용 경로를 끈 단독 실행에서도 같은 위치에서 재현됐다. 이 검사는 `PicoGroundEffects`의 잔상 도형을 다루며 새 그림자 제작 데이터는 사용하지 않는다. 이번 범위에서 수정하지 않았다.
- 초기 임시 폴더 기반 CPU 검사는 실행 환경의 접근 제한으로 실패했고, 승인된 실행으로 재실행해 통과했다. 이를 제품 기능 오류로 집계하지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1: 원본 PNG·시트 JSON·사용자 설정을 유지하고 옆에 `.png.alpha8` 18장을 생성했다. 알파 페이로드 합계는 281,158,320바이트(268.13MiB), 헤더 합계는 1,440바이트다. 저장 공간은 추가로 사용한다.
- `automate/run.py alpha-textures`가 카탈로그 또는 이미지에서 그림자를 수집하고 원자적으로 제작 데이터를 갱신한다. 준비에만 기존 Pillow 런타임을 사용한다. 게임 없는 공개 도형 시연도 같은 경로로 성공했다.
- 런타임은 원본·알파 해시와 크기를 확인한 뒤 R8로 올린다. 부재·원본 변경 시 PNG 호환 경로를 사용하고, 손상 데이터는 명시적으로 거부한다. 실행 중 제작 데이터를 갱신하지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

- I1 ↔ A1: 파일 계약 자동 검사 7개 통과. 홀수·짝수 폭의 OpenGL 검사용 그림자는 PNG와 전용 데이터가 동일한 화면 픽셀을 만들었고, PNG 디코더 미호출·이전 unpack 상태 복원을 확인했다.
- 확장 GPU 검사는 16/17개 통과했다. 실패 1개와 기존 경로 재현은 I2 참조. 전체 검사 통과로 보고하지 않는다.
- 실제 게임 그림자 18장 모두 SDL이 읽은 PNG의 전체 알파와 전용 데이터의 바이트가 정확히 일치했다. 정지 첫 화면 캡처를 두 경로로 저장해 표시를 확인했고 PNG 파일 전체 바이트도 동일했다. 전체 동작·직접 조작 확인과 사용자 외관 승인은 미검증이다.
- 다른 작업 중 설정 파일이 변경돼 비교용 복사본으로 고정했다. 세 비교 실행은 동일 설정 SHA-256 `203715b35919a2cfecef5431d96301a1bac6846bb366614fadf2e44a1553f3f3`을 사용했다. PNG 경로는 진단 실행에서만 강제 선택했으며 제품 파일·원본을 되돌리거나 이름을 바꾸지 않았다.

- Windows, Python 3.11.16/game2d, RTX 5070 Laptop GPU, OpenGL, 1920×1080, high, VSync 꺼짐. 부모·자식 시간은 합산하지 않는다. OS 파일 캐시를 비우지 않았으므로 콜드 로딩 실측이 아니며, Python 프로세스 생성·인터프리터 시작은 제외한다. 전체 알파 검증과 캡처는 첫 화면 측정 종료 후 수행했다. 따라서 `frozen_alpha2/timings.json`의 PNG 호출 수에는 사후 검증 호출도 포함된다.
- U2 ↔ A2: 현재 92개 아틀라스 페이지의 압축 바이트를 메모리에 미리 읽고 `unpack_payload()`만 비교했다. 작업 수는 1/2/4, 조건마다 3회이며 순서를 회전했다. 병렬 실행은 작업자 수만큼만 진행 중 작업을 유지하고 해제 결과를 장기 보관하지 않았다.

- 병렬 결과는 GPU 전송·동시 적재 버퍼·완료 대기와 결합하지 않은 CPU 해제 단독 결과다. 게임 로딩에서 0.9초가 그대로 줄어든다고 확정하지 않는다. 구현 시 해제 대기열을 제한하고 CPU 준비와 메인 스레드 GPU 전송을 연결해 같은 조건으로 재측정한다.
- 기존 통합 소스 상당수가 작업 시작 전부터 미추적 상태여서 이번 변경만의 독립적인 통합 커밋을 만들지 않았다. 관련 없는 기존 변경을 포함하거나 사용자 파일을 되돌리지 않았다.
