- 근거: 현재 대화의 사용자 요청과 현행 소스·문서.
- 사용자 발언의 정확한 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261114-movement-ui-integration-cleanup:scope]]` 현재 대화에서 “이동 훈련장 기준으로 통합해줘”, “asset tool에서 현재 대체된 기능들은 제거”, “문서들도 이에 맞춰서 정리”를 찾는다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 이동 훈련장을 기준으로 UI 단독 테스트 기능도 통합한다. 사용자는 두 프로그램을 합치는 방향을 제시했고 이번 대화에서 구현을 명시 요청했다.
- **사용자 제안 2 (U2):** `ui_test.py`, `rendering_test.py`, `asset_load_test.py`, `basic_flow.py`, `frame_interpolation_test.py`, `pose_parts_test.py`, `pose_tool_test.py`를 제거하고 `test_unreal*.py`는 다른 폴더로 옮긴다. `tests/blender/`는 현재와 앞으로 사용하지 않으므로 삭제한다.
- **사용자 제안 3 (U3):** 에셋 툴의 대체된 기능을 제거한다. 현행 문서는 대체 이력 설명 대신 남는 기능만 안내한다. 프로젝트 메모리도 현재 기준으로 정정한다.

U1~U3의 출처는 현재 대화다. 개별 발언의 정확한 시각은 scope 태그 대상이다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1~U3을 수용했다. 구현 결과·실행 검사와 최종 외관 승인을 구분한다.
- 삭제한 테스트 전용 화면·검사는 제거하고, 공통 UI 부품·2D 조립·보간·Unreal 수치 검사처럼 계속 사용하는 기능의 자동 검사는 유지했다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 훈련장 명중을 체력·HIT/DAMAGE·피해 숫자·록온·에너지 흡수로 연결하고 UI 디버그 조작을 유지한다. 이유는 이동·공격 결과부터 HUD 반응까지 한 실행에서 확인하기 위해서다.
- **구현상 판단:** `HudPreview`에 시연 상태·효과 관리를, `MovementHud`에 훈련장 상태 연결을 둔다. 입력·공유 카메라·이동·공격은 `MovementApplication`이 소유한다. 디버그 키는 F1~F9·B 등으로 분리한다. 이는 별도 사용자 사전 승인으로 기록하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 사용자는 A1에 이어 “응. 이동 훈련장 기준으로 통합해줘. UI 단독 테스트 기능은 일단 통합하고”라고 명시했다.
- 최종 코드 구조·키 배치·새 화면의 사용자 외관/사용감 승인은 아직 받지 않았다.

## 5. 반영 후 발견한 문제

- **I1:** 훈련장 카메라와 HUD 시연 카메라를 각각 갱신하면 같은 카메라의 속도·투영이 달라질 수 있었다.
- **I2:** UI 에너지 회복·Overdrive를 매 프레임 고정 레벨로 덮으면 흡수 결과가 유지되지 않았다.
- **I3:** SDL dummy 경로는 Compute 입자를 지원하지 않아 통합 HUD 초기화에 실패했다.
- **I4:** 전체 검사의 임시 폴더 접근 제한과 기본 CP949 환경이 일부 검사 실행을 방해했다. 삭제한 화면·제작 필드에 대한 검사 기대값도 남아 있었다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1: 훈련장 표적을 HUD 표적·명중 이벤트에 연결하고 UI 시연 기능을 공통 모듈로 추출했다. 무장 카드 전환·에너지·피해량·필살기 쿨다운은 시연 규칙이며 실제 총기 공격·본편 밸런스로 확대하지 않는다.
- U2: 지정 파일·`tests/blender/`와 사용되지 않는 `pose_session_check.py`를 제거했다. UI v2 단독 진입점도 없애고 자동 검사는 공통 모듈을 읽는다. `test_unreal*.py` 6개는 `tests/automated/`에 두고 경로 계산을 수정했다.
- U3: 에셋 툴의 Blender 포즈 편집·3D 렌더 버튼·CLI 옵션·`render.run`·내장 패널을 제거했다. 2D 조립의 프레임 입력 규칙은 `plan_fields.py`에 분리하고, 독립 Blender 코드의 출력 레시피는 해당 모듈에서 소유하게 했다. 모델·제작 입력·로컬 작업본은 삭제하지 않았다.
- 현행 README·명세·샘플 안내에서 삭제한 경로와 안내를 제거했다. 날짜별 원기록은 재작성하지 않았다. 사용자 요청에 따라 개인 프로젝트 메모리의 정정 기록도 저장했다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: HUD는 공유 카메라의 좌표만 읽고 카메라 갱신은 훈련장에서 한 번 수행한다. 표적 원형 중심과 록온 중심도 맞췄다.
- I2: 에너지·레벨을 HUD 시연 상태에서 검 효과로 공급한다. 직접 레벨 지정은 명시 입력에서만 수행한다.
- I3: OpenGL 경로는 Compute 입자, 소프트웨어 경로는 CPU 흡수 표현을 사용한다. CPU 경로도 도착 시 회복하며 일시정지 중 멈춘다.
- I4: 접근 제한 밖에서 전체 자동 검사를 실행하고 UTF-8 환경을 지정했다. 삭제 기능에만 해당하는 검사·기대값을 정리했으며 공통 UI import 부작용 검사는 독립 프로세스에서 수행하도록 바로잡았다.
- **V1:** 전체 자동 검사 683개 실행, 32개 선택 검사 생략, 실패 없음. 마지막 입력 정리 후 통합 6개·이동/공격 31개·UI v2 55개를 다시 확인했다.
- **V2:** 도형·실제 기체 각각 180프레임을 숨긴 실제 OpenGL 창에서 실행했다. 실제 기체 A/B/C 명중 각 1회, 수동 피해 포함 DAMAGE 480, Compute 입자와 Overdrive를 확인했다. HUD·공격·일시정지·타이틀·2D 에셋 툴 화면을 직접 열어 확인했다.
