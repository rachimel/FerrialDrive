# 분사 Trail·발 추종 마찰·콤보 속도

- 기록 작성 시각: 2026-11-13 23:19:14 KST. 근거: 현재 대화와 수정 파일·아래 로컬 검증 결과.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** Trail 가운데를 흰색으로 만들고 두 차례 더 가늘게 조정한다. 출처: `Trail 가운데는 하얗게`, `하얀색 폭 더 줄여줘`. 의도는 요청한 색·폭의 표현이다.
- **사용자 제안 2 (U2):** 분사 방향으로 번지는 표현을 요청하고 `손가락 효과`로 구체화한다. 실제 시간 표본 모션 블러 구현 요청으로 확정하지 않는다.
- **사용자 제안 3 (U3):** 페이드인은 짧게, 페이드아웃은 길게 해서 불꽃 인상을 강화한다.
- **사용자 제안 4 (U4):** 대시·부스트 중 발 위치에 항상 붙어서 발 위에 겹치는 마찰 효과를 요구했다. 후속으로 확대와 잘림 수정을 요청했다. 바닥 자국 강화라는 AI 해석은 정정했다.
- **사용자 제안 5 (U5):** 베기 콤보를 더 빠르게 재생한다. 속도·전진 거리의 관계를 확인한 뒤 `전진 거리 유지 — 공격 이동속도도 20% 증가`를 선택했다.
- **사용자 제안 6 (U6):** 왼쪽 이동에서 발 효과의 위아래가 뒤집히는 현상을 제보하고 `오른쪽 기준이니까 왼쪽 바라볼때 미러`로 표시 규칙을 확정했다. 의도: 오른쪽 원본의 위아래 형상을 보존한다. 개별 발언 시각은 위 TIME(scope)의 보완 대상이다.

## 2. AI가 제안한 것

- **AI 제안 1 (A1):** 흰 중심에서 기존 에너지색 가장자리로 셰이더에서 섞는다. 이유: 추가 이미지 없이 적용할 수 있다. 출처: 현재 대화 첫 가능 여부 답변.
- **AI 제안 2 (A2):** 콤보 1.25→1.5배와 전진 거리 유지/속도 유지 선택을 제시했다. 이유: 재생 시간만 줄이면 타격당 전진 거리도 줄어든다.
- 구현상 판단: 흰 폭 경계 0.06/0.36→0.03/0.18→0.015/0.09. 꼬리 휨·길게 늘인 결·폭 감쇠로 Smudge 인상을 근사한다.
- 구현상 판단: Trail 길이/강도 상승 0.03초, 기존 종료 유지 0.12초, 소멸 0.35초를 시험 수치로 사용한다.
- 구현상 판단: 발 효과는 기존 회색 마찰 이미지·발별 한 개·기본 64×32px·알파 0.85·30Hz 변형과 기존 동작 강도를 사용한다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U5를 반영했다. Trail 색/번짐은 렌더러, 페이드/외형/콤보 배율은 샘플 설정, 발 추종/수명은 접지 효과 모듈, 활성 조건은 이동 애플리케이션에서 담당한다.
- U6: 발 효과의 이동 각도 회전을 제거하고 기체가 바라보는 x방향으로만 좌우 미러한다. 분사 Trail 등 다른 입자는 기존 이동 각도 회전을 유지한다.
- 발 추종 효과는 대시·부스트·대시 공격 중에 표시한다. 일반 공격·정지·연결 대기에서는 제거한다. 바닥 잔상과 별개다.
- 콤보 1.5배속과 공격 전진 20% 증속을 함께 설정했다. 일반/대시 목표는 1·2타 32.4/108, 3타 43.2/144, 4타 21.6/72m/s다. 기존 4타별 전진 거리를 유지한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1은 `ㅇㅇ 그렇게 수정해줘`로 명시 수용했다. A2는 질문 응답의 전진 거리 유지 선택으로 수용했다.
- 흰 폭·발 효과 크기·페이드 시험 수치와 최종 화면의 사용자 외관 승인은 아직 받지 않았다.

## 5. 반영 후 발견한 문제

- **I1 — AI의 요구 해석 오류:** U4를 바닥 자국/먼지 강화로 해석해 한 차례 구현했다. 사용자 정정 후 이번 강화 프로필을 제거하고 기존 바닥 값을 복구했다.
- **I2 — 잘림 제보:** 왼쪽 위 기준 이미지 영역의 y를 렌더러에서 다시 뒤집어 다른 영역을 읽었다. GPU 색상 표본 검사로 올바른 좌표와 본체 앞쪽 패스를 확인했다.
- **I3 — 왼쪽 발 효과 뒤집힘:** 발 효과에도 이동 각도 회전을 적용해 왼쪽 이동 시 180도 회전으로 위아래가 뒤집혔다. 사용자 제보 후 코드에서 확인했다.
- 검증 환경: 기본 Python에는 Pico2D가 없고 제한 환경에서는 임시 파일 접근이 실패했다. 게임용 Python/허용된 실행으로 검증했다. 변경과 무관한 기존 문서 공백 경고는 수정하지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1: 사용자 정정 `발 위치에 항상 그리는`에 따라 바닥 강화 대신 매 프레임 발을 추종하는 별도 효과로 교체했다.
- U4 확대 요청으로 42×22→64×32px로 조정했다. I2의 `잘려서 보임` 제보로 원본과 렌더 좌표를 조사했다.
- U5의 전진 거리 유지 선택에 맞춰 재생 배율과 공격 전진 속도를 같은 비율로 올렸다.
- I3: U6의 오른쪽 원본/왼쪽 미러 규칙을 적용했다. 이동 방향과 시선 방향이 반대일 때도 시선 방향을 따른다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 발 효과를 매 프레임 교체해 발별 한 개만 유지한다. 발생 간격과 무관하게 갱신하고 입자 상한에서도 보존한다. 본체 앞에 그리며 동작 종료 시 즉시 제거한다.
- I2: 원본 왼쪽 위 좌표를 그대로 읽고 발 효과에는 투명 여백을 포함했다. 출력 배율을 보정하고 원본 이미지는 변경하지 않았다.
- 자동 검사: 접지 11개·실제 OpenGL 좌표/앞쪽 패스 1개·콤보/표현 24개 통과. 신규 콤보 검사에서 일반·대시 각 4타의 전진 거리를 30/60/144fps로 비교했다.
- 실제 화면: 잘림 수정 후 훈련장 150프레임과 대시/부스트 캡처를 확인했다. 결과는 로컬 `output/foot_friction_fixed/`다. 1.5배속 콤보는 누르기 유지 입력으로 실제 OpenGL 150프레임을 실행하고 `combo_01`~`combo_04`와 이동 복귀·중간 캡처를 확인했다. `output/combo_speed_150/held_report.json`과 `held_frames/`에 결과를 둔다. 기존 클릭 간격 입력만으로는 빨라진 4타 연계를 모두 확인하지 못해 검증 입력을 바꿨다. 사전 입력 실행과 물리 입력 사용감을 구분한다.
- 미검증: 물리 입력 사용감·모든 방향/공격의 외관·사용자 최종 승인. 기존 미커밋 코드에 덧붙인 수정이며 커밋·푸시는 수행하지 않았다.
- I3 후속 확인, 2026-11-13 23:25:26 KST 이후: 접지 검사 12개·실제 GPU 검사 2개 통과. 좌우 비대칭 4색 표본으로 수평 미러 뒤 위/아래가 유지되는지 확인했다. 발 추종·앞쪽 표시·이동과 시선 방향 분리도 검사했다. 실제 OpenGL 100프레임을 실행하고 20프레임 오른쪽 대시·60프레임 왼쪽 대시·80프레임 왼쪽 부스트 캡처에서 위아래 형상 유지를 확인했다. 결과는 `output/foot_friction_mirror/`다. 물리 입력 사용감과 사용자 외관 승인은 미확인이다.
