# 록온 획득 200/300m와 공통 해제 400m

- **기록 ID:** `FDLOG-20261117-lock-on-world-meter-ranges`
- 대화 범위: 2026-11-17 KST, 획득 거리와 소실 거리의 정의·수치 확정 및 구현 요청.
- 기록 작성 시각: 2026-11-17 10:07 KST. 개별 사용자 발언의 정확한 시각은 미제공이다. [[FDLOG_MISSING_TIME:FDLOG-20261117-lock-on-world-meter-ranges:scope]] 검색 단서: `획득 가능은 200m`, `록온을 획득하고 이 거리를 넘어가면 해제`, `해제는 400m`, `그렇게 구현해줘`.
- 상태: 구현·현재 문서 반영·자동 검사·실제 기체 OpenGL 지정 입력 재생 완료. 사용자 직접 조작/최종 사용감 승인·커밋·업로드는 미수행.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 일반 획득 200m, 우클릭 조준 획득 300m를 지정했다.
- **사용자 제안 2 (U2):** 소실 거리는 록온 획득 후 그 거리를 넘으면 해제되는 기준이라고 정의했다. 최초 `100m` 안과 이후 `300m 초과` 검토를 거쳐 공통 `400m 초과` 해제로 정했다. 사용자에게 수치 표와 우클릭 해제 후 유지 동작을 설명한 뒤 `ㅇㅇ 그렇게 구현해줘`로 구현을 명시 요청했다.
- 수치 자체를 고른 별도의 직접 이유는 밝히지 않았다. [[FDLOG_MISSING_REASON:FDLOG-20261117-lock-on-world-meter-ranges:U1-U2]] 위 수치 제안 전후의 설명에서 보완한다. 해제의 의미를 획득 후 거리 기준으로 분리하려는 의도는 U2의 정의에서 확인된다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1/U2를 일반 획득 ≤200m·조준 획득 ≤300m·공통 유지 ≤400m/해제 >400m로 반영했다. 우클릭을 놓거나 일반 획득 범위를 벗어나도 기존 록온은 유지 범위 안이면 보존한다.
- 첫 유효 후보 즉시 획득·다른 표적으로 교체 시 연속 1초 대기·사망/비활성 즉시 해제를 유지했다. 교체할 새 적은 현재 획득 범위 안에 있어야 한다.

## 3. AI가 제안한 것

- **과거 해석/검토:** 최초 `소실 100m`를 획득 거리의 추가 여유로 뜻했는지 질문했다. 사용자는 소실 거리의 독립 정의를 제시했고 최종 공통 400m로 정했다. 추가 여유 100m 방식이나 공통 300m는 현재 규칙이 아니다.
- **구현상 판단:** 실제 지면 거리와 마우스 최근접 순위를 분리했다. 거리값을 단순히 투영 픽셀 수치로 바꾸면 세로 투영·몸통 높이에 따라 같은 미터 거리의 결과가 달라지므로 `SwordTarget.position_m`을 범위 판정에 연결했다. 후보 우선순위는 기존 투영 월드 마우스 거리를 보존한다.
- 공통 `MouseAutoTargeting`에 별도 해제 거리와 외부 범위 거리값을 선택 인자로 추가했다. 해당 인자를 생략하는 기존 UI 시연/자동 검사 호출은 유지했다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 최종 200/300/400m 표와 우클릭 해제 후 록온 유지 동작에 대해 사용자가 `ㅇㅇ 그렇게 구현해줘`로 구현을 요청했다. 새 알고리즘·필드 이름·최종 사용감까지 별도 승인한 것으로 확대하지 않는다.

## 5. 반영 후 발견한 문제

- **I1 — 변경 전 코드 확인:** 획득과 해제에 같은 범위를 사용해 우클릭을 놓으면 범위가 줄면서 기존 표적이 풀렸다.
- **I2 — 변경 전 코드 확인:** 플레이어 root와 높이가 적용된 표적 중심의 투영 픽셀 거리를 사용해 실제 지면 미터 거리와 달랐다.
- 이번 수정의 관련 자동 검사에서 실패는 없었다. 자동 검사 통과와 원거리 교전 밸런스/최종 사용자 사용감은 구분한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1/U2: `movement_config.json`의 `targeting.range_m=200`, `aim_range_m=300`, `release_range_m=400`에 분리했다. 기존 표적은 공통 유지 거리로 검사하고 신규/교체 후보는 상태별 획득 거리로 필터링한다.
- I2: 실제 훈련장 표적 생성 때 설정의 `position_m`을 보존하고 `MovementHud.bind_world`에서 플레이어 지면 위치와 연결했다. 기존 공개 도형 입력은 지면 위치가 생략되면 중심을 지면 위 점으로 취급하는 호환 경로를 둔다. 실제 기체 경로는 높이를 적용하기 전의 지면 위치를 명시한다.
- `MovementHud.reset_training`에서도 같은 미터 설정을 복원한다. 기존 시연의 `v2.targeting_sample` 픽셀 값은 훈련장 록온 범위로 사용하지 않는다. 총탄 사거리·명중·카메라/레이더 표시 크기는 별도이며 이번 범위 변경으로 늘리지 않았다.

## 7. AI 해결 제안과 실제 해결 과정

- 관련 검사 **176개 통과**. 미세 경계 200/200.001m·300/300.001m·400/400.001m, 우클릭 해제 후 유지, 해제 후 유지 범위에서 재획득 금지, 획득 범위 안 후보만 교체 대기, 0.99/1초 경계와 입력 검증을 확인했다.
- 방향(축/대각선)·줌 0.5/1/2·세로 투영 0.2/0.8·몸통 높이 0/160px를 바꿔도 같은 지면 거리 판정인지 검사했다. 기존 사격·HUD·카메라·이동 회귀를 포함했다. 거리 계산의 불필요한 역투영을 정리한 뒤 관련 26개도 다시 통과했다.
- 실제 기체 OpenGL **380프레임 지정 입력 실행 완료**. 1프레임 A 획득, 우클릭 해제 후 유지, 300~400m 구간 유지, 351프레임 C와 399m에서 유지, 352프레임 약 400.6667m에서 해제를 보고서 좌표로 확인했다. 근거: `output/targeting_ranges_20261117/input.json`, `playback.json`. 자동 입력이며 사용자 손 조작/사용감 승인으로 기록하지 않는다.
- 현재 규칙·설정 위치·미터/표시 좌표의 구분을 PRE-PRD·원거리 명세·이동/UI 명세·샘플 안내에 반영했다. 기존 사용자 변경을 보존했다. 작업 대상에 이전 미커밋·미추적 내용이 있어 파일 전체를 이번 기능의 커밋으로 추가하지 않았다. 커밋·업로드 미수행.
