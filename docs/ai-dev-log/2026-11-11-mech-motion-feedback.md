## 1. 사용자가 제안한 것

- **U1:** 최신 파일을 찾는 경로가 너무 길다. “최신 모션 파일·위치를 찾기 어려움”, “너무 길어. 폴더가”가 직접 근거다.
- **U2:** 빈손을 주먹으로 닫고 손바닥이 몸통 안쪽을 향하게 한다. 최초 바깥쪽 응답은 “아 몸 안쪽”으로 정정했다. “맞아, 빈손도 주먹을 쥐게 해”로 화면 오른쪽의 빈손임을 확인했다.
- **U3:** 검을 든 손의 각도를 정면 쪽으로 조정한다. 손 높이는 “일단 ok”이며 확정적인 전체 자세 승인은 아니다. 후속으로 칼과 손의 길이 방향 사이를 80~100도로 지정하고, 기준이 손목→손가락 방향임을 확인했다.
- **U4:** 몸 자세를 약간 낮추고 왼발을 앞에 뻗는다. 구체적인 거리 수치는 지정하지 않았다.
- U2~U4는 현재 대화의 직접 수정 요구다. 사용자는 최초 확인 범위에서 관절 문제가 보이지 않는다고 보고했으며 이를 전체 전투 모션 승인으로 확대하지 않는다. 발언 시각은 scope 항목에서 분리한다.
- **U5, 후속 피드백:** 메카 기준 왼쪽 빈손의 주먹 모양은 좋으나 오른쪽 무장 손이 움직일 때 반대 방향으로 대응하지 않아 어색하다. 근거는 현재 대화의 “주먹을 쥐고 있는건 좋은데”, “반대편으로 움직이거나 하지 않아서”다. 정확한 방향축·이동량·시간 차이는 지정하지 않았다. 개별 발언 시각은 scope와 같은 미확인 항목이다.
- **U6, 실제 수정 요청:** “ㅇㅇ 그거 반영해서 애니메이션 수정해줘.”로 U5와 A4의 수정 방향을 진행하도록 요청했다. 구체적인 진폭 수치의 사전 승인은 아니다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1: 원본 경로를 이동하지 않고 루트 `모션 보기.lnk`와 짧은 `output/motion/` 검토 폴더를 추가했다. 바로가기는 폴더 탐색 없이 `idle.gif`를 직접 연다.
- U2: 화면 오른쪽 빈손은 실제 리그의 `hand_l`, 화면 왼쪽 검을 든 손은 `hand_r`다. 화면 기준의 사용자 표현과 메카 자체 좌우를 구분한다. 빈손 주먹과 검 파지를 별도로 수정한다.
- U3: 손의 위치·높이를 보존하며 칼손잡이 위치와 결합축, 손가락의 감김을 함께 수정한다. 칼의 월드 수직 각도로 해석하지 않는다.
- U4: 새 후보의 골반·양다리 포즈에 반영한다. 원본 모델·기존 v4 애니메이션을 덮어쓰지 않는다.
- U5: 주먹 모양에 대한 긍정 평가와 양팔 움직임 관계의 수정 피드백을 구분한다. 전체 Idle 승인으로 확대하지 않는다.
- U6: 기존 후보를 보존하고 왼팔 움직임만 수정하는 별도 Unreal 후보를 제작한다.

## 3. AI가 제안한 것

- **A1, 구현상 판단:** 골반을 12cm 낮추고 왼발을 +X 방향으로 35cm 전진시킨 초안을 잡는다. 양손의 기존 위치와 양발의 접지·발바닥 회전을 유지하도록 관절 회전을 조정한다. 이 수치는 사용자 확정값이 아니다.
- **A2, 구현상 판단:** 검의 실제 길이축을 주먹의 손가락 열 방향에 맞추고, 손목→손가락 방향과 약 90도를 이루게 한다. 두 축의 위치·회전을 동시에 맞춰 한손검 파지를 구성한다.
- **A3, 설명:** 칼에 IK 타깃을 새로 만드는 것은 이번 파지 수정의 필수 조건이 아니다. 손의 파지 기준점과 검손잡이의 결합을 먼저 맞춘다. 새 IK 리그 구조의 채택·구현 결정과 구분한다.
- 선택 근거: 기존 Unreal 5.8 리그·AnimDataController·render_units/MRQ를 재사용한다. DCC-MCP production reuse guide v1을 현재 공식 소스에서 읽고 검사했다. 기존 템플릿과 외부 후보를 조사했으며 새 플러그인·외부 에셋·유료 자료는 도입하지 않았다. 세부 근거는 로컬 `automate/workspace/motion_feedback/reuse_decision.json`이다.
- **A4, 후속 수정 방향:** 빈주먹·몸통 안쪽 손바닥 방향을 유지하고 빈팔에 무장 팔과 반대로 대응하는 작은 움직임을 부여한다. 같은 크기의 기계적인 좌우 반전은 피한다. 근거는 U5와 저장된 프레임의 양손 이동 관계다. 현재 답변에서 제시하는 방향이며 구체적인 축·진폭·지연 및 실제 키 수정은 미정·미수행이다. 제시 시각은 후속 정리 시각과 구분하며 개별 시각은 scope 미확인 항목에 포함한다.
- **A5, 후속 구현상 판단:** 0프레임 빈손 위치를 기준으로 오른손의 XYZ 이동에 -0.55배를 적용한다. 빈손의 기존 월드 회전과 손가락 키를 유지하며 상완·하완·손목 회전만 조정한다. 기존 1초 루프의 양팔 관계만 작게 고치기 위한 초안이며 55%는 사용자 확정값이 아니다. 버전별 Python 파일·새 리그·외부 에셋은 추가하지 않고 공통 제작 모듈과 JSON을 사용했다.

## 5. 반영 후 발견한 문제

- **I1:** 첫 후보에서 검이 손잡이를 감싸 쥐는 형태가 아니라 걸쳐진 것처럼 보였다. 사용자가 “닿아만 있다는 느낌”이라고 지적했다. 현재 형상의 실제 칼 길이축과 손 길이축 사이는 약 18.12도였다. 기존 결합 회전을 그대로 돌린 것만으로는 파지가 성립하지 않았다.
- **I2:** 최초 Unreal 실행은 쓰기 가능한 DDC가 없어 중단됐다. 작업 폴더 안의 캐시를 지정한 뒤, 사용자 셰이더 임시 경로 쓰기 제한으로 다시 중단됐다. 애니메이션 저장과 장면 생성 완료를 구분하고 부분 결과를 덮어쓰지 않았다. 허용된 전용 작업 프로세스에서 새 장면을 생성했다.
- **I3:** 최초 ‘오른손 주먹’을 검을 든 리그 오른손에 적용했지만 사용자가 뜻한 손은 화면 오른쪽의 빈손이었다. 후속 확인으로 바로잡았다. 프로젝트의 메카 자체 좌우 규칙을 화면 좌우로 바꾸지 않는다.
- **I4, 후속 동작 피드백:** 사용자가 빈팔의 반대 움직임 부재를 어색하다고 지적했다. 기존 `grip_reloaded.json`에서 양손 위치의 X·Y·Z가 함께 증가하는 0→3프레임, 함께 감소하는 6→9프레임을 확인했다. 저장된 평가 데이터 확인이며 새 Unreal 실행이나 전체 재생 검수는 아니다.
- **I5, 재생 창 확인 미완료:** 출력 GIF의 실제 재생을 확인하려 Helium의 빈 탭 창에 접근을 요청했으나 앱 접근 승인 시간이 초과됐다. 브라우저 조작은 수행하지 않았다. 사용자는 “아니 Helium은 왜?”라고 물었고 AI는 렌더 결과 재생 확인 목적이었다고 설명하고 해당 경로를 중단했다. 애니메이션 편집에 Helium을 사용한 것은 아니다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U3: 칼과 손의 각도를 맞추고 80~100도로 잡으라는 후속 요구를 반영한다. 손목→손가락 방향 기준임을 확인했다. 주먹의 가로 방향과 검의 실제 길이축을 맞추는 새 후보로 재작성했다.
- I3 ↔ U2: 사용자의 명시 응답에 따라 빈손도 별도로 주먹으로 닫고 손바닥을 몸통 쪽으로 돌린다.
- I4 ↔ U5: 빈주먹은 유지하면서 무장 손에 반대로 대응하는 움직임을 요구했다. 이번 응답에서는 피드백 해석·기존 프레임 확인·수정 방향 제시까지 수행했고 실제 키 수정은 하지 않았다.
- I4 ↔ U6: 후속 실제 수정 요청에 따라 빈팔 반대 움직임 후보를 제작했다. 아래 후속 결과는 앞선 피드백 확인만 수행한 단계와 구분한다.

## 7. AI 해결 제안과 실제 해결 과정

- 기존 공통 진입점 `automate/run.py`의 `unreal-animation`, `unreal-units`, `unreal-render`를 사용했다. 버전별 Python 파일·새 리그·외부 모델을 추가하지 않고 로컬 JSON의 포즈·부착 데이터로 수정한다.
- 첫 후보를 저장·별도 프로세스 재로딩하고, 사선·정면·측면·손 확대를 각각 12프레임 출력했다. 첫 후보의 손 위치 오차 최대 약 0.000088cm, 발 목표 오차 약 0.0000051cm, 팔꿈치 최소 내부각 약 128.12도였다. 이 수치와 사용자가 지적한 파지 결함을 별개로 기록한다.
- 수정 후보는 `/Game/MechLab/SwordIdle_GripAligned_20261111/A_SwordIdle`이다. 제작 요청·검증·렌더 근거는 `automate/workspace/motion_feedback/`에 보존한다.
- 검토 파일은 `output/motion/`에 두고 루트 `모션 보기.lnk`로 바로 재생 파일에 접근한다. `.lnk`와 출력물의 Git 제외를 확인했다. 정상 GIF는 12프레임/1,000ms, 느린 GIF는 12프레임/3,000ms임을 파일을 다시 읽어 확인했다.
- 최종 후보의 별도 Unreal 프로세스 재로딩 확인: 손/검 각도 약 89.99990~89.99996도, 양손 위치 오차 최대 약 0.000088cm, 발 목표 오차 약 0.0000051cm, 손잡이 부착 오차 약 0.000103cm, 반복 끝점 위치 오차 0cm다. 빈손 손바닥의 몸통 안쪽 방향도 확인했다. 근거: 로컬 `verification.json`과 `grip_reloaded.json`.
- 사선·정면·측면·검 파지 확대·빈손 확대의 각 12프레임 접촉 시트와 손 확대 이미지를 AI가 직접 열었다. 검손잡이가 손가락 안에 놓이고 빈손이 닫힌 형태를 확인했다. 모든 연속 시각의 정밀 충돌이나 정상/느린 재생의 실제 창 사용감을 보증하는 검사로 확대하지 않는다.
