# UI v2 공통 외곽과 몸통 비례 록온

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** HP를 더 얇게 하고 HP/에너지 외곽을 필살기 마름모에 맞춰 크기를 조정한다. 레벨 외곽은 HP를 침범하지 않고 붙으며 꺾임을 곡선으로 바꾼다. 경계의 정렬·접합이 의도다. 시각은 scope 태그를 따른다.
- **사용자 제안 2 (U2):** HIT 아래 바를 어두운 평행사변형으로 만들고 숫자 아래에 붙인다. 왼쪽 조각들의 위치·각도는 사라지는 잔상처럼 정리한다. 시각은 scope 태그를 따른다.
- **사용자 제안 3 (U3):** 표적 획득 테두리는 몸통에 위치하고 적 크기에 비례하되 현재보다 작게 표시한다. 01·02 로드아웃의 3D 회전은 계속 고려한다. 대상 부위와 후보 유지의 명시 요청이다. 시각은 scope 태그를 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1~U3을 수용했다. 공통 접점 계산·곡선 레벨 외곽·받침판/잔상·몸통 Rect 기반 테두리를 구현했다. 로드아웃의 기존 사선 표현을 유지하며 커서 반응형 3D 회전은 후보로 기록했다.
- 구현 범위와 새 이미지에 대한 사용자 최종 승인을 구분한다.

## 3. AI가 제안한 것

- **AI 확인 1 (A1):** “레이아웃 버튼”이 01·02 로드아웃인지 질문했다. 메뉴 글자 회전 제거와 대상이 다른지 확인하려는 의도다. 시각은 scope 태그를 따른다.
- **구현상 판단 (A2):** HP 채움은 16 논리 px, 레벨 곡선 강도는 12px로 시험했다. 마름모 크기는 바의 위/아래 경계에서 계산하고, 숫자 글꼴의 빈 하단 여백을 제외한 기준선에 받침판을 붙였다. 사전 승인 수치로 취급하지 않는다.
- **구현상 판단 (A3):** 몸통 표시 Rect와 비례 배율을 UI 상태로 공급하고 7 키에 크기 비교를 연결했다. 적의 실제 게임 데이터 연결을 구현한 것은 아니다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1에 사용자가 “맞아, 01·02 로드아웃 버튼”이라고 답해 지칭 대상을 확인했다. 새로운 3D 회전 기능의 구현 승인으로 확대하지 않는다. 시각은 scope 태그를 따른다.
- A2~A3의 수정본 외형은 확인 대기다.

## 5. 반영 후 발견한 문제

- **I1:** 큰 표적 시연에서 표적명이 다리와 겹쳤다. AI가 이미지에서 확인했으며, 이름표가 테두리 크기에만 붙어 기체 비율을 충분히 반영하지 못한 것이 원인이었다.
- **I2:** 곡선의 이동 검사를 정수 좌표처럼 정확 비교해 미세한 부동소수점 차이로 검사 1개가 실패했다. 외형 결함과 구분한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1: HP를 16px로 줄이고 마름모의 위/오른쪽/아래 꼭짓점을 두 바와 공유했다. 레벨 상단은 HP 아래 경계에 접하며 그 위로 올라가지 않는다. 곡선으로 연결했다.
- U2: 숫자 밑에 어두운 평행사변형을 붙이고 왼쪽에 점차 작고 투명한 세 조각을 배치했다. 시간 소멸 애니메이션으로 확대하지 않았다.
- U3: 카메라 투영 후 몸통 Rect의 중심·폭·높이에서 테두리를 계산한다. 몸통 정보가 없으면 프레임을 그리지 않는다. 기본·0.75배·1.5배로 확인했다.
- I1~I2에 대한 별도의 사용자 해결 제안은 이 기록 시점까지 없었다.

## 7. AI 해결 제안과 실제 해결 과정

- I1의 이름표를 몸통 높이도 반영해 아래로 옮기고 큰 표적 이미지를 다시 열어 확인했다. 도움말 글자도 사선 외곽 안으로 정리했다.
- I2는 곡선 좌표를 허용 오차가 있는 비교로 바꿨다. 이후 v2 자동 16개·기존 UI 포함 71개가 통과했다.
- 실제 Pico2D/SDL dummy에서 10개 상태 렌더·자원 해제·배율/viewport/clip 복원을 확인했다. 표적 크기·감소·숫자 이동·흡수·도움말 이미지를 열어 검토하고 기본/큰 표적/도움말의 수정본도 다시 확인했다.
- 실제 창 조작·Runner 드롭·전체 재생 사용감·게임 연결·수정본 승인·커밋은 기록 작성 시점에 미확인이다. 이미지 출력은 `output/ui_unit_test_v2/`이며 커밋하지 않는다.
