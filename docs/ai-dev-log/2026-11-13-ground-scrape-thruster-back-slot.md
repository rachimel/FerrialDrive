## 3. AI가 제안한 것

- **구현상 판단 A1:** 기존 SurfaceFull 형상·재질·Skeleton과 공통 animation_clip/render_units/MRQ/조립 경로를 재사용했다. 새 형상을 생성하거나 기존 Blender 본/웨이트/Constraint를 Unreal 리그에 복사하지 않았다.
- **구현상 판단 A2:** 흙은 마찰/파편/연기, 금속은 추후 spark/연기 프로필로 분기하도록 로컬 계약에 구분했다. Trail은 기존 `energy_color`와 실제 노즐 좌표를 재사용하는 연결 대상으로 남겼다. 금속 spark와 게임 Trail의 실제 구현 완료를 뜻하지 않는다.
- 제시/구현 확인 시각은 위 기록 시각이다. 제안과 개별 진행 보고의 정확한 발언 시각은 scope 참조.

## 5. 반영 후 발견한 문제

- **I1 — AI 조사 오류:** 이름에 슬롯이 없다는 이유로 백웨폰 슬롯이 없다고 단정했다. 사용자의 지적 후 후면 이미지·형상 목록·원본 드라이버를 대조해 기존 `Subarm_Weapon_Dock_L/R`와 승강 구조임을 확인했다. 잘못된 신규 마운트 제안은 채택하지 않았다.
- **I2 — 원본 기구 이관 공백:** 현재 Unreal에는 원본 승강/볼/좌우 슬롯이 단일 `subarm` 본으로 단순화돼 있다. 원본 평가에서 승강뿐 아니라 텔레스코프 길이와 가로 지지대 폭도 변한다. 균일 크기 변환만으로 대체하면 가로 지지대 정점 오차가 최대 0.065 모델 m라 해당 임시 접근은 사용하지 않았다.
- **I3 — 출력 환경:** 현재 작업본에 MRQ 활성화와 CustomDepth/알파 출력 설정이 빠져 첫 렌더가 실패했다. 설치/프로젝트 설정 변경 대신 출력 프로세스의 내장 플러그인·일회성 설정 인자로 해결하고 새 완료 기록을 확인했다.
- **I4 — 조사 보고 경로:** 최초 새 동작 작성은 저장된 뒤 이전 tracking 출력 경로 충돌로 보고가 중단됐다. 새 동작을 재생성하지 않고 inspect_only 요청과 새 tracking 경로로 재로딩했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U3: `등 스러스터 위에 검은 부분`이라는 사용자의 위치 정정으로 기존 도크를 식별했다. 새 마운트 추가가 아니라 기존 승강·가로 확장 구조를 보존하는 방향으로 정정했다.
- U2의 `지면에 수평` 정정을 새 스러스터 목표 축으로 반영했다. 원본의 하향 착지 감속 제어와 혼동하지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

- 원본을 저장하지 않고 기존 `subarm_deploy` 평가를 조사했다. 완전 전개에서 승강 1.04m·좌우 각각 0.39m 확장, 볼 방향은 위상 0.25→0.5에서 반영된다. 수치는 원본 루트 정규화 좌표이며 게임 월드 거리 적용값으로 확정하지 않는다. 외피/하부 도관 고정과 텔레스코프·가로 지지대 변형을 분리 기록했다.
- 새 스러스터 동작의 Unreal 재로딩 5표본에서 축 수직 성분 최대 약 1.88e-8, 파지 위치 오차 최대 약 1.95e-5cm다. 나머지 본 변환 보존을 대조했다. 자동 수치 검사는 전체 간섭/외관 승인을 뜻하지 않는다.
- 6면 정지 프레임과 게임 시점 3방향×4프레임, 총 18프레임을 실제 렌더·재합성했다. 통짜 대비 실루엣 일치, 잘림 없음, RGB 2/255 초과 차이는 프레임당 최대 1픽셀이다. AI가 6면·실제 배율·12개 게임 시점 프레임을 직접 열어 확인하고 `visual_review.json`에 판단과 한계를 기록했다.
- 승인 원본 `.blend`의 해시가 유지됨을 확인했다. AI 이미지·Unreal 작업본·검토 출력은 Git 제외 경로에 유지했다. 원본 제어 조사와 native 후보 렌더는 완료지만, 백웨폰 전개 자체의 Unreal 복원과 파티클/Trail/스왑 연결은 남아 있다.
