# 검 잔상 PBR 인스턴싱

- **기록 ID** `FDLOG-20261122-echo-instancing`
- 2026-11-22 KST. RTX 5070 Laptop·OpenGL 4.6, FHD·Medium·SMAA, 적 180기·15m 간격, 플레이어 HP 10만, 고정 60Hz 검 자동 입력, VSync·프레임 제한 해제, 무음.

## 1. 사용자가 제안한 것

- **U1** 검 잔상을 인스턴싱으로 바꾼다. 바로 앞 분석에서 전체 `PartPainter.paint` 호출 가운데 약 61%가 잔상이었고, 잔상마다 반해상도 렌더 타깃을 전환했다. 정확한 요청 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261122-echo-instancing:U1]]`. 검색 단서는 `잔상쪽을 instancing으로`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 선택된 비페이지 PBR 잔상을 같은 아틀라스 뱅크 조합별로 묶어 반해상도 타깃 한 장에 그린다. `PartPainter`·`InstancedQuads`와 파츠 포즈 테이블을 재사용하고 위치·보간율·색조·밝기·불투명도를 인스턴스별로 전달한다. 반투명 시트는 기존 잔상 순서로 화면에 합성한다.

## 3. AI가 제안한 것

- **A1 · 구현상 판단** 기존 120프레임에서 잔상 561개가 나타났고, 그중 335개가 서로 다른 상체·하체 방향 뱅크를 썼다. 뱅크 조합을 기준으로 묶으면 이 회차의 파츠 제출은 270회로 계산됐다. 혼합 뱅크의 허리 정렬이 유지되도록 셰이더 포즈 행 키에 리소스 적재 식별자·키포즈 쌍·원본 허리 위상을 포함했다.
- 재투영, 투명 여백, 확대 필터 및 순서에 대한 검증을 위해 같은 배경의 전체 화면과 별도로 반해상도 타일도 읽었다. 2×2 화면 미분이 참조하는 픽셀 묶음의 위치를 보존하도록 타일 시작점을 짝수 픽셀에 놓았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 인스턴싱 적용은 사용자 요청이다. 시트 크기·포즈 테이블·지원 조건과 검증 회차는 구현상 판단이다.

## 5. 반영 후 발견한 문제

- **I1** 전후 색상의 8비트 단위 차이가 둘 다 그려지는 영역 안에서 발견됐다. 반해상도 타일을 대조한 첫 구간에서 같은 타일 크기와 화면 목적지로 그려졌고, 바뀐 타일의 채널 차이는 최대 1단계였다. 확대·합성 후 전체 화면의 채널 차이는 최대 2단계였다.
- **I2** 인스턴싱용 시트 및 포즈 데이터를 함께 유지하면서 잔상 텍스처 사용량이 36→548KiB로 늘었다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 단일 잔상, 배치에서 처리할 수 없는 프로필·리소스와 OpenGL 초기화 실패에는 기존 개별 경로를 사용한다. 포즈 잔상 사이에 기존 스프라이트가 끼면 앞 배치를 먼저 합성한다. 순서·폴백 테스트를 추가했다.
- `566f1bb`와 기존 로컬 변경을 포함한 작업본에서 잔상 경로만 바꿔 비교했다. 각 회차 30프레임 예열 후 120프레임을 측정했고 단독 FPS 전후 각 4회의 실행 순서를 교차했다. 비교한 입력·교전 상태 해시 120개가 일치했다.
- 전체 FPS 중앙값은 **39.45 → 41.93**(+6.3%)였다. 프레임 작업 P50은 23.49→22.86ms, P95는 32.83→31.98ms였다. 네 쌍 모두 적용 후 FPS가 높았다.

- **I1** 아래 경과 시간은 전후 상세 계측 각 2회에서 프레임당 평균을 구한 뒤 회차 중앙값으로 나타냈다. 하위 함수 시간은 상위 행에 포함된다.

- **I2** 포즈 테이블을 64행으로 제한했고 측정 종료 시 28행을 사용했다. 잔상 텍스처의 논리 바이트를 보고에 합산한다. 원본과 요약은 로컬 `output/performance/echo_instancing_20261122/`에 있다.
