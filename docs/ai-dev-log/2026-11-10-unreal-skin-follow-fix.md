## 2. 사용자 제안 중 AI가 수용한 것

## 3. AI가 제안한 것

- **AI 제안 1 (A1, 구현상 판단):** 평가 메시의 기존 가중치 그룹을 인덱스 그대로 이름만 변환하고, 최종 객체의 실제 그룹 이름이 본과 연결되는지 검사한다.
  - 이유·근거: Blender 5.2에서는 `new_from_object`로 만든 메시를 새 객체에 연결할 때 기존 그룹 이름이 이미 포함됐다. 이전 코드는 변환한 그룹을 덧붙여 기존 `.L/.R` 그룹의 실제 가중치를 `_L/_R` 본에 연결하지 못했다.
- **AI 제안 2 (A2, 구현상 판단):** 기존 Skeleton을 재사용하는 새 Unreal 메시를 검증한 뒤 현재 Actor에 연결한다. 실제 Unreal 메시를 다시 FBX로 내보내 스킨 자체를 검사하고 점이 포함된 하위 본 샘플로 회귀 검사를 추가한다.
  - 이유·근거: 이전 본 행렬 왕복 검사와 원본 구조 지문은 교환 메시의 스킨 연결까지 검사하지 않았다. 같은 누락을 막기 위해 독립 기하 검사와 실제 호스트 입출력을 추가한다.
- 제시 시각·출처: 이번 AI 진단·수정 보고. 정확한 시각은 scope 항목에 포함한다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1):** 기존 교환 사본에서 본은 `UpperArm_L`인데 실제 정점 가중치 그룹은 `UpperArm.L`로 남았다. 메시/그룹 쌍 기준 252건의 잘못된 본 이름 참조가 있었다. 원본에는 없던 포팅 코드 결함이다.
- 원본의 Chest 하위 53개 본에 연결된 메시 268개 중 기존 교환 사본에서는 100개만 유효한 이름으로 검출됐다. 본 자체와 정지 형상은 보존돼 기존 검사로 발견하지 못했다.
- 기존 검사 결과를 모든 스킨 추종의 검증으로 확대할 수 없음을 원래 실험 기록에도 추가했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1의 Chest/Z축 정정으로 팔·어깨의 부모 회전과 메시 가중치 연결을 우선 검사했다. 사용자가 해결 구현을 제안한 것으로 기록하지 않는다. 수정본 연결 후 사용자의 긍정 응답으로 해당 재조작 확인을 기록했다.

## 7. AI 해결 제안과 실제 해결 과정

- I1↔A1: `blender_transfer.py`에서 기존 그룹을 인덱스 그대로 이름 변환하고 실제 객체의 최종 그룹을 검사하도록 수정했다. 고정 장착 부품은 교환용 사본의 가중치를 명시한 장착 본 하나로 구성한다. 원래 파일·정상 원본 가중치는 변경하지 않았다.
- 수정 사본에서는 잘못된 이름 참조가 0건이고 원본과 동일한 하위 메시 268개가 부모 회전을 따라왔다.
- I1↔A2: `/Game/MechLab/PlayerMech_FollowFix`를 기존 Skeleton과 37개 재질 슬롯을 재사용하는 새 메시로 가져왔다. 이 Unreal 메시를 FBX로 다시 내보내 검사했으며 Chest 30도 회전에서 하위 정점 **50,022개**, 최대 추종 오차 약 **1.06e-6 월드 좌표 단위**, 잘못된 이름 참조 0건으로 통과했다.
- 현재 Actor를 수정 메시로 연결했다. 본 수는 71개이며 기존 메시 에셋은 보존했다. 연결 전 저장한 Sequence 키 파일의 해시가 연결 후에도 일치했다. 본 이름·부모·Rest Pose와 원래 Blender 모델은 수정 대상이 아니다.
- 게임 에셋 없는 세 본·세 상자 샘플의 `Chest→Arm.L` 구조로 원본 blend·교환 blend·FBX의 독립 검사 3개를 통과했다. 각 파일에서 상체·팔 정점 16개가 부모 회전을 따라왔다. Unreal 수동 시연 전체를 검증한 것으로 확대하지 않는다.
- 시각 확인: 실제 Unreal 캡처와 Unreal 출력 메시의 Chest 30도 상태를 앞뒤좌우위아래 확대·240px로 AI가 확인했다. 어깨·상박·팔꿈치·전완·손의 연결을 확인했다. 이 검사 당시에는 사용자 재조작 확인 대기였고 이후 긍정 응답을 받았다. 전체 관절 가동·장갑 간섭은 미검증이다.
