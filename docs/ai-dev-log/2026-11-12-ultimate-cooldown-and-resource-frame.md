# 필살기 쿨다운 채움·자원 테두리

- **기록 ID:** `FDLOG-20261112-ultimate-cooldown-and-resource-frame`
- 기록·검증 기준: 2026-11-12 23:21 KST. 발언별 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261112-ultimate-cooldown-and-resource-frame:scope]]. `아래에서 부터 천천히 밝아지는`, `테두리 더 두껍게`, `왼쪽 아래`, `윗 테두리의 높이를 HP 바랑`, `진동할 때 모션 블러`를 검색한다.
- 상태: 독립 UI 구현·자동 검사·실제 GPU 캡처 확인. 본편 연결·실제 창 사용감·사용자 외관 승인은 별도다.

## 1. 사용자가 제안한 것

- **U1:** 필살기는 쿨다운 때 어두워지고 아래에서부터 천천히 밝아진다. 아이콘·HP/에너지/LV 테두리를 두껍게 하고 오른쪽 꺾임은 짧게 한다. LV 레이블은 숫자 왼쪽 아래, LV 영역 윗선은 HP 바와 같은 높이다.
- **U2 — 의견 질문:** 진동할 때 모션 블러를 넣는 안을 물었다. 구현 지시로 확정하지 않고 현재 HP 블러와 묶음 전체 적용 시 주의점을 답했다. U1/U2 시각은 scope 범위다.

## 2. AI가 제안한 것

- **A1 — 구현상 판단:** 쿨다운 아이콘의 기본 밝기는 22%, 밝은 영역은 남은/전체 시간 비율로 아래부터 자른다. 상태에 `ultimate_cooldown_duration_seconds`·`ultimate_recovery_ratio`를 추가해 표시가 샘플 설정에 직접 의존하지 않게 한다. 기본/샘플 기간은 기존 5초다.
- **A2 — 구현상 판단:** 외곽 3px·오른쪽 사선 7px를 시험하며 위/아래 길이는 같게 유지한다. LV는 숫자 표시 상자의 왼쪽 아래, LV 윗선은 HP 윗선에 맞춘다.
- **A3 — 의견 답변:** 묶음 전체의 진동 블러는 최대 속도 구간에 2~3 화면 px 정도를 권했다. 방향 전환 끝점은 선명하게 하고 수치 가독성을 우선한다. 기존 HP 개별 블러와 중복되지 않도록 고려해야 한다. 이번에는 추가 구현하지 않았다. A1~A3 시각은 scope 범위다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1을 구현했다. 필살기 준비 조건·사용 시 에너지 유지·완료 flash는 유지한다. 쿨다운 진행도는 실제 상태에서 계산하며 일시정지 때 갱신하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1/A2의 수치·클리핑·정렬 방식은 AI 구현상 판단이며 최종 외관 승인은 미확인이다. A3는 의견 답변이며 구현 수용을 추정하지 않는다.

## 5. 반영 후 발견한 문제

- 쿨다운 중 밝은 영역 클리핑이 추가되면서 기존 렌더 Mock에 clip 문맥 지원이 필요했다. 테스트의 Mock을 실제 렌더러 계약에 맞췄다. 실제 GPU 클리핑도 별도로 확인했다.
- 기존 로컬 폰트·미커밋 피해 숫자 모듈·플레이어 에셋/보간 작업은 별도로 보존한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1: 아이콘 밝기는 위로 채우고 테두리 두께와 오른쪽 사선 길이를 분리했다. LV는 왼쪽 아래로 옮기고 윗선을 HP와 정렬했다.

## 7. AI 해결 제안과 실제 해결 과정

- 선택한 UI 검사 103개 통과. 쿨다운 비율·하단 클리핑·어두운/밝은 영역·기간 검증·준비 강조선 조건·LV 윗선 정렬을 확인했다. GPU 입자 코드는 바꾸지 않았고 GPU 자동 검사는 재실행하지 않았다.
- 실제 RTX 5070 Laptop GPU에서 361프레임을 출력하고 회복 0/25/50/75/100% PNG를 직접 열었다. 아래부터 밝아지는 방향·외곽·사선·레이블 정렬을 확인했다. `output/ultimate_cooldown_fill/comparison.png`·`preview.gif`다.
- 묶음 전체 진동 블러는 미구현 제안이다. 실제 조작감·외관 승인은 남아 있다. 이번 기능만 커밋하며 업로드하지 않는다.
