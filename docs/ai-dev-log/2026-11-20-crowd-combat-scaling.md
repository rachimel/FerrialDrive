# 900~1,000기 교전의 충돌·표적·렌더링

**기록 ID** `FDLOG-20261120-crowd-combat`

**검증 환경** 2026-11-20 KST, Core Ultra 9 275HX·Intel(R) Graphics, FHD·중간 품질·SMAA·무음. 원자료는 로컬 `output/performance/encounter_crowd_review/`에 있다.

## 1. 사용자가 제안한 것

- **U1** 카운터·추가 모션·Break 잡기·Assault를 확장할 수 있도록 현행 전투의 병목과 구조를 수정한다. 적 동시 활동 목표는 900~1,000기다.
- **U2** 테스트할 때는 사운드를 끈다. 정확한 발언 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261120-crowd-combat:scope]] 이 대화의 `900~ 1000기`, `사운드는 꺼줘요`, `먼 적은 같은 에셋의 공유 프레임 허용`을 검색한다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1·U2** 현재 교전의 실제 AI·피격·렌더링을 함께 실행했다. 로직 벤치마크는 오디오 장치 없이, 실제 전투 벤치마크는 `--mute`로 실행했다.

## 3. AI가 제안한 것

- **A1** 전체 활동 수와 카메라에 들어온 기체 수를 따로 기록하고, 근거리·록온 기체의 품질을 보존하면서 원거리 프레임을 공유한다. 19:29 KST 300기 시험에서 프레임 평균 163.59ms 중 렌더 제출이 132.97ms였다. 40프레임 중 22프레임이 교전 상태였다.
- **A2** 이동 중 몸체 분리를 근처 후보로 좁히고 실제 접촉 해결은 기존 출현 순서로 수행한다. 공격자와 근접·사격 종류를 피격 사건에 보존한다. 근거는 이번 대화의 코드 분석과 변경 전 로직 측정이다.
- **A3** 1,000기 밀집 측정에서 CPU 렌더 제출이 60 FPS 예산을 초과했다. 같은 방향 아틀라스의 기체를 인스턴싱하고 각 기체의 원래 보간율·깊이 순서를 유지하는 Pico2D 확장을 제안했다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- **A1** 사용자가 전장 1,000기 동시 활동·현재 카메라 범위와 근거리·록온 현 품질·원거리 같은 에셋의 공유 프레임을 선택했다. 구체적인 반경 16m와 기종별 32MiB 텍스처 상한은 구현상 시험값이다.
- **A3** 사용자가 이 대화에서 ‘기체 묶음 렌더링까지 진행’을 선택했다. 기종별 깊이 맵 64타일과 드로우당 최대 64기는 구현상 시험값이다.

## 5. 반영 후 발견한 문제

- **I1** 충돌 격자와 원거리 본체 공유만 적용한 중간 단계에서도 렌더 제출이 컸다. 1,000기 120프레임 호출 프로파일에서 텍스처 아틀라스가 적 이름표와 HUD를 함께 담으면서 글자 표면 생성이 약 2만 8천 회 발생했다.
- **I2** 1,000기 밀집 시험의 두 실행에서 평균 업데이트는 14.92·19.28ms, 렌더 제출은 46.94·60.17ms, GPU 드로우 경과는 8.61·12.94ms였다. 단계별 CPU 시간과 GPU 질의 시간은 중첩될 수 있다. 목표 프레임 예산은 16.67ms다.
- **I3** 20:19 KST 연속 시험 보고서를 확인하면서 이동 순환에도 일반 자동 공격의 2초 초기화 설명이 기록된 것을 발견했다. 실행 입력과 보고서 표기를 일치시켰다.
- **I4** 기체별 보간율만 개별 전달한 첫 묶음은 밀집 시험 마지막 프레임에서 근거리 62기에 PBR 55회 제출이 필요했다. 기체마다 현재 프레임 쌍이 달라 자주 나뉘었다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **I1·I2 ↔ U1** 원거리 적은 사용자가 허용한 동일 에셋의 모션·방향·프레임만 공유했다. 모든 적의 이동과 공격은 같은 시뮬레이션에서 처리했다. 근거리·록온의 임계값, 외관과 조작감에 대한 최종 승인은 별도다.
- **I2·I4 ↔ A3** 근거리 기체별 프레임 번호·보간율을 GPU에 전달하는 경로를 실제 교전에 연결했다.

## 7. AI 해결 제안과 실제 해결 과정

- **충돌** 프로필 반경을 포함하는 미터 격자를 도입했다. 셀을 넘어 밀리면 다음 출현 순서부터 다시 조회한다. 매 갱신의 직접 재배치·사망·교체도 격자에 반영한다. 혼합 반경 무작위 이동 640회, 연쇄 밀림 및 기존 교전 검사를 확인했다. 1,000기 1/60초 이동 갱신은 12m 격자 675.93→5.48ms, 3m 격자 706.27→16.61ms였다. 동일한 가상 출현·추적 조건에서 각 3회차의 회차별 평균 중앙값이다. 갱신당 내부 스텝은 2회이며 렌더링을 포함하지 않는다.
- **피격·모션** 피격을 공격자 ID·공격 종류·피해량·방향으로 전달한다. HUD·무기 표적의 투영 갱신을 줄이고 교전 표적은 ID로 조회한다. 기존 공통 공격 클립과 선택형 공격별 클립·타이밍을 함께 지원한다. 카운터·제압·잡기·Assault의 판정과 새 에셋은 미구현이다.
- **HP** 교전의 적 HP와 파괴 시점을 모델에서 확정한다. HUD가 연결된 검·총·폭발과 훈련 키도 같은 판정을 사용한다. 외부 교전 코드에서 적용한 피해는 변경된 ID만 HUD로 전달한다. 선택·비선택 표적의 즉시 적용, 대상 초과 피해, 사망 표현 중복 방지와 단독 HUD를 검사했다.
- **묶음** 프레임별 파츠 좌표를 GPU 표로 재사용한다. 같은 모션·방향을 묶어 화면상 크기로 렌더한 뒤 기존 발 위치의 깊이 순서대로 합성한다. 전용 확대 필터·비단위 렌더러 스케일 등은 기존 경로로 처리한다. 그림자는 기존 해상도의 광원 깊이 맵을 타일에 보관해 서로 다른 포즈를 함께 투영한다. 기종별 추가 상한은 프레임 좌표 8MiB, 근거리 합성 타깃 8MiB, 256² 지면 깊이 맵 64개 16MiB다. 소형·중형에서 이동·공격·파괴의 서로 다른 프레임 68기를 겹쳐 2회에 제출했으며 RGB 차이는 최대 2/255였다. 80개 포즈의 그림자 160개는 3회 제출했고 최대 6/255였다. 캐시 재사용과 타일 교체 후도 대조했다.
- **렌더링** 근거리·록온은 기존 보간 경로로 그리고, 원거리 PBR 본체·지면 그림자는 필요할 때 캡처해 재사용한다. 이름표는 별도 2048² 아틀라스를 쓰고 도형 인스턴스는 GPU 텍스처 높이 한도에서 순서대로 나눠 그린다. 소형·중형에서 이동·공격·파괴 각 한 표본을 실제 OpenGL로 대조했다. 원본 픽셀 크기의 전경에서 RGB 채널 차이는 본체 최대 2/255, 그림자 최대 1/255였다. 거리 전환 중 전체 모션과 장시간 캐시 사용량은 미검증이다.
- **실행 조건** 자동 SMG는 60Hz 고정 갱신·준비 30·측정 120프레임이다. 플레이어 HP를 시험 프로세스에서 100,000으로 높였고 VSync와 자원 제한을 해제했다. 아래 모든 실행에서 측정 프레임 전체가 교전 상태였다. 6초 이동·스왑은 준비 뒤 360프레임을 재시작 없이 이어갔다. 실측값은 이 장비에서의 처리량이며 최소 사양 실기는 미검증이다.

- 6초 연속 시험은 360프레임 전체에서 1,000기가 생존했다. 마지막 프레임에서 가장자리 여유 영역을 포함해 381기를 렌더 대상으로 골랐고, 스프라이트 368기 중 318기가 원거리 공유 경로였다.
- 20초 연속 시험은 1,200프레임 전체에서 1,000기가 생존했다. 마지막 프레임의 스프라이트 138기 중 123기가 원거리 공유 경로였다. 측정한 모든 프레임이 60 FPS 예산을 넘었다. HP 분리 전후 실행 간 차이에는 CPU·GPU 처리 시간 변동이 함께 관측돼 HP 변경만의 비용으로 해석할 수 없다.
- **순서 교차 대조** 1,000기·12m·SMG, 같은 프로세스에서 조건별 준비 30·측정 90프레임, 2회차 역순이다. 원거리 프레임 공유는 전 조건에 적용했다. 개별 제출→본체만 묶음→본체·그림자 묶음의 평균 FPS는 1회차 9.24→13.46→15.41, 2회차 9.44→9.54→11.46이었다. CPU 렌더 제출 평균은 각각 82.43→50.52→40.35ms, 75.33→70.52→55.35ms였다. 원자료는 `batched_crossover/report.json`이다.
- **최종 부하** 20초 이동·스왑은 1,200프레임 전체 1,000기 생존, 14.02 FPS였다. 밀집 SMG는 마지막 스프라이트 361기 중 299기가 원거리 공유였고, 근거리 62기의 파츠를 16회, 근거리 지면 그림자 표시를 1회에 제출했다. 같은 실행에서 프레임당 업데이트 평균 30.01ms, 렌더 제출 69.59ms, GPU 드로우 경과 15.46ms였다. 깊이 타일 갱신·완성된 본체 스프라이트의 최종 화면 합성은 16회·1회에 포함하지 않는다. `batched_*` 보고서에 실제 설정·FPS 분포를 기록했다.
- **호환성** 보수 UHD 630 기능 가드를 추가로 켠 실행은 플레이어 PBR 초기화에서 중단됐다. 해당 카탈로그는 프래그먼트 텍스처 단위 26개를 요구하고 가드는 16개를 제공한다. 최소 사양 실기의 FPS는 미확인이다.
- **검증·인계** 실제 OpenGL 검사 27개 통과. 전체 자동 검사 1,138개 실행, 70개 생략, 실패 1건·오류 3건이다. 에너지 회수 검사에서 CPU 궤적과 GPU 회수량 기대값이 맞지 않았고, 네온 글자 검사에서 예상 텍스처 캐시 키를 찾지 못했다. 로그는 `batched_regression.txt`에 있다. 충돌·피격 `7d70d3a`, 부하 시험 옵션 `f3bb23b`, 적 HP 분리 `e2c875c`는 로컬 커밋이며 커밋만 추출한 환경에서도 교전 규칙·충돌 검사 17개를 통과했다. 기존 미커밋 PBR·HUD에 의존하는 묶음 렌더 연결은 작업 트리에 있다. 60 FPS 예산에서 남은 우선순위는 CPU 렌더 제출과 밀집 교전의 갱신 시간이다.
