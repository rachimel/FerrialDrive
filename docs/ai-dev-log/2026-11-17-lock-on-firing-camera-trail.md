## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 기관단총에 맞은 적을 록온하는 흐름을 정정하고, 이미 록온한 적을 향해 쏘도록 했다. 이유는 사용자가 의도한 표적 선택과 사격의 관계다.
- **사용자 제안 2 (U2):** 머리만 표적을 보는 기존 생각을 넓혀 머리·팔·상체에 하체 기준 좌우 ±45° 여유를 주기로 했다. 옆걸음이 어색하다는 사용감도 밝혔다. 후속 질문에서 한계 초과 시 하체도 따라 회전하는 후보를 선택했다.
- **사용자 제안 3 (U3):** 록온 표적이 화면 중심에 오는 안을 질문했다. 후속 질문에서 플레이어·표적 중간점 카메라를 선택했다. 획득 거리 수치 재조정은 나중으로 미뤘다.
- **사용자 제안 4 (U4):** 총알 Trail을 더 길게 요청했다. 정확한 길이와 별도의 직접 이유는 미제공이다. [[FDLOG_MISSING_REASON:FDLOG-20261117-lock-on-firing-camera-trail:U4]] `총알 Trail 더 길게` 전후의 표현 의도 설명으로 보완한다.
- **사용자 제안 5 (U5):** 특정 거리를 벗어나면 록온이 소실되도록 요청하고, 1초 대기는 이미 다른 적을 록온 중일 때 더 가까운 후보로 교체하는 경우인지 확인했다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1: 총탄 목표를 록온 좌표와 공유하고 실제 피격 처리에서는 표적 선택을 바꾸지 않도록 수정했다. 미획득은 마우스 자유 사격, 탄 퍼짐·가까운 적의 가로막음은 유지한다.
- U2: ±45°와 한계 초과 하체 추종을 현재 기준 문서에 반영했다. 실제 전신 `body` 출력으로 독립 회전이 완료됐다고 표현하지 않는다.
- U3: 선택한 중간점 카메라를 기존 부드러운 추적에 연결했다. 거리값 330/460과 교체 대기 1초는 유지했다.
- U4: Trail 길이를 36→108 투영 월드 픽셀로 늘렸다. 구체적인 3배 수치는 AI 구현상 판단이다.
- U5: 첫 획득 즉시·다른 표적으로 교체할 때만 연속 1초·범위 이탈/사망/비활성 즉시 해제로 해석해 반영했다. 다른 유효 후보가 있으면 즉시 재획득한다. '가까움'은 기존 마우스 월드 좌표 기준이며 플레이어 거리 기준으로 바꾸지 않았다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 표적 정중앙보다 플레이어·표적 중간점 카메라를 권했다. 고속 이동 중 플레이어를 화면 밖으로 놓칠 가능성을 줄이려는 이유다. 질문 `lock_on_camera`.
- **AI 제안 2 (A2):** 상체 ±45° 초과 시 하체도 따라 회전하는 안을 권했다. 상체 한계를 지키면서 목표 방향을 향하기 위한 규칙이다. 질문 `aim_yaw_limit`.
- **구현상 판단:** 긴 Trail을 프레임 이동량에 제한하지 않고 누적 비행 거리로 제한했다. 발사 지점 뒤로 꼬리가 뻗지 않게 하면서 높은 FPS에서 짧아지는 문제를 줄인다. 체력·피해 숫자·흡수·전역 카운터는 실제 피격 적 ID로 갱신한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- **I1 — 변경 전 사용자 지적/코드 확인:** `update_guns`는 마우스 좌표로 발사하고 `HudPreview.damage_target`은 피격 적 ID를 `apply_target`에 전달했다. 원하는 선택→사격 관계와 달랐다.
- **I2 — 변경 전 코드 확인:** 첫 획득에도 1초를 기다렸으며 이는 U5의 교체 대기 해석과 달랐다.
- **I3 — Trail 확인:** 한 프레임 이동량 제한 때문에 설정 길이만 늘려도 높은 FPS에서 짧게 표시됐다.
