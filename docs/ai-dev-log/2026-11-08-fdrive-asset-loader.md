# FDrive 에셋 로더 — 등록·공유 자원·디버그 핫 로드

- 기록 ID: **FDLOG-20261108-fdrive-asset-loader**
- 최종 검사·화면 확인·기록 기준 시각: 2026-11-08 19:52:28 KST에 확인한 도구 시각이다. 원래 요청 시각과 구분한다.
- 출처: 현재 대화 “일단 에셋 로더 툴을 만들어야함”과 범위 확인 응답 “1에 FDrive용 에셋 등록하고 디버그 모드에서 핫 로드까지”다. 1은 이미지·시트 미리보기와 로딩 검증을 뜻한다.
- 요청·범위 선택의 정확한 발언 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261108-fdrive-asset-loader:scope]] 위 검색 구절의 원문에서 시각을 확인한다. 사용자 제안 1~2와 AI 제안 1~3에 공통 적용한다.
- 상태: **공통 로더·도구·샘플 구현, 자동 검사 33개와 SDL dummy 화면 확인**. 실제 데스크톱 파일 선택 대화상자·마우스 조작·대형 에셋·낮은 사양 기기의 성능은 미검증이다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 에셋 로더 툴을 먼저 만든다.
  - 이유·근거: FDrive 기반과 플레이어 메카 제작의 후속 작업으로 도구 필요성을 직접 제시했다.
- **사용자 제안 2 (U2):** 이미지·시트 미리보기와 로딩 검증에 FDrive용 등록과 디버그 핫 로드를 포함한다.
  - 이유·근거: 첫 범위를 확인하는 질문에서 미리보기 범위를 선택하고 등록·디버그 갱신을 추가했다. 구체적인 UI 배치와 클래스명은 지정하지 않았다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1/U2를 지원하는 독립 도구를 구현하고 공통 로딩·등록·수명·갱신 코드는 `ferrial_drive/assets/`에 둔다. 기존 Blender 렌더 테스트와 시트 규격을 재사용한다.
- 일반 실행에서 자동 파일 조회를 하지 않고 디버그에서만 핫 로드한다. 새 자원의 로딩·검증에 실패하면 마지막 정상 자원을 보존한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1), 구현 판단:** 공통 카탈로그·관리자·Pico2D 백엔드와 도구 화면을 분리한다. 같은 ID의 핸들은 자원을 공유하고 마지막 참조 해제 시 정리한다. 에셋은 일반 이미지·기존 시트·본체/그림자 번들을 우선 지원한다.
  - 이유·근거: 기존 Asset Load Test는 Blender 빌드와 미리보기를 함께 다루며, PicoSprite는 생성 시 텍스처를 따로 로딩한다. 본편·Unit Test에서 공유할 등록과 수명 관리 계층이 필요하다.
- **AI 제안 2 (A2), 구현 판단:** 변경된 카탈로그·JSON·참조 이미지를 주기적으로 확인하고 렌더러 소유 스레드에서 새 자원을 검증한 뒤 교체한다. 등록 시에도 원본을 다시 검증하고 카탈로그를 저장 직전 다시 읽는다.
  - 이유·근거: 저장 중인 파일·잘못된 PNG·누락 참조·외부 등록 변경에서 기존 정상 자원과 사용자 작업을 보존하기 위한 처리다. 비동기 스트리밍 구현을 뜻하지 않는다.
- **AI 제안 3 (A3), 구현 판단:** 기존 공통 테마, 도형 샘플, 독립 테스트 진입점, 선택적 TimingRecorder 연결과 Windows 바로가기를 제공한다.
  - 이유·근거: 실제 게임 에셋·Blender 없이 도구를 시연하고 기존 Runner·계측 방식을 재사용하기 위해서다. 바로가기와 작업 카탈로그는 로컬 전용이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 사용자는 범위 질문에서 이미지·시트 미리보기/검증과 등록·디버그 핫 로드를 선택했다.
- A1~A3의 세부 API·UI·폴링 간격·저장 규격은 구현상 판단이며 사용자 미술·직접 사용 승인을 받은 것으로 기록하지 않는다.

## 5. 반영 후 발견한 문제

- **발견한 문제 1 (I1), 구현 중 수정:** 툴 화면에서 기존 렌더러의 클리핑 함수 이름을 잘못 연결해 첫 SDL dummy 실행이 실패했다. 올바른 `clip()` 호출로 정정했다.
- **발견한 문제 2 (I2), 실패 보존:** 이전 정상 미리보기가 남은 상태라도 현재 원본은 손상될 수 있다. 등록 시 실제 원본을 다시 검증하지 않으면 잘못된 참조가 저장될 수 있어 재검증을 추가했다.
- **발견한 문제 3 (I3), 메타데이터 처리:** JSON 루트가 배열인 등 규격 오류도 통일된 검증 오류로 처리해야 핫 로드가 기존 자원을 유지할 수 있다. 기존 파서 호출 경계에서 오류를 정규화했다.
- 최초 자동 검사는 실행 환경의 임시 폴더 쓰기 권한으로 실패했다. 권한을 허용한 검사에서 통과했으며 에셋 동작 실패로 해석하지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U2: 미리보기만이 아닌 등록과 디버그 핫 로드까지 첫 범위로 지정했다. 구현 중 I1~I3에 대한 별도 사용자 해결 제안은 없으며 AI가 검증 과정에서 수정했다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 기존 클리핑 호출을 재사용해 화면 없는 실제 렌더와 PNG 캡처를 확인했다. 활성 핫 로드 버튼의 대비와 경로 표시도 화면 검토 후 조정했다.
- I2: 등록 전 원본 재로딩·검증, 중복 ID 거절, 저장 직전 카탈로그 재읽기, 임시 파일을 통한 저장과 읽기 전용 샘플 보호를 구현했다.
- I3: 잘못된 JSON·시트 크기·누락 파일·손상 PNG에서 기존 자원 유지와 수정 후 복구를 검사했다. 로딩 중 파일 변경 시 후보를 폐기하며 성공한 경우에만 세대를 증가시킨다.
- 자동 검사: 신규 25개와 기존 에셋 파이프라인 8개 통과. 같은 ID 공유·마지막 해제·배포 모드 무조회·카탈로그 변경/삭제·부분 로딩 정리·등록 왕복·실제 PNG/시트/번들·합성 키 입력과 선택적 계측을 포함한다.
- 실행 확인: 도형 샘플을 실제 Pico2D SDL dummy에서 미리보기·캡처하고 프로파일 JSON을 생성했다. import만으로 Pico2D를 불러오거나 창을 열지 않는 경계와 독립 테스트 진입점도 확인했다. 실제 데스크톱 조작·파일 대화상자·대규모 성능 확인과 구분한다.
- 공개 대상은 소스·문서·직접 작성한 도형 샘플이다. 실제 게임 에셋과 출력·작업 카탈로그·로컬 바로가기는 포함하지 않는다.
