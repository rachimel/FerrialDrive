## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 현재 요구를 합친 프로그램 규모를 추산하고 목표 FPS를 60~165로 둔다. 수직동기화를 옵션에서 켤 수 있고 필터링 방법도 변경할 수 있어야 한다.
  - 이유·근거: 전체 2GiB 목표, 적·파티클·이펙트·HUD·ADV 요구를 정리한 뒤 프로그램 규모와 표시 성능·화면 옵션을 구체화했다. 옵션 기본값·필터링 종류·기기별 보장 범위는 지정하지 않았다.
- **사용자 제안 2 (U2), 최신 정정:** 게임 타깃을 **60FPS**로 정하고 **Live2D는 도입 가능한 경우 24FPS**로 한다.
  - 이유·근거: 최초 60~165FPS 요구와 AI의 예산 설명 뒤 직접 정정했다. Live2D 도입은 조건부이며 구체적인 통합 방법을 확정한 것은 아니다. 현재 기준 문서에는 이 최신 결정을 적용한다.

## 2. 사용자 제안 중 AI가 수용한 것

- U2의 최신 목표인 게임 60FPS·조건부 Live2D 24FPS와 U1의 수직동기화·필터링 변경 요구를 PRE-PRD 7.7절에 기록하고 관련 절과 맞춘다.
- 표시 속도와 게임 시간 처리, 기기별 실측 결과를 구분한다. 기존 2GiB 전체 목표와 적·효과 우선순위는 유지한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1), 규모 평가:** 현재 요구는 전용 2D 게임 프레임워크와 본편을 함께 구성하는 중형 개인 프로젝트로 평가한다.
  - 이유·근거: 현재 작업 파일의 `ferrial_drive/`는 Python 23개 파일·공백 포함 2,505줄이며 UI가 2,047줄이다. 독립 UI 실행부 457줄과 테스트·제작 도구는 이 집계에 포함하지 않는다. 공통 실행·전투·공간 검색·경로 탐색·파티클·ADV·Live2D 통합 등은 별도 구현·검증이 남아 있다. 줄 수는 현재 상태 참고치이며 완성도나 최종 코드량의 보장이 아니다.
- **AI 제안 2 (A2), 검증·옵션 해석:** 60FPS의 약 16.67ms와 165FPS의 약 6.06ms를 별도로 검증한다. 기준 내장 그래픽의 60FPS와 상위 성능·여유 장면의 165FPS를 구분하는 계획안을 둔다. 필터링은 초기에는 텍스처 확대·축소의 Nearest / Linear를 후보로 해석한다.
  - 이유·근거: 프레임률 범위 지정만으로 모든 기기·최대 부하의 165FPS를 보장할 수 없다. SDL2 공식 문서는 VSync 제어와 텍스처 확대·축소 모드를 제공하지만 실제 Pico2D의 SDL 버전·렌더러 지원은 확인해야 한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U1의 FPS·옵션은 사용자 직접 요구다. A1의 규모 평가, A2의 기기별 검증 계획과 필터 후보·기본값·실행 중 적용 방식은 사용자 확정 사항으로 기록하지 않는다.
- U2가 U1의 FPS 범위를 정정했으므로 A2의 165FPS 추가 검증 계획은 현재 목표에서 제외한다. Live2D의 24FPS는 사용자 요구이며 구체적인 갱신·렌더링 방식은 미정이다.

## 5. 반영 후 발견한 문제

- **발견한 문제 1 (I1), 문서 정합성:** 기존 문서에 목표 프레임률을 미정으로 둔 표현이 남아 있어 U1과 맞추어 갱신할 필요가 있었다.
- **발견한 문제 2 (I2), 목표와 검증 구분:** 목표 165FPS와 대상 기기의 실제 달성 성능은 별개이며, 표시 FPS 변화가 이동·판정·재생 시간의 변화로 이어지지 않도록 시간 처리를 설계해야 한다. 현재 실행 버그로 확인한 것은 아니다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1: 60~165FPS 목표와 수직동기화·필터링 변경 옵션을 직접 지정했다. 옵션 세부 UI와 대상 기기의 달성 성능은 추가 설명하지 않았다.
- I1/I2 ↔ U2: 후속 발언으로 게임 60FPS와 조건부 Live2D 24FPS를 지정했다. 수직동기화·필터링 요구는 유지한다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: PRE-PRD 5.2·7.4·7.6절의 프레임률 표현을 7.7절의 최신 요구와 연결한다.
- I2: FPS별 시간 예산, 시간 처리의 일관성, 동기화·제한 대기와 계산 비용의 구분을 기록한다. 고정 갱신 주기·보간·옵션 기본값·저장·적용 시점은 후속 설계로 남긴다.
- U2: PRE-PRD의 165FPS 목표를 제거하고 Live2D 표현 주기를 게임 주기와 구분한다. 실제 연동 가능성을 확인한 후 도입하며, 24FPS 제한의 적용 작업과 결과 재사용 방식은 미정으로 남긴다. U1과 A2는 변경 경위를 위한 당시 논의로 보존한다.
- 참고: [SDL2 VSync](https://wiki.libsdl.org/SDL2/SDL_RenderSetVSync), [SDL2 텍스처 확대·축소 모드](https://wiki.libsdl.org/SDL2/SDL_SetTextureScaleMode).
- 확인 범위: 현재 파일 규모 집계·문서 정합성·상대 링크·로그 형식·누락 인덱스·공백을 확인한다. 게임 실행·옵션 적용·165FPS·메모리 실측·시각 품질은 검증하지 않는다.
