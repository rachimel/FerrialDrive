# 검 이동·UI v2·보간·4타 연결과 마우스 기준 입력

- **상태:** 독립 이동 테스트에 UI v2·기체 보간·그림자 알파 보간·4타·부스트 캔슬·최신 속도·약한 블러를 연결했다. 마우스 기준 입력은 사용자 철회로 화면 기준 WASD로 복구했다. 실제 OpenGL 지정 입력 390프레임과 연속 이미지 195개를 출력하고 주요 전환 프레임을 검토했다. 일부 전환의 자세 튐은 남아 있으며 최신 입력 복구 후 실제 창 재조작은 미검증이다.

## 1. 사용자가 제안한 것

- **U1:** 검 이동 테스트에 프레임 보간과 UI v2를 넣으라고 요청했다. 출처는 현재 대화다.
- **U2:** 공격 모션을 추가하고 이동↔공격 전환의 자연스러움도 판단하라고 요청했다. 기능 연결 성공과 시각적 판단을 구분하는 요구다.
- **U3:** 기본 이동 25m/s·대시 50m/s·부스트 100m/s를 우선 시험하자고 제안했다.
- **U4:** U3을 기본 이동 50m/s·대시 100m/s·부스트 150m/s로 다시 지정했다. 최신 시험값이며 본편 전체 밸런스 확정으로 확대하지 않는다.
- **U5:** 멀미를 우려하며 모션 블러를 약하게 하라고 요청했다. 출처는 현재 대화다. 실제 멀미 감소를 검증했다는 뜻은 아니다.
- **U6:** 마우스 방향에서 W는 그대로, A/D는 수직 방향, S는 반대 방향을 바라보며 전진하는 이동안을 설명했다. AI는 마우스 기준 전후좌우로 해석해 입력을 연결했다. 기본 이동은 계산한 이동 방향을 바라보며 전진 모션을 사용한다.
- **U7:** U6의 조작감이 나쁘다며 해당 이동안을 철회했다. 출처는 현재 대화와 철회 대상으로 첨부한 이전 설명 이미지다.
- **U8:** 세로가 느려 보이는 원인 설명 후 현재 속도 유지를 선택했다. 방향별 실제 속도를 다르게 만드는 보정은 설정상 맞지 않는다고 지적했다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1~U2를 기존 재사용 모듈에 연결했다. 테스트 실행 파일이나 UI 테스트 실행부를 게임 모듈에서 import하지 않는다.
- U4를 최신 설정과 이동 기본값에 반영했다. 부스트의 기존 0.2초를 유지하므로 30m로 환산했다. 이 환산은 구현상 판단이다.
- U5에 따라 이동 테스트에서 카메라 블러 계수 0.15·최대 4px·9회 샘플, 기체 블러 강도 20%·기본 노출 8ms를 사용한다. 공통 UI v2 샘플 파일의 기존 값은 보존했다.
- U6을 W 전방·A 좌측 90도·D 우측 90도·S 반대 방향으로 구현했다. 대각선을 정규화하고 조준 벡터가 0이면 마지막 기체 방향을 사용한다. 대시·일반 부스트의 몸은 기존대로 조준 방향을 따르며 부스트 추진 방향은 시작 순간 고정한다.
- U7에 따라 U6 입력만 철회하고 화면 기준 WASD로 복구했다. U8에 따라 50/100/150m/s와 세로 투영 0.3209를 유지한다.

## 3. AI가 제안한 것

- **A1, 구현상 판단:** 기존 Unreal 모션 16개를 8방향에서 정/역방향 네이티브 벡터와 24fps 참조로 출력했다. 128개 클립을 같은 보간 규약으로 변환했다. 기체 형상·골격·애니메이션 키는 수정하지 않았다.
- **A2, 구현상 판단:** 공격 4개는 같은 AnimSequence의 기존 UI v2 보간 32클립을 재사용했다. 현재 훈련장과 같은 월드 원점 피봇으로 정렬하고, 공격의 새 전신/그림자 시트 32클립을 기존 패스로 출력했다. 팔을 내린 정면 어깨 128px 배율을 유지한다.
- **A3, 구현상 판단:** 달리기 위상은 선형으로 유지하고 공격은 기존 UI v2의 전체 구간 SmoothStep과 1.25배 재생을 사용한다. 그림자는 두 프레임 알파를 GPU에서 한 번 혼합한다. 기체 벡터를 그림자의 실제 모션 벡터로 간주하지 않는다.
- **A4, 구현상 판단:** 달리기 반복은 기준 12.22m/s에 비례해 현재 약 4.09배로 재생하고, 전환은 0.12초를 유지한다. 노출은 재생 배율에 맞춰 원본 시간으로 환산한다. 이 빠른 주기의 자연스러움은 속도 검증과 구분한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U1~U6은 사용자의 요청과 후속 조정이다. AI가 구현한 피봇 정렬·캐시·재생 배율·세부 블러 수치를 사용자 최종 품질 승인으로 승격하지 않는다.
- 이전에 제시된 다리 분리안은 여전히 조건부 검토 후보다. 이번 연결에서 상하체를 분리하지 않았다.

## 5. 반영 후 발견한 문제

- **I1:** 첫 GPU 캐시 8개 설정에서 모션 전환 시 텍스처 재준비로 CPU 그리기가 최대 약 350ms 멈췄다.
- **I2:** 클립 내부 보간만으로 모션 간 자세 차이는 없어지지 않았다. 달리기→1타의 팔/발 자세 변경, 역방향 공격의 전신 방향 급변, 공격→부스트의 준비 자세 복귀가 뚜렷하다.
- **I3:** 기존 카메라 블러는 계수 0.75·최대 24px·33회 샘플, 기체 잔상은 65%·16ms였다. 고속 이동에서 사용자가 U5로 약화를 요청했다.
- **I4:** 지정 입력의 마우스 위치가 실제 데스크톱 마우스 이벤트에 덮일 수 있었다. 재현 모드에서는 종료 키 외 실제 입력을 받지 않도록 분리했다.
- **I5:** 사용자가 마우스 상대 조작감과 세로 화면 속도 차이를 지적했다. 세로 투영 0.3209 때문에 동일한 월드 거리의 화면 변위가 세로에서 작다. 기본 50m/s는 가로 1280px/s, 세로 약 411px/s로 투영된다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U5로 I3의 블러 약화를 지시했고 이동 테스트 설정에서 반영했다.
- U6으로 마우스 기준 상대 이동을 제안했다. 입력은 반영했으며 S는 뒤돌아 전진한다. 이 변경을 I2의 모션 간 자세 연결 해결로 주장하지 않는다.
- 이후 U7로 상대 이동을 철회하여 고정 WASD로 복구했다. U8로 월드 속도는 유지하고 방향별 증폭은 적용하지 않았다. 기체가 이동 방향을 바라보는 기본 달리기는 유지한다.
- I2의 손 위치·공격 궤적을 바꾸는 추가 모션 제작이나 다리 분리에 대한 최종 결정은 받지 않았다.

## 7. AI 해결 제안과 실제 해결 과정

- I1은 이동 128개·공격 32개를 시작 시 GPU 캐시에 준비하도록 변경했다. 최종 실행에서도 캐시 수 128/32를 확인했다. 원본 시트 크기 합계 추정 약 1,341MiB, 보간 텍스처 약 1,498MiB이며 실제 VRAM 피크나 다중 기체 예산을 뜻하지 않는다.
- 재사용 연결은 `movement_combat.py`, `ui_v2/movement_hud.py`, `rendering/pico_shadow_blend.py`에 분리했다. HP/에너지는 훈련 표시이고 미니맵 위치·검 장착·부스트 준비 상태는 이동 상태에서 공급한다. 기존 메뉴·일시정지·스캔라인·무기 카드·월드 전용 카메라 필터를 사용한다.
- **시각 판단:** 같은 방향의 4타 종료→달리기 복귀는 기존 Idle 끝점과 이동 진입 모션 덕분에 비교적 잘 연결된다. 달리기→1타, 역방향 공격, 부스트 캔슬은 현재 자연스럽다고 판정하지 않는다. 일반 공격·부스트 반응을 늦추지 않으면서 표현상의 시작 자세를 연결하는 후속 검토가 필요하다.
- 검토는 전체 지정 입력을 렌더하고 34개 주요 프레임을 직접 확인하는 방식으로 진행했다. 연속 이미지 195개 출력과 전체 이미지 직접 검토는 구분한다. 초기 전환표는 `output/sword_movement_20261113/transition_review/contact_sheet.png`다. 철회 전 마우스 상대 이동·최신 속도·약한 블러의 기록은 `mouse_relative_review/report.json`, `frames/`, `movie/`, `mouse_relative_ui_v2.png`다. 과거 12.22/22.5/60m/s 결과 및 입력 복구 후 상태와 구분한다.
- 최신 실제 OpenGL 390프레임 실행에서 CPU 그리기 평균 약 11.29ms·최대 약 62.59ms, GPU 캐시 128/32를 확인했다. 이미지 기록 비용·초기 표시 비용·실제 GPU 시간을 구분한다. 시작 시 준비 비용이 있으며 이 수치로 60FPS 전체 보장을 주장하지 않는다.
- 자동 검사: 이동/공격/상대 입력 32개 통과, UI 회귀 188개 중 185개 통과·선택 조건 3개 생략, 보간 계약 16개 중 8개 통과·선택 조건 8개 생략이다. 실제 창의 전체 사용자 조작·전환 선호·멀미 여부는 사용자 확인 전이다.
- 입력 철회 후 이동·공격 자동 검사 32개를 다시 통과했다. 고정 WASD가 마우스 위치와 무관하며 가로·세로 월드 거리가 같은지 확인했다. 실행 중인 사용자 창에는 입력을 보내거나 재시작하지 않았다. 복구된 입력은 다음 실행부터 적용된다.
- 전용 부스트 공격·명중/피해 판정·본편 전투 연결·지형 IK는 이번 범위에 포함하지 않았다. 기존 관계없는 변경·미추적 공통 파일을 섞는 커밋과 AI 에셋 업로드는 수행하지 않았다.
