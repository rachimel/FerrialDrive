# 600기 공격 도형의 GL 상태 조회 단축

**기록 ID** `FDLOG-20261122-attack-gl-state`

2026-11-22 KST 작성. RTX 5070 Laptop GPU, FHD, 중간 PBR, 적 600기·간격 12m, 자동 SMG·무음. 앞선 그림자·본체 최적화가 적용된 `ef3b845`가 기준이다.

## 1. 사용자가 제안한 것

- **U1** 이전 600기 그리기의 `glGet*` 621회가 발생하는 경로를 다시 분해한다. 가림 순서를 유지하며 공격 이펙트의 상태 조회를 줄일 수 있으면 적용하고 픽셀·CPU·GPU를 대조한다. 요청의 정확한 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261122-attack-gl-state:U1]]이다. 검색 단서는 `남은 glGet 621회는 어디서 나오는지`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 본체 합성 중 공격 도형 호출을 별도 집계했다. 본체·공격의 호출 위치와 인스턴스 데이터를 유지하고 각 도형 패스의 상태 관리만 바꿨다.

## 3. AI가 제안한 것

- **A1** SDL/GL 제출 경계마다 호환 프로필 속성 스택으로 블렌드와 픽셀 업로드 상태를 보존한다. 이 도형 패스는 기존 가위 영역을 사용한다. 프로그램·뷰포트·활성 텍스처 유닛·유닛 0의 2D 바인딩은 직접 확인·복원한다. [OpenGL 4.6 호환 명세 21.6절·표 23.34](https://registry.khronos.org/OpenGL/specs/gl/glspec46.compatibility.pdf)
- **A2** 현재 경로의 호출 위치 집계와 같은 프레임의 전후 측정을 분리한다. CPU는 제출 경과를, GPU는 호출 구간 타임스탬프와 인스턴스 드로우의 타임스탬프를 따로 기록한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 가림 순서 유지, 조회 감소 시 적용, 600기 전후 대조는 사용자 요청이다. 속성 스택 사용과 측정 구간은 구현상 판단이다.

## 5. 반영 후 발견한 문제

- **I1** 첫 전체 화면 대조는 화면 지우기와 플레이어 방향 리소스 준비가 양쪽에서 동일하게 고정되지 않아 캡처 일부에 차이가 있었다.
- **I2** UHD 630 검토용 가드에서 추가한 GL 함수가 미등록으로 차단됐다. 실제 GPU 함수 등록과 검토 프로필의 목록은 별도로 관리한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 90프레임의 기준 재생에서 게임에 바인딩된 `glGet*` 평균 616.6회를 아래처럼 귀속했다. SDL 내부 호출은 이 집계 범위 밖이다.

| 호출 위치 | 평균 / 프레임 |
| --- | ---: |
| 본체 사이의 적 공격 도형 | 285.2 |
| 플레이어 파츠·그림자·업스케일·아틀라스 적재 | 130.5 |
| HUD | 60.0 |
| 적 본체 준비·그림자 | 49.5 |
| 그 외 월드 그리기 | 48.4 |
| 적의 기타 도형 | 32.0 |
| 그 외 | 11.0 |

공격 도형 285.2회는 공통 진입 상태 196.0회와 업로드 상태 89.1회다. 개별 제출의 16개 조회 중 12개를 줄였다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1** 재생 전 화면을 같은 색으로 지우고 월드·적 리소스의 준비 상태를 한 프레임에서 공유했다. 동일 경로끼리 12쌍을 대조해 조건을 확인한 뒤 전후 렌더 순서를 번갈아 실행했다. CPU·GPU는 120쌍씩, 호출 수는 90쌍을 따로 쟀다. 본체·공격·HUD가 포함된 FHD RGBA 12쌍에서 변경 픽셀은 0이었다. 해당 공격 도형 호출은 평균 17.8회로 동일했다.
- **I2** 명세의 호환 프로필 저장 그룹을 확인하고 프로젝트의 UHD 630 검토 목록에 네 함수를 등록했다. 실제 RTX에서 가드를 연 총기·충격파 테스트와 SDL 클립·스케일·렌더 타깃·업로드 예외 상태 복원 테스트가 통과했다. UHD 630 실기는 미측정이다. [Intel 호환 프로필 문서](https://www.intel.com/content/www/us/en/support/articles/000103355/graphics/processor-graphics.html)

| 측정 | 전 | 후 |
| --- | ---: | ---: |
| 공격 도형 `glGet*`, 평균/프레임 | 285.2 | 71.3 |
| 전체 `glGet*`, 준비 상태 고정 전후 대조 평균/프레임 | 593.8 | 355.9 |
| 공격 도형 CPU 평균 | 1.535ms | 1.218ms |
| 전체 그리기 CPU 평균 / P95 | 30.747 / 41.564ms | 30.548 / 42.957ms |
| 공격 도형 인스턴스 드로우 GPU 타임스탬프 중앙값 | 0.026ms | 0.025ms |
| 전체 그리기 GPU 타임스탬프 평균 | 19.037ms | 19.264ms |

GPU 타임스탬프에는 드라이버 제출 사이의 유휴 시간이 포함된다. 공격 패스 전체 GPU 타임스탬프 중앙값은 0.104 → 0.122ms, 평균은 3.964 → 3.588ms로 변동폭이 컸다. 직접 확인한 이득은 공격 도형의 상태 조회와 CPU 제출 구간이다. 전체 CPU·GPU 개선은 일관되게 확인되지 않았다.

전후 대조의 변경 경로는 플레이어(파츠·그림자·업스케일 합계 약 120회), 공격 도형(71.3회), HUD(60회) 순이었다. 기본 자동 검사 1,089개가 통과했고 선택 실행 88개는 기본 실행에서 제외됐다. 별도로 도형 11개·적 가림과 공격 2개·총기 2개·충격파 7개가 통과했다.
