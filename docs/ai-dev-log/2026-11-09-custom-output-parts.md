## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 출력 단위를 추상화해 NPC마다 다른 장식도 담는 기능을 제안했다. 이유·근거는 NPC별 장식의 차이를 직접 언급한 요청이다.
- **사용자 제안 2 (U2):** 출력 파츠의 ID·이름·부착점·시트/마스크·상태·순서, 메카 기본 프리셋과 목록/선택 파츠 편집 구조 설명 후 “네 그러면 그렇게 진행해주세요”라고 진행을 승인했다. 이후 “다시 resume 해줘”로 작업 재개를 요청했다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1/U2를 반영해 고정 출력 목록을 v2 동적 파츠로 바꾸고 추가·복제·삭제·이름 편집·표시 여부·상태 편집을 연결했다. 기존 메카 구성은 기본 프리셋으로 제공하며 NPC 기본 구성은 본체만 둔다.
- 등 스러스터는 전용 고정 출력 항목을 늘리는 대신 수직·수평·양방향 전환 상태를 가진 파츠 템플릿으로 제공한다. 다리 스러스터는 분리 대상에 추가하지 않는다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1), 설명 후 사용자 진행 승인:** 출력 파츠는 그리기 단위로 관리하고 게임 장비·부위 판정은 별도 ID 참조로 연결한다. 파츠 이름 변경이 순서·상태 연결을 끊지 않게 한다.
- **AI 제안 2 (A2), 구현 판단:** `body`를 프레임 기준 파츠로 유지하고 삭제를 막는다. 상태는 동작과 별도로 정의하되 선택한 상태의 FPS·프레임 수·크기·기준점을 본체와 비교한다. 부착 위치는 같은 장면에서 출력한 좌표를 사용한다.
- **AI 제안 3 (A3), 구현 판단:** v1 작업본은 읽을 때만 보완하고 저장 시 v2로 기록한다. 사용자 파츠와 상태의 ID는 파일 경로에 안전한 영문/숫자/밑줄로 제한하며 대소문자만 다른 중복을 거절한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U2가 A1을 포함한 출력 파츠 구조 설명 뒤 진행을 명시 승인했다. A2/A3의 구체 UI 배치·버전 번호·ID 제약과 실제 조작감은 구현 판단이며 별도 최종 사용성 승인을 받은 것으로 간주하지 않는다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1), 자동 검사:** 복제 파츠의 동작 상태는 복사됐지만 편집기는 파츠 기본 상태를 선택해 표시했다. 선택 상태와 편집 대상이 달라질 수 있었다.
- 상태별 색상 시트를 바꾸면서 기존 마스크를 무조건 상속하면 다른 자세의 마스크가 섞일 수 있어 상속 조건을 명확히 했다. 이는 구현 위험에 대한 AI 판단이다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1이 스러스터 전용 확장에서 NPC 장식까지 다루는 출력 파츠 구조로 범위를 정리했다. U2의 재개 요청에 따라 검사를 이어갔다. 파츠 ID·상태·시트의 실제 이름과 모델 형상은 사용자 모델에 임의 적용하지 않았다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 복제 후 현재 동작에서 선택한 상태로 편집기를 맞추고 상태 삭제/파츠 삭제 시 참조를 정리한다. 원본 파츠와 복제 파츠의 상태 사전은 독립 복사한다.
- 기본 시트를 상속하는 상태는 기본 마스크도 상속한다. 새 색상 시트를 지정하면 마스크는 별도로 지정한다. 상태 클립 접두사와 동작별 선택을 메타데이터로 전달한다.
- 파츠 목록과 순서 목록을 스크롤하고 선택 파츠의 공통 설정을 오른쪽에 배치했다. 별도 파츠/상태 이미지도 합치지 않고 내보내며 같은 게임 공통 표시기가 선택한 상태를 재생한다.
- 기존 시트 참조·동작·전환 이벤트를 보존하는 프리셋 적용과 v1→v2 보완을 확인했다. v2에서 삭제한 메카 기본 파츠는 재삽입하지 않는다.
