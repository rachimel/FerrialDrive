# 자동화 분리·새 Unreal 리그 후보·프리렌더 재검토

- **기록 ID:** FDLOG-20261110-automate-fresh-rig
- 상태 기준: **2026-11-10 22:56 KST**. 현재 세션에서 실제 확인한 내용과 후속 응답을 정리한다.
- 개별 원문 시각은 미확인 — [[FDLOG_MISSING_TIME:FDLOG-20261110-automate-fresh-rig:scope]] 현재 대화의 `automate 폴더에 따로 분리`, `하체도 조준 방향`, `프리렌더 경로를 Unreal로` 발언에서 보완한다.

## 1. 사용자가 제안한 것

- **U1:** 불필요한 output 정리, 기존 요구에 맞춘 새 KeyPose, Unreal 제어점과 사용법, 기존 Blender 리그 폐기·Unreal 새 리깅을 요청했다. 이유: 이전 검수가 좁은 V자 팔 접힘까지 정상으로 판정했고 복잡도를 늘렸다고 지적했다. 출처: 현재 대화의 선행 요청.
- **U2:** 행동 전 짧은 보고와 AGENTS 반영을 요청했다. 이유: 권한 확인이 생략돼도 작업 상황을 알 수 있어야 한다. 출처: `뭐 동작 할 때, 짧게라도 보고해`.
- **U3:** output에 의존하는 자동화 경로와 필수 파일을 루트 `automate/`로 분리하라고 요청했다. 출처: `그런 자동화 경로랑 ... 필수 파일들은 automate 폴더에 따로 분리`.
- **U4:** 질문 응답에서 **보행 하체도 조준 방향 유지**를 확정했다. 하체를 WASD 방향으로 따로 돌리지 않는다.
- **U5:** 출력 질문에서 FBX→별도 `.blend`→기존 렌더를 선택한 뒤, 후속으로 **Unreal 프리렌더 + 툴의 파츠 조립 분리**가 어떨지 의견을 요청했다. 최신 발언은 재검토 제안이며 최종 채택으로 취급하지 않는다.

## 2. 사용자 제안 중 AI가 수용한 것

- U2/U3을 AGENTS에 반영했다. 실행 파일·패키지·필수 입력·호스트 런타임을 분리하고 이전 요청의 참조를 수정했다.
- U1에 따라 모델 원본을 보존하고 형상만 인계한 뒤 Unreal에서 새 본·웨이트·FK 제어점을 작성했다. 기존 Blender 본·웨이트·Constraint·수치 포즈를 복제하지 않았다. 실제 메카의 새 KeyPose 제작은 아직 미완료다.
- U4를 PRE-PRD·기본 무기 사양·애니메이션 흐름에 반영했다. U5의 최종 프리렌더 경로는 후속 논의 중이다.

## 3. AI가 제안한 것

- **구현상 판단 A1:** `automate/run.py`에서 기존 Asset Tool·모델 모듈을 재사용한다. 모델은 Blender 호스트에서, MCP 클라이언트는 별도 런타임의 공식 SDK로 실행한다. CLI는 예약 업데이트 실패 이력이 있어 자동 호출하지 않았다.
- **구현상 판단 A2:** 최소 상자 3개로 새 골격·웨이트·FK 키를 먼저 확인했다. 실제 메카는 형상 기준 후보 본 59개와 강체 부품 연결 417개로 작성했다. 이를 승인된 완성 리그로 간주하지 않는다.
- **AI 의견 A3:** Unreal에서 리깅·애니메이션·프리렌더, 툴에서 출력된 2D 파츠·레이어·패킹을 담당하는 안을 권고한다. 3D 부착·파지·가림과 파츠 식별은 Unreal에서 보존한다. 한 동작·한 방향을 본체/손·무기/그림자로 출력·재합성해 먼저 검증할 것을 제안한다. 근거: 왕복 변환 비용, 기존 툴의 조립 책임, Epic Movie Render Pipeline/Graph의 출력·레이어 지원. 파츠 분리·재합성 전체 경로는 미검증이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1-A3의 별도 명시 승인은 아직 없다. U1/U3은 사용자가 먼저 요청한 작업이며 AI 구현을 AI 제안 수용으로 바꾸지 않는다.
- 새 리그의 외관·가동·모션 품질은 사용자 승인 전이다. Unreal 프리렌더도 의견 교환 단계다.

## 5. 반영 후 발견한 문제

- **I1:** output의 CLI·패키지와 과거 요청이 읽는 `.blend` 5개가 필수 입력이었다.
- **I2:** 대형 output 폴더 7개 통삭제는 자동 승인 검토에서 거절됐다. 혼합된 스크립트·검사 근거·포즈의 복구/재생성 근거가 부족한 광범위 비가역 삭제라는 이유였다. 같은 삭제를 우회하지 않았다.
- **I3:** 기본 FBX 가져오기는 Static Mesh를 만들었고 Interchange의 FBX 기능 플래그가 꺼져 있었다. Skeleton 속성의 Python 직접 대입도 불가능했다.
- **I4:** 모델 공통 모듈은 Blender 안에서 인자를 읽으므로 일반 Python 직접 호출로는 인자가 전달되지 않았다.
- **I5:** 첫 6면 캡처는 같은 시점이 반복돼 무효였다. 재시도 중 `Level Editor Subsystem Realtime Override` ensure와 MCP 시간 초과가 발생했다. 6면 검토와 최종 표시 설정 복구는 미완료다. 에디터는 당시 프로세스가 살아 있었고 강제 종료하지 않았다.
- **I6:** 유연한 벨로즈·피스톤 추종, 발목/가슴 피벗, 손 목표 IK·자동 관절 제한·파지/수납 전환과 큰 자세 간섭은 미검증/미구현이다. 교환 재질도 최종 검증 전이다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **I1/U3:** 필수 파일 7개를 `automate/bin`, `packages`, `workspace/retained_inputs`로 이동했다. Unreal 런타임 441개도 `automate/runtime/unreal/python`로 이동했다. 요청 5개를 갱신하고 수정 전 요청과 이동 전후 SHA-256을 보존했다.
- **U1:** 원본 `base_pose.blend` 해시를 유지했다. 본·정점 그룹·Constraint가 없는 417개 형상만 FBX로 인계했다. 이 중간 FBX 생성을 최종 출력 형식 채택으로 취급하지 않았다.
- **U4:** 전진·후진·측면 이동 모두 전신 조준 방향을 유지하도록 현행 요구를 갱신했다.

## 7. AI 해결 제안과 실제 해결 과정

- **I2:** 재생성 가능한 이미지 6,978개, 937,658,919바이트로 삭제 범위를 줄였다. 계획한 이미지의 잔존은 0개였다. `.blend`·스크립트·JSON은 이미지 정리에서 삭제하지 않았다. 필수 `.blend` 5개는 별도 해시 확인 이동으로 보존했다. 폴더 전체 삭제는 미수행이다.
- **I3:** 변환 중에만 FBX 기능 플래그를 켜고 복구했다. Unreal에서 만든 Root seed에 새 관절을 추가하고 최종 Skeleton 사본·웨이트 메시를 만들었다. 상자 샘플의 회전 키·메시 변화와 제어점/채널 표시를 에디터 캡처에서 확인했다.
- **실제 메카:** 417 Static Mesh·37 Material을 가져왔다. 원본 실제 정점 경계와 가져온 부품 중심의 최대 차이는 약 0.000033cm였다. 본 59개·연결 417개·편집 맵·12fps Sequence를 만들고 `arm_lower_l_CONTROL` API 선택과 화면 채널 표시를 확인했다. 실제 메카의 새 동작 키는 아직 작성하지 않았다.
- **I4:** 모델 경로가 Blender 백그라운드 호스트를 실행하도록 수정했다. Asset Tool 조회, 모델/MCP 도움말, 분리 후 로컬 MCP 실제 호출이 성공했다. 이후 I5로 현재 연결은 복구 확인이 필요하다.
- **I5:** 무효 캡처를 검토에서 제외하고 실시간 표시 API 호출을 제거했다. 표시/연결 복구와 유효한 다각도 렌더는 남았다. 새 bootstrap의 경로·문법은 확인했으나 에디터 재시작에 의한 자동 시작은 미검증이다.
- **무결성/공개:** `verify_dependencies.py`의 파일 7개·런타임 441개·요청 5개 실패는 0개였다. 실행 파일·런타임·패키지·작업본·개인 설정의 Git 제외를 확인했다. DCC 스킬 검사는 오류·경고 없이 통과했다. 커밋·업로드는 수행하지 않았다.
