# HUD 스캔라인 호출 귀속과 GL 상태 조회 단축

**기록 ID** `FDLOG-20261122-hud-gl-state`

2026-11-22 KST 작성. RTX 5070 Laptop GPU·FHD·중간 PBR·SMAA·적 600기·12m 간격·자동 SMG·무음 조건이다. 플레이어 파츠·업스케일 최적화까지 적용한 `98cd8eb`가 기준이다.

## 1. 사용자가 제안한 것

- **U1** HUD의 `glGet*` 약 60회를 호출 주체별로 분해하고 스캔라인의 횟수를 확인한다. 중복 조회를 줄일 수 있으면 적용하고 600기 픽셀과 CPU·GPU 시간을 대조한다. 요청의 정확한 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261122-hud-gl-state:U1]]이다. 검색 단서는 `HUD에서 나오는 glGet 60회도 쪼개봐`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 스캔라인 함수, SDL 조회, 텍스처를 기준으로 분류한 실제 SDL 도형 제출, HUD의 OpenGL 호출을 각각 계측했다. SDL 내부의 GL 호출은 집계 범위 밖이다.

## 3. AI가 제안한 것

- **A1** 방향성 블러는 파츠·SMAA에서 쓰는 블렌드·클립 속성 스택을 공유한다. SDL 타깃 전환과 화면 합성 순서는 유지한다.
- **A2** Compute 흡수 파티클은 블렌드를 속성 스택에 맡긴다. 픽셀 언팩 상태는 텍스처 업로드가 있는 파티클 아틀라스 생성에서만 저장·복원한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 호출 위치 분해와 변경 전후 검증이 사용자 요청이다. 블러의 상태 그룹과 파티클 아틀라스 업로드 범위는 구현상 판단이다.

## 5. 반영 후 발견한 문제

- **I1** 스캔라인 호출 중 발생한 도형 제출을 그 함수의 것으로 집계하면, 이미 대기 중인 다른 텍스처의 제출까지 포함되고 나중에 제출된 스캔라인도 놓칠 수 있다.
- **I2** 파티클 CPU 비용은 줄었으나 HUD 전체 평균은 늘었다. GPU 타임스탬프 구간은 명령 사이의 유휴 시간을 포함해 평균과 짝별 차이 중앙값이 달랐다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 90쌍의 호출 계측에서 HUD를 아래와 같이 분해했다. 다른 HUD 기능에는 게임 코드에서 바인딩한 `glGet*`이 잡히지 않았다.

| 위치 | 변경 전/후 평균 `glGet*`/프레임 |
| --- | ---: |
| 스캔라인 | 0 → 0 |
| 자원 패널 피격 블러 | 11 → 4 |
| 히트 카운터 블러 | 11 → 4 |
| 누적 피해 카운터 블러 | 11 → 4 |
| Compute 흡수 파티클 | 27 → 15 |
| **HUD 전체** | **60 → 27** |
| 전체 그리기 | 311.8 → 271.8 |

파티클의 기존 27회는 공통 패스 11회와 버퍼·언팩 16회였다. 공통 래스터 조회 7회와 현재 경로에서 사용하지 않는 언팩 조회 5회를 없앴다. 전체 그리기에서는 공유 방향성 블러를 사용하는 월드 합성도 7회 줄었다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1** 제출 당시 SDL 텍스처가 스캔라인 캐시에 있는지 확인해 귀속했다. 스캔라인 프레임당 평균 21.93번의 레이어 호출, 11번의 SDL 도형 제출, SDL 스케일·뷰포트·출력 크기 getter 합계 65.8회를 확인했다. 스캔라인 코드는 변경하지 않았다.
- **I2** CPU·GPU는 실행마다 별도의 120쌍으로 쟀다. 프레임의 준비된 리소스를 공유하고 순서를 교대했다. 두 실행에서 전체 화면 RGBA 캡처 각각 12쌍이 픽셀 단위로 일치했다. CPU는 마지막 강제 완료 대기를 제외한 제출 경과이며, GPU 구간은 CPU가 다음 명령을 보낼 때까지의 유휴 시간도 포함한다.

| 측정 | 첫 실행 전 → 후 | 반복 실행 전 → 후 |
| --- | ---: | ---: |
| 흡수 파티클 CPU 평균 | 0.137 → 0.104ms | 0.152 → 0.129ms |
| HUD 블러 합성 CPU 평균 | 개별 미계측 | 0.312 → 0.283ms |
| HUD 전체 CPU 평균 | 6.258 → 6.499ms | 7.346 → 7.612ms |
| HUD GPU 타임스탬프 평균 | 1.368 → 1.754ms | 1.634 → 1.895ms |
| 전체 그리기 CPU 평균 | 19.113 → 19.350ms | 22.514 → 22.653ms |
| 전체 GPU 타임스탬프 평균 | 14.138 → 13.925ms | 15.556 → 15.710ms |

두 실행에서 같은 프레임끼리 뺀 HUD CPU 시간의 중앙값은 각각 −0.019ms와 −0.068ms이고 GPU는 절대값 0.001ms 이하다. 별도의 동일 경로 대조에서도 HUD 평균에 약 0.37ms 차이가 생겼다. 순서를 바꾸면 큰 지연이 먼저 그리는 쪽으로 이동했고, 동일 경로의 지연 프레임을 세분화하니 무기 카드의 네온 마스크 생성이 먼저 재생한 쪽에 잡혔다. 지속적으로 확인된 효과는 조회 감소와 블러·파티클 제출의 국소 CPU 감소다.

기본 자동 검사 1,090개가 통과했고 선택 검사 89개가 기본 실행에서 제외됐다. 별도로 실제 OpenGL 렌더링 검사 31개와 HUD 배치 검사 19개가 통과했다. UHD 630 실기 계측은 하지 않았다.
