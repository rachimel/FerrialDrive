## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 검 Trail을 만들고 에너지 레벨에 따라 범위를 키운다. 확인 질문에 시각 효과와 실제 공격 판정 모두 확대하도록 선택했다. 의도: 에너지 증가가 실제 공격 범위에도 반영된다.
- **사용자 제안 2 (U2):** 높은 에너지에서 휘두를 때 잔상이 남도록 한다. 확인 질문에 검뿐 아니라 기체 전체 잔상도 포함하도록 선택했다.
- **사용자 제안 3 (U3):** 초기 시안보다 Trail을 크게 하고 레벨별 차이를 뚜렷하게 벌린다. 대시 공격은 더 큰 Trail을 사용한다.
- **사용자 제안 4 (U4):** Y축 판정 보정 후 `판정 더 유하게`라고 방향을 구체화했다. 찌르기는 `>` 같은 모양을 요청했다.
- **사용자 제안 5 (U5):** V를 더 선명하게 표시하고 1레벨의 가로 폭을 조정한다. 확인 질문에서 `칼날 길이를 기준으로 V 전체 가로 폭이 25%`를 선택했다. 양쪽 각각 25%라는 해석과 구분한다. 정확한 발언 시각은 위 TIME(scope)의 보완 대상이다.

## 2. AI가 제안한 것

- **AI 제안 1 (A1):** 현재 Unreal 120Hz 검날 좌표를 사용해 Trail과 실제 판정의 기본 면을 함께 만들고 기본 도형 표적으로 확인한다. 이유: 모션과 어긋나는 임의의 원호를 새로 만들지 않고 실제 궤적을 재사용할 수 있다. 출처: 현재 대화의 구조 설명.
- 초기 시험 제시값은 범위 1/1.15/1.3배·잔상 0/2/4개였다. U3 이후 확대된 시험값으로 교체했다. 초기 값·최종 값의 사용자 외관 승인은 받지 않았다.
- 구현상 판단: 최종 시험 길이는 레벨별 1.3/1.8/2.4배, 대시는 추가 1.35배다. 수명 0.10/0.18/0.26초, 잔상 상한 0/3/6개와 레벨별 밝기/색을 분리했다.
- 구현상 판단: Y 판정에 월드 ±1.5m의 여유를 적용하고, 현재 평면 투영 배율로 환산한다. 3타 찌르기는 기존 동작 분류에 따라 `>`를 사용한다. 구체적인 크기·타격 구간은 시험 설정이다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U4를 훈련장에 반영했다. 범위 배율과 대시 배율은 실제 검날 끝점 연장과 판정에 함께 사용한다. 추가 Y 여유는 판정에만 적용하여 그림을 세로로 늘리지 않는다.
- U5: 1레벨 일반 공격의 원래 칼날 표시 길이를 기준으로 V 양쪽 날개 끝 사이를 25%로 설정했다. 상위 레벨/대시는 기존 상대 배율로 확대한다. 표시와 명중 면에 같은 날개 좌표를 사용한다.
- 검날 기록은 `basic_combo_follow_20261112/blade_trajectory.json`의 실제 cutting edge를 사용한다. 파란 칼등 좌표와 구분한다. 기존 모델·파지·공격 모션·원본 에셋은 수정하지 않았다.
- 레벨은 애플리케이션이 소유하고 HUD·검 효과에 함께 공급한다. 훈련장 1/2/3 키와 사전 입력으로 바꾸며, 자원 회복/소모·승강 요구량은 구현하지 않았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 실제 판정 확대와 전신 잔상은 질문 응답으로 명시 선택했다. U3/U4의 후속 조정 지시는 반영했다.
- V 전체 폭 25%는 U5의 질문 응답으로 확정했다. 흰 중심부 굵기·외곽 두께·알파의 구체적인 수치는 구현상 판단이며 최종 외관 승인은 받지 않았다.
- AI가 선택한 배율·시간·색·Y 허용량과 최종 캡처의 사용자 승인은 미확인이다. 침묵이나 자동 검사 통과를 수용으로 취급하지 않는다.

## 5. 반영 후 발견한 문제

- **I1 — 부분 캡처:** 첫 영역 캡처가 투명하게 저장됐으나 전체 화면 캡처는 정상임을 확인했다. 정확한 원인은 확정하지 않았다 — [[FDLOG_MISSING_CAUSE:FDLOG-20261114-sword-energy-trail-hit-afterimage:I1]]. 검색 단서: `output/sword_energy_trail/diagnose_capture.py`의 동일 프레임 전체/영역 비교와 초기/최종 PNG.
- **I2 — 사전 입력 순서:** 같은 프레임에서 Shift를 지정한 뒤 reset을 처리하여 대시 입력이 지워졌다. 대시 비교가 일반 공격으로 실행된 보고를 발견했다. 실제 키보드 문제가 아니라 검증 입력 처리 순서 문제다.
- 초기 베기 면의 겹치는 폭 때문에 방사형 경계가 드러났다. 렌더 면을 이어진 삼각형/정점 알파로 그리도록 바꾸고 판정의 얇은 외곽 여유는 별도로 유지했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U3에 따라 일반/대시 길이와 레벨별 밝기·수명·잔상 차이를 확대했다. 에너지 레벨 3의 대시도 별도 비교했다.
- U4에 따라 Y축에 추가 허용 범위를 적용했다. 찌르기는 진행축을 따르는 `>`의 두 날개를 표시하고 양쪽 날개를 판정 면에도 포함했다.
- U5에 따라 고정 픽셀 폭을 칼날 길이 비율로 교체했다. 희미하던 V의 꼬리 알파를 높이고 두 선 전체에 별도 흰 중심부를 추가했다.

## 7. AI 해결 제안과 실제 해결 과정

- `MovementCombat`이 실제 갱신 구간별 타격 ID·클립·원본 시간·실제 시간·월드 위치·Shift 상태를 제공한다. `SwordEffects`가 같은 가속 위상으로 최대 1/240초 간격의 면·명중·잔상 상태를 계산한다. 프레임 안의 연계 전환도 나눠 처리한다.
- 준비/복귀/연결 대기에는 새 판정을 만들지 않는다. 같은 타격의 같은 표적은 한 번만 명중한다. 사라지는 시각 Trail과 전신 잔상에는 잔류 판정을 주지 않는다. 원본 기록의 `combat_hit_windows_approved=false`는 그대로 두고, 설정의 활성 구간을 시험값으로 기록했다.
- 전신 잔상은 과거 기체 자세·방향·월드 위치를 저장하고 공유 아틀라스의 독립 알파로 합성한다. 본체의 다음 그리기는 알파 1로 복구한다. 새 이미지·모델·추가 색상 아틀라스를 제작하지 않았다.
- I1: 렌더 명령을 Flush하고 전체 화면을 읽은 뒤 행 단위로 필요한 영역을 저장한다. 실제 GPU에서 픽셀 동일성을 검사하고 최종 실제 PNG를 열어 확인했다. I2: reset을 같은 프레임의 다른 입력보다 먼저 처리하고 회귀 검사를 추가했다.
- 자동 검사: 검 효과/이동/콤보 68개와 실제 GPU 잔상 알파/다음 본체 복구·캡처 2개, 총 70개 통과. 텍스처 비교 검사는 별도로 9개 통과·선택 GPU 3개 미실행이었다. 후속 변경 뒤 재실행하지 않은 검사를 최신 결과로 합산하지 않는다.
- 실제 실행: 실제 에셋 OpenGL 400프레임과 기본 도형 `--demo` 400프레임 실행. `output/sword_energy_trail/forgiving/`에서 레벨 1/2/3·대시·찌르기·표적 반응 캡처를 직접 확인했다. 첫 타격 같은 시점에서 레벨 1/2는 A/B, 레벨 3은 A/B/C까지 명중했다. 대시에서는 위치 이동도 빠르므로 표적 명중 수만으로 범위 차이를 비교하지 않는다.
- 공개 시연 입력은 `samples/sword_movement/trail_sample.json`의 직접 작성한 수치와 생성기다. 실제 모델 없이도 Trail·판정·레벨 시연을 실행한다. 실제 기체 전신 잔상은 게임 에셋 경로에서 검증했다.
