## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1)** 중복 그리기 호출을 합치고 텍스처 전환을 어떻게 줄일지 검토한다. 목표는 현재 카메라와 근거리 품질을 유지한 1,000기 교전이다.
- **사용자 질문 2 (U2)** 적 이동을 Compute와 Numba 중 어디에 두는 게 맞는지 물었다. 개별 발언 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261121-enemy-draw-runs:U1-U2]]이다. 같은 대화의 `drawcall 중복되는 거`와 `적 이동은 Compute`에서 확인할 수 있다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 기존 근거리 파츠 합성과 원거리 공유 포즈의 최종 제출을 각각 검증했다. **U2** 현재 적 이동과 공격의 서브스텝 의존성을 확인했다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1)** 근거리 시트는 기종·모션·방향·표본 번호·보간율이 모두 같을 때 합성 결과를 재사용한다. 기체별 화면 위치와 표시 순서는 따로 유지한다.
- **AI 제안 2 (A2)** 원거리는 실제로 그릴 정수 픽셀의 가로 구간으로 가림을 검사한다. 같은 캐시 텍스처의 제출을 최대 16개 묶음 안에서 앞으로 당긴다. 중간에 다른 본체와 가로 구간이 겹치거나 개별 적·공격 효과가 있으면 기존 순서를 따른다. 새 포즈는 원래 자리에 먼저 그려 캐시를 채운다.
- **AI 제안 3 (A3)** 적 이동의 다음 후보는 CPU Numba다. 최대 1/120초 간격으로 앞 기체의 밀림과 격자 변경을 다음 기체가 바로 읽는다. 위치·반경·속도를 연속 배열에서 묶음 처리하고 기존 순차 충돌 결과와 대조해야 한다. 겹치는 서로 다른 원거리 포즈의 전환이 계속 크면 여러 포즈를 한 장에 넣고 UV를 선택하는 아틀라스를 검토한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 중복 제출 병합은 사용자 요청이다. 보간율을 정확히 일치시키는 조건과 16개 탐색 폭은 AI의 구현 결정이다. 이동 백엔드와 추가 아틀라스는 검토 단계다.

## 5. 반영 후 발견한 문제

## 6. 사용자 해결 제안과 실제 해결 과정

## 7. AI 해결 제안과 실제 해결 과정

- **A1·A2 ↔ I1** FHD·중간 PBR, 적 1,000기·12m 간격, 자동 SMG, 사운드 끔으로 같은 프로세스에서 변경 전·후·후·전 순서로 측정했다. 조건당 준비 30프레임 후 90프레임을 기록했다. 마지막 화면의 표시 후보 306기, 파츠 본체 285기와 원거리 공유 본체 227기는 네 실행에서 같았다.
- 근거리 본체 3,291개에 사용한 합성 칸은 3,291→2,877개였다. 이 수치는 합성한 인스턴스 수다. 적 본체를 그리는 동안 텍스처를 지정한 SDL 복사·geometry 호출은 14,753→10,873회, 그 호출 사이에서 텍스처가 바뀐 횟수는 10,408→6,867회였다. 횟수는 교차 측정 두 번 모두 같았다. 드라이버 내부 GL 호출은 따로 측정하지 않았다.
- 호출 계측을 끈 교차 측정에서 기준은 16.93·19.70 FPS(p95 106.02·85.75ms), 변경은 14.18·20.40 FPS(p95 120.17·90.60ms)였다. 60 FPS에는 미달했고 전체 프레임 시간의 일관된 개선은 확인되지 않았다.
- 33개 GPU·교전 검사가 통과했다. 겹치는 포즈끼리는 순서를 유지하면서 가로로 떨어진 두 텍스처의 10기 배치를 3묶음으로 줄였고 기존 개별 제출과 픽셀이 일치했다. 근거리에서는 같은 보간율과 다른 보간율, 한 제출의 64기 경계도 검사했다.
- 커밋 기준 전체 무음 자동 검사 1,123개 중 67개 생략, 실패 0개였다. Numba를 끈 경로에서 별도로 실행한 두 가지 가림·텍스처 검사도 통과했다. 직접 조작감과 이동 백엔드 간 속도는 이번 측정에 포함하지 않았다.
