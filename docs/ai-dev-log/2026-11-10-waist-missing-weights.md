# 허리·스커트 누락 가중치 수정 후보

- **기록 ID:** `waist-missing-weights`
- 기록 시각: 2026-11-10 01:07:19 KST. 실제 발언별 시각과 구분한다.
- 출처: 현재 대화의 어깨 제어점 질문·허리 회전 화면과 “허리 회전에 스커트가 딸려오는것까진 ok인데 일부 정점이 안따라옴” 정정.
- 개별 발언 시각은 미확인이다. [[FDLOG_MISSING_TIME:waist-missing-weights:scope]] 현재 대화의 위 인용과 수정 보고 시각을 확인한다.
- **상태:** 사용자의 “네 적용 ㄱ” 확인 후 기본 제작 모델 `base_pose.blend`에 적용했다. 기존 포즈 작업본은 미변경이다.

## 1. 사용자가 제안한 것

**U1:** 어깨 IK처럼 보이는 제어점이 하부에 있는 이유를 묻고 허리 회전 시 스커트 문제를 수정하도록 요청했다. 뒤이어 스커트의 허리 추종 자체는 허용하며 일부 정점만 따라오지 않는 문제라고 한정했다. 작업 중 포즈는 버렸다고 알렸다. 이유는 사용자 첨부 화면의 실제 변형 이상이다. 시각은 scope 누락을 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

U1에 따라 기본 `base_pose.blend`를 검사했다. 스커트를 골반에 분리하는 최초 해석을 철회했다. 허리 추종·본 계층·어깨 매핑을 유지하고 누락 가중치만 보완하는 범위로 좁혔다.

## 3. AI가 제안한 것

**A1:** 기존 정상 가중치는 보존하고, 누락 정점만 기존 기준 메시의 가까운 유효 정점에서 복사하는 후보를 만든다. 스커트는 기존 연결 스커트, 허리 외장은 Waist 가중치의 내부 코어를 기준으로 사용한다. 근거는 두 가시 메시의 누락 정점과 회전 시 고정되는 정점의 일치다.

**A2:** 어깨 원은 손 목표 IK가 아닌 `ShoulderWingLower.L/R`에 매핑된 몸체 제어점임을 설명한다. 현재 하부 배치는 설정대로이며 이번 수정에서는 변경하지 않는다. 상부 어깨 제어 확대는 별도 기능이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

허리 추종 유지와 누락 정점 수정은 U1의 명시 요구다. 사용자가 전후 비교를 본 뒤 “네 적용 ㄱ”으로 A1의 후보와 기본 모델 적용을 수용했다. 어깨 배치 변경을 요청하거나 승인한 것으로 취급하지 않는다.

## 5. 반영 후 발견한 문제

**I1:** 원본 `Skirt_Segmented_Shell_v076`의 493정점 중 125개, `Waist_Sculpted_Three_Tier_v047`의 265정점 중 93개에 가중치가 없었다. 새 포즈에서 생긴 결함이 아니라 기본 모델의 기존 결함이다. 앞 스커트 덧장 두 개는 Surface Deform을 사용하므로 가중치가 없다는 이유만으로 수정하지 않았다.

**I2:** 기존 가중치 보완 함수는 무가중치 정점을 기준 후보에 포함할 수 있어 실제 복사가 없는 상태도 처리 수로 셀 수 있었다. 유효 가중치 정점만 기준으로 사용하도록 공통 경로를 정리했다. 원본의 가중치 누락 발생 원인을 확정한 것은 아니다.

## 6. 사용자 해결 제안과 실제 해결 과정

U1의 후속 정정으로 회전 관계 변경 대신 누락 가중치 수정으로 범위를 확정했다. 사용자 포즈는 이미 버린 상태라 복구·덮어쓰기를 수행하지 않았다. 사용자에게 가중치나 본 수정을 직접 요구하지 않았다.

## 7. AI 해결 제안과 실제 해결 과정

`model_weights.py`에 기존 보완 기능을 분리하고 `motion_blocking.py`와 공통 연산 `repair_unweighted`가 재사용하게 했다. 명시적인 enabled=true에서만 실행하며 기존 가중치를 보존한다. 검토 렌더가 Pose Mode 파일에서도 실행되도록 촬영 전 Object Mode로 전환한다.

기본 도형 회귀 검사 20개를 통과했다. 누락 기준 정점 배제·기존 가중치 보존·명시 활성화·기준 가중치 부재 실패를 포함한다. `model_pipeline.py`로 지정된 두 메시만 수정한 후보를 만들었다. 수정 전후 중립 24장, 비틀기·기울이기 56장을 직접 비교했다. 누락 가중치는 218개에서 0개, 6개 회전 표본의 정점 추종 오차는 최대 약 4.92e-7이었다. Pose Editor의 허리 제어점 30도 회전과 저장·재로딩도 통과했다. 실제 GUI 입력·전체 관절 가동·연속 간섭은 미검증이다.

설정은 `Tools/blender_pipeline/workspace/basic_weapons/waist_weight_repair_20261110/repair.json`, 수정 후보는 `output/pose_rig_waist_audit_20261110/repair_candidate/candidate.blend`, 회전 검사·비교는 같은 출력 폴더에 있다. 후보 검수 당시에는 원본을 보존했고 사용자 확인을 기다렸다.

사용자 확인 후 기존 `base_pose.blend`에 검수한 가중치만 반영했다. 기존 파일은 같은 출력 폴더의 `before_apply/base_pose.blend`에 보존했다. 대상 두 메시의 구조 지문이 검수 후보와 같고, 다른 객체 지문·116개 패킹 이미지·이미지 경로가 유지됨을 저장·재로딩 후 확인했다. 적용 파일에서도 여섯 회전 검사의 최대 추종 오차가 약 4.89e-7이며 누락 정점은 0이다. 적용 파일의 사선 확대/240px 렌더도 확인했다.

`base_pose.json`과 현재 동작 제작 설정의 소스 해시를 갱신하고 적용 모델 레지스트리를 추출했다. 새 기본 해시는 `d84ab62b9f7cc67b9bf5112e9ad32c2e3cb439262660b5daa2028b250d315c56`이다. 과거 후보의 소스 해시·사용자 작업본·별도 `player_mech.blend` 릴리스는 변경하지 않았다. 최종 근거는 `applied_check.json`, `applied_rotation_check.json`, `applied_review/`다. 에셋 업로드는 수행하지 않았다.
