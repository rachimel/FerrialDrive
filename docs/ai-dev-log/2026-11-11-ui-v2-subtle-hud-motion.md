# UI v2 미세 글자 명도·에너지 호흡·빠른 전환

- **기록 ID: ui-v2-subtle-hud-motion**. 대화·구현·검증·정리: 2026-11-11 KST, 현재 대화.
- 개별 발언의 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:ui-v2-subtle-hud-motion:scope]] 검색 단서: `광과민성`, `Breathing`, `글자와 숫자만`, `피해 숫자와 COUNTER 표시`.

## 1. 사용자가 제안한 것

- **U1**: MAP·HP·RANGED·MELEE·카운터·데미지에 약한 깜빡임을 넣는다. 광과민성 우려로 약하게 해 달라고 했으며 질문에 글자와 숫자만 적용한다고 선택했다.
- **U2**: 에너지에는 Breathing을 적용한다. 에너지 느낌을 표현하려는 의도를 밝혔다.
- **U3**: 인디케이터 등장/퇴장을 빠르게 한다. 질문에 록온이 아닌 피해 숫자와 COUNTER 표시를 선택했다.

## 2. AI가 제안한 것

- 구현상 판단으로 글자 94~100%·샘플 간격 0.6초의 부드러운 변화를 사용한다. 호흡은 2.4초 주기·82~100%로 한다. 큰 면적에 동시 점멸을 추가하지 않는다.
- 피해 숫자는 각 등장/퇴장 0.06초로 단축하고 총 수명은 유지한다. COUNTER는 기존 즉시 표시 대신 등장 0.06초·퇴장 0.05초의 짧은 전환을 제시했다. 수치는 시험값이다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U3를 반영했다. 표시별 고정 샘플을 smoothstep으로 연결하며 패널과 HP 채움은 미세 명도 대상에서 제외했다. 에너지 채움·끝선·문구만 호흡한다. UI 시계는 일시정지 중에도 이어진다.
- 실제 피해 숫자 펼침 인자인 `damage_popup` 설정에 시간을 넣었다. 전체 수명 1.15초·게임 상태·록온 시간은 유지한다. COUNTER가 논리적으로 꺼져도 퇴장이 끝날 때까지 출력한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 글자/숫자 범위와 피해 숫자/COUNTER 대상은 사용자 명시 선택이다. 명도·주기·전환 시간의 별도 최종 승인은 확인 전이다.

## 5. 반영 후 발견한 문제

- 피해 숫자에 전달되는 실제 펼침 값은 `damage_popup`이며 기존 `animation`의 별도 펼침 키는 실행부에서 직접 전달하지 않았다. 이번 실제 설정 두 곳은 같은 수치로 맞췄다.
- 이번 자동 검사·렌더에서 추가 실패는 확인하지 않았다. 개인별 시각 반응을 검사한 것은 아니다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1 선택에 따라 글자만 바꾸고 패널을 함께 점멸시키지 않았다. U3 선택에 따라 록온 시간은 수정하지 않았다.

## 7. AI 해결 제안과 실제 해결 과정

- 명도 샘플·호흡 함수와 `IndicatorFade`를 표현 모듈에 두고 시간 갱신은 실행부가 관리한다. `minimum_opacity=1`로 각 장식을 정지할 수 있다.
- UI **119개**·획득 **7개**, 총 **126개 통과**. 작은 명도 범위·60fps 변화량·연속성·호흡 주기·전환 반전/완료·전체 피해 수명·받침판 투명도 유지 등을 검사했다.
- 피해/COUNTER 전환과 호흡을 60fps 시간 간격 **240프레임**으로 렌더하고 주요 이미지를 검토했다. 출력은 `output/ui_unit_test_v2/subtle_hud_motion/`다. 실제 창 조작·개인별 시각 반응·GPU 성능·최종 외관 승인·업로드는 미확인/미수행이다.
