## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 문서를 전반적으로 최신화하고 Blender 애니메이션 제어를 사용하지 않으며 Unreal에서 조작하도록 바꾸라고 요청했다. Pose Tool도 필요하지 않다고 밝혔다. 후속으로 **Blender 모델링 → Unreal 리깅 → `.blend` 반환 → 기존 파츠·레이어 분리 이후 경로**로 역할을 구체화했다. 의도는 사용자가 명시한 제작 역할과 문서를 일치시키는 것이다. Unreal 선택의 별도 이유는 미제시 — [[FDLOG_MISSING_REASON:FDLOG-20261110-unreal-pipeline-document-refresh:U1]] 같은 대화의 Unreal 전환 요청 이전/이후 발언에서 선택 이유를 확인한다.
- **사용자 제안 2 (U2):** 권한 확인창이 생략되면 진행을 알 수 없으므로 행동할 때 짧게 보고하고 AGENTS.md에도 적으라고 요청했다. 제거·최신화한 부분을 구체적으로 보고하라고 했다.
- **사용자 제안 3 (U3):** KeyPose 검수가 유의미한 동작을 만들기보다 복잡도를 늘린다고 평가했다. 사용자가 기존 검수 결과를 직접 열었으며 상박·하박이 지나치게 좁은 V자로 접힌 자세도 AI가 정상 판정했다고 제보했다. 정지 자세 승인과 실제 모션 품질이 연결되지 않은 문제를 지적한 것이다.
- 시각·출처: 현재 사용자의 직접 발언. 정확한 시각은 scope에 포함한다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1: Blender의 현재 역할을 모델링·UV/재질·반환 변환/검사·렌더로 정리하고 리깅·포즈·키·타이밍 편집을 Unreal로 옮기는 문서 변경으로 수용했다. 기존 파츠·레이어 설정과 출력 경로는 유지한다.
- U2: `AGENTS.md`에 조회·수정·실행·검증 전 행동과 목적을 짧게 보고하고 단계 변경 때 다시 보고하는 규칙을 추가했다. 계획·실제 변경·확인 결과를 구분한다.
- U3: 별도 KeyPose 사전 승인·확정 대기를 현행 절차에서 제외하고 전체 동작의 실제 재생과 문제 프레임 확인으로 정리했다. 모델 외형 변경 승인을 폐지한 것은 아니다.
- 수용 시각·근거: 현재 AI 응답과 이어진 문서 반영. 개별 시각은 scope에 포함한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** **Unreal 짧은 동작 초안 → 전체 재생 검수 → 수정·재검수**로 단순화하고 KeyPose를 제작·진단 수단으로 사용한다. 정지 자세 승인으로 타이밍·중간 궤적·무게감이 검증되지 않는데 대기 단계가 추가되는 문제를 줄이기 위한 제안이다.
- **구현상 판단:** 새 `unreal_pipeline.md`에 역할·반환 계약·현재 도구 한계를 모으고 관련 현행 문서를 연결했다. 과거 문서의 원기록은 재작성하지 않고 현재 기준 안내만 덧붙였다. 이는 문서 구성 판단이며 프로그램 구현이나 자동 품질 판정 기능 추가가 아니다.
- 시각·출처: 현재 AI의 단순화 설명·문서 변경 안내. 정확한 시각은 scope에 포함한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1에 대한 별도 명시적 수용 응답은 아직 확인되지 않았다. 사용자의 후속 팔 자세 제보를 A1 전체의 승인으로 확대하지 않는다. 현재 문서의 절차 단순화는 U3의 문제 평가를 반영한 AI 조치다.
- U1·U2는 AI 제안의 수용으로 바꾸지 않고 사용자 직접 요구로 유지한다. 신규 Unreal 리그 변환기·모든 기존 동작의 품질·코드/파일 삭제를 승인받았다고 쓰지 않는다.

## 5. 반영 후 발견한 문제

- **I1 — 기존 문서 혼재:** 현재 도구와 41개 반환 초안이 있는데 상위 문서는 Blender 키포즈 제작 또는 Unreal 채택 미확정으로 안내했다. 현재 작업에서 읽기 확인한 문서 불일치다.
- **I2 — 기존 AI 검수 문제 제보:** 사용자가 검수된 자세에서 상박·하박의 과도한 V자 접힘을 확인했다. 이번 문서 변경으로 새로 발생한 문제가 아니다. 해당 후보 이미지를 이번 작업에서 다시 열거나 정상/비정상 각도를 새로 계측하지 않았다. 특정 파일 전체의 재검증 완료로 쓰지 않는다.
- **I3 — 반환 구현의 차이:** 현재 `blender_transfer.py`와 batch 경로는 기존 Blender 본 이름·Rest Pose 매핑에 기반한다. 사용자가 요청한 Unreal 신규/변경 리그의 `.blend` 반환까지 구현돼 있다고 볼 수 없다.
- **I4 — 문서 갱신 중 적용 실패:** 첫 일괄 패치는 동일 파일 삭제/추가 형식으로 거부돼 적용되지 않았다. 안내 문서 묶음도 표의 원문 불일치에서 저장 전에 멈췄다. 각각 작은 수정과 정확한 원문 확인으로 재적용했다. 기존 사용자 변경을 되돌리지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1·I3 ↔ U1: 사용자가 모델링/리깅 도구와 `.blend` 이후 기존 경로의 경계를 직접 정했다. 이를 현행 명세·PRE-PRD·README·Asset Tool 안내·샘플의 기준으로 반영했다.
- I2 ↔ U3: KeyPose 검수의 실효성과 잘못 통과된 팔 자세 제보는 사용자에게서 나왔다. AI가 이를 새로 발견하거나 기존 후보를 전부 수정했다고 기록하지 않는다.
