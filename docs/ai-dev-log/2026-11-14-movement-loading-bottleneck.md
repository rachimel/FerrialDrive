- **AI 제안 1 (A1):** 그림자 준비·공유 아틀라스 읽기·검증·압축 해제·전송·로딩 화면 비용을 나눠 실측한다. 이유는 예전 개별 보간 경로를 현재 병목으로 오인하지 않기 위해서다. 출처는 현재 대화의 계측 보고, 시각은 scope 참조.
- **AI 제안 2 (A2):** 그림자를 제작 시 알파 전용 데이터로 준비하는 방향을 최우선으로 검토하고, 다음으로 아틀라스 압축 해제 비용을 줄인다. 근거는 아래 2회 실측이며 제시 시각은 결과 확인 이후다. 구체적인 저장 형식·압축·병렬화 방식과 실제 절감량은 미확정이다.

## 5. 반영 후 발견한 문제

- **I1:** U1의 기존 시작 지연이다. 이번 제품 수정으로 생긴 회귀가 아니다. 과거와 동일 조건의 시작 시간 기준이 없어 최근 변경 중 무엇이 악화시켰는지는 확정하지 않는다.
- 현재 경로는 high 공유 아틀라스와 별도 R8 그림자 적재다. 본체 개별 보간 PNG의 Python 알파 사전 곱셈 경로가 이번에 측정된 병목은 아니다.

| 측정 구간 | 1회 | 2회 |
| --- | ---: | ---: |
| 진단 실행부 시작→첫 게임 화면 present 반환 | 6.232초 | 6.098초 |
| 창 생성·준비 | 0.569초 | 0.581초 |
| app.enter 전체 | 5.437초 | 5.270초 |
| 그림자 준비 18회 | 2.775초 | 2.685초 |
| └ PNG→RGBA 읽기·변환·행 복사 | 2.368초 | 2.328초 |
| 공유 아틀라스 전체 | 2.301초 | 2.185초 |
| └ 압축 해제 92회 | 1.404초 | 1.417초 |
| └ GPU 전송 완료 대기 포함 92회 | 0.537초 | 0.528초 |
| └ 파일 읽기 | 0.036초 | 0.038초 |
| └ SHA-256 확인 | 0.021초 | 0.021초 |
| 로딩 화면 show 115회 | 0.115초 | 0.103초 |

- 행은 하위 호출·대기를 포함한 경과 시간이다. 부모·자식 행을 합산하지 않는다. GPU 전송 행은 독점 GPU 실행시간이 아니다. `load.upload_complete` 앞의 별도 `glFinish` 대기는 해당 행 밖이며 아틀라스 전체 구간에는 포함된다.
- 그림자 18장의 디스크 합계는 10.89MiB, 해상도 합계는 281,158,320픽셀이다. 현재 코드는 이를 RGBA로 읽고 채널을 추출한다. RGBA 누적 페이로드는 1,072.53MiB, 최종 알파 누적 페이로드는 268.13MiB다. 누적 처리량이며 동시에 점유하는 RAM이나 RAM 피크 실측이 아니다.
- `read_rgba_image()`는 PNG 해제·RGBA 변환 뒤 행마다 `ct.string_at()`으로 복사해 합친다. 이후 `load_alpha_texture()`가 `rgba[3::4]`와 추가 전송 버퍼를 만든다. 정확히 어느 복사 연산이 몇 초인지는 이번 집계에서 분리하지 않았다.
- 아틀라스는 BC7+zlib 색상 34페이지와 RGBA+zlib 벡터 58페이지, 총 92페이지다. GPU 텍스처 페이로드는 886.43MiB다. 전체 VRAM 사용량이 아니다. 모든 페이지를 시작 시 순차 해제·적재한다.
- 그림자 준비가 app.enter의 약 51%, 아틀라스 압축 해제가 약 26%다. 아틀라스의 짧은 파일 읽기 시간과 비슷한 재실행 결과는 현재 조건에서 CPU 데이터 준비를 우선 조사할 근거다. 그림자 파일 읽기 자체는 PNG 해제와 분리 측정하지 않았다.

- I1 ↔ A2: 우선순위는 그림자의 런타임 PNG→RGBA→알파 변환 제거, 다음으로 벡터를 포함한 아틀라스 압축 해제 비용 감소다. 병렬화는 CPU 준비와 메인 스레드 GPU 작업을 분리해 검토한다. 이미지 품질과 시작 시 전체 준비 범위를 바꾸는 선택은 사용자와 논의한다.
