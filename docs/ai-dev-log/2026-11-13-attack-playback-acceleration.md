# 공격 재생 위상의 후반 가속

- **기록 ID:** `FDLOG-20261113-attack-playback-acceleration`
- 작성·확인: **2026-11-13 13:55 KST**. 대화 범위: `프레임 보간 위상 함수도 가속도에 맞춰볼까?` → `이동 가속 말고` → `그 재생 시간` → `ㅇㅇ 그렇게 하자`. 개별 발언의 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261113-attack-playback-acceleration:scope]] 현재 대화의 해당 구절로 검색한다.
- 근거: 현재 대화, [검 이동 명세](../unit-tests/sword_movement.md), [보간 명세](../unit-tests/frame_interpolation.md), 자동 검사, 로컬 `output/attack_playback/accelerated_report.json`과 연속 캡처.
- 상태: 게임/공유 보간기와 UI v2 공격 연결·자동 검사·실제 OpenGL 사전 지정 입력 확인. 사용자 직접 조작·사용감 승인·커밋·업로드는 미수행이다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 프레임 보간의 재생 위상도 가속하도록 제안하고, 기체 이동이 아닌 모션의 재생 시간을 뜻한다고 정정했다. 근거는 위 대화이며 시각은 scope 참조. 세부 감각상의 이유는 미제시다. [[FDLOG_MISSING_REASON:FDLOG-20261113-attack-playback-acceleration:U1]] 검색 단서는 `프레임 보간 위상 함수도 가속도에 맞춰볼까`다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1을 기체 위치·이동 가속과 분리한 공격 모션의 시간 배분 변경으로 수용했다. 기존 이동 속도·거리·마우스 방향 규칙은 유지한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 기존 SmoothStep 위상은 느림→빠름→느림이므로, 초반 준비 동작은 천천히·후반 휘두르기는 빠르게 하는 가속형 위상을 제안했다. 총 타격 시간은 유지하고 그 안의 시간 배분만 바꾸자는 설명이며 시각은 scope 참조.
- **구현상 판단:** 곡선은 `p(t)=2t³−t⁴`를 선택했다. 현재 이동의 SmoothStep 속도를 누적하고 0~1로 정규화한 위상이며, 재생 속도는 `p'(t)=2(3t²−2t³)`로 증가한다. 사용자가 정확한 다항식을 별도 지정한 것은 아니다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1에 `ㅇㅇ 그렇게 하자`로 명시 응답했다. 초반 느림·후반 빠름·총 시간 유지가 수용 범위다. 구현 결과의 외관/사용감 승인은 별도다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1):** 실제 모션 셰이더에 새 위상을 추가한 뒤 첫 GPU 비교에서 큰 차이가 검출됐다. 비교용 도형의 정답 셰이더와 uniform 전달은 여전히 선형/SmoothStep만 지원해 새 위상을 선형으로 처리했다. 기준 경로의 미지원이 원인이었다.
- 기존 공격의 본체·그림자·보간 끈 원본 프레임 선택이 서로 다른 시간 계산을 사용했다. 새 위상은 세 경로를 함께 연결해야 하므로 기존 시간 분리도 이번 범위에 포함했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1의 정정을 반영해 이동 계산을 변경하지 않고 재생 곡선만 교체했다. 1·2타 목표 45/90m/s, 3타 60/120m/s, 4타 30/60m/s와 전체 시간 이동 가속은 유지한다.
- I1의 수정안은 사용자 제안으로 확인하지 않았으며 AI의 수정은 다음 절에 기록한다.

## 7. AI 해결 제안과 실제 해결 과정

- 공통 CPU `target_phase`와 기존·아틀라스 GPU 보간기에 `accelerate`를 추가했다. 검 이동의 `combat.easing`, UI v2의 `player_asset.combo_easing`에서 선택하며 반복 이동·Idle의 곡선은 유지한다. 아틀라스의 기존 `smoothstep` 인자는 호환한다.
- 본체/그림자/원본 프레임은 같은 목표 위상을 사용하고, 블러는 노출 구간의 각 시간 표본에 같은 곡선을 적용한다. 블러 후에 곡선을 한 번 더 적용하지 않는다. UI v2 공격에는 실제 1.25배 재생 속도를 블러 노출에 전달한다.
- I1: 비교용 도형 셰이더와 easing 코드 전달에도 새 위상을 추가했다. 기존 GPU에서 0/25/50/75/100% 시점을 기준 도형과 대조했고, 아틀라스에서는 CPU 변환 위상을 선형 렌더한 픽셀과 일치하는지 별도 검사했다.
- 자동 검사 **131개 실행, 126개 통과·선택 검사 5개 생략**. 보간 17개·아틀라스 12개·검 이동 41개·UI 보간 연결 7개·UI v2 54개를 포함한다. 생략은 별도 로컬 Unreal 정답/네이티브 UI 검사이며 모든 에셋의 품질 승인을 뜻하지 않는다.
- 실제 중간 품질 OpenGL에서 4타 사전 지정 입력 **112프레임**을 실행했다. 이전 이동 가속 구현 보고서와 비교해 기록된 **109프레임의 위치·속도·공격 상태·방향이 전부 동일**했다. 연속 캡처를 열어 초반 준비/후반 베기·그림자·표시를 확인했다. 물리 키보드 사용감과 사용자 승인은 미검증이다.
- 명중 판정·피해 시점은 아직 이 프로그램에 연결되지 않았다. 향후 판정을 연결할 때 원래 시간과 표시 위상을 구분해야 한다.
