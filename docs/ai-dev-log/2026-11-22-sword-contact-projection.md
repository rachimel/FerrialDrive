# 검 베임선·불꽃 카메라 투영 비용 절감

- **기록 ID** `FDLOG-20261122-sword-contact-projection`
- 2026-11-22 KST 계측. FHD·Medium·SMAA, 적 180기·15m 간격, 플레이어 HP 10만, 고정 60Hz 자동 검 입력, 무음, VSync와 프레임 제한 해제다.

## 1. 사용자가 제안한 것

- **U1** `draw_contacts`에서 정점마다 `world_to_screen`을 호출하는 비용을 줄인다. 화면을 보존하고 같은 180기 입력·품질에서 전후 함수 시간과 FPS를 비교해 별도 커밋한다. 정확한 요청 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261122-sword-contact-projection:U1]]`. 검색 단서는 `검 베임선·불꽃부터 최적화`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** `draw_contacts`가 카메라 위치·화면 중심·충격 오프셋·줌을 호출당 한 번 읽는다. 좌표에서 카메라 위치를 빼고 줌을 곱한 뒤 화면 중심과 충격을 더하는 기존 부동소수점 연산 순서를 유지한다.

## 3. AI가 제안한 것

- **A1 · 구현상 판단** 같은 프로세스에서 전후 메서드만 교체했다. 각 조건은 30프레임 예열 뒤 120프레임 측정이며 FPS 네 쌍의 실행 순서를 교차했다. 함수 직접 시간 두 쌍, `cProfile` 호출 추적 한 쌍, 화면 읽기는 별도 회차다. FPS 비교는 기존 정점 버퍼 재사용이 있는 실제 작업본 기준이다. 해당 선행 변경은 이번 커밋 범위 밖이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 전후 계측과 화면 보존은 사용자 요구다. 실행 순서·표본 수·두 함수 계측 방식은 구현상 판단이다.

## 5. 반영 후 발견한 문제

- **I1** 서로 다른 실행의 전체 화면 해시는 A/B와 기존 방식의 A/A 재실행에서 각각 120장 중 3장만 일치했다. 이 결과로는 접촉 효과의 픽셀 동일성을 판정할 수 없었다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 전후 120프레임의 입력·교전 상태 해시가 일치했다. 제출한 정점·색상·인덱스는 접촉 이펙트가 있는 114프레임의 199,184개 정점에서 바이트 단위로 일치했다. Git 기준의 별도 제출 경로에도 같은 투영 변경을 적용해 이 정점·인덱스 비교를 120프레임 반복했다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1** 같은 실행의 같은 프레임에서 접촉 효과 직전의 실제 OpenGL 배경을 복제한 뒤 두 구현으로 합성했다. 충격 오프셋이 최대 15.97px인 1920×1080 활성 프레임 114장의 픽셀이 모두 일치했다.
- **U1** 회차 중앙값은 관측 FPS **33.55 → 37.37**(+11.4%), 프레임 작업 P50 **28.64 → 26.03ms**, P95 **40.77 → 36.41ms**다. 네 쌍 모두 적용 후 관측 FPS가 높았다.
- 전체 프레임 기준 `PicoSwordEffects.draw_contacts` 평균은 **3.10 → 1.98ms**(−36.0%)다. `_SwordContactBuffers.prepare` 평균은 0.16ms 수준을 유지했다. 별도 `cProfile`에서는 `vertex`가 호출 수를 프레임당 1,659.87회로 유지하며 포함 시간이 4.62→0.70ms였다. `LookAheadCamera.world_to_screen`은 프레임당 1,659.87회·3.55ms에서 0회가 됐다. 직접 함수 시간과 프로파일러의 포함 시간을 합산하지 않았다.
- 검 이펙트·카메라 충격 자동 검사 35개가 통과했다. 측정 스크립트·원본과 요약은 로컬 `output/performance/sword_contact_projection_20261122/`에 있다.
