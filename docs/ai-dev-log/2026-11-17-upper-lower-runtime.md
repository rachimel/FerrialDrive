## 1. 사용자가 제안한 것

- **사용자 승인·지시 1 (U1):** 제시한 8종 확장 결과에 긍정 응답하고 훈련장 연결을 지시했다. 출처: `좋은데? 일단 연결 ㄱㄱ`. 해당 후보를 실제 입력에 연결하는 것으로 해석해 진행한다. 시각은 scope 참조.

## 2. 사용자 제안 중 AI가 수용한 것

- U1을 수용했다. 원본·활성 에셋 파일은 보존하고 새 런타임 자료를 설정에서 선택한다. 이동 경로·공격 전진 방향·총탄/록온 규칙은 유지한다.
- 상체가 먼저 현재 시선을 보간 추종하며 하체는 ±45° 초과 뒤 정렬까지 추종한다. 이동·공격 중에도 같은 상태를 사용한다.

## 3. AI가 제안한 것

- **AI 구현상 판단 1 (A1):** 5초 고정 입력의 검수 클립을 그대로 게임에 등록하지 않는다. 원본 동작 위상과 상체 8방향×하체 8방향을 함께 Unreal에서 평가한 표를 만든다. 다른 자세의 PNG를 임의로 섞지 않고 파지·허리 위치·가림을 보존하기 위해서다.
- **AI 구현상 판단 2 (A2):** 기존 `PicoAtlasSprite`의 적재·발광·그림자 경로를 재사용한다. 새 표는 12fps 원본 프레임을 선택하며 모션 벡터 보간으로 표현하지 않는다. 표가 없는 부스트·전환·조준 이동/사격은 기존 경로로 재생한다.
- **AI 구현상 판단 3 (A3):** 원본의 120Hz 본 추적을 허리 기준으로 회전·투영해 총구·검날·발 부착을 연결한다. 공격 중 시선 변화도 효과 표본에 전달하고 잔상은 생성 당시 방향을 보존한다.
- **AI 구현상 판단 4 (A4):** 초기 네 표만 고품질 적재량이 약 1.6GiB여서 전체 상시 적재를 피한다. 약 1.5GiB의 동작별 캐시를 쓰고 현재 기체·살아 있는 잔상은 프레임 중 유지한다. 동시 필수 자료가 크면 일시 초과할 수 있다. 실제 프레임 성능과 구분한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U1은 제시한 후보의 연결 지시다. 표의 세부 구현·캐시 수치·새 런타임 조작감에 대한 별도 사용자 승인을 추정하지 않는다.

## 5. 반영 후 발견한 문제

- **I1 — 입력 자료:** 5초 고정 시선 경로는 실제 마우스·동작 위상과 독립적으로 선택할 수 없다.
- **I2 — 제작 배치 연결:** 배치 `operation`, 그림자 장면의 `shadow_reference_only`/`map`, 재사용 하체 메시 경로가 기존 규약과 달라 준비가 실패했다. 실패 보고를 보존하고 완료 에셋은 재생성하지 않았다.
- **I3 — 확장한 방향의 그림자:** 검 1타 448프레임 중 4프레임에서 그림자가 오른쪽 경계에 닿았다. 전 상태의 참조/그림자 알파를 조사해 해당 동작에만 여백 확장이 필요함을 확인했다.
- **I4 — 총 부착 기준:** 부착 항목이 없는 원본 총 동작에서 승인된 검수 후보의 `weapon_gun → hand_r` 기준을 빠뜨렸다. 초기 총 표는 연결하지 않고 r02로 다시 제작했다.
- **I5 — 검사 환경/기대치:** NumPy/Pillow는 기본 게임 환경에 없어 기존 `automate/runtime/` 의존성을 사용했다. 총 명중 카메라 기대치 6/8과 현행 설정 10/16이 다른 검사 1개도 발견했다. 본 작업에서 그 수치를 변경하지 않았다.
- **I6 — 90° 회전 환산:** 최종 부착점 대조에서 총구의 화면 위치가 최대 약 56픽셀 어긋났다. ±90° pitch에서 Euler yaw를 길이가 거의 0인 X축 투영으로 추출해 방향이 손실됐다. 기존 검사는 같은 환산을 거친 값끼리 비교해 이를 발견하지 못했다. r02_gun은 활성화하지 않았다.
- **I7 — 활성화 후 검사 가정:** 첫 록온 검사는 발사 방향이 항상 화면 수평이라고 가정했다. 상체 회전 뒤에는 총구 위치도 변하므로 올바른 표적 방향의 x 성분이 1보다 작아졌다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1과 재개 요청에 따라 연결했다. I1~I7의 구체적인 구현·수정은 AI가 수행했으며 사용자 해결안으로 분류하지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 공통 `unreal-pose-table prepare/run/pack/extend-canvas/merge`를 추가했다. 기존 제작·MRQ·아틀라스 모듈을 재사용한다. 표에 한해 최대 4,096프레임을 허용하며 같은 자세를 두 프레임 유지하고 짝수 프레임만 출력한다. 일반 짧은 동작의 기존 길이 제한은 유지한다. [MRQ Output Frame Step](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/MoviePipelineOutputSetting?application_version=5.8)은 시험 렌더의 파일 번호로 확인했다.
- I2: 기존 규약에 맞춰 요청을 수정하고 실패 보고·완료 장면을 보존했다. 원본 모델·리그·동작 키를 수정하지 않았다.
- I3: 검 1타만 512→768 캔버스·1,400→2,100cm 직교 폭으로 다시 출력해 cm당 픽셀 수·광원·자세를 유지했다. 검 3,328프레임과 최종 총 3,776프레임의 실루엣·에너지 알파가 일치하고 본체·그림자 잘림이 없다. RGB 차이는 검 53·총 83프레임의 각 1픽셀, 최대 검 164·총 188/255다. 원인은 미확정 — [[FDLOG_MISSING_CAUSE:FDLOG-20261117-upper-lower-runtime:I3]]. 검색 단서: `r01/pack_verification.json`·`r03_gun/pack_verification.json`과 상태별 `verification.json`.
- I4: 총의 `weapon_gun → hand_r` 추종을 명시하고 원본의 총/손 상대 변환을 유지했다. 최종 총 r03_gun에도 동일하게 적용했다. 초기 총 표는 보존하며 최종 카탈로그에서 제외한다.
- I6: 공통 `pose_math.to_euler`에서 수직 X축이면 Y축으로 yaw를 구하도록 수정했다. 환산 전 의도한 월드 쿼터니언과 실제 저장·재로딩된 Unreal 본을 비교하도록 검사를 분리했다. 새 총 r03_gun에는 암묵적인 Root 제어도 명시했다. 검 r01은 pelvis에 회전을 반영하고 Root 피봇을 보존한 기존 출력으로 구분해 검증했다. 최종 총 30,208개 본 자세의 최대 위치 오차는 약 0.00392cm·각도 오차는 약 0.00137°다. ±90°·근접 각도 왕복과 Root/무기 방향 검사를 추가했다.
- I7: 첫 자동 획득 뒤 1발 발사와 선택 표적→실제 총구의 정규화 방향을 확인하도록 해당 검사를 수정했다. 명중·록온 동작 코드는 바꾸지 않았다.
- 입력·효과 연결: 이동/공격 갱신 뒤 몸의 시선 기준만 갱신한다. `PoseAttachments`·`PoseBladeTrajectory`는 같은 3D 추적을 투영하고 `AttackEcho`는 생성 당시 자세 키를 가진다. 게임은 새 `data/runtime/upper_lower/`를 읽으며 `output/`을 필수 입력으로 참조하지 않는다.
- 활성 자료: `data/runtime/upper_lower/player_20261117_connected_r02/catalog.json`은 검 r01·총 r03_gun의 15동작·각 64조합을 참조한다. 검 대기·달리기·대시·4타, 총 비조준 대기·4방향 달리기·대시·사격·정지 조준이다. 기본 설정에는 `upper_lower`만 추가해 다른 작업의 총기·음향·카메라 설정을 보존했다. 별도 `--config` 없이 실행한 80프레임에서도 새 카탈로그 선택을 확인했다.
- 자동 검사: 관련 131개 중 129개 통과·환경 선택 2개 생략. 추가 총기 검사 33개 통과. 현행 카메라 10/16과 과거 기대치 6/8인 검사 1개는 제외해 별도 기록했다. 전체 저장소 검사 통과로 확대하지 않는다. 근거는 `automated_verification.json`이다.
- 실제 렌더: 최종 검 자료의 900프레임, 수정한 총의 640프레임·46발, 고품질 80프레임, 활성 기본 설정 80프레임을 실제 OpenGL에서 스크립트 입력으로 실행했다. 검 Trail·생성 당시 방향의 잔상·총구·새 표/기존 출력 전환과 45° 안에서도 이어지는 하체 정렬을 캡처·추적으로 확인했다. 이전 총 자료로 검사한 품질 변경의 상태 보존은 새 총 외관 검증과 구분한다. 사람의 직접 조작은 수행하지 않았다.
- 부착·패키지: 실제 Unreal 검날 양끝·총구·양발 35,520점을 런타임 투영과 비교해 최대 0.00884픽셀 차이를 확인했다. 새 메시 점의 실측은 아니다. 최종 3품질 Atlas 45개·페이지 해시 597개·클립 텍스처 묶음 5,760개를 확인했다. 보존 입력·기존 에셋 967개는 해시 변경·누락이 없다.
- 검토 자료: `output/upper_lower_runtime_20261117_review/runtime_melee.gif`·`runtime_gun.gif`, 같은 이름의 프레임 시트, `gun_ready_corrected_all_pairs.png`와 최종 실제 창 캡처를 직접 열어 확인했다. GIF는 60Hz 게임의 매 6프레임 표본이다. 잘린 기록용 근접 화면을 실제 렌더 잘림으로 취급하지 않는다.
- 남은 한계: 화면은 8방향·12fps 프레임 선택이며 새 표에 모션 벡터 보간을 적용하지 않는다. 제자리 회전의 발 미끄러짐과 미지원 부스트·전환·조준 이동/사격의 기존 출력 복귀가 남아 있다. 최종 저품질의 상하체 적재량은 약 0.94GiB이며 고품질은 동작별 캐시를 사용한다. 고품질 80프레임의 CPU draw 최대 908ms는 첫 적재 지연을 포함하므로 무중단 성능이나 실제 GPU 시간으로 보고하지 않는다. 연속 메시 충돌·접지·사용자의 최종 사용감 확인은 미완료다.
