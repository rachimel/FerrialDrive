## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 적 피격 시 카메라 피드백을 추가한다. 발생 조건은 직접 지정했으며 별도의 세부 이유는 제시하지 않았다.
- **사용자 제안 2 (U2):** 검의 카메라 충격을 우선 12px로 시험한다. 첫 수치는 잠정 시험값이다.
- 시각·출처: 위 대화 범위·발언과 TIME(scope) 검색 단서를 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1: 훈련장의 실제 검 명중 사건에만 연결했다. 본편 전투 완성이나 다른 무기 피드백 구현을 뜻하지 않는다.
- U2: `samples/sword_movement/movement_config.json`에 최대 진폭 12px를 반영했다. 지속 시간은 앞서 제안한 범위 안의 0.1초다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 일반 명중에 2~4px·0.08~0.12초의 짧은 방향성 충격을 시험하고 빠르게 감쇠 복귀한다. 연속 공격의 시야 방해를 줄이려는 제안이다. 최초 구현상 선택은 3px·0.1초였으며 이후 U2로 검 진폭을 12px로 바꿨다.
- **AI 제안 2 (A2):** 같은 타격의 동시·연속 프레임 명중은 충격을 합산하거나 재시작하지 않는다. 고정 HUD·조준·자동 타겟 선택은 충격과 분리하고, 월드·적 HP·록온·피해 숫자는 함께 움직인다.
- 구현상 판단: 표적에 가장 가까운 해당 타격의 검끝 이동 방향을 사용한다. 유효 궤적이 없는 호출에서는 투영한 기체 방향을 사용한다. 초 단위의 결정적 감쇠 곡선을 사용하며 새 타격도 진폭을 교체한다.
- 제안 시각·출처: 현재 채팅의 최초 AI 답변과 TIME(scope) 범위. 구현상 판단의 기록 시각은 위 작성 시각이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1/A2: 사용자의 `ㅇㅇ 일단 그렇게 해보자`로 잠정 시험을 수용했다.
- 이후 U2가 검 진폭을 12px로 지정했다. 0.1초 지속·중복 비누적·입력/표시 분리 방향을 유지했다. 구현 뒤 최종 강도·사용감의 별도 승인은 아직 없다.

## 5. 반영 후 발견한 문제

- **I1, 검증 환경:** 처음 선택한 기본 Python에는 Pico2D가 없어 기존 이동/UI 검사 일부가 실행 오류를 냈다. 제품 회귀로 판단하지 않았으며 프로젝트 전용 환경으로 다시 검증했다.
- **I2, 수치 경계:** 60Hz 누적 시간에서 0.1초 종료 경계에 부동소수점 잔여 오프셋이 약 1e-31px 남았다. 눈에 보이는 현상은 아니며 종료 허용 오차와 6프레임 복귀 검사로 정리했다.
- 새 표시 결함은 확인한 캡처에서 발견하지 못했다. 전체 방향·반복 전투의 사용감이 검증됐다는 뜻은 아니다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U2는 버그 수정이 아닌 강도 조정 요청이다. AI가 검 설정만 12px로 바꾸고 연결 검사·실제 렌더에서 최대값을 확인했다.
- I1/I2에 대한 별도의 사용자 해결 제안은 이번 대화에 없다.

## 7. AI 해결 제안과 실제 해결 과정

- `CameraImpact`에 충격 방향·수명·타격별 중복 방지를 분리했다. `LookAheadCamera`의 표시 오프셋은 추적 위치·속도·줌을 변경하지 않으며 표시의 정방향·역방향 변환에 함께 적용한다. 조준·자동 타겟 선택은 충격을 제외한 역변환을 사용한다. 레이더 중심도 충격을 제외한다.
- 실제 살아 있는 표적의 검 명중에서만 발생한다. 빈 휘두르기·사망 표적·F1 피해 시연에는 발생하지 않는다. 일시정지는 수명을 멈추고 훈련장 초기화는 충격과 타격 중복 기록을 제거한다.
- I1: `.venv-capability-test`의 Python과 SDL dummy에서 최종 관련 검사 195개를 실행해 192개 통과·선택적 GPU 검사 3개 제외·실패 0개를 확인했다. 범위는 `test_movement*.py`, `test_ui_v2*.py`, `test_sword_movement.py`, `test_camera_impact.py`다.
- 신규 핵심 검사 6개는 진폭 상한·방향·시간 간격 독립·다중 명중·조준/타겟 불변·HP/피해 숫자 좌표·일시정지·초기화·비활성을 확인한다. I2의 60Hz 종료 경계도 포함한다.
- 숨긴 OpenGL 창에서 실제 기체 80프레임을 실행했다. `energy_trail_input.json` 입력에서 8프레임 표적 B·9프레임 표적 C가 같은 타격에 명중했고, 최대 오프셋 길이는 정확히 12px였다. 두 번째 명중은 충격을 재시작하지 않았으며 15프레임부터 오프셋은 정확히 0이다. 화면 캡처를 직접 열어 명중 장면·HP·피해 숫자·고정 HUD의 표시를 확인했다.
- 근거 출력: `output/verification/camera_impact_20261116/report.json`, `frames/00008.png`, `frames/level_1.png`. 렌더 기록은 I2의 종료 허용 오차 정리 전이며 그 미세 경계 정리는 자동 검사로 확인했다. 캡처는 직접 조작·전체 재생 평가를 대신하지 않는다.
- 기존 관련 파일 다수가 다른 작업과 함께 미추적/미커밋 상태다. 관계없는 기존 변경을 포함하지 않기 위해 이번 작업을 별도 커밋하지 않았다. AI 에셋·검증 출력은 추가하지 않았다.
