# 직접 OpenGL 정점 스트리밍 대조

- 기록 ID `FDLOG-20261123-native-vbo-stream`
- 기록일 2026-11-23 KST

## 1. 사용자가 제안한 것

- **U1** 정점을 VBO에 묶어 올리고 Flamegraph에서 병목을 다시 확인한다. 요청 시각 `[[FDLOG_MISSING_TIME:FDLOG-20261123-native-vbo-stream:U1]]`. 대화에서 `VBO에 한꺼번에 올리는`과 `Flame Graph를 다시 확인`으로 찾는다.

## 2. 사용자 제안 중 AI가 수용한 것

- 월드·HUD의 일반 정점과 인덱스를 순서대로 묶어 업로드했다. 직접 셰이더, 타깃, 클립과 텍스처 갱신 경계에서 그룹을 제출했다. 기존 인스턴싱·그림자 경로와 함께 전체 화면을 비교했다.

## 3. AI가 제안한 것

- **A1** 512KiB CPU 정점 저장소와 2MiB GL 버퍼를 재사용한다. 새 범위에 그룹 전체를 올리고, 공간을 다 쓰면 GL 저장소를 재지정한다. 상태와 순서가 같은 연속 기본 도형은 하나의 호출로 병합한다. 두 용량과 묶는 기준은 구현상 판단이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- VBO 후보 검증은 사용자 요청이다. 기본 렌더 경로를 전환하는 결정과 직접 조작 검수는 확인되지 않았다.

## 5. 반영 후 발견한 문제

- **I1** 180기에서 드로우 호출은 줄었지만 30기와 180기 전체에서 프레임 꼬리 개선이 일관되지 않았다.
- **I2** 시간 일부가 즉시 `_draw`에서 다음 GL 경계의 VBO 제출로 옮겨졌다. 첫 계측은 아무 정점도 없는 제출 호출까지 포함해 최종 실행에서는 유효한 그룹만 제출했다.
- **I3** 느린 프레임에서 파츠 그리기의 미분류 시간이 컸다. 포즈 준비, 아틀라스 확보, 확대·SMAA를 나눠 다시 수집했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** RTX 5070 Laptop FHD 180기 120프레임 추적에서 일반 GL 드로우는 프레임당 182.4→158.0회였다. VBO는 프레임당 26.0회, 약 97KiB를 업로드했다. 텍스처 갱신·클립·인덱스 단위 시험을 포함한 캔버스 검사 5개가 통과했다. 30기·180기의 각 10개 시점에서 플레이어·적 그림자 깊이 맵과 사용 타일이 일치했다. 최종 RGB는 각각 첫 3개 시점에서 일치했고 나머지에 일부 픽셀 차이가 남았다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1·I2** RTX 5070 Laptop FHD, 준비 45·측정 120프레임, 상세계측 없는 순서 교대 두 번씩 비교했다. 180기 Medium p50은 클라이언트 배열 20.90–22.53ms, VBO 20.13–20.17ms였다. p99는 각각 53.31–61.13ms와 53.08–53.40ms였다. 30기 High p50은 각각 17.48–25.54ms와 17.50–22.49ms였고 편차가 컸다. 기본은 클라이언트 배열로 유지하고 VBO를 선택할 수 있게 했다.
- **I3** 별도 함수 추적의 VBO 11번 프레임은 104.26ms였다. `PartAtlasResidency.require` 45.88ms, 그 안의 `AtlasTextureCache.acquire` 20.25ms 및 그 안의 `_upload_gl` 3.66ms였다. `renderer.filtered_polygons`는 16.81ms, VBO 제출은 1.89ms였다. 수치는 포함 경과 시간이다. 클라이언트 배열의 가장 느린 28번 프레임에서도 아틀라스 확보가 45.04ms였다.
- **I3 후속** 페이지 준비 결과를 기다리는 구간을 분리한 VBO 실행의 가장 느린 30번 프레임은 63.54ms였다. 아틀라스 확보 33.88ms 중 페이지 준비 결과 대기 9.84ms, 캐시 확보 15.39ms가 기록됐다. GL 업로드 2.34ms는 캐시 확보에 포함된다. VBO 제출은 1.20ms였다. 페이지 준비 결과 대기는 파일 읽기·해제·스케줄링을 분리한 수치가 아니다.
- 2GiB 제한을 건 180기 VBO 시험은 120프레임을 완료했고 프로세스 커밋 최고치는 약 947MiB였다. 1,000기 Low VBO 6프레임을 확인했다. Intel 및 장시간 직접 조작은 미수행이다.
