- **U1:** 기존에 테스트한 프레임 보간을 `ui-unit-test-v2`에 적용한다. 기존 실험을 현재 UI 시연에서 재생하려는 직접 요청이다.

## 2. AI가 제안한 것

- **A1, 구현상 판단:** 기존 Unreal MRQ 캡처·변환기·`PicoFrameInterpolator`를 재사용한다. 초기 실험의 이전 콤보 후보 대신 현재 v2의 KneeFlex Idle·Timing 콤보와 저장된 방향별 카메라를 사용한다. 원본 포즈·재질·리그 변경 없이 데이터 범위를 맞추기 위한 판단이다.
- **A2, 구현상 판단:** 재사용 `PicoMotionSprite`가 40클립을 로딩 중 준비하고 기존 `DirectionalPlayback`·`ComboPlayback`의 연속 시간을 받는다. 재생 중 PNG 디코딩/텍스처 업로드를 피하고 기존 클릭 예약·대기·방향 유지·정지/초기화를 공유한다. 카탈로그가 없거나 보간을 끄면 기존 파츠/도형으로 실행한다.
- **A3, 구현상 판단:** 첫/끝 전체 위상의 SmoothStep·후방 노출 16ms·강도 65%를 초기값으로 연결한다. A/B 실험의 최종 전환 방식은 새로 확정하지 않고 현재 클릭 연계의 잔여 시간 이월을 유지한다. 구현 근거는 현행 소스·명세와 로컬 실제 렌더다. 별도 사전 제안·수용으로 승격하지 않는다.

## 5. 반영 후 발견한 문제

- **I1, 출력 환경:** 첫 전용 Unreal 프로세스가 작업 공간 밖 DerivedDataCache 쓰기 제한으로 렌더 전 종료됐다. 에셋 생성 이전의 로그로 원인을 확인했다.
- **I2, 변환 판정:** 매우 작은 Idle 후면 움직임에서 자동 재투영 최소 오차가 벡터 배율 4를 선택했다. 같은 조건의 나머지 39클립은 채널 `[0,1]`·축 `[-1,1]`·배율 2였다. 후면에서 배율 4/2의 오차는 각각 약 0.04930/0.05110으로 근접했다.
- **I3, 시각 검토:** 빠른 검격 일부에서 기존 6회 역매핑이 진동하며 상체/검 주변 픽셀이 흩어졌다. 블러를 꺼도 나타났다. 가림으로 사라진 표면의 부재와 수렴 문제를 구분한다.
- **I4, 후속 검사 오류 확인:** 2026-11-12 23:29:31 KST에 크기를 재확인하면서 초기 `endpoint_alignment.json`이 불투명한 창 버퍼 전체 1280×720의 알파 경계를 비교했음을 확인했다. 아래 최초 경계 차이 0px 보고는 유효하지 않다. 투명 RGBA 타깃 재비교의 최대 차이는 21px였다. 당시 원인은 미확인이었으며 후속 기록에서 현재 파츠의 Follow 동작과 보간용 Timing 동작이 다름을 확인했다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1:** 같은 전용 배치 작업에 필요한 캐시 접근 권한으로 재실행했다. 40캡처·120개 MRQ 작업이 완료됐으며 원본 맵·애니메이션 키는 변경하지 않았다. 현재 도구 목록에 DCC 도구가 없고 CLI가 PATH에 없어 기존 자동화 경로를 사용했다. 최신 production reuse 계약·Epic 기본 패스·기존 템플릿 범위를 확인한 근거는 `automate/workspace/ui_v2_interpolation_20261112/`에 보존했다. 새 외부 에셋·플러그인은 도입하지 않았다.
- **I2:** 변환기의 `--decoder`로 같은 조건에서 확인한 공통 규약을 명시할 수 있게 했다. 현재 움직이는 표면의 측정 후보에 없으면 거절하고 provenance에 명시 선택을 구분한다. 후면만 새 `n_native2` 결과로 변환했으며 처음 자동 결과도 보존했다. 40클립·304구간의 길이, 같은 방향·축·배율, 정/역 색상 일치를 확인했다. 정/역 RGBA 평균 오차의 최대는 약 0.000147이다.
- **I3:** 역매핑을 16회·완화율 0.5로 조정했다. 기존 6회와 동일 26개 Unreal 중간 시점에서 재비교했으며 알파 IoU가 0.02 넘게 나빠진 시점은 없었다. 현재 최저 IoU는 약 0.741, 26개 중 25개에서 벡터 보간 RGBA 오차가 단순 혼합보다 낮았다. 빠른 검·팔의 가림 경계 왜곡은 남는다. 기존 48fps 실험 입력의 비교이며 새 40클립 전체의 정답 렌더 품질 통과로 확대하지 않는다.
- **자동 검사:** `test_ui_v2_interpolation`, `test_frame_interpolation`, `test_combo_playback`, `test_directional_playback`, `test_ui_v2`, `test_ui_v2_filtering`을 GPU/로컬 벡터 선택 검사까지 포함해 **94개 통과**했다. 동일 원본 프레임 번호의 서로 다른 시점에서 중간 픽셀이 달라지고, 40클립을 순환해도 준비한 GPU 텍스처가 재사용되며 종료 때 해제됨을 확인했다.
- **화면 검증:** 일반 진입점을 실제 OpenGL 창으로 실행했다. 최초 보고의 “시작 자세 40개 알파>20 경계 차이 0px”는 I4에서 검사 오류로 정정했다. Idle·4타의 8방향 중간 이미지와 사선 전체 52프레임 시트를 직접 열어 확인했다. 24fps·약 2.17초 8방향 연계 GIF를 생성했다. 원본 포즈 수정이나 사용자 외관 승인으로 취급하지 않는다.
- **I4 후속 조치:** 투명 RGBA 렌더 타깃에서 재측정하고 `endpoint_alignment_transparent.json`으로 분리했다. 기본 사선 Idle 첫 자세는 검 포함 114×200px, 정면 Idle은 130×196px다. 알파>0과 알파>20에서 두 크기가 각각 같았다. 이는 정면 어깨 너비 128px 설정과 다른 측정 범위다. 비교 메타데이터는 정정했으며 콤보 불일치의 원인 규명·수정은 아직 수행하지 않았다.
- **비용·한계:** 보간 텍스처 추정은 약 202.15MiB, 이번 장치의 시작 준비는 약 3.12초다. 드라이버 메모리·GPU 실행 시간·다수 기체 성능과 구분한다. 전체 프레임 합성이므로 원래 파츠별 가림/실시간 Energy Mask 제어는 미연결이다. 결과·정렬 비교·미리보기는 `output/ui_unit_test_v2/interpolation/`에 보존한다.
