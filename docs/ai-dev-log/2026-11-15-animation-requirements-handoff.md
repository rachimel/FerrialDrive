## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1) — 전투 모션:** 총 인출, 총↔검 스왑, 카운터, 가드, 쓰러짐, 멀티미사일 모델·전개·수납을 제작하고 피드백받는다. **모션을 강하게 과장한다.** 총·검은 모두 오른손으로 사용한다. 무기는 사용하는 손 반대쪽 슬롯에 수납한다.
- **사용자 제안 2 (U2) — 파츠와 재사용:** Head를 별도 파츠로 분리한다. 쓰러짐은 우선 몸·다리에 적용하고 팔을 교체하는 구조를 검토한다. 카운터가 백웨폰과 같은 서브암 슬롯 공간 하나를 차지하는 안을 검토한다. 카운터 슬롯 점유는 기획 제안이며 최종 게임 규칙으로 단정하지 않는다.
- **사용자 제안 3 (U3) — 멀티미사일:** `ref.png`의 포드 형태를 반영하며 선택한 한쪽 백웨폰 슬롯에 하나를 장착한다. 기체 기준 왼쪽·오른쪽 어느 슬롯이든 선택 가능하다. **수납 시 발사구는 Top, 전개 시 정면을 향한다.** 중앙 막대기는 위로 전개하며 회전하지 않는다. 슬롯은 승강을 따르고 **슬롯 탈착부만 90도 회전**, 미사일 포드가 함께 움직인다. 전개 상태에서 Head와 약간 거리를 둔다.
- **사용자 제안 4 (U4) — 프리렌더와 Atlas:** 전개 애니메이션을 수정하고 멀티미사일 장착 상태도 프리렌더한다. 범위 질문에 **이동·공격·가드·쓰러짐 등 기존 모션 전체**를 선택했다. 이어 몸 이미지를 재사용할 수 있는지, 현재 Atlas가 합성된 프레임 단위라는 점을 질문했다. 전체 모션 표현 목표와 몸까지 조합별로 중복 렌더하는 제작 방식의 확정은 구분한다.
- **사용자 제안 5 (U5) — 인계:** 현재 요구사항을 기록하고 다음 세션에서 이어간다.
- U1~U5의 출처는 현재 대화의 요청·명시 응답이며 정확한 발언 시각은 scope 태그 참조. 직접 설명하지 않은 선택 이유를 추가로 확정하지 않는다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1~U3을 제작·검토 범위에 반영했다. 최신 방향은 **수납=Top / 전개=정면**이다. 과거의 중앙 포드·양쪽 동시 포드·옆 방향에서 정면으로 비트는 동작은 최신 요구를 충족한 결과로 사용하지 않는다.
- U4의 전체 모션 범위를 기록했다. 다만 몸 Atlas 공유와 장비별 출력 방식을 검토하기 전에 전체 조합을 다시 렌더하지 않는다. 재사용 구현을 확정하거나 완료한 상태가 아니다.
- U5에 따라 모델·키·렌더 제작을 진행하지 않고 요구사항과 재개 위치만 정리했다. 수용 출처는 현재 AI 답변이며 시각은 scope 태그 참조.

## 3. AI가 제안한 것

- **AI 제안 1 (A1, 초안 분할):** 총 인출/수납, 총→검/검→총, 카운터 인출/회수, 가드 진입/유지/피격/해제, 총/검 쓰러짐의 12개 동작으로 작업 요청을 나눴다. 이는 제작용 분할이며 개별 모션의 최종 품질 승인과 다르다.
- **AI 제안 2 (A2, 표현 후보):** 큰 실루엣·체중 이동·빠른 본동작·강조 정지·늦은 회수로 과장한다. 쓰러짐 팔은 공통 몸통의 시간축·어깨 연결·지면 접촉을 따르게 한다. Head는 목 기준점과 몸통을 따른다.
- **AI 제안 3 (A3, 구조·수치 후보):** 좌우용 포드를 두 번 모델링하지 않고 단일 원본과 장착 위치를 공유한다. 양쪽 슬롯의 전방 기울임 방향은 같다. Head 폭의 약 20%를 수직 여유 초안으로 잡으면 승강량은 모델 좌표 1.04→약 1.302m다. 실척·최종 외관·텔레스코프 스트로크 승인 수치가 아니다.
- **AI 제안 4 (A4, 다음 검토):** 몸과 백웨폰을 별도 출력·저장·재생하는 경로를 작은 동작 하나에서 먼저 확인한다. 몸 자세·방향·프레임이 같은 경우의 공유 범위를 판단하고 가림·장비가 몸에 드리우는 그림자·지면 그림자·보간 벡터를 별도로 다룬다. 분리 시트가 있다는 사실만으로 현재 보간 Atlas의 파츠 재사용이 구현됐다고 판단하지 않는다.
- 이유·근거: 중복 제작·저장을 줄이면서 연결·접촉·가림을 유지하기 위한 후보와 구현상 판단이다. 출처는 앞선 AI 설명·작업 JSON·이번 코드 조회이며 발언 시각은 scope 태그 참조.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 사용자는 모델·모션 초안 제작과 후속 전개 동작 수정을 지시했다. 총·검 오른손과 전체 기존 모션의 장착 프리렌더 범위는 명시 응답이다.
- 최초 6셀 블록아웃에 동작 제작을 허용했으나 이후 레퍼런스 형상·한쪽 장착·수납 방향이 바뀌었다. 최초 응답을 후속 후보 전체의 최종 외관 승인으로 확대하지 않는다.
- A3의 구체적인 간격 수치·최종 외관과 A4의 구현 방식은 별도 최종 확정 전이다. 몸 재사용 질문을 런타임 구조 변경 승인으로 간주하지 않는다.

## 5. 반영 후 발견한 문제

- **I1 — 방향과 제시:** 기존 네이티브 백웨폰 동작은 옛 포드·옆 방향 회전을 사용한다. 새 레퍼런스 포드의 위쪽 장착 후보만 제시했으며 수납·전개 두 상태와 전체 동작을 명확히 제시하지 못했다. 사용자가 반대로 이해했다고 지적했고 후보는 `needs_revision`이다.
- **I2 — Head 간격:** 기존 승강량에서는 전개 포드의 하단 높이가 Head 상단보다 약 0.082 모델 m 낮다. 이는 높이 범위 비교이며 실제 메시 충돌 판정과 다르다. 새 승강량은 계산 후보일 뿐 네이티브 키에 반영되지 않았다.
- **I3 — 몸 이미지 공유:** 현재 보간용 Atlas는 컬러 프레임과 전후방 벡터를 패킹한다. `UniqueFrames`의 중복 제거도 전체 프레임 바이트 단위다. 현재 `PicoAtlasSprite`에는 장비만 교체하며 몸 영역을 공유하는 파츠별 재생 구조가 없다. 기존 백웨폰 검토 `motion/mech.json`도 포드까지 `body` 한 레이어에 포함한다. 합성된 프레임에서 몸만 그대로 분리해 재사용할 수 있다고 보고하지 않는다.
- 제작 도구의 `MechBundle`은 분리 시트를 지원한다. 이 기능과 현재 게임의 보간 Atlas 경로는 구분한다. 기존 몸 프레임에 장비의 가림·그림자가 포함됐으면 장비 없는 공통 몸으로 바로 쓸 수 있는지 추가 검증해야 한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U3: 사용자가 수납 Top·전개 정면, 중앙 막대기 무회전·탈착부만 회전을 정정했다. 작업 계약에 상태별 방향을 기록했다.
- I2 ↔ U3: 사용자가 Head 주변 여유를 요청했다. 정적 Head 29개·포드 22개 메시로 간격을 측정했다.
- I3 ↔ U4: 사용자가 전 조합 렌더에 앞서 몸 재사용과 합성 Atlas 구조를 지적했다. 읽기 전용으로 실제 저장 형식·재생 코드를 확인했으며 구현은 변경하지 않았다. U5에 따라 다음 세션으로 넘긴다.

### 다음 세션 재개 순서

1. **몸 Atlas 공유 범위·재생 구조부터 검토한다.** 기존 모션 전체 프리렌더 목표는 유지하되 몸까지 장비 조합별로 중복 출력하는 방식은 확정하지 않는다. 실제 몸·장비 분리, 가림·그림자·프레임/벡터 기준을 한 동작에서 검증할 범위를 정한다.
2. Unreal에서 **Top 수납→막대기 상승→탈착부 전방 90도→정면 전개**와 역순 수납을 수정한다. 중앙 막대기는 회전하지 않는다. 한쪽 포드·좌우 장착·Head 여유·덮개·스트로크·전 구간 간섭을 확인하고 수납/전개를 같은 카메라에서 명시한다.
3. 검증한 구조로 장착 프리렌더를 기존 모션 전체에 확장한다. 총/검 전환·카운터·가드·쓰러짐의 미완성 네이티브 동작은 별도로 제작·검수한다. 초안 JSON의 존재를 제작·렌더 완료로 취급하지 않는다.
