## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 현재 RPM 확인, 느린 탄속 개선, 총알 텍스처 적용, 연사 증가와 스왑 속도 2배. 근거는 훈련장 직접 사용 후의 탄속·속도감 피드백이다. 발언 출처: `bullet의 projectile speed가 매우 느려` 및 `스왑 스피드는 여기서 2배`.
- **사용자 제안 2 (U2):** 연사를 900 RPM으로 지정했다. 출처: `900 RPM으로 ㄱㄱ`. 구체적인 900 선택 이유는 밝히지 않았다. [[FDLOG_MISSING_REASON:FDLOG-20261117-gun-tempo-dash-aim:U2]] 같은 발언 앞뒤의 연사감 설명에서 보완한다.
- **사용자 제안 3 (U3):** 대시 중 조준 전환이 보이지 않는다고 보고했다. 출처: `그리고 대시할 때는 aim 전환이 없네`.
- **사용자 선택 (U4):** 탄속 후보 질문에서 `5배 · 5,500`을 선택했다. 직접 밝힌 선택 이유는 없다. [[FDLOG_MISSING_REASON:FDLOG-20261117-gun-tempo-dash-aim:U4]] 질문 `bullet_speed`의 선택과 추가 설명에서 보완한다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1~U4를 반영했다. 기본 훈련장의 `weapons.gun`에 연사 1/15초·탄속 5,500, `swap_speed=2`를 설정했다. 기존 도형 1대1 전투의 `CombatConfig` 기본값과 별도 샘플 수치는 유지했다.
- 대시/부스트의 조준 진입·해제 선택을 연결했다. 실제 이동·탄약·명중 규칙과 표현을 분리했다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 탄속을 현재 1,100의 5배인 5,500으로 설정하는 후보를 제시했다. 기존 사거리 900픽셀의 통과 시간이 약 0.16초여서 빠른 탄환과 보이는 이동을 함께 시험하려는 제안이다. 질문 `bullet_speed`에는 3배/10배 후보도 제시했다.
- **구현상 판단:** 추가 제작 이미지 없이 로딩 중 64×16 RGBA 탄두·꼬리 텍스처를 준비하고 종료 시 해제했다. 표시 크기 36×6·색은 `weapons.effects`에 분리했다. 새 3D 동작 제작 없이 기존 조준 진입·해제 클립을 대시/부스트에도 선택한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1은 U4의 명시 선택으로 수용됐다. 나머지 구현상 판단에 대한 별도 최종 외관/사용감 승인은 받지 않았다.

## 5. 반영 후 발견한 문제

- **I1 — 변경 전 사용자 보고:** 탄속과 연사가 기대보다 느리고 총탄이 선으로만 표시됐다. 코드 확인: `shot_interval_seconds=0.085`로 약 705.88 RPM, 탄속 1,100, `draw_gun_effects` 선 표시.
- **I2 — 변경 전 사용자 보고:** 대시 중 조준 전환이 생략됐다. `WeaponAnimation.update`가 정지 이외 상태의 전환을 지우고 `select`가 대시 반복을 전환보다 먼저 선택했다.
- **I3 — 변경 후 AI 자동 검사:** 초기화 없는 표현 테스트에서 새 총탄 렌더러를 호출해 `NoneType` 오류가 발생했다. 실제 렌더러가 준비된 경우에만 그리도록 수정하고 같은 검사군을 다시 실행했다. 최초 시스템 Python에는 Pico2D가 없어 프로젝트 전용 환경으로 재검증했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1/U2/U4: 900 RPM·탄속 5배·텍스처·스왑 2배를 적용했다. 연사/탄속은 훈련장 설정, 스왑 배율은 무기 모션 시간과 실제 재생 속도 양쪽에 적용했다. 일반 2배·Overdrive 합성 4배이며 조준/이동 전체에 스왑 배율을 적용하지 않는다.
- I2 ↔ U3: 대시·부스트 중 기존 조준 진입/해제 모션을 재생하고 반복으로 복귀하도록 수정했다. 전환 중 이동과 사격은 유지한다.
