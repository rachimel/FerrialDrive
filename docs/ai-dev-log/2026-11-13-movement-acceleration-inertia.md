# 일반 이동의 SmoothStep 가감속과 키 해제 관성

- **기록 ID:** `FDLOG-20261113-movement-acceleration-inertia`
- 작성·현재 확인: **2026-11-13 14:14 KST**. 대화 범위: `대시 가속도 SmoothStep으로` → 가속 시간 0.2초 선택 → 일반 이동 전환으로 확대 → `아 달리기` 정정 → `이동 키를 놓으면 관성 정도는 넣자`. 개별 발언의 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261113-movement-acceleration-inertia:scope]] 해당 구절로 현재 대화를 검색한다.
- 근거: 현재 대화, [검 이동 명세](../unit-tests/sword_movement.md), 현행 이동/공격 코드, 자동 검사와 로컬 `output/movement_acceleration/report.json`·캡처.
- 상태: 일반 이동 가감속/관성 구현·자동 검사·실제 OpenGL 사전 지정 입력 확인. 사용자 실제 키보드 사용감·새 제동 모션 외관 승인·커밋·업로드는 미수행이다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 일반 대시에도 SmoothStep 가속을 요청하고 가속 시간은 질문에 **0.2초**를 선택했다. 정지 시 0→100m/s·달리던 중 50→100m/s라는 질문의 기준을 따른다. 세부 감각상의 이유는 미제시다. [[FDLOG_MISSING_REASON:FDLOG-20261113-movement-acceleration-inertia:U1]] 검색 단서는 `대시 가속도 SmoothStep으로`이며 시각은 scope 참조.
- **사용자 제안 2 (U2):** 달리기/Idle/대시 전환에도 가속을 요청했다. 걷기라는 표현을 `아 달리기`로 정정했으며 별도 걷기 모드 추가로 해석하지 않는다. 관련 속도 전환을 같은 계열로 연결하라는 요구이며 시각은 scope 참조.
- **사용자 제안 3 (U3):** 이동 키를 놓으면 관성을 넣도록 요청했다. 앞선 즉시 정지 규칙을 대체하는 최신 요구다. 감속 시간·세부 관성 길이는 사용자가 직접 지정하지 않았고 시각은 scope 참조.

## 2. 사용자 제안 중 AI가 수용한 것

- U1·U2: idle→달리기·idle→대시·달리기↔대시는 현재 속도에서 새 목표까지 0.2초 SmoothStep으로 가감속한다. 목표 50/100m/s와 입력 방향 규칙은 유지한다.
- U3: 키 해제 후 마지막 방향으로 감속해 정지한다. 감속 도중 새 입력은 즉시 방향/목표를 갱신한다. 최고 속도에서 놓으면 달리기 약 5m·대시 약 10m를 더 이동한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 대시 가속 시간 0.2/0.12/0.3초를 질문했고 0.2초를 추천했다. 사용자가 가속 시간을 결정할 수 있도록 한 제안이며 시각은 scope 참조.
- **구현상 판단:** 일반 이동 전환과 관성 감속도 같은 `movement_acceleration_seconds=0.2`를 사용한다. 관성 요청 뒤 AI가 이 기준을 설명했으며 사용자의 별도 감속 시간 지정으로 간주하지 않는다.
- **구현상 판단:** 프레임 평균 이동량과 프레임 끝의 순간 속도를 분리한다. 속도 곡선을 구간 적분해 이동하고 다음 전환은 순간 속도에서 시작한다. 달리기 반복 재생과 블러 노출은 가감속한 실제 속도를 따른다.
- **구현상 판단:** 공격의 자동 전진/연계 대기와 부스트 30m/0.2초는 일반 이동 관성에 합치지 않는다. 새 걷기 상태나 전용 제동 에셋은 만들지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1의 **0.2초**를 명시 선택했다. 더 짧거나 긴 가속 시간은 채택하지 않았다.
- 관성 자체는 U3의 직접 요청이며 AI 제안으로 바꾸지 않는다. 감속에 같은 0.2초를 쓰는 세부 구현과 최종 사용감은 별도 승인으로 기록하지 않는다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1):** 기존 공격 이동 인터페이스는 구간 평균 속도만 전달했다. 이를 일반 이동 가속의 시작 속도로 재사용하면 프레임 분할에 따라 시작값이 달라질 수 있음을 코드에서 확인했다. 평균 속도와 종료 순간 속도의 구분이 필요했다.
- 기존 자동 검사는 기본 이동을 즉시 50/100m/s로 시작하고 키 해제 즉시 정지한다고 가정했다. 이 기대값은 최신 요구와 달라 갱신했으며 이전 구현의 버그로 분류하지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U3에 따라 구현 중 유지하려던 즉시 정지 방침을 관성 감속으로 바꿨다. 현재 기준 문서·샘플에서 즉시 정지 설명도 교체했다. 모션 전환 0.12초와 위치 가감속 0.2초는 별도로 기록한다.
- I1의 기술적 해결안은 사용자 제안으로 확인하지 않았으며 다음 절에 AI 조치를 기록한다.

## 7. AI 해결 제안과 실제 해결 과정

- `LocomotionController`가 목표/시작/종료 속도와 경과 시간을 관리한다. 방향만 바꿀 때 같은 목표 속도의 가속을 다시 시작하지 않는다. 감속 중에는 기존 이동 상태와 방향으로 이동하고 종료 후 Idle로 전환한다.
- I1: 공격은 구간 평균 속도로 거리를 계산하면서 종료 순간 속도를 별도 전달한다. 일반 이동 복귀는 이 속도에서 시작한다. 공격 연결 대기의 정지와 부스트 종료 뒤 잔여 시간 이동은 기존 동작을 유지한다.
- `samples/sword_movement/acceleration_input.json`으로 idle→달리기→대시→달리기→관성 정지·idle→대시·감속 중 방향 변경·부스트 복귀를 재현한다. 캡처가 있으므로 `--report`와 함께 실행한다.
- **자동 검사 110개 통과:** 이동/공격 45개·UI v2 54개·게임 설정 7개·콤보 4개. 30/60/144fps의 가속/정지 거리, 1/30/60/144fps의 달리기→대시→달리기→관성 정지 전체 거리 200m를 확인했다. 최고 속도·대각선 정규화·부스트 거리·공격 방향 고정/전진도 검사했다.
- **실제 OpenGL 155프레임 사전 지정 입력:** 달리기는 0.1초에 25m/s·0.2초에 50m/s, 대시 전환은 0.1초에 75m/s·0.2초에 100m/s였다. 대시→달리기는 같은 시간 동안 100→50m/s, 키 해제는 0.2초에 0m/s로 끝났다. 부스트는 150m/s였고 이후 일반 이동 복귀도 확인했다.
- 보고서의 `speed_mps`는 해당 프레임 평균, `movement_speed_mps`는 종료 순간 속도다. 감속 마지막 프레임에는 이동량이 남아 평균 속도가 0보다 클 수 있다. 다음 프레임 이후는 완전히 정지한다. 관성 중 캡처를 직접 열어 본체·바닥·그림자·HUD 표시를 확인했다. 물리 키보드 사용감과 사용자 승인으로 확대하지 않는다.
