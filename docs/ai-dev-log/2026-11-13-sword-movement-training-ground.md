# 검 이동 테스트·1km 훈련장과 흙 텍스처 준비

- **기록 ID:** `FDLOG-20261113-sword-movement-training-ground`
- 기록 시각: 2026-11-13 02:48 KST. 사용자 발언 시각과 구분한다.
- 후속 정리: 2026-11-13 02:51 KST. 눈금 채택과 검 달리기 방향의 명시 응답을 반영한다.
- **현재 상태:** 독립 검 이동 테스트·1km 맵·거리 눈금·8방향 기체·프레임별 그림자 연결 완료. 흙 반복 간격은 10m다. 최종 OpenGL 입력 240프레임과 8방향 241프레임을 확인하고 실제 창에서 H 그림자 표시 전환을 확인했다. 사용자가 직접 조작하겠다고 하여 입력 제어를 넘겼다. 본편 게임 연결·사용자 사용감 승인은 별도다.
- 개별 발언의 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261113-sword-movement-training-ground:scope]] 현재 대화의 `검을 가지고 이동 테스트`, `훈련용맵은 가로 세로 1km`를 검색한다.

## 1. 사용자가 제안한 것

- **U1:** 검을 가지고 이동 테스트를 만들 수 있을 것 같다고 제안했다. 출처는 현재 대화다. 준비도 판단과 후속 작업 방향으로 다루며 완성 코드 작성 요청으로 확대하지 않는다.
- **U2:** 인터넷에서 적당한 흙 텍스처를 가져오고, 훈련용 맵을 가로·세로 1km로 시험하자고 제안했다. 출처는 현재 대화다. 정확히 1km를 고른 개별 이유는 미확인이다. [[FDLOG_MISSING_REASON:FDLOG-20261113-sword-movement-training-ground:U2]] 같은 발언 전후의 맵 크기 논의를 확인한다.
- **U3:** `일단 눈금 표시하고, 후진이랑 측면 달리기는 필요없을거 같음`이라고 요청했다. 범위 확인 질문에 `달릴 때 몸을 이동 방향으로 돌려 전진 모션 사용`을 명시적으로 선택했다. 출처는 현재 대화와 질문 응답이다. 이번 검 이동 테스트의 기본 달리기에 적용하며 총의 이동 중 사격 규칙이나 대시·부스트 방향 규칙의 변경으로 확대하지 않는다.
- **U4:** `실제로 검 들고 이동할 수 있게 테스트 만들어줘`로 구현을 명시적으로 요청했다. 현재 대화가 출처이며 기존 코드 작성 보류를 해제한 요청이다.
- **U5:** 방향이 어색하면 다리만 분리하는 안도 검토하자고 제안했다. 전신 회전 결과의 문제 여부를 먼저 확인하는 조건부 후보이며 현재 분리 구현의 지시로 확대하지 않는다.
- **U6:** 화면의 그림자 누락을 지적하고 기존 에셋 로더의 그림자 불러오기 기능을 상기시켰다. 신규 그림자 규칙 제안이 아니라 기존 기능의 연결 누락 지적이다.
- **U7:** 바닥 반복이 두드러진다고 지적하고 원본 해상도를 물었다. AI는 실제 원본이 1024×1024px임을 답했다. 이후 `일단 sparse 하게하고 추후에 맵 만들 때 생각해보자`로 성긴 반복과 지면 세부 작업 보류를 지시했다.

## 2. 사용자 제안 중 AI가 수용한 것

- U2의 흙 텍스처 확보를 수행했다. 1,000m × 1,000m는 훈련장 시험 크기로 적절하다고 평가했으며 최종 게임 맵 규격으로 확정하지 않았다.
- U3의 눈금 표시와 검 달리기 중 이동 방향 전신 회전을 수용했다. 후진·측면 달리기 전용 모션은 이번 제작 요구에서 제외했다. PRE-PRD·기본 무기 애니메이션 사양·현재 검 이동 안내에 반영했다.
- U4로 독립 실행 테스트와 본편 재사용 모듈을 구현했다. U5는 조건부 후보로 남겼으며 U6은 기존 그림자 패스·파츠 합성 경로 복원으로 대응한다. U7에 따라 원본은 보존하고 반복 간격만 2m→10m로 조정했다.

## 3. AI가 제안한 것

- **A1, 구현상 판단:** Poly Haven의 `Dirt`(Charlotte Baglioni, CC0)에서 1K Diffuse PNG를 선택했다. 검 이동을 관찰할 단순한 바닥 후보이며 색상 원본만 확보했다. 출처는 <https://polyhaven.com/a/dirt>, 사용 조건은 <https://polyhaven.com/license>다.
- **A2:** 바닥은 작은 텍스처를 반복하고 화면에 보이는 범위만 그리는 구성을 제안했다. 현행 PRE-PRD의 전폭 5m와 정면 어깨 너비 128px 기준을 연결하면 25.6px/m이며, 맵 한 변은 25,600px에 해당한다. 이는 해당 표시 배율에서의 환산이며 카메라 확대·바닥 투영에 따른 화면 크기를 고정하지 않는다.
- **A3:** 이동 속도와 거리를 읽기 쉽도록 거리 눈금을 제안했고 사용자가 U3으로 표시를 요청했다. 간격은 10m, 100m마다 강조하는 시험안을 후속으로 제시했다. 이 간격의 별도 사용자 승인은 아직 받지 않았다.
- **A4, 구현상 판단:** 기존 Pico2D 런타임·카메라·파츠 로더와 Unreal v03/r02 모션을 재사용했다. 거리 계산·모션 상태·바닥 표현·입력 연결을 분리했다. 달리기 12.22m/s·대시 22.5m/s·부스트 12m/0.2초·전환 0.12초·경계 반경 2.5m는 시험용 값이며 본편 확정값이 아니다.
- **A5, 구현상 판단:** 전신 메시를 기존 재질·골격·키 그대로 8방향 출력해 16개 동작/128개 클립/704프레임을 기존 `unreal.import`로 패킹했다. 시트 제한 때문에 묶음을 나누었다. 새 공통 `unreal-directional` 경로를 사용하며 버전 전용 Python 파일은 만들지 않았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1의 구체적인 텍스처 선택과 A2의 구현 방식에 대한 별도 사용자 수용은 아직 확인하지 않았다. 텍스처를 가져오라는 U2의 요청 범위에서 후보를 준비했다.
- A3의 눈금 표시 자체는 U3으로 수용했다. 10m/100m 간격은 AI의 시험안과 구분한다.
- U4는 앞서 정리한 독립 이동 테스트의 구현 요청이며 시험용 세부 수치·전신 회전 사용감·새 렌더의 품질 승인을 뜻하지 않는다.

## 5. 반영 후 발견한 문제

- 다운로드 원본은 열렸고 공식 MD5와 일치했다. 타일 반복 이음새·게임 배율의 가독성·실제 렌더 성능은 미검증이다.
- 기존 이동 편집 안내는 전진 초안 15개를 선택하며 게임의 8방향 이동 입력·후진/측면 달리기·상하체 독립 조합을 미연결로 명시했다. U3 반영 후 검 후진·측면 전용 달리기는 제작 요구에서 제외한다. 게임 입력·방향별 출력·상하체 독립 조합은 여전히 미연결이며 이번에 동작을 재검증하지 않았다.
- **I1:** 초기 전신 출력의 전체 프레임을 단일 시트에 패킹하면 기존 최대 시트 크기를 넘었다. 파츠 로더와 상한을 유지하고 여러 번들로 나누었다.
- **I2:** 초기 전신 카탈로그에 지면 그림자 레이어가 빠졌고 사용자가 U6으로 지적했다. AI가 누락을 인정했다. 기존 그림자 기능이 없었던 것으로 설명하지 않는다.
- **I3:** 원본 폭 2m를 그대로 반복해 한 타일이 화면 약 51×16px가 되면서 반복무늬가 두드러졌다. U7에 따라 10m 간격(약 256×82px)으로 넓혔다. 원본 해상도와 표시 반복 간격은 구분한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U3으로 눈금을 채택하고 후진·측면 전용 달리기를 생략했다. 방향 확인 응답을 바탕으로 검 기본 달리기의 몸 방향을 이동 방향으로 명시했다. 실제 입력·렌더링 연결은 아직 수행하지 않았다.
- U4 이후 독립 테스트의 실제 입력·렌더링 연결을 구현했다. U6은 I2의 기존 그림자 경로 복원을, U7은 I3의 성긴 반복과 지면 표현 보류를 지시했다. U5의 다리 분리는 방향 전환 결과를 확인한 뒤 검토한다.

## 7. AI 해결 제안과 실제 해결 과정

- 원본은 `data/images/textures/polyhaven/dirt/dirt_diff_1k.png`, 출처·라이선스·원본 범위·검증 해시는 같은 폴더의 `source.json`에 보존했다.
- 파일 크기는 5,504,678바이트, MD5는 `033b3aaa80b816a1a53ed211d69a3328`이다. 공식 API의 값과 대조했으며 이미지를 직접 열어 흙 바닥 후보로 확인했다. `git check-ignore`로 원본의 공개 제외 상태를 확인했다.
- 실제 맵 생성·충돌 경계·카메라 연결·이동 입력·모션 연결·직접 조작 검증·커밋·업로드는 수행하지 않았다.
- 위 미수행 상태는 최초 준비 시점의 기록이다. U4 이후 `tests/sword_movement_test.py`·`ferrial_drive/combat/locomotion.py`·`training_ground.py`·`movement_application.py`와 샘플 설정을 추가했다. Runner의 소스 비실행 `standalone` 판별과 import 시 창 미생성, 게임 에셋 없는 기본 도형 실행을 확인했다.
- 이동 검사 19개 통과: 30/60/144Hz 거리 일치·대각선 정규화·즉시 정지·부스트 방향/거리 유지·종료 잔여 시간·경계·좌우 Shift 독립·포커스 해제·일시정지·모션 전환·그림자 누락 카탈로그 거부·지정 입력의 조준 보존·자원 정리를 확인했다. 공통 런타임은 9개 중 8개 통과/1개 선택 조건 생략, 기존 파츠 가져오기 14개 통과다. 이미지 패킹 검사는 기본 환경의 Pillow 누락과 임시 폴더 접근 제한 후 기존 이미지 런타임을 지정한 정상 환경에서 재실행했다.
- 최초 실제 OpenGL 사전 입력 240프레임에서 달리기·대시·부스트·정지·일시정지·복귀를 확인했다. 당시 흙 반복은 2m·그림자는 누락된 상태였다. 해당 CPU 그리기 평균 약 7.48ms를 최종 수정 결과의 성능으로 쓰지 않는다. GPU 시간·지속 키 직접 조작·사용자 사용감 승인과 구분한다.
- I2의 수정은 기존 `shadow_reference_only`·`shadow_pass.py`·파츠 로더를 사용한다. 같은 포즈·카메라·광원의 무그림자 기준과 비교해 프레임별 검정 RGBA 그림자를 만들고 바닥→그림자→본체 순서로 합성한다. H 표시 전환과 기본 그림자 알파 0.5를 연결한다.
- 그림자 후처리에서 전체 픽셀 순회가 길어져 실제 처리 시간을 확인한 뒤 공통 변환을 개선했다. 전체 알파·중성색·최저 밝기 검사를 유지하며 RGB 차이가 있는 영역만 비율 계산한다. 기존 출력과 픽셀 일치, 관련 검사 6개 통과를 확인했다.
- 기존 작업 트리에 이 작업 전부터 있던 다수의 변경과 미추적 공통 구현이 있어 일괄 커밋·업로드하지 않았다. AI 기체·시트·렌더와 로컬 제작 입력은 공개 제외 경로에 보존한다.
- **최종 확인(2026-11-13 03:29~03:32 KST):** 그림자 포함 128클립/704프레임의 모든 그림자가 비어 있지 않고 최대 알파는 206이었다. 그림자 보정 전 기록한 원본 AnimSequence 16개 해시가 같았다. 대표 4개 색상 프레임은 그림자 추가 전후 RGBA 픽셀이 같았다.
- 실제 에셋은 `data/catalog/prerender/player_sword_locomotion_8dir_shadow/catalog.json`의 8개 번들이며 본체/그림자를 기존 로더로 불러온다. 최종 사전 입력 240프레임과 8방향 241프레임을 OpenGL에서 완료했고, 8방향 이동 후 위치는 중앙 (500m, 500m)으로 돌아왔다. 실제 창에서 H를 눌러 그림자 숨김/복원을 확인한 뒤 표시를 켜두었다.
- 최종 8방향 실행의 CPU 그리기 평균은 약 2.65ms, 텍스처 크기 합계 추정은 약 801.33MiB다. GPU 시간·실제 VRAM 피크·다중 기체 성능을 뜻하지 않는다. 검토 이미지는 `output/sword_movement_20261113/movement_shadow.png`, `running_shadow.png`이며 보고는 `native_shadow_report.json`, `directions_report.json`, `shadow_summary.json`이다.
- 직접 지속 키 조작과 사용감·전신 회전 자연스러움·연속 지형 접지는 사용자 확인 전이다. 사용자의 `그러면 내가 할게` 이후 UI 입력은 중단하고 창을 그대로 인계했다. 포커스 해제 자동 일시정지는 창 선택 후 Esc로 해제한다. 다리 분리는 아직 조건부 검토 후보다.
