# 스캔라인과 부드러운 에너지 띠 합성

**기록 ID** `FDLOG-20261123-scanline-energy-band`

**기록일** 2026-11-23 KST

## 1. 사용자가 제안한 것

- **U1** 기본 줄무늬를 재사용하고 부드러운 에너지 띠를 패널에 합성하도록 요청했다. 무기 카드의 `hud.draw.panel_scanlines` 비용을 기준으로 검토했다. 정확한 시각 [[FDLOG_MISSING_TIME:FDLOG-20261123-scanline-energy-band:U1]]은 이번 대화의 `일단 그렇게 구현해줘` 발언으로 찾는다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 기존 줄무늬를 유지하고 부드러운 띠를 같은 패널 외곽 안에서 합성했다. 띠가 패널 사이 빈 Y 구간을 건너뛰는 동작과 글자·아이콘 앞뒤 순서를 유지했다.

## 3. AI가 제안한 것

- **구현상 판단** 줄무늬와 코사인 알파 띠를 같은 캐시 텍스처의 두 열로 두었다. 띠는 샘플 위치만 이동하고 기존 배치에 연속으로 제출한다. 같은 패널의 화면 변환을 한 번 조회하고 띠를 두 도형으로 나누는 연산을 제거했다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 부드러운 띠의 외관은 사용자 확인 대기다.

## 5. 반영 후 발견한 문제

- 최종 자동 검사와 화면 캡처에서 패널 외곽 누출 또는 줄무늬 차이는 확인되지 않았다. 띠 내부 밝기는 연속 형태로 바뀐다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** HUD 배경에서 부드러운 밝기 띠를 패널 안으로 제한했다. OpenGL 실제 HUD에서 띠가 이름·수치 뒤에 합성되는 것을 확인했다.

## 7. AI 해결 제안과 실제 해결 과정

- Intel Graphics·직접 OpenGL·FHD·보통·180기 시작·자동 대시와 사격 240프레임 상세 계측에서 `hud.draw.panel_scanlines` 평균 포함 시간은 1.043→0.730ms, 무기 카드 하위는 0.569→0.426ms였다. 프레임당 `scanline_layer` 호출은 21.50→10.77회, 줄무늬 관련 GL 도형 제출은 10.77회로 같았다. 전체 교전의 프레임 분포는 단일 전후 실행이며 개선을 확정하지 않는다.
- 직접 OpenGL의 띠 비활성 줄무늬 RGB는 일치했다. SDL 소프트웨어에서 부드러운 띠의 연속 밝기·사선 패널 클립·배율·캐시를 검사했다. UI v2와 HUD 배치 자동 검사 167개가 통과했고 선택 검사 3개를 건너뛰었다. 전후 캡처와 Flamegraph는 `output/scanline_energy_band/`에 저장했다. 직접 조작은 미검증이다.
