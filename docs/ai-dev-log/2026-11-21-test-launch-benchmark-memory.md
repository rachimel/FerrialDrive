# 독립 테스트 실행 복구와 벤치마크 메모리 표시

- 기록 ID `FDLOG-20261121-test-launch-benchmark-memory`
- 이 대화의 사용자 요청 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261121-test-launch-benchmark-memory:U1-U2]]` 검색 단서는 `오류나는 테스트들`, `메모리 사용량도 제목에서`다.

## 1. 사용자가 제안한 것

- **U1** 오류가 나는 테스트를 실행할 수 있게 복구해 달라고 했다.
- **U2** Hardware Benchmark의 창 제목에 메모리 사용량을 표시해 달라고 했다.

## 2. 사용자 제안 중 AI가 수용한 것

- 자동 검사와 Runner 규약의 독립 실행을 따로 재현했다. Benchmark 제목에 RAM Working Set과 GPU 메모리 표본을 추가했다.

## 3. AI가 제안한 것

- **A1 · 구현상 판단** 현재 Python 환경의 패키지를 우선 사용한다. 로컬 Python 3.11용 패키지의 우선순위가 높으면 다른 Python에서 실행할 때 Pillow·NumPy 확장 import가 실패했다.
- **A2 · 구현상 판단** Benchmark 기본 환경에서는 실제 GPU 기능으로 PBR을 실행한다. 기존 제한은 프래그먼트 텍스처 16단위이며 현행 PBR은 26단위를 요구한다. 창 제목은 최근 표본을 재사용하고 WDDM 전용·공유 카운터 또는 DXGI 로컬 값을 표시한다.
- **A3 · 구현상 판단** 압축 테스트의 기본 비교 묶음이 없으면 실행마다 도형의 기존·공유 RGBA 비교 묶음을 만들어 열린다. 로컬 KTX2·Oodle 도구가 없어도 기본 도형을 볼 수 있다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1~A3은 U1~U2를 반영하는 구현 선택이다. 별도 사용자 확인은 없었다.

## 5. 반영 후 발견한 문제

- **I1** 초기 자동 검사는 Pillow·NumPy의 바이너리 확장 import가 연쇄 실패했다.
- **I2** 초기 독립 실행에서 Hardware Benchmark의 Movement·Combat은 GPU 단위 제한, 텍스처 압축은 기본 비교 묶음 부재로 종료됐다.
- **I3** OpenGL 검사를 모두 켜자 에셋 테스트의 전역 SDL dummy 설정이 다른 검사로 새었다. 검 Trail 테스트는 제거된 컴파일 메서드를 참조했고, 설정 저장 검사는 이전 그림자 해상도를 기대했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1·U2** 오류 재현 뒤 테스트 입력과 Benchmark 기본 옵션을 조정했다. 자동·직접 조작 제목에서 메모리와 HUD·월드 시간을 함께 표시했다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1** Python 3.13 프로젝트 환경에서 자동 검사 1,151개를 실행했다. 기본 실행은 1,075개 통과, 76개 선택 검사 제외였다.
- **I2** Runner와 같은 별도 프로세스에서 독립 테스트 파일 11개가 정상 실행됐다. Hardware Benchmark의 Movement·Combat 직접 조작과 Movement 자동 측정에서 실제 창 제목을 수집해 RAM·GPU 표본이 갱신됨을 확인했다.
- **I3** SDL 설정을 해당 테스트 수명으로 제한하고 검 Trail 컴파일 검사와 PBR 그림자 기준을 현행 경로에 맞췄다. OpenGL 선택 검사를 켠 자동 검사 1,151개에서 1,146개 통과·조건부 제외 5개를 확인했다. 별도 렌더링 검사 30개도 통과했다.
