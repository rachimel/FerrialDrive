# 600기 그리기의 CPU·GPU 비용 분리

**기록 ID** `FDLOG-20261122-render-cpu-gl-boundaries`

2026-11-22 KST 작성. RTX 5070 Laptop GPU, FHD, 중간 PBR, 자동 SMG, 적 600기·12m 간격·무음 조건이다.

## 1. 사용자가 제안한 것

- **U1** 원거리 SDL 제출을 90% 넘게 줄인 효과가 0.58ms에 그친 이유를 확인한다. CPU 준비·제출·대기와 GPU 패스를 분리해서 다음 작업 순서를 결정한다. 요청의 정확한 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261122-render-cpu-gl-boundaries:U1]]이다. 검색 단서는 이 대화의 `CPU 준비·제출·대기랑 GPU 패스 시간을 분리`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 기존 600기 시나리오에서 일반 측정, CPU 범위·네이티브 API 계측, GPU 타임스탬프, 강제 완료 대기를 나눠 실행했다. CPU 상위 후보인 적 공격 표시의 도형 경로는 같은 시뮬레이션 프레임에서 기존 두 백엔드를 대조했다.

## 3. AI가 제안한 것

- **A1** SDL의 명령 쌓기, 렌더 타깃·상태 경계, GL 상태 조회·GL draw 호출을 따로 기록한다. API 바깥 시간은 Python/준비/미계측 호출·계측 오버헤드를 포함하는 잔여 시간으로 표기한다.
- **A2** GPU 타임스탬프 실행에만 SDL 패스별 flush를 넣고 결과는 실행이 끝난 뒤 회수한다. 별도 실행에서 제출 직후 `glFinish`를 걸어 강제 완료 대기를 측정한다.
- **A3** 도형 제출을 기존 SDL 배치로 바꾼 진단 비교와 호출 위치의 실측을 근거로, 반복 상태 저장·복구의 우선순위를 정한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 사용자가 확정한 범위는 비용 분리와 다음 작업 우선순위 확인이다. 계측 경계, 대조 백엔드와 개선 후보 순서는 구현상 판단이다.

## 5. 반영 후 발견한 문제

- **I1** 한 번의 SDL 제출이 반드시 지배적인 실행 비용이라는 가설이 맞지 않았다. 원거리와 근거리 본체의 최종 합성 GPU 시간은 작았고, 자주 분리된 공격 표시 도형·근거리 PBR·근거리 그림자 타일에서 CPU 상태 조회가 반복됐다.
- **I2** 일반 교전의 회차별 그리기 벽시계 시간이 크게 달랐다. 상세 추적 실행의 절대값을 기본 실행의 FPS로 환산하거나, GPU 경과 시간을 CPU 시간에 그대로 합산할 수 없다.
- **I3** 기존 SDL 도형 배치 경로는 픽셀 대조가 같았으나 현재 인스턴싱보다 느렸다. 네온 글로우와 필터 폴리곤의 반복 생성은 HUD에서 별도 비용으로 확인했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 표준 하드웨어 벤치마크의 일반 240프레임과 각 진단 실행의 160프레임을 따로 보관했다. 동일 프레임 도형 비교는 120프레임이며 앞선 GPU 작업을 완료한 뒤 제출을 재고 실행 순서를 교대했다.

## 7. AI 해결 제안과 실제 해결 과정

### CPU와 대기 결과

- 표준 실행 프레임 작업 평균 43.56ms, 그리기 제출을 포함한 CPU 경과 평균 36.03ms. 별도 일반 재생 두 차례의 그리기 벽시계는 39.57/27.12ms, 렌더 스레드 CPU 시간은 36.52/26.47ms였다.
- 상세 CPU 그리기 평균 45.70ms 중 잡은 API 진입∼복귀 시간은 총 15.84ms였다. GL 상태 조회 8.84ms(약 847회, 그중 `glGetIntegerv` 7.66ms), SDL 상태·flush 경계 1.69ms, SDL 그리기 요청 1.26ms, GL draw 호출 0.07ms다. GL 상태 변경 2.41ms, SDL 텍스처·문자 준비 0.89ms, SDL 조회·기타 0.60ms, GL 업로드 0.08ms도 포함된다. 나머지 29.86ms는 Python 준비·미계측 호출·계측비를 합한 잔여다.
- 직접 재어 본 준비 중 컬링 0.71ms, HUD 패널 배치 조사 1.00ms, HUD 글로우 마스크 신규 생성 1.41ms, 필터 텍스처 신규 생성 1.46ms였다. 글로우 신규 생성은 프레임당 약 0.14회로, 호출당 평균 약 9.8ms에 해당한다.
- 일반 재생의 프레임 말단 SDL flush 평균은 약 0.001~0.002ms, `present` 평균은 0.07~0.39ms였다. 별도의 `glFinish` 강제 완료 대기는 평균 4.38ms·P95 9.67ms였다. GL 상태 조회 시간은 드라이버 복귀까지의 경과이며, 그 안의 암묵적 동기화와 CPU 실행을 별도 분해한 값은 아니다.

### GPU 타임스탬프 구간

| 패스 | 평균 ms | P95 ms |
| --- | ---: | ---: |
| 프레임 전체 | 5.30 | 13.33 |
| 적 전체 | 2.65 | 5.02 |
| 근거리 본체 PBR 시트 | 1.63 | 3.71 |
| 근거리 그림자 | 0.66 | 0.64 |
| 적 본체 최종 합성·공격 표시 | 0.24 | 0.67 |
| 원거리 그림자 | 0.05 | 0.13 |
| 플레이어 파츠 그리기 | 0.95 | 2.66 |

타임스탬프는 명령이 GPU에 도달해 완료되는 구간으로 패스 내부 유휴 시간을 포함할 수 있다. 평균과 P95는 꼬리 스파이크 때문에 순서가 뒤집힐 수 있다. 상위 패스와 그 안의 하위 패스는 합산하지 않는다. [OpenGL 4.6 명세 4.3절](https://registry.khronos.org/OpenGL/specs/gl/glspec46.core.withchanges.pdf)

### 호출 위치와 개선 우선순위

1. 현재 제일 큰 반복 호출 위치는 `PrimitiveBatch.flush` → `PrimitiveInstances.render` → `SdlOpenGLPass.batch`다. 제출 약 15.6회/프레임에서 상태 조회 3.11ms, 그중 공통 배치의 정수 상태 조회 약 171.5회/프레임에서 2.48ms였다. 120프레임의 기존 SDL 도형 경로 대조에서 캡처 8쌍이 픽셀 일치했으나 적 그리기 평균은 기존 인스턴싱 9.12ms, 기존 SDL 배치 12.22ms였다. 현재 인스턴싱을 유지하면서 가림 순서를 유지할 수 있는 제출 경계의 상태 관리 비용을 줄이는 후보로 남긴다.
2. 첫 코드 변경 후보는 근거리 그림자 타일이다. `PartShadowMap.depth_pass`가 타일마다 상태를 저장·복구했고, 약 11.2회/프레임의 조회 비용은 1.74ms였다. 타일 갱신을 기다리는 텍스처/포즈 준비를 먼저 끝내고, 같은 깊이 아틀라스에 쓰는 연속 타일을 한 패스에서 처리하는 방식이 독립 검증에 적합하다.
3. `bind_atlas_textures`의 근거리 PBR 바인딩 조회는 약 112회/프레임, 1.48ms였다. 그리기 그룹의 소유권이 명확한 범위에서 원래 바인딩 캡처·복원을 재사용하는 후보가 있다. HUD는 화면 전체 배치보다 실측된 신규 글로우·필터 텍스처 생성이 우선 후보다.

실행 및 원자료는 로컬 `output/performance/crowd_render_breakdown/`의 `fresh_reference/report.json`, `render_sections.py`, `sections.json`, `render_callsites.py`, `sections_callsites.json`, `draw_hotspots.txt`, `primitive_backend_diagnostic.json`에 있다. 분석은 RTX 5070 Laptop에서 측정했고 UHD 630 실기는 미측정 상태다.
