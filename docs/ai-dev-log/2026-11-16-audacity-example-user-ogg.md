# Audacity 예시 인계와 사용자 OGG 피격음 채택

- **기록 ID:** `FDLOG-20261116-audacity-example-user-ogg`
- 대화 범위: 2026-11-16 현재 대화. 개별 요청 시각은 확인하지 않았다. [[FDLOG_MISSING_TIME:FDLOG-20261116-audacity-example-user-ogg:scope]] 검색 단서: `예시 타이밍이랑 음량대로`, `metal-hit-1.ogg`, `써`, `아 일단 했어`.
- 예시 파형 인계 검증: 2026-11-16 21:35:19 KST. 최종 OGG 검증: **2026-11-16 21:41:50 KST**. 발언 시각과 구분한다.
- 현재 상태: **사용자가 출력한 `data/audio/hit-metal-1.ogg`를 금속 피격 완성본으로 연결**했다. 원본 직접 적재·추가 가공 없음, 재생 gain 0.8·공통 master 0.4다. 게임 창 재시작 후 직접 조작·스피커 청감은 미검증이다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 자신이 만든 Audacity 예시의 타이밍·음량을 게임에 반영하도록 요청했다. 출처는 현재 대화의 명시적 반영 요청이다.
- **사용자 제안 2 (U2):** 금속이 칼로 찢기는 느낌의 소리를 찾도록 요청한 뒤 `ㄱㄷ`로 대기를 요청했다. 탐색을 멈췄으며 새 음원을 게임에 추가하지 않았다.
- **사용자 제안 3 (U3):** 합쳐진 MP3와 레이어를 유지한 프로젝트 저장을 언급한 뒤 직접 완료했다고 정정하고 자신의 OGG를 사용하도록 요청했다. 실제 파일명은 `hit-metal-1.ogg`였다. 별도 MP3를 출력하거나 프로젝트를 덮어쓰지 않았다.
- 개별 시각·출처 검색 단서는 머리말을 따른다. U1·U3의 구체적인 파일 사용 방식 이외의 추가 배경은 제시되지 않았다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1: 5개 트랙의 저장된 PCM·네이티브 샘플레이트·스테레오·게인·배치를 추출해 연결했다. 최종 채택 상태와 구분하는 중간 결과다.
- U3: 이후 금속 명중을 완성 OGG 한 파일로 대체했다. 기본 sword hit·thud를 중복 재생하지 않는다. 비금속 표적은 기존 기본 명중 사건을 유지한다.

## 3. AI가 제안한 것

- **AI 구현상 판단 (A1):** Audacity 재가공 결과가 프로젝트 파형에 저장되어 있으므로 MP3 원본 재편집 대신 저장된 PCM을 읽었다. 트랙 게인은 clang -16dB·267 +3dB·나머지 0dB, 클립 시작은 thud/sword/267 0초·knock 0.0498095238초·clang 0.0808843537초였다.
- **AI 구현상 판단 (A2):** 예시 원파형의 최대 진폭이 1을 넘어 공통 0.5 감쇠로 16bit WAV를 만들었다. 개별 음원의 정규화·추가 리버브·변주 없이 상대 균형을 보존했다. 이 WAV 구성은 U3로 최종 금속 명중 연결에서 제외했다.
- **AI 해결 제안 (A3):** OGG 원본은 보존하면서 게임 재생 gain만 0.8로 조정하겠다고 사전 보고했다. 연타의 합산 클리핑 I2를 피하기 위한 약 -1.94dB 시험값이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 예시를 게임에 사용하는 근거는 U1, 최종 OGG를 채택하는 근거는 U3다. AI의 구체 감쇠 수치·최종 청감에 대한 별도 승인은 확인되지 않았다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1):** 예시의 긴 꼬리와 5레이어를 유지한 채 32채널에서 휘두르기·Overdrive 8연타를 재생하자 267 두 번이 누락됐다. 48채널에서는 누락이 없었다.
- **문제 2 (I2):** 완성 OGG의 재생 gain 1.0에서 휘두르기·마찰/대시 지속음과 Overdrive 8연타를 합치자 포화 샘플 4개가 확인됐다. 원본 파일을 수정하지 않고 재생 gain 0.8로 해결했다.
- 공통 프로젝트 인계기의 초기 검사에서 DB 연결 미해제와 부동소수점 비교 오류를 발견해 연결 종료·허용 오차 비교로 수정했다. 최종 36개 검사에 포함해 재검증했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U3의 사용자 완성 OGG를 채택했다. 새 합성·변환·추가 리버브를 적용하지 않았다. U2의 음원 탐색은 대기 상태이며 이번 채택에 섞지 않았다.
- Audacity 원본·이전 WAV와 bank는 보존했다. 예시 프로젝트는 후속 파일 조회에서 `data/audio/projects/hit-metal-example.aup3`에 있는 것을 확인했으며 AI가 이동한 것으로 기록하지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

- 재사용 인계기는 `automate/audacity_project.py`, 진입점은 `sound-project`다. 저장된 float32·단일 클립·중앙 패닝만 지원하며 실시간 효과·피치/속도 변경·엔벌로프·미저장 작업은 거절한다. 공개 가능한 수치 파형으로 독립 검사를 제공한다. 게임은 이 인계기를 실행하지 않는다.
- 예시 추출본은 `data/audio/user_audio/audacity_example_v1/`, 이전 bank·프로젝트 스냅샷은 `data/audio/revisions/20261116_audacity_example/`에 보존했다. 21:35:19의 검증에서 원본 프로젝트 해시 일치와 PCM 양자화 오차 0.5 LSB 이하를 확인했다. 당시 원본 경로와 후속 이동 위치를 구분한다.
- 최종 OGG의 SHA-256은 `93708f2591439bcab1db5022dde7ea3294b75d32be79629662a97a7a39517163`, 길이는 약 1.77884초다. 출처 기록은 `data/audio/user_audio/hit_metal_ogg_source.json`, 연결은 `bank.json`의 `hit_metal` 한 레이어다. 원본 바이트 일치를 확인했다.
- `MovementSoundCues`가 `hit_metal.replaces_hit=true`를 읽어 금속 명중의 기본 레이어 중복을 방지한다. 비금속·기존 공개 시연의 기본 동작은 유지했다. 청취 기록도 같은 규칙을 적용했다.
- **관련 검사 36개 통과**. 금속 완성본 한 번·비금속 기본 명중·금속/비금속 동시 접촉을 검사했다. 최종 실제 믹서 일반 명중 peak **10496/32767**, Overdrive 8연타·휘두르기·지속음 동시 재생 **27623/32767**, 모두 **클리핑 0·레이어 누락 0**이다. OGG 8회·이전 5개 명중층 0회를 확인했다.
- 최종 공통 `sound-preview --only contact`도 클리핑·누락 0이었다. 금속 명중 6회는 OGG만 사용했고 일반 명중 1회만 기본 두 레이어를 사용했다.
- 청취와 보고는 `output/audio/user_hit_metal_ogg_20261116/`에 둔다. 게임 실행 중에는 이미 읽은 파일이 유지되므로 재시작 후 적용된다. 실제 스피커 청감·게임 창 직접 조작·커밋·업로드는 미수행이다. 원본·가공 에셋은 Git 제외를 유지한다.
