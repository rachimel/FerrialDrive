# UI v2 느린 Scanline·빠른 밝기 띠

- **기록 ID: ui-v2-dual-scanline-motion**. 원래 대화·구현·정리: 2026-11-11 KST, 현재 대화.
- 개별 발언의 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:ui-v2-dual-scanline-motion:scope]] 검색 단서: `천천히 스크롤`, `밝은 영역은 빠르게 스크롤링`.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1)**: Scanline을 천천히 스크롤하고, 그중 밝은 영역이 빠르게 스크롤하는 추가 효과를 겹친다. 목표는 현재 발언에 명시한 두 이동 속도의 대비이며 별도 이유는 제시하지 않았다.

## 2. AI가 제안한 것

- 별도 수용을 요청한 후보는 없다. 구현상 판단으로 아래 방향의 기본 선 3px/s, 밝은 띠 120px/s·높이 24px·불투명도 0.22를 설정했다. 시간 상태는 입력·표현과 분리하고 일시정지 중 정지하게 했다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1을 반영했다. `ScanlineMotion`이 두 이동량을 갱신하고 뷰에는 `ScanlineVisual`만 전달한다. 느린 선은 반복 텍스처의 UV로 이동하며 밝은 띠는 같은 패턴의 밝기만 높인다. 글자·표식·테두리에는 이동/밝기 효과를 적용하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 속도·폭·밝기 수치와 수정본 사용감에 대한 명시 수용은 아직 확인하지 않았다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1)**: 미리보기 제작에서 game2d 환경에 Pillow가 없어 GIF 변환 준비가 한 번 실패했다. 게임 실행 오류는 아니었다. UI 자동 검사 실패는 발견하지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1에 대한 별도 사용자 해결 제안은 없었다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: game2d에서 실제 프레임 PNG를 출력하고 기존 이미지 변환 환경으로 GIF를 만들었다. 게임 환경의 추가 의존성은 늘리지 않았다.
- UI 자동 88개·획득 7개, 총 **95개 통과**. 프레임 간격 독립·일시정지/재개·F5 초기화와 실제 SDL 120프레임의 텍스처 재사용을 확인했다. 시간 갱신과 렌더 캐시를 분리해 매 프레임 새 텍스처를 만들지 않는다.
- 별도 전투 렌더는 24fps 시간 간격의 **72개 프레임·3초 GIF**다. 주요 중간 이미지를 열어 밝은 띠 이동·표시 범위를 확인했다. 패턴 텍스처는 4개로 유지됐다. 실제 창 재생 사용감·사용자 외관 승인·GPU 성능·업로드는 미검증/미수행이다.
- 출력은 `output/ui_unit_test_v2/scanline_motion/`이며 공개하지 않는다. 패널 자체의 등장 효과는 별도 미연결 상태다.
