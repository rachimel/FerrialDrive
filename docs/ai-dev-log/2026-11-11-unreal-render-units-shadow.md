# Unreal 출력 단위 분리·지면 그림자 패스

- 기록 ID: FDLOG-20261111-unreal-render-units-shadow

## 1. 사용자가 제안한 것

- U1: 출력 단위 분리와 그림자 전용 패스만 우선 구현하고 GUI 직접 조작은 사용자가 맡도록 요청했다. 출처: 현재 대화의 위 발언. 의도는 구현 범위와 수동 확인 담당을 명시한 것이다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1 범위로 구현했다. 기존 Unreal 리그·모델 원본·사용자 편집 키를 보존하고 새 출력 후보만 생성했다. GUI 자동 조작·에디터 재시작은 수행하지 않았다. 새 제작용 KeyPose/전체 동작 작성은 이번 범위에 포함하지 않았다.

## 3. AI가 제안한 것

- A1(구현상 판단): 기존 GeometryScript 강체 조립을 공통 함수로 추출하고 417개 부품을 8개 출력 Mesh/Actor로 묶었다. 기존 59본 Skeleton을 공유하고 Leader Pose로 같은 포즈를 따른다. 전체 숨김 Mesh 하나로 그림자를 투사해 분리 단위마다 그림자가 중복되거나 달라지는 문제를 줄였다. 근거: 설치된 Unreal 기본 기능·공식 문서와 실제 렌더 비교.
- A2(구현상 판단): 중성 수신면을 그림자 유무 2회 렌더해 표시 색상 밝기 비율로 검정 RGB·가변 알파 그림자를 산출했다. 최종 인계에서 수신면을 제외하고 shadow를 첫 순서에 넣었다. 중성 조건·같은 가림 알파를 검사하고 완료 전 manifest 가져오기를 거부한다. 임의 재질의 물리 조명 복원은 아니다.
- A3(구현상 판단): 전용 Unreal 프로세스와 별도 작업 프로젝트를 사용하고, 새 결과 에셋만 원래 프로젝트로 복사했다. 원래 에디터/MCP 연결을 건드리지 않도록 배치 시작 가드를 추가했다. 외부 유료 플러그인/에셋은 추가하지 않았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U1은 구현 범위에 대한 명시 요청이다. A1~A3의 세부 구현과 진단 이미지·최종 외관·사용감에 대한 사용자 승인은 아직 받지 않았다. 구현 사실과 사용자 품질 수용을 구분한다.

## 5. 반영 후 발견한 문제

- I1: 매우 짧은 12fps 진단 클립은 기본 30fps 압축 길이가 정수가 아니어서 엔진 압축 단언 오류를 일으켰다.
- I2: 맵 Save As 뒤 참조 Sequence의 카메라 바인딩이 이전 맵을 가리켜 빈 참조 PNG가 생겼다. 분리 Mesh별 그림자 계산과 Rotator 인자 처리 때문에 음영 차이/화면 밖 그림자도 발견했다.
- I3: 최종 통짜 참조와 분리 렌더는 프레임마다 경계 1픽셀에서 최대 RGB [25,25,26] 차이가 남았다. 알파는 완전히 같다. 잔여 차이의 정확한 원인은 미확인 — [[FDLOG_MISSING_CAUSE:FDLOG-20261111-unreal-render-units-shadow:I3]] release/verification.json과 같은 위치의 통짜/분리 렌더를 엔진 수준에서 비교해 보완한다. 엄격 비교의 passed=false를 통과로 바꾸지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1에 따라 GUI 확인은 사용자 담당으로 남겼다. 기존 프로젝트에 새 출력용 에셋 14개만 추가하고 해시를 대조했다. 기존 리그·동작·설정·현재 창은 변경하지 않았다. Asset Tool에서 열 결과와 Unreal 출력 장면 경로를 편집 안내에 기록했다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 편집 bracket과 0.5초(12fps 6프레임·7키)의 진단 클립을 사용했다. 출력은 첫 2프레임이다. 진단 클립 생성은 validation_motion=true일 때만 실행하고, 제작 시 같은 Skeleton의 animation 입력 또는 Rest Pose를 사용한다.
- I2: 참조 맵을 저장한 뒤 재로딩하고 카메라를 바인딩했다. 전체 숨김 Mesh 한 개만 그림자를 투사하도록 바꾸고 Rotator의 pitch/yaw/roll을 명시했다. 최종 그림자는 캔버스 안에 있으며 PNG를 직접 열어 모델·그림자 표시를 확인했다.
- V1: 실제 Unreal 5.8에서 417부품 → 본체 276/좌우 손 각 38/총 22/검 19/칼집 12/좌우 슬롯 각 6의 8개 출력 단위를 생성했다. 59본 공유, 중복·누락 없음, 원본 431개 파일의 해시 유지, 손목 진단 동작 전달, 실루엣 차이 0을 확인했다. 색상 8개+그림자 1개 × 2프레임, 512×512, 12fps, 공통 기준점이다.
- V2: 지면 그림자 RGB는 [0,0,0], 알파는 가변이며 화면 경계에서 잘리지 않았다. 파츠+그림자를 기준 바닥에 재합성한 결과 전체 렌더와 RGBA 최대 [1,1,1,0] 차이다. I3의 통짜 비교는 별도 엄격 실패로 남겼다.
- V3: 게임 에셋 없는 상자 샘플도 2색상+그림자 × 2프레임을 렌더·가져오기 했다. 재합성은 RGB 최대 [2,1,1], 알파 차이 0이며 프레임마다 1픽셀이 1을 초과한다. 무손실 렌더 정합으로 표현하지 않는다.
- V4: 기존 unreal.import → plan.create → plan.validate(check_sheets) → plan.export를 실제 결과에 실행했다. 기존 MechBundle 로더로 9파츠/2프레임을 읽고, 패킹과 재출력 시트에서 모든 원본 RGBA 프레임을 복원해 픽셀 완전 일치를 확인했다. 자동 검사 9개 통과(분리 보존·그림자 변환/오입력·기존 인계/원본 보존·미완료 그림자 거부).
