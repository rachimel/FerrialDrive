# 피드백 반영: 공격 고정 속도·부스트 콤보·에너지 연출·카메라 블러

- 기록 작성·확인 시각: 2026-11-14 00:47:26 KST 이후. 근거: 현재 대화의 사용자 발언·질문 응답과 아래 검사/출력. 친구들의 직접 발언을 확인한 기록이 아니라 사용자가 전달한 피드백이다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 친구 피드백으로 일반 공격 1·2·4타 50m/s, 3타 70m/s와 대시 공격 1·2·4타 90m/s, 3타 120m/s를 전달했다. 검 Trail을 사용하고 부스트로 콤보가 끊기지 않게 요청했다.
- **사용자 제안 2 (U2):** 질문에서 부스트 중 공격을 멈췄다 재개하는 방식이 아니라 `공격 동작과 콤보 연계를 계속 진행`하도록 선택했다.
- **사용자 제안 3 (U3):** 가속 해제를 요청하고 질문에서 `공격 이동 가속만` 선택했다. 첫 타격 프레임부터 U1의 속도로 이동한다. 일반 달리기/대시 가감속과 공격 모션의 후반 가속 재생은 별도다.
- **사용자 제안 4 (U4):** 카메라 모션 블러를 강하게·방향성 있게 요청했다가 `약간 약하게`로 후속 조정했다. 기체 개별 블러가 아닌 카메라 필터라고 명시했다.
- **사용자 제안 5 (U5):** `레벨 3 Trail을 기본으로` 요청하고 질문에서 이전 레벨 3의 크기·밝기·잔상을 새 레벨 1로 옮기도록 선택했다. 시작 에너지 레벨만 3으로 바꾸는 뜻과 구분한다. 각 레벨 차이도 더 뚜렷하게 요청했다.
- **사용자 제안 6 (U6):** 전신 잔상에 에너지색을 혼합하도록 요청했다.

## 2. AI가 제안한 것

- **AI 제안 1 (A1):** 부스트는 위치 이동을 우선하고 공격 시간·입력·Trail은 병행하도록 구조를 분리한다. 이유: 입력 예약과 타격 진행을 초기화하지 않고 부스트 기동을 제공할 수 있다.
- 구현상 판단: 공격 재생 1.5배와 `accelerate` 위상은 유지하고 위치 이동만 `constant`로 설정한다. 콤보 경계뿐 아니라 부스트 준비/추진 경계에서도 실제 갱신 구간을 나눈다.
- 구현상 판단: 카메라 블러 시안 0.45/12px에서 최종 0.35/9px로 낮추고 17샘플·방향 치우침 0.65를 사용한다. 일반 UI v2 기본 설정이 아닌 검 훈련장 설정을 변경한다.
- 구현상 판단: 최종 레벨 범위 2.4/3.6/5.0배, Trail 수명 0.26/0.36/0.48초, 잔상 상한 6/9/12개로 구분한다. 대시 추가 배율은 1.35다. 기준 이동 시 V 외관도 보존해 새 1레벨 전체 폭은 원래 칼날 길이의 약 46.15%다.
- 구현상 판단: 잔상은 생성 당시 에너지색과 원래 명암을 55/70/85%로 혼합한다. 알파 0.30/0.40/0.50과 수명도 레벨별로 나눈다. 저장 자세에 별도 모션 블러를 다시 적용하지 않는다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U6를 구현했다. 공격 속도·연출은 설정, 공격/부스트 진행은 `MovementCombat`, 궤적·명중·잔상은 `SwordEffects`, 색 혼합은 재사용 렌더러에서 처리한다.
- 부스트를 받아도 현재 타격 ID·재생 시간·다음 예약과 자동 반복을 초기화하지 않는다. 수동 연결 대기도 부스트 중 유지하고 다음 공격을 받을 수 있다. 실제 부스트가 이동을 담당하는 동안 공격 이동을 합산하지 않는다.
- 에너지 레벨은 1로 시작한다. 이전 레벨 3의 범위·밝기·잔상 6개를 새 기본으로 옮긴다. 자원 획득·소모·승강 요구량과 적 피해량은 이번 변경 범위가 아니다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U2·U3·U5의 동작 범위는 사용자 질문 응답으로 명시 선택했다. U4는 카메라 필터로 정정하고 강도를 낮추라는 후속 요청을 반영했다.
- AI가 선택한 상위 레벨 세부 수치·최종 색 혼합률·블러 수치의 사용자 외관/사용감 승인은 아직 받지 않았다. 구현 사실·자동 검사·캡처 확인을 승인으로 확대하지 않는다.

## 5. 반영 후 발견한 문제

- 기존 부스트 요청은 콤보와 자동 예약을 초기화했고 부스트 중 자동 연계도 차단했다. 요청한 새 규칙과 충돌하므로 해당 경로와 검사를 교체했다. 기존 규칙의 버그가 아니라 사용자 요구 변경이다.
- 이전 재생 증속 작업의 `타격당 거리 유지` 검사는 U1/U3의 새 속도·가속 해제와 양립하지 않는다. 현재 지정 속도·실제 타격 시간·프레임률별 거리를 검증하도록 갱신했다.
- 레벨 조절을 반복할 때 동작 검사가 실제 튜닝 값에 묶여 깨지는 문제를 확인했다. 고정 수치 fixture의 알고리즘 검사와 새 기본값 보존 검사를 구분했다.
- 이전 기록의 빈 캡처 현상이 일부 실행에서 전체 화면에도 간헐적으로 재현됐다. 원인은 미확정이며 이전 기록의 CAUSE(I1)를 유지한다. 상태 기록을 추가한 실행에서는 정상 캡처를 얻어 실제 이미지를 확인했다. 일반 실행의 모든 캡처가 정상이라고 확정하지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U2의 동시 진행 선택에 맞춰 부스트 중 연계/자동 반복 차단과 초기화를 제거했다. 부스트 종료 후 진행 중 타격의 고정 속도로 돌아간다.
- U3에 따라 첫 프레임부터 공격 속도를 직접 적용했다. 일반 이동 가감속·부스트 곡선·공격 모션 위상은 별도로 둔다.
- U5/U6에 따라 새 기본·레벨 차이를 설정하고 저장된 각 잔상에 생성 당시 에너지색을 연결했다. 원래 명암과 섞어 기체 형태를 보존한다.

## 7. AI 해결 제안과 실제 해결 과정

- 일반/대시 4타의 첫 프레임 속도·거리와 부스트 준비/추진/종료·수동 예약·자동 반복·방향 고정·30/60/144fps 일관성을 검사했다. 부스트와 공격의 시계는 함께 진행하고 이동은 부스트가 우선한다.
- OpenGL 공유 아틀라스와 모션 보간에 독립 색 혼합을 추가했다. 본체의 다음 그리기는 색 혼합 0·알파 1로 복구한다. 기본 SDL 경로는 에너지색 곱셈 근사와 공유 색 복구를 사용한다. 예외 시에도 원래 색을 복구하는 검사를 추가했다.
- 카메라 필터는 월드 이동축을 사용하고 HUD는 필터 밖에 둔다. 정지/비활성 시 건너뛰고 길이와 방향 치우침을 설정에서 관리한다.
- 자동 검사: 검/이동/콤보 77개·UI v2 55개·GPU 잔상 색/공유 색 복구 2개·프레임 보간 16개·실제 방향성 블러 7개, 총 **157개 통과**. 로컬 선택 입력을 요구하는 프레임 보간 2개는 건너뛰었다.
- 실제 실행: `feedback_combo_boost_input.json` 300프레임에서 공격·부스트·Trail이 동시에 활성인 36프레임을 기록했다. 첫 프레임 일반 50m/s·대시 90m/s와 3타 70/120m/s를 확인했다. 타격 시간·예약·다음 타격이 이어지는 캡처도 확인했다. 결과는 `output/feedback_combo_boost/`다.
- 레벨 비교: 실제 에셋 400프레임에서 잔상 상한 6/9/12개를 확인했다. 창 상태 기록을 추가한 `output/sword_energy_rebased/inspected/`의 정상 PNG에서 새 기본·상위 효과·에너지색 혼합·V·카메라 블러를 직접 확인했다. CPU draw 평균 시간과 실제 GPU 시간을 혼동하지 않는다.
- 독립 시연: 같은 부스트 시나리오를 `--demo`로 300프레임 실행했다. 게임 에셋 없이 OpenGL 실행과 결과 보고서 생성을 확인했다. 결과는 `output/feedback_combo_boost/demo/report.json`이다.
- 미검증: 물리 키보드/마우스 사용감·모든 방향/교차 자세의 외관·최종 밸런스·사용자 승인·실제 GPU 시간·본편 피해/자원 시스템. 기존 미커밋 제작 코드에 이어 수정했으며 커밋·푸시는 하지 않았다.
