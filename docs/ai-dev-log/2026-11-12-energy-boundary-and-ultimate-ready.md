# 에너지 경계 VFX·Overdrive 전환·필살기 준비 표시

- **기록 ID:** `FDLOG-20261112-energy-boundary-and-ultimate-ready`
- 작성·검증 기준: 2026-11-12 21:46 KST. 요청·수용의 개별 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261112-energy-boundary-and-ultimate-ready:scope]]. 현재 대화의 `직선을 늘려`, `글자들이 퍼지는`, `damping`, `V키 있잖아`와 확인 응답을 검색한다.
- 근거: 현재 대화·실제 소스·자동 검사·고정 시간 GPU 캡처. 상태는 독립 UI 예제 구현이며 본편 규칙 확정·사용자 외관 승인과 구분한다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 레벨 오른쪽 위·아래 사선 길이를 같게 하고 가운데 직선을 늘린다. Overdrive는 반짝이며 글자가 퍼지는 등장, fade-out 퇴장을 요청했다.
- **사용자 제안 2 (U2):** 에너지 문구 축소/필요성을 검토하고 채움 경계에 반짝임·위로 흩날리는 입자를 요청했다. 확인 응답에서 ENERGY 제거·OVERDRIVE만 축소 표시를 선택했다.
- **사용자 제안 3 (U3):** 피격을 더 강하게 하고 흔들림에 damping을 적용한다. 록온 damping은 시험 적용하며 거슬리면 제외할 수 있도록 한다.
- **사용자 제안 4 (U4):** 필살기 준비는 에너지 LV3·쿨다운 0이다. 준비 중에만 록온과 같은 강조선 애니메이션을 적용하고 쿨다운 완료 때 flash한다.
- **사용자 정정 (U5):** 기존 필살기 키는 V다. AI가 U키를 제시한 것을 바로잡았다. U1~U5 시각은 scope 누락 범위다.

## 2. AI가 제안한 것

- **AI 제안 1 (A1):** ENERGY 제거·OVERDRIVE만 축소하는 안을 확인 질문으로 제시했다. 사용자 요청의 문구 필요성 검토를 구체화하기 위한 선택지다.
- **AI 제안 2 (A2):** 필살기 사용 시 에너지 유지·5초 쿨다운을 예제값으로 제시했다. 본편 규칙을 임의 확정하지 않고 독립 시연을 가능하게 하기 위한 안이다.
- **구현상 판단 (A3):** 경계 입자는 효과 종류 1로 기존 생성/갱신 Compute 두 개에 추가한다. 생성 주기는 CPU 요청, 입자별 생성·상승·흩어짐·수명은 GPU다. 초당 40개·수명 0.8초·무회복이며 빈/완충 상태에서는 새로 생성하지 않는다.
- **구현상 판단 (A4):** 피격은 플레이어 0.34초·16Hz·상한 ±7 화면 px, 타겟 0.28초·18Hz·상한 ±5 화면 px로 시험한다. 지수 감쇠 1.8과 종료 구간 완화, 해석적 속도를 적용한다. 록온도 조절 가능한 감쇠 1.8을 공유한다.
- **구현상 판단 (A5):** OVERDRIVE는 12px·바 폭 40%, 투명도 등장 0.065초·글자 확산 0.42초·퇴장 0.18초다. 강조선 이동/정지는 록온과 같은 함수·설정을 공유하고 준비 flash는 0.28초다. 수치는 최종 외관 승인을 뜻하지 않는다. A1~A5의 시각은 scope 범위다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U5를 구현했다. V 사용은 준비 조건을 검사하고 재입력으로 남은 쿨다운을 초기화하지 않는다. 필살기 소비량·실제 공격 판정은 추가하지 않았다.
- 에너지/Overdrive 충전 규칙과 도착별 분할 회복은 유지하며 경계 불꽃에 회복량을 배정하지 않았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 확인 응답에서 A1·A2를 선택했다. 예제 5초·에너지 유지의 수용이며 본편 밸런스 확정이 아니다.
- A3~A5는 AI 구현상 판단이다. 사용자의 최종 외관 승인은 아직 없다. 록온 감쇠는 U3에 따른 시험 적용이다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1):** AI가 기존 V 표기를 확인하지 않고 U키를 제시했다. 사용자 U5로 정정했다.
- **문제 2 (I2):** 최초 캡처에서 입자가 작고 Overdrive 등장 초반의 투명도가 낮아 반짝임을 보기 어려웠다.
- **기존 의존성 (I3):** HEAD UI 설정이 미커밋 피해 숫자 확장(`ui/damage.py`)에 의존한다. 로컬 폰트와 이 별도 작업을 사용해 검사하며 이번 커밋에 섞지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U5: 기존 V 표기와 키 입력을 일치시켰다. 합성 V 입력·5초 쿨다운·에너지 유지·정지 중 시간 고정을 자동 검사했다.
- U3: `damping`·`hit_damping`을 설정값으로 분리했다. 0으로 지수 감쇠를 끌 수 있고 종료 구간 완화는 유지한다.

## 7. AI 해결 제안과 실제 해결 과정

- I2 ↔ A3/A5: 입자 크기·상승량·발생률을 조정하고 글자 투명도 등장과 확산 시간을 분리했다. 글자별 별 모양 반짝임을 추가했다. 실제 GPU로 60fps 시간 간격 450프레임을 출력하고 주요 PNG를 직접 열었다. 준비 flash는 391~407프레임에 한 번 재생됐다. 결과는 `output/energy_boundary_vfx/preview.gif`·`comparison.png`다.
- **자동 검사:** UI 97개·GPU 요청 6개·실제 렌더 25개, 합계 128개 통과. 사선 대칭·확산/퇴장·V 입력·준비 조건·재입력·정지·감쇠·입자의 상승/소멸·혼합 시 무회복·두 Compute 프로그램 유지를 확인했다.
- **커밋 분리 확인:** 공유 파일의 기존 에셋 수정을 제외한 별도 검사본도 I3의 의존성을 공급해 UI 97개·요청 6개를 통과했다. 현재 HEAD만으로 독립 실행이 검증됐다는 뜻은 아니다.
- **스트레스:** 16,384개·24구간·1280×720·예열 30/측정 120프레임, RTX 5070 Laptop GPU에서 활성 수 일치·갱신 평균 약 0.143ms·렌더 약 0.515ms. `output/performance/massive_energy_particle_boundary_revision.json`이다. 에너지 오브 장면의 단계별 GPU 시간이며 전체 프레임·혼합 효과 최악 조건 성능으로 확대하지 않는다.
- **남은 범위:** 실제 창 조작감·사용자 외관 승인·본편 필살기 규칙/피해 판정 연결. 기존 별도 작업을 보존하며 이번 소스·문서만 기능별 커밋한다. 업로드는 하지 않는다.
