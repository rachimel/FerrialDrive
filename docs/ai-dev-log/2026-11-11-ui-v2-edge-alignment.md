## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** HIT/DAMAGE를 더 오른쪽으로 옮긴다. HP를 아래·왼쪽으로 옮겨 에너지와 붙이고 레벨 사선과 만나게 하며 마름모도 조정한다. 의도는 배치·공유 경계의 정렬이다. 시각은 scope 태그를 따른다.
- **사용자 제안 2 (U2):** LOCK ON 글자 끝을 두꺼운 선 쪽에 맞춘다. 테두리 안으로 파고드는 강조선만 지우고 남은 선을 테두리에 붙인다. 무장 L자는 제거하고 바깥 왼쪽 외곽을 굵게 한다. 겹침과 장식의 정리를 명시했다. 시각은 scope 태그를 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1~U2를 수용해 v2 표시·설정·형상 검사와 관련 문서를 수정했다. 실제 전투 규칙과 v1 표현은 변경하지 않았다.

## 3. AI가 제안한 것

- **구현상 판단 (A1):** 카운터 기준 오른쪽 여백을 34→14px로 줄였다. HP 채움 16px는 유지하며 접합 경계 쪽으로 내리고, HP 아랫변/에너지 윗변과 HP 오른쪽/레벨 왼쪽 사선을 공유하도록 계산했다. 사용자 사전 승인 수치로 취급하지 않는다.
- **구현상 판단 (A2):** 글자 치수와 선 방향에서 LOCK ON 끝점을 계산했다. 강조선·무장 왼쪽 외곽은 축소 전 3px, 글자 간격/끝 여백은 7/2px로 시험했다. 시각은 scope 태그를 따른다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1~A2의 수치·최신 이미지에 대한 수용은 확인 대기다. 요청의 구현과 최종 외관 승인을 구분한다.

## 5. 반영 후 발견한 문제

- 기존의 “레벨은 HP보다 항상 아래”라는 검사 조건은 옆으로 맞붙이는 새 요구와 맞지 않았다. AI가 검증 조건을 검토하면서 확인했다. 높이 범위가 겹치는 것과 실제 면의 침범을 구분할 필요가 있었다.
- 이번 수정 뒤 새 외관 문제에 대한 사용자 제보는 기록 시점까지 없었다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1에 따라 두 바의 공유 아랫변/윗변과 레벨 접합 사선을 만들었다. 마름모 중심·크기도 그 경계에 맞춰 다시 계산했다.
- U2에 따라 테두리 내부로 향하던 선을 제거하고 왼쪽 위 변을 강조했다. 글자 끝을 해당 선의 위쪽 끝에 정렬했다. 무장 L자 대신 기존 바깥 왼쪽 변 전체를 강조했다.

## 7. AI 해결 제안과 실제 해결 과정

- 레벨 비침범 검사를 공유 사선의 어느 편에 면이 있는지 확인하는 방식으로 바꾸고 두 바가 같은 변을 공유하는지도 검사했다.
- 기존 UI 포함 자동 검사 71개 통과. Pico2D/SDL dummy로 긴 카운터를 포함한 11개 상태를 렌더링하고 배율/viewport/clip 복원·금속 패널 미생성·자원 해제를 확인했다. 기본·긴 숫자·크기별 표적·피해·타겟 없음·흡수 이미지를 열어 확인했다.
- 실제 창 조작·Runner 드롭·전체 재생 사용감·수정본 승인·커밋은 기록 작성 시점에 미확인이다. PNG는 `output/ui_unit_test_v2/`의 재생성 가능한 출력이며 커밋하지 않는다.
