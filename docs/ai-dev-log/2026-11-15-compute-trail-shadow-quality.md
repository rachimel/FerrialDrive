# Compute Trail 정점 생성·그림자 품질 연동

- **기록 ID:** `FDLOG-20261115-compute-trail-shadow-quality`
- 기록·검증일: 2026-11-15 KST. 실제 측정 시작 시각은 각 report에 기록했다.
- 개별 발언 시각 미확인: `[[FDLOG_MISSING_TIME:FDLOG-20261115-compute-trail-shadow-quality:scope]]`. 현재 대화의 `그림자도 높음 50%`, `Compute Shader에 정점 데이터 생성을 맡기고`, `유저입장에서 공격이 들어간거 같은데 왜 안맞지` 발언에서 보완한다.
- 근거: 사용자 요청·현행 소스·`output/performance/compute_trail_20261115/`·`output/performance/shadow_quality_20261115/`와 자동 검사.
- 상태: 구현·자동 검사·GPU 정점/화면 비교·실제 게임 비교 완료. 목표 165FPS·실제 UHD 630·수백 기·전체 모션/방향·사용자 외관 승인은 미검증이다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 그림자를 높음 50%·보통 25%·낮음 12.5%로 기존 품질 선택에 연동한다. 기존 그림자 50% 고정과 구분한 명시 구현 요청이다. 메모리·품질을 같은 선택으로 조절하려는 요청이며 시각은 scope 태그 대상이다.
- **사용자 제안 2 (U2):** 정점 데이터를 Compute Shader에서 생성하고 다시 비교한다. 앞선 Trail CPU 비용을 줄이려는 명시 구현 요청이다. 출처는 현재 대화이며 시각은 scope 태그 대상이다.
- **사용자 제안 3 (U3):** Collision과 Rendering을 주요 병목으로 보고, 플레이어가 맞았다고 느끼는 공격이 빗나가지 않도록 더 단순한 Collision mask와 margin을 검토한다. 현재는 방향 제안이며 특정 캡슐 규격·수치의 적용 지시는 없다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1을 수용해 3등급 알파 데이터를 분리 준비하고 초기 적재·실행 중 저장 적용을 연결했다. 기체와 그림자는 배율을 별도로 사용한다.
- U2를 수용해 기존 판정·CPU 기준 표시를 유지하면서 곡선/정점 생성을 Compute로 옮겼다. 생성 결과는 GPU SSBO에서 바로 표시하고 런타임 CPU readback을 하지 않는다.
- U3의 타격감 의도를 수용했다. 현행은 검날 궤적의 볼록다각형과 원형 표적을 검사하고 세로 1.5m 여유를 추가한다는 점을 설명했다. 이번 구현은 판정 규칙을 바꾸지 않았다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** CPU는 궤적·판정·접힘 구간 분류만 맡고 Compute는 곡선 보간·띠 정점·UV·알파를 생성한다. 작은 제어점/작업 배열만 전송해 Python 벡터·SDL_Vertex 생성을 줄이기 위해서다. CPU 기준과 같은 보간·찌르기 폭·레이어 순서를 보존한다.
- **AI 제안 2 (A2):** 품질별 `.alpha8.x2/.x4/.x8`을 미리 준비하고 저장 성공 때 기체·그림자를 함께 교체한다. 실행 중 원본 PNG 축소를 피하고, 준비·저장 실패 시 이전 등급을 유지하기 위해서다.
- **AI 제안 3 (A3):** 같은 로드 장면에서 CPU/Compute 순서를 바꿔 반복 측정하고 정점·UV·알파·실제 화면을 별도로 비교한다. 계측/컴파일 준비와 표시 차이를 개선량으로 오해하지 않기 위해서다.
- **AI 제안 4 (A4), 미구현 후보:** 표시용 곡선 Trail과 분리한 짧은 구간별 캡슐+히트 여유를 검토한다. 유효 공격 시간·후방 빈틈·타격당 중복 명중 방지는 유지하는 방향이다. 구간 사이 누락과 과한 판정 확대를 별도로 검증해야 한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1은 U2의 `일단 Compute Shader에 정점 데이터 생성을 맡기고, 다시 비교`로 명시 수용했다.
- A2는 U1의 품질 연동 요청 수행 방법이다. 외관·메모리 측정과 사용자 승인은 별개다.
- A3는 요청받은 비교를 수행하는 계측 판단이다. A4는 사용자 U3와 같은 방향의 제안이지만 구체적인 도형·margin 정책 적용을 별도 확정하지 않았다.

## 5. 반영 후 발견한 문제

- **I1:** GPU 검사에서 샘플 카탈로그의 첫 항목을 그림자로 가정했으나 일반 이미지였다. `shadow` 시트가 있는 문서를 선택해 수정했다.
- **I2:** 그림자 검수 캡처를 present 뒤에 읽어 이전/설정 화면이 잡혔다. 표시 직전의 실제 draw 완료 후 캡처하고 설정 적용 진행 화면은 제외했다.
- **I3:** 낮은 배율의 작은 홀수 이미지가 0px가 되지 않도록 올림·최소 1px와 요청 배율 일치를 검사했다. 원본 좌표와 실제 텍스처 크기는 분리했다.
- **I4:** Compute 이후에도 최종 평균 13.89ms로 165FPS 예산 6.06ms를 넘었다. HUD 평균 약 7.27ms가 남는다. GPU 이관만으로 목표를 달성했다고 판단하지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I4 ↔ U2: CPU reference와 Compute 경로를 함께 남겨 같은 조건에서 직접 비교했다. 표시용 데이터만 옮기고 검 궤적 기록·스윕 판정·한 타당 한 번 명중 규칙은 보존했다.
- U1 ↔ A2: 현재 18개 그림자 시트의 54개 품질 파일을 준비했다. 실제 R8 적재량은 높음 67.04MiB·보통 16.77MiB·낮음 4.20MiB다. 원본 PNG·프레임·피봇을 바꾸지 않았고 필터의 화면 픽셀 기준 부드러움은 유지했다.
- U3의 단순·넉넉한 판정은 후속 설계 후보로 남겼다. 현재 표적은 정적 원형 범위이며 호출부는 시작/끝에 같은 중심을 전달한다. 공간 후보 필터 없이 활성 구간마다 표적을 순회하는 현재 구조는 수백 기 성능 검증과 구분한다.

## 7. AI 해결 제안과 실제 해결 과정

- A1: `ComputeSwordTrail`은 CPU 구간/제어점·job 전송, Compute SSBO 생성, storage barrier, instanced draw로 구성했다. 첫 표시에서 프로그램을 준비하며 기능이 없는 렌더러는 CPU로 돌아간다. Compute 오류를 정상 CPU 성공으로 숨기지 않고 실제 백엔드를 기록한다.
- A2: `GameSettings.shadow_scale`, 배율별 제작 데이터·검증, `PicoAssetResource.prepare_alpha_scale`과 기존 설정 저장 transaction을 연결했다. 실패 시 후보를 해제한다. 별도 품질 파일이 없을 때 다른 크기로 조용히 적재하지 않는다. 배율 미지정 호환 API의 기존 PNG fallback은 유지한다.
- A3: 최종 FHD·기체 50%·그림자 25%·레벨 3 공격, 동일 장면 고정, 조건당 준비 90/측정 660프레임×2회(역순)를 비교했다. 논리 CPU 8개·Job CPU 50%·커밋 1GiB·UHD 630 검토 가드를 사용했다. 호스트는 Ultra 9 275HX/RTX 5070 Laptop이며 실기 i3/UHD 처리량을 재현한 값이 아니다.

| 항목 | CPU 정점 | Compute 정점 |
| --- | ---: | ---: |
| 프레임 wall 평균 | 18.93ms | 13.89ms |
| 실측 FPS 평균 | 52.83 | 72.01 |
| 회차별 p99 평균 | 42.22ms | 27.60ms |
| 월드 wall 평균 | 8.02ms | 3.62ms |
| 전체 draw GPU elapsed 평균 | 1.216ms | 1.250ms |

- 전체 프레임 wall은 약 5.04ms(26.6%) 감소했다. GPU elapsed는 제출 공백을 포함할 수 있고 GPU 전용 실행 시간과 다르다. 두 조건 모두 예산 초과 100%였으며 아직 목표 미달이다. 최초 3회 비교는 그림자 연동 전 약 19.72→15.33ms였고 최종 표와 섞어 개선량을 계산하지 않는다.
- 정점·UV·알파 비교, 찌르기 레이어·긴 시간값, 실제 화면·GPU 상태 복구, 그림자 3등급·원본 보존·준비/저장 실패 복구·설정 즉시 적용·기존 전투/판정 등 관련 검사 93개 통과했다. validation·오류 메시지·검사 readback barrier 보강 후 최종 93개 재확인도 통과했다.
- 데이터 검사는 18개 원본/54개 품질 파일의 배율·해시를 확인했다. 새 높음 50% 데이터가 기존 50% 알파와 18개 모두 바이트 단위로 일치했다. 원자료는 `shadow_quality_20261115/data_report.json`이다.
- 실제 동작 50/140/240 simulation frame의 CPU/Compute 화면을 캡처했다. 평균 채널 차이는 0.046/0.317/0.301(0~255)였고 동일 자세·찌르기/곡선 규칙의 육안 불일치는 발견하지 않았다. 전체 8방향·전 프레임·사용자 외관 승인을 완료한 뜻은 아니다.
- I1/I2는 검사 선택·캡처 시점 수정이며 제품 표현 변경으로 기록하지 않는다. 그림자 3등급 캡처도 직접 열어 접지·크기·위치와 부드러움을 확인했다.

## 확인 상태

- 구현·로컬 데이터 준비·자동 검사·실제 OpenGL 비교 완료. 물리 입력·장기 플레이·실제 UHD 630·수백 기는 별도 검증 대상이다.
- 사용자 직접 조작 벤치마크 기본 경로를 유지한다. 열린 이전 프로세스는 코드 변경을 자동 반영하지 않으므로 검수에는 새 실행을 사용한다.
- 기존 대량 미커밋·병행 변경을 되돌리지 않았다. 공개 제외된 로컬 에셋은 커밋/업로드하지 않았다. 이번 작업의 커밋·업로드는 미수행이다.
