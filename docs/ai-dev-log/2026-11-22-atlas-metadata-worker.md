# 방향 메타데이터 워커와 GC 지연 확인

- **기록 ID** `FDLOG-20261122-atlas-metadata-worker`
- 2026-11-22 KST. RTX 5070 Laptop·OpenGL, FHD·Medium·SMAA, 적 180기·15m 간격, 플레이어 HP 10만, 고정 60Hz 검 자동 입력, VSync·프레임 제한 해제, 무음.

## 1. 사용자가 제안한 것

- **U1** 방향 메타데이터를 렌더 스레드 밖에서 준비하고, 이전 180기 재생에서 `PartMotionCatalog.direction` 안에 잡힌 약 140ms 지연을 확인한다. 정확한 요청 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261122-atlas-metadata-worker:U1]]`. 검색 단서는 `방향 메타데이터 준비를 렌더 스레드 밖에서`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 캐시 미스 때 방향 JSON 읽기·파싱과 코팅 파일 검증을 기존 페이지 워커에서 처리한다. 전투 스트리밍은 완료된 결과만 카탈로그 LRU에 반영한다. GPU 텍스처 적재·자원 수명·상주 핀은 렌더 스레드에서 관리한다.

## 3. AI가 제안한 것

- **A1 · 구현상 판단** 파일 읽기, `orjson.loads`, GC 콜백의 시작·종료를 같은 프레임에서 추적했다. 처음 두 상세 재생에서 파싱 156.91ms 사례를 봤고, 수집 콜백을 연결해 지연의 원인을 재확인했다.
- 다음에 요청된 방향을 기존 페이지 업로드와 함께 미리 준비한다. 기종별 활성 방향 작업 한 건 이외에 최대 세 방향을 대기시킨다. 취소된 결과는 카탈로그를 갱신할 수 없다. 시작·명시적 선적재의 필수 방향은 결과가 필요할 때까지 확보한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 메타데이터 워커 이동과 지연 확인은 사용자 요청이다. 조기 준비 범위, 반복 회차와 진단 항목은 구현상 판단이다.

## 5. 반영 후 발견한 문제

- **I1** 기존 적 방향 `000-0.json`의 측정 프레임 6에서 `_read_direction`은 136.53ms였다. 50,215바이트 JSON의 `orjson.loads` 경과 134.46ms 안에 **세대 2 GC 134.29ms**가 포함됐다. 해당 프레임의 방향·코팅 파일 읽기 합계는 0.71ms였다. 전체 프레임은 167.71ms였다.
- **I2** 워커 경로도 세대 2 GC 지연이 나타났다. 최종 적용 상세 회차의 프레임 86에서 워커 `orjson.loads` 183.18ms 중 세대 2 GC가 **182.84ms**였고 같은 프레임 작업 시간은 **209.51ms**였다.
- **I3** 처음에는 방향 한 건씩 메타데이터를 읽도록 해 적 대체 표시가 120프레임에 159~170회로 늘었다. 이후 파이프라인에서 다음 방향을 앞당겨 113~156회로 낮췄다. 기존 상세 계측과 분리한 대조 회차에서는 91~104회였다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** `8308031`과 기존 로컬 변경을 포함한 작업본에서 카탈로그·방향 상주 구현만 교체했다. 30프레임 예열 후 120프레임을 측정했고, FPS 전후 각 4회와 폴백·GC 상세 실행을 분리했다. 폴백·상세 회차의 프레임별 입력·교전 상태 해시 120개가 일치했다.
- FPS 중앙값은 **41.19 → 40.19**였다. 프레임 작업 P50은 23.21→23.47ms, P95는 32.51→31.87ms, P99는 38.20→36.36ms였다. 각 조건의 개별 최고 프레임은 166.09→201.15ms였다. 꼬리 프레임이 일부 회차에 나타났다.
- 120프레임당 폴백 중앙값은 플레이어 **14.5→19회**, 적 **97→131.5회**였다. 적은 한 프레임에서 복수 기체가 대체될 수 있다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1·I2** 상세 전후 각 2회의 적 스트리밍 P95는 6.13~6.36→5.03~5.16ms였다. 플레이어 스트리밍 P95는 6.87~7.04→5.92~6.27ms였다. 렌더 스레드의 적 `_read_direction`은 18~20→0회였고, 적용 후 워커에서 방향 메타데이터 38~40회를 읽었다. 세대 2 GC는 워커에서도 프레임 지연으로 관측됐다.
- 적용 후 플레이어 렌더 경로의 `_read_direction` 13회는 콜스택을 별도 확인했다. 등 무장 기준점의 `anchor_offset` 직접 조회와 라이브 파츠 `prepare_draw → require`에서 발생했다.
- 워커 지연을 고정한 상태에서 렌더 스레드 폴링과 소유권, 취소된 결과 미반영, 다음 방향 조기 준비 및 필수 요청의 작은 페이지 중복 적재 방지를 확인했다. GPU 검사를 포함한 자동 검사 55개가 통과했다. 원본 상세 기록과 요약은 로컬 `output/performance/atlas_metadata_worker_20261122/`에 있다.
