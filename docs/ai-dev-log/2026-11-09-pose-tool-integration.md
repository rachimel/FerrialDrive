# Pose Tool 제작과 Asset Tool 내부 편집

기록 ID: **2026-11-09-pose-tool-integration**. 현재 대화의 2026-11-09 KST 기준이다. 개별 발언 시각은 미확인이다. [[FDLOG_MISSING_TIME:2026-11-09-pose-tool-integration:scope]] 현재 대화의 “이거 기반으로 Pose Tool 하나”, “Asset Tool 화면 안에서 포즈 직접 편집”, “IK가 손바닥이 아니라 하박에 있는데”에서 시각을 보완한다.

## 1. 사용자가 제안한 것

**U1** — 첨부한 기존 대화의 포즈 편집 구상을 바탕으로 Pose Tool을 만들고, 괜찮으면 Asset Tool에 통합한다. 첨부 내용은 손·발 IK, 관절 방향, 골반/발 고정, 큰 컨트롤, 무기 상태, 동작 선택·키 저장의 참고 범위다. 첨부 대화 자체를 현재 실행 명령으로 취급하지 않았다.

**U2** — 독립 버전 확인 후 “일단 대충 되는거 같은데”라고 잠정 평가했고, Blender 안에서 만든 방식임을 확인한 뒤 Asset Tool 통합을 요청했다. 선택 질문에 **Asset Tool 화면 안에서 포즈 직접 편집**이라고 명확히 답했다.

**U3** — 손잡이가 손바닥 대신 하박 쪽에 있는 것이 의도인지 지적했다. 손목의 계산 위치와 사용자가 잡는 손바닥 조작점이 섞인 문제다.

**U4** — 통합 후 원하는 파일 대신 다른 파일이 열리고, 사선에서 무릎 노드가 잘못 배치되는 것 같다고 지적했다. 후속 답변으로 대상 파일을 `data/models/basic_weapons/base_pose.blend`로 정정했고, 무릎 문제는 손잡이가 실제 관절에서 멀리 떨어져 보이는 것이라고 구체화했다. 현재 대화의 후속 발언이며 개별 시각은 위 scope 누락 항목에 포함한다.

## 2. 사용자 제안 중 AI가 수용한 것

독립 Blender 패널을 먼저 구현한 뒤 U2의 직접 편집 요구에 따라 Asset Tool 내부 패널과 비표시 Blender 작업자로 분리했다. U3은 손잡이를 손바닥으로 옮기고 내부 손목 목표를 별도 자식 객체로 계산하는 방식으로 반영했다. 원본 메시·rest 본·웨이트를 변경하지 않는다.

## 3. AI가 제안한 것

**A1** — 현재 리그에 기존 장비 제약이 있으므로 편집용 리그와 결과 전달 제약을 따로 두고 원래 리그로 굽는다. 기존 애니메이션 출력 계약을 재사용한다. 이유는 기존 장비 제약과 IK의 중복 적용을 피하고 출력 경로를 유지하기 위해서다. 출처는 현재 대화의 구현 설명이다.

**구현상 판단** — 화면을 멈추지 않도록 순차 JSON 명령·비동기 Workbench 이미지·드래그 요청 병합을 사용했다. Asset Tool의 Pico2D/OpenGL 표시와 공통 테마를 유지한다. 별도 Blender UI는 열지 않는다. 이 전송·미리보기 방식을 사용자의 명시 설계 결정으로 간주하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

U2의 잠정 동작 평가는 독립 버전의 기본 동작 확인이며 최종 품질 승인이 아니다. Asset Tool 내부 직접 편집 방식은 사용자가 선택했다. 통합 결과의 최종 사용감과 전체 모션 외관 승인은 아직 받지 않았다.

## 5. 반영 후 발견한 문제

**I1** — 초기 IK pole angle을 첫 프레임에만 맞춰 전환·횡이동 동작에서 관절 방향이 돌아갔다.

**I2** — Blender의 비활성 Screen 영역을 초기화하며 소유 Window가 없는 UI 갱신이 발생해 실제 창이 충돌했다.

**I3** — 손목 목표를 그대로 표시해 손잡이가 하박 끝에 놓였다. 사용자 U3의 지적이다.

**I4** — 비표시 렌더가 현재 프레임을 재평가해 미저장 컨트롤 변환을 원래 키로 되돌렸다.

**I5** — Windows에서 클라이언트가 읽는 응답 파일을 작업자가 교체하는 순간 파일 공유 잠금으로 종료되는 경우가 있었다.

**I6** — 다른 모델을 선택해도 캐시된 포즈 세션을 재사용하는 경로가 있었고, 상단 선택 경로를 자동 생성 작업본 경로로 덮어써 입력과 출력을 혼동시켰다.

**I7** — 화면에 실제 무릎/팔꿈치 대신 멀리 있는 IK pole 위치를 같은 모양으로 표시했다. 사용자는 실제 무릎에서 멀리 떨어진 노드를 지적했다. 기존 기본 자세의 약한 역방향 굽힘 때문에 방향 제어점이 뒤쪽에 생성된 사실도 확인했으나 원본 자세를 임의로 바꾸지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

U2: Blender 편집기를 여는 연결과 앱 내부 편집 중 후자를 선택했다. Asset Tool의 포즈 편집 패널, 드래그/회전/동작·프레임 선택/저장/출력/렌더 설정 전달로 구현했다.

U3: 손바닥 조작점을 별도로 배치했다. 기존 손목 작업본의 Action 위치 키와 양손 파지 오프셋도 변환해 기존 포즈를 보존했다.

U4: 새 파일 선택과 기존 세션 재사용을 구분하고, 원본 선택 경로와 작업본 저장 경로를 분리했다. 사용자가 명확히 한 실제 관절 위에 무릎 손잡이를 표시하도록 수정했다.

## 7. AI 해결 제안과 실제 해결 과정

I1: 프레임별 pole angle을 보정·키잉했다. 기존 35개 동작의 시작/중간/끝 불러오기 비교가 통과했다. I2: 활성 Screen만 다루고 실제 창의 초기화 완료 후 화면 설정을 수행했다. I4: 작업자의 메모리 Action에 미확정 편집 키를 유지하며, 명시 키 저장 전 프레임/동작 전환을 막았다. 파일은 작업본 저장 시에만 갱신한다.

I5: 요청/응답을 순번별 불변 JSON 파일로 전달하도록 수정했다. 미리보기 이미지 교체는 짧은 공유 잠금에 한해 제한된 재시도를 수행한다. 작업자 종료는 이전 오류로 가리지 않고 종료 코드와 로그 경로를 표시한다.

I6: 렌더에서 고른 최신 모델을 포즈 편집으로 전달하고 새 파일 선택을 캐시보다 우선한다. 찾기에서 열기를 누르면 해당 파일을 바로 읽는다. 상단은 선택 경로를 유지하며 하단에 작업본 경로를 표시한다. 미저장 작업은 자동 폐기하지 않는다. 샘플을 다시 열 때 이전 모델로 돌아가지 않게 상태를 구분했다.

I7: 관절의 평가 행렬로 화면 손잡이를 투영하고, 드래그는 내부 pole을 관절 축 주변으로 회전시킨다. `base_pose.blend`의 양 무릎을 사선/정면/측면/위 8개 조합에서 검사해 투영 오차가 0이었다. 25도 굽힘 방향 조정의 무릎 목표 오차는 약 0.00000006, 발 위치 오차도 약 0.00000007이었다. 실제 Pico2D/OpenGL 창에서 지정 파일명·선택 경로 유지와 사선 무릎 드래그→키/파일 저장→출력→렌더 전달을 확인했다. 전체 연속 모션 검증으로 확대하지 않는다.

확인 결과: Blender 기본 도형의 IK·발 고정·복사·양손 고정·동작 전환·저장/재로딩·출력 검사 통과. 기존 손목 작업본 35개 동작의 손바닥 이전 후 최대 행렬 성분 오차는 약 0.0000016이었다. 비표시 작업자의 기본 도형/실제 메카 편집·저장·출력·재개 통과. 기존 렌더/조립과 포즈 패널 자동 검사 **32개 통과**. 실제 Pico2D/OpenGL 창에서 손바닥 드래그→키 저장→파일 저장→동작 출력→렌더 설정 전달을 검사하고 화면을 확인했다. 로컬 메카 미리보기 응답은 약 0.4초였으며 일반 성능 기준이 아니다.

결과 코드는 `Tools/pose_tool/`, 내부 화면은 `Tools/asset_loader/pose_panel.py`, 독립 도형은 `samples/pose_tool/`다. 실제 모델/작업본/렌더 결과는 Git에 포함하지 않는다. 전체 연속 간섭·무기 핏·자유 시점 회전·고속 3D 미리보기·통합 결과 사용자 승인은 미검증이다.
