# PBR 방향 페이지 텍스처 배열 실험

- **기록 ID** `FDLOG-20261123-pbr-direction-arrays`
- 작업일 2026-11-23 KST.

## 1. 사용자가 제안한 것

- **U1** `PartPainter`의 PBR 방향 페이지를 배열로 묶어 바인딩을 줄인다. 화면과 64 MiB 한도를 보존하고, 같은 180기 입력·품질에서 바인딩·함수별 CPU 시간·GPU 시간·P99·FPS를 비교해 별도 커밋한다. 정확한 요청 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261123-pbr-direction-arrays:U1]]` 검색 단서는 `PartPainter의 PBR 방향 페이지도 텍스처 배열로`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 동일 입력에서 경로만 바꿔 정순·역순 실측을 수행하고 기준의 CPU 상태와 렌더 순서를 유지한다. 전체 화면 픽셀과 기존 예산을 각각 검사한다.

## 3. AI가 제안한 것

- **구현상 판단** 선적재하는 PBR 모션의 방향을 채널별 배열로 만든다. 방향 페이지 크기가 달라 큰 쪽으로 맞춰야 하므로 패딩도 아틀라스 예산에 포함한다. 인접 두 방향의 표면을 섞을 때 (sampler, layer)를 사용하고, 단일 방향과 기존 보조 셰이더는 동일 배열 저장소의 2D 뷰를 쓴다. 포맷이 섞이거나 추가 예산을 넘는 모션은 기존 경로를 사용한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 배열 후보를 구현·검증하라는 U1에 따라 시험했다. 기본 적용 여부는 화면과 성능 검사 결과를 기준으로 판단했다.

## 5. 반영 후 발견한 문제

- **I1** 본체를 포함해 패딩한 후보는 상주 방향 폴백이 달라졌다. 기본 180기 두 비교에서 방향 폴백이 32→78회, 33→79회였고, 캡처 프레임 41에서 플레이어 자세가 달랐다.
- **I2** 대부분의 실제 인접 뱅크는 각 채널의 폭·높이가 달랐다. Medium에서 별도 64 MiB 등 무기 번들도 채널별로 패딩이 필요했다. 같은 페이지가 맞물려도 2D와 배열에서 정규화된 텍스처 좌표를 계산하는 크기가 달라질 수 있다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 테스트는 180기, 15m 간격, HP 100,000, 자동 검 60Hz, FHD Medium/SMAA, 예열 120·계측 240프레임, VSync 끔 조건을 전후 동일하게 사용했다. 기본 실행과 등 무기만 배열화한 대조에서 같은 조건을 반복했다. 픽셀 검사에는 프레임마다 등 무기를 그리는 동일 조건을 별도로 적용했다.

## 7. AI 해결 제안과 실제 해결 과정

- 전체 배열 후보의 순서별 FPS는 44.79→33.01, 44.03→35.18이었다. 프레임 작업 P99는 31.94→48.30ms, 33.56→49.63ms였다. 등 무기만 배열화한 후보는 42.68→45.80, 38.51→43.38 FPS였고 P99는 38.87→34.62ms, 38.93→35.42ms였다. 등 무기 전용 수치는 별도 실행의 값이다.
- 240프레임 함수 상세 계측에서 등 무기 2방향 보간이 전후 236회였다. 제출당 `SDL_GL_BindTexture`는 12→1회, `glBindTexture`는 3→14회였다. 바인딩 합계는 15회로 같았다. 기존 2D는 텍스처 상태 스택으로 복원하고 배열 후보는 개별 복원 호출을 사용했다.
- 등 무기만 바꾼 상세 비교에서 CPU 포함 경과는 `PartPainter.paint` 0.239→0.335ms/프레임, 내부 `TexturedQuadPass.draw` 0.029→0.015ms/프레임, 바인딩 API 경과 합계 0.0175→0.0109ms/프레임이었다. GPU timestamp는 등 무기 2방향 제출당 0.0185→0.0408ms였다. 전체 후보에서 등 무기 GPU 평균은 0.0177ms여서 독립 실행의 GPU 경과를 직접적인 셰이더 비용으로 단정하지 않는다.
- 전체 후보 상세 비교의 CPU `PartPainter.paint`는 비각도 제출 1.095→1.685ms/프레임, 각도 깊이 0.428→0.477, 비등무기 각도 색상 0.249→0.301ms였다. 후자의 GPU 2·3·4뱅크 제출당 평균은 각각 0.364→0.677, 0.394→0.724, 0.395→0.701ms였다. 폴백으로 해당 제출 표본 수가 달라졌다.
- 64 MiB 등 무기 번들 논리 GPU 할당 최고치는 17.59→19.72 MiB였다. 배열 5개의 저장소가 약 19.55 MiB이며, 2D 뷰는 저장소를 참조한다. 이 수치는 드라이버 정렬을 포함한 물리 VRAM 측정과 구분한다.
- 전체 화면 RGB 35개 중 두 대조군 중 하나와 일치한 것은 전체 후보와 등 무기 전용 후보 모두 6개였다. 두 변경 전 대조의 차이는 3개였다. 대표 프레임 41에서 전체 후보는 22,796픽셀·최대 채널 차이 207, 등 무기 전용은 75픽셀·최대 차이 9였다.
- GPU 검사 14개가 통과했다. 배열에 할당된 픽셀, 패딩으로 인한 예산 거절, 2D 뷰 해제 후 마지막 페이지까지 유지되는 저장소를 검사했다.
- 실험은 하드웨어 벤치마크의 `--pbr-direction-arrays`로 재현한다. 게임 기본 경로는 기존 2D 방향 페이지를 사용한다. 원시 실행과 픽셀은 `output/performance/pbr_direction_arrays_20261123/`에 보관했다.
- 외장 GPU의 별도 검사에서 12개 유닛의 배열 바인딩이 GL 텍스처 상태 스택으로 복원됐다. 배터리·그래픽 전환 이후 GPU 재실행을 보류했다. 상태 스택을 연결한 후보의 전후 계측과 내장 GPU 실기는 미검증이다.
