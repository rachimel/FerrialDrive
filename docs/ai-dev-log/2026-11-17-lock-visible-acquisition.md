# 화면 내 주변 적 획득·록온 경계 반복 수정

- **기록 ID:** `FDLOG-20261117-lock-visible-acquisition`
- 범위: 2026-11-17 현재 세션. 개별 발언·검증의 정확한 시각은 미제공이다. [[FDLOG_MISSING_TIME:FDLOG-20261117-lock-visible-acquisition:scope]] 검색 단서: `완전히 벗어나려고 하면 카메라가 흔들리네`, `주변에 적이 보이면`.
- 상태: 구현·현행 명세·관련 자동 검사 완료. 실제 장치의 직접 조작감·사용자 승인·커밋·업로드는 미수행.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 화면을 완전히 벗어나려 할 때 카메라가 흔들린다고 보고하고, 새 획득은 주변에 적이 보이는 경우로 제한한다. 직전 거리 제한 제거·화면 이탈 해제의 후속 조정이다. 출처·시각은 scope를 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

- 획득 200m·조준 300m를 현행 규칙에서 제거하고 화면 가시성 후보로 교체했다. 기존 표적의 유지·플레이어 완전 화면 이탈 해제·마우스 최근접 순위·교체 1초는 유지한다.

## 3. AI가 제안한 것

- **구현상 판단:** 새 후보는 현재 화면과 플레이어 중심 화면 모두에 적 본체가 일부라도 보이는 경우로 제한한다. 록온 카메라 복귀 도중 보이는 다른 먼 적을 연쇄 획득하지 않도록 한다. 줌을 반영하고 피격 흔들림·이름·HP·무기/VFX는 제외한다.
- **구현상 판단:** 화면 이탈로 해제한 적의 허용 조건을 중간점 카메라의 플레이어 부분 노출에서 플레이어 중심 화면의 적 노출로 변경했다. 기체 포즈에 따른 표시 폭 변화로 조건이 반복 반전되는 것을 막는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 화면 내 주변 적 제한은 U1의 요구다. 본체 사각형·플레이어 중심 화면 확인 등 세부 구현과 최종 사용감의 별도 사용자 수용은 아직 없다.

## 5. 반영 후 발견한 문제

- **I1:** 이전 구현에서 기체 표시 폭을 동작처럼 변화시키며 15초·900프레임을 재현하자 초기 획득을 포함한 상태 전환이 15회였다. 해제한 적이 중간점 화면에서 다시 허용돼 카메라 목표가 반복 변경됐다. 사용자 실제 입력 기록은 없으며, 같은 증상을 만드는 구현 경로를 재현한 결과다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1의 화면 제한을 `MovementHud`에 연결하고 `MouseAutoTargeting.acquisition_ids`로 전달했다. 기존 거리 기반 일반 UI 시연 호출은 호환 경로로 유지한다. 조준은 탄 퍼짐만 줄이며 후보 화면 범위는 같다.

## 7. AI 해결 제안과 실제 해결 과정

- I1의 재허용 조건을 플레이어 중심 화면 기준으로 변경했다. 새 후보 전체에도 주변 조건을 적용해 다른 먼 적을 번갈아 획득하는 경로를 막았다.
- 같은 15초 재현에서 상태는 초기 록온→68프레임 해제의 2회만 기록됐다. 이후 재획득은 없었고 카메라는 플레이어 방향으로 계속 복귀했다. 근거: `output/performance/lock_visible_acquisition_20261117/before.json`·`after.json`.
- 관련 자동 검사 **47개 통과**. 부분 노출/완전 이탈·줌·일반/조준 동일 획득·거리와 독립된 화면 후보·기존 표적 유지·인접 먼 표적 추가 시 반복 방지·카메라 복귀 방향·다수 적 전투 연결을 확인했다.
- 실제 low Combat·SMG 45프레임 실행이 정상 종료했다. 마지막 주변 화면 조건 추가 뒤 준비 5·측정 20프레임의 최종 실행도 정상 종료했다. 근거는 같은 출력 경로의 `combat_final/report.json`이다. 성능 비교나 직접 조작 사용감 판정과 구분한다.
