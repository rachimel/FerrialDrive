# UI v2 카운터 간격·방향성 강화와 전환 흔들림 보정

- 대화 범위: 2026-11-12 KST. 개별 요청 시각 미확인 [[FDLOG_MISSING_TIME:FDLOG-20261112-ui-v2-motion-stability:scope]] — 현재 대화에서 “간격 축소”, “방향성 더 강하게”, “뭔가 흔들리거든” 검색.
- 근거: 사용자 요청·UI 시간 곡선·GPU 필터 코드·자동 검사와 실제 OpenGL 렌더.
- 상태: 반영·자동 검사·GPU 중심 안정성/재생 확인. 사용자 직접 조작·최종 외관 수용 미확인.

## 1. 사용자가 제안한 것

- **U1:** HIT·누적 데미지 간격을 더 줄이고 로드아웃·무기 교체 방향성을 강화한다.
- **U2:** 전환·로드아웃 애니메이션이 흔들려 보이니 수정한다. 판단 근거는 사용자의 실행 화면 체감이다. 추가 배경과 개별 발언 시각은 위 범위를 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1은 두 카운터의 간격과 두 전환의 GPU 블러 설정에 반영했다. U2는 필터가 표시 중심을 밀고 끝점에서 블러가 갑자기 꺼지는 원인을 먼저 수정했다.

## 3. AI가 제안한 것

- **구현상 판단 A1:** 기준 Y 266/376→276/366으로 간격 110→90px를 줄이면서 중앙은 유지한다. 크기 배율 0.9는 유지한다.
- **구현상 판단 A2:** 무기 블러는 샘플 49·셔터 0.075초·세기 0.9·상한 24px, 로드아웃은 별도 v2 설정의 샘플 49·셔터 0.075초·세기 0.85·상한 48px로 조정한다. 기존 v1 잔상 설정은 변경하지 않는다.
- **구현상 판단 A3:** 대칭 가중 커널로 표시 중심을 고정하고, 과거 시간창의 평균 변위 대신 현재 easing 곡선의 순간 속도를 사용한다. 실제 카드 이동 곡선·순서·시간은 유지한다. 작업 중 원인과 보정 방향을 설명했다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1~A3의 구체적 수치와 보정 후 외관에 대한 사용자 응답은 아직 없다.

## 5. 반영 후 발견한 문제

- **I1:** 기존 한쪽 샘플 커널은 번짐 크기 변화에 따라 밝기 중심을 이동시킨다. 또한 뒤쪽 시간창의 변위가 종료 직전까지 남아 있다가 정지 상태에서 0으로 바뀐다. 코드 분석과 GPU 중심 검사로 보정 대상을 확인했다.
- **I2:** 추가한 순간 속도 수치 검사에서 곡선의 최대 기울기 지점에 유한 차분 오차가 발생했다. 차분 간격을 1e-6→1e-8로 줄여 제품 코드와 검사 근사 오차를 구분했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1에 따라 카운터 간격을 줄이고 두 블러를 강화했다. U2에 따라 I1을 보정했다. 01·02 위치, 두 카드의 동일 높이·대응 변 길이와 전환 중 선택 규칙은 유지한다.

## 7. AI 해결 제안과 실제 해결 과정

- A3: GPU 커널을 이동축 양쪽의 대칭 가중치로 바꾸고, `WeaponSwapVisual.velocity`와 `LoadoutVisual.velocity()`를 추가했다. 시작·끝·로드아웃 반환점에서 순간 속도와 블러 폭이 0이 되므로 종료 때 잔여 블러가 갑자기 사라지는 차이를 줄인다.
- v2 자동 80개·기존 로드아웃 13개·실제 OpenGL 필터 5개, 합계 98개 통과. 다양한 블러 폭에서 밝기 중심의 이동이 0.1px 미만임을 확인했다. 순간 속도와 원래 곡선의 수치 미분 일치·구간 경계 0·필터 연속성·상태 복원·자원 수명을 검사했다.
- 실제 OpenGL 로드아웃 31·무기 교체 13프레임을 생성하고 중간 프레임 모음을 직접 열었다. 카운터 표시 범위 Y 288~432·중앙 360을 재확인했다. 결과는 `output/ui_unit_test_v2/equipment_stable/`과 `output/ui_unit_test_v2/counter_compact/`에 둔다.

- 코드·설정·문서·자동 검사·실제 OpenGL 확인 완료. 전체 화면의 모든 흔들림이 해소됐다는 사용자 확인이나 실제 GPU 시간 계측으로 확대하지 않는다. 커밋·업로드 상태는 Git 기록을 따른다.
