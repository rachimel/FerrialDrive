## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 일시정지 호버의 연결부 Breathing·왼쪽 이동, 제목 확대, 메탈릭 베젤 텍스처. 후속으로 광택 축소·베젤 두께 축소·중앙에서 퍼지는 광택·푸른 기를 크게 줄인 회색을 요청했다.
  - 이유·판단 근거: 사용자가 초기 생성 광택이 작위적이라고 지적했다. 출처는 현재 대화와 TIME(scope).
- **사용자 제안 2 (U2):** 타이틀은 첨부 스케치를 바탕으로 START 아래 서브 메뉴가 펼쳐지며 나머지 메뉴가 내려가는 구성이다. SUITE를 사용하고 Hover 자간을 최종 12px로 지정했다. 배경은 미정이며 미구현 항목은 비활성으로 두는 선택을 명시했다.
  - 이유·판단 근거: 스케치의 옆 배치를 세로 펼침으로 정정했고 Hold의 의미를 Hover로 확인했다. 로컬 참조 사본은 `data/images/ui/concepts/title_layout_20261117.png`다. 출처는 현재 대화와 TIME(scope).
- **사용자 제안 3 (U3):** 설정 등 팝업은 일반 사각형·테두리 제거·등장 애니메이션·SmoothStep. 안내 두 줄과 선택 문구를 지우고, 재시작 필요 설정을 변경했을 때만 뒤로·저장 사이에 안내한다.
  - 이유·판단 근거: 첨부 화면의 두 문장을 삭제 대상으로 지정하고 안내 위치를 후속 정정했다. 출처는 현재 대화와 TIME(scope).

  - 이유·판단 근거: Standby 표시의 색 변화 요청이다. 출처는 현재 대화와 TIME(scope).

## 2. 사용자 제안 중 AI가 수용한 것

- U1~U4를 수용했다. 베젤은 5회 생성·수정 중 마지막 회색 후보를 연결했고 동적 표면·글자·발광은 분리했다. 타이틀 실제 게임 기능은 추가하지 않았다.
- 재시작 필요 항목 목록은 현재 비어 있다. 두 실제 설정은 즉시 적용이며 임의로 재시작 대상으로 바꾸지 않았다. 향후 등록 필드의 저장값/작업값 차이를 판정하도록 구현했다.
- 수용·반영 출처는 현재 진행 보고와 TIME(scope)다. 구현 완료와 결과의 사용자 승인은 구분한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 팝업을 페이드인하면서 중앙에서 약하게 확대하는 등장 방식을 제시했다. 갑작스러운 출현을 줄이기 위한 판단이다. 출처는 현재 대화와 TIME(scope).
- **구현상 판단:** 일시정지 호버 이동 8px/0.14초, Breathing 1.4초, 제목 48px. 타이틀 펼침 144px/0.2초, 호버 0.18초. 팝업 배율 0.97→1/0.16초. 모두 이동·등장은 기본 SmoothStep을 사용한다. 자간 12px는 사용자 지정값이다.
- **구현상 판단:** Standby Trail만 기존 에너지 표시색과 빨강을 65% 추가 혼합하고 UI·기체·전신 잔상은 기존 표시 경로를 유지한다. 실제 검증 색은 에너지 `#B1C8DD`, Trail `#E4707A`다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 사용자는 팝업 등장에 SmoothStep을 명시했다. 세부 확대 배율·시간과 호버 이동량·호흡 주기의 최종 외관 승인은 아직 없다.
- 일시정지의 연결부→패널→글자 순서 등장안은 여전히 제안 단계다. 이번 팝업 등장 구현과 혼동하지 않는다.

## 5. 반영 후 발견한 문제

- **I1 — 생성 후보:** 초기 금속 베젤의 광택·두께·푸른 기에 사용자 정정이 있었다. 각 후속 결과는 이전 후보를 자동 승인한 것으로 보지 않는다.
- **I2 — 검증 실행부:** 지정 입력 모드는 실제 마우스를 차단하므로 해당 모드에서 이벤트를 주입한 검증은 유효하지 않았다. 일반 창 검증에서는 외부 포인터/포커스가 개입했다. 이를 제품 기능 오류와 구분하고 화면 없는 실제 SDL 입력 검증으로 재확인했다.
- **I3 — 후속 UI 요구:** 고정 설명과 선택 문구는 사용자가 제거를 요청했다. 재시작 안내를 항상 띄우는 방식은 채택하지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1: 광택을 줄이고 얇게 만든 뒤 중앙 반사광·거의 무채색 회색으로 수정했다. 원본은 수정하지 않았고 선택된 이미지 사본은 `data/images/ui/pause_menu/bezel_v005.png`다. 실제 표시 크기로 확인했다.
- I3 ↔ U3: 설명 두 줄·선택 문구를 삭제했다. 필요 항목의 실제 변경에만 뒤로·저장 사이 중앙에 `다시 시작시 적용`을 표시하며 현재 기본 설정에서는 표시하지 않는다. 적용 중·오류 표시는 보존했다.
- U2에 따라 NEW GAME·SURVIVAL·LOAD는 비활성이다. CONFIG와 EXIT는 기존 동작에 연결한다.

## 7. AI 해결 제안과 실제 해결 과정

- 일시정지 표현/호버, 타이틀 메뉴/호버, 팝업 표시값과 설정 입력을 분리했다. 입력 Rect를 고정하거나 실제 펼침 위치와 함께 갱신하여 표시 변환 때문에 클릭 포획이 흔들리지 않도록 했다. 팝업 등장 중에는 클릭을 포획하지 않는다.
- I2의 재검증에서 실제 SDL 마우스 이벤트로 호버 진입·복귀·영역 밖 놓기 취소·계속 버튼 재개를 확인했다. 35개 동작 캡처와 상태 기록을 남겼다. 사용자가 직접 조작한 검증은 아니다.
- 최종 관련 검사 **153개 실행, 148개 통과·선택 검사 5개 제외**. 팝업 전환/재진입/입력 차단, 재시작 조건, 타이틀 펼침·빠른 반전·자간·이동한 CONFIG 입력, Trail/잔상 색 분리를 포함한다.
- 실제 SDL 렌더로 타이틀 닫힘·중간·펼침·자간과 팝업 등장·완료 화면을 확인했다. 팝업 네 모서리 바탕 픽셀이 같고 바깥 테두리가 없음을 확인했다.
- 실제 기체·OpenGL로 일반/Standby 검 Trail을 같은 공격 시점에 캡처했다. 일반 `#A0E6FF`, Standby Trail `#E4707A`가 실제 생성 조각에 기록됐다. 일반·발동·무지개 Overdrive 색 선택 검사를 통과했다.
- 출력·검증 프로그램은 `output/ui_review/pause_menu_20261117/`에 둔다. 금속 원본과 생성 조건은 로컬 `data/images/ui/pause_menu/`에 보존하며 Git 제외를 확인했다. 필수 실행부가 `output/`에 의존하지 않는다.
