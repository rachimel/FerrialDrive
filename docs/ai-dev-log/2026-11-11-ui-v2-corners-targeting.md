# UI v2 꼭짓점 테두리·적 3기·R 획득

- **기록 ID: ui-v2-corners-targeting**. 원래 대화·구현·정리 범위: 2026-11-11 KST, 현재 대화.
- 개별 발언의 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:ui-v2-corners-targeting:scope]] 검색 단서: `꼭짓점에 모일수록 두껍게`, `적은 3개`, `R 표적 교체는 기존 록온 획득 기능 요구사항에 맞게 변경`.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1)**: 미니맵·대화창의 테두리를 꼭짓점에 가까워질수록 두껍게 한다. 의도는 요청한 외형이며 별도 이유는 제시하지 않았다.
- **사용자 제안 2 (U2)**: 적 3기를 기존 위치·오른쪽·위쪽에 놓고 대화창의 가림을 연출한다. 근거: 현재 구현 요청과 배치 확인 응답.
- **사용자 제안 3 (U3)**: R 교체를 기존 록온 획득 요구사항에 맞춘다. 근거: 현재 요청과 `docs/ranged_targeting.md`.
- **사용자 제안 4 (U4)**: 좌상단·우하단에 가까워질수록 두껍게 하고 가늘어지는 형태에 곡선을 제안했다. 의도는 후속 요청의 외형이며 별도 이유는 제시하지 않았다. 출처: `좌상단이랑 우하단`, `선형으로 하지 않고 곡선`.
- **사용자 제안 5 (U5)**: 미니맵·대화창을 조금 키우고 대화창을 위로 많이 올린다. 근거: 현재 후속 요청. 별도 이유는 제시하지 않았다.
- **사용자 제안 6 (U6)**: 가는 테두리 구간을 줄이고, 대화창을 조금 내린 뒤 맵을 정렬한다. 이후 미니맵 여백을 대화창보다 작게 요청했다. 근거: 현재 후속 발언.
- **사용자 제안 7 (U7)**: 무기 패널의 임시 3D 회전 효과를 삭제한다. 근거: 현재 후속 요청.
- **사용자 제안 8 (U8)**: 테두리의 픽셀 계단을 필터링하고, 꼭짓점에서 약 3px는 최대 굵기를 유지한다. 근거: 현재 후속 요청.

## 2. AI가 제안한 것

- **AI 제안 1 (A1)**: 왼쪽·오른쪽·위쪽에 한 기씩 두고, 위쪽 적과 록온 표시 일부를 대화창이 덮는 배치를 제시했다. 목적은 가림 대상·배치 해석을 확인하는 것이다. 출처: 현재 대화의 배치 확인 질문.
- **구현상 판단**: 최대 두께 5px·곡선 변화 180px·8분할·2배 렌더/선형 축소, 샘플 획득 거리 330/460px·동률 1도는 조절 가능한 값이다. 본편 밸런스 승인으로 취급하지 않는다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U8을 구현했다. 공통 테두리 형상, 필터 렌더러, 적별 샘플 상태, 입력 없는 재사용 획득 모듈로 책임을 나눴다. 최종 테두리는 좌상단·우하단의 3px 구간을 최대 두께로 유지하고 SmoothStep 곡선으로 가늘어진다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1은 사용자가 `그 배치로 진행`으로 명시 수용했다. 수정본 외관과 샘플 수치에 대한 최종 승인은 확인하지 않았다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1)**: 첫 렌더에서 오른쪽 표적 HP가 카운터와 겹치고, 대화창이 위쪽 록온 대부분을 덮었다. AI가 이미지를 열어 확인했다.
- **문제 2 (I2)**: HP 보존 검사에서 전체 후보 소진 후의 새 각도 우선 순서를 누락한 예상값 때문에 검사 1개가 실패했다. 선택 로직의 결함은 아니었다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1·I2에 대한 별도 사용자 해결 제안은 이 기록 작성 시점까지 없었다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 오른쪽 적을 (920,460)으로 옮기고 대화창을 y=44로 올렸다. 재렌더 이미지를 열어 오른쪽 HP 겹침 해소와 상단 록온 일부 노출을 확인했다.
- I2: 새 순환에서 현재 각도·거리로 재정렬한다는 명세에 맞춰 검사 예상 순서를 수정했다.
- U4 후속 반영: 두 강조점만 5px로 유지하고 다른 꼭짓점을 1px로 바꿨다. 변화 구간은 8분할한 SmoothStep 곡선으로 만들었다. 이 외형의 사용자 승인은 확인 전이다.
- U5 후속 반영: 구현상 판단으로 미니맵 논리 크기를 240×160, 대화창을 (360,8)의 560×130으로 조정했다. 기존 0.9배 미니맵 표시 배율은 유지한다. 개별 수치와 수정본 외관의 사용자 승인은 확인 전이다.
- U6 후속 반영: 곡선 구간을 180px까지 늘려 가는 구간을 줄였다. 최종 미니맵 위치는 (20,20), 대화창은 (360,28)로 맞춰 미니맵의 여백을 더 작게 했다.
- U7: 별도 커서 회전은 없음을 확인하고 입체적으로 보이던 카드 위/아랫변 기울기와 글자 변형을 제거했다. 옆변 사선과 비활성 크기는 유지한다.
- U8: 꼭짓점의 3px 유지 구간을 추가하고 패널 면/테두리를 2배 렌더·선형 축소한다. 위치·투명도와 분리한 32개 LRU 텍스처와 렌더 상태 복원·종료 해제를 구현했다.
- 자동 검사: 기존 UI 포함 81개와 표적 획득 7개, 총 **88개 통과**. 실제 SDL에서 중간 밝기 픽셀·캐시 재사용·예외 시 렌더 상태 복원·자원 해제를 확인했다. 별도 Pico2D/SDL dummy의 **8개 상태 렌더**와 합성 R/D/T/F1/Esc 입력·정지 중 R 차단을 확인했다. 오른쪽·상단 가림 전후·도움말 이미지를 직접 열어 검토했다.
- 재사용 모듈은 구현했고 전투 프로토타입 연결은 하지 않았다. 실제 창 직접 조작·Runner 드롭·사용자 외관 승인·업로드는 미수행이다. 출력은 재생성 가능한 `output/ui_unit_test_v2/corner_targeting/`이며 공개 파일에 포함하지 않는다.
