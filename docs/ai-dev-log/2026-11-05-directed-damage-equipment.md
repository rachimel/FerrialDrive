# 공격 방향·연속 피해 배치와 무장 HUD 조정

- 기록 ID: `FDLOG-20261105-directed-damage-equipment`
- 기록 기준 시각: 2026-11-05 03:28:13 KST(작업 중 시계 확인). 현재 대화의 요청·후속 정정을 함께 정리한다.
- 출처: “데미지 인디케이터의 전반적인 크기를 25%”, “공격이 뻗는 방향 쪽(적 너머)”, “연속 적중할수록 배치 범위가 넓어짐”, “10%만 줄이자”, “무기 이름 폰트 크기 10% 키우자”.
- 개별 요청·정정·구현의 정확한 시각은 모른다. [[FDLOG_MISSING_TIME:FDLOG-20261105-directed-damage-equipment:scope]] 보완 시 위 검색 구절과 일시정지/무기 이름 폰트 요청의 원문 시각을 확인한다. 아래 U1~U7/A1에 공통 적용한다.
- 상태: 코드·설정·명세 반영, UI 자동 검사 55개 통과, Pico2D SDL dummy 렌더링 확인. 실제 창 직접 조작·최종 시각 승인·커밋·업로드는 미수행이다.

## 1. 사용자가 제안한 것

- U1: 개별 피해 숫자를 처음에는 25% 축소하도록 요청했다가 **기존 대비 10% 축소**로 정정했다. 크기 기준은 최신 정정을 따른다.
- U2: 숫자를 적 중심에서 공격 방향의 ±45도, 총 90도 범위에 배치한다. 방향 질문에 “적 너머”를 선택했다.
- U3: 이후 처음에는 0도에서 시작해 점점 90도로 퍼지도록 요청했다. 시간에 따라 숫자가 이동하는 방식과 구분하는 질문에 **연속 적중할수록 배치 범위가 넓어짐**을 선택했다.
- U4: 무기 이름과 01·02 번호에 Ferrial HUD를 시험하고, 오른쪽 여백이 아래보다 큰 웨폰 카드를 옮겨 두 여백을 맞춘다. 번호 패널도 새 글꼴에 맞춰 크기를 조정하고 카드 오른쪽 끝과 정렬한다. 여백 불일치는 사용자가 직접 지적했다.
- U5: 일시정지 제목에도 Ferrial HUD를 시험한다. 첨부 화면의 기존 제목이 대상이다.
- U6: 무기 이름은 후속 요청에서 **가물치 고딕**으로 바꾸고 다시 **크기를 10% 확대**한다. Ferrial 무기 이름 시험안보다 이 정정을 우선한다. 탄약 숫자의 크기 변경은 요청하지 않았다.
- U7: 이번 조정으로 게임의 기본 테마가 어느 정도 정해진 것 같다고 평가했다. 이를 새 화면의 최종 시각 승인이나 본편 검증 완료로 확대 해석하지 않는다.
- U1/U4~U6의 구체적인 크기 비율·폰트 선택에 대한 추가 판단 근거는 제시되지 않았다. [[FDLOG_MISSING_REASON:FDLOG-20261105-directed-damage-equipment:style-values]] 보완 시 “10%만 줄이자”, “가물치 고딕”, “일시 정지 폰트도” 전후의 직접 설명을 확인한다. 요청한 시각 방향 자체와 불명인 추가 이유를 구분한다.

## 2. AI가 제안한 것

- A1: 첫 비교값으로 **1/2/3/4타의 전체 배치 범위를 0/30/60/90도**로 설정하고 4타부터 최대 범위를 유지한다. 4타와 초기 반경 48~84px는 구현상 판단이며 사용자 확정 수치가 아니다. 설정으로 조절한다.
- 같은 대상의 마지막 숫자까지 사라지거나 명시적으로 제거되면 연속 적중 상태를 초기화한다. 기존 숫자는 옮기지 않고 새 숫자의 중심 각도 범위만 넓힌다. 재사용 모듈은 방향을 입력받고 테스트 실행부만 마우스로 가짜 방향을 공급한다.
- 숫자 전체가 최대 ±45도 안에 있도록 완료 크기를 예약하고, 6px 간격으로 다른 피해 숫자를 피한다. 시작 0도는 숫자 중심의 방향이며 글자 자체를 선으로 압축하지 않는다.
- 색·폰트 역할·HUD 기본 배치가 잡혔다는 평가에 동의하되 실제 전투 배경과 이펙트 위의 가독성은 다음 확인으로 남긴다고 설명했다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U6을 반영했다. 전체 피해 배율은 0.9이며 자릿수 배율과 곱한다. HIT·누적 DAMAGE 크기는 이 조정의 대상이 아니다.
- `DamageNumbers.add(direction=...)`는 화면 기준 오른쪽 +X·아래 +Y 벡터를 정규화하고 owner별 연속 적중을 센다. 본편은 대상별 고유 owner와 실제 공격 방향을 제공한다. 방향 생략 시 기존 주변 분산 동작을 유지한다.
- 테스트는 플레이어 중심에서 유효 마우스 위치로 향하는 마지막 2차원 방향을 사용한다. 하단 디버그 영역·버튼·창 밖·전환·일시정지 중 방향 갱신을 멈춰 피해 버튼을 누르면서 조준이 바뀌지 않게 했다. 플레이어 피격 숫자는 기존 주변 분산을 유지한다.
- 무기 이름은 가물치 무료고딕 14px 역할의 표시 배율을 활성 1.0→1.1, 비사용 0.8→0.88로 바꿔 정확히 10% 확대했다. 스왑 중에도 연속 보간하며 이름 배경 크기·긴 이름 폭 제한은 실측 결과를 따른다. 탄약은 기존 가물치 48px·비사용 0.5배다.
- 일시정지는 Ferrial HUD Square Wide 26px, 번호는 같은 폰트 14px다. 웨폰 카드 오른쪽·아래 여백은 모두 16px로 맞췄다. 번호는 실측 최대 크기에 좌우 8px·상하 4px 패딩, 사이 간격 6px를 적용해 오른쪽 끝에 정렬한다. 현재 SDL 실측 탭은 40×23px다.

## 4. AI 제안 중 사용자가 수용한 것

- 사용자는 전방 방향과 연속 적중에 따른 범위 확장을 명시적으로 선택했다. 이는 U2/U3의 확인 응답이다. A1의 4타·반경·수명 연동 초기화와 최종 화면에 대한 별도 승인은 아직 확인하지 않았다. 기본 테마 평가를 세부 수치 승인으로 간주하지 않는다.

## 5. 반영 후 발견한 문제

- 이번 조정 뒤 확인한 기능 검사 실패는 없다. 25%→10%, Ferrial 무기 이름→가물치는 사용자 요구 정정이며 구현 버그로 분류하지 않는다.
- 실제 전투 상태·공격 방향 연결과 직접 창 조작은 미확인이다. 기존과 마찬가지로 다른 HUD·기체·화면 경계 회피는 구현하지 않았고 피해 숫자끼리의 겹침만 회피한다. 연속 숫자가 많으면 생성 반경이 커질 수 있다.

## 6. 사용자 해결 제안과 실제 해결 과정

- 여백 불일치에는 U4의 동일 여백·우측 정렬 요구를 적용했다. 폰트·크기·배치 범위의 후속 정정은 U1/U3/U5/U6 순서로 현행 기준에 반영했다. 직접 조작에 따른 추가 문제 보고는 이번 기록 시점까지 없다.

## 7. AI 해결 제안과 실제 해결 과정

- 방향이 있는 새 숫자는 현재 연속 적중 단계의 각도 안에서 후보를 찾고, 완성 글자 크기·장면 이동 폭을 예약한다. 다른 숫자와 겹치면 반경을 늘린다. 기존 숫자의 위치는 유지한다. 피해 표시·플레이 흐름·설정·렌더링 책임은 분리했다.
- UI 자동 검사 55개 통과: 자릿수별 0.9배, 8방향 연속 피해·6px 간격·기존 위치 고정, 0도 시작·점진 확장·대상별 독립·만료/clear 초기화, 디버그/정지 중 방향 유지, 카드 여백과 폰트 실측 번호 크기·정렬을 확인했다.
- 실제 Pico2D(SDL dummy)로 전방·상방·좌방 피해, E 스왑 중간/완료, F 전환, 일시정지를 렌더링했다. 로컬 확인 자료는 `output/ui-polish/`에 둔다. 실제 사용자 창 조작이나 GPU 성능 측정 결과는 아니다.
- PRE-PRD·UI 명세·샘플·폰트 안내·작업 정리·검사 안내와 기록 인덱스를 최신 결정에 맞췄다. 이전 자료와 폰트 원본은 보존했다.
