# DCC 연결과 12fps 수동 후보정 인계

기록 ID: **2026-11-09-dcc-animation-edit-handoff**. 확인 시각: 2026-11-09 13:24:48 KST.
개별 사용자 발언 시각은 미확인 [[FDLOG_MISSING_TIME:2026-11-09-dcc-animation-edit-handoff:scope]]. 같은 대화의 ‘설치하고 Blender 연결’, ‘후보정은 내가’, ‘지금 이거 계속하고’로 보완한다.

## 1. 사용자가 제안한 것

- **U1**: DCC-MCP 설치와 Blender 연결 확인 후 기존 수정 계속.
- **U2**: 모든 동작의 손목 문제, 칼집 각도, 발도, 적극적인 달리기, 시작/끝 유지 포즈를 수정하고 재생을 12fps로 변경.
- **U3**: 애니메이션 후보정은 직접 수행하므로 방법만 안내하되 현재 작업은 계속.

## 2. AI가 제안한 것

- **A1, 구현상 판단**: 기존 리그와 파지를 보존하며 팔꿈치 방향과 전완 회전을 함께 풀어 손목에 집중된 회전을 줄인다. 모델·웨이트 변경 없이 수치 포즈와 공통 보정 모듈을 재사용한다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1-U3 반영. 기본 보정과 12fps 작업본을 인계하고 추가 연출 후보정은 사용자에게 남긴다.

## 4. AI 제안 중 사용자가 수용한 것

- A1의 구체적인 수치와 최종 외관은 사용자 승인 전이다. 작업 계속 승인을 외관 승인으로 취급하지 않는다.

## 5. 반영 후 발견한 문제

- **I1**: 기존 WristSwivel의 고정 회전과 독립 손 목표가 과도한 손목 굽힘을 만들었다. 검 대기 표본은 팔꿈치 재계산만으로 약 154도에서 50도로 감소했다.
- **I2**: 발도/수납은 단순 손목 보정으로 해결되지 않는다. 검→총 469~475, 총→검 495~501 및 503 프레임의 왼손 굽힘이 남았다. 인출 길이와 연속 간섭도 승인하지 않았다.
- **I3**: 장시간 저장·재검사 호출은 전송 시간 제한에 걸렸지만 작업은 완료됐다. 재실행하지 않고 같은 인스턴스의 상태와 생성 메타데이터로 완료를 확인했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U3에 따라 추가 연출 후보정은 중단하고 파일 안의 ‘후보정_안내’와 확인 마커로 인계했다. 모든 프레임에 키가 있는 FK 작업본임을 명시했다.

## 7. AI 해결 제안과 실제 해결 과정

- DCC-MCP CLI 0.20.53, Blender 어댑터 0.1.43 설치. 작업용 백그라운드 Blender 5.2.3에서 실제 장면 조회·열기·수정·저장·렌더 호출 확인. 사용자의 기존 Blender 창을 제어한 것은 아니다.
- 재사용 조사: 기존 리그/공통 출력 경로 선택. Rigify·Retarget은 기존 리그를 바꾸거나 외부 모션을 전제로 해서 미채택. 조사 근거는 로컬 `output/dcc_setup/reuse_decision.json`.
