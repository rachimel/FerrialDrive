# SMG 버스트 분리·부스트 어택·대시 마찰음

- **기록 ID:** `FDLOG-20261117-smg-split-boost-attack-dash-gain`
- 기록·검증 확인: 2026-11-17 13:15 KST. 개별 발언 시각은 미제공이다. [[FDLOG_MISSING_TIME:FDLOG-20261117-smg-split-boost-attack-dash-gain:scope]] 검색 단서: `jet_boost.ogg`, `GEN3는 짧게 나눠`, `어택만 앞으로`, `쓸리는 음 게인`.
- 상태: 구현·설정·실제 SDL 더미 믹서 녹음·관련 자동 검사 완료. 실제 장치 청취·사용감 승인·커밋·업로드는 미수행.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 새 `jet_boost.ogg`를 제작했다고 알렸다. 직전의 음원 연결 작업에 이어 제공한 파일로 보고 시험 연결했다. 명시적인 교체 명령과 맥락상 해석을 구분한다.
- **사용자 제안 2 (U2):** GEN_3는 버스트이므로 짧은 여러 파일로 나누고 무작위 재생하는 방향을 제시했다. 이유는 원본이 단발 음원이 아니기 때문이다.
- **사용자 제안 3 (U3):** 부스트 발동음에 지연이 느껴져 어택을 앞으로 당기는 방법을 제시했다.
- **사용자 제안 4 (U4):** 대시 쓸림음 게인을 약간 낮춘다. 추가 수치·이유는 제시하지 않았다. 발언 출처·시각은 scope를 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1의 파일을 `data/source/audio/sources/jet_boost.ogg`에서 확인하고 기존 부스트의 원본 대체 후보로 연결했다.
- U2에 따라 GEN_3 전체 반복을 중단하고 짧은 WAV 4개를 실제 발사 사건에 연결했다. 기존 재생기의 직전 후보 제외 무작위 선택을 사용한다.
- U3에 따라 발동 사건을 바꾸지 않고 약한 앞부분 0.29초만 제외했다. U4는 대시 활성 상태에서만 마찰음 gain 0.85를 적용했다.

## 3. AI가 제안한 것

- **구현상 판단:** 5ms 파형 RMS와 피크 변화를 보고 앞부분의 강한 타격 4구간을 `[0.022,0.066]`, `[0.102,0.138]`, `[0.175,0.207]`, `[0.249,0.280]`초로 추출했다. 결과 길이는 44.01·36.01·32.02·31.00ms다. 청취로 단발 분리 품질을 승인한 결과는 아니다.
- 샘플은 기존 import의 peak 0.58 정규화·앞 3ms/끝 15ms 페이드를 사용하며 사건 음량은 0.85다. 원본 버스트와 이전 연결은 보존했다.
- **구현상 판단:** 부스트는 RMS 주음이 원본 약 0.30초에서 커지는 점을 근거로 0.29초를 줄였다. 새 시작 앞 3ms만 페이드하고 정규화·끝 페이드·피치 편집은 하지 않았다. 대시 마찰의 15% 감소는 작은 조정의 첫 시험값이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 버스트 분리·무작위 선택·부스트 어택 조정·마찰음 감소는 U2~U4의 요구다. 구간·후보 수·0.85 배율·최종 음색의 별도 사용자 승인은 아직 없다.

## 5. 반영 후 발견한 문제

- **I1:** 이전 AI가 길이만 비교해 GEN_3 버스트 전체를 단발마다 재생한 선택이 부적절했다. U2의 정정으로 단발 후보 추출로 바꿨다. 이전의 클리핑 검사 통과가 사건 단위 적합성을 보장하지 않았다.
- **I2:** 원본 부스트의 주음이 늦게 커진다는 U3의 피드백을 받았다. 10ms RMS 기준 최대 RMS의 50% 도달은 원본 0.30초였다. 물리 오디오 장치의 입력 지연을 측정한 값과 구분한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U2: 짧은 파일 여러 개를 만들고 발사마다 하나를 선택하도록 했다. 원본 전체 재생 별칭은 활성 사건에서 제외했다.
- I2 ↔ U3: 주음 앞부분만 당겼다. 준비 종료·부스트 시작 사건·부스트 움직임/속도는 유지했다.
- U4: 기존 두 마찰 레이어 비율을 유지하며 대시에서만 동시 감쇠한다. 다른 상태의 쓸림은 gain 1로 복귀하며 자갈·지속 분사·새 부스트 발동음은 이 배율로 바꾸지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

- `sound-import --regions`에 범위 내 비중첩 오름차순 구간 JSON을 지원했다. 단순 추출용 `--trim-only`는 정규화·끝 페이드 없이 앞 3ms만 페이드한다. `sound-preview --only boost`의 단독 기록 경로도 연결했다.
- 부스트 원본 1.87812→후보 1.58812초. 10ms RMS의 50% 도달은 약 0.30→0.01초다. 새 시작의 3ms를 제외한 PCM 꼬리와 sample peak가 원본 선택 구간과 일치했다. cooldown 0.12초·레이어 음량 0.85·재생률 변주 0.015를 유지했다.
- 대시 설정은 공통 bank의 `motion.dash_scrape_gain=0.85`이며 `MovementSoundCues`가 대시 활성 여부로 적용한다. 대시→다른 쓸림·부스트 전환 시 gain 복원을 자동 검사했다.
- 실제 SDL 더미 믹서에서 24회 선택 중 직전 반복 0·네 후보 모두 선택, 부스트와 다른 사건 보존, 겹침·NaN·빈 구간 JSON의 저장 전 거부를 확인했다. 음원 관련 자동 검사는 분리 직후 30개, 대시 gain 연결 뒤 **31개 통과**했다. 합산해 별개의 검사 수로 보고하지 않는다. 전체 검사는 미수행이다.
- 단발/900 RPM+빈 탄창 녹음 피크 6532/7279, 부스트 어택 수정 후 피크 5608, 각 녹음 클리핑·채널 누락 0이다. 실제 전투 전체 혼합·장치 청취·최종 사용감 검증과 구분한다.
