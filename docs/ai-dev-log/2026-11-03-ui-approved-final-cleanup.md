# UI Unit Test 승인·최종 코드 정리

- 작성일: 2026-11-03, 한국 시간
- 사용자 결정: 현재 UI Unit Test 승인. 표현은 유지하며 코드를 정리하고 성능 병목 후보의 반복 비용을 줄인 뒤 커밋한다.
- 코드에서 확인한 낭비: 동일 글자의 TTF 크기/ascent 측정 반복, 링의 매 프레임 제곱근 계산과 선마다 동일 색 재설정, 같은 버튼 목록·공격 방향 상태 재생성, 타겟 없음의 HP 표시 매 프레임 초기화, 블러 샘플마다 같은 감쇠 지수 계산.
- 글자 측정은 역할·텍스트 기준 512개 LRU, ascent는 글꼴 역할별 캐시로 바꿨다. 렌더러 종료 시 정리한다. 기존 텍스처 캐시 256개는 유지한다.
- 링은 정수 이동을 분리해 반지름·두께·중심 소수부별 32개 캐시에 픽셀 범위를 보관한다. 색 변환은 64개 캐시를 사용한다. 기존 픽셀 중심·내외측 경계 계산과 알파 중첩 방지 방식을 유지하고 링 색 설정은 링당 한 번만 한다. 추가 캐시는 일반 수치 데이터이며 폰트·텍스처 같은 네이티브 리소스를 추가 생성하지 않는다.
- 레이더 고정 설정 검증을 로드 시점으로 이동했다. 카운터 감쇠 계산을 그리기 한 번으로 끌어올렸다. 버튼 상태는 활성 조건이 바뀔 때만 다시 만들며 고정 버튼 객체를 재사용한다. 방향이 같은 프레임의 HudState 재생성을 없앴다. 클릭 판정은 좌표를 이동해 임시 Rect 생성을 줄였다.
- 승인된 설정 JSON·배치·색·폰트·숫자·수명은 바꾸지 않았다. Pico2D 원본·기존 SDL 렌더링 방식을 유지한다. OpenGL 연결은 별도 작업이며 이 정리에서 구현하지 않는다. 실제 타겟팅·설정 기능도 추가하지 않았다.
- 변경 소스와 공백 오류를 읽어 확인했다. 사용자 직접 테스트 경계를 유지하며 자동 테스트·프로그램 실행·렌더링·성능 측정은 수행하지 않았다. 실제 FPS 향상이나 측정으로 확인된 병목 해소를 주장하지 않는다. 캐시 예열 후 반복 측정·계산·상태 설정이 생략되는 경로를 코드에서 확인한 상태다.
- 이번 관련 파일만 커밋하고 기존 깍두기 폰트 삭제 4개는 별도 변경으로 남긴다. 원격 업로드는 수행하지 않는다.
