# 입자 이동시간 변동·카운터 노출/여백

- **기록 ID:** `FDLOG-20261112-particle-timing-counter-exposure`
- 기록·검증 기준: 2026-11-12 23:44 KST. 발언별 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261112-particle-timing-counter-exposure:scope]]. `이동 시간 줘보자`, `느낌이 없다고`, `노출 시간을 더`, `로드아웃 교체랑 비슷하게`, `숫자 영역으로 잘리지 않도록`, `일단 여백`을 검색한다.
- 상태: 독립 UI·GPU 구현/검증. 본편 연결·실제 창 사용감·사용자 외관 승인은 별도다.

## 1. 사용자가 제안한 것

- **U1:** 앞서 논의한 입자별 이동시간 차이를 실제로 적용한다.
- **U2:** HIT·DAMAGE 블러가 약하게 느껴져 노출 시간을 늘리는 안을 물으며 로드아웃 교체와 비슷한 블러를 요청했다. 번짐이 숫자 영역으로 잘리지 않도록 우선 여백을 요청했다. U1/U2 시각은 scope 범위다.

## 2. AI가 제안한 것

- **A1 — 구현상 판단:** 기존 6개 이동시간 0.85~1.125초의 평균 0.9875초를 보존하고 최대 ±18%로 바꾼다. GPU에서 요청별 시드·짝별 해시로 증감을 상쇄하며 홀수 요청은 마지막을 평균값으로 둔다. 고정 도착 간격과 변동을 중복 적용하지 않는다.
- **A2 — 구현상 판단:** 로드아웃과 같이 현재 순간 속도×노출을 사용한다. 탄성 숫자 속도는 중앙 차분으로 계산하며 노출 0.045→0.075초·세기 0.85·전환 0.12→0.18초·최대 96px로 시험한다. 숫자 밖 최소 24px와 실제 블러 반경의 사방 여백을 둔다.
- **A3 — 검증 판단:** 기존 Massive Energy Particle Stress에 `duration_variation` 입력·보고 항목을 추가해 비교한다. 프로그램은 생성/갱신 두 개·입자 구조 80바이트·기존 드로 경로를 유지한다. 수치·보간·해시 방식은 AI 구현상 판단이며 개별 시각은 scope 범위다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1/U2를 반영했다. 분할 에너지 회복·도착 한 번 지급·뒤 입자의 동적 목표는 유지했다. 숫자 레이블·고정 자릿수·받침판은 계속 필터 밖에 둔다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 사용자는 앞선 이동시간 차이 제안을 `이동 시간 줘보자`로 수용했다. ±18%와 노출/전환/여백 수치는 AI 구현상 판단이다. 최종 외관 승인은 아직 없다.

## 5. 반영 후 발견한 문제

- **I1:** 이전 숫자 블러는 과거 이동량에 진행률 감쇠가 다시 적용되고 숫자 상자에서 잘려, 노출을 늘려도 체감이 제한될 수 있었다. 사용자 U2의 실제 느낌과 구분되는 코드상 관찰이다.
- **I2:** 이동시간을 무작정 무작위로 바꾸면 요청 평균과 회복 템포가 달라질 수 있다. 평균 보존을 별도 검증했다.
- 기존 로컬 폰트·미커밋 피해 숫자/에셋/플레이어 보간 작업은 그대로 두고 이번 기능만 커밋한다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U2: 로드아웃과 같은 노출·순간 속도 방식으로 맞추고 사방 합성 여백을 추가했다. 문자 자체의 회전 마스크와 필터 합성 여백을 구분했다.
- I2 ↔ U1: 이동시간을 생성 때만 결정하고 각 입자는 기존 경과시간/수명 진행률로 이동한다.
