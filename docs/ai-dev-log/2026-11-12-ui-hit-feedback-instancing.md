# UI 축소 블러·피격 반응·고정 흡수 경로와 GPU Instancing

- **기록 ID:** `FDLOG-20261112-ui-hit-feedback-instancing`
- 대화 범위: 2026-11-12 현재 대화. 개별 요청·확인 발언의 정확한 시각은 미확인 — [[FDLOG_MISSING_TIME:FDLOG-20261112-ui-hit-feedback-instancing:scope]]. 현재 대화의 `축소쪽을 확인해봐`, `필압있는 펜`, `각 방향당 6개` 발언을 검색한다.
- 기록 작성 기준 시각: 2026-11-12 18:50:38 KST.
- 근거: 현재 대화, UI v2 명세·샘플 설정, 실제 OpenGL 검사와 `output/performance/ui_particles_instanced.json`.
- 상태: 독립 UI 샘플 구현·자동 검사·숨긴 OpenGL 창의 렌더 검토. 실제 창 조작·본편 전투 연결·사용자 최종 외관 승인은 별도다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 로드아웃·무기 패널의 수평 모션 블러가 세로로 흔들리는 느낌을 지적하고 축소 처리를 확인하도록 요청했다. 근거는 사용자의 화면 관찰이다.
- **사용자 제안 2 (U2):** 적 피해 시 타겟 HP바 진동과 에너지 오브 흡수, 플레이어 피해 시 HP UI의 약한 블러·수직 진동과 최대 오프셋 설정을 요청했다. 피해 주체 구분은 확인 질문에 `맞아, 그 기준으로 구현`이라고 답해 확정했다.
- **사용자 제안 3 (U3):** 필압 펜처럼 오브 근처가 가장 굵고 밝으며 멀어질수록 가늘고 약한 Trail을 요청했다. 오른쪽 적의 오브는 오른쪽에서 오도록 요청했고, 오른쪽에서 에너지 바로 들어오며 왼쪽 적만 필살기 아이콘을 경유하는 분기에 명시 동의했다.
- **사용자 제안 4 (U4):** 간단한 이미지의 GPU 업로드·Bindless를 검토한 뒤 Instancing 사용을 제안했다. 최종 경로 지시는 무작위 곡선 생성 대신 왼쪽·오른쪽 각각 6개 경로를 미리 정하고 번호만 무작위 선택하는 것이다.
- 각 요청의 정확한 발언 시각은 위 scope 누락 태그에 포함한다.

## 2. AI가 제안한 것

- **AI 구현상 판단 1 (A1):** 축소된 블러 레이어를 화면 픽셀에 1:1로 합성한다. 재확대 시 생기는 세로 좌표 오차를 없애기 위한 선택이다.
- **AI 구현상 판단 2 (A2):** 타겟은 0.22초·20Hz·화면 `(0, ±3px)`, 플레이어 HP는 0.28초·18Hz·`(0, ±4px)`로 제한한다. 플레이어 블러는 최대 3px·세기 0.22다. 수치는 조절용 시안이며 별도 사용자 승인을 추정하지 않는다.
- **AI 구현상 판단 3 (A3):** 128×64 공용 오브/Trail 아틀라스와 경로 좌표 201개를 재사용한다. Instancing은 GPU에서 리본 좌표·폭·필압을 계산하며 매 프레임 오브당 진행률/경로 슬롯 16바이트만 전송한다. OpenGL 3.3 미만·소프트웨어는 CPU 꼭짓점 묶음을 사용한다.
- 제시/검토 근거는 이번 코드·검사와 현재 대화다. 구현 방식의 정확한 제시 시각은 scope 누락 범위다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U4를 반영했다. 초기 무작위 제어점 생성 시안은 폐기하고, 최종 샘플 설정에는 왼쪽·오른쪽 각 6개의 고정 제어점만 둔다.
- 타겟 피해에서만 오브 3개를 생성하며 동시 24개를 유지한다. 실제 게임의 에너지 획득량·좌클릭 공격 피해 판정은 추가하지 않았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 피해 주체 구분과 좌우 경유 방식은 사용자 확인 답변으로 확정했다.
- 진동/블러 수치·경로 제어점의 외관·GPU 내부 구현은 AI의 구현상 판단이다. 이번 구현 보고만으로 사용자 외관 승인으로 취급하지 않는다.

## 5. 반영 후 발견한 문제

- **문제 1 (I1, 기존 증상 재현):** 0.9/0.81배에서 수평 블러 적용 전후 세로 중심이 약 0.30/0.15px 달랐다. 블러 레이어의 화면 좌표를 논리 좌표로 되돌려 재확대하는 과정이 원인이었다.
- **문제 2 (I2):** 초기 흡수 경로 일부가 화면 아래로 나갔다. 바 진입 구간을 위쪽 곡선으로 수정했고 오른쪽 경유점은 대시 표시와 겹치지 않게 에너지 채널 기준으로 정했다.
- **문제 3 (I3):** CPU 꼭짓점 구성과 반복 곡선 계산 비용이 컸다. 캐시·연속 버퍼·샘플 조정 후 24개 약 2.7ms, 이후 Instancing에서 약 0.10ms의 예열 후 제출 시간을 확인했다. 최초 시안과 최종 설정의 샘플 수 차이를 포함한 결과이며 순수 GPU 시간 비교가 아니다.
- **문제 4 (I4):** 512개 스트레스 입력에서 SDL이 남긴 픽셀 업로드 row length/skip 상태 때문에 접근 오류가 발생했다. 업로드 전 unpack/PBO 상태를 고정하고 종료 때 원상복구하도록 수정했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1: 축소를 먼저 확인하라는 요청에 따라 실제 OpenGL 픽셀 중심과 세로 표시 구간을 비교했다. 1:1 합성 후 관련 검사를 통과했다.
- I3 ↔ U4: 사용자 제안의 Instancing을 오브와 Trail 모두에 연결했다. 경로 번호만 무작위 선택하는 고정 후보는 샘플 JSON에서 방향별 6개로 관리한다.

## 7. AI 해결 제안과 실제 해결 과정

- I1 ↔ A1: 화면 픽셀 기준 합성으로 수정했다. SDL scale/viewport/clip·블렌드 복원과 방향성/알파 검사를 유지했다.
- I2 ↔ A2/A3: 좌우 경유점을 분리하고 고정 곡선의 전체 이동을 렌더했다. 오브 선두와 거리 기반 필압 리본을 주요 프레임에서 직접 열어 확인했다.
- I3/I4 ↔ A3: 고정 경로는 생성 시 업로드하고 프레임마다 작은 인스턴스 데이터만 보낸다. 텍스처 유닛·프로그램·viewport/scissor·blend·pixel unpack/PBO 상태를 복원한다. 512개 입력의 unpack 복원 검사를 추가했다.
- **확인 결과:** UI v2 자동 검사 88개·실제 OpenGL 렌더 검사 11개 통과. GPU 경로 재업로드 방지·프레임당 두 instanced draw·화면 픽셀 출력·리소스 해제를 확인했다.
- **렌더:** 60fps 시간 간격의 84프레임과 오른쪽 적 흡수 장면을 출력했다. 주요 PNG를 직접 열어 검토했고 미리보기는 `output/ui_unit_test_v2/hit_feedback/preview.gif`다. 시연에는 공개 가능한 기본 도형을 사용했다.
- **계측:** 예열 1회·2회×3묶음의 제출 벤치마크. 24개 평균 약 0.10ms, 512개 약 0.40ms다. CPU 준비·드라이버 제출을 포함하며 GPU 완료 시간을 기다리지 않는다. 전체 프레임 성능·실전 대량 파티클 성능으로 확대하지 않는다.
- **미확인:** 실제 창 직접 조작·사용자 외관 승인·본편 전투 연결·순수 GPU 시간. 업로드는 수행하지 않는다. 기능별 커밋 상태는 Git 기록으로 구분한다.
