## 2. 사용자 제안 중 AI가 수용한 것

## 3. AI가 제안한 것

- F5로 같은 전투를 초기화하는 경우와, 같은 프로세스에서 전투를 닫고 다시 여는 경우를 분리했다. 수동 전체 수집 전후와 이후 같은 부하를 비교하고, 고정 크기 소형 객체의 주소도 표본 조사했다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

## 5. 반영 후 발견한 문제

- 교전 중 자동 GC를 끄고 F5를 12회 실행했을 때 Private Bytes는 2.46 MiB 증가했다. 자동 GC를 켠 대조군에서는 3.83 MiB 증가했다. 별도 `tracemalloc` 실행에서 교전 중 전체 수집으로 감소한 추적 할당은 켬 2.55 MiB, 끔 2.56 MiB였다.
- 같은 프로세스에서 교전을 3회 닫았을 때 GC를 끈 쪽의 Private Bytes는 1,281.67 → 1,656.99 MiB였다. 종료된 전투 객체가 3개 남았다. GC를 켠 쪽은 1,251.13 → 1,336.79 MiB였고 종료된 전투 객체가 1개 남았다.

## 7. AI 해결 제안과 실제 해결 과정

- FHD Medium·SMAA, 180기·15 m, 자동 검 입력 및 60 Hz 고정 업데이트로 실행했다. 준비 구간을 제외한 일반 실행은 모드별 3,600프레임, 할당 추적은 모드별 1,440프레임, 전투 종료 검사는 진입당 90프레임이었다. 세 실험 모두 각 모드의 게임 상태 해시가 일치했다. `tracemalloc` 집계는 추적 시작 이후의 Python 할당만 포함한다.
- 교전 중 GC를 끈 실행에서 `gc.collect(2)`는 168.73 ms 걸렸고 `pymalloc` 사용 블록 3.22 MiB를 회수했다. Private Bytes는 2,210.70 MiB, arena는 228개로 유지됐다. 이후 F5 6회에도 arena는 228개였고 기존 풀의 사용 가능 블록은 3.04 → 1.19 MiB로 줄었다. Private Bytes는 2,208.98 MiB에 끝났고 중간 표본 최고치는 2,217.88 MiB였다.
- 256바이트 `bytes` 할당 65,536개 중 2,048개 주소를 표본으로 뽑았다. 해제 후 `VirtualQuery`에서 계속 커밋 상태로 관측된 주소는 GC 끔 140개, 켬 246개였다. 같은 크기를 다시 할당하자 두 모드에서 이 주소가 모두 재사용됐다.
- 3회 종료 뒤 `gc.collect(2)`를 실행하자 종료된 전투 객체가 두 모드에서 모두 0개가 됐다. Private Bytes는 GC 끔 242.41 MiB, 켬 27.98 MiB 감소했고 수집 시간은 각각 625.01 ms, 304.50 ms였다. 수집 뒤에도 시작값보다 높은 커밋이 남았으며 이 잔여량의 원인은 분리 계측하지 않았다. 장시간 플레이는 이번 범위에 포함하지 않았다.
