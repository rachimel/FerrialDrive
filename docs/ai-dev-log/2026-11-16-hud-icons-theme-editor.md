# HUD 아이콘·에너지 표현과 외부 테마 편집기

## 1. 사용자가 제안한 것

- **U1:** 대시·스왑 아이콘 위치 조정, 슬롯 확대와 원 테두리 강화, 에너지 게이지를 레벨별 Trail 색과 통일, 흰 스파크의 광·활동 증가를 요청했다. 베임선은 전체를 줄이지 않고 사라지는 부분에서 두께·투명도를 보간하도록 정정했다.
- **U2:** 미사일·카운터를 이미지로 대체하고 무기 아이콘도 만들도록 요청했다. 기존 도안을 PNG로 옮기는 것과 새 디자인을 구분했다. 컨셉 기반 생성물은 현재 모델과 맞지 않는다고 지적하고 실제 모델 렌더→아이콘화를 선택했다. 이유는 직접 제시한 모델 일치와 불필요한 그리기 호출 절감이다.
- **U3:** 카운터의 방패 윤곽·피격점·반사 방향을 여러 차례 정정했다. `디테일`은 화살표 파편이 아니라 피격점의 충돌·반사 표현이라고 확인했다. 카드 레퍼런스 뒤에는 아이콘 전체를 방어막·반사 화살표로 바꾸되 기존 HUD처럼 단순화하도록 요청했다. 최신은 좁은 닫힌 타원·입사선·직선 반사 화살표, 별빛·안쪽 곡선·독립된 파랑 배경 제거, 반사 뒤 푸른 윤곽의 투명화다.
- **U4:** 외부 툴에서 테마 팔레트를 편집하고 위젯에 색을 연결하며 미리보기를 원했다. 별도 게임 창만 띄우는 방식 뒤에 툴 내부 미리보기를 명확히 요청했다.
- U1~U4 출처는 현재 사용자 발언·첨부 이미지·선택 응답이다. 개별 시각은 scope 태그 참조. 별도로 밝히지 않은 미적 선택 이유는 추정하지 않는다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1을 반영했다. 대시는 HP 왼쪽, 스왑은 자원·무기 영역 사이 중앙이다. 슬롯은 120px, 미사일 원 테두리는 3.5px이며 카운터 원 테두리는 제거한다. 세부 수치는 AI 구현상 판단이다.
- U1의 에너지 색은 이동 설정의 Trail 팔레트를 HUD에 공급한다. 흰 경계 스파크의 레벨별 발생량·강도·점멸을 강화한다. 베임선은 남은 형상을 유지하고 지움 경계에서만 두께·투명도를 보간한다. 블러와 투명도 보간은 독립이다.
- U2의 검·PDW·미사일은 기존 모델의 평가 메시 복사본을 촬영한다. 원본 파일을 저장하지 않으며 카메라·단색 표현만 정한다. 실제 형상·비율을 바꾸지 않는다.
- U3은 최신 카운터 PNG에 반영하고 UI 원형 패널에 합성한다. 이전 생성물·잘못 해석한 파편형 결과를 최종으로 쓰지 않는다. 마지막 결과의 최종 사용자 승인은 별도다.
- U4는 외부 Tkinter 편집기와 실제 Pico2D HUD 미리보기로 연결했다. 게임 코드가 도구 모듈에 의존하지 않도록 팔레트·저장·갱신은 `ferrial_drive/ui/theme.py`에 둔다.

## 3. AI가 제안한 것

- **A1:** 대시를 HP 왼쪽에 붙이고 스왑을 두 영역 사이 중앙에 놓는 방향을 제시했다. 사용자 선택 응답으로 위치 방향을 확인했다.
- **A2 — 구현상 판단:** 모델 렌더를 정지 UI 이미지용 공통 `model-icon` 경로로 만들었다. Blender 원본 형상·재질 렌더와 HUD 단색 렌더를 분리한다. Unreal 동작 제작 경로를 변경한 것은 아니다.
- **A3 — 구현상 판단:** 팔레트와 위젯 역할 연결을 분리하고 미리보기 작업본과 게임 적용 테마를 분리했다. 파일 변경을 읽고 마지막 정상 테마를 유지한다. 내장 미리보기는 별도 숨긴 Pico2D 프로세스의 960×540 이미지를 0.2초 간격으로 받는다. 부모 편집기에서 테스트 프로그램을 import하지 않는다.
- 구체적인 색·스파크 수치·구현 구조·갱신 주기는 AI 판단이며 사용자 확정 수치로 승격하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1은 `그 방향으로 조정` 응답으로 수용했다.
- 실제 모델 렌더 사용은 사용자 U2의 직접 제안이다. AI가 먼저 제안한 것으로 기록하지 않는다.
- 카운터 중간 결과에 `나머지는 ㄱㅊ`, `그나마 낫다` 뒤 추가 정정이 이어졌다. 이를 마지막 PNG나 전체 UI의 최종 승인으로 처리하지 않는다.
- A3의 외부 도구·툴 내부 미리보기는 U4의 명시 요구다. 코드 구조·자동 검사 통과를 사용자의 직접 조작 수용으로 처리하지 않는다.

## 5. 반영 후 발견한 문제

- **I1:** 기존 내부 도안 선을 굵게 만든 범위를 사용자가 원 테두리로 정정했다. 이미지화 역시 기존 도안 래스터화와 새 디자인의 의도가 달랐다.
- **I2:** 컨셉 기반 새 무기 이미지가 실제 모델과 달랐다. 사용자가 지적했다. 현재 모델에서 직접 촬영하는 경로로 변경했다.
- **I3:** `반사 디테일`을 속도선·파편 추가로 해석해 화살표가 깨진 형태가 됐다. 사용자가 거절했고 피격점 표현으로 확인했다. 이후 전체 아이콘 방향도 U3에 따라 바뀌었다.
- **I4:** 초기 외부 툴은 별도 미리보기 창만 제공했다. 사용자가 툴 내부 표시를 요구해 숨긴 렌더 프로세스·내장 이미지 표시로 바꿨다. 화면 확인에서 아래 연결 버튼이 잘린 것을 발견해 레이아웃을 고쳤다.
- 최초 편집기 검증 캡처가 다른 창을 잡아 창 핸들 기반 캡처로 고쳤다. 잘못된 검증 이미지는 올바른 편집기 캡처로 교체했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1/U2: 원 테두리와 내부 도안을 구분하고 미사일·카운터를 이미지 문양으로 처리했다.
- I2 ↔ U2: `base_pose.blend`의 Sword/Gun, 최신 포드 작업본의 Port_Master를 직접 렌더했다. 모델 변경·재생성·리깅 수정은 하지 않았다.
- I3 ↔ U3: 피격점과 반사 방향을 정정하고 카드 스타일 참고 후 단순한 타원·화살표 구성으로 변경했다. 생성 프롬프트와 후보는 로컬에 보존한다.
- I4 ↔ U4: 팔레트·위젯 연결 옆에 실제 HUD를 표시하고 상태 버튼·선택 위젯 확대를 추가했다.

## 7. AI 해결 제안과 실제 해결 과정

- 로컬 최종 아이콘 명세는 `data/images/ui/hud_icons/model_v3/manifest.json`이다. 검·PDW는 model_v2, 포드·카운터는 model_v3을 참조한다. 카운터는 `counter_final.png`다. AI 생성·모델 렌더는 Git 제외 대상임을 확인했다.
- 모델 요청은 `Tools/blender_pipeline/workspace/hud_icons_20261116/`, 렌더 근거는 `output/verification/model_hud_icons_20261116/`에 둔다. 원본 SHA-256이 제작 보고와 같은 상태임을 재확인했다. 포드는 최신 로컬 형상 작업본이며 게임 본체·백웨폰 동작 에셋 교체 승인을 뜻하지 않는다.
- 편집기 진입점은 `python automate/run.py hud-theme`, 로컬 바로가기는 `HUD 테마 편집기.lnk`다. 공개 샘플은 `samples/hud_theme_editor/`, 편집 작업본은 도구의 workspace, 게임 적용 테마는 `data/settings/hud_theme.json`으로 분리한다.
- 위젯별 범위의 색을 중첩 적용한 뒤 복구한다. 레벨별 에너지·Overdrive 상태색은 유지한다. 원형 패널은 기존 캐시를 사용하고 PNG 문양은 이미지 한 번으로 그린다. 전체 HUD draw call·GPU 시간·FPS 개선을 측정한 것으로 확대하지 않는다.

## 확인 상태

- 실제 에셋 360프레임 실행과 카운터·레벨별 UI 캡처를 확인했다. 근거는 `output/verification/hud_theme_editor_20261116/actual_icons/`다.
- 편집기 안의 실제 HUD, 실행 중 팔레트 변경, 창 핸들 캡처와 연결 버튼 배치를 확인했다. 근거는 `output/verification/hud_theme_editor_20261116/embedded_final/`이다. 검증 색을 게임 기본 테마에 저장하지 않았다.
- 최종 관련 자동 검사 206개 실행, 201개 통과·5개 건너뜀·실패 0개다. UI v2·테마·훈련장 연결·검 효과·파티클 요청·공통 실행부·게임 설정을 묶어 확인했다. 사용자 직접 마우스 조작·색감 승인·전체 해상도·배율·모든 위젯 상태의 검수는 별도다.
- 기존 미커밋 변경을 보존했다. 이 작업의 커밋·업로드는 하지 않았다.
