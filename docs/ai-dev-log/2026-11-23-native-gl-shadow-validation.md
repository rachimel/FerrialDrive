# 직접 OpenGL 전환 후보와 그림자 대조

- 기록 ID `FDLOG-20261123-native-gl-shadow-validation`
- 기록일 2026-11-23 KST

## 1. 사용자가 제안한 것

- **U1** SDL Flush와 OpenGL 전환을 묶으면서 그림자 오류가 생기는지 전체 교전 경로에서 확인한다. 사용자는 변경을 적용한 뒤 플레이어 그림자 오류를 보고했다.
- **U2** SDL 렌더러를 제거하고 렌더링 상태를 직접 관리한다. 비교 후 남은 화면 차이가 전환을 막을 정도인지 물었다.
- 요청과 발견의 정확한 시각 `[[FDLOG_MISSING_TIME:FDLOG-20261123-native-gl-shadow-validation:U1-U2]]`. 대화에서 `그림자가 깨지지 않고 묶을 수 있는지`, `플레이어 그림자 오류가 생겨`, `SDL_Renderer버리고`로 찾는다.

## 2. 사용자 제안 중 AI가 수용한 것

- 월드·HUD·후처리를 같은 교전에서 다뤘다. 플레이어 지면·본체 그림자, 적 지면 그림자와 사용된 타일, 최종 화면을 대조했다.
- 본편·이동 훈련·벤치마크에 직접 OpenGL 후보를 연결했다. SDL 창·입력은 유지하고 텍스처·렌더 타깃·뷰포트·블렌드·표시를 직접 관리했다.

## 3. AI가 제안한 것

- **A1** SDL 큐 변경 추적, 중간 렌더 타깃의 GL 프레임버퍼 전환, 직접 OpenGL 캔버스를 같은 자동 입력으로 비교한다. 중간 타깃만 전환하면 SDL 호출 경계가 남으므로 실제 SDL 렌더러 생성 여부도 검사한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 직접 상태 관리 요청으로 후보를 검증했다. 후보를 기본값으로 적용하는 결정과 실사용 외관 승인은 보류 상태다.

## 5. 반영 후 발견한 문제

- **I1** 사용자가 이전 제출 경계 변경 뒤 플레이어 그림자 오류를 보고했다. 당시 오류 화면과 입력은 이번 대조에서 확보하지 못했다.
- **I2** 같은 경로를 두 번 실행해도 피해 숫자와 아틀라스 준비 시점이 달랐다. 자동 비교에서 피해 숫자와 충격파 난수 시드를 고정하고, 아틀라스 디코딩 완료 프레임을 맞추는 조건을 별도로 실행했다.
- **I3** 직접 OpenGL 후보는 SDL 큐 제출을 없앴지만 두 교전 조건에서 프레임 시간이 늘었다. Python에서 추가 도형 큐를 구현한 실험도 더 느려 제외했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **I1·U2** Pico2D 호출이 실제 SDL 렌더러를 만들지 않도록 연결했다. 30기와 180기 교전에서 실제 `SDL_RenderFlush`는 0회였다. 본편 타이틀을 띄웠고 Low 1,000기는 6프레임 실행을 확인했다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1·I2** Intel 내장 GPU FHD 180기 Medium, 96프레임 중 10개 시점에서 플레이어 지면·본체 깊이 맵 30장, 적 지면 깊이 맵 10장, 사용 중인 적 타일 574개의 바이트 해시가 일치했다. 가장 많은 화면 픽셀이 달라진 53번 프레임에서 HUD 숫자·잔상과 일부 선 차이를 확인했다. 최종 화면 전체는 픽셀 단위로 다르다.
- **I3** 프레임 캡처·상세 계측을 끄고 각 45프레임 준비, 90프레임 측정했다. 30기 High의 작업 시간 p50은 SDL 18.70ms, 직접 GL 20.96ms였다. 180기 Medium은 p50 19.55→24.29ms, p95 46.40→57.18ms였다. SDL 컨텍스트는 GL 4.6, 후보는 호환 GL 4.3으로 연결했다. 성능 차이로 기본값 `opengl`을 유지했다.
- 자동 검사는 직접 GL 2개 통과, 런타임·설정·벤치마크·계측 48개 통과와 2개 건너뜀이다. 다른 GPU, 직접 조작 중 그림자 오류 재현, 지속 교전의 2GiB 제한은 확인하지 않았다.
