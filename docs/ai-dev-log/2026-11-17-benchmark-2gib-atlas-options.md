# 벤치마크 2GiB 상한과 아틀라스 절감 검토

- **기록 ID:** `FDLOG-20261117-benchmark-2gib-atlas-options`
- 작성·검증 확인: 2026-11-17 12:30 KST. 대화는 현재 세션이며 개별 발언 시각은 미제공이다. [[FDLOG_MISSING_TIME:FDLOG-20261117-benchmark-2gib-atlas-options:scope]] 검색 단서: `2GiB로 마진은 올리는데`, `아틀라스 데이터를 줄일 방안`.
- 상태: 벤치마크 프로필·문서 반영, 절감안 검토·채널 분석 완료. 아틀라스 형식·적재 정책은 미변경. 커밋·업로드 미수행.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 벤치마크 여유를 2GiB로 올리고 아틀라스 절감 방안을 검토한다. 앞선 1GiB 로딩 실패에 대한 대응이다. 출처·시각 범위는 scope를 따른다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1을 수용해 `samples/hardware_profile_benchmark/profile.json`의 `memory_mib`를 2048로 바꾸고 사용법·시연·성능 목표 문서를 맞췄다. 공통 `ResourceLimits`의 기본값이나 사용자 저장 품질은 바꾸지 않았다. 과거 1GiB 측정 기록은 보존했다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 필요한 페이지 집합과 마스크 저장 형식을 먼저 검토하고 벡터 해상도·정밀도 조정은 품질 비교 후 검토한다. 현재 입력을 분석해 조건과 비용을 `docs/tool-usage/atlas_memory_options.md`에 정리했다. 제시 시각은 scope 범위이며 구체적인 우선순위는 AI 판단이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 상한 2GiB는 U1의 명시 요구다. 개별 절감안에 대한 별도 수용·품질 변경 승인은 받지 않았다.

## 5. 반영 후 발견한 문제

- **I1:** 현재 저장 품질은 high다. 2GiB 적용을 Windows에서 확인했지만, high 실행은 업로드 복사 버퍼 할당에서 실패했다. 최대 커밋 약 2037.57MiB다. 상한 완화를 최적화 완료로 보고하지 않는다.
- **I2:** medium 에너지 18페이지 전체를 검사했으며 모든 페이지에서 RGB가 서로 다르고 고정 지배 채널도 없다. 채널 하나 추출로 표현을 보존할 수 있다고 판단하지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1의 여유 상한을 반영했다. high 품질을 자동으로 낮추거나 상한을 추가로 높이지 않았다.

## 7. AI 해결 제안과 실제 해결 과정

- 2GiB·medium으로 격리해 예열 10/측정 30프레임을 실행했다. 정상 완료, GPU 기능 위반 0, 최대 커밋 **1288.27MiB**다. 짧은 실행 확인이며 장시간 사용감·60FPS 충족 검증이 아니다. high의 실패와 구분한다.
- 관련 자동 검사 21개 중 **20개 통과·1개 GPU 선택 검사 제외**. 메모리 초과 거절·Windows Job 검증을 포함한다.
- 현행 manifest의 GPU 논리량은 high 1801.34MiB, medium 829.32MiB, low 227.84MiB다. WDDM 실측이나 RAM 실측으로 취급하지 않는다. R8 전환은 medium 기준 약 179.88MiB의 계산상 절감 가능성이 있으나 필터링·샘플 후 max 연산의 동등성을 확인해야 한다.
