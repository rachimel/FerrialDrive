# 근거리 그림자·PBR 패스의 GL 상태 재사용

**기록 ID** `FDLOG-20261122-gl-state-pass`

2026-11-22 KST 작성. RTX 5070 Laptop GPU, FHD, 중간 PBR, 적 600기·간격 12m, 자동 SMG·무음으로 대조했다.

## 1. 사용자가 제안한 것

- **U1** 근거리 그림자 타일을 시작점으로 삼는다. 한 깊이 아틀라스 묶음에 대해 처음에 OpenGL 상태를 읽고 마지막에 복원한다. 중간에는 타일별 상태만 적용한다. 600기 픽셀, `glGet*`, CPU·GPU 시간을 대조하고 결과가 맞으면 범위를 넓힌다. 요청의 정확한 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261122-gl-state-pass:U1]]이다. 검색 단서는 이 대화의 `근거리 그림자 타일부터 적용해줘`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 그림자 묶음을 우선 구현하고 동일 타일·배치 요청으로 검증했다. 결과를 확인한 뒤 근거리 일반 PBR 본체와 선택 지연 조명의 깊이·재질 패스까지 확장했다.

## 3. AI가 제안한 것

- **A1** GL 상태의 소유 구간을 SDL 명령과 렌더 타깃 전환 경계로 잡는다. 같은 네이티브 패스에 들어가기 전에 포즈·아틀라스 리소스를 준비한다.
- **A2** 같은 교전 프레임의 요청을 추출해 기존/변경 경로의 순서를 교대한다. CPU 경과, API 호출 수, GPU 타임스탬프를 각각 실행해 계측 간 간섭을 줄인다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 근거리 그림자부터 확인하고 조건부로 확장하는 범위가 사용자 요청이다. 상태 소유 경계와 비교 절차, PBR 확장 순서는 구현상 판단이다.

## 5. 반영 후 발견한 문제

- **I1** 한 시뮬레이션 프레임을 연속 렌더하면 첫 실행이 텍스처 준비 예산과 방향 리소스 상태를 바꿔 그림자 타일 수가 달라질 수 있었다.
- **I2** 선택 GPU 검사에서 소형 적 Break 픽셀 최대 오차 20과 지연 조명 키포즈 캐시의 채널 오차 1이 나왔다. 추적을 끈 경로에서도 두 실패의 위치와 오차가 동일했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 같은 아틀라스의 새 타일을 모아 프로그램·프레임버퍼·깊이 상태를 한 번만 설정하고 복원했다. 중간에는 뷰포트·가위 영역·깊이 지우기·정점 제출을 타일마다 수행한다. 같은 시나리오에서 처리 타일 수가 짝마다 일치했고, CPU 대조 실행의 평균은 18.46타일·18.46패스에서 18.46타일·1.28패스로 바뀌었다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1** 각 프레임에서 실제 교전이 선택한 근거리 그림자·본체 요청을 그대로 대조했다. 전체 화면 대조는 준비용 렌더를 먼저 수행하고 이미 준비된 동일 리소스와 시뮬레이션 상태를 양쪽에 사용했다. 그림자와 본체의 재생 캐시는 양쪽에 따로 두었다.
- **A1** PBR은 텍스처 유닛과 타깃을 처음 쓸 때 원래 바인딩을 저장하고, 뒤이어 바뀐 이름만 바인딩한다. 패스 종료·예외 시 복원하고 포즈 텍스처 퇴거 전에도 추적을 종료한다. SDL 합성 사이에 끼는 공격 이펙트와 HUD는 현재의 SDL/GL 경계를 사용한다.
- **I2** 지연 조명은 재질 패스와 화면 깊이 선행 패스 모두 추적 사용/미사용 픽셀 일치를 추가 확인했다. 그림자 GPU 검사에서 두 타일의 상태 조회 횟수와 업로드 예외 시 복원을 확인했다.

| 범위 | 평균 `glGet*` 호출/프레임 | CPU 평균 ms | GPU 타임스탬프 평균 ms |
| --- | ---: | ---: | ---: |
| 근거리 그림자 깊이 타일 | 130.0 → 9.8 | 2.139 → 0.224 | 0.870 → 0.055 |
| 근거리 그림자 전체 | 143.1 → 22.9 | 2.796 → 0.876 | 0.894 → 0.067 |
| 근거리 PBR 본체 시트 준비 | 166.8 → 36.3 | 4.171 → 2.946 | 0.442 → 0.444 |
| 전체 그리기 | 870.9 → 621.1 | 29.011 → 27.527 | 23.993 → 20.609 |

호출 수는 90쌍, CPU와 GPU는 별도로 120쌍씩 측정했다. 전체 화면은 그림자·본체의 변경 경로를 교대로 바꿔 렌더했으며 CPU 측정 프레임의 컬링 후 적은 평균 294기였다. CPU는 제출 완료까지의 벽시계 시간이고 마지막 강제 완료 대기는 계측 밖이다. 타임스탬프는 드라이버 제출 사이의 GPU 유휴 시간도 포함한다. 전체 CPU P95는 47.55 → 42.61ms였다. 그림자·본체·전체 화면에서 각각 12쌍의 FHD RGBA 캡처 차이는 0픽셀이었다.

기본 자동 검사는 1,089개 통과·87개 선택 검사 제외다. 실제 적 GPU 검사는 14개 통과·기존 실패 2개 재현, 압축 아틀라스 GPU 포함 검사는 8개 통과다.

원자료와 재생 스크립트는 로컬 `output/performance/gl_state_pass/`의 `shadow_600.json`, `body_600.json`, `frame_600.json`과 같은 이름의 Python 파일에 있다. UHD 630 실기는 미측정 상태다.
