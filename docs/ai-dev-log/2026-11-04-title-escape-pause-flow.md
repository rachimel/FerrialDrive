## 1. 사용자가 제안한 것

- U1: 타이틀에서 ESC로 바로 전투에 진입하는 흐름을 정리하고, 일시정지의 ESC는 전투 복귀로 연결한다.
- U2: 확인 질문에서 ‘타이틀에서는 ESC 동작 없음’으로 확정했다. 일시정지의 타이틀 버튼으로 돌아온 경우에도 동일하다.
- 이유·의도·판단 근거: 전투의 ESC는 일시정지를 여는데 타이틀에서는 전투 직행인 것이 어색하며 일관된 흐름을 원한다고 사용자가 직접 설명했다.

## 2. AI가 제안한 것

- 별도 기능 제안은 없다. 타이틀 복귀 후 ESC의 목적지가 일시정지인지 무동작인지 확인했고 사용자가 U2로 확정했다.
- 구현상 판단: 기존 일시정지 열기/복귀와 반복 입력·전환 중 입력 차단은 유지하고, 타이틀에서 전투로 이동시키는 ESC 분기만 제거한다. 변경 범위를 작게 유지하기 위한 판단이다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1/U2를 수용해 `tests/ui_test.py`의 타이틀 ESC 전투 진입 분기를 제거했다.
- 전투 진입은 타이틀의 `전투 HUD 보기` 버튼을 사용한다. 전투 ESC는 일시정지, 일시정지 ESC는 전투 복귀다.
- UI 명세와 직접 테스트 안내를 같은 동작으로 갱신했다.

## 4. AI 제안 중 사용자가 수용한 것

- 사용자는 확인 질문에서 타이틀 ESC 무동작을 선택했다. 이를 AI의 별도 기능 제안에 대한 승인으로 중복 계산하지 않는다.
- 변경 이후의 실제 조작·완성 승인 발언은 아직 없다.

## 5. 반영 후 발견한 문제

- I1: 이전 일시정지 도입 후에도 타이틀의 ESC 전투 직행이 남아 있었다. 사용자가 이번 요청에서 지적했고 AI가 최초 타이틀과 일시정지→타이틀 복귀 뒤 모두 재현했다.
- 원인: 전투/일시정지 조건에 해당하지 않으면 ESC 처리의 마지막 분기가 `change_scene("combat")`를 호출했다.
- 일시정지 ESC 복귀는 수정 전에도 동작했다. 이를 이번에 새로 구현했다고 기록하지 않는다. 이번 수정 뒤 추가 문제는 자동 검사에서 발견하지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1/U2: 사용자가 일관된 ESC 흐름을 요구하고 타이틀 무동작으로 확정했다.
- 실제 조치: 타이틀의 ESC 전투 진입만 제거했다. 전투/일시정지 상태와 기존 페이드·입력 차단은 유지했다.
- 확인: 최초 타이틀·복귀 타이틀에서 ESC 무동작, 버튼으로 전투 재진입, 일시정지 ESC 복귀를 자동 검사했다.

## 7. AI 해결 제안과 실제 해결 과정

- 별도 해결 방향을 추가하지 않고 사용자가 확정한 U2를 반영했다.
- 경계 검사: ESC 반복/페이드 중 재입력에 의한 되튐이 없고, 정지·닫힘 페이드 동안 카운터 수명이 멈췄다가 복귀 후 진행하는지 확인했다. HP·타겟 상태 보존도 확인했다.
