## 1. 사용자가 제안한 것

**U1**: 원하는 자세를 만들 수 있도록 양팔 상박과 양쪽 허벅지에 제어점을 추가한다. 이유와 근거는 기존 제어점만으로 원하는 동작이 나오지 않는다는 사용자 설명이다.

**U2**: 상박·허벅지 조작에 손과 발도 따라오게 한다. 손가락을 펴는 동작은 포함하지 않는다. 기존 파지의 로컬 굽힘을 보존하는 범위로 해석했다.

**U3**: 원하는 전방 팔 자세를 만들 때 발생하는 IK 비틀림을 직접 조절하고, 굽힘도 함께 조절할 수 있게 한다. 출처는 현재 대화의 비틀림 발생 설명과 조작 기능 요청이다.

## 2. AI가 제안한 것

**A1**: 상박·허벅지 회전, 팔꿈치·무릎 굽힘 각도, IK 굽힘 방향을 별도로 조절한다. 이유는 팔다리 전체 회전과 말단 고정 상태의 방향 조절을 함께 제공하기 위해서다. 출처는 이번 구현 전 AI 설명이다.

구현상 판단: 원본 본 계층 대신 편집용 Empty 계층에 회전 제어점 4개를 추가하고 손·발 목표와 pole을 자식으로 둔다. 마디 중간의 선택점과 실제 어깨·고관절 회전 원점을 구분한다. 보라색 바깥 링은 어깨→손목 또는 고관절→발목 축 주위로 pole을 돌린다. 각도 제한·자동 비틀림 보정은 추가하지 않는다.

## 3. 사용자 제안 중 AI가 수용한 것

**U1–U3 구현**: 전체 마디 회전과 말단 추종, 손가락 파지 유지, 굽힘 방향 조절 및 기존 굽힘 각도 조작의 병행을 구현했다. 사용자 파일의 원본 메시·rest 본·웨이트·본 계층은 수정하지 않았다.

## 4. AI 제안 중 사용자가 수용한 것

새 링 구성·색상과 내부 계층 방식에 대한 별도 사용자 수용은 아직 없다. 사용자 요구 구현과 최종 사용감 승인을 구분한다.

## 5. 반영 후 발견한 문제

**I1**: 기존 작업본에 제어점 부모만 추가하면 기존 손·발 목표의 로컬 키가 새 부모 기준으로 해석되어 자세가 바뀔 수 있다. 구현 중 확인한 구조적 위험이며, 실제 사용자 작업본을 손상시킨 사건으로 기록하지 않는다.

**I2**: 여러 동작을 평가하는 변환 과정은 키 저장 전 손가락·컨트롤·독립 무기 편집을 잃을 수 있다. 변환 전 현재 값을 별도로 보관해야 한다.

## 6. 사용자 해결 제안과 실제 해결 과정

사용자는 손·발 추종과 손가락 제외 범위를 명확히 했고, IK 비틀림과 굽힘의 직접 조작을 요청했다. I1·I2의 내부 키 변환 알고리즘을 지정한 것은 아니다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1**: 방문한 동작의 매 프레임 월드 목표를 보관하고 새 부모 좌표계에 다시 기록한다. 새 동작 초기화에도 상박·허벅지 제어점을 포함하며, 반복 초기화는 중복 적용하지 않는다.
- **I2**: 현재 proxy 본의 로컬 자세, 모든 제어점 월드 자세, 독립 무기와 장비 속성을 보관·복원한다. 원본 파일 해시는 검사 전후 동일하다.
- **조작**: 상박·허벅지 선택 후 `R` 또는 축 버튼으로 회전한다. 관절 안쪽 링은 굽힘, 보라색 바깥 링은 손·발의 위치와 회전을 고정한 IK 방향이다. 드래그 취소용 자세 복구와 양손 고정의 유지/해제 경로를 사용한다.

- **실제 모델 검사**: `output/pose_tool/upper_twist_model_02/report.json` 통과. `base_pose.blend`의 6개 동작을 보존하고 동일 기능을 검사했다. 전후 6면과 양쪽 어깨·무릎 확대를 직접 검토했다. 기능 검사용 자세이며 최종 키포즈 승인이나 장갑 간섭 검증을 뜻하지 않는다.
