## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 적에 배칭과 인스턴싱을 적용하라고 요청했다. 출처: `일단 배칭이랑 인스턴싱 적용해줘.`
- **사용자 제안 2 (U2):** SMG의 레벨 1/2/3·Overdrive 피해를 12/16/20/30, Overdrive를 10초·탄약 소모 없음으로 지정했다. 출처: `Overdrive 시 총 탄약 소모 없애고`, `Overdrive 10초`, `smg`.
- **사용자 제안 3 (U3):** Bullet Trail이 에너지색을 따르게 하고 강철 명중 스파크를 검보다 적게 요청했다. 출처: `Bullet Trail도 에너지 색상 따라가고`, `강철 피격 시 튀는 스파크 VFX 검보다는 적게`.
- **사용자 제안 4 (U4):** 총탄 명중 카메라 피드백을 일반 6px·Overdrive 8px로 지정했다.
- 사용자 직접 이유가 없는 항목에 별도 동기를 추정하지 않는다. 구체적인 출처 시각은 위 scope의 보완 대상이다.

## 2. AI가 제안한 것

- **AI 제안 1 (A1, 구현상 판단):** 적 도형을 순서대로 모아 공통 쿼드 인스턴스로 처리한다. 소프트웨어는 기존 SDL 정점 배치, 이름·상태는 도형 뒤 텍스트 층으로 둔다. 몸체·선·HP바·적 탄환을 같은 경로로 처리해 호출 수를 줄이는 목적이다.
- **AI 제안 2 (A2, 구현상 판단):** 총 불꽃은 금속·강철에만 4개, 최대 0.18초·900 투영 px/s·너비 1.6px·상한 128개로 둔다. 검은 기존 22개·0.55초다. 적은 수·짧은 수명으로 총과 검의 반응량을 구분한다.
- **AI 제안 3 (A3, 구현상 판단):** 피해는 발사 시 저장하고 에너지색은 표시 시점 값을 사용한다. 총/검 카메라 사건 ID를 구분하고 명중별 진폭을 공급해 검 진폭을 보존한다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1: `rendering.backend=auto`를 OpenGL 인스턴싱·software 정점 배치로 연결했다. 같은 교전을 사용하는 일반·3배속 진입점에 적용한다.
- U2: 발사 시 12/16/20/30 피해, 실제 10초 지속, 빈 탄창에서도 소모 없는 Overdrive 사격을 연결했다. 강제 탄창 충전은 하지 않으며 사격 사건의 기존 탄약 회복 유예 갱신은 유지한다. 종료 후 일반 탄약 소모 규칙을 사용한다.
- U3: 흰 알파 Trail 텍스처를 공유하고 정점 색상만 갱신한다. 강철 불꽃도 같은 텍스처의 도형 제출에 합친다.
- U4: 총 일반 6px·Overdrive 8px의 명중 진폭을 적용했다. 기존 검 진폭을 바꾸지 않았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 배칭·인스턴싱 적용, 피해·지속 시간·탄약 소모·에너지색·총 카메라 수치는 사용자 직접 지정이다.
- A1의 텍스트 층과 쿼드 선 끝점, A2의 불꽃 수·수명·속도, A3의 발사 시 피해 저장은 구현상 판단이다. 세부 표현의 사용자 외관 승인을 받았다는 뜻이 아니다.

## 5. 반영 후 발견한 문제

- **I1:** SDL software의 사각형 채우기와 정점 도형은 알파 반올림이 달라 픽셀 완전 일치 검사에 실패했다. 관련 비교에서 채널 최대 오차 2 이내로 확인하고 허용 범위를 명시했다. 선은 1px 쿼드·정사각 끝점이므로 이전 SDL 선과 완전히 같은 픽셀이라고 주장하지 않는다.
- **I2:** CPU에서 정점을 생성하는 SDL 배치가 OpenGL 비교에서 더 느렸다. 호출 수 감소만으로 성능 향상을 판단하지 않는다.
- **I3:** 교전 종료 뒤 총 불꽃이 멈춰 남을 수 있는 갱신 경로를 코드 검토에서 확인했다. 잔여 사망 표현과 함께 총 불꽃 수명도 진행하도록 수정하고 전멸 뒤 소멸을 검사했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1을 명시적 적용 요청으로 받아 구현했다. SDL/Pico2D 원본은 수정하지 않았다.
- U2~U4의 수치와 동작을 기존 SMG·Overdrive·카메라·에너지 표현에 연결했다. 피해·남은 탄약·숫자 HUD·록온·명중 재질은 기존 상태를 사용한다.

## 7. AI 해결 제안과 실제 해결 과정

- A1: 재사용 도형 명령 수집·SDL 정점 큐·공통 쿼드 `glDrawArraysInstanced`를 구현했다. 한 도형은 위치/선 양끝·색·종류 48바이트이며 CPU 버퍼·GPU 텍스처 저장 공간을 재사용한다. 문자 앞에서 상태를 복원하고 종료·실패 시 자원을 정리한다. 클립·스케일·렌더 타깃·이후 SDL 그리기·버퍼 재사용·예외 폐기를 검사했다.
- I2의 비교: 같은 30기 초기 장면에서 247개 도형·텍스트 29개. 모드 순서를 바꿔 6회차, 회차당 40회·예열 5회로 공통 `TimingRecorder` 계측. 적 렌더 구간 중앙 CPU 시간은 개별 호출 0.9799ms·SDL 정점 배치 1.8980ms·인스턴싱 0.9009ms였다. 인스턴싱은 도형 제출 1회·프레임당 11856바이트를 전송한다. GPU 시간·전체 FPS가 아니며 대상 하드웨어 일반화는 하지 않는다. 소프트웨어는 기능 호환 경로로 구분한다.
- U2~U4: 탄환에 발사 피해·실제 접촉 위치/방향을 보존한다. 기존 두 원소 명중 목록은 유지한다. 금속 불꽃은 별도 규칙 모듈에서 실제 시간으로 갱신하고 재질·상한·수명을 검사했다. 에너지색은 텍스처 재생성 없이 정점에 전달한다. 일반/Overdrive 진폭은 6/8px로 각 명중에 지정한다.
- **자동 검사:** 관련 134개 통과. 마지막 I3 갱신 후 관련 54개 재확인 통과. 빈 탄창 Overdrive·일반 복귀·발사 후 레벨 변화·12/16/20/30 피해·6/8px·강철 불꽃 수·Trail 정점 색·기존 이동·GPU 배치·상태 복원을 포함한다.
- **렌더 확인:** 실제 플레이어 에셋·적 인스턴싱·3배 이동 설정으로 705프레임 실행했다. 적 AI는 해당 진단 실행의 메모리 상태에서만 긴 회수 상태로 두었다. 저장된 적 설정은 바꾸지 않았다. 75프레임 LV2 색 `#78D0FF`, 카메라 6px·잔탄 38; 115프레임 Overdrive 색 `#FF4044`, 카메라 8px·잔탄 0·발사 누계 20; 690프레임 잔여 약 0.167초·잔탄 0·발사 누계 308; 702프레임 Overdrive 종료·잔탄 0·발사 누계 313을 확인했다. 검토 이미지를 직접 열어 Trail·불꽃·HUD·도형을 확인했다.
- 재생성 결과: `output/combat_test_v1_5/batching/`와 `smg_feedback/`. 현재 명세·샘플 실행 안내를 갱신했다. 실제 키보드 조작·사용감 승인·최소 사양 GPU 성능·커밋·업로드는 수행하지 않았다.
