# 흰색 크로스헤어 마우스 추적·실행기 경계 점검

- 작성일: 2026-11-03, 한국 시간
- 사용자 요청: 크로스헤어를 마우스에 맞춰 움직이고 색을 변경한다. 후속 확인으로 색 변경은 크로스헤어만 흰색으로 지정했다. Runner와 ui_test의 독립성도 지적했다.

## 크로스헤어

- UI 테스트 입력부가 마지막 유효 포인터 좌표를 기억해 `UiView.combat(cursor_position=...)`에 전달한다. 첫 입력 전에는 화면 중앙, 창 밖에서는 마지막 유효 위치를 유지한다.
- 원+십자는 `colors.crosshair=#FFFFFF`를 사용한다. 버튼 위·장면 전환 중에도 좌표를 갱신하며 HUD 전환 이동량은 적용하지 않는다. 플레이어·레이더 중심과 나머지 색은 유지한다.

## 구조 점검 결과

- `Tools/unit_test_runner`는 ferrial_drive나 ui_test를 직접 import하지 않는다. 실행 루프·창·드롭·수명 주기를 담당한다.
- `tests/ui_test.py`는 TestProgram·WindowSpec·Stop과 직접 실행용 run에 의존하는 실행기 어댑터다. `ferrial_drive/ui`의 재사용 모듈은 실행기를 import하지 않는다. 역할 분리는 있으나 ui_test가 실행기 라이브러리 없이 독립 실행되는 구조는 아니다.
- 같은 프로세스·Pico2D 전역 창/렌더러를 공유하므로 테스트별 실행 격리는 없다. `loader.py`는 드롭한 파일만 새 모듈로 읽으며 보조 모듈을 모두 다시 읽거나 제거하지 않는다. 재드롭 후에도 기존 UI 모듈이 캐시에 남는 것이 완전 재시작을 안내했던 이유다.
- 공통 타입 의존·프로젝트 경로 설정과 실행 격리/재로딩을 별개의 문제로 구분해야 한다. 이번 작업에서 Runner 구조를 재작성하거나 모듈 재로딩 문제를 해결하지 않았다.

## 확인 상태

- 코드·호출 관계를 읽어 검토했다. 사용자 직접 테스트 방침에 따라 자동 검사·실행·렌더링·실제 창 조작은 수행하지 않았다. 실행기 완전 재시작 후 마우스 추적·흰색 원/십자·중앙 레이더 유지 여부를 확인한다.
