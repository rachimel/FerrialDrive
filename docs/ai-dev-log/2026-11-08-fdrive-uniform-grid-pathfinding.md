# FDrive 균일 격자·A*와 경로 탐색 최적화 후보

- 기록 ID: **FDLOG-20261108-fdrive-uniform-grid-pathfinding**
- 기록 작성 기준 시각: 2026-11-08 19:00:54 KST에 확인한 도구 시각이다. 사용자 발언 시각과 구분한다.
- 출처: 현재 대화의 “균일 격자로 하고”, “경로 탐색은 A* 또는 좀 심각하면 JPS+ / Goal Bounding”과 직전 공간 검색 구조 검토다.
- 제안·수용의 정확한 발언 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261108-fdrive-uniform-grid-pathfinding:scope]] 위 검색 구절의 원문에서 시각을 확인한다. 사용자 제안 1~2와 AI 제안 1~2, 수용에 공통 적용한다.
- 상태: **설계 방향의 PRE-PRD 반영**. 공간 검색·경로 탐색 코드 구현과 성능 검증은 수행하지 않는다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 공간 검색 구조는 균일 격자로 한다.
  - 이유·근거: 2D 맵에서 옥트리·쿼드트리·균일 격자를 검토한 뒤 “ㅇㅇ 균일 격자로 하고”라고 선택했다.
- **사용자 제안 2 (U2):** 경로 탐색은 A*를 우선으로 하고, 병목이 심하면 JPS+ / Goal Bounding을 검토한다.
  - 이유·근거: 낮은 사양과 수백 기 장면을 고려하는 논의에서 조건부 최적화 방향을 직접 제시했다. 구체적인 전환 기준과 성능 수치는 지정하지 않았다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1/U2를 PRE-PRD 7.4절에 반영한다. 균일 격자와 A*를 기본으로 하고 JPS+·Goal Bounding은 실측 후 검토할 후보로 남긴다.
- 8.4절에는 셀 크기·이동 비용·기체 크기·국소 회피·재탐색·전처리 갱신 등 미정 사항을 구분한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 높이를 사용하지 않는 2D 이동·충돌에는 균일 격자를 먼저 사용하고 쿼드트리는 분포와 실제 조회 비용을 확인한 뒤 비교한다.
  - 이유·근거: 이동 개체의 등록·주변 조회를 단순하게 구현하고 비교 기준을 확보하려는 제안이다. 적 수만으로 트리의 우위를 확정하지 않았다.
- **AI 제안 2 (A2), 기술 검토:** 공간 검색용 격자와 길찾기용 격자의 역할을 구분하고, JPS+의 균일 비용·전처리 조건과 통행 정보 변경 시 갱신 비용을 확인한다. Goal Bounding은 A*·JPS+ 등에 결합 가능한 가지치기로 구분한다.
  - 이유·근거: [저자 구현 설명](https://github.com/SteveRabin/JPSPlusWithGoalBounding)은 JPS+의 전처리와 균일 비용 격자 조건, Goal Bounding의 다른 탐색 방식과의 결합을 설명한다. 기존 맵 요구에는 장애물 추가·제거와 파괴물이 있어 전처리 정보의 유효성을 확인해야 한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U1에서 A1의 균일 격자 사용을 명시 수용했다.
- A2는 이번 요구를 문서화하면서 확인한 기술 조건이다. 구체적인 셀 크기·이동 규칙·최적화 구현·자동 전환 정책을 사용자가 승인한 것으로 기록하지 않는다.

## 5. 반영 후 발견한 문제

- **발견한 문제 1 (I1), 기준 문서 갱신:** 기존 7.4절은 공간 분할 구조와 경로 탐색을 모두 미정으로 두고 있어 U1/U2의 최신 결정을 반영할 필요가 있었다.
- **발견한 문제 2 (I2), 적용 조건:** 파괴물·장애물 변경 후 과거 전처리 데이터를 그대로 사용하면 탐색 조건과 맞지 않을 수 있다. 실제 구현 버그가 아니라 후보 기술의 적용 시 검토할 조건이다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1/U2: 균일 격자와 A* 기본 사용, 병목 시 JPS+ / Goal Bounding 검토라는 방향을 직접 지정했다.
- 맵의 정확한 크기·적 수·목표 프레임률은 이번 선택으로 확정하지 않는다. 앞서 AI가 제시한 수치 제안을 사용자 확정값으로 옮기지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: PRE-PRD 7.4절의 미정 표현을 최신 기본 방식과 조건부 최적화 후보로 교체하고 8.4절의 세부 미정 항목과 연결한다.
- I2: 전처리 데이터의 무효화·갱신·재생성 또는 유효한 탐색으로의 전환을 검토 조건으로 기록한다. 생성 시간·저장 공간·동적 갱신 비용과 경로 요청·재탐색 횟수를 계측 대상으로 구분한다.
- 확인 범위: 현재 요구와 미정 사항, 상대 링크·로그 형식·누락 인덱스·공백을 확인한다. 알고리즘 구현·경로 정확성·성능·실제 창 조작은 검증하지 않는다.
