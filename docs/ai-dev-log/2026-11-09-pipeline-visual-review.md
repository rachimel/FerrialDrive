- 근거: 현재 대화의 사용자 요청과 선택 응답, 모델 제작/검토/보정 코드, 로컬 실행 보고서.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 파이프라인의 위험한 선택은 의견을 묻고 수정하며, 중간 출력 이미지를 AI가 의도와 대조해 검사한다. 근거: “실제로 뽑은 중간 단계 이미지 결과를 바탕으로 내가 의도한 바인지 검사를 해야”. 목표 정의와 출력 검토의 책임을 사용자에게 넘기는 설명을 정정한 요청이다.
- **사용자 제안 2 (U2):** 중간 이미지를 제시하고 사용자가 문제없으면 OK로 다음 단계에 진행한다. 앞/뒤/좌/우/위/아래 확인에 드는 시간도 묻는다. 근거: “별 문제 없으면 OK로”.
- 제안 시각은 위 scope TIME의 보완 대상이다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1/U2를 수용했다. 사용자 요청에서 AI가 목표·보존 대상·확인 항목을 정리하고 이미지를 직접 본 뒤 근거를 제시한다. AI 판단과 실제 사용자 응답을 별도 기록한다. 무응답을 승인으로 해석하지 않는다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1):** 팔 보정의 손 위치 이동을 기본 금지하고 별도 허용 시에만 이동한다. 이유: 손목 각도만 줄이면서 파지·공격 궤적이 달라질 수 있다.
- **AI 제안 2 (A2):** 동작 생성 중 웨이트 보수를 별도 활성화한다. 이유: 포즈 생성과 메시 바인딩 수정의 영향 범위를 나눈다. 기존에도 weight_repair 설정이 있을 때만 보수했으며, 이번에는 enabled=true까지 명시하도록 좁혔다.
- 고정 촬영 조건·검토 상태 파일·아래쪽 보조광·검토 시간 측정은 요구 실현을 위한 **구현상 판단**이다. 이를 별도의 사용자 승인으로 승격하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1: 명시 수용. 실제 선택 응답 “손 위치 유지가 기본, 이동은 별도 지정”.
- A2: 명시 수용. 실제 선택 응답 “웨이트 보수는 별도 지정할 때만”.
- 중간 이미지와 6면 확인은 U2의 직접 요구다. 구현 결과 자체의 승인과 구별한다.

## 5. 반영 후 발견한 문제

- **I1:** 플레이어 기준의 실제 6면 이미지를 열자 밑면이 어두워 세부 관찰이 어려웠다. 기존 두 광원은 위쪽에 위치했다. 렌더 성공을 6면 품질 확인 성공으로 취급하지 않았다.
- 기존 승인 에셋의 결함 원인이나 전체 애니메이션 실패 원인은 이번에 확정하지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U1/U2: model_pipeline에 전후 고정 촬영, 6면/두 크기, 시간 측정과 중간 검토를 연결했다. model_review는 이미지/후보 지문, 항목별 관찰, 보존 여부, AI 판단과 사용자 응답을 기록한다.
- 중간 확인이 붙은 source는 다음 모델 수정·동작 생성·보정·베이크에서 실제 OK를 요구한다. 결함을 같은 단계에서 재수정할 때는 review_revision과 새 이미지 검토를 사용한다. 기존 기록 없는 에셋과 기존 게임 출력까지 전역 차단하지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

- A1: allow_shift 기본 false, 도달 불가 시 오류, 목표 각도/말단 오차 미해결을 requires_strategy_change와 unresolved_samples로 기록한다. 명시적 이동 허용 경로는 유지한다.
- A2: weight_repair.enabled=true에서만 보수한다. 간이 미리보기의 형상 처리 생략도 기본 해제했다.
- I1: 모델은 수정하지 않고 검토용 아래쪽 보조광을 추가했다. 재출력 밑면의 512px/240px 이미지를 직접 열어 검은 음영에 묻혔던 표면이 보이는 것을 확인했다. 최종 게임 조명이나 재질 승인과 구별한다.
