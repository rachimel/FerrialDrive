# UI v2 볼드 텍스트·조작키 강조

- **기록 ID: ui-v2-bold-guide-keys**. 대화·구현·검증·정리: 2026-11-11 KST, 현재 대화.
- 개별 발언의 정확한 시각은 미확인이다. [[FDLOG_MISSING_TIME:ui-v2-bold-guide-keys:scope]] 검색 단서: `텍스트 렌더링할 때 볼드`, `조작키를 볼드로`.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1)**: 텍스트 렌더링에서 볼드를 선택하는 기능을 넣는다.
- **사용자 제안 2 (U2)**: 조작 가이드에서 조작키를 볼드로 표시한다. 별도 레이아웃·색상 변경은 요청하지 않았다. 근거는 현재 직접 요청이다.

## 2. AI가 제안한 것

- 별도 디자인 제안 없이 U1~U2를 구현했다. 구현상 판단은 SDL_ttf 합성 볼드·굵기를 구분한 캐시·`**키 이름**` 표기다. 키 강조가 설명 글자에 번지지 않도록 폰트 상태를 복원하고 굵어진 폭으로 구간을 배치한다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U2를 반영했다. 공통 `text`·크기/기준선 측정, v2 투영/네온 출력에 `bold=True`를 지원한다. 가이드 본문은 혼합 굵기 출력으로 조작키 16개만 강조하고 설명·헤더의 기존 굵기를 유지한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 합성 볼드 방식과 최종 외관의 별도 명시 승인은 확인 전이다. 기능과 적용 대상은 사용자 직접 요구다.

## 5. 반영 후 발견한 문제

- 이번 자동 검사와 실제 SDL 렌더에서 추가 실패를 확인하지 않았다. 실제 창 사용감과 GPU 성능은 미검증이다.

## 6. 사용자 해결 제안과 실제 해결 과정

- 기존 오류에 대한 수정 요청이 아닌 기능 추가다. 별도 오류 해결 제안은 해당하지 않는다.

## 7. AI 해결 제안과 실제 해결 과정

- 볼드 작업 전후 폰트 상태를 보존하고 일반/볼드별 측정·텍스처를 재사용한다. 혼합 굵기는 각 구간의 실제 폭과 같은 기준선을 사용한다. 닫히지 않은 강조 표기는 원문으로 둔다. 기존 개폐 표시 순서는 유지한다.
- UI 자동 **104개**·표적 획득 **7개**, 총 **111개 통과**. 실제 SDL 픽셀·캐시 구분·일반 글자 복원·측정 오류 후 상태 복원·혼합 폭·최대 폭·개폐 중 본문 숨김을 검사했다.
- 같은 시간의 일반/볼드 두 화면을 렌더하고 비교 이미지를 열어 키 강조와 줄 배치를 검토했다. 본문 폭은 **302/392/356/377px**, 가용 폭은 **504px**다. 차이 영역은 가이드 본문 안에만 있으며 나머지 픽셀은 같았다. 출력은 `output/ui_unit_test_v2/guide_bold/`에 둔다.
- 실제 창 직접 조작·사용자 최종 외관 승인·업로드는 미검증/미수행이다.
