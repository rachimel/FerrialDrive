# 포즈 파츠 편집과 Ctrl+Z

기록 ID: **2026-11-09-pose-part-editing**. 현재 대화의 2026-11-09 KST와 Blender 전환 후속 발언을 포함한다. 개별 발언 시각은 미확인이다. [[FDLOG_MISSING_TIME:2026-11-09-pose-part-editing:scope]] 같은 대화의 “Ball Joint랑 손이랑 분리”, “Ctrl + Z 기능 추가해줘”, “포즈 편집만 Blender로”에서 시각을 보완한다.

## 1. 사용자가 제안한 것

**U1** — 손목 Ball Joint와 손을 연결하고, 파츠 평행이동·손가락 조작·파츠별 이전 프레임 복제를 요청했다. 총은 한 파츠로, 칼과 칼집은 각각 독립 파츠로 두고 칼을 칼집에 꽂힌 배치로 자동 정렬하는 기능을 요청했다. 월드 축 이동/회전 버튼은 화살표로 표시하고 불필요한 버튼을 제거하도록 했다.

**U2** — 진행 중 Ctrl+Z를 추가 요청했다. U1을 대체하지 않고 같은 편집 흐름에 포함했다.

**U3** — 축 버튼을 작게 줄이고 아이콘으로 바꾸되 방향 화살표가 아니라 `+`/`−`로 표시하도록 정정했다. 마우스로 조작하는 모델 위 축 화살표는 굵게 하도록 요청했다.

**U4** — “손가락 주먹으로 만드는거 없나”, “반응성 더 키울 수 있어?”라며 한 번에 주먹을 만드는 조작과 응답 개선을 요청했다.

**U5** — 이어서 “그냥 툴 대신 Blender에서 하는걸로”, “기능은 유지해줘 다만 바로가기를 루트 폴더에”라고 요청했다.

**U6** — 작업을 잠시 중지한 뒤 Asset Tool 전체 기능을 옮겼는지 확인했다. 포즈 편집만 옮기고 렌더·조립·미리보기·등록 등은 Asset Tool에 유지한다는 설명 후 “ㅇㅇ 그러면 계속해 / 포즈 편집만 Blender로”라고 범위를 확정하고 재개했다.

**U7** — 첨부한 양손 확대 화면에서 검지가 다른 세 손가락과 다르게 굽혀지고 왼손은 손등 쪽으로 말린다고 지적했다. 주먹에서 엄지를 제외한 네 손가락이 같은 방식으로 손바닥 쪽에 말리도록 플러그인 수정을 요청했다. 출처는 현재 대화의 “검지가 다른 손가락들과는 다른 각도로 굽혀짐”, “주먹 만들 때 네 손가락이 같이 말리도록”과 첨부 이미지 2개다. 시각 누락은 위 scope에 포함한다.

## 2. 사용자 제안 중 AI가 수용한 것

Asset Tool 내부 편집에 U1·U2를 반영했다. 원본 모델의 메시/rest 본/웨이트를 수정하지 않고 별도 편집 작업본에 적용한다. 총/칼/칼집은 서로와 손/본체의 자동 부착을 끊고 기존 프레임별 월드 배치를 보존했다.

후속 U4–U6에 따라 현재 사용자 진입점을 Blender 포즈 편집으로 전환했다. Asset Tool에는 Blender 실행과 출력 렌더 설정 불러오기만 연결한다. 기존 내장 편집 소스는 검사·호환용으로 보존한다.

U7을 수용해 네 손가락의 공통 굽힘 축과 양손의 손바닥 방향을 수정했다. 기존 작업본에서도 주먹을 다시 적용할 수 있으며 이전 포즈 키를 일괄 재작성하지 않는다.

## 3. AI가 제안한 것

**구현상 판단** — 기존 리그의 Pose 제약과 본별 Action, 기존 무기의 조립 루트를 재사용한다. 손목 볼은 손 회전 기준을 따르는 제약으로 연결한다. 파츠 목록은 몸체·IK/손가락/장비/기타로 나누며 기존 고정 본 버튼·수납/파지·보조손 고정 버튼을 제거한다.

**구현상 판단** — Undo는 객체 변환·손가락 본·Action 키·현재 프레임/동작을 함께 보관한다. 드래그 요청 ID로 한 드래그를 한 단계로 묶고 최대 48단계를 유지한다. 출력은 별도 Blender에서 굽는다. 이유는 출력 파일 재로딩으로 편집 객체와 Undo 참조가 끊기지 않게 하기 위해서다. 출처는 현재 대화의 구현 설명과 코드다.

**구현상 판단 — Blender 전환 후**: 앞서 설명한 48단계 원격 이력 대신 Blender 기본 Undo/Redo·자동 키·네이티브 변환을 사용한다. 관절 손잡이는 평가된 실제 위치에 표시하고 드래그는 기존 pole의 굽힘 방향으로 변환한다. 주먹/펴기는 절대 회전값으로 설정해 반복 클릭 누적을 막는다. 별도 이미지 생성/파일 전달을 편집 경로에서 제거한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

U1·U2는 사용자 요청이다. 구체적인 저장 구조·48단계·조건별 버튼 배치에 대한 사용자 최종 승인은 아직 받지 않았다.

후속 U6은 **포즈 편집만 Blender로 이동**하는 범위에 대한 명시 수용이다. 최종 사용감·주먹 모양·전체 관절 간섭에 대한 사용자 승인은 아직 받지 않았다.

## 5. 반영 후 발견한 문제

**I1 — 기존 구조**: `Wrist_Ball` 메시가 `WristSwivel`을 따르고 손은 별도 세계 회전 제어를 받아 볼과 손의 회전이 달라졌다.

**I2 — 확장 과정**: 독립 무기를 본체 계층에서 분리하면 기존 8방향 렌더 루트의 자식에서 빠져 본체와 다른 방향으로 남을 수 있었다.

**I3 — 확장 검사**: 저장 장면의 활성 객체/모드에 의존하는 카메라 추가 연산이 출력 준비 검사에서 실패했다.

**I4 — 주먹 확대 검사**: 손가락 마디마다 rest roll이 달라 같은 로컬 Z 회전이 일부 관절에서 반대로 적용됐다. 기존 굽힘 연산도 영향을 받았다.

**I5 — 사용자 후속 확인**: I4의 수정은 각 손가락 뿌리의 축을 따랐다. 손가락 뿌리 자체의 축 차이와 손바닥 면을 향하는 부호를 보정하지 못해 네 손가락의 방향 차이와 왼손의 손등 방향 굽힘이 남았다. 당시 검사는 중지의 손끝–뿌리 거리만 검사해 이 문제를 놓쳤다.

## 6. 사용자 해결 제안과 실제 해결 과정

U1에 따라 손–볼 회전을 연결하고 파츠별 월드 변환, 손가락 관절, 이전 프레임 복제와 한 번의 칼집 정렬을 구현했다. 정렬은 부모 연결이나 인출 애니메이션 생성으로 확대하지 않았다. U2에 따라 Ctrl+Z와 화면 되돌리기를 연결했다.

U5·U6에 따라 최근 포즈 기능을 Blender 패널로 옮기고 프로젝트 루트에 로컬 `Pose Tool.lnk`를 만들었다. 기본 입력은 사용자가 지정한 모델의 포즈 파일 `data/models/basic_weapons/base_pose.blend`다. 파일을 찾지 못하면 다른 모델이나 샘플로 자동 대체하지 않는다. 렌더·애니메이션 조립·에셋 미리보기/등록·맵 기능은 Asset Tool에 유지했다.

U7에 따라 I5를 수정했다. 네 손가락의 같은 관절에는 같은 굽힘각을 적용하고, 양손 모두 손바닥 쪽으로 말리는지 실제 본 좌표와 확대 이미지로 확인했다.

## 7. AI 해결 제안과 실제 해결 과정

I1: 손바닥 제어와 rest 좌표 관계를 사용하는 손목 볼 회전 제약을 추가했다. 확인한 손 회전에서 손/볼 중심 차이는 약 0.00000025, 목표 회전 차이는 0이었다. 원본은 보존했다.

I2: 출력 설정의 `extra_root_objects`에 총·칼·칼집을 전달하고 렌더 준비에서 같은 출력 루트 아래 묶었다. 정적 배치뿐 아니라 방향 회전도 같이 적용하는지 검사했다. 편집 중에는 독립 파츠를 유지한다.

I3: 저장 모델의 카메라·그림자 바닥·광원을 활성 UI 모드에 의존하지 않는 데이터 API로 생성하도록 수정했다.

U3 반영: 오른쪽 축 버튼을 40×28 크기의 `−`/`+` 6개로 한 줄에 배치하고, 모델 위 마우스 조작 화살표는 3px 선과 큰 화살촉으로 표시한다. 버튼 조작과 마우스 조작의 표시를 구분했다.

검증: 실제 `base_pose.blend`에서 월드 이동, 무기 독립성, 손가락 회전/Undo, 이전 프레임 복제, 칼집 정렬/Undo, 드래그 한 단계 Undo, 저장/출력 뒤 Undo, 원본 해시 보존을 검사했다. 포즈 UI·기존 렌더/조립/구도 자동 검사 **48개 통과**. 실제 Pico2D/OpenGL 창에서 축 화살표·Ctrl+Z·손가락·칼집 정렬을 조작하고 캡처했다. 기본 도형 샘플에도 손가락과 독립 무기를 추가하고 기존 Blender IK·저장/재로딩 검사를 통과했다.

전체 관절 가동 범위·연속 간섭·무기 삽입 여유·전체 전투 모션·사용자 최종 사용감 승인은 별도다. 원본 모델/작업본/이미지 출력은 Git에 포함하지 않는다.

Blender 전환 검증: 기본 도형과 실제 `base_pose.blend`에서 파츠 월드 이동/회전, 무기 독립성, 손목 볼 회전, 양손 주먹의 반복 클릭/펴기, 무릎 굽힘과 발 목표 유지, 이전 프레임 복제, 칼집 정렬, 저장/출력과 원본 해시 보존을 확인했다. Blender 실제 창에서 전용 탭을 열고 기본 Undo 장면 복구 및 **Ctrl+Z 키 입력**을 확인했다. Python 타이머 호출에는 UI 연산자의 Undo push가 자동으로 붙지 않아 검사에서 명시적으로 기록하며, 키보드 이벤트에 의한 복구를 별도로 검사했다.

I4 해결: 손가락 뿌리의 굽힘 축을 각 마디의 rest 좌표로 변환한다. 실제 모델의 확대 이미지에서 수정 전/후를 비교했고, 주먹일 때 평가된 중지 끝–뿌리 거리가 열린 손의 80% 미만인지 검사했다. 이 검사를 실제 주먹 접촉·충돌 검증으로 확대하지 않는다.

Asset Tool 자동 검사 **48개 통과**, 기존 실제 모델 파츠/Undo/출력 회귀 검사 통과. 출력된 설정을 새 `--render-preset` 경로로 실제 Asset Tool 창에서 불러와 모델·동작·프레임·240×240 설정 전달을 확인했다. 한 실제 모델의 월드 축 조작·키 저장·평가는 10회 평균 약 23ms였으며 입력 지연·GPU 시간·일반 성능 보장은 아니다. 검증 결과는 `output/pose_tool/native_model_keyboard_final/`, `native_parts_regression/`, `native_sample_final/`, `output/performance/`에 둔다.

실행 경로 확인: 바로가기 대상·인자를 확인하고 같은 실행기로 기본 모델을 열었다. 별도 작업본 저장/재로딩 뒤 전용 패널 등록, Layout 뷰포트, 자동 키, 독립 무기, 숨긴 내부 pole과 Asset Tool용 Python 경로를 확인했다. 결과는 `output/pose_tool/native_launcher_check_02/report.json`이다. 같은 중지 거리 검사를 포함한 실제 모델 최종 검사도 `native_model_final/`에서 통과했다.

I5 해결: 검지–소지 뿌리의 배치로 손의 공통 가로축을 구하고, 기존 무기 파지와 같은 Hand 로컬 -Z 손바닥 면을 향하도록 굽힘 부호를 고정했다. 공통 축을 각 마디의 rest 좌표로 변환하므로 뿌리와 마디의 서로 다른 roll에 의존하지 않는다. 주먹과 증분 굽힘에 같은 축을 적용하며 엄지의 기존 조작은 유지한다.

회귀 검사 `tests/blender/check_pose_fingers.py` 추가: 수정 전 실제 모델의 왼손 검지에서 손바닥 쪽 변위가 약 -0.139로 실패했다. 수정 후 양손 네 손가락 모두 손바닥 쪽 변위가 양수이며 같은 마디의 방향 내적이 0.999 이상이고, 손끝–뿌리 거리는 열린 손의 약 47–48%다. 반복 클릭·25도 증분 굽힘·저장/재로딩·원본 해시 보존을 확인했다. 기본 도형, 실제 원본, 이전 버전에서 만든 작업본 모두 통과했다. 기존 네이티브 파츠·IK·복제·저장·동작 출력 회귀 검사도 통과했다. 손바닥/측면 확대 이미지는 `output/pose_tool/finger_axis_final/`, 이전 작업본 검사는 `finger_axis_existing_work/`, 전체 회귀 검사는 `finger_axis_native_regression/`에 둔다. 전체 접촉·간섭 검증과 사용자 최종 사용감 승인은 별도다.
