## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 색상·보간 해상도를 줄인 후보를 Unit Test로 만들고 KTX와 Oodle을 비교하도록 요청했다. 이유는 앞선 첫 화면 로딩 지연과 용량 절감 논의이며 시각은 scope 참조.
- **사용자 제안 2 (U2):** 더 적극적으로 아틀라스로 묶어 압축률과 캐시 공유 효과를 검토하자고 제안했다. 이유·근거는 사용자 발언 `압축률이 올라가지 않아?`, `캐시도 공유 가능하고`이며 시각은 scope 참조.
- **사용자 제안 3 (U3):** 화면 전체 보간이 장기적으로 저렴한지 질문했다. 대상 수 증가의 비용을 검토하려는 논의이며 실제 대체 구현 요청으로 확정하지 않았다. 시각은 scope 참조.
- **사용자 제안 4 (U4):** 문제 해결 과정을 기록하고 기존 방식과 디스크·RAM·GPU 적재량을 Unit Test에서 비교하도록 요청했다. 첨부 이미지로 실제 내부 포맷, GPU Storage, 디스크, 업로드, 디코딩, VRAM, CPU/GPU 프레임과 PSNR/SSIM 항목을 제시했다. GPU Storage와 프로세스 VRAM을 분리하라는 요구를 포함한다. 시각은 scope 참조.
- **사용자 제안 5 (U5):** 반해상도를 적용하지 않은 Oodle도 비교하도록 요청했다. 해상도 축소와 코덱 효과를 분리하는 추가 요구이며 시각은 scope 참조.
- **사용자 제안 6 (U6):** 기존 보간의 Premultiplied Alpha 사용 여부를 질문하고 프리렌더 과정에서 미리 처리할 수 있는지 제안했다. 기존 시작 비용을 실행 전으로 옮기는 논의이며 게임 기본 경로 교체 승인으로 확대하지 않는다. 시각은 scope 참조.

## 2. 사용자 제안 중 AI가 수용한 것

- U1·U2·U4·U5를 독립 실행/재사용 모듈과 여섯 후보의 공정한 데이터 범위 비교에 반영했다. U6의 사전 변환은 이미 이번 후보 제작 경로에서 적용한 방식과 일치하며, Unreal 출력 후 공통 변환·패킹에서 수행할 수 있다고 설명했다.
- U3는 대상 수·화면 채움 면적·움직임 추정·가림·UI 제외·표시 지연을 비교할 별도 과제로 수용했다. 이번 작업에서 화면 전체 보간을 구현하지 않는다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1, 구현상 판단):** 최대 2048×2048, 패딩 4픽셀·4픽셀 정렬의 공유 페이지를 첫 기준으로 사용한다. 고유 색상/벡터를 별도 보존하며 재생은 인덱스로 참조한다. 단일 페이지에 억지로 맞추지 않고 GPU 제한과 클립 참조 페이지 수를 확인한다. 시각은 scope 참조.
- **AI 제안 2 (A2, 구현상 판단):** 색상만 BC7, 벡터는 무손실 수치 형식으로 유지한다. 축소는 signed16 변위를 해석해 처리하고 새 픽셀 단위로 재인코딩한다. 색상은 사전 알파 곱셈 뒤 채널별 면적 필터를 사용한다. 수치 손상·투명 경계 번짐을 피하려는 판단이며 시각은 scope 참조.
- **AI 제안 3 (A3, 구현상 판단):** KTX UASTC RDO 1→BC7+Zstd 6, Oodle BC7 RDO 30+zlib 6으로 실제 파이프라인을 비교한다. 인코더의 RDO 수치가 같은 품질을 뜻하지 않으므로 GPU 내부 형식과 품질을 함께 확인한다. 원해상도 Oodle도 RDO 30을 유지한다. 시각은 scope 참조.
- **AI 제안 4 (A4):** 프리렌더 출력 원본을 보존하고 실행용 데이터의 알파 변환·공유 아틀라스·압축을 제작 단계에서 수행한다. 실행 시는 읽기·압축 해제·GPU 전송으로 제한한다. 기존 시작 병목을 발견한 뒤 설명했으며 게임 본편 기본 적용은 후속 결정이다. 시각은 scope 참조.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 반해상도 비교 제작은 U1, 아틀라스/공유 실험은 U2, 측정 항목은 U4로 요청/수용됐다. 원해상도 Oodle은 U5로 추가됐다.
- 2048 페이지·패딩·RDO 수치·정확한 필터/압축 형식은 AI 구현상 판단이다. 사용자 최적값 승인으로 기록하지 않는다. 후보의 최종 시각 승인과 게임 기본 적용 결정은 받지 않았다.

## 5. 반영 후 발견한 문제

- **I1, 기존 시작 병목:** 첫 160클립 실행은 첫 화면 약 39.79초, 알파 곱셈 32.49초였다. 후속 동일 범위 실행은 32.37초, 알파 곱셈 26.55초였다. CPU 픽셀 반복문이 지배 구간이라는 근거다. 두 실행의 개별 값을 평균/최저 보장이나 cold start로 취급하지 않는다.
- **I2, 새 아틀라스 GPU 비용:** 최신 한 클립 재생에서 기존 GPU 비교 패널 약 0.090ms, 공유/압축 후보 약 0.130~0.133ms였다. 인덱스·분기·uniform·샘플링 구조를 바꾼 비용이며 용량 감소를 프레임 성능 개선으로 주장할 수 없다. 원인별 비용 분해는 아직 하지 않았다.
- **I3, 반해상도 시각 손실:** 실제 표시 크기에서 얇은 선·칼끝·표면이 부드러워졌다. 움직이는 영역 SSIM은 반해상도 Oodle 약 0.809(블러 끔)/0.815(켬)으로, 블러가 손실을 없애지 않았다. 전 모션에 대한 사용자 승인이 아니다.
- **I4, GPU Storage와 VRAM 차이:** 모든 데이터의 논리 GPU 텍스처 저장량에 비해 WDDM 전용 점유가 훨씬 작고 후보 간 비례하지 않았다. 실제 장치는 NVIDIA RTX 5070 Laptop GPU, OpenGL 4.6/NVIDIA 592.01이었다. 특정 한 클립을 그린 조건이므로 전체 페이지의 동시 상주/물리 할당 비용을 입증하지 않는다. 드라이버 내부 원인은 미확정이다.
- **I5, 계측 보완:** 첫 구현은 GPU 메모리의 종료 전 한 표본만 기록했다. 로딩 전/직후/종료 전과 30프레임 간격의 전용·공유 표본을 추가했다. 초기 결과 파일은 이전 방식의 기록이며 최신 필드의 결과로 바꾸어 해석하지 않는다. 재측정 기록은 시각별 경로와 최신 통합 보기를 분리하도록 개선했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U6: 프리렌더 뒤 실행용 변환/패킹에서 미리 알파를 곱하는 경로를 설명했다. 이번 후보의 공통 제작기가 이미 사전 처리하며 원본은 유지한다. 일반 게임 에셋 로더를 기본 교체하지 않았다.
- I2·I4 ↔ U2·U4: 캐시 공유·GPU 포맷·별도 프로세스·GPU 시간·전용/공유 점유를 함께 측정하도록 반영했다. 메모리 절감만을 근거로 더 빠르다고 결론내리지 않는다.
- I3 ↔ U5: 원해상도 Oodle을 같은 파라미터로 추가했다. 움직이는 영역 SSIM 약 0.9944/0.9945(블러 끔/켬), PSNR 약 43.82/44.08dB로 반해상도보다 손실이 작았다. 해상도 유지와 압축을 분리해 비교할 수 있다.

## 7. AI 해결 제안과 실제 해결 과정

- 공통 제작/인코더·GPU 아틀라스·독립 화면·계측을 분리했다. 기존 보간기에 기본 비활성 `TimingRecorder`를 선택 주입하고 실행 루프에 선택적 present 완료 알림을 추가했다. Pico2D 원본은 수정하지 않는다. SDK·KTX 도구·패키지는 `automate/`의 로컬 제외 경로에 보존한다.
- 기존 입력과 원본 에셋은 읽기만 수행했다. AI 결과물·로컬 SDK/설정/절대 경로가 포함된 자료는 Git 제외 대상이다. 공개 기본 도형은 `samples/texture_comparison/`의 직접 작성한 수치와 코드다.
- 8클립 예비 비교 후 전체 160클립으로 확장했다. 원해상도 공유는 색상 34+벡터 59=93페이지, 반해상도는 색상 9+벡터 15=24페이지다. 원해상도 색상 참조 1,824회→고유 1,040개, 반해상도는 1,033개다. 벡터 1,824개는 전부 고유였다. 모든 클립이 각 종류 최대 2페이지 참조 제한을 통과했다.
- 실제 GPU 조회에서 색상 BC7 `0x8E8C`, 벡터 RGBA8 `0x8058`을 확인했다. KTX와 Oodle이 같은 벡터 텍스처를 공유하는 기본 도형 OpenGL 검사를 통과했고, 같은 후보의 재참조는 추가 GPU 저장 0바이트였다. 인스턴스 1/8/32개 비교 조작을 제공하지만 해당 세 부하 전체의 성능 측정 완료를 뜻하지 않는다.

- 표는 일반 본체/그림자 시트·HUD·바닥을 제외한 실제 비교 입력 범위다. 첫 present는 Python 테스트 진입 기준이며 프로세스 생성 자체는 제외한다. OS 디스크 캐시를 비우지 않았고 여섯 경우 각각 단일 실행 결과다. 원해상도 Oodle은 기존 다섯 기준 뒤 별도 추가 측정했다. 사전 변환·디스크 압축·공유·해상도 변화 효과가 함께 포함되며 코덱 단독 효과로 해석하지 않는다.
- 원해상도 공유의 움직이는 영역 SSIM 약 0.99994/0.99995, 반해상도 RGBA 약 0.82186/0.82721, KTX 약 0.80168/0.80711이었다. 기본 품질 검사는 `combo_03/s`의 위상 0.15/0.5/0.85와 블러 켬/끔이며 실제 160클립 전체 시각 검사와 구분한다. 지정 캡처를 직접 열어 반해상도 흐림과 원해상도 보존을 검토했다.
- 최신 통합 측정·원본 보고서·품질 이미지는 로컬 `data/texture_comparison/sword_all_half_20261113/benchmark/summary.json`에서 연결한다. 마지막 추가 실험은 `runs/20261113_121108_d0a23f/`다. 초기 전체 보고서는 `benchmark/<후보>.json`, 이후 실험은 시각별 하위 폴더에 보존한다.
- 검증: 기존 보간/실행/이동 검사 48개 통과·선택 조건 9개 생략. 새 축소·캐시·손상 데이터·품질 지표 8개와 실제 KTX/Oodle GPU 공유/해제 1개, 총 9개 통과. 기본 도형과 실제 160클립 각각 6후보의 OpenGL 실행을 확인했다. Runner standalone 판별과 import 무실행도 확인했다. 전체 사용자 키 조작·모든 방향/모션 품질·최종 선호·본편 통합·캐시 스트리밍·병렬 로딩은 별도다.
