# Intel 180기 배열 복원 CPU와 느린 프레임 추적

- **기록 ID** `FDLOG-20261123-intel-array-cpu-tail`
- 작업일 2026-11-23 KST.

## 1. 사용자가 제안한 것

- **U1** 배열 바인딩 횟수가 줄었는데 `PartPainter.paint`에서 CPU 시간이 늘어 보이는 이유를 조사하고, 실제 느린 장면에서 다음 병목을 찾는다. 정확한 요청 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261123-intel-array-cpu-tail:U1]]` 검색 단서는 `Binding이 줄었는데 CPU time은 다시늘어나`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 동일 배열의 유닛별·일괄 복원만 바꾸는 함수 대조와, 게임 기본 2D 경로의 전체 장면 추적을 각각 수행했다. 두 조건에 HUD·그림자·파츠·SMAA·전투 효과를 그대로 사용했다.

## 3. AI가 제안한 것

- **계측상 판단** 다른 프로세스의 중첩 함수 측정으로 비용 위치를 확인하고, 같은 프로세스에서 복원 경로를 교차해 시간 분포와 렌더 스레드 CPU 사이클을 다시 비교한다. 전체 장면에서는 측정한 480프레임 중 작업 경과 상위 12개를 각 실행의 전체 평균과 비교한다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U1 범위에서 구현 변경 없이 조사했다.

## 5. 반영 후 발견한 문제

- **I1** 기존 실행에서 `PartPainter.paint` 평균은 측정 순서에 따라 반대 방향으로 변했다. 바인딩 호출과 실제 프레임의 CPU 함수 경과, 렌더 스레드 실행량은 각각 다르게 움직일 수 있다.
- **I2** Windows의 `thread_time_ns`는 수백 µs짜리 개별 호출에서 약 97%가 0을 반환했다. 스레드 사이클은 Windows `QueryThreadCycleTime`으로 별도 측정하고 경과 시간으로 환산하지 않았다. [Windows API](https://learn.microsoft.com/en-us/windows/win32/api/realtimeapiset/nf-realtimeapiset-querythreadcycletime)

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** Intel(R) Graphics 드라이버 32.0.101.8860, FHD Medium/SMAA, 180기·간격 15m, HP 100,000, 자동 검 60Hz, 준비 120프레임, VSync 끔을 고정했다. 기본 2D 가벼운 프레임 계측 480프레임에서는 51.56 FPS, 작업 P99 27.57ms였다. 함수 상세 계측의 FPS는 별도로 해석한다.

## 7. AI 해결 제안과 실제 해결 과정

- **I1** 정순·역순에서 등 무기 2방향 보간 각 236회. 일괄 복원으로 `glBindTexture` 14→8회, `glGetIntegerv` 11→5회, SDL 바인딩은 1회였다. `bind_atlas_textures` 복귀는 정순 17.89→7.85µs, 역순 18.24→7.66µs/제출이었다.
- 상세 정순·역순에서 `paint` 평균은 363.83→384.15 / 363.35→383.26µs, 중앙값은 346.80→349.40 / 347.65→346.40µs였다. `sampler.batch` 진입은 61.4→71.6 / 61.1→72.1µs로 증가했다. 이 구간은 해당 호출의 배열 복원을 수행하기 전이며 SDL 플러시 자체는 2.35→2.53 / 2.26→2.59µs였다. 배열 uniform 제출 전체는 35.8→41.6 / 37.7→38.3µs, 사각형 제출은 26.5→27.0 / 25.8→27.5µs였다.
- 같은 프로세스에서 매 프레임 복원만 교차한 472회, 동일 입력 위상 118개에서 `paint` 평균은 222.88→218.63µs, 중앙값은 199.90→203.25µs였다. 렌더 스레드 CPU 사이클 평균은 649,542→652,314회로 약 0.4% 증가했다. 바인딩 복귀의 절약은 반복됐고, 함수 전체의 일정한 CPU 경과 증가는 재현되지 않았다. 상세 계측에서만 나타난 평균 차이를 일괄 복원의 직접 비용으로 판단하지 않는다.
- 기본 2D의 CPU 측 draw 제출은 평균 16.50ms, P99 22.83ms였다. update는 평균 2.45ms, present는 0.27ms였다. 전체 draw의 GPU 시간 질의는 평균 7.18ms, P99 16.97ms였다. 제출 CPU 경과와 GPU 경과는 같은 프레임에서 겹칠 수 있다.
- 가벼운 함수 계측을 두 번 반복했을 때, 상위 12개 프레임에서 draw 제출 평균은 21.47→31.92 / 21.53→28.89ms, update는 2.53→3.55 / 2.56→3.22ms였다. 상세 계측의 프레임 성능은 서로 다른 수준을 섞어 비교하지 않는다.
- **HUD 처리량** HUD 전체는 전체 평균 9.62~9.73ms, 늦은 프레임 평균 11.96~13.32ms였다. `PicoRenderer.text`는 1.80ms에서 2.33~2.51ms, 내부 `_atlas_text`는 0.55ms에서 0.71~0.77ms였다. 크기 측정은 평균 151회/프레임과 0.32ms였다. `HudBatchQueue.flush`의 빈 호출 약 50회는 0.10ms였고, 실제 제출 약 80회는 0.79~0.81ms였다. 텍스트 아틀라스 제출은 23회/프레임이었다. 함수 포함 시간은 중첩되므로 합산하지 않는다.
- **적 제출** `EncounterView.draw`는 3.98~4.02ms에서 상위 프레임 5.44~6.30ms였다. `EnemyPartBatch.prepare`는 0.97~0.99ms에서 1.37~1.43ms, `EnemyCrowdAtlas._draw_quads`는 0.52ms에서 0.67~0.84ms였다. 군집 본체 패킹의 자체 시간은 평균 0.41ms이고 상위 프레임 0.50~0.52ms였다. 해당 장면은 군집 아틀라스 원거리 경로와 근거리 파츠를 함께 실행했다. 적 렌더 GPU 패스 평균은 두 실행에서 1.65ms였다.
- **아틀라스 꼬리** `PartAtlasResidency.stream`은 전체 평균 0.17~0.18ms에서 상위 프레임 1.45~2.08ms였다. `_prepare_prefetch`가 상위 프레임당 0.77~1.18ms, 실제 GL 텍스처 전송은 0.10~0.13ms였다.
- 별도 렌더 스레드 추적 480프레임에서 `_prepare_prefetch` 5건은 각각 3.85~6.80ms였다. 이미 준비된 방향 메타데이터를 받아 플레이어 `combo_02/2`, `combo_03/4`, `combo_04/0`, `combo_04/1`과 소형 적 `attack/5`를 준비했다. 각 건의 `Path.resolve()` 12회에 2.60~6.18ms가 쓰였다. 소형 적 공격 38번 프레임은 42.18ms였고 이 중 `_prepare_prefetch` 6.80ms와 그 안의 경로 해석 6.18ms를 확인했다. `catalog.direction` 0.021ms, 작업자 제출 0.033ms였다. 경로 해석은 `_describe_direction`의 페이지 키 생성과 `TexturePageWork.__init__`을 지날 때 반복된다.
- 다음 수정 지점은 P99의 방향 페이지 경로 해석과 평균 제출의 HUD 텍스트다. 방향 메타데이터 작업자가 해석한 페이지 키를 전송하면 렌더 스레드에서 다시 경로를 찾을 필요가 줄어든다. HUD에서는 동일 문자열의 크기·아틀라스 배치를 재사용하고, 배치를 끊는 텍스처 전환을 줄이는 작업의 비용을 따로 비교한다.
- 같은 렌더 스레드 추적에서 검 접촉 효과 `PicoSwordEffects.draw_contacts`는 평균 1.69ms, 상위 12프레임 2.07ms였다. 측정 480프레임에 `ShaderProgram.__init__` 호출은 0회였다.
- 기존 py-spy 도구로 Python 스택도 별도 수집했다. 초기화와 예열을 포함한 벤치마크 루프 스택 2,288개에서 `EncounterView._draw` 포함 465개, `HudBatchQueue.flush` 자체 61개를 확인했다. 수집 시간이 끝나 대상 벤치마크의 정상 종료 보고서는 없었다. 표본 비중은 프레임 시간으로 환산하지 않았다.
