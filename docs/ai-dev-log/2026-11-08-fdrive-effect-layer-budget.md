# FDrive 전투 이펙트 레이어·자원 예산

- 기록 ID: **FDLOG-20261108-fdrive-effect-layer-budget**
- 기록 작성 기준 시각: 2026-11-08 19:12:49 KST에 확인한 도구 시각이다. 사용자 발언 시각과 구분한다.
- 출처: 현재 대화의 “이펙트도 화려하게”, “이펙트 레이어도 따로 넣고”와 앞선 기종별 이미지 공유·씬별 필요 이미지 로딩 설명이다.
- 개별 요구의 정확한 발언 시각은 미확인이다. [[FDLOG_MISSING_TIME:FDLOG-20261108-fdrive-effect-layer-budget:scope]] 위 검색 구절의 원문에서 시각을 확인한다. 사용자 제안 1과 AI 제안 1에 공통 적용한다.
- 상태: **이펙트 요구와 추산 항목의 문서 반영**. 이펙트 시스템·후처리 구현과 성능 검증은 수행하지 않는다.

## 1. 사용자가 제안한 것

- **사용자 제안 1 (U1):** 화려한 전투 연출을 위해 별도 이펙트 레이어를 추가한다.
  - 이유·근거: 사용자가 화려한 이펙트가 필요하다고 직접 설명했다. 앞선 자원 논의에서는 동일 기종의 이미지 공유와 전투 씬에 필요한 이미지의 선택적 로딩을 제시했다.

## 2. 사용자 제안 중 AI가 수용한 것

- U1을 PRE-PRD 5.2·7.4절에 반영한다. 기체·전투 판정과 효과 재생을 구분하고, 기존 이미지 공유·씬별 로딩 원칙을 효과 자원에도 적용한다.

## 3. AI가 제안한 것

- **AI 제안 1 (A1), 설계 검토:** 레이어는 논리적인 표시·관리 단위로 두고 표시 순서·수명·재생 상태를 관리한다. 메모리·동시 효과 수·화면 점유와 중첩·갱신·그리기 비용을 별도로 계측한다.
  - 이유·근거: 낮은 사양의 내장 그래픽을 고려하는 규모 추산에서 기체 수만으로 연출 비용을 판단할 수 없다. 레이어의 존재만으로 별도 화면 크기 렌더 타깃을 필수 할당한다고 가정하지 않는다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 사용자는 U1의 별도 레이어와 화려한 연출 요구를 직접 제시했다. A1의 구체적인 정렬·합성·자원 한도·품질 조절·렌더 타깃 구현을 승인한 것으로 기록하지 않는다.

## 5. 반영 후 발견한 문제

- **발견한 문제 1 (I1), 요구의 명시:** 기존 문서는 잔상·Rim Lighting·Bloom과 후처리를 언급했지만 전투 이펙트의 독립 관리 계층과 규모 추산 항목이 명시적이지 않았다. 새 실행 버그가 아닌 요구사항 보완이다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1: 별도 이펙트 레이어를 추가하도록 요청했다. 기존 전투 규칙과 개체 이미지 공유·필요 자원 로딩 원칙을 유지하면서 문서에 반영한다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 5.2절에 이펙트 계층·표시 순서·논리 레이어 정의를 두고 7.4절에 공유 자원·씬별 로딩·이펙트 부하 검증 항목을 추가한다. 세부 자원 예산과 합성·품질 정책은 8.4절에 미정으로 남긴다.
- 확인 범위: 문서 정합성·상대 링크·로그 형식·누락 인덱스·공백을 확인한다. 이펙트 생성·게임 실행·실제 화면 품질·낮은 사양 기기의 성능은 검증하지 않는다.
