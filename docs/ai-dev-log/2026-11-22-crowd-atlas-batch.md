# 고정 군집 아틀라스 묶음 제출과 HUD 계측

**기록 ID** `FDLOG-20261122-crowd-atlas-batch`

2026-11-22 KST 작성. 실제 비교는 2026-11-21 밤부터 자정을 넘겨 진행했다.

## 1. 사용자가 제안한 것

- **U1** 현행 고정 아틀라스의 원거리 본체·그림자를 묶고 가림과 공격 효과 순서를 유지한다. 제출 주체를 구분해서 180·600기를 변경 전후 비교한다.
- **U2** HUD 스캔라인에서 실제로 줄일 수 있는 비용을 검토한다.
- 요청의 정확한 한국 시각은 [[FDLOG_MISSING_TIME:FDLOG-20261122-crowd-atlas-batch:scope]]다. 검색 단서는 이 대화의 `지금 쓰는 고정 아틀라스의 원거리 본체랑 그림자도`와 `그러면 scanline을 최적화할 수는 없어`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1** 현재 `EnemyCrowdAtlas` 사용하는 본체와 그림자 경로를 대상으로 했다. 180·600기 화면 비교와 동일 프레임 재그리기를 실행했다.
- **U2** 스캔라인 패턴·밝은 띠의 결과를 보존하면서 CPU 도형 준비 비용을 줄였다.

## 3. AI가 제안한 것

- **A1** 기존 발밑 Y 정렬에서 연속한 원거리 본체만 같은 텍스처의 UV·정수 화면 사각형으로 제출한다. 공격 중 기체, 근거리 PBR, 공유 포즈 캐시, 디버그 표시 경계에서 순서를 지킨다. 그림자 패스는 같은 시트의 타일을 기존 순서로 묶는다. 근거는 `78de62e`와 GPU 픽셀 대조다.
- **A2** 큐 flush 호출 위치와 실제 큐에 담긴 도형을 분리해서 계측한다. 원거리 본체 개별 복사, 본체 배치, 그림자, HUD 스캔라인 제출을 별도 항목으로 기록한다. 근거는 앞선 스캔라인 귀속 재현과 `15763ba`다.
- **A3** 스캔라인의 화면 내부 패널은 재클리핑 없이 쓰고, 패널별 색과 기본 투명도는 한 번 계산한다. 비정수 배율과 밝은 띠에서 픽셀과 시간을 대조한 뒤 반영한다. 근거는 `3253288`과 `scanline_replay.json`이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- 요구 범위는 U1과 U2를 따른다. 연속 구간 규칙, 512개 사각형의 재사용 버퍼, 계측 분류와 스캔라인 내부 연산은 구현상 판단이다.

## 5. 반영 후 발견한 문제

- **I1** 겹침·공격·록온이 섞인 GPU 장면의 개별 복사와 배치 사이에서 786,432개 색상 채널 중 1개가 1단계 달랐다. 6개 사각형마다 제출하도록 제한한 검사는 기존 배치와 픽셀이 일치했다.
- **I2** 전체 교전 프레임 시간은 두 기체 수 모두에서 실행 순서별 변동이 컸다. 제출 감소만으로 전체 FPS 향상을 확정할 수 없었다.
- **I3** 스캔라인 함수 안에서 다른 텍스처의 배치가 프레임당 8회 제출됐다. 스캔라인 도형 자체의 제출 10.36회는 미니맵·텍스트·필터 폴리곤 등의 함수에서 발생했다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U1** 같은 장면에서 배치 플래그만 바꿨다. 원거리 공격 중인 기체·록온한 근거리 기체가 다른 적과 겹치는 경우를 검사했다.
- **U2** 스캔라인 표시를 유지한 채 처리한 정점의 위치·UV·색상과 최종 GPU 픽셀을 비교했다.

## 7. AI 해결 제안과 실제 해결 과정

- **A1 ↔ I1** `encounter_view.py`의 기존 정렬과 가림 경계를 유지했다. `enemy_crowd_atlas.py`는 정점과 인덱스 버퍼를 재사용하며 그림자 투명도를 정점에 실었다. 512개를 넘으면 입력 순서대로 다음 제출을 이어 간다. 실제 OpenGL 겹침·록온·근접/사격 효과 검사에서 최대 RGB 차이가 1이었다.
- **A2 ↔ I2·I3** `--compare individual_crowd_atlas baseline`에서 개별 복사와 배치를 교대로 실행했다. `sdl_calls_per_frame`에는 실제 제출 주체, `hud_submit_triggers_per_frame`에는 큐를 비우게 한 호출 위치를 기록한다. 600기에서 실제 `hud.submit.scanlines`의 Geometry 제출은 10.36회이며, 스캔라인 함수가 유발한 다른 텍스처의 제출 8회는 `hud.submit.other_textured`에 들어간다.

### 180기·600기 전후 비교

RTX 5070 Laptop GPU, FHD, 중간 PBR, 자동 SMG, 무음, 12m 배치, 같은 프로세스에서 순서를 뒤집었다. SDL 제출은 예열 30·측정 90프레임씩 두 회차의 평균이다. 배치 후 본체 제출은 공격 효과 등에 필요한 개별 복사와 Geometry 제출을 합친 값이다. 이 값은 SDL API 호출 횟수다.

| 적 수 | 원거리 본체 제출/프레임 | 원거리 그림자 제출/프레임 | 같은 프레임 적 그리기 평균 (ms) | 같은 프레임 적 그리기 P50 (ms) |
| ---: | ---: | ---: | ---: | ---: |
| 180 | 92.99 → 17.01 | 92.98 → 1.00 | 4.59 → 4.37 | 4.08 → 3.89 |
| 600 | 155.36 → 20.86 | 155.33 → 1.00 | 11.76 → 11.19 | 9.93 → 9.74 |

- **I2** 같은 프레임 비교는 각 시뮬레이션 상태에 두 방식의 `draw_targets`를 호출하고 다음 프레임에서 순서를 뒤집었다. 미리 밀린 GPU 작업을 끝낸 뒤 CPU 구간과 제출 flush를 측정했다. 후속 GPU 작업 완료까지 걸린 평균은 180기 5.18→4.92ms, 600기 12.12→11.65ms였다. 두 방식의 원거리·근거리 본체 수는 각 프레임에서 같았다.
- 상세 계측을 끈 전체 화면 3회차의 프레임 작업 평균 범위는 180기 28.70~41.44→33.83~37.90ms, 600기 46.27~48.70→41.01~55.73ms였다. 회차별 방향이 엇갈렸다. 스캔라인 변경 효과는 아래 별도 재생에서 확인했다.
- **A3** OpenGL 10개 패널에서 조건당 320프레임, 정수·비정수 배율과 화면 경계, 움직이는 밝은 띠를 비교했다. 캡처 40쌍이 픽셀 단위로 같았다. 스캔라인 호출 시간 평균 0.3418→0.2907ms, P50 0.3241→0.2691ms였다. 패턴·클리핑과 색 계산 변경이며 제출 횟수 자체는 그대로다.
- UTF-8 일반 자동 검사 1,173개 중 1,088개 통과, 85개 생략이다. HUD 배치 19개·HUD 필터 17개·군집 아틀라스 선택 GPU 검사 2개가 통과했다. UHD 630 실기와 직접 조작은 미검증이다.
