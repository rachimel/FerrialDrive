## 1. 사용자가 제안한 것

- **U1:** 게임 실행 중 프레임 보간 Unit Test와 모션 블러를 요청했다. 원본 3D가 있으므로 Unreal 프리렌더의 모션 벡터를 활용하도록 지적하고 실제 검 동작 연결·테스트 출력을 요청했다.
- **U2:** SmoothStep은 각 중간 프레임마다가 아니라 처음/끝 KeyFrame 목표 위상에 적용하도록 정정했다. 강도는 손가락 도구처럼 조절하고 노출 시간도 별도로 유지하며, 잔상 방향성과 콤보 1~4타 표시를 요청했다.
- **U3:** 연속 1→2타에서 위상이 0으로 초기화되지 않는다고 지적했다. 이월/0 시작 두 후보 비교 후 렉의 원인 파악과 A/B 전환 표시를 요청했다. 이유·근거는 각 요구와 현재 화면에서의 체감이며, 개별 시각은 기록 범위를 따른다.

## 2. AI가 제안한 것

- **A1:** 기본 도형과 실제 중간 시점 정답을 비교하고, 실제 모션은 native MRQ 벡터의 정/역방향 출력으로 연결한다. 픽셀 변위를 AI로 추정하지 않고 가시 표면의 양방향 대응 정보를 얻기 위한 제안이다.
- **A2:** 강도는 선명한 보간/잔상 합성의 비율, 노출은 시간 구간으로 분리한다. 후방/양방향/전방 잔상을 비교하고 역재생에서는 시간 방향도 뒤집는다.
- **A3:** A는 남은 시간 이월, B는 새 타격의 위상 0 표시로 구분한다. B는 경계 잔여 시간을 버리므로 시간 연속성과 첫 프레임 표시의 차이를 비교한다. 성능 문제는 CPU 계측 후 클립·배경 캐시와 단일 재생기로 대응한다. 제안 시각·출처는 기록 범위를 따른다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U3을 독립 테스트·재사용 렌더 모듈·자동화·명세에 반영했다. Pico2D 원본·원본 애니메이션 키·리그·본편 전투 판정은 변경하지 않았다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- U1의 실제 Unreal 연결, U2의 방향/강도/노출 요구와 U3의 두 후보 비교·전환 요청은 명시 지시다. 사용자가 A/B 중 최종 방식을 선택하거나 가림·전체 외관을 승인했다고 간주하지 않는다.

## 5. 반영 후 발견한 문제

- **I1:** RenderOffscreen 실행이 설치된 태블릿 입력 플러그인에서 충돌했다. 현재 렌더 맵은 제작용 프로젝트가 아니라 전용 prerender_host에 있었다.
- **I2:** 정확한 마지막 키 시각이 Sequence 반복 경계로 환산돼 정/역방향의 양 끝 자세가 달랐다. 중간 프레임의 대응은 거의 일치했다.
- **I3:** 이월 방식은 다음 타격의 첫 출력 위상이 0보다 클 수 있다. 동시 A/B는 두 재생기와 준비 비용을 사용했다. CPU 호출 계측에서 이미지 알파 변환·텍스처 준비와 매 프레임 체크무늬 반복 그리기가 비용으로 확인됐다.
- **I4:** 모션 벡터만으로 가려진 표면을 복원하지 못한다. 빠른 검/팔의 번짐과 래스터 경계 오차가 남으며 모든 프레임이 혼합보다 우수하지 않았다.

## 6. 사용자 해결 제안과 실제 해결 과정

- U3으로 I3의 전환 의미를 명확히 했다. 두 후보를 비교하고 한 번에 하나만 표시하도록 선택했다. U2로 잔상 강도·방향·노출을 별도 조작하도록 했다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: 기존에 사용한 일반 Unreal 전용 배치 방식과 실제 맵 소유 프로젝트를 사용했다. 설치·프로젝트 플러그인 설정을 변경하지 않았다.
- I2: 원본 키를 수정하지 않고 검증 Sequence 끝에 1 tick의 시간 여유를 두었다. 재출력 후 정/역방향의 색상 오차를 확인했다. 2타 원본 `.uasset` 해시는 기존 인계 기록의 `47fd3b9562522962d4d119871844c63abfc7d6db45d84044c36bf4164087088b`와 일치했다.
- Unreal 5.8 native MRQ 고정밀 EXR 벡터와 PNG를 출력했다. Blender 5.3.0은 EXR/PNG 디코딩·변환에만 사용했다. 네 동작에서 동일한 RG 채널·축 부호·배율이 측정됐고, 원본 384×384와 공통 크롭 `(55,56,245)`를 유지했다. 입력은 로컬 `data/frame_interpolation/`, 원시 출력·캡처는 `output/frame_interpolation/`, 보존 요청·재사용 조사는 `automate/workspace/frame_interpolation_20261112/`에 뒀다.
- I3: 한 재생기에서 Tab/버튼으로 A/B를 전환한다. R은 같은 1타 시작점으로 되돌린다. 네 클립을 사전 준비해 CPU 디코딩·알파 변환·GPU 업로드를 재사용하고, 체크무늬를 캐시했다. CPU 120프레임 계측에서 배경 누적 시간 약 0.535→0.016초, 네 클립 알파 변환 8회 누적 약 1.351→0.519초였다. 총 프레임/GPU 성능으로 확대하지 않는다.
- 실제 OpenGL 포함 **16개 검사 통과**. 네 동작의 **26개 중간 구간**에서 알파 IoU 최솟값 약 0.807, **24개**에서 벡터 보간 오차가 단순 혼합보다 낮았다. 방향 반전·강도 0%·블러 노출·첫 위상·캐시 재사용·해제를 확인했다.
- 정적 캡처를 직접 열어 실제 검 동작과 A/B 전환 화면을 확인했다. 앞선 도형 테스트의 화면 자동 조작은 사용자가 중단했으며, 이번 작업에서는 추가 화면 자동 조작을 하지 않았다. 실제 중간 정답은 블러 없는 48fps이며 시간 오차를 별도로 표시한다. I4·사용자 품질 승인·다른 방향·본편 연결·다수 기체 성능은 남아 있다.
