# Intel 교전 RAM 증가와 PBR 액션 시트 중복

- **기록 ID** `FDLOG-20261123-intel-pbr-action-memory`
- 작업일 2026-11-23 KST.

## 1. 사용자가 제안한 것

- **U1** 근거리 적 GL 공통화와 PBR 배열 작업 이후 RAM이 600MiB에서 약 1.9GiB로 오른 이유를 조사한다. 정확한 요청 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261123-intel-pbr-action-memory:U1]]` 검색 단서는 `600MiB에서 1.9GiB`다.
- **U2** 외장 GPU 필수 사양을 결정하기 전에 성능을 유지하며 메모리를 줄인다. 정확한 요청 시각은 미확인이다. `[[FDLOG_MISSING_TIME:FDLOG-20261123-intel-pbr-action-memory:U2]]` 검색 단서는 `성능을 최대한 살리면서도 메모리를 줄여야`다.

## 2. 사용자 제안 중 AI가 수용한 것

- **U1·U2** GPU별 Working Set·Private Bytes·DXGI 메모리를 대조하고 Intel의 같은 전투에서 로딩 호출별 증가량을 측정한다. UHD 630·8GB 목표는 유지한 상태에서 중복 저장을 줄인다.

## 3. AI가 제안한 것

- **A1, 구현상 판단** 모든 클립을 현재 PBR 무기 카탈로그가 그리는 2D 시트는 로딩에서 GPU 업로드를 생략한다. 미지원 동작의 폴백은 품질 변경과 함께 준비·교체해 실시간 업로드와 시각 변경을 피한다. 근거는 2026-11-23 KST Intel의 로딩 단계별 표본이다.

## 4. AI가 제안한 것 중 사용자가 수용한 것

- A1은 U2 범위에서 시험하고 작업 트리에 반영했다. 최소 사양 변경 결정은 없다.

## 5. 반영 후 발견한 문제

- **I1** 비교 시작점인 RTX 5070 Laptop 2D 실행은 로딩 직후 Working Set 614~621MiB였다. Intel 2D는 배열과 키 캐시를 사용하기 전에도 1,394~1,396MiB였다. DXGI 로컬 사용량은 대표 표본에서 261→911MiB였다. 사용자가 본 약 1.9GiB의 실행 조건은 표본으로 확인되지 않았다.
- **I2** Intel에서 수동→일괄 배열 복원의 Working Set 피크는 1,766→1,770MiB와 1,775→1,779MiB였다. Intel 2D의 근거리 GL 공통화 전후 재검사에서는 로딩 직후 1,393→1,388MiB, 피크 1,735→1,703MiB였다.
- **I3** 두 렌더 경로가 모두 `MovementApplication.load_action_assets`로 같은 카타나·아킴보·레일의 구형 2D 시트를 PBR 모션 뒤에 올렸다. Intel에서 Working Set 증가는 각각 27.1·449.4·40.6MiB였다. 같은 구간 DXGI 로컬 증가는 각각 27.1·448.5·40.5MiB였다. GPU 구간과 프로세스 RAM은 합산하지 않는다.

## 6. 사용자 해결 제안과 실제 해결 과정

- **U2** FHD Medium/SMAA·180기·15m 간격·HP 100,000·자동 검 60Hz·예열 120·계측 480프레임에서 Intel 2D 경로를 실측했다. 배열과 아틀라스 키·HUD 레이아웃 초안은 비교에서 제외했다. 전후 실행 순서를 양쪽에서 바꿨다.

## 7. AI 해결 제안과 실제 해결 과정

- **A1** High·Medium·Low에서 실제 선택한 플레이어의 PBR 그룹이 세 구형 카탈로그의 모든 모션을 포함함을 확인했다. 구형 시트가 필요한 동작은 로딩 단계에서 준비한다. 품질 변경 적용 전 실패·취소 시 기존 폴백을 유지하고 후보를 닫는다.
- 제한 없는 네 번의 실측에서 전후 각 두 실행 평균은 로딩 직후 Working Set 1,393.0→911.2MiB, 피크 1,719.4→1,314.2MiB, 피크 Private Bytes 2,764.2→2,473.8MiB, 로딩 직후 DXGI 로컬 911.3→521.3MiB다. 로딩은 12.42→11.92초였다.
- FPS는 37.83→38.98, 프레임 작업 P99는 40.23→42.38ms였다. 두 짝에서 P99가 1.16ms와 3.13ms 증가했다. 전투 프레임 자체에 텍스처 업로드를 추가하지 않았으며, 꼬리 차이의 인과는 미확인이다.
- 180기 앱에서 카운터·톤파·샷건·레일의 PBR 그리기를 각각 30회 이상 확인했다. 전체 화면 RGB 35개 중 34개가 동일했다. 차이는 HUD 4픽셀의 채널 최대 1이었다. 변경 전 반복에서도 같은 샘플의 HUD 10픽셀이 달랐다. 설정·HUD·폴백 자동 검사 45개가 통과했고 1개는 건너뛰었다.
- 기본 2GiB 커밋 제한으로는 로딩을 마쳤다. 첫 프레임에서 커밋 1,956MiB에 도달해 벤치마크의 128MiB 여유 검사로 중단됐다. 실제 UHD 630의 FPS와 메모리 예산 달성은 미검증이다.
- `output/performance/prepared_paths_hud_layout_20261123/`에 단계별 메모리, 고정 프레임 캡처와 보고서를 보관했다. 무기 PBR 연결 자체가 기존 미커밋 작업에 있어 시트 중복 수정도 현재 작업 트리에서 검증했다.
