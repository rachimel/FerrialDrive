## 1. 사용자가 제안한 것

- U1: 본편과 독립적인 Unit Test `asset_load_test.py`를 만들고 기존에 정한 파이프라인대로 에셋이 실제 프리렌더링되고 불러와지는지 확인한다.

## 2. AI가 제안한 것

- A1: 기존 파이프라인 문서의 첫 검증안에 따라 기본 도형·짧은 동작의 **저장 Blender 작업본 → 8방향 본체/그림자 → 시트·메타데이터 → Pico2D 재생**을 먼저 구현한다. 기체 디자인·전투·전체 맵의 완성을 전제로 두지 않는다.
  - 이유·근거: 현재 범용 프리렌더 경로는 명세만 있고 기존 Blender 경로는 표정 리그용이었다. 최소 실제 출력 경로부터 확인하면 게임 런타임과 제작 도구의 경계를 검증할 수 있다.
- 160×160px·4프레임·8 FPS·Cycles 8 samples는 첫 샘플을 위한 구현상 판단이다. 사용자 확정 게임 규격이 아니다. 본체·그림자 PNG를 서로 정렬된 고정 크기 격자로 패킹해 크롭 오프셋 문제를 첫 범위에서 줄인다.
- 재생은 Blender 없이 이미지·JSON만 읽게 하고 최초 생성·재렌더만 별도 백그라운드 Blender에서 실행한다. 사용자 편집 창과 기존 표정 리그 MCP 연결은 변경하지 않는다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1을 수용해 `tests/asset_load_test.py`를 추가했다. Runner의 standalone 규약·직접 CLI 실행을 모두 지원하고 자체 창·입력·효과 갱신·리소스 정리를 소유한다.
- 생성기는 기본 도형 메카·다리 동작을 만들고 `.blend`로 저장한 뒤 실제로 다시 불러온다. 고정 정사영 3/4 카메라·광원으로 8방향×4프레임의 본체/그림자 총 64장을 렌더한다.
- `SSheetCutil.py --pack-prerender`와 독립 빌드가 같은 패킹 함수를 사용한다. 본체/그림자 시트와 기존 편집기 v1 호환 JSON, 방향별 동작 대응 번들을 작성한다. 게임용 로더·초 단위 재생·Pico2D 합성은 `ferrial_drive/assets/`에 분리했다.
- 미리보기는 8방향 원래 배율, 선택 방향 3배 확대, 그림자 분리·발 피봇을 표시한다. 방향 카드/좌우키·Space·다음 프레임·본체/그림자 토글·재렌더·종료를 제공한다. 도구 공통 테마를 사용하며 게임 HUD를 확장하지 않는다.
- 설정·원본 작업본·생성 결과를 분리하고 매 실행 새 작업 폴더를 만든다. 성공 결과만 마지막 포인터에 게시한다. 설정과 렌더/패킹 코드가 같을 때 캐시를 재사용하며 실패·취소는 이전 성공 결과를 덮지 않는다.
