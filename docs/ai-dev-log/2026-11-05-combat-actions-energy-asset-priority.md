# 선택형 스왑·무기 스킬·Overdrive 및 에셋 제작 우선 전환

- 기록 ID: `FDLOG-20261105-combat-actions-energy-asset-priority`
- 기록 기준 시각: 2026-11-05 01:37:18 KST(작업 중 시계 확인).
- 대화 범위: 현재 대화의 UI 피드백부터 PRE-PRD 반영 요청까지. 2026-11-05 날짜 문맥의 전투 논의를 포함하며 이전 발언의 날짜는 추정하지 않는다.
- 개별 제안·정정·수용 발언의 정확한 시각은 모른다. [[FDLOG_MISSING_TIME:FDLOG-20261105-combat-actions-energy-asset-priority:scope]] 보완 시 현재 대화에서 아래 검색 구절의 원문 시각을 확인한다. U1~U5/A1~A4의 제시·수용 시각에 공통 적용한다.
- 출처: 현재 대화의 사용자 발언과 AI 답변. 검색 구절: “카운터도 스왑 동작 중 하나”, “그건 보존할거임”, “스킬의 에너지 소모량”, “PRE_PRD.md에 반영”.
- 상태: 기획·우선순위 문서 반영. 전투 구현·밸런스·Blender 제작 검증과 구분한다.

## 1. 사용자가 제안한 것

- U1: 전투 준비(스탠바이) 페이즈에서 스왑 액션을 선택한다. 카운터도 선택지 중 하나이며 원거리 → 근접의 서브 암 전개를 포함한다. 멀티미사일의 최소 락온 거리처럼 각 액션의 제약과 효과를 검토한다.
  - 이유·근거: 사용자가 전한 친구 피드백은 전투가 단순하고 스왑 카운터 강제가 양날의 검이라는 내용이다. 카운터 폐기가 아니라 선택형 액션이라는 후속 정정을 기준으로 삼는다.
- U2: 스킬 키와 에너지 소모형 무기 스킬을 추가한다. 바람베기는 포위 탈출, 파워 샷은 거리 확보 용도다. 비용은 스킬마다 다르게 두고 수치는 추후 밸런싱한다. 필살기는 메카 에너지 레벨 3에서 사용한다.
  - 이유·근거: 사용자는 액션을 풍부하게 하려는 목적과 기술별 용도를 직접 설명했다. 래비지는 초기 발언의 총기 기술 후보로만 기록한다.
- U3: 레벨 3 일반 에너지를 완충한 뒤 Overdrive 게이지를 더 충전한다. 일반 에너지 소비에도 누적 OD 충전은 보존하며, OD 종료 후 에너지 레벨 초기화는 유지한다.
  - 이유·근거: 사용자가 레벨 3 필살기의 발동 자격과 OD 추가 충전을 구분했고, AI의 충전 보존 제안에 명시적으로 동의했다. 종료 후 초기화는 기존 규칙의 유지 요청이다.
- U4: 이번 논의를 PRE-PRD에 반영하고, 시간이 부족하므로 에셋 제작을 우선한다. UI Unit Test는 현재 수준에서 멈춘다.
  - 이유·근거: 사용자가 전한 UI 피드백은 정적인 인상·세부 표현 부족·레퍼런스 검토 필요다. 시간 부족과 제작 우선순위는 사용자 직접 발언이다.
- U5: “에셋 제작 파이프라인을 구체화”하려는 요청이라고 후속 정정했다. 즉시 제작할 개별 에셋을 고르는 요청으로 해석하지 않는다.
  - 이유·근거: AI가 첫 제작 대상을 묻자 사용자가 작업 범위를 직접 바로잡았다. 시간 부족이라는 U4의 우선순위 근거를 유지한다. 개별 시각은 위 scope 누락 항목에 포함한다.

## 2. AI가 제안한 것

- A1: 빠르게 획득·소비하는 에너지 순환과 스킬/방어/축적 사이의 선택을 권했다. 레벨별 상시 화력 보정 축소도 제안했다.
  - 이유·근거: 스킬 소비가 레벨 하락·화력 하락·필살기 및 OD 지연을 동시에 유발하면 스킬을 아낄 위험이 있다는 설계 의견이다. 검증 결과가 아니다.
- A2: 일반 에너지 소비로 OD 추가 충전의 진척을 지우지 않는 방향을 제안했다.
  - 이유·근거: 일반 스킬을 쓰면서도 OD를 향한 진전을 남기려는 제안이다.
- A3: 스왑 액션의 조건·효과·위험·실패 처리와 기술별 역할을 먼저 정하고, 구체적인 비용은 이후 조정하는 방향을 제안했다. 부가 액션 실패와 무기 전환 성공을 분리하는 안도 제시했다.
  - 이유·근거: 선택지의 용도와 제약을 명확히 하고 기본 조작이 막히는 위험을 줄이려는 설계 의견이다.
- A4: 기존 Blender 연결을 재사용하고 작업본/공통 렌더 설정/미리보기/캐릭터·맵 출력/게임 검증으로 나누는 제작 초안을 작성했다. 첫 검증은 기본 도형의 짧은 8방향 동작으로 제안한다.
  - 이유·근거: 기존 소스는 명령 전달과 표정 생성에 한정돼 범용 출력 경로가 없다. 공통 배율·기준점·설정 재현을 먼저 검증하려는 설계 제안이다. 제시 시각은 위 scope 누락 항목에 포함한다.

## 3. 사용자 제안 중 AI가 수용한 것

- U1~U4를 수용해 PRE-PRD 4.1~4.5·4.9절과 작업 우선순위를 갱신한다. 스킬 비용 수치는 추가하지 않는다.
- 기존 기술 영구 성장·카운터 세부 판정·OD 종료 시 레벨 1/게이지 0 규칙은 유지한다. 전투 준비 페이즈와 OD Standby의 용어를 구분한다.
- U5를 수용해 개별 에셋 제작 대신 Blender 제작 안내에 파이프라인 초안을 구체화한다. Blender 장면 조작이나 새 도구 코드는 작성하지 않는다.

## 4. AI 제안 중 사용자가 수용한 것

- A2의 **충전량 보존**은 “그건 보존할거임”으로 명시 수용했다.
- A1의 빠른 순환 확정·상시 화력 보정 축소는 수용 미확정이다. A3의 액션별 검토는 사용자 요구와 일치하지만 무기 전환/부가 액션의 실패 분리까지 확정한 발언은 없다. 이 내용들은 확정 규칙으로 추가하지 않는다.
- 비용 수치 조정은 U2의 후속 정정에 따라 보류한다. OD 충전 재개·발동에 필요한 일반 에너지 조건과 발동/종료 시 추가 게이지 처리는 미정으로 남긴다.
- A4의 구체적인 설계 방식은 사용자 확인 전 초안이다. U5의 파이프라인 구체화 요청을 세부 구현 방식 전체의 승인으로 취급하지 않는다.

## 5. 반영 후 발견한 문제

- 이번 작업은 문서 변경이며 새 전투 기능을 실행하지 않았다. 반영 후 동작 문제는 검증하지 않았다.
- I1: 문서 반영 전에 기존 문서의 스왑 카운터 고정·레벨 3 완충 즉시 OD Standby·UI 완성 후 에셋 착수 문구가 최신 사용자 요구와 충돌함을 AI가 확인했다. 새 구현 버그가 아니라 기준 문서의 갱신 대상이다.

## 6. 사용자 해결 제안과 실제 해결 과정

- I1 ↔ U1/U3/U4: 사용자의 선택형 카운터·추가 OD 충전·에셋 우선 정정을 기준으로 이전 문구를 교체한다. 미정 사항은 8절에서도 구분한다.
- 사용자 요청 범위는 문서 반영과 작업 우선 전환이며, 스킬 수치 결정이나 전투 코드 구현 승인이 아니다.

## 7. AI 해결 제안과 실제 해결 과정

- I1: PRE-PRD와 Blender 제작 안내의 착수 순서를 맞추고, 이 기록 및 인덱스를 연결한다. 작업 전부터 있던 다른 변경과 사용자 보완 기록은 보존한다.
- 확인 범위: 변경 내용·문서 내 이전 조건의 잔존 여부·링크·공백을 확인한다. 전투 실행·체감 밸런스·Blender 조작·모델 제작·렌더링은 이번 문서 작업에서 수행하지 않는다.
- 커밋·업로드는 수행하지 않는다. 다음 우선 작업은 Blender 프리렌더 에셋 제작이다.
