# 상·하체 분리와 시선 추종 검토

상태: **승인된 분리 프리뷰를 실제 입력용 자료로 확장해 이동·UI 훈련장에 연결했다. Unreal 평가·분리 렌더·재합성·패킹과 실제 Pico2D OpenGL의 스크립트 입력 검증을 완료했다. 사용자의 직접 조작감 확인은 남아 있다.**

확장 범위: **검 7개·총 8개 동작에 상체 8방향×하체 8방향을 함께 평가한 7,104프레임을 사용한다. 부스트·무기 전환·조준 이동/사격은 기존 전신 출력을 유지한다.**

## 동작

- 조준 목표와 실제 몸의 방향을 분리한다. 상체는 목표 방향을 보간 추종하며 하체보다 먼저 반응한다.
- 하체는 상체와의 방향 차이가 ±45°를 넘으면 보간 추종한다. 시작각 안에 재진입해도 정렬될 때까지 추종한다. 차이를 45°로 유지하지 않는다.
- 각도는 수평면의 도, 시간은 초다. ±180° 경계를 최단 방향으로 처리한다. 일시정지의 0초 갱신은 방향을 바꾸지 않는다.
- 보간 속도와 정렬 종료 오차는 설정으로 주입한다. 로컬 후보의 상체 시정수 0.12초·하체 시정수 0.24초·정렬 오차 0.1°는 **검토용 값**이며 사용자 확정 수치가 아니다. 시정수는 회전 완료 시간이 아니다.
- 검·총과 조준 여부에 관계없이 같은 상체 선행·하체 추종 규칙으로 확장한다. 이동·공격 중에도 상체의 시선 기준 방향은 현재 목표를 보간 추종한다. 이동 경로와 공격 전진 방향은 몸의 시선 회전과 분리한다.
- 기존 팔·허리·다리 동작 위에 추종 회전을 더하며 손/무기 상대 파지를 유지한다. 공격의 월드 검 궤적은 회전이 적용된 새 동작에서 추적해야 한다. 기존 고정 궤적·Trail·명중 판정과 섞어 연결하지 않는다.
- 정지 조준과 검·총 확장 프리뷰 확인 뒤 사용자가 훈련장 연결을 지시했다. 원래 프리뷰는 `automate/workspace/upper_lower_all_states_20261117/r01/`에 보존한다. 실제 입력용 자료와 검증 범위는 아래 훈련장 연결을 따른다. 총탄 방향과 록온 획득 정책은 유지한다.
- 훈련장 기본 설정의 기존 표적 A/B/C 배치는 제거했다. 설정을 이미 읽은 실행 창은 재실행해야 적용된다. 적 에셋 파일·록온/명중 모듈은 보존한다.

| `ferrial_drive/combat/upper_lower.py` | 동작·방향 선택과 같은 자세의 검날·총구·발 부착점 |

| `tests/automated/test_aim_follow.py` | 여유각·추종 지속·정렬·최단 방향·프레임률·초기화 검사 |
| `tests/automated/test_unreal_aim_review.py` | 기본 골격의 월드 회전·파지 변환·부품 분할 보존 검사 |

준비 진입점은 `python automate/run.py unreal-aim-review --request 요청.json`이다. 요청은 새 `automate/workspace/`의 `workspace`, `rig_plan`, `baseline_request`, 새 `/Game/MechLab/`의 `asset_root`, 12프레임 배수의 `frame_count`, `follow`, 시간순 `targets`를 받는다. `attachments={본:추종할 본}`은 기존 첫 자세에서 고정 파지 변환을 계산한다. `batch.json`·타격 없는 조준 `samples.json`·현행 본 연결에서 나눈 `groups.json`·출처 해시 `recipe.json`을 만든다. 준비만으로 Unreal을 실행하지 않는다.

선택적인 `motion_sequence`는 `request`·`start_frame`·`frame_count`·`loop` 구간을 0부터 빈틈 없이 나열한다. 같은 메시·12fps 원본의 동작을 이어 재생하며 반복은 원본 시작·끝 자세가 같은 경우만 허용한다. 생략하면 기존 첫 자세 고정 요청을 유지한다. 원본의 첫 자세 기준 월드 파지는 로컬 회전으로 환산해 연속 클립의 경계에서 초기화되지 않게 한다. 실제 동작과의 일치는 Unreal 저장·재로딩과 렌더로 별도 확인한다.

`batch.json`은 기존 `unreal-animation`에 전달한다. 각 클립은 12fps·12프레임, 중간 자세는 120Hz로 준비한다. 연속 동작을 저장 길이에 맞춰 나눠도 방향·추종 상태는 이어진다. 본 추적 결과는 기존 저장 모듈이 허용하는 `Tools/unreal_pipeline/workspace/`의 대응 작업 경로에 둔다. 검토 이미지 출력은 기존 `unreal-units`·`unreal-render`·`unreal.import`를 재사용한다.

`unreal-animation`·`unreal-units`는 `--python-mode editor`(기본) 또는 `--python-mode commandlet`을 받는다. 명령줄 전용 방식은 `-run=pythonscript -script=공통스크립트`를 사용하며 기본 방식의 `-ExecutePythonScript`와 함께 전달하지 않는다. 현재 환경에서는 전용 프로세스에 `-ddc=InstalledNoZenLocalFallback`과 `-LocalDataCachePath=프로젝트/output/캐시경로`를 전달해 제작했다. 렌더에는 `-ShaderWorkingDir=프로젝트/output/셰이더경로`도 사용한다. 프로젝트 설정 파일을 바꾸지 않으며 각 실행에 별도 `-abslog=로그경로`를 남긴다.

## 훈련장 연결

- 활성 설정은 `samples/sword_movement/movement_config.json`의 `upper_lower`다. 최종 카탈로그는 `data/runtime/upper_lower/player_20261117_connected_r02/catalog.json`이며 검 r01과 회전 환산을 수정한 총 r03_gun만 선택한다. 총 r01/r02_gun은 채택하지 않았다. 기존 모델·동작·활성 에셋 파일은 보존했다.
- 검 대기·달리기·대시·4타, 총 비조준 대기·4방향 달리기·대시·사격·정지 조준을 포함한다. 동작 위상과 두 방향을 함께 Unreal에서 평가한다. 상체·하체의 내부 추종 상태는 연속 각도지만 화면은 8방향·원본 12fps 프레임을 선택한다. 새 표에는 모션 벡터 보간을 적용하지 않는다.
- 검날·총구·양발은 같은 120Hz 본 추적을 허리 기준으로 회전·투영한다. Trail·명중은 회전된 검 궤적을 사용하고 잔상은 생성 당시 자세를 보존한다. 이동 경로·공격 전진 방향은 시선과 분리한다.
- 7,104프레임의 본체 실루엣·에너지 알파가 참조와 일치하고 본체·그림자 잘림은 없다. RGB는 136프레임의 각 1픽셀에서 2/255를 넘으며 최대 188/255다. 원인 미확정이며 전체 색상 일치로 보고하지 않는다.
- 실제 OpenGL에서 검 중심 900프레임, 최종 총 640프레임·46발, 고품질 80프레임과 기본 설정 80프레임을 재생했다. 실제 Unreal 부착점 35,520개는 화면 좌표 차이 최대 0.009픽셀 이내다. 자동 검사·캡처 검토이며 사람의 직접 조작이나 연속 메시 간섭 전체 검증은 아니다.
- 남은 한계는 제자리 회전의 발 미끄러짐, 8방향 전환, 12fps 프레임 선택, 미지원 동작의 기존 전신 출력 복귀다. 캐시는 약 1.5GiB를 기준으로 필수 동작·잔상을 유지하며 일시 초과할 수 있다. 고품질 80프레임 검사에서 첫 동작 적재를 포함한 CPU draw 최대 908ms가 관측돼 무중단 성능을 보장하지 않는다.
- 실행 중인 기존 창에는 새 코드가 반영되지 않는다. 다음 훈련장 실행부터 적용한다. 제작·검증 상세와 재생 자료는 [연결 기록](../ai-dev-log/2026-11-17-upper-lower-runtime.md)을 따른다.

## 검토 대상과 미완료 범위

- 원본 모델·리그·사용자 편집 키를 보존한다. 상체의 월드 회전은 하체 회전을 중복 누적하지 않도록 허리 로컬 회전으로 환산한다. 총은 기존 손의 상대 파지 변환을 유지하도록 요청한다.
- 현재 본 연결에서 body 부품을 나누며 과거 부품 ID 목록을 새 스커트 작업본에 복사하지 않는다. 준비 목록의 누락/중복 보존과 실제 Unreal 메시 생성은 별도다.
- 같은 자세의 전체 참조와 분리 재합성을 비교한다. 허리 틈·목/어깨·손/총·수납부·스커트·가림·에너지 마스크·그림자를 확인한다. 서로 다른 자세·방향의 이미지를 자유 조합할 수 있다고 가정하지 않는다.
- 시선의 좌우 이동·빠른 반전과 하체의 추종 시작/종료를 전체 재생·중간 프레임·실제 게임 표시 크기에서 확인한다. 기존 조준 자세의 비틀림에 추가 회전이 합쳐지는 외관도 확인한다.
- 자동 검사는 동작 수치·요청 준비만 검증한다. 실제 Unreal 평가 자세·연속 장갑 간섭·발 접지·회전 사용감과 사용자 외관 승인을 대신하지 않는다.
- `MovementApplication`은 새 카탈로그를 선택하며 지원하지 않는 동작은 기존 Atlas로 재생한다. 초기 요청 준비와 당시 실행 차단은 [이전 개발 기록](../ai-dev-log/2026-11-17-upper-lower-aim-follow.md), 실제 제작과 현재 연결은 위의 기록으로 구분한다.
