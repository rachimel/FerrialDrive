# UI Unit Test 명세

상태: **공통 모듈·메뉴 렌더링 초안 구현 / 독립 실행 프로그램 연결 전**

- 첫 창 크기는 **1280×720**으로 확정했다.
- 공통 모듈과 메뉴 렌더링 진행 상태는 [구현 기록](../ai-dev-log/2026-11-03-ui-unit-test-implementation.md)을 따른다. 전투 HUD·표시 규칙·전환 입력 정책은 아직 연결하지 않았다.

## 목적과 실행

- **Unit Test는 독립 실행할 수 있고 게임에 쉽게 연결될 수 있는 테스트 프로그램**이다.
- 이번에는 메뉴·전투 HUD의 UI 반응성, 장면 전환과 정보 표시를 확인한다. 실제 게임에 적용할지는 결과를 본 뒤 결정한다.
- **`.py` 진입점으로 독립 실행**한다. 파일명과 세부 실행 명령은 구현 시 정하고, 게임 실행 없이 사용할 수 있게 한다.
- Python·Pico2D 필수 조건과 모듈 원본을 수정하지 않는 확장 검토 원칙을 유지한다. OpenGL 연결 방식은 별도 검증 사항이다.

## 장면과 구성 요소

| 테스트 장면 | 구성 요소 | 표시 내용 |
| --- | --- | --- |
| 전투 HUD | 버튼·패널·텍스트·게이지·레이더·원형 크로스헤어 | 콤보 수, 데미지, 플레이어 HP, 타겟 적 정보와 HP 게이지 |
| 메뉴 | 버튼·패널·텍스트 | 테스트용 메뉴 항목. 최종 게임 메뉴 구성은 미확정 |

- 원형 크로스헤어는 **원과 십자 형태**로 구성한다.
- 콤보 수·데미지 표시는 Baldr Sky를 참고한다. 데미지를 최근 값·누적 값 중 어떻게 표현할지는 레이아웃 조정 과정에서 정한다.
- 레이더의 표시 범위·방향·기호와 크로스헤어의 이동·상태 반응은 아직 미정이다.
- 실제 전투, 적 AI, 타겟 선택 시스템, 이동·발사 기능은 이번 확인 범위에 포함하지 않는다. HUD에는 샘플 상태를 전달한다.

## 레이아웃과 스타일

- **AI가 초안을 배치하고, 사용자가 실제 화면을 보며 세부를 조정**한다. 최종 위치·버튼 문구·형태를 지금 확정하지 않는다.
- 배치·문구·색·형태·폰트 역할은 동작 코드와 분리한다. 버튼 표시명과 동작 식별자는 별도로 관리한다.
- 기본 텍스트는 **에스코어 드림**, 굵기 **200·300·400**을 우선 후보로 유지한다. HUD는 **깍두기 도면체**를 사용한다.
- 레퍼런스는 배틀필드 3·메탈기어 라이징 리벤전스·에이스 컴뱃과 F-15/F-16 HUD다.
- 커서 반응형 유사 3D 회전·확대·판정 확장은 선택 후보로 유지한다. 기본 레이아웃의 실행 조건으로 요구하지 않는다.
- 클릭 판정 여유 폭은 표시 크기와 구분해 설정한다. 확대·회전을 도입하면 판정 영역이 겹칠 때의 선택 규칙도 정한다.
- 명일방주의 반응성은 참고 후보로 유지한다.

## 입력

- **Esc:** 메뉴 ↔ 전투 HUD 전환.
- **마우스 좌클릭:** 버튼과 상호작용.
- UI에서 처리한 클릭과 다른 입력을 구분한다. 향후 게임 연결 시 같은 클릭이 전투 행동으로 중복 전달되지 않아야 한다.
- 키보드 포커스 이동·방향키 탐색과 추가 단축키는 이번 확정 범위에 포함하지 않는다.

## 애니메이션

- **SmoothStep을 중심으로 평행이동·투명도 변화**를 사용한다.
- **elastic 계열 보간은 투명도 애니메이션에 사용하지 않는다.** 이동 등 다른 속성에 사용할지는 실제 화면에서 비교한 뒤 정한다.
- 보간·시간 진행은 UI와 분리된 공통 애니메이션 모듈에서 처리한다. UI는 대상 속성·시작값·종료값·지속시간·보간 방식을 지정한다.
- 기본 배치와 애니메이션 이동량을 구분하고 표시와 입력 판정이 최종 위치를 공유한다.
- **재생 중 취소·재입력과 전환 중 입력 처리 규칙은 레이아웃을 확인한 뒤 결정**한다. 구현 단계에서 임의로 정책을 선택하지 않는다.

### 추가 보간 후보 [비교 후 선택]

첫 구현은 SmoothStep을 기준으로 한다. 아래 후보를 모두 구현할 필요는 없으며 실제 레이아웃에서 필요한 곡선부터 비교한다. 링크는 곡선 참고 자료이며 Flutter 도입을 뜻하지 않는다.

| 후보 | 성질 | 검토 용도 |
| --- | --- | --- |
| [easeInOutCubicEmphasized](https://api.flutter.dev/flutter/animation/Curves/easeInOutCubicEmphasized-constant.html) | 느린 시작 후 빠르게 가속하고 천천히 정착 | 사용자가 제안한 첫 등장, 패널 진입 |
| [easeInOutQuint](https://api.flutter.dev/flutter/animation/Curves/easeInOutQuint-constant.html) | 시작·끝은 느리고 중간 변화가 가파름 | 같은 지속시간에서 중간 이동을 더 빠르게 느끼게 하는 전환 |
| [elasticInOut](https://api.flutter.dev/flutter/animation/Curves/elasticInOut-constant.html) | 시작값·목표값의 범위를 넘는 탄성 진동 | 이동 등 일부 강조 효과. 적용 여부는 미정 |
| [fastEaseInToSlowEaseOut](https://api.flutter.dev/flutter/animation/Curves/fastEaseInToSlowEaseOut-constant.html) | 느린 시작 후 매우 빠른 가속, 느린 마무리 | 메뉴·패널 전환 후보 |
| [fastLinearToSlowEaseIn](https://api.flutter.dev/flutter/animation/Curves/fastLinearToSlowEaseIn-constant.html) | 초반 빠른 직선적 진행 후 긴 감속 | 빠른 위치 반응과 부드러운 정착 후보 |

- 공통 애니메이션은 곡선을 교체할 수 있도록 구성한다. 일부 Flutter 곡선은 두 Bézier 구간을 사용하는 `ThreePointCubic`이므로 이름만 보고 단일 다항식으로 대체하지 않는다.
- 탄성 곡선의 범위 초과와 투명도 등의 속성 제한은 구분해서 처리한다. 실제 HP·데미지 같은 원본 상태값은 시각 효과 때문에 바꾸지 않는다.

## 재사용 모듈과 샘플

- UI 구성 요소·애니메이션·장면 전환·HUD는 재사용 모듈로 분리한다.
- 실행부는 창·입력·시간 갱신과 테스트 장면을 연결한다. 모듈 import만으로 창이나 실행 루프가 시작되지 않는다.
- 샘플 상태는 테스트와 향후 게임이 공유할 **표시용 데이터 규격**으로 설계한다. 테스트 화면은 가짜 데이터를 공급하고, 게임 연결 시 실제 상태를 이 규격으로 전달한다.
- 게임 엔티티 객체·전역 상태·세이브에 직접 의존하지 않는다. 아직 게임 데이터 구조가 없으므로 실제 연결 호환성은 연결 시 별도로 검증한다.
- 데이터에는 플레이어 HP, 타겟 정보·HP, 콤보·데미지와 레이더 표시용 정보를 제공한다. 정확한 필드·단위·타겟 없음 처리와 샘플 갱신 조작은 설계 단계에서 정한다.
- 샘플과 실행 안내는 [툴 시연 데이터 기준](../tool-usage/tool_demo_data.md)에 따라 제공한다.

## 완료 기준

1. 안내된 `.py` 진입점으로 게임 없이 두 테스트 장면을 실행한다.
2. Esc 전환과 좌클릭 버튼 상호작용을 확인한다.
3. 전투 HUD의 지정 정보와 구성 요소가 샘플 상태로 표시된다.
4. SmoothStep 이동·투명도 효과가 UI 코드와 분리되어 동작한다.
5. 배치·문구 변경이 버튼 동작 연결이나 샘플 데이터 공급 구조를 깨뜨리지 않는다.
6. 사용자가 실제 화면에서 레이아웃을 평가한다. 자동 검사 결과와 시각·조작 확인 결과는 구분한다.

실행 파일명·초기 장면 같은 내부 기본값은 구현 시 정하고 안내한다. 해상도·상세 표시 데이터와 미정 입력·애니메이션 정책은 해당 기능을 구현할 때 확인한다.
