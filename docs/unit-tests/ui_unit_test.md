# UI Unit Test 명세

상태: **현재 UI Unit Test 사용자 승인 / 최종 코드 정리 반영 / 설정 기능 미정 / 정리 후 실행 미확인**

2026-11-03 사용자가 현재 UI Unit Test를 승인하고 코드 정리와 반복 비용 제거를 요청했다. 승인된 배치·색·폰트·효과 타이밍을 유지한다. 실제 타겟 선택·적중·게임 상태 연결과 설정 기능은 남아 있다. 승인된 시안과 이후 코드 정리의 실행·조작 검증 상태를 구분한다.

- 첫 창 크기는 **1280×720**으로 확정했다.
- 실행 파일은 `tests/ui_test.py`다. [변경 이력 목록](../ai-dev-log/README.md)과 [실행·조작 안내](../../samples/ui_unit_test/README.md)를 따른다. 최근 변경의 자동 검사·실행·화면 확인은 수행하지 않았다.

## 목적과 실행

- [Unit Test 실행 도구](../../Tools/unit_test_runner/README.md)는 파일 선택·별도 프로세스 실행·종료·오류 표시를 담당한다. `tests/ui_test.py`는 Runner import·상속 없이 직접 실행하고, 자체 창·입력·시간·렌더링 수명은 `ferrial_drive/ui/standalone.py`에서 관리한다. 게임에서 재사용할 뷰·표시 상태·효과는 이 실행 루프와도 분리한다.
- 공통 실행기를 파일 인자 없이 실행하면 대기 GUI가 열린다. 테스트 `.py`는 이 GUI 창에 드롭하며 UI 테스트가 별도 창으로 열린다. 테스트 창 X·메뉴 종료는 해당 테스트만 닫는다. Runner를 닫으면 소유한 테스트 프로세스도 종료한다. 최신 프로세스 분리 수정은 사용자 실행 확인 전이다.
- **Unit Test는 독립 실행할 수 있고 게임에 쉽게 연결될 수 있는 테스트 프로그램**이다.
- 이번에는 메뉴·전투 HUD의 UI 반응성, 장면 전환과 정보 표시를 확인한다. 실제 게임에 적용할지는 결과를 본 뒤 결정한다.
- 공통 실행기 GUI 창에 `tests/ui_test.py`를 드롭한다. `python tests/ui_test.py`로 직접 실행할 수도 있다. 실제 게임 실행·세이브·게임 에셋은 필요 없다.
- 같은 파일을 재드롭하면 이전 프로세스를 종료하고 새 소스·보조 모듈·설정을 새 프로세스에서 읽는다. 이전 Python/바이트코드 캐시를 재사용하지 않으며 Runner 자체 재시작 없이 UI 모듈 변경을 반영하는 경로를 구현했다. 현재 변경을 처음 적용할 때에는 기존 Runner를 한 번 완전히 재시작한다.
- Python·Pico2D 필수 조건과 모듈 원본을 수정하지 않는 확장 검토 원칙을 유지한다. OpenGL 연결 방식은 별도 검증 사항이다.

## 장면과 구성 요소

| 테스트 장면 | 구성 요소 | 표시 내용 |
| --- | --- | --- |
| 전투 HUD | 버튼·패널·텍스트·게이지·레이더·원형 크로스헤어 | 콤보 수, 데미지, 플레이어 HP, 타겟 적 정보와 HP 게이지 |
| 메뉴 | 버튼·패널·텍스트 | 테스트용 메뉴 항목. 최종 게임 메뉴 구성은 미확정 |
| 일시정지 | 어두운 배경·패널·버튼 | 계속, 설정, 타이틀로, 테스트 종료 |

- 타이틀의 테스트 메뉴는 `전투 HUD 보기 / 설정 / 테스트 종료` 세 버튼이다. 타이틀의 `표시 초기화`는 제거했고 전투 HUD 하단의 테스트용 `표시 초기화`는 유지한다. 타이틀·일시정지에 설정 버튼을 두되, 설정 항목·기능은 미정이므로 현재는 비활성 상태로 표시한다. `buttons`의 `enabled=false`로 클릭을 소비하고 동작을 실행하지 않는다.
- 플레이어·훈련 표적 A의 임시 기체 도형과 기체 아래 이름표는 **유닛 테스트 전용**이다. `tests/ui_test.py`에서 그리며 `UiView.combat`에는 포함하지 않는다. 실제 게임에는 게임 기체를 연결한다. 타겟 패널의 적 이름은 샘플 문자열을 고정하지 않고 실제 `TargetInfo.name`을 표시한다.
- `샘플 상태 조작` 안내 문구는 제거하고, 하단 피해·타겟·초기화 버튼은 유지한다. 테스트 버튼 그리기·동작 연결도 테스트 실행부가 담당한다.
- 크로스헤어 원은 **3px**, 십자는 **2px**다. `layout.crosshair_thickness_pixels`는 원, `layout.crosshair_cross_thickness_pixels`는 십자 두께를 조절한다.

- 원형 크로스헤어는 **흰색 원과 십자 형태**로 구성하고 마우스 위치를 따른다. 색은 `colors.crosshair=#FFFFFF`로 분리한다. 첫 포인터 입력 전에는 중앙에 두고 창 밖으로 나가면 마지막 유효 위치를 유지한다. 버튼 위·장면 전환·일시정지와 열기/닫기 중에도 위치를 갱신한다. 플레이어·레이더 중심과 HUD 전환 이동량은 적용하지 않는다.
- 테스트용 플레이어 도형은 **항상 화면 중앙**에 표시한다. 창 크기의 절반으로 위치를 계산하고 HUD 전환 이동량은 적용하지 않는다. 플레이어의 이번 피해 숫자도 중앙 기준을 공유한다.
- 콤보 수·데미지 표시는 Baldr Sky를 참고한다. **HUD 오른쪽에는 플레이어가 적에게 입힌 피해 합계만** 표시한다. 플레이어가 받은 피해는 이 합계에 더하지 않는다.
- **이번 피해량은 공격을 받은 플레이어·적 각각의 주변 무작위 위치에 빨간 숫자**로 표시한다. 피격마다 위치를 한 번 정해 그 자리에 고정하고 TV 등장·역순 퇴장으로 표현한다. 기존 위쪽 이동과 머리 위 고정 오프셋은 제거한다. 이번 피해와 HIT·누적 피해 카운터들은 분리한다.
- 레이더는 **플레이어를 둘러싸는 방향 인디케이터**다. 별도 패널·RADAR/N 글자·미니맵 축과 점은 제거한다. 감지 거리 안의 적 중 **화면에서 플레이어 중심 200px 원 밖에 있는 적만** 링 위의 채워진 이등변삼각형으로 표시한다. 화면 거리 200px 이하에서는 화살표를 숨긴다. 꼭짓점은 적의 화면 위치를 향하고 링 반경은 일정하게 유지한다.
- 레이더 중심은 플레이어의 화면 중앙을 공유하며 HUD 전환 이동량을 적용하지 않는다. 크로스헤어만 마우스 화면 좌표로 이동한다. 재사용 뷰는 마우스를 직접 읽지 않고 실행부가 `UiView.combat`의 `cursor_position`에 좌표를 공급한다.
- 실제 전투, 적 AI, 타겟 선택 시스템, 이동·발사 기능은 이번 확인 범위에 포함하지 않는다. HUD에는 샘플 상태를 전달한다.

## 레이아웃과 스타일

- AI가 배치한 초안을 사용자가 실제 화면을 보며 조정했고 **현재 UI Unit Test의 배치·표현을 승인**했다. 본편 연결 시 필요한 추가 조정과 현재 승인 범위를 구분한다.
- 배치·문구·색·형태·폰트 역할은 동작 코드와 분리한다. 버튼 표시명과 동작 식별자는 별도로 관리한다.
- 메뉴 제목·소제목·본문·설명·버튼·순번은 사용자 제공 **Cafe24OhsquareAir-v2.0.otf**로 비교한다. HUD는 TARGET에 에스코어 드림 SCDream6(Bold), 전투 제목에 SCDream5(Medium), 적 이름·나머지 라벨·본문·버튼에 SCDream4(Regular)를 유지한다. **HIT 숫자·이번 피해·누적 DAMAGE 숫자는 학교안심 운동장**을 사용한다. 기존 크기·색·배치와 카운터 갱신 효과는 유지하고 HP 숫자는 표시하지 않는다. 메뉴 폰트는 최종 확정이 아닌 비교 시안이다.
- 상단 브랜드·UI 테스트 표시·구분선과 하단 조작 안내는 표시하지 않는다. 전투 중 Esc는 일시정지를 연다.
- 장면 제목 `전투 HUD`는 좌상단 (28, 24)에 에스코어 드림 Medium 42px로 표시한다. `ui_config.json`의 `layout.combat_heading`으로 위치, `fonts.combat_title.size`로 크기를 조절한다. 메뉴 제목과 독립적으로 변경한다.
- 타겟 패널은 **왼쪽 TARGET + 오른쪽 적 이름**의 세로 중심을 맞춘다. 상단 중앙에 위쪽 여백 24px로 배치하며, TARGET 14px는 SCDream6(Bold), 적 이름 18px는 SCDream4(Regular)의 전용 역할로 표시한다. 타겟 HP 숫자는 숨기고 HP 바만 표시한다. 시안 크기는 372×58px, 안쪽 좌우 여백 13px, HP 바 두께 6px다. 이름은 최대 240px로 제한해 긴 이름은 말줄임하며, 타겟 없음도 오른쪽에 표시한다. 패널 배경 알파 0.45와 선명한 테두리는 유지한다. 값은 `ui_config.json`에서 조정한다.
- 콤보의 표시명은 **HIT**로 변경한다. 카운터들은 패널 없이 **큰 숫자 + 작은 HIT/DAMAGE**로 기준선을 맞춘다. 시안 크기는 HIT 숫자 76px, 라벨 16px, 누적 피해 60px, 이번 피해 36px다. 내부 `combo_count`·설정 키는 유지한다. 샘플 조작 버튼은 y=656·높이 48px로 아래 여백 16px에 맞춘다.
- **HIT·DAMAGE 모두 플레이어의 공격이 적에게 적중할 때만 나타난다.** DAMAGE는 플레이어가 적에게 가한 피해 합계이며, 피격 피해는 합산하지 않는다. 최초·초기화 직후에는 숨긴다. 샘플은 `damage_target`으로 실제 적용한 피해가 0보다 클 때 두 표시를 함께 켠다. `damage_player`·타겟 전환·메뉴 왕복·무효 공격은 표시 수명을 갱신하지 않는다.
- 표시 시간은 `CounterVisibility`로 카운터 값·숫자 이동과 분리한다. 마지막 적중부터 **2초 유지 + 0.3초 SmoothStep 페이드**는 조절용 시안이며 `counter_visibility`에서 변경한다. 페이드가 완전히 끝나면 **HIT·DAMAGE의 원본 누적 값과 두 회전 표시 상태를 모두 0으로 초기화**한다. 다음 적중은 `1 HIT`·이번 피해량부터 새로 누적한다. 페이드 도중 재적중하면 기존 값에 누적하고 유지 시간을 갱신한다. HP는 초기화하지 않는다.
- `CounterVisibility.update()`는 표시 수명이 끝난 프레임에만 `True`를 반환한다. 실행부가 이 반환값으로 카운터를 초기화하며 표시 수명 모듈은 게임 상태를 직접 바꾸지 않는다. 본편은 유효 적중 이벤트에서 `show()`를 호출하고 `UiView.combat`에 공통 `counters_opacity`를 전달한다. 메뉴에서도 수명은 진행하고 종료 시 초기화하지만 일시정지 동안에는 수명·초기화를 멈춘다.
- 플레이어 HP는 수치·기존 좌하단 패널·제목을 없애고 **플레이어의 공격 방향 반대편에 세로 바만** 둔다. `attack_direction_x`는 왼쪽 -1·오른쪽 1이며 바는 반대쪽에 표시한다. 기본 폭 6px·높이 72px·중심에서 좌우 거리 56px는 `player_hp_bar`에서 조절한다. HP는 아래부터 채운다. 샘플에서 UI 버튼을 가리키지 않는 마우스의 좌우 위치로 공격 방향을 공급하고, 정중앙·창 밖·장면 전환 중에는 마지막 방향을 유지한다. 실제 공격 시스템은 구현하지 않는다.
- **플레이어·타겟 HP 감소는 즉시 반영**하고, 새 HP와 이전 표시 끝점 사이를 `colors.health_loss`의 진한 빨간색(시안 `#8F2028`)으로 채운다. 이 구간은 `t²`로 처음에는 느리게, 점점 빠르게 새 HP까지 줄어든다. `health_trail.duration_seconds`(시안 0.6초)는 매 감소의 표시 시간이다. 추가 피해는 **현재 표시 중인 끝점을 유지한 채 목표 HP를 갱신하고 t=0으로 재시작**한다. 같은 HP를 매 프레임 전달해도 시간은 초기화하지 않는다.
- 감소 표시 상태는 실제 HP·뷰와 별도인 `HealthTrail`로 관리하고 플레이어·타겟에 각각 둔다. 회복·표시 초기화는 새 HP로 즉시 맞춰 감소 구간을 없앤다. 타겟 유무 전환은 타겟 표시만 초기화하며 플레이어 효과는 유지한다. 실제 게임 연결부도 다른 타겟으로 바꿀 때 해당 표시 상태를 초기화한다. 메뉴에서도 표시 시간은 진행하며 실제 피해·HP 계산에는 영향을 주지 않는다.
- 레이더 링 반경은 200px, 두께는 2px다. `radar.radius_pixels`·`ring_thickness_pixels`로 분리하며 거리별 삼각형 크기·알파는 유지한다.
- 본편의 메인 컬러 레퍼런스는 **Pantone 20-0011 TPM Bezel**이며 [PRE-PRD 5.6절](../Ferrial_Drive_PRE_PRD_v0.1.md)을 따른다. 회색 기반 쿨톤 청회색 방향이고 게임용 HEX/RGB 값·세부 팔레트는 미정이다. 씬·UI 적용은 **3D 프리렌더 씬을 만든 뒤 진행할 별도 과제**이며, 현재 승인된 Unit Test의 시연 팔레트는 유지한다.
- 누적 피해도 **큰 숫자 + 작은 DAMAGE**의 가로 배치로 바꾸고 기준선을 맞춘다. `누적 가한 피해`라는 상단 제목은 표시하지 않는다. 숫자 자리는 동일한 폭으로 배치하고, 전체 폭이 `layout.damage_max_width`를 넘으면 숫자만 축소해 DAMAGE 공간을 확보한다.
- 콤보와 데미지 카운터를 함께 **카운터들**이라고 부른다. **콤보 위·데미지 아래**로 묶고, 숫자+라벨 전체의 오른쪽 끝을 맞춘다. `layout.counter_stack`의 시안은 오른쪽 여백 32px·행 사이 간격 8px다. **카운터들 사이 여백의 중심은 화면 높이의 절반**에 둔다. 1280×720에서 콤보 표시 영역의 하단은 y=356, 데미지 표시 영역의 상단은 y=364가 된다. 콤보 상단은 실제 표시 높이에서 역산한다. 자릿수가 늘면 숫자는 왼쪽으로 확장하며 오른쪽 정렬을 유지한다. 기존 고정 `top_pixels` 설정은 제거했다.
- 레퍼런스는 배틀필드 3·메탈기어 라이징 리벤전스·에이스 컴뱃과 F-15/F-16 HUD다.
- 커서 반응형 유사 3D 회전·확대·판정 확장은 선택 후보로 유지한다. 기본 레이아웃의 실행 조건으로 요구하지 않는다.
- 클릭 판정 여유 폭은 표시 크기와 구분해 설정한다. 확대·회전을 도입하면 판정 영역이 겹칠 때의 선택 규칙도 정한다.
- 명일방주의 반응성은 참고 후보로 유지한다.

## 입력

- **Esc:** 메뉴에서는 전투 HUD 진입, 전투에서는 일시정지 열기, 일시정지에서는 계속. 타이틀 복귀는 일시정지의 `타이틀로` 버튼을 사용한다.
- **마우스 좌클릭:** 버튼과 상호작용.
- UI에서 처리한 클릭과 다른 입력을 구분한다. 향후 게임 연결 시 같은 클릭이 전투 행동으로 중복 전달되지 않아야 한다.
- 키보드 포커스 이동·방향키 탐색과 추가 단축키는 이번 확정 범위에 포함하지 않는다.

## 일시정지

- 전투 화면 위에 `일시 정지`와 `계속 / 설정 / 타이틀로 / 테스트 종료`를 표시한다. 제목은 전용 `fonts.pause_heading`에 Cafe24 Ohsquare 일반형 26px를 사용한다. 버튼·타이틀의 글꼴은 기존 Ohsquare Air를 유지한다. 화면 중앙 400×388px 패널, 배경 어둡게 하기 0.75, SmoothStep 페이드 0.16초는 조절용 시안이다. 일시정지 패널 자체의 채움 알파는 `pause.panel_fill_opacity=0.85`로 분리한다. 타이틀·타겟 패널은 기존 공통 채움 알파 0.45를 사용한다.
- `PauseState`는 표시 상태와 페이드만 관리한다. 실행부는 `blocking` 동안 피해 숫자·카운터 갱신·카운터 표시 수명·HP 감소 효과·공격 방향을 멈춘다. 크로스헤어 위치는 계속 갱신한다. 계속하면 전투 효과는 멈춘 지점부터 진행하며 일시정지 시간을 보충하지 않는다.
- 열기·닫기 페이드 중에도 전투 갱신과 Esc·좌클릭을 차단한다. 일시정지 중 포인터 입력은 해당 메뉴에만 전달하며 배경 클릭도 소비한다. 전환 시작 시 버튼 누름 상태를 지운다.
- `타이틀로`는 일시정지를 닫고 기존 0.32초 전환으로 메뉴에 복귀한다. 샘플 HP·누적 값은 보존하고, 메뉴에서는 기존처럼 효과 시간이 진행한다. `테스트 종료`는 테스트 창만 닫는다. 실제 게임의 저장·종료 동작은 게임 연결부에서 결정한다.

## 애니메이션

- **SmoothStep을 중심으로 평행이동·투명도 변화**를 사용한다.
- **elastic 계열 보간은 투명도 애니메이션에 사용하지 않는다.** 이동 등 다른 속성에 사용할지는 실제 화면에서 비교한 뒤 정한다.
- 보간·시간 진행은 UI와 분리된 공통 애니메이션 모듈에서 처리한다. UI는 대상 속성·시작값·종료값·지속시간·보간 방식을 지정한다.
- 기본 배치와 애니메이션 이동량을 구분하고 표시와 입력 판정이 최종 위치를 공유한다.
- **메뉴↔HUD 전환 완료까지 Esc·좌클릭을 소비**한다. 대기열에 저장하거나 방향을 반전하지 않는다. 전환 시작 시 버튼 누름 상태를 해제해 다음 장면에서 남은 클릭이 작동하지 않게 한다.
- 콤보·누적 피해가 늘면 **변경되는 숫자 자리만 새 숫자가 아래에서 올라와 이전 숫자를 위로 밀어내는 카운터**로 표현한다. 두 숫자는 한 글자 높이 간격으로 이동하며, 이전 숫자 알파는 `(1 - 진행률) ** outgoing_fade_power`로 줄인다. 숫자 영역 밖은 잘라낸다. 자릿수가 같아도 값이 바뀌는 자리에는 적용하며, 숫자가 같은 자리·HIT·DAMAGE·쉼표는 고정한다. 같은 값에는 반복 재생하지 않는다.
- 카운터 갱신의 **숫자 세로 이동과 페이드·블러 진행률을 분리**한다. `CounterVisual.vertical_progress`는 세로 위치 전용이며, `progress`·`progress_before`는 기존 SmoothStep의 0~1 값을 유지해 페이드·블러 강도·블러 길이에 사용한다. 카운터 전체의 출현·숨김은 기존 `CounterVisibility`를 유지한다.
- 세로 이동 시안은 `damage_counter.vertical_easing=elastic_in_out`, `elastic_strength=0.35`, `elastic_period=0.4`다. 같은 원본 시간에서 계산한 SmoothStep과 elasticInOut을 비율로 혼합하고, 이동 출력은 0~1로 자르지 않는다. 강도 0이면 기존 SmoothStep, 1이면 elasticInOut 전체를 사용한다. 이는 약하게 혼합해 비교할 임시값이다. `vertical_easing=smooth_step`으로 이동만 복원할 수 있다. HIT·DAMAGE는 같은 설정을 공유한다.
- 모션 블러는 현재 글자를 지정 방향으로 늘이는 방향성 잔상 근사다. 잔상 끝일수록 알파를 낮추고, 셔터 구간의 이동량에 맞춰 길이를 제한한다. `damage_counter`의 시안은 이동 0.20초, 셔터 0.085초, 샘플 9개, 잔상 알파 0.58, 이전 숫자 감쇠 지수 1.4다. `blur_direction=[0,-1]`은 위쪽, `blur_length_pixels=28`은 최대 길이다. 블러는 움직이는 자리에만 적용한다. `blur_samples=0`·`blur_opacity=0`·`blur_length_pixels=0`이면 잔상은 끈다.
- 콤보와 누적 피해는 `number_counter` 표현·`damage_counter` 효과 설정을 공유하고, 각각 독립된 `RollingCounter` 표시 상태를 가진다. 콤보는 기존 76px·강조색·쉼표 없는 정수·HIT 배치를 유지하며, `layout.combo_max_width` 안에서 숫자만 축소해 라벨 공간을 확보한다. 초기화·값 감소는 두 표시 상태에 각각 즉시 반영한다.
- 원본 합계는 즉시 갱신하고 회전 표시 상태는 `RollingCounter`로 분리한다. 회전 중 추가 피해는 최신 합계 하나로 병합해 현재 회전 뒤에 반영한다. 값이 줄거나 표시를 초기화하면 즉시 새 값으로 맞추며 잔상도 없앤다. 메뉴에서도 시간은 진행하고 HUD 재진입 시 같은 값을 다시 회전시키지 않는다.

### 추가 보간 후보 [비교 후 선택]

첫 구현은 SmoothStep을 기준으로 한다. 아래 후보를 모두 구현할 필요는 없으며 실제 레이아웃에서 필요한 곡선부터 비교한다. 링크는 곡선 참고 자료이며 Flutter 도입을 뜻하지 않는다.

| 후보 | 성질 | 검토 용도 |
| --- | --- | --- |
| [easeInOutCubicEmphasized](https://api.flutter.dev/flutter/animation/Curves/easeInOutCubicEmphasized-constant.html) | 느린 시작 후 빠르게 가속하고 천천히 정착 | 사용자가 제안한 첫 등장, 패널 진입 |
| [easeInOutQuint](https://api.flutter.dev/flutter/animation/Curves/easeInOutQuint-constant.html) | 시작·끝은 느리고 중간 변화가 가파름 | 같은 지속시간에서 중간 이동을 더 빠르게 느끼게 하는 전환 |
| [elasticInOut](https://api.flutter.dev/flutter/animation/Curves/elasticInOut-constant.html) | 시작값·목표값의 범위를 넘는 탄성 진동 | 카운터 갱신의 세로 이동에 약하게 혼합해 비교한다. 다른 이동에 적용할지는 미정 |
| [fastEaseInToSlowEaseOut](https://api.flutter.dev/flutter/animation/Curves/fastEaseInToSlowEaseOut-constant.html) | 느린 시작 후 매우 빠른 가속, 느린 마무리 | 메뉴·패널 전환 후보 |
| [fastLinearToSlowEaseIn](https://api.flutter.dev/flutter/animation/Curves/fastLinearToSlowEaseIn-constant.html) | 초반 빠른 직선적 진행 후 긴 감속 | 빠른 위치 반응과 부드러운 정착 후보 |

- 공통 애니메이션은 곡선을 교체할 수 있도록 구성한다. 일부 Flutter 곡선은 두 Bézier 구간을 사용하는 `ThreePointCubic`이므로 이름만 보고 단일 다항식으로 대체하지 않는다.
- 탄성 곡선의 범위 초과와 투명도 등의 속성 제한은 구분해서 처리한다. 실제 HP·데미지 같은 원본 상태값은 시각 효과 때문에 바꾸지 않는다.

## 재사용 모듈과 샘플

- UI 구성 요소·애니메이션·장면 전환·HUD는 재사용 모듈로 분리한다.
- 실행부는 창·입력·시간 갱신과 테스트 장면을 연결한다. 모듈 import만으로 창이나 실행 루프가 시작되지 않는다.
- 샘플 상태는 테스트와 향후 게임이 공유할 **표시용 데이터 규격**으로 설계한다. 테스트 화면은 가짜 데이터를 공급하고, 게임 연결 시 실제 상태를 이 규격으로 전달한다.
- 게임 엔티티 객체·전역 상태·세이브에 직접 의존하지 않는다. 아직 게임 데이터 구조가 없으므로 실제 연결 호환성은 연결 시 별도로 검증한다.
- 표시 규격은 `ferrial_drive/ui/state.py`의 `Health`·`TargetInfo`·`RadarContact`·`HudState`다. HP는 현재/최대 값, 타겟 없음은 `None`, 콤보와 누적 가한 피해는 0 이상의 정수다.
- `RadarContact.x/y`는 감지 거리용 플레이어 기준 상대 좌표이며 x 양수는 오른쪽, y 양수는 위다. `radar.range_units`와 같은 단위로 감지 여부와 거리별 크기·알파를 계산한다. 별도의 필수 `screen_x/screen_y`는 카메라 투영 후의 절대 화면 픽셀 좌표이며 왼쪽 위 원점·오른쪽/아래가 양수다. 게임 연결부가 두 좌표를 전달한다. 화면 거리로 200px 원 내부·경계를 숨기고, 바깥 화살표 방향은 화면 좌표로 계산한다. 아군·감지 범위 밖·감지 상대 좌표가 영벡터인 대상도 표시하지 않는다.
- 샘플은 감지 거리 1.0의 정규화 상대 좌표를 사용한다. 실제 게임의 감지 거리를 확정한 값은 아니다. `ui_config.json`에서 감지 거리·화면 링 반경·삼각형 크기·링 투명도를 분리해 조정한다. `arrow_length_pixels`는 근거리 기준 삼각형 높이, `arrow_half_width_pixels`는 밑변 너비의 절반이다.
- **적이 멀어질수록 삼각형 높이·폭과 알파값을 함께 선형 감소**시킨다. 꼭짓점은 같은 반경의 링 위에 유지한다. 감지 한계에서 `arrow_min_scale`(시안 0.45), `arrow_min_opacity`(시안 0.25)가 되며, 알파는 장면 전환 알파와 곱한다. 샘플의 근거리 적은 훈련 표적 위치 (756,342)로 원 안에 있어 숨기고, 원 밖 중거리·감지 한계의 적 2개만 표시한다.
- 이번 피해 숫자는 `DamageNumbers`에 피격 소유자·피해량·피격 기체의 화면 기준 좌표를 전달한다. 화면 좌표는 왼쪽 위 원점의 픽셀, 수명은 초다. 생성할 때 x·y 오프셋을 각각 균등 추출하며 이후 갱신에서는 위치를 바꾸지 않는다. `animation.damage_scatter_x_pixels`(시안 64px)·`damage_scatter_y_pixels`(시안 44px)는 축별 ±분산 범위다. 수명은 기존 1.15초이며 자체 알파는 끝까지 1로 유지한다. HP·누적 값과 애니메이션 상태는 별개다.
- 이번 피해 숫자는 **TV 켜짐 형태로 순차 등장하고 역순으로 퇴장**한다. 높이 1px 선에서 가로를 펼친 뒤 세로를 펼치고, 완성 크기를 유지하다가 세로를 1px까지 접은 뒤 가로선을 중앙으로 접어 없앤다. 숫자 영역의 중심은 고정한다. `animation.damage_width_expand_seconds`(0.05초)·`damage_height_expand_seconds`(0.06초)의 같은 SmoothStep 곡선을 퇴장에서는 역재생한다. 총 수명 1.15초에 등장 0.11초·완성 크기 유지 0.93초·퇴장 0.11초를 포함한다. 등장·퇴장 시간 합은 전체 수명보다 짧아야 하며 두 시간을 모두 0으로 두면 즉시 나타나고 수명 끝에 즉시 사라진다. HIT·DAMAGE 카운터들의 페이드와 초기화 규칙은 별개다.
- 가짜 상태는 `samples/ui_unit_test/hud_sample.json`, 배치·문구·색·폰트·애니메이션 값과 버튼 동작 ID는 `ui_config.json`을 사용한다. 두 파일은 실행 중 저장·수정하지 않는다.
- 샘플 버튼은 적 피해 +120, 플레이어 피해 +75, 타겟 유무, 표시 초기화다. 잔여 HP까지 차감하고, 적에게 적용한 피해만 합계에 더한다. 샘플 콤보는 적 피해 버튼의 유효 적용 횟수이며 실제 게임 규칙이 아니다.
- 타겟팅은 고정 샘플 `훈련 표적 A`를 표시·숨김하는 시연이다. 조준으로 대상을 선택·전환하거나 공격 적중을 판정하는 로직은 없다. 현재 단계는 전투 HUD의 표시·반응 기본 구성이며 실제 전투·타겟 선택·카메라 좌표 연결과 사용성 검증은 남아 있다.
- 샘플과 실행 안내는 [툴 시연 데이터 기준](../tool-usage/tool_demo_data.md)에 따라 제공한다.

## 완료 기준

### 승인 후 코드 정리

- 글자 크기 측정은 텍스트·폰트 역할별 최대 512개 LRU 캐시, ascent는 로드된 역할별로 보관한다. 해당 렌더러 종료 시 모두 비운다. 폰트를 바꿀 때는 렌더러를 새로 만든다.
- 링 픽셀 범위는 반지름·두께·중심 소수부별 최대 32개, RGB 변환은 최대 64개를 캐시한다. 정수 이동은 재계산 없이 반영하며 링의 알파 중첩 방지 규칙을 유지한다. 링 색 설정은 각 선이 아닌 링당 한 번 수행한다.
- 레이더의 고정 설정 검증은 `UiConfig` 로드 시 수행한다. 카운터의 이전 숫자 감쇠 계산은 블러 샘플마다 반복하지 않고 해당 카운터를 그릴 때 한 번 계산한다.
- 테스트 버튼 목록은 피해 버튼 활성 상태가 바뀔 때만 다시 만들고, 공격 방향은 좌우가 달라질 때만 상태를 교체한다. 타겟 없음의 HP 표시를 매 프레임 초기화하지 않는다. 클릭 판정은 포인터를 로컬 좌표로 옮겨 임시 사각형 생성을 줄인다.
- 이번 작업은 기존 SDL 어댑터의 반복 비용 정리다. 실제 FPS·CPU/GPU 병목 위치·화면 동일성은 측정하지 않았다. OpenGL 렌더러 연결은 별도 작업이다.

### 선택적 성능 계측

- 게임·테스트가 공유하는 `TimingRecorder`를 선택적으로 연결한다. `tests/ui_test.py --profile [JSON 경로]`로 활성화하며 기본 실행·Runner 드롭은 계측 비활성이다.
- update/draw와 효과 갱신·주요 뷰·렌더러 호출을 집계하고 화면 표시·프레임 대기는 별도 이름으로 수집한다. 정상 종료 시 JSON을 저장한다. 중첩된 포함 경과 시간을 합해 프레임 시간으로 해석하지 않는다.
- 승인된 표현 값은 유지한다. 계측은 실행 비용을 추가하며 실제 GPU 시간을 측정하지 않는다. [공통 계측 안내](../tool-usage/performance_timing.md)의 범위·종료 조건·미검증 상태를 따른다.

### 기능 확인 기준

1. 안내된 `.py` 진입점으로 게임 없이 두 테스트 장면을 실행한다.
2. 메뉴 진입·Esc 일시정지·계속·타이틀 복귀와 좌클릭 버튼 상호작용을 확인한다. 정지 중 효과 시간과 배경 버튼 입력이 차단되고, 재개 후 같은 지점부터 이어져야 한다.
3. 전투 HUD의 지정 정보와 구성 요소가 샘플 상태로 표시된다.
4. SmoothStep 이동·투명도 효과가 UI 코드와 분리되어 동작한다.
5. 배치·문구 변경이 버튼 동작 연결이나 샘플 데이터 공급 구조를 깨뜨리지 않는다.
6. 사용자가 실제 화면에서 레이아웃을 평가한다. 자동 검사 결과와 시각·조작 확인 결과는 구분한다.

최초 장면은 메뉴다. 세부 위치·색·크기·시간 값은 실제 화면에서 조정한다. 구현 완료와 위 완료 기준의 사용자 확인 완료는 구분한다.
