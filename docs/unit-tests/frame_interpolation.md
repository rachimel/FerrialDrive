# 모션 벡터 프레임 보간 Unit Test

## 목적과 범위

Unreal 검 콤보의 원본 유지·단순 혼합·모션 벡터 보간·같은 시각의 정답 렌더를 비교한다. 이동 훈련장에서는 I 키로 보간을 전환한다.

- 진입점: `tests/frame_interpolation_unreal_test.py`. 로컬 `data/runtime/frame_interpolation/player_combo/catalog.json`에서 1~4타를 불러온다. 본편 게임의 재생기를 수정하지 않는다.
- 재사용: `ferrial_drive/rendering/motion_vectors.py`, `pico_interpolation.py`. import로 창이나 루프를 시작하지 않는다.
- 자동 검사 입력: `samples/frame_interpolation/`. 숫자와 기본 도형으로 구성하며 게임 에셋을 요구하지 않는다.
- Pico2D가 연 SDL OpenGL 렌더러와 기존 셰이더 확장을 사용한다. Pico2D 원본·본편 재생/입력·전투 판정은 수정하지 않는다.

## 위상 규칙

게임 공격은 별도 가속형 `accelerate` 위상 `2t³−t⁴`를 지원한다. 재생 속도는 0에서 증가하고 총 시간은 유지한다. 기존 비교 프로그램의 기본 SmoothStep/선형 전환과 구분한다. CPU 목표 위상과 기존·공유 아틀라스 GPU 셰이더가 같은 곡선을 사용하며 블러 노출 표본에도 적용한다.

SmoothStep은 **처음 KeyFrame과 끝 KeyFrame의 목표 위상 사이에 한 번** 적용한다. 각 중간 프레임 또는 인접 원본 프레임 구간에서 반복하지 않는다.

1. 첫/끝 KeyFrame 사이의 정규화한 시간 진행률을 `u`라 한다.
2. 기본 곡선은 `s(u) = u²(3−2u)`다. 비교용 선형 곡선은 `s(u) = u`다.
3. 목표 위상은 `q = q_start + (q_end − q_start) × s(u)`다. 기본 시연은 0→1을 사용한다.
4. 목표 위상 `q`로 인접 원본 프레임과 구간 보간률 `alpha`를 찾는다. 동일 간격 구간이 N개면 `v=q×N`, `i=min(floor(v), N−1)`, `alpha=v−i`다.
5. `alpha`에는 SmoothStep을 다시 적용하지 않는다. 중간 원본 프레임마다 속도가 0이 되는 것을 피한다.

원본 순서·첫/끝 자세·전체 재생 길이는 유지한다. 중간 자세의 도달 시각과 속도 분포는 곡선에 따라 바뀐다. 이미 타이밍을 조정한 공격에 전체 곡선을 적용하면 타격 자세의 도달 시각도 바뀌므로 본편 적용 전 판정 시각과 함께 확인한다. 이번 테스트는 게임 판정을 연결하지 않는다.

## 모션 벡터 보간

프레임 A의 표면 픽셀을 B로 옮기는 `A→B`, B의 표면 픽셀을 A로 옮기는 `B→A` 변위를 사용한다. 단위는 **해당 원본 프레임 쌍 사이의 픽셀 변위**이며 픽셀/초 또는 렌더 내부 서브샘플 변위와 혼용하지 않는다.

중간 픽셀을 만드는 양 끝 이미지의 위치를 반복 역매핑하고, 두 이미지의 premultiplied RGBA를 혼합한다. 색상은 업로드 시 미리 알파를 곱하고 합성 출력에서 복원한다. 각 프레임 영역 바깥은 투명하게 취급하며, 아틀라스의 인접 구간을 샘플하지 않도록 경계를 제한한다.

역매핑은 16회·완화율 0.5를 사용한다. 큰 변위와 가림 경계에서 고정점 반복의 진동을 줄이지만 사라진 표면을 복원하지 않는다. 기본 캐시는 4클립이며 호출자가 `cache_capacity`로 조절한다. UI v2의 `PicoMotionSprite`는 40클립을 미리 준비한다. 현행 UI 연결과 한계는 [UI v2](ui_unit_test_v2.md)를 따른다.

기본 도형의 벡터는 표면 변환에서 정확한 대응점으로 계산하고 투명 여백까지 연장한다. 이것은 광학 흐름 추정이나 실제 Unreal 벡터 출력 검증이 아니다.

## 모션 블러

- 기본 노출 시간은 0.016초, 표시는 16ms다. `B`로 끄거나 켜고 `[`/`]`로 0.004초씩 조절한다.
- 노출 구간에서 9개 시각을 균일하게 샘플한다. 각 시각에 **전체 KeyFrame 위상 곡선 → 인접 원본 선택 → 벡터 보간**을 적용한 뒤 premultiplied RGBA를 평균한다.
- 기본 잔상 방향은 **후방**이다. 현재 시간보다 이전의 재생 시각을 모아 이동 뒤쪽에 잔상을 만든다. 전방은 이후 시각, 양방향은 앞뒤 시각을 사용한다. 역재생에서는 시간 방향도 반전한다. 검·팔 등 각 표면의 벡터를 사용하며 화면 전체에 고정 각도 블러를 적용하지 않는다.
- **강도와 노출 시간은 독립 조절**한다. 강도 0~100%(기본 65%)는 선명한 보간 결과와 잔상 평균 결과의 혼합 비율이다. 0%는 선명한 결과, 100%는 잔상 평균을 전부 적용한다. 노출 시간은 잔상을 모으는 시간 범위다. 강도 혼합도 premultiplied RGBA에서 수행한다.
- 화면의 노출 시간에 재생 속도 배율을 곱해 클립 시간 구간으로 변환한다. 속도를 낮추면 같은 노출 시간의 이동량과 블러 길이도 줄어든다.
- 노출 구간이 중간 원본 프레임의 경계를 넘으면 해당 구간의 프레임과 벡터를 선택한다. 첫/끝 KeyFrame 바깥은 끝점으로 제한한다. 클립 사이 전환·반복 경계 연결은 범위 밖이다.
- 정답 도형도 같은 노출 시각을 직접 그려 평균한다. 단순 Gaussian blur나 두 이미지의 투명도 혼합을 모션 블러라고 표시하지 않는다.

## 실제 Unreal 검 콤보

```powershell
python tests/frame_interpolation_unreal_test.py
```

이 파일도 Runner의 탐색·드롭으로 별도 실행한다. 1~4 버튼 또는 숫자 키로 타격을 선택하고, 재생 중에는 **1→2→3→4→1** 순서로 이어진다. Space로 멈추고 시간 막대로 각 타격을 살핀다. 각 타격의 처음/끝 목표 위상에 SmoothStep을 한 번 적용한다. 보간률에 곡선을 재적용하지 않는다.

기본 화면은 연속 콤보 경계의 **A/B 전환 비교**다. A는 이전 타격을 넘긴 시간을 다음 타격에 이월하고, B는 다음 타격의 시간 진행률을 0으로 두어 첫 프레임을 반드시 한 번 출력한다. B는 그 경계의 잔여 시간을 버리므로 실제 재생 길이가 화면 갱신 간격에 따라 약간 늘어날 수 있다. 두 후보의 선택은 사용자 비교 후 결정한다.

한 후보만 재생하며 원본/혼합/벡터/실제 정답 렌더 네 패널을 표시한다. 상단 A/B 버튼 또는 `Tab`으로 시간 처리 후보를 전환한다. 전환 자체는 현재 자세·위상을 유지하며, `R`로 선택한 후보를 1타부터 다시 시작한다. 곡선·속도·블러 방향·강도·노출은 유지한다. 시간 막대를 드래그하면 원하는 진행률에서 정지한다. 후보 전환 표시가 없는 기본 네 패널은 `--single`로 실행한다.

### 성능과 현재 확인

네 동작의 CPU 입력·GPU 텍스처를 시작할 때 준비하고 재사용한다. A/B별 두 재생기를 동시에 돌리지 않는다. 텍스처 캐시는 최대 네 클립이며 종료·퇴출 시 해제한다. 고정 체크무늬 배경도 텍스처 한 장을 재사용한다.

2026-11-12 실제 OpenGL 포함 자동 검사 16개가 통과했다. 검 콤보 네 동작의 26개 중간 구간을 실제 48fps 정답 시각과 비교했다. 그중 24개에서 벡터 보간의 가시 영역 RGBA 오차가 단순 혼합보다 낮았고, 알파 IoU의 최솟값은 약 0.807이었다. 이는 전체 외관 승인이나 가림 복원 완료를 뜻하지 않는다.

CPU 호출 계측 120프레임 실행에서 체크무늬 그리기의 누적 시간은 약 0.535초→0.016초로 줄었다. 네 동작 시작 준비 중 알파 변환 8회의 누적 시간은 약 1.351초→0.519초였다. 계측 오버헤드·시작 비용·프레임 대기를 포함하는 CPU 측정이며 GPU 실행 시간이나 전투 성능으로 확대하지 않는다. `--profile output/performance/선택이름.prof`로 같은 호출 계측을 선택 실행한다. 시작 준비 시간과 재생 중 전환 정지를 구분한다.

현재 입력은 Unreal에서 만든 1타 내려베기·2타 가로베기·3타 찌르기·4타 후방 베기 후보다. 1~3타는 0.5초·6구간, 4타는 2/3초·8구간이며 원본은 12fps다. 실제 정답 렌더는 48fps이며 가장 가까운 시점과 해당 위상을 표시한다. 임의 보간 시각과 정답 렌더 시각의 오차는 최대 약 10.42ms다. 보고서에 실제 시간차를 기록하고, 수치 검사는 정답과 정확히 겹치는 중간 시점을 선택한다.

실제 정답 렌더는 **블러 없는 이미지**다. 블러 품질을 물리적인 Unreal 모션 블러 정답과 비교했다고 주장하지 않는다. 도형 샘플은 같은 방향·강도·노출로 직접 그린 정답을 제공한다.

네 동작의 원본 캔버스는 384×384, 공통 크롭은 왼쪽 위 `(55,56)`·245×245다. 같은 카메라 좌표와 크롭을 유지해 타격 전환 시 배율·중심이 바뀌지 않게 한다. 이 크롭은 해당 후보의 실측 결과이며 다른 동작에 공통 규격으로 강제하지 않는다.

### 출력·변환 경로

- `python automate/run.py unreal-motion-vectors --unreal UnrealEditor.exe --project 프로젝트.uproject --request 요청.json`으로 전용 Unreal 프로세스를 실행한다. 기존 사용자 에디터·동작 키·리그는 수정하지 않는다.
- 요청은 `map`, `animation`, 새 `asset_root=/Game/MechLab/Interpolation_*`, 새 `output`, `size`, `duration_seconds`, `source_fps`, `reference_fps`다. `captures` 배열은 여러 타격을 같은 프로세스의 MRQ 큐에서 출력한다.
- MRQ의 기본 `MovieRenderQueue_MotionVectors` 재질·32비트 고정밀 EXR과 PNG를 사용한다. 정방향·역방향은 같은 원본 AnimSequence를 서로 다른 검증 Sequence에서 재생한다. 마지막 키가 다음 반복으로 바뀌는 것을 피하려고 검증 Sequence에 1 tick의 끝점 여유를 둔다. 원본 키는 바꾸지 않는다.
- 변환은 Blender 백그라운드에서 `automate/unreal/motion_vector_convert.py -- --source 렌더폴더 --output 새데이터폴더 --crop LEFT TOP SIZE`를 실행한다. Blender는 EXR/PNG 디코딩에만 사용한다. 리그·포즈·렌더를 새로 만들지 않는다. Pillow·OpenEXR 패키지 추가 설치는 필요 없다.
- `--decoder 규약.json`은 같은 출력 조건에서 검증한 `channels`·`signs`·`scale`을 명시한다. 현재 클립에서 측정된 후보에 없으면 실패하며 자동 최소 오차 선택과 명시 선택을 provenance로 구분한다. 움직임이 매우 작은 Idle의 자동 배율 판정은 다른 방향·큰 변위 검격과 함께 확인한다.
- 변환기는 정/역방향 색상 일치, 움직이는 표면의 벡터 존재, 채널·축·배율 후보의 재투영 오차, 변위 범위·크롭을 확인한다. 현재 네 동작에서 같은 규약인 `X=−2×(R−0.5)×원본폭`, `Y=+2×(G−0.5)×원본높이`가 측정됐다. 이 규약을 다른 Unreal 버전·재질에 무검증 복사하지 않는다.
- 현재 표면에서 이전 시각으로 향하는 변위는 정방향 렌더의 B 프레임에서 얻고, A→B는 역재생 렌더의 대응 A 프레임에서 얻는다. 임의 부호 반전 하나로 양방향 벡터를 대체하지 않는다. 투명 여백의 벡터는 가까운 가시 표면 값으로 확장한다.
- 보존 요청·재사용 판단은 `automate/workspace/frame_interpolation_20261112/`, 원시 EXR·진단 출력은 `output/frame_interpolation/`, 로컬 재생 입력은 `data/runtime/frame_interpolation/`다. 실제 모델에서 나온 이미지·벡터는 Git 공개 대상에서 제외한다.

## 외부 프리렌더 입력 계약

`--dataset 프레임쌍.json` 또는 여러 프레임쌍 JSON을 나열한 클립 JSON을 전달한다. 이미지·벡터 경로는 해당 JSON 기준이다. 프레임쌍은 동일 크기이며, 클립은 동일 시간 간격이고 인접 경계 이미지가 일치해야 한다.

```json
{
  "schema_version": 1,
  "label": "Unreal 변환 결과",
  "size_pixels": [192, 192],
  "duration_seconds": 0.16666666666666666,
  "origin": "top_left",
  "vector_units": "pixels_per_pair",
  "vector_encoding": "signed16_rgba_x64",
  "image_a": "a.png",
  "image_b": "b.png",
  "forward_a_to_b": "a_to_b.rgba",
  "backward_b_to_a": "b_to_a.rgba"
}
```

클립 JSON은 `{"schema_version": 1, "pairs": ["pair_00.json", "pair_01.json"]}`으로 작성한다.

벡터 파일은 위쪽 원점의 행 우선 RGBA 원시 바이트이며 각 픽셀은 4바이트다. `X=(R×256+G−32768)/64`, `Y=(B×256+A−32768)/64`로 복원한다. 각 성분의 범위는 -512~약 511.984px, 양의 Y는 아래쪽이다. 색 보정·알파 곱·손실 압축을 적용하지 않는다. 색상과 벡터는 동일 크롭·패딩·피봇·배율을 유지한다. 현재는 전체 프레임 단위 입력이며 기존 파츠 번들의 크롭 아틀라스 연결은 범위 밖이다.

Unreal MRQ의 기본 벡터 파일을 이 JSON에 바로 넣을 수 있다고 가정하지 않는다. 정규화·채널·방향·렌더 샘플 간격을 확인해 위 계약으로 변환해야 하며 양방향 데이터가 필요하다. 첫 프레임의 이전 이력, 프레임 건너뛰기, 노출·Temporal Sampling의 영향도 실제 출력으로 확인한다. [Epic 렌더 패스 문서](https://dev.epicgames.com/documentation/unreal-engine/cinematic-render-passes-in-unreal-engine), [SideFX flipbook 문서](https://www.sidefx.com/docs/houdini/nodes/out/labs--flipbook_textures-1.0.html)를 참고한다.

## 한계와 검증 구분

- 가림으로 사라지거나 새로 드러난 표면을 복원하지 않는다. 3번 장면은 이 한계를 드러내는 사례이며 모든 구간의 품질 통과를 기대하지 않는다.
- 끝점 변위는 회전의 실제 곡선 궤적을 완전히 표현하지 않는다. 가는 검의 회전과 큰 움직임은 정답 도형과 비교한다.
- 벡터 패딩·역매핑 수렴·알파 경계에 따른 결함이 남을 수 있다. 블러를 끈 상태도 반드시 확인한다.
- 보간은 이미 래스터화된 원본을 다시 샘플하므로 직접 그린 정답보다 경계가 부드러워질 수 있다. 끝점 일치와 중간 시점의 경계 오차 허용 범위를 구분한다.
- 실제 Unreal 검 콤보 1~4타의 단일 사선 카메라 연결을 제공한다. 다른 방향·메카 파츠 개별 조립·투명 재질·최종 128px 표시·다수 기체 성능·전체 전투 모션·사용자 외관 승인은 별도 검증이다.
- 자동 수치 검사, 숨긴 실제 OpenGL 실행, 보이는 창의 입력 확인, 사용자 품질 승인을 구분해 기록한다.
