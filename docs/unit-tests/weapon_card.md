# 무기 카드 v2 표시 규격

## 구성

- 카드마다 왼쪽 원형 보조 슬롯 하나, 굵은 아래 사선·가는 위 사선, 무기 이름·실루엣·잔탄 수와 하단 띠를 표시한다.
- 위·아래 사선의 기울기는 같다. 굵은 아래 선의 오른쪽 위 끝과 가는 위 선의 아래 시작점을 하단 띠 윗선에서 붙인다. 두 선의 끝 단면은 수평이며 별도의 가로 연결부는 없다. 하단 띠는 굵은 아래 선과 연결한다. 하단 띠 오른쪽 끝도 사선으로 자르며 얇은 외곽선은 그리지 않는다.
- 원의 세로 중심은 가는 사선 전체 중점에 맞추고, 원 오른쪽 끝은 해당 중점에서 왼쪽으로 12px 띄운다. 원과 가는 선이 겹치지 않아 위 선 전체를 끊김 없이 그린다. 이름·무기 실루엣은 원과 사선 오른편에 배치한다.
- 기본 속성은 하단 띠보다 큰 글자를 띠 안에서 잘라 표시한다. 오른쪽 `MELEE/RANGED` 영역과 분리하고 잔탄보다 낮은 대비를 사용한다.
- 추가 속성이 있을 때만 작은 아이콘을 표시한다. 현재 `FIRE`는 불 도형이며, 도안이 없는 값은 머리글자로 표시한다. 이는 표시용 임시 규약이며 게임 효과 판정이 아니다.
- 속성·근접/원거리 구분은 가물치 무료고딕을 사용한다. 속성별 고유색은 미정이며 현재 UI 공통색을 사용한다.
- 원형 보조 슬롯의 백웨폰·카운터는 임시 도형이다. 실제 이미지 경로를 공급할 수 있으며 사용·교체·충전 판정은 연결하지 않는다.

## 연결

- 실행 진입점은 `tests/ui_unit_test_v2.py`다. 기존 E 무기 교체·F 로드아웃 전환·일시정지·초기화 입력을 사용한다.
- `ferrial_drive/ui_v2/weapon_card.py`는 카드 내용만 그린다. `UiV2View.weapon_cards()`의 기존 배율·이동·투명도·방향성 블러 안에서 슬롯과 내용을 함께 그린다.
- 무기 교체 0.12초·로드아웃 0.5초, 곡선·입력 예약·일시정지 및 고정 번호 탭은 기존 제어를 따른다. 이동 거리는 카드의 실제 왼쪽 끝으로 계산한다.
- `v2.style.weapon_card_shape=concept`가 현재 카드다. 기존 `trapezoid/slanted` 표시 경로도 보존한다.
- 카드 배치와 도형 치수는 `v2.layout.weapons`·`v2.style.weapon_card`, 글꼴은 `v2_weapon_attribute`·`v2_weapon_kind`에서 조절한다.
- 장비 표시 배율은 `equipment_scale=1.0`이다. DPI-aware 캔버스의 물리 픽셀 기준으로 카드 원본 420×132px·원 지름 80px·하단 띠 28px·아래/위 선 18/7px를 사용한다. 글꼴 원본 크기도 이름 18px·속성 48px·구분 18px·잔탄 46px로 정한다. 긴 이름·속성 폭 초과 때만 해당 텍스트를 영역에 맞춘다.
- FHD 카드 기준 영역은 `[1484,792,420,132]`이며 2행을 8px 간격으로 놓아 오른쪽·아래 기준 여백 16px를 유지한다. 이름은 `v2_weapon_name`, 잔탄은 `v2_ammo` 역할이다. 다른 DPI/해상도의 실제 표시 검증과 이번 FHD 캡처를 구분한다.

## 표시 데이터

`WeaponInfo`의 기존 이름·잔탄·이미지 인자는 그대로 유지한다. 선택 필드는 다음과 같다.

| 필드 | 역할 |
| --- | --- |
| `base_attribute` | 기본 속성 표시 문자열. 빈 문자열이면 생략 |
| `additional_attributes` | 추가 속성 표시 목록. 생성 시 불변 tuple로 보관 |
| `auxiliary_kind` | `back_weapon`·`counter` 또는 `None` |
| `auxiliary_image_path` | 원형 슬롯 안에 표시할 선택 이미지 |

- 샘플은 근접 `SLASH`·원거리 `IMPACT`, 첫 로드아웃의 원거리에만 `FIRE`를 표시한다. 근접 원은 카운터, 원거리 원은 백웨폰 임시 도형이다. 이를 실제 무기별 속성·장비 규칙 확정으로 해석하지 않는다.
- 재사용 모듈 import만으로 창·입력·실행 루프를 시작하지 않는다. 실제 게임은 같은 표시 데이터에 실제 상태를 공급한다.
- 자동 검사·렌더링·직접 조작·최종 외관 승인은 구분한다. 이번 작업의 결과는 [개발 기록](../ai-dev-log/2026-11-13-weapon-card-concept.md)을 따른다.
