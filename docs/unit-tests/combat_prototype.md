# 전투 프로토타입

상태: **임시 도형 1대1 전투·전투 생성 Trail 접촉 판정 구현 / 전투 자동 검사 51개 통과 / 4단 공격 정적 렌더 확인 / 실제 조작·사용감은 사용자 테스트 담당**.

정식 에셋 제작을 기다리지 않고 이동·회피·반격과 승패를 확인한다. 독립 실행 진입점은 `tests/combat_test.py`이며, 조작과 샘플 환경은 [샘플 안내](../../samples/combat_prototype/README.md)를 따른다. Runner가 소스를 실행하지 않고 `standalone`으로 판별하는 것을 확인했다. Runner GUI 드롭 자체는 이번 작업에서 조작하지 않았다.

## 모듈 책임

| 위치 | 책임 |
| --- | --- |
| `ferrial_drive/combat/config.py` | 전투 수치·훈련장·설정 로드 및 기본 검증 |
| `ferrial_drive/combat/geometry.py`, `trails.py` | 월드 벡터·칼날 궤적·Trail 다각형·이동하는 대상과의 접촉 검사 |
| `ferrial_drive/combat/simulation.py` | 입력 요청을 받아 고정 주기로 이동·충돌·공격·피해·승패 처리 |
| `ferrial_drive/combat/application.py` | 실제 장치 입력·일시정지·포커스·재시작·HUD 상태 연결 |
| `ferrial_drive/combat/view.py` | 월드→화면 투영·임시 도형·기존 HUD 표현 |
| `tests/combat_test.py` | 실행 옵션·공통 실행부 연결 |
| `samples/combat_prototype/` | 개인 에셋이 필요 없는 훈련장·임시 수치·실행 안내 |

규칙 모듈은 Pico2D·UI·테스트·Tools를 import하지 않는다. 화면이 없는 본편 상태에서도 `CombatWorld`와 `CombatInput`을 사용한다. 기체·탄환·사거리는 월드 좌표로 계산하고 화면에서 Y축을 압축·반전한다. 카메라는 플레이어 중심이므로 기존 HUD의 중앙 플레이어 앵커를 유지한다. 적 HP는 유일한 적 한 기에 연결하며 일반적인 타겟 선택 기능은 아니다.

## 구현 범위

- WASD 보행·Shift 달리기·마우스 독립 조준. 보행 입력 해제 즉시 정지.
- Space의 고정 방향·고정 거리 대시. 재입력에 의한 방향 변경·중첩·입력 예약·별도 무적 없음. 종료 후 추가 쿨타임 없음.
- 일반 검 공격 전 구간 대시 캔슬, 대시 시작 0.08초 이내 입력의 별도 대시 공격. 이후 입력은 조준 방향의 일반 검 공격이다. 이 입력 구간은 임시값이다.
- 검 4단 연계와 입력 예약. 도형 기체의 베기·가로베기·찌르기·뽑아베기를 서로 다른 임시 칼날 궤적으로 구분한다. 최종 메카 애니메이션을 검증한 결과가 아니다.
- **Trail은 전투에서 생성한다.** 이전/현재 칼날 위치 사이에 폭을 가진 다각형을 만들고, 화면과 명중 검사가 같은 다각형을 사용한다. **Trail과 기체의 원형 피격 범위가 접촉하면 명중**하며, 전방 부채꼴 전체를 미리 타격하지 않는다. 타격 구간 동안 남은 Trail도 유효하고, **타격 종료·대시 캔슬·전투 종료 시 Trail과 판정을 함께 제거**한다. 같은 공격은 같은 대상에게 한 번만 피해를 준다. 기본 Trail은 에너지 레벨과 연결하지 않는다.
- E 검/총 전환. 일반 검 공격 중 전환 캔슬은 이번에 열지 않았다. 대시 캔슬 후에는 전환할 수 있다. 전환 쿨타임 0.28초는 임시값이다.
- 45발 기관단총, 우클릭 조준 시 탄 퍼짐 감소·무한 예비 탄약. 장착·수납 여부와 관계없이 마지막 실제 발사 1초 뒤부터 탄약이 지수적으로 회복한다. 다시 발사하면 대기 시간과 회복 속도를 초기화한다. 탄창이 비었을 때 일정 시간 뒤 전탄을 채우는 별도 재장전은 없다. 일부만 회복돼도 발사할 수 있다.
- 이동·탄환·근접의 벽 차단, 기체 간 몸체 충돌, 연속 선분 기반 탄환 명중으로 얇은 벽·대상 건너뛰기 방지.
- 적 근접 기체 한 기. 접근→공격 준비 동작→방향 고정 근접 공격→회수 흐름. 공격 시작 시 방향을 고정한다. 별도 경고 표시 없음.
- 작은 사각 장애물 장면의 모서리 후보에 A*를 적용한 적 우회. 대규모 격자 맵·동적 장애물·다수 기체 길찾기 검증은 아니다.
- 실제 피해 기반 플레이어/적 HP·무장·잔탄·피해 숫자·HIT/DAMAGE·레이더. HIT/DAMAGE는 표시가 이어지는 동안의 누적값이다. 마지막 적중 후 유지·페이드가 끝나 완전히 사라지면 실제 집계와 숫자 표시 상태를 함께 0으로 초기화한다. 다음 적중은 새 집계로 시작한다. 페이드 중 재적중하면 누적을 이어가며 표시 수명을 갱신한다. 일시정지 중 표시 수명은 진행하지 않는다. 검의 4단 연계 상태와 카운터 초기화는 분리한다.
- 시작 대기·일시정지·포커스 상실 시 입력 해제·승패·재시작·종료·선택적 공통 계측.

걷기·대시·공격·탄약 수치와 경계 접촉 시 정지 처리 등은 이 프로토타입의 잠정 구현이다. 대시는 경계·벽·기체를 통과하지 않으며 정해진 시간 후 끝난다. 대시와 달리기는 에너지를 사용하지 않는다.

## 현재 조정값

| 항목 | 임시값 |
| --- | --- |
| 보행 / 달리기 | 360 / 576 월드 단위/초 |
| 적 이동 | 220 월드 단위/초 |
| 대시 | 300 월드 단위 / 0.20초 |
| 검 사거리 | 125 월드 단위 |
| 검 준비 / 타격 / 회수 | 0.07 / 0.08 / 0.13초, 합계 0.28초 |
| 검 연계 입력 예약 | 종료 전 0.12초 |
| Trail 폭 | 8 월드 단위, 반폭 4 |
| Trail 궤적 분할 | 최대 1/240초·회전 5도 간격 |
| 탄약 회복 대기 | 마지막 실제 발사 뒤 1초 |
| 탄약 회복 속도 | `2 × exp(1.6 × t)` 발/초. `t`는 회복 시작 후 경과 초 |

탄약 회복량은 속도를 시간 구간에 적분하며, 한 발 미만의 진행량도 이월한다. 회복 속도는 실제 발사 시 초기화한다. 빈 탄창은 마지막 발사부터 약 3.26초에 완충하며, 회복은 탄창 최대치에서 멈춘다. 수납만으로 대기를 줄이거나 가속을 초기화하지 않는다. 일시정지·포커스 상실 중에는 회복도 정지한다. HUD는 회복 대기 시간과 현재 발/초를 표시한다. 칼날 위치·궤적은 전투에서 계산하며 벽에 닿으면 잘라낸다. 대상의 프레임 사이 이동과 타격 활성 시간을 함께 검사한다.

## 후속 범위

에너지·자동 가드·근접 우클릭 투사체 차단·스왑 카운터·Break·Break Assault·Overdrive·스킬·필살기·두 번째 로드아웃·보스·교관 ADV·정식 프리렌더 에셋 연결은 이번에 구현하지 않았다. 일반 적 경고 표시는 제외하며 보스급 특정 공격의 경고 표시는 대상·방식 미정이다. 생략을 현행 전투 규칙의 폐기로 취급하지 않는다.

## 검증 구분

- 자동: 전투 규칙/Trail 41개·실제 Pico2D/SDL dummy 연결 10개, 총 51개 통과. 기존 이동·탄약·카운터 검증에 Trail 밖 비명중·빠른 휘두르기·빠른 대상 통과·타격 시작 전 통과 비명중·타격 종료/캔슬 제거·벽 차단·세계 좌표 유지·30/60/144 FPS 명중 일관성·표시와 판정의 동일 다각형 사용을 추가했다.
- 렌더링: SDL dummy에서 4단 공격의 중간 프레임을 각각 출력해 Trail·무기·적중 표시를 확인했다. 재생성 출력은 `output/combat_prototype/trail_review/`에 둔다. 정적 이미지이며 전체 동작·실제 조작 검증을 대신하지 않는다.
- 실제 조작: 사용자 직접 테스트 방침을 유지한다. 이번 Trail 변경에서 실제 창을 열거나 조작하지 않았다. 과거 검사 결과는 [최초 구현 기록](../ai-dev-log/2026-11-10-combat-prototype-implementation.md)을 참고한다.
- 성능: 프레임 계측 출력 경로만 확인했다. 목표 기기 60FPS·GPU 시간·다수 적·전체 메모리 목표 달성은 검증하지 않았다.
