# 대화 기록의 Codex 원문 근거

## 현재 사용하는 방법

대화 기록 도구에서 누락 항목을 선택하고 **원문 찾기**를 연다. Codex 프로젝트와 채팅을 고르고 검색 구절로 발언을 찾은 뒤 **선택 근거 가져오기**를 누른다. 대화·턴·발언 ID, 공개 발언의 짧은 인용, UTC/KST 기록 시각을 보완 초안에 가져온다. **적용**을 눌러야 문서를 저장한다.

여러 발언의 시각을 묶는 항목은 두 끝점을 골라 범위로 가져온다. 이 범위는 선택한 두 원문 기록의 시각이며, 범위 안 모든 제안·승인을 자동 검증했다는 뜻은 아니다. 같은 내용을 반복한 발언도 서로 다른 ID면 구분한다.

가져온 자료는 **Codex 원문 선택으로 보완**, 직접 입력한 확인은 **사용자가 원문 확인으로 보완**, 기억으로 보완한 자료는 **사용자 회고**로 구분한다. 원문 가져오기는 실제 레코드를 읽고 선택 후 변경 여부를 다시 확인한다. 그 발언이 해당 제안·이유·수용을 뒷받침하는지는 사용자가 판단한다.

다음은 실제 ESC 확정 응답의 위치를 기록한 예다.

```text
대화 ID: 01a1a3f4-ccc2-71f3-b551-8a45d0f91af1
발언 UTC: 2026-11-04T07:44:44.647Z
발언 KST: 2026-11-04 16:44:44.647
발언자: 사용자
원문: 타이틀에서는 ESC 동작 없음
연결: 타이틀의 ESC 동작을 무동작으로 확정한 응답.
```

대화 제목은 검색을 위한 보조 정보로 추가할 수 있다. 턴 ID·메시지 ID를 확인할 수 있으면 함께 기록한다. 해당 ID가 없을 때 만들어 넣지 않는다. UTC 발언 시각과 로컬 파일 수정 시각을 혼동하지 않는다. 원문을 확인한 지금 시각은 보완 시각이며 당시 발언 시각과 별개다.

## 근거로 말할 수 있는 범위

- 사용자 발언·확인 응답: 요청, 이유, 결정, 승인·정정의 직접 근거.
- AI의 사용자에게 보인 응답: 제안이나 반영 보고의 근거. 실제 수정·실행·검사 성공은 코드/변경 내용/검사 결과도 확인한다.
- 기존 요약만 확인한 경우: 요약 근거라고 표시한다. 원문 확인으로 승격하지 않는다.
- 누락된 이유나 승인을 주변 발언에서 추정하지 않는다. 짧은 인용이 실제로 뒷받침하는 항목만 보완한다.

원시 로그 전체·도구 출력 전체를 프로젝트 문서에 복사하지 않는다. 필요한 사용자/공개 AI 응답과 위치만 발췌한다. 숨겨진 추론과 관계없는 대화는 근거로 사용하지 않는다. 개인 컴퓨터의 로그 경로는 로컬 연결 정보로만 취급한다.

## 기록 조회 방식과 한계

공식 [Codex App Server 문서](https://learn.chatgpt.com/docs/app-server#list-thread-items)는 저장된 기록의 `thread/turns/list`·`thread/items/list` 읽기를 설명한다. 항목에는 턴·메시지 ID가 있고 기록된 시각은 선택적으로 제공된다. 이번 구현은 이 API가 아니라 **로컬 Codex 저장 형식 어댑터**를 사용한다.

프로젝트 소속 ID로 범위를 정하고, 해당 채팅의 `response_item` 중 사용자·공개 AI 메시지만 읽는다. analysis·도구 출력·주입된 환경 안내는 제외한다. 기록에 없는 시각은 미상이며, 턴 시각이나 파일 수정 시각으로 대체하지 않는다. 시각은 발언 레코드의 기록 시각이지 키 입력 시작이나 실제 발화 시작을 측정한 값은 아니다.

현재 지원 범위는 프로젝트/채팅 검색, 원문 선택, 시각·범위 가져오기, 검색 결과의 로컬 JSON 내보내기다. 로컬 원문이 없는 채팅·원격 기록·저장 형식 변경은 자동 복구하지 않는다. Codex 채팅의 특정 발언을 앱에서 직접 여는 기능과 대량 누락 자동 확정은 구현하지 않았다. 화면의 누락 이동은 프로젝트 Markdown 안의 위치로 이동한다.
