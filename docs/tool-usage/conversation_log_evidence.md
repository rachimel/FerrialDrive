# 대화 기록의 Codex 원문 근거

## 현재 사용하는 방법

대화 기록 도구에서 누락 항목을 선택하고, 직접 원문을 확인한 경우 `원문 확인`을 선택한다. 근거 칸에는 **대화 ID·발언 시각·발언자·짧은 원문 인용**을 함께 넣는다. 기억으로만 보완하면 `사용자 회고`를 선택한다. 도구는 입력한 근거를 저장하며 원문 일치 여부를 자동 검증하지 않는다.

다음은 실제 ESC 확정 응답의 위치를 기록한 예다.

```text
대화 ID: 01a1a3f4-ccc2-71f3-b551-8a45d0f91af1
발언 UTC: 2026-11-04T07:44:44.647Z
발언 KST: 2026-11-04 16:44:44.647
발언자: 사용자
원문: 타이틀에서는 ESC 동작 없음
연결: 타이틀의 ESC 동작을 무동작으로 확정한 응답.
```

대화 제목은 검색을 위한 보조 정보로 추가할 수 있다. 턴 ID·메시지 ID를 확인할 수 있으면 함께 기록한다. 해당 ID가 없을 때 만들어 넣지 않는다. UTC 발언 시각과 로컬 파일 수정 시각을 혼동하지 않는다. 원문을 확인한 지금 시각은 보완 시각이며 당시 발언 시각과 별개다.

## 근거로 말할 수 있는 범위

- 사용자 발언·확인 응답: 요청, 이유, 결정, 승인·정정의 직접 근거.
- AI의 사용자에게 보인 응답: 제안이나 반영 보고의 근거. 실제 수정·실행·검사 성공은 코드/변경 내용/검사 결과도 확인한다.
- 기존 요약만 확인한 경우: 요약 근거라고 표시한다. 원문 확인으로 승격하지 않는다.
- 누락된 이유나 승인을 주변 발언에서 추정하지 않는다. 짧은 인용이 실제로 뒷받침하는 항목만 보완한다.

원시 로그 전체·도구 출력 전체를 프로젝트 문서에 복사하지 않는다. 필요한 사용자/공개 AI 응답과 위치만 발췌한다. 숨겨진 추론과 관계없는 대화는 근거로 사용하지 않는다. 개인 컴퓨터의 로그 경로는 로컬 연결 정보로만 취급한다.

## 자동 연결을 추가할 경우

공식 [Codex App Server 문서](https://learn.chatgpt.com/docs/app-server#list-thread-items)는 저장된 기록의 `thread/turns/list`·`thread/items/list` 읽기를 설명한다. 항목에는 턴·메시지 ID가 있고 기록된 시각은 선택적으로 제공된다. `userMessage`와 사용자에게 보인 `agentMessage`를 선택해 근거를 연결하는 방식으로 확장할 수 있다. 요약 목록만 읽고 원문을 확인했다고 처리하지 않는다.

현재 도구에는 Codex 기록 자동 검색·가져오기·원문 대조·채팅의 특정 발언 열기를 구현하지 않았다. 위 식별 정보는 근거 칸에 입력하는 방식이다. 화면의 누락 이동은 프로젝트 Markdown 안의 위치로 이동하는 기능이다.
