# 툴 시연용 테스트 데이터

상태: **요구사항 정리 / 독립 샘플·시연 연결 미구현**

## 원칙

- 각 툴을 시연할 수 있는 최소 데이터를 게임과 독립적으로 제공한다.
- 공개 가능한 기본 도형·직접 작성한 수치 데이터 등을 사용한다. 로제 원화·게임 모델·세이브와 AI 생성 에셋을 필수로 요구하지 않는다.
- 샘플은 `samples/<tool_name>/`에 필요한 참조 파일과 함께 보관한다. 기존 `data/`·`output/capability_test/`의 로컬 파일이나 개인 절대 경로에 의존하지 않는다.
- 필요한 Python 패키지·Blender 등의 실행 환경은 별도로 안내한다. 게임 데이터 독립성이 실행 환경의 설치 불필요를 뜻하지 않는다.
- 실제 툴이 지원하는 기능 경로로 확인한다. 저장·출력이 있는 툴은 샘플 원본과 작업 결과를 분리한다. UI 시연처럼 저장이 목적이 아닌 프로그램에 불필요한 저장 기능을 추가하지 않는다.

## 도구별 샘플 구성안

| 대상 | 최소 데이터 | 확인할 기능 |
| --- | --- | --- |
| 표정 스튜디오 | 기본 도형으로 만든 파츠·텍스처·마스크, 최소 표정 키와 편집 프로젝트 | 불러오기·곡선 편집·표정 변화·저장·출력 |
| Blender 제작 경로·후속 프리렌더 툴 | 기본 도형 모델·짧은 동작·카메라·광원 설정 | AI 조작 연결·미리보기·방향별 본체·그림자 추출 |
| 스프라이트 시트 도구 | 작은 도형 스프라이트 시트와 프레임 정보 | 시트 불러오기·프레임 지정·저장 |
| UI Unit Test | 가짜 상태값·테스트 장면·UI 설정 | UI 반응·장면 전환·HUD 표시 |

위 목록은 샘플 구성안이다. 후속 툴의 아직 없는 기능을 구현 완료로 표시하지 않는다.
현재는 UI Unit Test용 샘플을 우선 준비한다. 다른 툴의 샘플 연결은 각 툴 작업에서 진행한다.

## 샘플별 안내

각 샘플에는 필요한 파일, 데이터 형식·출처, 실행 환경, 시연 시작 방법, 조작 순서와 기대 결과를 기록한다. 원본과 결과의 저장 위치도 구분한다.

## 완료 조건

1. 실행 환경을 준비한 뒤 실제 게임 데이터 없이 샘플만으로 시연을 시작한다.
2. 주요 기능을 직접 조작하고 편집 결과를 확인한다.
3. 저장·출력이 있는 툴은 결과를 다시 불러와 확인한다. 샘플 원본은 변경되지 않아야 한다.
4. 다른 작업 디렉터리에서 실행해도 샘플 참조가 유지된다.
5. 어떤 도구·기능을 확인했는지와 남은 미검증 항목을 기록한다.

현재 표정 스튜디오와 Blender 경로는 로컬 `data/portrait_editor/`의 실제 작업 데이터를 참조한다. 원본은 output에서 분리했지만, 공개 가능한 독립 샘플 제공은 아직 별도 작업이다.
